### Added (publication descriptor and receipt types, F22 a2, 2026-11-12)

New package `decoy_engine.publication` with the `decoy-publication/v1` descriptor (`_decoy_publication.json`): canonical JSON (sorted keys, fixed separators, ASCII) holding `schema`, `unit` (`immutable_directory/v1`), `operation_id`, `result_id`, the sorted artifacts (`path`, `role`, `rows`, `sha256`, `size`), the vault (`null` or `sha256`, `size`, `entry_count`) and `engine_version`. `result_id` is a domain-separated SHA-256 of the canonical artifact list only. One field declaration drives the writer (`build_descriptor`, `encode_descriptor`) and the strict reader (`decode_descriptor`), which refuses a missing or unknown schema, missing or unknown fields, any non-exact JSON type (a `bool` is never a count), negative or oversized counts, unknown tokens, any digest or `operation_id` that does not `re.fullmatch` its shape (a trailing newline included), duplicate keys, non-finite numbers, absolute or `..` paths, unsorted artifacts, a `result_id` that does not recompute, non-canonical bytes and anything over 1 MiB, with a `ValueError` naming a closed check token only. Also `PublicationRequest`, `CommitReceipt`, `ArtifactSummary` and `VaultBinding`, each shape-checked when built. Nothing calls them yet; publishing with the descriptor arrives in a later slice.
