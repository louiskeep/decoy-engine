### Added (durable directory publish, destination lock and member reads, F22 a1b, 2026-11-11)

`fileaccess` gains the `publication` stage label. On Linux and macOS, on both the ambient and strict policies, a `publication` directory stage keeps its pending name `._decoy_publication_pending_<token>` for its life, its files are 0600 (owner bits restored when the umask stripped them), and `publish()` is durable: every staged file and directory is fsynced deepest first, the stage is renamed onto the leaf, then the parent (the commit point) and each directory above it are fsynced up to and including the anchor (the strict capability root; on the ambient policy the mount boundary). A failure before the rename raises with the errno only and keeps the stage for `abort()`; a failure after it raises the new `CommitUncertain` with the leaf bound and kept. On the ambient policy an unreadable directory above the ones this attempt created ends the walk only when another uid owns it. `OutputDir` gains `lock(timeout_s)` (`flock` on `.<leaf>.decoy-lock` beside the leaf, never unlinked; `LockTimeout`, or `LockUnavailable` with no lock-free fallback), `read_member(component, limit=)` (bounded, `None` when absent, `LeafTooLarge` over the limit) and `sync_chain()`. The new errors carry an errno name only. Other labels and Windows are unchanged.
