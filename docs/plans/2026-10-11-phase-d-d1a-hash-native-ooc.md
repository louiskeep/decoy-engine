## 1. Why + what
The out-of-core (DuckDB + Arrow) route admits `hash` but computes it in pure Python (`kernel/_scalar.hash_array`). The native-chunked route already masks `hash` through the compiled companion kernel (`native/_kernels_keyed.native_keyed_hash` -> `_crypto_ext.load_compiled_crypto_kernel().derive_batch`). D1a routes the OOC route's `mask_batch` hash compute through that SAME kernel for admitted-type columns, so admitted OOC hash (including string columns, the common case) runs on Rust/Arrow. No new Rust, no ABI change.

**Normalization-version decision (Cam, 2026-10-11).** The native (Rust) and Python hash paths normalize text (NFC) under different Unicode versions (Python runtime unidata 14.0.0; the Rust `unicode-normalization` crate uses newer tables). For text containing codepoints assigned after the Python runtime's Unicode version, the two produce different tokens for the same value. Cam ACCEPTED this difference: the native (Rust) path is the go-forward canonical result; the Python path is the fallback and may differ on that rare text. The accepted-difference is confined to post-Python-version codepoints (confirmed in §3); it is a version-transition artifact, not a bug. Two obligations attach: a stability lock-test (§3) and a user-facing doc note for anyone transitioning from Python-only to Rust (§9).

## 2. Scope
Three distinct OOC hash-compute entrypoints (verified @ cc2f1c71; reachability re-confirmed, correcting rev 3):

**IN (routed native when eligible):** the `hash` branch reached through `mask_batch` in BOTH streaming drivers, `_runner.py:428` (`_stream_table`) and `_stream_driver.py:333` (`stream_table`). `mask_batch` skips ONLY the incoming child FK columns (`_runner.py:349` `skip_columns = child_columns`), so admitted PAYLOAD and PARENT-KEY hash columns both flow through it and are both routed native. Whole column takes ONE path, never half-native. Parent-key relations are then built by `build_parent_key_relation_aligned` (`_runner.py:477`), which COPIES the already-masked output; it performs no hashing and must NOT be recorded as a hash invocation.

**OUT for D1a, EXPLICITLY DECLINED with a recorded caller-visible reason (Python retained, deferred to a later FK-key-native slice):** REMAP FK hash at `_stream_join.py:709` and `_batch_join.py:345`, which hash via `mask_column(pa.array(normalized, from_pandas=True), ...)`. The pandas-normalized REMAP value has an EFFECTIVE Arrow type that can differ from the source schema and between batches (null-only vs integer; bool-normalize yields integer); a safe effective-type contract for those is its own slice. Reason `fk_key_hash_remap_native_deferred`. D1a leaves these byte-identical (still `hash_array`).

**Also out:** categorical + bucket_perturb native-OOC; SEQ route (D2); any change to the companion crate / ABI / the native-chunked route; any change to OOC admission/routing; any change to `hash_array` itself; the 100M/200M growth proofs (D4c).

## 3. Eligibility, pinning, the parity + stability contract (folds #1 + #3)
A `mask_batch` hash column is routed native only when ALL hold, decided ONCE at run/table-prep and immutable for the run:
1. The companion loads and is ABI-compatible (abi-3), established once per run.
2. The column's up-front Arrow type is admitted AND parity-eligible (below).

**Parity-eligible native type set (confirmed by a runnable comparison, native vs Python, fixed key, over input classes):** `utf8`, `large_utf8`, `bool`, `int8..int64`, `uint8..uint64`. The confirmation showed native == Python for ASCII, common accented text, NFC decomposed-vs-composed (both paths compose correctly), and old emoji; native and Python agree on all shared-Unicode-version text. The ONLY divergence is post-Python-version codepoints (e.g. U+0897), which Cam accepted (§1). Bool and every integer width agree by construction (one-byte bool; length-prefixed signed encoding incl. negatives and unsigned > 2**63).

**Declined types (keep Python, recorded reason):**
- **Timezone-aware timestamps**: DECLINED (`hash_input_type_tz_timestamp_deferred`). This is NOT the accepted normalization case; it is a missingness/format divergence. `pa.array([-2**63], type=timestamp("ns", tz="UTC"))` has Arrow `null_count==0` but `to_pylist()` yields `NaT`, so Python `hash_array` emits `None` (missing) while Rust canonicalizes the tick to a token (present). Null-vs-value divergence is not acceptable under the accepted-difference, so tz-aware is deferred until a bounded preprocessing contract exists.
- **Non-admitted types** keep Python and are NOT assumed to succeed: a non-null float raises `float_canonicalization_unsupported` and a tz-naive datetime raises `timezone_naive_datetime` (reproduced). D1a preserves these TYPED ERRORS; it never manufactures a successful baseline. A null-typed array is distinguished from an all-null array of an admitted type.

**Stability lock-test + version guard (the "confirm stability" obligation).** The accepted divergence set is a function of the Python runtime Unicode version and the Rust crate's Unicode tables (`unicode-normalization` resolves to 0.1.25 in `Cargo.lock`, which carries Unicode 17.0.0 tables; `Cargo.toml` uses a compatible-range caret, so a `cargo update` could change the tables). Fixed-token tests alone are NOT sufficient: by Unicode's normalization-stability contract, already-assigned characters keep their normalization across versions, so a newer table can change the normalization of NEWLY assigned characters while every fixed-token fixture stays green. D1a therefore pairs two guards: (a) fixed-token tests over a known string set (incl. a normalization-sensitive post-version sequence) that lock customer-visible tokens, AND (b) an explicit dependency/table-version guard that asserts the resolved `unicode-normalization` version (and its Unicode table version), so ANY table-version change triggers review independently of the token tests. Verification and released artifacts build from the locked dependency set. A table-version bump is then a deliberate, reviewed, versioned decision (it changes re-identification output), never silent.

**Pinning + call-site threading (#3).** The companion is loaded ONCE per run at table-prep (`native_keyed_hash` reloads per call at `_kernels_keyed.py:60`, so D1a threads the PRE-LOADED kernel into the per-batch native call, not a bare `native_keyed_hash`). The per-column decision (native / declined+reason) is computed from the companion-load result + the up-front INPUT Arrow type (hash output is always string, so output schema is not evidence of input type) and threaded, immutable, into both drivers' `mask_batch` path. Each native batch VALIDATES its incoming Arrow type against the pinned expectation (and rejects a missing pinned column; `mask_batch` currently skips absent columns silently) and ABORTS the run on mismatch, never switching path mid-column. The LazySource schema/read reopen gap (`profile/_readers.py:211`, which `open_batches` already addresses) is bound so prep-time type matches the streamed type. A mid-run companion fault ABORTS with no Python switch, no returned partial result, and sink abort without commit.

## 4. Caller-visible disposition (folds #4, program §5)
§5 requires each cell {native-admitted + parity + compute-witness} OR {declined with a caller-visible reason}; nothing silently falls back. Codex affirmed D1a need not hard-fail on no-companion.
- `_chunked_evidence` is not a shared publication channel and does not reach the OOC return. D1a adds a concrete **`ExecutionResult.quality_metrics`** entry for OOC hash disposition, keyed by table + column, carrying the per-column executed-backend and (when declined) the reason. The OOC runner returns quality metrics (`_runner.py:271`) and `_pipeline_route_exec.py:422` copies them into the caller result, so no new public result class is needed; thread the entry through BOTH drivers and BOTH resident and sink return paths, asserted THROUGH `run_pipeline`.
- **Truthful executed-backend label.** The OOC Python `hash_array` loop is neither the pandas oracle nor an Arrow-Python kernel; labeling it `PANDAS_ORACLE` (`_operator_registry.py:44`) would misreport. D1a adds a truthful token `PYTHON_SCALAR = "python_scalar"` in `_operator_registry.py` for the OOC Python hash loop; native payload/parent-key hash reports `rust_companion`. A declined cell is never counted native-admitted. The `build_parent_key_relation_aligned` COPY is not a hash invocation and is not recorded as one.
- Reason codes (value-free; strategy, column, Arrow type only; never cell/key/derivation values): `crypto_extension_unavailable`, `hash_input_type_not_native_admitted:{col}:{type}`, `hash_input_type_tz_timestamp_deferred:{col}`, `fk_key_hash_remap_native_deferred:{site}`.

## 5. Behavior-preservation + parity contract
1. **Byte-identical to the canonical result:** for every parity-eligible admitted cell, native output is byte-identical to the Python reference FOR ALL INPUT WITHIN THE SHARED UNICODE VERSION (KAT-pinned crypto; the vast-majority case). For post-Python-version codepoints the native (Rust) result is authoritative per the accepted decision; the divergence from the Python-14 path is a documented, tested characterization, not a parity failure.
2. **Oracle parity:** OOC native hash strict-equal (D0 `_strict_compare`, modulo frozen D0 gaps) to the pandas oracle on a parent-key hash column, an FK-chain payload hash column, and a non-FK payload hash column, for shared-version inputs. The existing D0 baseline fixtures carry no post-version codepoints, so they pass unchanged.
3. **Per-batch == whole-column**, **Never half-native** (decision pinned at prep; mid-run fault aborts), as §3.
4. **No silent fallback (§5):** every `mask_batch` hash column is {native + witness + `rust_companion`} OR {Python + `python_scalar` + a caller-visible reason}. REMAP sites report `fk_key_hash_remap_native_deferred`, unchanged. No capability regression on a no-companion install.
5. **Stability:** the lock-test pins native's normalization output (§3); the native result is deterministic (confirmed in §3).
6. **Witness:** native hash proves native-result-CONSUMED at the insertion boundary (observe the INSERTED object, not merely `mask_column`'s return); declined reports Python-only. No existing test weakened; `hash_array` untouched.
