# GEN-TYPES: the small core generate types a user with no source data needs

Status: plan

Rules consulted: 00-universal, risk-and-exceptions, development-loop, code-review, testing,
architecture, feature-dev, cross-cutting-concerns, api-and-compatibility, exploration, reuse-first,
security, config-secrets-and-supply-chain, documentation, verification, profiles/local-operations,
catalogs/recurring-defects

Base: engine main `4694c91f`. Roadmap row 24q. Engine only; CLI docs and examples follow through
the GEN-CLI catalog (row 24o), which reads the option registry and needs no second list.

**Prerequisites.** Rows 24i and 24j are merged. GEN-STRICT (row 24k) E0 (#425), E1 (#430) and E3
(#424) are merged: the strict per-type option registry `config/_generate_options.py` and its public
view `generate_option_catalog()` (#460) exist on main and this plan extends them in place. GEN-STRICT
E2 (the plan-time wrapper `check_generate_columns`, derived grammar at validate) is unbuilt; slice
E4 here touches the same grammar, so whichever lands second rebases (textual, not semantic, overlap;
see Slices). Line numbers below are from `4694c91f` and will move.

**Guarantee.** A user with no source file can say "this column is a constant", "this column follows
normal(40, 10)", "this column is drawn from my SKU list, weighted by this column", "print this
column as an int / decimal(2) / date / bool", and "derived: if(x > 0, a, b)". Each either produces
exactly that, with the same output for the same seed on every route that admits it, or is refused
with a coded, value-free reason.

**Non-goals:** truncated (resampled) distributions; distributions fitted to data (that is
`statistical`); string functions in `derived` (audit A8's second half; recorded as a follow-up);
`unique` on the new types (A4, row 24m); boolean with a rate, calendar patterns (A6); free text (A7);
the streamed route admitting `lookup`; pinned mode admitting `lookup`; native kernels for the new
types; removing the legacy V1 `strategy: distribution` code in `generators/_distribution.py`.

**Design notes:** three new generate types (`constant`, `distribution`, `lookup`), one new per-column
option (`output_type`), one grammar form (`if(c, a, b)`) plus lazy evaluation of the conditional
nodes. Every new key lives in the one registry (`GENERATE_OPTIONS` / `COMMON_OPTIONS`); the catalog
picks them up with no second list. Generation code goes in a new `generation/types/` sub-package
(generation/ already has 26 direct modules). The emission cast for `output_type` is one function
called from the two Arrow boundaries (resident/pinned `arrow_table`, streamed `_table_batches`).

## Why

The 2026-11-08 generation completeness audit (CLI `docs/records/2026-11-08-generation-completeness-
audit.md`, section A) tested what a user in each industry expects to generate and found the small
core types missing:

- A1: no parametric distributions. `type: normal` and `type: distribution` are refused. A user with
  no data cannot say "age ~ normal(40, 10)"; they must invent a CSV and run `decoy fit`. The
  capability matrix lists a twelfth generation strategy, `distribution`, that the schema refuses.
- A2: no constant. The workaround is a one-category `categorical`.
- A3: no lookup list from a file (ICD-10, product catalog, SKU list). `categories_file` is refused;
  `categories` is inline only.
- A5: no explicit output type. CSV output is all text; fitted numbers print 15 decimals.
- A8: `derived: if(...)` fails at run.

Row 24q bundles these as one engine row. Each is small; together they are what the audit's
priority 2 calls "fill the small core types".

## Behavior

### E1: `constant` and parametric `distribution`

`constant`:

```yaml
- name: country
  type: constant
  value: "US"          # required: str, int, float (finite) or bool
```

Every row gets `value`. The Arrow type follows `_categorical_type`'s rule for one homogeneous
value (`generation/_admission.py:95`): str to string, bool to bool, int to int64, float to float64.
`null_probability` applies as on every type. No random draw: `GEN_KIND_TO_SITE` maps it to
`DETERMINISTIC_NO_DRAW`. Admitted on the streamed route, pinnable.

`distribution`:

```yaml
- name: age
  type: distribution
  family: normal       # required: normal | lognormal | uniform | exponential | poisson | beta | zipf
  mean: 40
  std: 10
  min: 18              # optional clip, every family
  max: 90
```

Per-family parameters (all required for their family, all refused on any other family with
`generate_option_unknown`, the `_fitted_only_str` precedent at `config/_generate_options.py:100`):

| family | keys | numpy call | Arrow type | range rule (`generate_option_range`) |
|---|---|---|---|---|
| normal | `mean`, `std` | `rng.normal(mean, std, n)` | float64 | std > 0 |
| lognormal | `mu`, `sigma` (of the underlying normal) | `rng.lognormal(mu, sigma, n)` | float64 | sigma > 0 |
| uniform | `low`, `high` | `rng.uniform(low, high, n)` | float64 | low < high |
| exponential | `mean` | `rng.exponential(mean, n)` | float64 | mean > 0 |
| poisson | `mean` | `rng.poisson(mean, n)` | int64 | 0 < mean <= 1e9 |
| beta | `alpha`, `beta` | `rng.beta(alpha, beta, n)` | float64 | alpha > 0, beta > 0 |
| zipf | `s`, `n` (support 1..n) | inverse CDF over 1..n with `rng.random(n)` | int64 | s > 0, 1 <= n <= 1,000,000 |

Every number key must be a finite int or float (bool refused); `family` outside the set gets
`generate_option_value_unknown`. `min`/`max` clip with `numpy.clip` after the draw; `min > max`
gets `generate_option_range`; on the int families they must be ints. The generator seeds one
`numpy.random.Generator` per column from `GenDeriveContext.for_column(...).base_int("np")`, the same
derivation `_apply_null_probability` uses (`generation/synthesize.py:505`), so the output depends
on the seed, the table and column identity and the column config only.

Zipf is bounded because numpy's unbounded `zipf` needs s > 1 and returns values up to 2^63; a
"rank among n products" column needs a finite support. The bounded form is the standard finite
Zipf (Zipf-Mandelbrot with q = 0): P(k) proportional to 1 / k^s for k in 1..n, sampled by
`numpy.searchsorted` on the cumulative weights (the same inverse-CDF shape the categorical sampler
uses), computed once per column.

Streamed route: `ParametricStream` holds the one Generator and draws each batch in row order.
NumPy fills an array of n draws element by element from the bit generator, so batches of sizes
k and n - k concatenate to the one-shot draw of n; AT-3 proves this per family under the locked
numpy. Pinnable: the draw depends only on the seed and config.

The capability matrix's `distribution` entry becomes this type; the "legacy entry, not a
streamed-generation promise" note in `scripts/gen_capability_matrix.py:178` is replaced and
`docs/capability-matrix.md` regenerated (sentry `tests/sentry/test_capability_matrix.py`).

The catalog gains family-conditional requirements. `GenerateTypeOptions` (public, #460) gets one
additive field, `required_when: Mapping[str, Mapping[str, tuple[str, ...]]]` (default empty), e.g.
`{"family": {"normal": ("mean", "std"), ...}}`. The existing inline special case in
`option_problems` (reference `distribution: weighted` needs `weights`) moves into the same
`CONDITIONAL_REQUIRED` table, so the catalog shows it too. `closed_key_schema` emits one nested
`if family then required` branch per entry.

### E2: `output_type`

```yaml
- name: price
  type: distribution
  family: lognormal
  mu: 3
  sigma: 0.5
  output_type: decimal(2)    # int | decimal(n), 0 <= n <= 18 | date | bool
```

One registry key, listed in the `keys` of each type that accepts it (so the catalog shows it per
type, not as common):

| type | int | decimal(n) | date | bool |
|---|---|---|---|---|
| constant, categorical, lookup, derived, formula | yes | yes | yes | yes |
| distribution | yes | yes | no | no |
| sequence | yes, only without prefix/suffix/pad_length | yes, same rule | no | no |
| faker | yes | yes | yes | yes |
| grouped_series, derived_aggregate | yes | yes | no | no |
| windowed_date | no | no | yes | no |
| reference, statistical, group_key | not accepted (`generate_option_unknown`) | | | |

`reference` takes its type from the parent; `statistical` already owns its cell format from the
snapshot; `group_key` is a hex key. A known value on a type that cannot carry it gets the new
config code `generate_output_type_unsupported`; an unparseable value (`decimal(x)`, `float`) gets
`generate_option_value_unknown`.

Cast rules (one function, `generation/types/_output_type.py`):

- `int` to int64: Python int as is; float with no fractional part; numeric text matching
  `\A[+-]?\d+\Z`; bool refused. A fractional float is refused, not rounded (the user asked for an
  int; a silent round hides a modelling error). Use `decimal(0)` to round.
- `decimal(n)` to `decimal128(38, n)`: through `decimal.Decimal(str(v))`, quantized with
  `ROUND_HALF_EVEN` (IEEE 754 default, the rounding pyarrow's own decimal cast uses). Over 38
  digits is a cast failure.
- `date` to date32: `datetime.date`, `datetime.datetime` (date part), ISO `YYYY-MM-DD` text.
- `bool` to bool: bool; int 0/1; text `true`/`false`/`1`/`0`, case-insensitive (Faker `pybool`
  gives `True`).
- None stays null.

Where it runs: at the Arrow boundary only, after the formula post-pass and null masking, in
`arrow_table` (`generation/_statistical_column.py:88`, used by the resident route at
`generation/synthesize.py:186` and by pinned execute) and in `_table_batches`
(`generation/_streamed.py:281`, after `restore_declared` at line 298). Same-table readers
(`derived`, `formula`) keep seeing the generator's values, as today; the declared type is an output
contract, not a change to what siblings read. `numeric_plan` / `planned()`
(`generation/_numeric_typing.py:246`) and the admission schema return the declared Arrow type for
a column with `output_type`, so the streamed schema and the resident table agree.

A value that cannot be cast fails the run with runtime code `output_type_cast_failed`, naming the
table, column and target type, never the value or the row's other cells.

Cross-table references read the parent's emitted values, so a child FK into a declared-int parent
carries ints. AT-9 checks this on every route that admits `reference`.

### E3: `lookup` (weighted list from a file or a shipped code set)

```yaml
- name: sku
  type: lookup
  file: data/skus.csv          # or: codeset: icd10   (exactly one of file, codeset)
  value_column: sku            # default: first column for a file, `code` for a codeset
  weight_column: units_sold    # optional
```

A new type, not `categories_file` on `categorical` (see Owner questions Q2). Compile reads the file
once, the way `read_and_pin_snapshots` reads snapshots (`plan/_generation.py:148`):
`fileaccess.config_relative(path, base_dir)`, one read under a new `FileRole.LOOKUP`, the 16 MiB
embedded-artifact cap (`EMBEDDED_SNAPSHOT_MAX_BYTES`, line 47), a sha256 digest, and the bytes
pinned in `GenerationPlan` (`plan/_types.py:410`) under a new `lookups` field keyed by the
declared string. A replay of the plan uses the pinned bytes, never the disk.

Formats by extension: `.csv` through the engine's one CSV reader (`profile/_csv_reader.py`, the
only `csv.reader` caller allowed by `tests/sentry/test_csv_scan_single_copy.py`), header row
required; `.parquet` through the arrow adapter. Anything else gets `lookup_file_format_unsupported`.
`codeset:` names a shipped corpus from `CODESET_REGISTRY` (icd10, hcpcs, mcc, ndc) and loads it with
`transforms._codeset_loader.load_corpus`; no file read, no digest needed beyond the shipped one.

Values are text (CSV cells) or the Parquet column's scalar type; `output_type` casts them. The
weight column must hold finite numbers >= 0 with a positive sum (`_weight_ok`'s rule,
`config/_generate_options.py:176`, reused); a blank weight cell is a refusal, not zero. Duplicate
values are kept as separate entries (their weights add), which is what a weighted SKU list with
repeated SKUs means. Row cap 1,000,000 entries.

Sampling reuses the categorical sampler (same `random.Random` stream shape as `CategoricalStream`,
`generation/_column_streams.py:134`), so a lookup over a file with values [a, b] and weights [1, 3]
gives byte-identical output to `categorical` with the same lists and seed. The seed fingerprint
replaces `file` with its content digest, the `snapshot_file` precedent
(`generators/derivation.py:105`, `_SNAPSHOT_FILE_KEY`): moving the file keeps output, editing it
changes output.

Refusals (plan namespace, compile time, value-free: they name the column, the role and a count,
never a cell or the path beyond `fileaccess.shown`): `lookup_file_unreadable`,
`lookup_file_too_large`, `lookup_file_format_unsupported`, `lookup_column_missing`,
`lookup_file_empty`, `lookup_weight_invalid`, `lookup_too_many_entries`. Config time:
exactly one of `file`/`codeset` (missing or both: `generate_option_value_unknown` on the second,
`missing` on neither); unknown codeset name: `generate_option_value_unknown`.

Streamed route: declined (`ADMISSION_MATRIX` entry `(False, "file-backed lookup; resident only in
this row")`). Pinned mode: `REJECTED_TYPES["lookup"] = ("pinned_lookup_unsupported", ...)`.
`unique: true` is refused by `unique_type_problems` (`config/_generate_unique.py:81`) because
`lookup` is not in `UNIQUE_TYPES`.

### E4: `if(c, a, b)` in `derived`, and lazy conditionals

Grammar (`expressions/grammar.lark`): one new primary,
`"if" "(" expr "," expr "," expr ")" -> if_op`, evaluated exactly like the existing ternary
`a if c else b` (line 34). No ambiguity with the ternary: the function form needs two commas inside
the parentheses, the ternary needs `else`; AT-12 parses both shapes and the mixed nesting.

Lazy evaluation: today `_ExprTransformer` (`expressions/_lark_parser.py:243`) is a bottom-up
`lark.Transformer`, so every branch of a ternary or `case_when` is evaluated before the choice and
`if(a == 0, 0, 100 // a)` raises on a = 0. The docstrings at `ternary` (line 265) and
`case_when_op` (line 402) record this as known. E4 evaluates `ternary`, `if_op`, `case_when_op`,
`or_expr` and `and_expr` top-down: a small `lark.visitors.Interpreter` subclass visits the
condition first and only the chosen branch, and hands every other node to the existing transformer
methods unchanged. Rows that evaluated before evaluate to the same value (AT-14 replays the derived
corpus byte for byte); rows that raised only because of an unchosen branch now evaluate.

The evaluator is shared with mask-side `derived` / `case_when` (`transforms/derived.py`), so the
change applies there too. That is the intended reading of a conditional; a split evaluator would be
a second copy of the grammar's semantics. Recorded as `Changed` in the changelog fragment.

Validate-time grammar refusal (an unparseable `if(` with two arguments) stays GEN-STRICT E2's job;
until E2 lands it fails at run as every bad expression does today
(`plan/_checks.py:581` skips syntax errors).

## Enumerations

### Exit paths

- Config refusal from `option_problems` via `_options_valid` (`config/_tables.py:305`): new types'
  keys, families, ranges, `output_type` values, `file`/`codeset` exclusivity.
- Config refusal `generate_output_type_unsupported` from the same validator (E2).
- Compile refusal from the lookup pin pass inside `pin_and_check_snapshots`
  (`plan/_generation.py:426`), which `compile_plan` and `run_config_only_checks` both call: the
  seven `lookup_*` codes.
- Pinned compile refusal `pinned_lookup_unsupported` (`generation/_pinned_compile.py:52`).
- Streamed admission decline for `lookup` (falls back to the resident route, as `formula` does).
- Run failure `output_type_cast_failed` (E2) and the existing `derived_evaluation_failed` (E4: now
  raised only by the chosen branch).

### Routes

- Resident: `_generate_column` dispatch (`generation/synthesize.py:280`), then `arrow_table`.
- Streamed: `make_column_stream` (`generation/_column_streams.py:249`), then `_table_batches`
  (`generation/_streamed.py:281`).
- Pinned: `PINNABLE_TYPES` (`generation/_pinned_compile.py:38`), pinned execute, `arrow_table`.
- Mask-side expressions: `transforms/derived.py` through `expressions.evaluate`
  (`expressions/_lark_parser.py:217`), E4 only.

### FK shapes

- A child `reference` into a parent column of a new type: the pool is the parent's emitted values,
  so it carries the declared or inferred Arrow type (AT-9).
- A new-type column as a child FK: N/A because none of the new types reads another table; a column
  that must point at a parent stays `type: reference`.

### Fields

- `constant`: `value`.
- `distribution`: `family`, `mean`, `std`, `mu`, `sigma`, `low`, `high`, `alpha`, `beta`, `s`, `n`,
  `min`, `max`.
- `lookup`: `file`, `codeset`, `value_column`, `weight_column`.
- `output_type` on the types in the E2 table.
- `GenerateTypeOptions.required_when` (public, defaulted); `GenerationPlan.lookups` (internal plan
  field).

### Output surfaces

## Engineering calls made

- One registry: every new key in `GENERATE_OPTIONS`; family and file/codeset rules in one
  `CONDITIONAL_REQUIRED` table that the reference weighted rule also moves into. No second list.
- `distribution` uses flat keys plus `family`, matching every other type's flat options, rather
  than a nested `params:` mapping the registry cannot check per key.
- Clip, not truncate, for `min`/`max`: clipping keeps one draw per row and so keeps streamed
  prefix stability; truncation by resampling does not. Truncation is a follow-up if asked for.
- Zipf requires `n` (bounded support); see Q4.
- `output_type` casts at emission only; siblings read generator values. A cast before the formula
  pass would give `derived` Decimal values that do not mix with floats.
- A fractional float to `int` is refused, not rounded.
- `lookup` declines the streamed route and pinned mode in this row: the pinned bytes would need a
  pinned-plan carrier and the streamed route a resident list per stream; both are follow-ups with
  no user waiting on them.
- New `FileRole.LOOKUP` rather than reusing `REFERENCE` or `CORPUS`: those carry other policy
  (bundled Parquet tables, code-set corpora); a strict policy can allow lookup files on their own.
- Lazy conditionals apply on mask and generate sides alike (one evaluator).

## Owner questions

Recommended answer first.

1. **Parameter names for `distribution`.** Recommend the table above: `mean`/`std` for normal,
   `mu`/`sigma` of the underlying normal for lognormal (numpy and SciPy convention), `low`/`high`,
   `mean` for exponential and poisson, `alpha`/`beta`, `s`/`n`. Alternative: lognormal by
   `median` and geometric std, which business users find easier but which no library uses.
2. **Lookup as a new type or as `categories_file` on `categorical`.** Recommend a new `lookup`
   type: it has its own keys (`value_column`, `weight_column`, `codeset`), its own refusals and
   route limits, and `categorical` keeps an inline-only contract. Alternative: `categories_file`
   on `categorical`, which matches the audit's tested spelling but makes `categories` conditionally
   required and puts file I/O behind an existing type.
3. **Lookup sources in this row.** Recommend CSV, Parquet and the four shipped code sets
   (`codeset: icd10`), since the code-set loader exists and ICD-10 is the audit's first example.
   Alternative: files only, code sets later.
4. **Zipf support.** Recommend bounded only (`n` required, s > 0): a rank column needs a finite
   range and numpy's unbounded form returns values up to 2^63. Alternative: `n` optional, unbounded
   when absent (requires s > 1).
5. **`decimal(n)` rounding.** Recommend round half even (IEEE 754 and Arrow default; no bias over
   many rows). Alternative: round half up, which matches spreadsheet habit.
6. **E4 on the mask side.** Recommend yes (one evaluator; only rows that raised change).
   Alternative: keep mask-side eager, which needs a second evaluator path and a flag.
