# GEN-TYPES: the small core generate types a user with no source data needs

Status: plan

Rules consulted: 00-universal, risk-and-exceptions, development-loop, code-review, testing,
architecture, feature-dev, cross-cutting-concerns, api-and-compatibility, exploration, reuse-first,
security, config-secrets-and-supply-chain, documentation, verification, profiles/local-operations,
catalogs/recurring-defects

Base: engine main `2aec8be8` (revised after review round 1; first draft on `4694c91f`). Roadmap row 24q. Engine only; CLI docs and examples follow through
the GEN-CLI catalog (row 24o), which reads the option registry and needs no second list.

**Prerequisites.** Rows 24i and 24j are merged. GEN-STRICT (row 24k) E0 (#425), E1 (#430) and E3
(#424) are merged: the strict per-type option registry `config/_generate_options.py` and its public
view `generate_option_catalog()` (#460) exist on main and this plan extends them in place. GEN-STRICT
E2 (the plan-time wrapper `check_generate_columns`, derived grammar at validate) is unbuilt; slice
E4 here touches the same grammar, so whichever lands second rebases (textual, not semantic, overlap;
see Slices). Line numbers below are from `2aec8be8` and will move.

**Guarantee.** A user with no source file can say "this column is a constant", "this column follows
normal(40, 10)", "this column is drawn from my SKU list, weighted by this column", "print this
column as an int / decimal(2) / date / bool", and "derived: if(x > 0, a, b)". Each either produces
exactly that, with the same output for the same seed on every route that admits it, or is refused
with a coded, value-free reason.

**Non-goals:** truncated (resampled) distributions; distributions fitted to data (that is
`statistical`); string functions in `derived` (audit A8's second half; recorded as a follow-up);
`unique` on the new types (A4, row 24m); boolean with a rate, calendar patterns (A6); free text (A7);
the streamed route admitting `lookup`; pinned mode admitting `lookup`; native kernels for the new
types; removing the legacy V1 `strategy: distribution` code in `generators/_distribution.py`.

**Design notes:** three new generate types (`constant`, `distribution`, `lookup`), one new per-column
option (`output_type`), one grammar form (`if(c, a, b)`) plus lazy evaluation of the conditional
nodes. Every new key lives in the one registry (`GENERATE_OPTIONS` / `COMMON_OPTIONS`); the catalog
picks them up with no second list, and the per-family allowed keys are derived from the one
`CONDITIONAL_REQUIRED` table. Generation code goes in a new `generation/kinds/` sub-package
(generation/ already has 25 direct modules; `kinds`, not `types`, so it never shadows the stdlib
module). `output_type` compiles to an existing declared-casting format descriptor (F06,
`declared_casting/_catalog.py`); the emission cast is one function called from the two Arrow
boundaries (resident/pinned `arrow_table`, streamed `_table_batches`). Lookup files are pinned by
the same read helper, the same pinned-artifact record and the same digest-verified serializer as
statistical snapshots, and fingerprinted through one key-to-digest map.

## Why

The 2026-11-08 generation completeness audit (CLI `docs/records/2026-11-08-generation-completeness-
audit.md`, section A) tested what a user in each industry expects to generate and found the small
core types missing:

- A1: no parametric distributions. `type: normal` and `type: distribution` are refused. A user with
  no data cannot say "age ~ normal(40, 10)"; they must invent a CSV and run `decoy fit`. The
  capability matrix lists a twelfth generation strategy, `distribution`, that the schema refuses.
- A2: no constant. The workaround is a one-category `categorical`.
- A3: no lookup list from a file (ICD-10, product catalog, SKU list). `categories_file` is refused;
  `categories` is inline only.
- A5: no explicit output type. CSV output is all text; fitted numbers print 15 decimals.
- A8: `derived: if(...)` fails at run.

Row 24q bundles these as one engine row. Each is small; together they are what the audit's
priority 2 calls "fill the small core types".

## Behavior

### E1: `constant` and parametric `distribution`

`constant`:

```yaml
- name: country
  type: constant
  value: "US"          # required: str, int, float (finite) or bool
```

Every row gets `value`. The Arrow type follows `_categorical_type`'s rule for one homogeneous
value (`generation/_admission.py:95`): str to string, bool to bool, int to int64, float to float64.
`null_probability` applies as on every type. No random draw: `GEN_KIND_TO_SITE` maps it to
`DETERMINISTIC_NO_DRAW`. Admitted on the streamed route, pinnable.

`distribution`:

```yaml
- name: age
  type: distribution
  family: normal       # required: normal | lognormal | uniform | exponential | poisson | beta | zipf
  mean: 40
  std: 10
  min: 18              # optional clip, every family
  max: 90
```

Per-family parameters (all required for their family, all refused on any other family with
`generate_option_unknown`). One table drives both rules: the `CONDITIONAL_REQUIRED` entry for
`family` lists each family's required keys, and the keys a family allows are that list plus `min`
and `max`. `option_problems` derives the refusal from it (a family key not in the chosen family's
allowed set is `generate_option_unknown`), the catalog's `required_when` reads it, and
`closed_key_schema` builds its branches from it. There is no per-key family check beside it (no
`_fitted_only_str`-style callable per key, `config/_generate_options.py:100`), so `mean`, shared
by normal, exponential and poisson, is listed once per family in one place:

| family | keys | numpy call | Arrow type | range rule (`generate_option_range`) |
|---|---|---|---|---|
| normal | `mean`, `std` | `rng.normal(mean, std, n)` | float64 | std > 0 |
| lognormal | `mu`, `sigma` (of the underlying normal) | `rng.lognormal(mu, sigma, n)` | float64 | sigma > 0 |
| uniform | `low`, `high` | `rng.uniform(low, high, n)` | float64 | low < high |
| exponential | `mean` | `rng.exponential(mean, n)` | float64 | mean > 0 |
| poisson | `mean` | `rng.poisson(mean, n)` | int64 | 0 < mean <= 1e9 |
| beta | `alpha`, `beta` | `rng.beta(alpha, beta, n)` | float64 | alpha > 0, beta > 0 |
| zipf | `s`, `n` (support 1..n) | inverse CDF over 1..n with `rng.random(n)` | int64 | s > 0, 1 <= n <= 1,000,000 |

Every number key must be a finite int or float (bool refused); `family` outside the set gets
`generate_option_value_unknown`. `min`/`max` clip with `numpy.clip` after the draw; `min > max`
gets `generate_option_range`; on the int families they must be ints. The generator seeds one
`numpy.random.Generator` per column from `GenDeriveContext.for_column(...).base_int("dist")`, a new
sixth RNG family added to `GEN_FAMILIES` (`generators/derivation.py:191`). It must not use `"np"`:
the null mask already draws `default_rng(base_int("np")).random(n)` on the same column
(`generation/synthesize.py:540`, streamed `generation/_column_streams.py:225`), and
`null_probability` is excluded from the fingerprint (`generators/derivation.py:52`), so a shared
family would make the mask and the draw read the same uniforms. For `uniform` the nulls would be
exactly the rows below `low + p * (high - low)`. Zipf's `rng.random(n)` uses the same `"dist"`
Generator. The output depends on the seed, the table and column identity and the column config
only. Adding a family label gives it a disjoint HMAC sub-key and moves no existing family's
value; the native draw-site catalogue and `_determinism_protocol.py` gain the label.

Zipf is bounded because numpy's unbounded `zipf` needs s > 1 and returns values up to 2^63; a
"rank among n products" column needs a finite support. The bounded form is the standard finite
Zipf (Zipf-Mandelbrot with q = 0): P(k) proportional to 1 / k^s for k in 1..n, sampled by
`numpy.searchsorted` on the cumulative weights (the same inverse-CDF shape the categorical sampler
uses), computed once per column.

Streamed route: `ParametricStream` holds the one Generator and draws each batch in row order.
NumPy fills an array of n draws element by element from the bit generator, so batches of sizes
k and n - k concatenate to the one-shot draw of n. A probe under numpy 2.2.6 (one of the three
`uv.lock` bands; 2.4.6 and 2.5.0 not probed) confirmed this for all six numpy families and
`random()` at batch sizes 1, 7 and 1000 over 2,000 draws; AT-3 proves it per family under every
locked numpy. Pinnable: the draw depends only on the seed and config.

The capability matrix's `distribution` entry becomes this type; the "legacy entry, not a
streamed-generation promise" note in `scripts/gen_capability_matrix.py:178` is replaced and
`docs/capability-matrix.md` regenerated (sentry `tests/sentry/test_capability_matrix.py`).

The catalog gains family-conditional requirements. `GenerateTypeOptions` (public, #460) gets one
additive field, `required_when: Mapping[str, Mapping[str, tuple[str, ...]]]` (default empty), e.g.
`{"family": {"normal": ("mean", "std"), ...}}`. The existing inline special case in
`option_problems` (reference `distribution: weighted` needs `weights`) moves into the same
`CONDITIONAL_REQUIRED` table, so the catalog shows it too. `closed_key_schema` emits one nested
`if family then required` branch per entry, plus the derived `not` branch for keys outside the
chosen family's allowed set, so the JSON schema and `option_problems` refuse the same key.

### E2: `output_type`

```yaml
- name: price
  type: distribution
  family: lognormal
  mu: 3
  sigma: 0.5
  output_type: decimal(2)    # int | decimal(n), 0 <= n <= 18 | date | bool
```

One registry key, listed in the `keys` of each type that accepts it (so the catalog shows it per
type, not as common):

| type | int | decimal(n) | date | bool |
|---|---|---|---|---|
| constant, categorical, lookup, derived, formula | yes | yes | yes | yes |
| distribution | yes | yes | no | no |
| sequence | yes, only without prefix/suffix/pad_length | yes, same rule | no | no |
| faker | yes | yes | yes | yes |
| grouped_series, derived_aggregate | yes | yes | no | no |
| windowed_date | no | no | yes | no |
| reference, statistical, group_key | not accepted (`generate_option_unknown`) | | | |

`reference` takes its type from the parent; `statistical` already owns its cell format from the
snapshot; `group_key` is a hex key. A known value on a type that cannot carry it gets the new
config code `generate_output_type_unsupported`; an unparseable value (`decimal(x)`, `float`) gets
`generate_option_value_unknown`.

Cast rules. `output_type` is not a second format registry: it compiles once, at config
validation, to a parse spec of the F06 declared-casting catalog (`declared_casting/_catalog.py`,
"the only format descriptor registry", CODEMAP declared-casting row), and the cast runs that
descriptor's kernel through `parse_value` (`_catalog.py:433`):

| `output_type` | declared-casting parse spec | Arrow type |
|---|---|---|
| `int` | `{"id": "integer/ascii/v1", "signed": true, "bit_width": 64}` | int64 |
| `decimal(n)` | `{"id": "decimal/plain/v1", "precision": 38, "scale": n}` | `decimal128(38, n)` |
| `date` | `{"id": "date/iso8601/v1"}` | date32 |
| `bool` | `{"id": "boolean/text/v1"}` (new descriptor, below) | bool |

The Arrow type comes from the same mapping `declared_casting/_boundary.py:60` `arrow_type` uses:
its body moves into `arrow_type_for_spec(parse_format)` in the same module, which `arrow_type` and
the generate cast both call, plus one `boolean` branch. Bounds and rounding are the kernels': the
int64 range from `int_bounds` (`_numeric.py:81`), decimal precision overflow from `_from_parts`
(`_numeric.py:137`), ISO date shape from `parse_date` (`_date.py:34`).

What generation adds is only the step from a generated Python value to the kernel's input text,
`to_lexeme(value, spec)` in `generation/kinds/_output_type.py`:

- int target: Python int as `str(v)`; float with no fractional part as `str(int(v))`; text passed
  as is (the kernel's `[+-]?[0-9]+` decides); bool refused. A fractional float is refused, not
  rounded (the user asked for an int; a silent round hides a modelling error). Use `decimal(0)` to
  round.
- decimal target: int, float (through `Decimal(repr(v))`), `Decimal`, or plain numeric text, then
  `round_to_scale(d, n)`, a new function in `declared_casting/_numeric.py` beside `_PINNED`, so the
  one decimal module owns the one rounding rule (`ROUND_HALF_EVEN`, the mode `_PINNED` names at
  `_numeric.py:33`). The kernel itself still refuses scale loss, so the rounding is explicit and in
  one place. NaN and infinity are refused.
- date target: `datetime.date` and `datetime.datetime` (date part) as `isoformat()`; ISO text as is.
- bool target: bool as `true`/`false`; int 0/1 as `0`/`1`; text as is.
- None stays null and never reaches a kernel.

`boolean/text/v1` is the one descriptor this row adds to the catalog: a `BooleanText` model in
`contracts/_declared_formats.py` (logical `boolean`), parse kernel accepting `true`/`false`/`1`/`0`
case-insensitive (Faker `pybool` gives `True`), output kernel `true`/`false`, registered vectors,
both directions so the catalog's exact-inverse check holds. It is not added to F06's
`_LOGICAL_FOR` (`contracts/declared_casting.py:118`): declared source columns do not gain a
boolean type in this row (recorded in V2/deferred).

Where it runs: at the Arrow boundary only, after the formula post-pass and null masking, in
`arrow_table` (`generation/_statistical_column.py:88`, used by the resident route at
`generation/synthesize.py:186` and by pinned execute) and in `_table_batches`
(`generation/_streamed.py:281`, after `restore_declared` at line 298). Same-table readers
(`derived`, `formula`) keep seeing the generator's values, as today; the declared type is an output
contract, not a change to what siblings read. `numeric_plan` / `planned()`
(`generation/_numeric_typing.py:246`) and the admission schema return the declared Arrow type for
a column with `output_type`, so the streamed schema and the resident table agree.

A value that cannot be cast fails the run with runtime code `output_type_cast_failed`, naming the
table, column, target type and the kernel's declared-casting reason code (for example
`declared_decimal_overflow`), never the value or the row's other cells.

Seed: `output_type` joins `_EXCLUDED_FROM_FINGERPRINT` (`generators/derivation.py:52`), like
`null_probability` and `unique`. It changes how a value is printed, not which value is drawn, so
adding it to a column must not re-seed the column. AT-17 checks the values before the cast are
equal with and without it.

Sinks: CSV and Parquet carry int64, `decimal128`, date32 and bool natively. The fixed-width writer
takes only `str`, `int` and `float` layout types (`config/_fixed_width.py:89`) and refuses a
`Decimal`, a `date` or a `bool` cell (`profile/_fixed_width_writer.py:75`). E2 therefore refuses a
fixed-width target whose layout carries a column with `output_type` `decimal(n)`, `date` or `bool`,
at plan compile, with `generate_output_type_unsupported` at the target column's location. The
engine has no database sink (`connectors/` holds object stores and SFTP only); CLI-side database
delivery reads the Arrow types and is the GEN-CLI row's concern.

Cross-table references read the parent's emitted values, so a child FK into a declared-int parent
carries ints. AT-9 checks this on every route that admits `reference`.

### E3: `lookup` (weighted list from a file or a shipped code set)

```yaml
- name: sku
  type: lookup
  file: data/skus.csv          # or: codeset: icd10   (exactly one of file, codeset)
  value_column: sku            # default: first column for a file, `code` for a codeset
  weight_column: units_sold    # optional
```

A new type, not `categories_file` on `categorical` (Owner decision 2). There is one compile-time
pin path for file-valued generate keys, not a second loop beside the snapshot one:

- Read. The body of the read loop in `read_and_pin_snapshots` (`plan/_generation.py:148`) moves
  into `read_pinned_artifact(role, declared, field_key, base_dir, cap, codes)` in the same module:
  `fileaccess.config_relative`, one `fileaccess.read_all` under `role`, the strict/ambient failure
  split recorded after the handler closes, the cap, and the sha256. `codes` is a small frozen
  record naming the unreadable and too-large reason codes, so snapshots keep
  `statistical_snapshot_unreadable` / `dp_snapshot_embedded_artifact_too_large` and lookups get
  `lookup_file_unreadable` / `lookup_file_too_large`. `read_and_pin_snapshots` calls it and then
  parses JSON as today; the lookup pass calls it with `FileRole.LOOKUP` and the 16 MiB
  `EMBEDDED_SNAPSHOT_MAX_BYTES` cap (line 47) and then parses the table.
- Carry. `GenerationPlan` (`plan/_types.py:410`) gains `lookups: tuple[PinnedSnapshot, ...]`,
  reusing the `PinnedSnapshot` record (`plan/_types.py:368`; `release_id` is `None`) keyed by the
  declared string in `source_path`, which stays diagnostic only.
- Serialize. `_pinned_snapshot_from_dict` (`plan/_serialize.py:296`) splits: its sha256 re-check of
  `payload_b64` (lines 317 to 334) becomes `_verified_pinned_bytes(data, position, code)`, which the
  snapshot reader and a new `_pinned_lookup_from_dict` both call before parsing. A lookup whose
  recomputed digest disagrees is refused with `lookup_pinned_digest_mismatch` at
  `generation.lookups[<index>]`. The same `to_dict` writer serves both tuples.
- Thread. Execution builds `lookup_lists: dict[(table, column), LookupList]` from the plan the way
  it builds `statistical_specs`, and passes it on the same carrier: the `legacy_kwargs` of the
  prepared plan entry (`generation/_plan_entry.py:71`) into `_generate_tables_from_config`
  (`generation/synthesize.py:79`) and on to `_generate_column` (`:166`, `:280`). The resident
  generator reads only this mapping, never `file`.

A replay of the plan uses the pinned bytes, never the disk.

Formats by extension: `.csv` through the engine's one CSV reader. `read_csv_source`
(`profile/_csv_reader.py:492`) opens a path itself, so E3 adds a bytes entry beside it in the same
module: `read_csv_bytes(raw, *, table)`, which feeds the existing `_read_csv_rows` scan and parse
(`:235`) an open callable over `io.BytesIO(raw)` instead of a file handle, with one fixed lookup
dialect (comma delimiter, header row required, the reader's `utf-8-sig` decode at `:245`) and
`dtype=str`. Its `PipelineValidationError` codes (`source_*`) are mapped to `lookup_file_unreadable`
by the lookup pass, which catches only that class and raises after the handler closes. No new
`csv.reader` caller is added (`tests/sentry/test_csv_scan_single_copy.py` stays green unchanged).
`.parquet` through `pyarrow.parquet.read_table(pa.BufferReader(raw))`. Anything else gets
`lookup_file_format_unsupported`. AT-10 counts disk opens of the lookup path across compile and
run: exactly 1.
`codeset:` names a shipped corpus from `CODESET_REGISTRY` (icd10, hcpcs, mcc, ndc) and loads it with
`transforms._codeset_loader.load_corpus`; no file read, no digest needed beyond the shipped one.

Values are text (CSV cells) or the Parquet column's scalar type; `output_type` casts them. The
weight column must hold finite numbers >= 0 with a positive sum (`_weight_ok`'s rule,
`config/_generate_options.py:176`, reused); a blank weight cell is a refusal, not zero. Duplicate
values are kept as separate entries (their weights add), which is what a weighted SKU list with
repeated SKUs means. Row cap 1,000,000 entries.

Sampling reuses the categorical sampler (same `random.Random(...).choices` call shape as
`CategoricalStream`, `generation/_column_streams.py:134`). The column seed differs from a
`categorical` column with the same lists, because the fingerprint holds `type` and the keys, so
AT-16 asserts equality at the sampler: the same values, weights and one shared `random.Random`
seed give the same draws through both. It does not claim the two columns' outputs are
byte-identical.

Fingerprint. `strategy_config_fingerprint` (`generators/derivation.py:142`) today special-cases one
key, `snapshot_file`, with a `snapshot_content_digest` argument and a disk-read fallback under
`FileRole.SNAPSHOT` (`:115` to `:140`, `:172` to `:178`). E3 replaces that with one small registry
`FILE_VALUED_KEYS = {"snapshot_file": (FileRole.SNAPSHOT, fallback allowed), "file": (FileRole.LOOKUP,
no fallback)}` and one argument `content_digests: Mapping[str, str]` (key to `"sha256:<hex>"`). The
payload replaces each file-valued key with its digest from the map. `snapshot_file` keeps today's
standalone disk-read fallback for callers with no plan. A lookup `file` with no digest in the map
raises (fail closed): the fingerprint never reads a lookup file from disk. The five existing
call sites of `snapshot_content_digest=` (`_statistical_column.py:83`, `_synthesize_derived.py:145`,
`synthesize.py:374`, `:537`, `window.py:206`) move to `content_digests={"snapshot_file": d}`
(pre-GA, hard rename). Moving the lookup file keeps output, editing it changes output.

Refusals (plan namespace, compile time, value-free: they name the column, the role and a count,
never a cell or the path beyond `fileaccess.shown`): `lookup_file_unreadable`,
`lookup_file_too_large`, `lookup_file_format_unsupported`, `lookup_column_missing`,
`lookup_file_empty`, `lookup_weight_invalid`, `lookup_too_many_entries`, and on plan load
`lookup_pinned_digest_mismatch`. Config time:
exactly one of `file`/`codeset` (missing or both: `generate_option_value_unknown` on the second,
`missing` on neither); unknown codeset name: `generate_option_value_unknown`.

Streamed route: declined (`ADMISSION_MATRIX` entry `(False, "file-backed lookup; resident only in
this row")`). Pinned mode: `REJECTED_TYPES["lookup"] = ("pinned_lookup_unsupported", ...)`.
`unique: true` is refused by `unique_type_problems` (`config/_generate_unique.py:81`) because
`lookup` is not in `UNIQUE_TYPES`.

### E4: `if(c, a, b)` in `derived`, and lazy conditionals

Grammar (`expressions/grammar.lark`): one new primary,
`"if" "(" expr "," expr "," expr ")" -> if_op`. No ambiguity with the ternary
`a if c else b` (line 34): the function form needs two commas inside the parentheses, the ternary
needs `else`. A probe against the locked lark 1.3.1 (Earley, `ambiguity="resolve"`,
`expressions/_lark_parser.py:46`) parsed `if(x > 0, a, b)`, `if (c, a, b)`,
`if(c, a if d else e, b)` and `x if if(c, a, b) else y` to the expected `if_op` / `ternary` nodes,
kept `iffy + 1` a column reference, and refused `if(c, a)` with `UnexpectedCharacters`; AT-12 pins
these.

`if_op` never reaches a consumer. `compile_expr` (`expressions/_lark_parser.py:74`) rewrites each
`if_op(c, a, b)` subtree into the existing `ternary(a, c, b)` node (children reordered to the
ternary's `(then, cond, else)` order) right after `_PARSER.parse` (`:137`). Every reader of the
tree then sees one conditional node kind: the evaluator, `_get_column_refs`
(`transforms/derived.py`, used by `plan/_checks.py:654`), the numeric typing of derived columns
(`generation/_numeric_derived.py:89` and `:117` know `ternary` and return `_UNK` for anything
else, so an unrewritten `if_op` would print a numeric `derived` column as text), and the lazy
interpreter below. AT-18 checks `derived_uses_as_numbers` is the same for `if(c, a, b)` and
`a if c else b`.

Lazy evaluation: today `_ExprTransformer` (`expressions/_lark_parser.py:243`) is a bottom-up
`lark.Transformer`, so every branch of a ternary or `case_when` is evaluated before the choice and
`if(a == 0, 0, 100 // a)` raises on a = 0. The docstrings at `ternary` (line 265) and
`case_when_op` (line 402) record this as known. E4 evaluates `ternary` (which now also carries every `if(...)`), `case_when_op`,
`or_expr` and `and_expr` top-down: a small `lark.visitors.Interpreter` subclass visits the
condition first and only the chosen branch, and hands every other node to the existing transformer
methods unchanged. Rows that evaluated before evaluate to the same value (AT-14 replays the derived
corpus byte for byte); rows that raised only because of an unchosen branch now evaluate.

The evaluator is shared with mask-side `derived` / `case_when` (`transforms/derived.py`), so the
change applies there too. That is the intended reading of a conditional; a split evaluator would be
a second copy of the grammar's semantics. Recorded as `Changed` in the changelog fragment.

Validate-time grammar refusal (an unparseable `if(` with two arguments) stays GEN-STRICT E2's job;
until E2 lands it fails at run as every bad expression does today
(`plan/_checks.py:653` skips syntax errors).

Lazy evaluation means a typo'd column name inside an unchosen branch no longer raises at run.
That is acceptable because the compile-time column-reference check
(`check_derived_column_refs`, `plan/_checks.py:580`) walks the whole tree, both branches, and
refuses a missing reference before any row is evaluated.

## Pre-mortem (failure modes)

| # | Failure | Where it would bite | Guard |
|---|---|---|---|
| P1 | numpy changes a distribution's stream between versions (NEP 19 does not promise stream stability for `Generator` methods) | goldens differ on another numpy | goldens pinned under the locked numpy per Python band, the gen-num-shape precedent; AT-4 is a golden, AT-3 is a structural prefix test that holds on any numpy |
| P2 | a batch boundary changes streamed output | streamed vs resident differ | AT-3 batches at 1, 7 and 1000 per family; AT-5 route parity |
| P3 | `output_type` cast runs on one route and not another | CSV shows `12.3` resident and `12.30` streamed | one cast function, two call sites; AT-8 removes each call and must go red |
| P4 | `planned()` disagrees with the emitted type | streamed `pa.array(values, type=field_.type)` raises | AT-7 on every type x output_type cell that the table allows |
| P5 | a lookup file changes between compile and run | output from a file nobody validated | bytes pinned at compile, run reads the plan only; AT-10 swaps the file after compile |
| P6 | a lookup refusal quotes a cell value or a full path | data in logs | value-free text from the reason registry; AT-11 hostile corpus with a sentinel value in every cell |

## Engineering calls made

- One registry: every new key in `GENERATE_OPTIONS`; family and file/codeset rules in one
  `CONDITIONAL_REQUIRED` table that the reference weighted rule also moves into, and from which
  each family's allowed keys are derived. No second list.
- One format registry: `output_type` names F06 catalog descriptors; generation owns only the
  value-to-lexeme step.
- One pin path: lookups share the snapshot read helper, record, digest check and fingerprint map.
- Distribution draws get their own RNG family so they never share uniforms with the null mask.
- `distribution` uses flat keys plus `family`, matching every other type's flat options, rather
  than a nested `params:` mapping the registry cannot check per key.
- Clip, not truncate, for `min`/`max`: clipping keeps one draw per row and so keeps streamed
  prefix stability; truncation by resampling does not. Truncation is a follow-up if asked for.
- Zipf requires `n` (bounded support); see Owner decision 4.
- `output_type` casts at emission only; siblings read generator values. A cast before the formula
  pass would give `derived` Decimal values that do not mix with floats.
- A fractional float to `int` is refused, not rounded.
- `lookup` declines the streamed route and pinned mode in this row: the pinned bytes would need a
  pinned-plan carrier and the streamed route a resident list per stream; both are follow-ups with
  no user waiting on them.
- New `FileRole.LOOKUP` rather than reusing `REFERENCE` or `CORPUS`: those carry other policy
  (bundled Parquet tables, code-set corpora); a strict policy can allow lookup files on their own.
- Lazy conditionals apply on mask and generate sides alike (one evaluator).
- `if(...)` is sugar for the ternary, rewritten at compile, so no reader learns a new node kind.

## Owner decisions

Decided on the recommended answer (owner standing approval 2026-11-10). The alternatives are kept
for the record.

1. **Parameter names for `distribution`.** Decided: the table above: `mean`/`std` for normal,
   `mu`/`sigma` of the underlying normal for lognormal (numpy and SciPy convention), `low`/`high`,
   `mean` for exponential and poisson, `alpha`/`beta`, `s`/`n`. Alternative: lognormal by
   `median` and geometric std, which business users find easier but which no library uses.
2. **Lookup as a new type or as `categories_file` on `categorical`.** Decided: a new `lookup`
   type: it has its own keys (`value_column`, `weight_column`, `codeset`), its own refusals and
   route limits, and `categorical` keeps an inline-only contract. Alternative: `categories_file`
   on `categorical`, which matches the audit's tested spelling but makes `categories` conditionally
   required and puts file I/O behind an existing type.
3. **Lookup sources in this row.** Decided: CSV, Parquet and the four shipped code sets
   (`codeset: icd10`), since the code-set loader exists and ICD-10 is the audit's first example.
   Alternative: files only, code sets later.
4. **Zipf support.** Decided: bounded only (`n` required, s > 0): a rank column needs a finite
   range and numpy's unbounded form returns values up to 2^63. Alternative: `n` optional, unbounded
   when absent (requires s > 1).
5. **`decimal(n)` rounding.** Decided: round half even (IEEE 754 and Arrow default; no bias over
   many rows). Alternative: round half up, which matches spreadsheet habit.
6. **E4 on the mask side.** Decided: yes (one evaluator; only rows that raised change).
   Alternative: keep mask-side eager, which needs a second evaluator path and a flag.
