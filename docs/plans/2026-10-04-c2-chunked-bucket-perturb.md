## 1. Goal and scope

`bucket_perturb` never runs on the native chunked route today: it is in `CHUNKED_ROUTE_VETOED_STRATEGIES` (`execution/native/_requirements.py:153`), so any table carrying a bucket_perturb column is vetoed whole to the pandas oracle (every sibling column too). C2 makes **native-admissible bucket_perturb** a first-class chunked-native operator, executed per chunk through the compiled kernel that already exists (`native_bucket_perturb`, `execution/native/_bucket_perturb_ext.py:178`), with byte-and-type parity against the pandas-oracle chunked route, so a bucket_perturb column no longer forces its table off the native route.

**Native-admissible domain (exact, BLOCKER 1).** C2 does NOT widen the existing full-frame native domain. There are three distinct source-type layers, and the plan keeps them straight:
- The shared upstream chunk-safety gate (`_chunked_bucket_perturb.py:68,101`) accepts BOTH `pa.string()` and `pa.large_string()`, for the pandas chunked (oracle) route. C2 leaves this unchanged.
- The existing native config resolver `bucket_perturb_config_rejection` accepts EXACTLY `pa.string()` (`_operator_config_rejections.py:97`, the `resolved != pa.string()` check at line 105). But the first-chunk PROFILE loses Arrow width: an Arrow `large_string` converts through pandas to an `object` profile that maps back to `pa.string()` (`_chunked_profile.py:34`, `_requirements.py:78`), so profile-based resolution does NOT reliably stop a real `large_string` first chunk from reaching the native route.
- Therefore C2 native admits EXACTLY `pa.string()`. A real `large_string` source is a **native-decline / oracle-positive** case (section 4.2 adds the real-type gate precisely because profile resolution loses width). `large_string` is NOT a native-positive matrix case.

Widening native bucket_perturb (full-frame and chunked) to `large_string` is a separate future slice, out of scope here.

Out of scope (explicit, each stays on its current path, unchanged by C2):
- Autodetected `date_format` (absent/empty `date_format`, `_detect_format` scans the whole column): the one cross-row reduction, not chunk-safe. Already excluded by the chunk-safety gate (`check_chunked_compatibility`); C2 keeps it there, unchanged.
- `large_string` source (native-decline to oracle, per above), non-string source, timezone-directive formats (`%z`/`%Z`), invalid bucket, missing namespace, `when:`, FK-key edges: each stays on its existing reject/oracle/error path with its existing code (section 4.1 case table).
- The full-frame / unified-slice route: unchanged. Any type reconciliation is applied only on the native CHUNKED leg (section 3).
- group_key (C3) and date_shift (C4): remain in `CHUNKED_ROUTE_VETOED_STRATEGIES`. C2 removes only bucket_perturb from that set.

## 3. The output-type decision (core choice) -- content-dependent, matching the oracle (Codex-confirmed correct)

**Decision: on the chunked route, native-admissible bucket_perturb output type must equal the pandas-oracle chunked route's type for the same chunk content, per chunk and for the reassembled column. That is: a zero-row OR all-null chunk -> Arrow `null`; any chunk with at least one masked (non-null) value (including all-UNPARSEABLE-but-non-null values, which pass through as strings) -> `pa.string()`; the reassembled column via `concat_masked_chunks` -> `pa.string()` (or `null` if the whole column is empty/all-null).** This is NOT a string-pin.

Rationale (Codex-confirmed): unlike categorical, bucket_perturb already has a fully-specified, tested chunked output-type behavior on the oracle leg, and bucket_perturb is in `_NULL_ON_EMPTY_STRATEGIES`. The parity contract is native == oracle; the oracle yields `null` on empty/all-null chunks. Therefore:
- C2 must NOT add bucket_perturb to the `_chunked_schema_rule.py` string-pin set. `build_schema_rule` is constructed before the native/oracle fork and passed into BOTH legs (`_chunked_entry.py:407,420,433`), so a string-pin would force the oracle leg's empty chunk from `null` to `string`, breaking the existing `test_bucket_perturb_chunked.py` empty-chunk assertions. Out of scope and a regression.
- Instead, the **native leg reproduces the oracle leg's content-dependent types** via a post-kernel reconciliation in the bucket_perturb branch (section 4.5). The exact predicate: convert the kernel result to `pa.null()` iff the chunk is zero-row OR the (source == output) column is entirely null; otherwise keep `pa.string()`. An all-unparseable NON-null chunk stays `string` (the values pass through as strings), matching the oracle. This mirrors the full-frame reconciliation at `_shadow_assembly.py:54`.
