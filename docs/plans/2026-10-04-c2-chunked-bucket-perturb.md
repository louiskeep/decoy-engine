## 1. Goal and scope

`bucket_perturb` never runs on the native chunked route today: it is in `CHUNKED_ROUTE_VETOED_STRATEGIES` (`execution/native/_requirements.py:153`), so any table carrying a bucket_perturb column is vetoed whole to the pandas oracle (every sibling column too). - The shared upstream chunk-safety gate (`_chunked_bucket_perturb.py:68,101`) accepts BOTH `pa.string()` and `pa.large_string()`, for the pandas chunked (oracle) route. C2 leaves this unchanged.
- The existing native config resolver `bucket_perturb_config_rejection` accepts EXACTLY `pa.string()` (`_operator_config_rejections.py:97`, the `resolved != pa.string()` check at line 105). Widening native bucket_perturb (full-frame and chunked) to `large_string` is a separate future slice, out of scope here.

## 3. The output-type decision (core choice) -- content-dependent, matching the oracle (Codex-confirmed correct)

**Decision: on the chunked route, native-admissible bucket_perturb output type must equal the pandas-oracle chunked route's type for the same chunk content, per chunk and for the reassembled column. That is: a zero-row OR all-null chunk -> Arrow `null`; any chunk with at least one masked (non-null) value (including all-UNPARSEABLE-but-non-null values, which pass through as strings) -> `pa.string()`; the reassembled column via `concat_masked_chunks` -> `pa.string()` (or `null` if the whole column is empty/all-null).** This is NOT a string-pin.

Rationale (Codex-confirmed): unlike categorical, bucket_perturb already has a fully-specified, tested chunked output-type behavior on the oracle leg, and bucket_perturb is in `_NULL_ON_EMPTY_STRATEGIES`. The parity contract is native == oracle; the oracle yields `null` on empty/all-null chunks. Therefore:
- C2 must NOT add bucket_perturb to the `_chunked_schema_rule.py` string-pin set. `build_schema_rule` is constructed before the native/oracle fork and passed into BOTH legs (`_chunked_entry.py:407,420,433`), so a string-pin would force the oracle leg's empty chunk from `null` to `string`, breaking the existing `test_bucket_perturb_chunked.py` empty-chunk assertions. Out of scope and a regression.
- Instead, the **native leg reproduces the oracle leg's content-dependent types** via a post-kernel reconciliation in the bucket_perturb branch (section 4.5). The exact predicate: convert the kernel result to `pa.null()` iff the chunk is zero-row OR the (source == output) column is entirely null; otherwise keep `pa.string()`. An all-unparseable NON-null chunk stays `string` (the values pass through as strings), matching the oracle. This mirrors the full-frame reconciliation at `_shadow_assembly.py:54`.

## 6. Risk, rollback, docs, gates

- **Risk: R2** (compatibility/routing change; no destructive or irreversible side effect). The kernel, config resolver, oracle-chunked admission module, and upstream chunk-safety + source gates all exist and are tested. Novel surface: the native chunked branch, the empty/all-null -> null reconciliation (3 / 4.5 / 5.2), the native real-type gate (4.2), and the fixture migration (4.8). Chief hazard: a per-chunk type divergence on empty/all-null chunks (native string vs oracle null) -- the exact + cross-leg type pins (5.2) are designed to catch it.
- **Rollback:** revert the branch; the veto set returns bucket_perturb to the oracle. No data migration, no persisted state.
- **Docs:** CHANGELOG + compatibility-contract (4.11); Barry pass with exact-HEAD receipt; update the roadmap + RECENTLY-SHIPPED on merge (standing rule).

## 7. Resolved design decisions (Codex round-1 answers folded)

1. **Source-type seam (open Q1):** the authoritative chunk SOURCE gate already runs before native routing (`_oracle_preflight`, `_chunked_oracle.py:217,323`); non-string manual input already raises `chunked_bucket_perturb_source_dtype_unsupported`. The new native real-type gate (4.2) is ADDITIVE and NARROW: it enforces the native exact-`pa.string()` domain, catching `large_string` that profile resolution collapses to `pa.string()`. It is not the general source gate and does not duplicate the upstream emission.
2. **Empty/all-null (open Q2):** NO, `_mask_chunk_native` does not emit `null` for empty/all-null chunks; the kernel always returns `pa.string()`. C2 adds an explicit post-kernel reconciliation in the branch (4.5), predicate = zero-row OR all-null -> `pa.null()`, else `string`.
3. **Forcing replacement (open Q3):** `date_shift` by default (single-column, explicit-format, namespaced, upstream-chunk-compatible, native-dispatch-vetoed); `group_key` only where a `group_by` sibling already exists. Both remain in `CHUNKED_ROUTE_VETOED_STRATEGIES` after C2.
