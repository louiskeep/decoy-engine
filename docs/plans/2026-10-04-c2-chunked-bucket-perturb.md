This slice is the direct analogue of **C1** (deterministic categorical) and inherits its template. The important **difference** from C1 is the output-type decision (section 3): categorical was string-pinned on both legs; bucket_perturb must instead reproduce the oracle-chunked route's **content-dependent** type (empty/all-null chunk -> Arrow `null`, valued chunk -> `string`, reassembled column -> `string`), because that behavior already exists and is tested, and a blanket string-pin would corrupt the oracle leg.

## 1. Goal and scope

`bucket_perturb` never runs on the native chunked route today: it is in `CHUNKED_ROUTE_VETOED_STRATEGIES` (`execution/native/_requirements.py:153`), so any table carrying a bucket_perturb column is vetoed whole to the pandas oracle (every sibling column too). C2 makes **native-admissible bucket_perturb** a first-class chunked-native operator, executed per chunk through the compiled kernel that already exists (`native_bucket_perturb`, `execution/native/_bucket_perturb_ext.py:178`), with byte-and-type parity against the pandas-oracle chunked route, so a bucket_perturb column no longer forces its table off the native route.

In scope: bucket_perturb that is **native-admissible** per the existing resolver `bucket_perturb_config_rejection` (`execution/native/_operator_config_rejections.py:62-107`): string source, explicit non-empty `date_format`, no timezone directive (`%z`/`%Z`), valid `bucket` in {week, month, quarter}, mandatory namespace. This is exactly the v1 full-frame native domain (`docs/plans/2026-09-21-native-bucket-perturb.md`); C2 does not widen it.

Out of scope (explicit, each stays on its current path, unchanged by C2):
- Autodetected `date_format` (the `date_format` is absent/empty and `_detect_format` scans the whole column): this is the one cross-row reduction and is **not chunk-safe**. It is already excluded by admission (`bucket_perturb_requires_date_format`) and already fails/declines on the chunked route today. C2 keeps it on the oracle (or its existing reject path), unchanged, and must not admit it.
- Non-string source, timezone-directive formats, invalid bucket, missing namespace: stay on their existing reject/oracle paths with their existing codes.
- The full-frame / unified-slice route: unchanged. Any new type reconciliation is applied only on the two CHUNKED legs (section 3).
- group_key (C3) and date_shift (C4): remain in `CHUNKED_ROUTE_VETOED_STRATEGIES`. C2 removes only bucket_perturb from that set.

## 2. Established facts (engine HEAD a2b97856)

- **Kernel exists, full-frame parity-tested; C2 builds no new Rust.** `native_bucket_perturb` (`execution/native/_bucket_perturb_ext.py:178-242`) reuses the compiled `derive_index_batch` index kernel. Pandas is the parse/format authority (`pd.to_datetime(..., format=date_format, errors="coerce")` + `strftime`), matching the oracle exactly. Rows are grouped by distinct bucket_size (leap-year months differ), one `derive_index_batch(pool_size=size)` per group, offsets scattered back order-preservingly (`_grouped_offsets`, lines 119-175) -> byte-identical to the oracle's per-row `% bucket_size`. Runs full-frame via `execution/physical/_shadow_operators.py:240-251`; covered by `tests/physical/test_shadow_bucket_perturb.py`. The kernel pins `pa.string()` per batch (`_bucket_perturb_ext.py:196`).
- **bucket_perturb is row-local; no cross-chunk state (except autodetect, already excluded).** Each row's output is a pure function of `(value, job_seed, namespace, bucket, date_format)` via `derive(job_seed, namespace, canonicalize(value))` then `% bucket_size` (`transforms/bucket_perturb.py:94-120`). With an explicit `date_format` there is no whole-column reduction, no sorting, no sibling state, no global row index. Chunk-safety is therefore automatic for the admitted domain. Confirmed by the oracle-chunked parity module docstring (`tests/unit/execution/test_bucket_perturb_chunked.py:1-30`) and `_chunked_bucket_perturb.py`.
- **The parity ORACLE is the pandas-oracle CHUNKED route, not the full-frame route.** `run_mask_pipeline_chunked` already admits bucket_perturb as a CONDITIONAL strategy (gated on explicit `date_format`), wired via `execution/_chunked_bucket_perturb.py` and reached through the upstream preflight `check_chunked_compatibility` (`execution/_chunked.py`). So the upstream chunk-safety gate (C1's site 5) **already passes** admissible bucket_perturb; C2 needs no change there (less work than C1). C2's native leg must match this oracle leg byte-for-byte on values, Arrow type, metadata, order, warnings, errors, evidence.
- **Output TYPE is content-dependent and ALREADY correct on the oracle-chunked leg.** `tests/unit/execution/test_bucket_perturb_chunked.py` (section "3. Empty-chunk parity", lines 370-398) pins: an empty/all-null chunk yields Arrow `null` (promotable by `concat_masked_chunks`, line 390-392); a valued chunk yields `pa.string()`; an empty+valued concatenation promotes to `pa.string()` (line 395); an all-empty/all-null column matches the oracle `null` (line 398). Full-frame reconciliation differs (`execution/physical/_shadow_assembly.py:26,54-55`: bucket_perturb is in `_NULL_ON_EMPTY_STRATEGIES` -> empty->null, all-null->null, else->string). **Note the real difference from categorical**: categorical is in `_TOKENIZING_STRATEGIES` (empty->float64); bucket_perturb is in `_NULL_ON_EMPTY_STRATEGIES` (empty->null). C1's string-pin is therefore NOT transferable: see section 3.
- **THE veto is the single load-bearing change.** `CHUNKED_ROUTE_VETOED_STRATEGIES = frozenset({"bucket_perturb", "group_key", "date_shift"})` (`execution/native/_requirements.py:153`). Removing `bucket_perturb` flips, together, all three refusal sites that read the shared constant:
  1. `execution/native/_dispatch.py:242-251` (`_static_route_decision`, emits `bucket_perturb_not_native_chunked_route:<col>`).
  2. `execution/native/_phase3_eligibility.py:109-117,135` (eligibility mirror).
  3. `execution/native/_chunked_evidence.py:45-50` (`_planned_backend` -> `PANDAS_ORACLE` for a vetoed strategy).
- **Config-rejection resolver already exists and is complete** (`bucket_perturb_config_rejection`, `_operator_config_rejections.py:62-107`), dispatched from the compiler (`_requirements.py:540-548`) and `native_route_eligibility` (`_plan.py:329-337`). bucket_perturb is already in `NATIVE_KERNEL_STRATEGIES` (`_requirements.py:126-137`). ## 3. The output-type decision (core choice) -- content-dependent, matching the oracle

**Decision: on the chunked route, native-admissible bucket_perturb output type must equal the pandas-oracle chunked route's type for the same chunk content, per chunk and for the reassembled column. That is: an empty-or-all-null chunk -> Arrow `null`; any chunk with at least one masked (non-null) value -> `pa.string()`; the reassembled column via `concat_masked_chunks` -> `pa.string()` (or `null` if the whole column is empty/all-null).** This is NOT a string-pin.

Rationale: unlike categorical (C1), bucket_perturb already has a fully-specified, tested chunked output-type behavior on the oracle leg (`test_bucket_perturb_chunked.py:370-398`), and bucket_perturb is in `_NULL_ON_EMPTY_STRATEGIES`, not `_TOKENIZING_STRATEGIES`. The parity contract is native == oracle; the oracle yields `null` on empty/all-null chunks. Therefore:
- C2 must NOT add bucket_perturb to the `_chunked_schema_rule.py` string-pin set the way C1 added categorical. Doing so would force the type to string on BOTH chunked legs (C1 established that `build_schema_rule` applies on the oracle leg too), which would change the oracle leg's empty-chunk type from `null` to `string` and break the existing `test_bucket_perturb_chunked.py` empty-chunk assertions. That is out of scope and a regression.
- Instead, the **native leg must reproduce the oracle leg's existing content-dependent types**. The native kernel pins `pa.string()` per batch; the open implementation question (section 4) is the empty/all-null chunk: the native branch must yield an Arrow `null`-typed array for a chunk with no masked values, matching the oracle, so that per-chunk parity holds and `concat_masked_chunks` promotes exactly as it does for the oracle. The builder determines whether `_mask_chunk_native` already routes empty/all-null chunks around the kernel (emitting null) or whether an explicit empty/all-null -> null guard is needed in the bucket_perturb branch; either way the acceptance tests (section 5) pin the per-chunk type.

**Cross-route note:** C2 does NOT create a new route-dependent schema difference the way C1 did, because it reconciles the native leg TO the already-correct oracle leg rather than pinning a new type. The full-frame route (`_shadow_assembly.py` null-on-empty) and the chunked route already agree on null-on-empty for bucket_perturb. Record the admission change in `docs/compatibility-contract.md` (ROUTE-OUTPUT-CONTRACT: bucket_perturb now runs native on the chunked route; output type unchanged from the oracle chunked route) and `CHANGELOG.md`, and run the Barry documentation pass with an exact-HEAD gate receipt (section 6).

## 4. Implementation

The minimal change set (by analogy to C1 commit `05a3ec85`, with the differences called out):

1. **Remove the veto (single load-bearing change).** `_requirements.py:153` -- drop `bucket_perturb` from `CHUNKED_ROUTE_VETOED_STRATEGIES`, conditioned on native-admissibility through the normal fallback: a non-admissible bucket_perturb column (autodetect format, non-string source, tz directive, bad bucket, no namespace) still routes its table to the oracle via the existing non-native fallback. This flips the three refusal sites (section 2) together.
2. **Source-type admission.** Add `bucket_perturb_source_type_rejection(column, schema)` (string-only) and a `bucket_perturb` branch in `real_type_rejection` (`_real_type_admission.py`), mirroring C1's `categorical_source_type_rejection`, so a non-string source reroutes to the oracle BEFORE masking, never failing from the kernel after admission. Confirm whether `bucket_perturb_config_rejection`'s source check already runs at chunked preflight; if it does, this step is a no-op or a consolidation, not a duplicate gate. Do not double-emit.
3. **`_INDEX_KERNEL_STRATEGIES`** (`_dispatch.py:75`): add `bucket_perturb` so the index kernel loads at preflight; keep the `index_extension_unavailable` companion-absent downgrade (bucket_perturb reroutes to the oracle when the companion is absent).
4. **`_mask_chunk_native` bucket_perturb branch** (`_chunk_masking.py`): add `elif strategy == "bucket_perturb":` calling `native_bucket_perturb(source, bucket=<cfg>, date_format=<cfg>, mask_key=..., namespace=..., index_kernel=..., native_threads=...)`, set `evidence.compiled_kernel_executed = True`. Thread the scalar `bucket` / `date_format` config to the branch (via `_chunked_entry.py`, analogous to C1's config threading but without a prepared-artifact object). Nulls restore positionally (kernel null-masks), exactly as the oracle.
5. **Empty/all-null chunk -> Arrow `null`** (the section-3 crux): ensure the native branch yields a `null`-typed array for a chunk with no masked values, matching the oracle chunked leg and `concat_masked_chunks` promotion. Prefer the smallest change that makes per-chunk parity hold; do not alter the oracle leg.
6. **Evidence/backend** (`_chunked_evidence.py:35`): add `bucket_perturb` to `_COMPANION_STRATEGIES`. 7. **Do NOT touch `_chunked_schema_rule.py` string-pin set** (section 3). If any schema-rule change is needed at all, it is only to ensure bucket_perturb is left to its content-dependent type, not pinned. State the rationale in the diff.

## 5. Acceptance tests (written before implementation; red-before recorded)

Parity contract: native chunked == pandas-oracle chunked, byte-for-byte on values AND Arrow field type AND metadata, row/column order, warnings, errors, evidence. New support + suites mirror C1's `_chunked_categorical_support.py` / `test_chunked_categorical_admission.py` / `test_chunked_categorical_parity.py`.

1. **Parity matrix.** Native-admissible bucket_perturb (buckets {week, month, quarter}), **string source, explicit date_format**, over chunk shapes {empty, all-null, single-row, ragged last chunk, all-null chunk beside a valued chunk, null-block-then-valued, valued-then-null-block}, chunk sizes {1, 7, 50_000}, native_threads {1, 4}, both `pa.string()` and `pa.large_string()` source dtypes (the oracle admits both, `test_bucket_perturb_chunked.py:210,247`). Assert native == oracle per chunk AND across the reassembled column (values + Arrow type + metadata). Include a chunk-boundary split that puts the same source value in two chunks, and multiple namespaces.
2. **Output-type pins (section 3).** Per chunk: an empty/all-null chunk's native output Arrow type is `null`; a valued chunk's is `pa.string()`; the reassembled column is `pa.string()`; an all-empty/all-null column reassembles to `null`. These must equal the oracle chunked route's types for the identical input (assert against the oracle, not hardcoded, so the two cannot silently diverge).
3. **Determinism across chunks.** Same source value in different chunks -> same perturbed date; equals the full-frame result for the same `(mask_key, namespace, bucket, date_format)`. Leap-year month (29/28/30/31-day buckets) covered so the per-bucket-size grouping is exercised across a chunk boundary.
4. **Null and unparseable preservation.** Nulls stay null; an unparseable value (does not match date_format) passes through unchanged, matching the oracle, across chunk boundaries.
5. **Lifted veto + mirrors.** The three refusal sites no longer emit `bucket_perturb_not_native_chunked_route` for an admissible column; a table with an admissible bucket_perturb column runs native (not vetoed whole to the oracle). Assert the eligibility mirror and evidence agree.
6. **Fail-closed / oracle-fallback cases (NOT positive native cases).** Each stays on its existing path with its existing code: autodetect (`date_format` absent/empty), `date_format=""`, invalid-but-truthy date_format, timezone-directive format (`%z`/`%Z`), non-string source, invalid bucket, missing namespace, `when:` predicate, FK-key edge (both orientations). Assert the native route declines these BEFORE masking and the oracle handles them unchanged.
7. **Companion-absent downgrade.** With the index companion unavailable, an admissible bucket_perturb column downgrades (`index_extension_unavailable`) and runs on the oracle, byte-identical; evidence reports planned `rust_companion` + executed `pandas_oracle`.
8. **Evidence/backend.** Admitted: planned + executed `rust_companion`, `compiled_kernel_executed is True`, `kernel_calls["bucket_perturb"]` present and consistent across chunk/bucket-group structure.
9. **No prepared-artifact over-build.** (bucket_perturb has no CDF/corpus; a smoke assertion that the branch passes scalar config, no per-chunk rebuild of any resolved structure. Lighter than C1.9.)
10. **Fixture-migration proof.** The migrated oracle-forcing fixtures (now `date_shift`/`group_key`) still force the oracle and still assert what they asserted; no test silently becomes a no-op because its forcing strategy got admitted.

Record red-before for the new suites (fail on current main because bucket_perturb is vetoed), green-after.

## 6. Risk, rollback, docs, gates

- **Risk:** low-medium. The kernel, config resolver, oracle-chunked admission module, and upstream chunk-safety gate all already exist and are tested. The only novel surface is the native chunked branch + the empty/all-null -> null type reconciliation (section 3/5.2) and the fixture migration. The chief hazard is a per-chunk type divergence on empty/all-null chunks (native string vs oracle null); the parity matrix (5.1/5.2) is designed to catch it.
- **Rollback:** revert the branch; the veto set returns bucket_perturb to the oracle. No data migration, no persisted state.
- **Docs:** CHANGELOG + compatibility-contract (section 4.10); Barry pass with exact-HEAD receipt; update the roadmap + RECENTLY-SHIPPED on merge (standing rule).
- **Gates:** Codex plan-gate (this doc) -> Sonnet tests-first build (red-before) -> dennis adversarial -> Codex final -> merge on local gates with Cam's go. 3-round review cap then escalate.
