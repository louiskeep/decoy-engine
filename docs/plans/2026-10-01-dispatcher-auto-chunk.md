## Problem

`run_pipeline` already chunks large single-table mask jobs on its own ("auto-chunk", default on). The decision and the lane today:

- **When.** `_pipeline_chunk_route.decide_chunk_route` calls `_planner.classify_job` once (that one call also feeds the `explain_plan` stamp) and routes chunked when `auto_chunk` is true and the mode is `chunked`. The planner requires exactly one mask table, no generate tables, no FK relationships, the pandas substrate, scalar work only, every strategy passing `check_chunked_compatibility` (which also refuses a transform-bearing table, `per_table_transforms_present`), no `when:` predicate, no fpe join group, date_shift only with an explicit `date_format`, and, on the loaded source: a resident `pa.Table` (a `LazySource` is rejected by `_pipeline_sources.lazy_source_rejection`), at least `auto_chunk_threshold_rows` rows (default `AUTO_CHUNK_THRESHOLD_ROWS_DEFAULT = 100_000`), chunk-stable dtypes (integers only when null-free; string, float, bool, temporal and null types), no extra loaded frames, and the bucketize, group_key, text_mask, code_set and bucket_perturb source gates.
- **Lane.** `_pipeline_generate_mask.run_generate_and_mask_steps` calls `_pipeline_route_exec.run_mask_chunked`, which slices the resident table into zero-copy `chunk_size_rows` slices (default `CHUNK_SIZE_ROWS_DEFAULT = 50_000`), drains the pandas oracle `_chunked.run_mask_pipeline_chunked`, and joins the chunks with `concat_masked_chunks` (strict, no type promotion except null-typed chunks to the agreed type) and `combine_chunks`.

So the lane choice runs backwards. Below the threshold, the default-on unified slice (`_unified_slice`, Task 4.5) runs eligible jobs on native kernels. Above it, `_unified_slice_admission.cheap_admission` declines because `route_chunked` is set, and the job runs chunk by chunk on pandas. The largest jobs take the slowest lane. B1 made `decoy_engine.run_mask_chunked` the production-shaped chunked entry point; benchmark runs R074 and R075 measured its predecessor, `run_native_or_oracle_chunked`, against the pandas oracle on a 1M-row table. No production code calls `run_mask_chunked` yet (the physical seam's adapters reference it, and that seam is disconnected). Auto-chunk also records only `mode: chunked`; nothing says which backend masked each column.

## Guarantee (pinned)

For every `run_pipeline` call:

1. **When is unchanged.** For the same inputs, `route_chunked`, the existing `quality_metrics["auto_chunk"]` keys (`mode`, `chunk_size_rows`, `threshold_rows`, `source_rows`, `chunk_count`, `reason`) and the `explain_plan` stamp are the same as today. B2 changes only the lane that executes a job already routed to chunked.
2. **Lane.** A routed table runs through `run_mask_chunked` (B1), which picks the native or the oracle route for the whole table. Only the kill switch `chunked_dispatcher_enabled=False` runs today's lane (`run_mask_pipeline_chunked` plus `concat_masked_chunks`, unchanged) instead. The lane is recorded (guarantee 5).
3. **Output contract.** The routed output is B1's output, joined. Compared with the same call under `chunked_dispatcher_enabled=False` (today's lane), whichever B1 route ran, for any valid `native_threads`, with or without the compiled companion:
   - (a) the same column names in the same order and the same rows in the same order;
   - (b) every masked column has the same values (nulls included) and the same Arrow type, and its field is nullable with no field metadata, as today, except that a string-output column (hash, truncate, and redact with a string or default `redact_with`) is always `string`, where today's lane leaves it `null` when every chunk is all-null;
   - (c) every passthrough column (configured `passthrough`, and unconfigured columns kept under the passthrough policy) equals the source column: type, values, nulls, field nullability and field metadata (`field.equals(source_field, check_metadata=True)`). Today's lane returns the pandas round trip instead: `large_string` becomes `string`, `time32` and `time64[ns]` become `time64[us]`, `date64` becomes `date32` with sub-day milliseconds dropped, a column whose `b"pandas"` metadata disagrees with its field follows the metadata (UTC metadata on an `America/New_York` field comes back UTC), and every field becomes nullable without field metadata (`b2r4_shapes_probe.out`, `b2r4_meta_oracle_probe.out`);
   - (d) no schema metadata (`schema.metadata is None`). Today's lane carries chunk 0's `b"pandas"` metadata, or none when chunk 0 needed a null cast.

   Masked-column values also equal the forced full-frame run (`auto_chunk=False`), as `tests/unit/execution/test_auto_chunk_routing.py` asserts today; types and schema equal it except for the differences in (b) to (d). These differences are deliberate: B1 revision 9 carries passthrough columns without pandas, and Cam's direction is that the Rust path does not reproduce pandas quirks.
4. **Side channels.** Vault entries are the same pairs in the same order as today's lane. Row errors fail closed with `RowErrorsFailedError`, nothing quarantined, as today. The warnings tuple and `quality_metrics["code_set_corpora"]` equal today's (probe over the existing strategy matrix: `b2r4_side_probe.out`).
5. **Evidence, never silent.** Every routed result carries `quality_metrics["auto_chunk"]["lane"]` (`dispatcher` or `legacy_oracle`), `["lane_reason"]` (`null` on the dispatcher lane, `dispatcher_disabled` on the legacy lane), `["native_threads"]`, and `quality_metrics["chunked_route"]`: `native_admitted`, `reroute_reason`, `pandas_read_passthrough`, and per configured column `column`, `strategy`, `planned_backend`, `executed_backend` and `calls`. A column planned for Rust that ran on pandas is visible together with the reason. The payload is JSON-safe and deterministic: two runs with the same inputs and companion state produce equal `quality_metrics`. Elapsed time lives in `ExecutionResult.timings` only.
6. **Threads.** `native_threads` is an `int` from 1 to 1024 inclusive (not `bool`), default 1. B2 validates it on the `run_pipeline` surface for every call: `require_positive_int` first, then an explicit rejection of values above B1's `MAX_NATIVE_THREADS` (1024), both raising `ExecutionError(code="invalid_execution_knob")` with the other knobs, before profiling. B1's own check (`invalid_native_threads`) stays as the second line and cannot fire from `run_pipeline`. The value reaches the compiled kernels on the dispatcher lane and changes no output byte.
7. **No mid-run fallback.** The lane and the route are fixed before the first chunk is masked. An error after that propagates with its existing type and code; nothing retries on another lane.
8. **Non-routed calls unchanged.** A call that does not route chunked never enters the new code: outputs and `quality_metrics` are byte-identical to today, including the all-default `quality_metrics == {}` golden contract, for any valid knob values of `native_threads` and `chunked_dispatcher_enabled`. Invalid values fail early under guarantee 6.

## Non-goals

Changing when auto-chunk triggers (planner gates, threshold, the `chunk_size_rows` default or its meaning); multi-table dispatch (B7); platform or CLI wiring (B3, B4), admission pricing for native cost and threads (B5), and release or artifact work (B3, B5 and the phase-boundary release); incremental output sinks or lazy batch input (B6a, B6b): the routed output is still fully materialized and concatenated; widening native admission (Phase C), including tables with unconfigured columns, which B1 vetoes to the oracle route (`uncovered_columns`); native admission for unconfigured passthrough columns is program slice B8, which reopens B1's admission contract and so stays out of B2; transforms on the chunked route (A8 keeps transform-bearing tables off it, Design 9); changing `run_mask_chunked`, the oracle `run_mask_pipeline_chunked`, `concat_masked_chunks`, the unified slice, or `classify_job`; changing the full-frame or unified-slice output shape to match guarantee 3 (see Known issues); fixing the byte-estimate defect in Known issues; adaptive or byte-based chunk sizing; the Phase E 100M-row performance gate (B2 carries its own bounded merge benchmark, section 11); showing the lane in `explain_plan`, which stays a static classification.

## Design

### 1. Where it plugs in

`_pipeline_route_exec.py` is at 597 lines against the 600-line goal, so the lane logic goes in a new module `execution/_pipeline_auto_chunk.py`:

```
run_auto_chunk(config, source, *, table, engine_version, registry, adapter, vault_writer,
    chunk_size_rows, key_provider, native_threads, dispatcher_enabled)
    -> tuple[outputs, timings, boundary_conversion_ms, warnings, quality_metrics]
```

`_pipeline_route_exec.run_mask_chunked` keeps its name, its five-part return and its current parameters, gains `native_threads: int = 1` and `dispatcher_enabled: bool = True`, and becomes a delegate to `run_auto_chunk`. Existing imports (`tests/physical/test_characterization_chunked.py`, `physical/drivers/_chunked.ResidentChunkedAggregatorAdapter`) keep working; the adapter forwards the two new parameters, and `tests/physical/test_lossless_forwarding.py` is extended for them.

`run_pipeline` gains two keyword arguments next to the auto-chunk knobs: `native_threads: int = 1` and `chunked_dispatcher_enabled: bool = True`, validated in the existing fail-early block before profiling (`native_threads` with `require_positive_int`, then an explicit `native_threads > MAX_NATIVE_THREADS` rejection with `ExecutionError(code="invalid_execution_knob")`, since `require_positive_int` alone accepts 1025; `chunked_dispatcher_enabled` with `require_bool`) and threaded through `run_generate_and_mask_steps` to the routed call. `MAX_NATIVE_THREADS` is B1's constant in `execution/native/_chunked_entry.py`; if importing that module in the fail-early block costs measurable import time, the builder moves the constant to a dependency-free module both import, and never duplicates the literal. The knobs are runtime resource knobs like `auto_chunk`, never config fields, so they stay out of `pipeline_config_hash`. `_pipeline.py` is 679 lines on this base, exactly its ratchet in `tests/sentry/test_module_size.py` (A8 raised it from 635). B2 adds no net lines there: the builder keeps the ratchet by moving lines out (for example the auto-chunk paragraph of the `run_pipeline` docstring into `_pipeline_routing`'s module docstring, which it already points to), never by raising or loosening the ratchet. `_pipeline_auto_chunk.py` stays under the 600-line goal and must not exceed 700 lines.

### 2. Lane selection (once per routed table, before any chunk is masked)

1. `dispatcher_enabled` is false: legacy lane, `lane_reason = "dispatcher_disabled"`.
2. Otherwise: dispatcher lane, `lane_reason = null`.

The legacy lane is exactly today's code path (`run_mask_pipeline_chunked` plus `concat_masked_chunks`), so its output is today's by construction.

Revision 3.1 had two more legacy cases, a type-parity gate and a metadata-parity gate. Both are removed. They sent a table to pandas only so that its passthrough columns and schema metadata would come out with pandas' round-trip types and metadata, which is exactly what B1 revision 9 stops doing. The probe (`b2r4_shapes_probe.out`, run through `run_pipeline` with B1 as the lane and no gates) found no correctness reason to keep them:

- Masked-column values were equal to today's lane for every formerly gated shape: `date64` with whole-day and sub-day values, `time64[ns]` with microsecond-aligned values, `time32`, `large_string`, and sources built by `Table.from_pandas` with a `StringDtype` column (masked and passthrough), a nullable `Int8` column, non-empty `DataFrame.attrs`, a named RangeIndex, a stored non-range index, and a tz-aware column. With an unconfigured column forcing B1's oracle route, where carried columns reach the pandas adapter as null placeholders under the source's `b"pandas"` metadata, `Int8` and `StringDtype` passthrough columns, `int64` metadata on an `int32` field and UTC metadata on an `America/New_York` field all masked without error and with today's masked values (`b2r4_meta_oracle_probe.out`).
- `time64[ns]` with a value that is not whole microseconds, and malformed `b"pandas"` JSON, fail in `profile_source` on every lane, before routing, so no lane gate can change their outcome.
- A stored non-range index column (`__index_level_0__`) is unconfigured, so B1 reroutes the table to its oracle route (`uncovered_columns`), where the pandas adapter restores it as the index; the column is missing from the output on both lanes and on the full-frame route (probe). That is today's behavior, unchanged by B2.

### 3. Output contract and join

The dispatcher lane's output is what `run_mask_chunked` yields, joined; B2 adds no type mapping, cast or metadata of its own.

**Join.** `concat_masked_chunks` cannot be reused unchanged: it rebuilds every field as `pa.field(name, type)` and casts any chunk whose schema differs, so a non-nullable passthrough field comes back nullable, while field metadata survives because `Schema.equals` ignores it (probe `nonnullable_field`, `field_metadata`). The legacy lane keeps it, unchanged. The dispatcher lane uses a free function in `_pipeline_auto_chunk.py`:

```
join_dispatcher_chunks(chunks: list[pa.Table], *, table: str) -> pa.Table
```

1. Column names must be equal across chunks; otherwise `ExecutionError(code="chunked_schema_mismatch")`, as in `concat_masked_chunks`.
2. Per column: if every chunk has an equal field (`Field.equals(..., check_metadata=True)`), that field is the target. Otherwise `concat_masked_chunks`' type rule applies: the single non-null type the chunks agree on, `null` when every chunk is `null`, and `chunked_schema_mismatch` when two chunks hold different non-null types; the target field is then the field of the first chunk with that type.
3. Chunks whose schema differs from the target (`check_metadata=True`) are cast to it; the result is `pa.concat_tables(...).combine_chunks()` with no schema metadata.

B1 already gives every string-output and passthrough column one field across chunks, so step 2's fallback only meets columns of strategies that run on B1's oracle route (categorical, bucket_perturb, date_shift and the rest), whose per-chunk types are the oracle's; for those the rule gives today's result.

**What differs from today's lane.** Exactly guarantee 3 (b) to (d). Acceptance test 0 records the differences per source type and fails on any difference outside that list, so a pyarrow or pandas upgrade that changes the legacy lane, or a B1 change, surfaces as a fixture diff for review instead of a silent change.

### 4. Dispatcher lane execution

The lane produces the same slices as today (`source.slice(start, chunk_size_rows)` for `start` in `range(0, num_rows, chunk_size_rows)`) and calls:

```
run_mask_chunked(config, slices, table=table, engine_version=engine_version, registry=registry,
    adapter=adapter, vault_writer=vault_writer, chunk_result_sink=chunk_results,
    key_provider=key_provider, base_row_offset=0, native_threads=native_threads)
```

`adapter` is `run_pipeline`'s pandas adapter (exactly `PandasExecutionAdapter`), so B1's `adapter_requested` veto does not fire and B1's stock-adapter carrying (rule R1) applies. `run_mask_chunked` runs the oracle's eager preflight first (B1 guarantee 3), so config errors carry today's codes in today's order.

**Per-table fallback.** The native-or-oracle choice is B1's, made once per table before the first chunk is masked: when the native route refuses the table, the same call runs B1's oracle route, and the refusal is recorded in `reroute_reason`. Refusals that can reach an auto-chunked table include a strategy the chunked native route does not run (for example `categorical_not_native_chunked_route:<column>`, `date_shift_not_native_chunked_route:<column>`), a strategy whose fallback policy is not native (`fallback_policy_not_native:<column>:python_only` for fpe, bucketize and text_redact), a Faker provider without a native pool (`faker_provider_not_native:<column>:<provider>`) or with non-string output (`faker_provider_output_not_string:<column>:<provider>`), unconfigured columns (`uncovered_columns:[...]`), and a missing or incompatible companion (`crypto_extension_unavailable`, `index_extension_unavailable`). The codes above were observed on main by the probe (`b2r4_side_probe.out`, `b2r4_shapes_probe.out`); the list is illustrative, and the evidence records whatever B1 returns. The `when_predicate_not_native` and `adapter_requested` refusals cannot arise from `run_pipeline` (the planner rejects `when:`, and the adapter is pandas); if one ever does, it is recorded the same way. B7 reuses this per-table choice for each independent table.

Established pattern: other engines with an optional accelerated backend also fall back per unit of work at plan time and report why. Apache Gluten (Velox under Spark) falls back unsupported operators to vanilla Spark and reports a fallback reason per operator. Spark RAPIDS with `spark.rapids.sql.explain=NOT_ON_GPU` logs why each operator stayed on the CPU. Polars' streaming engine runs operations it does not support on the in-memory engine. All three decide before execution and never switch partway through a stream. B2 does the same (guarantee 7). After the first chunk the vault writer and the chunk-result sink already hold that chunk's side effects, so a retry on another lane would duplicate them.

Schema drift on a later chunk cannot happen here: every chunk is a slice of one resident table, so every slice has the source's Arrow types, and an all-null slice keeps its column's type rather than becoming `null`-typed. For the same reason B1's `chunked_leading_null_type` cannot fire. If `native_chunk_schema_drift` ever fires, it propagates as the typed `ExecutionError` B1 defined, on either route.

**Passthrough columns.** On the dispatcher lane a carried passthrough column never goes through pandas (B1 rules R3 and R4), and every passthrough column in the output is the source column (B1 design item 5); guarantee 3 (c) follows. A passthrough column that a sibling-reading strategy names, or whose name equals any string in another column's config entry (B1 rule R2 (b), a deliberate over-approximation), still goes through pandas on B1's oracle route; a value pandas refuses in it raises B1's `chunked_passthrough_value_unrepresentable`, which propagates under guarantee 7. Today's lane raises the raw pandas exception for the same input. `when:` cannot make a column read here, because the planner refuses `when:`.

### 5. Results and evidence

- `timings`: `aggregate_chunk_timings(chunk_results)`, as today. Native chunk results carry one record per column per chunk (B1), so the rollup has the same shape.
- `boundary_conversion_ms`: sum over chunks (zero on the native route).
- `warnings`: `aggregate_chunk_warnings(chunk_results)`. `quality_metrics["code_set_corpora"]`: `aggregate_chunk_code_set_corpora(chunk_results)`. Both as today.
- `quality_metrics["chunked_route"]`: `aggregate_chunked_route_evidence(chunk_results)` with each column's `elapsed_ms` removed; it carries B1's `pandas_read_passthrough`. On the legacy lane the same shape is built from `plan_column_backends` (planned backends) with `executed_backend = pandas_oracle`, `calls` equal to the chunk count, `native_admitted = false`, `reroute_reason = lane_reason`, and `pandas_read_passthrough` listing every passthrough column of the table (configured passthrough without `when:` plus unconfigured columns, sorted), since today's lane converts all of them; so both lanes report alike.
- `quality_metrics["auto_chunk"]`: today's six keys plus `lane`, `lane_reason` and `native_threads`, on routed runs only. Non-routed runs stamp exactly what they stamp today.
- One INFO log line per routed job naming the table, lane, `native_admitted` and `reroute_reason`. It contains no values.

### 6. Threads

`native_threads` defaults to 1, matching B1's library default. Production callers pass their admitted reservation (B5 prices it; B3 and B4 pass it). It is forwarded only on the dispatcher lane; the legacy lane and every non-routed route ignore it. The unified slice's own threading is not changed.

### 7. Companion not installed

The engine imports and runs without the companion. B1's preflight probes the crypto kernel only for tables with a hash column, and the index kernel only for tables with a native Faker column. A missing or ABI-incompatible companion sends that table to B1's oracle route with `crypto_extension_unavailable` or `index_extension_unavailable`, and evidence reports those columns as planned `rust_companion` or `rust_pool_select`, executed `pandas_oracle`. Tables using only redact, truncate and passthrough need no companion and run on the native route (`arrow_python`). The output contract holds in every case (guarantee 3): B1 applies the same schema rule and carrying on both routes.

### 8. Chunk size

Unchanged: a fixed row count, `chunk_size_rows` (default 50,000), caller-set, validated as today and recorded in the stamp. Reasons:

- Values do not depend on chunk boundaries for any admitted strategy; that is the value-keyed contract the planner enforces.
- Keeping today's boundaries keeps the chunk-result count and the vault entry order the same as today, which guarantee 4 relies on.
- Row-count batches are the established pattern for this kind of engine: pyarrow's dataset scanner defaults to `batch_size = 131_072` rows, and DuckDB stores row groups of 122,880 rows.

A different default, or byte-aware sizing for wide rows, is a performance decision that needs a measured run first. It belongs with B6a and B6b, which bound memory, or to a follow-up after Phase E. B2 does not change it.

### 9. Composition with A8 and lazy sources

A8 is on the base. `run_pipeline` calls `prepare_transform_sources` once, before routing (`_pipeline.py` lines 426 to 440): it refuses what routing would refuse, then replaces each resident transform-bearing table with its transformed table, so routing prices the data that will run. A lazy transform-bearing table stays raw. Neither reaches B2's lane: the planner's `check_chunked_compatibility` call refuses any transform-bearing table through `_transforms_gate.reject_per_table_transforms` (`_chunked.py` line 285), which `classify_job` records as the reason `per_table_transforms_present` and which also skips the runtime source gates (`_planner.py` lines 317 to 344). The job then runs on another route. `run_mask_chunked` itself refuses a transform-bearing table before reading a chunk (B1, PR #186), so even a direct call cannot mask one without its transforms. A `LazySource` is rejected by the planner's runtime gate, so auto-chunk never sees one and B2 never materializes one. Lazy-source admission to full-frame under `auto` (A8's rule) is decided earlier, by `resolve_execution_route`, which B2 does not change.

### 11. Merge evidence: performance and memory

The program's standing Rust merge rule needs "faster, within its declared memory ceiling". B1's predecessor runs (R074, R075) measured the dispatcher directly, not through `run_pipeline`, so they are not B2's evidence. B2 adds a bounded local benchmark. It is merge evidence, not the Phase E 100M gate.

- **Harness.** A new `scripts/bench-auto-chunk`, next to `scripts/bench-unified-slice`. It calls `run_pipeline` with default auto-chunk knobs (threshold 100,000, chunk size 50,000, so 20 chunks).
- **Workload.** B1's representative shape, generated exactly as follows. `rng = numpy.random.default_rng(20261001)`; `k = rng.integers(0, 10**9, size=1_000_000, dtype=numpy.int64)`; `ks = k.tolist()`; one `pa.table` built directly from Python strings (no pandas, so no schema metadata) with four null-free `string` columns, in this order, each built element-wise over `ks`: `email` = `[f"user{v:09d}@example.com" for v in ks]` (hash, namespace `bench_ns`), `secret` = `[f"secret-{v:09d}" for v in ks]` (redact), `zip` = `[f"{v:09d}" for v in ks]` (truncate, length 3), `ref` = `[f"keep-{v:09d}" for v in ks]` (passthrough). Global seed 42. The record states the source's raw Arrow size (`Table.nbytes`) for each configuration. 1M rows keeps the run well inside the devbox's shared memory cap of about 12 GB.
- **Configurations.** (a) dispatcher off; (b) dispatcher on, `native_threads=1`; (c) dispatcher on, `native_threads=4`; (d) the same table plus one unconfigured column `extra` = `[f"x{v:09d}" for v in ks]`, so B1 reroutes to its oracle route (`uncovered_columns`), on and off; (e) the workload rebuilt as `pa.Table.from_pandas(df, preserve_index=False)` from a frame with `df.attrs = {"bench": "b2"}`, on and off. Revision 3.1 used (e) to price the metadata-parity legacy fallback; that gate is gone, so (e) now shows that a pandas-origin source with schema metadata gets the dispatcher's speed. (d) measures what default-on B2 costs the jobs it does not speed up.
- **Method.** Each trial runs in a fresh subprocess, one at a time, with no other heavy test process on the box: either as a benchmark test under `/home/cam/bin/pytest-one`, or as a single script process that takes the same lock. Thread environment pinned (`native_threads` as above; `OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`). One warmup trial per configuration, discarded, then seven measured rounds. Each round runs every configuration once, in an order shuffled by a seeded RNG (seed and order recorded), so load or thermal drift spreads across configurations instead of landing on one. Reported per configuration: all seven wall times of the `run_pipeline` call, their p50 and their maximum (max-of-seven), and each trial's peak RSS. Seven samples cannot support a p95, so none is reported or gated here; a p95 bar needs at least 3 warmups and 20 measured trials and belongs to certification (Phase E). The record names the CPU, and the pyarrow, pandas, engine and companion versions.
- **Correctness-oracle isolation.** Generate each dispatcher-off reference in a separate, unmeasured subprocess. Every measured subprocess constructs the fixed-seed source, executes exactly one assigned configuration, captures its own `ru_maxrss` (`resource.getrusage(RUSAGE_SELF).ru_maxrss`, KiB on Linux, recorded in bytes) as soon as `run_pipeline` returns, and then writes its output (Arrow IPC) plus JSON evidence for the parent. The parent performs the correctness comparison against the reference outside every measured subprocess. Reference generation, reference loading, and cross-result comparison never contribute to a measured trial's RSS. The measured figure is whole-process on purpose: interpreter start, imports and source construction count toward the ceiling, because a production worker pays them too.
- **Correctness.** Every measured trial's output satisfies guarantee 3 against its configuration's dispatcher-off reference. For this all-string, null-free workload that means `Table.equals(reference)` (values, types and field nullability, schema metadata excluded) for every trial, and, on dispatcher-on trials, `schema.metadata is None` and each passthrough field equal to the source field with `check_metadata=True`. (b), (c) and (e) on report `native_admitted = true` with zero oracle fallbacks in `chunked_route`. A trial that fails any check fails the run.
- **Declared memory ceiling (before measuring).** 2.0 GiB peak RSS for every measured trial process, where GiB means 2 x 1024^3 bytes = 2,147,483,648 bytes. This is an absolute safety ceiling for this 1M-row workload, not a scaling claim: it says nothing about memory at other row counts or widths. Working default; Cam may adjust.
- **Bars.** (b), (c) and (e) on each have lower p50 and lower max-of-seven than their dispatcher-off run ((a) for (b) and (c)). Every measured trial stays under the ceiling. For (d), dispatcher-on p50 is at most 1.05 times dispatcher-off p50 (the cost of preflight and evidence on a rerouted table); the 1.05 factor is a working default Cam may adjust. Missing a bar stops for Cam, as the standing rule says.
- **Recording.** Each run gets the next benchmark run ID and a row in the sprint and testing ledger. The plan, CHANGELOG and docs quote a B2 speed figure only as "measured" with that run ID. This plan states no B2 speed figure.

## Known issues (tech debt, not blockers)

- **Route-dependent output shape (needs Cam).** Guarantee 3 makes the auto-chunk route's output differ from the full-frame and unified-slice routes, which still reproduce pandas (the unified slice rebuilds its output with `Table.from_pandas` to match full frame, `_unified_slice.py` lines 292 to 330). For one table, crossing `auto_chunk_threshold_rows` can therefore change a passthrough column's type (`large_string`, `time32`, `date64`, `time64[ns]`), its nullability and field metadata, an all-null string-output column's type, and whether `b"pandas"` schema metadata is present. Masked values do not change. Bringing full frame and the unified slice to the same Arrow-exact contract is a separate output change with its own plan.
- **Pre-existing on main, not caused by B2.** With the default `use_byte_estimate_routing=True`, `run_pipeline` raises `AttributeError` (`'datetime.date' object has no attribute 'encode'`) for a mask table with a `date32`, `date64`, `time32`, `time64` or time-zone-aware timestamp column, before routing, on every route: `_mem_estimate_schema.sample_average_string_bytes` treats every column whose profile dtype is not fixed-width as a string (probe `b2r4_tb2.out`; reproduced on the pre-A8 tree `9d7f86ec`). Those types reach auto-chunk only with `use_byte_estimate_routing=False` until it is fixed. It needs its own slice.
- Tables with unconfigured columns kept under the passthrough policy run on B1's oracle route (`uncovered_columns`). That is correct and visible in evidence, but many real configs leave columns unconfigured, so partial-mask jobs run wholly on pandas until program slice B8 admits unconfigured passthrough columns natively.
- A stored pandas index column (`__index_level_0__`) is dropped from the output on today's chunked lane, the dispatcher lane and full frame (probe), because the pandas adapter restores it as the index. B2 keeps that behavior.
- A read passthrough column (B1 rule R2) still goes through pandas on B1's oracle route; a value pandas refuses there raises B1's `chunked_passthrough_value_unrepresentable` where today's lane raised the raw exception. B1's R2 (b) over-approximation applies (a column named like any config string is read).
- Library callers get `native_threads=1` unless they pass a budget; platform and CLI pass reservations from B3, B4 and B5.
- The routed output is still fully materialized and concatenated; peak memory includes the whole output (B6a).
- `explain_plan` does not show the lane, because the B1 route depends on companion availability at run time; the run's own `quality_metrics` does.
