# F-audit: no-legacy generation compute audit (terminal Phase F slice)

## 0. Why

Phase F re-baselined generation onto a unified streaming core (FR0, `generation/_streamed.py`) with a route-independence contract (resident == streamed, byte-identical), a windowed_date column (FR1), and local 1M/10M capacity evidence (F4a). FR3 (Rust generation kernel selection) was SHELVED after it measured SLOWER than vectorized RNG, so generation computes every value on Python/numpy and NEVER on the Rust companion. F-audit is the mandatory terminal slice that PROVES, from a matrix DERIVED FROM THE DISPATCH PREDICATES (not observed dispositions), that each generation path runs on its classified compute backend and nowhere else, that generation makes ZERO compiled-companion calls BY DESIGN (observed at the deterministic-index entry, a guarded invariant not an accident), that admitted plans actually run on the CORE across both materialization routes, and that the production mixed route holds across the generate -> mask -> sink seam (the mask half cites D-audit; F-audit adds the generate side + the hand-off). The original program obligation "no fallback from a CLAIMED Rust generation backend" is INAPPLICABLE because FR3 shelved; its remaining obligations stay. Scope is the generation COMPUTE backend, its materialization route, and the seam; not the sink orchestration or the retained legacy whole-table oracle. No new compute path is built; no production behavior changes; no hard-deletes are planned (opportunistic only, graphify-traced; none expected).
