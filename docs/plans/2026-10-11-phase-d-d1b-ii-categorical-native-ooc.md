## 1. Why + what
The out-of-core route masks deterministic `categorical` by remapping each non-null source value onto the category pool in a pure-Python loop (`_mask_group_b.categorical_array`, uniform or weighted CDF). The compiled companion already carries the index kernel (`derive_index_batch`), and an existing native ext `native/_categorical_ext.native_categorical` already performs that remap through it (used by the native-chunked route). D1b-ii routes the OOC seam's categorical compute through that SAME ext when the companion is present and the column is eligible, so admitted OOC categorical runs on the compiled index kernel instead of the Python loop. No new Rust, no ABI change; `native_categorical` and the oracle handler are untouched.

This completes the D1 operator group (hash shipped as D1a, bucket_perturb as D1b-i). It reuses D1a's proven mechanism (per-column decision pinned at prep, index kernel loaded once and threaded, declined-with-reason + caller-visible disposition, insertion-boundary witness, abort-on-drift, predeclared perf) and the D1b-i lessons. Like hash and unlike bucket_perturb, categorical keys on arbitrary SOURCE text through the shared NFC canonicalization, so the accepted native-vs-Python Unicode-version difference (D1a / Cam 2026-10-11) applies and carries the same documentation + stability lock. Categorical has NO date arithmetic, so it has none of bucket_perturb's pandas-Timestamp range concern.

## 2. Scope
The OOC categorical compute has one entrypoint: `_mask_group_b.categorical_array`, reached from the Group-(b) mask dispatch in both streaming drivers' `mask_batch`/`mask_column` path. Only the DETERMINISTIC categorical is OOC-reachable (the compat gate rejects non-deterministic categorical as `out_of_core_categorical_nondeterministic_unsupported`; a non-det value reaching the seam is a wiring bug).

The native dispatch lives in the Group-(b) OOC ADAPTER, not inside `categorical_array` (which stays untouched); the adapter chooses native vs the oracle function per the pinned decision.

**IN (routed native when eligible):** dispatch to `native/_categorical_ext.native_categorical(array, categories, cdf, mask_key=job_seed, namespace, index_kernel, native_threads)` when ALL hold (decided once at prep, immutable for the run): (a) the companion loads and `load_compiled_index_kernel()` succeeds (abi-3); (b) the column is native-admissible per the SAME two-stage predicate the native-chunked route uses (`prepare_chunked_categoricals`): **stage A** config via `prepare_categorical(...)` (admits ONLY deterministic + namespaced + non-empty all-STRING categories + a buildable weight CDF) WITH the non-finite-weights exception boundary the chunked wrapper already applies (a NaN / infinity / overflowing weight sum escapes `_build_cdf` as a bare `ValueError`/`OverflowError`; catch it and decline, matching `_categorical_prepared.py:~88`, so it never crashes nor reaches native), AND **stage B** `source_is_string(schema, name)` (`_categorical_prepared.py:106` — the compiled index kernel's admitted categorical source is EXACTLY `pa.string()`). Both stages decline with a coded, value-free reason. The prepared `PreparedCategorical` (categories + cdf, prepared ONCE per run) and the pinned string source-type are captured at prep and threaded, with the loaded index kernel, into the native call. Uniform (`cdf is None`, pool = len(categories)) and weighted (`cdf` = `_build_cdf` output, pool = `_WEIGHTED_CDF_RES`, searchsorted) both covered. Nulls restore to None at position. Whole column takes ONE path, never half-native.

**Empty / all-null short-circuit:** `native_categorical` calls `derive_index_batch` UNCONDITIONALLY (an empty or all-null batch still invokes the kernel). So the OOC adapter short-circuits an empty or entirely-null batch AFTER prep + the pinned-schema check, returning `pa.nulls(len)` WITHOUT invoking `native_categorical` (no kernel call), and the native-call count accumulates the ACTUAL calls over the whole column.

**OUT for D1b-ii, EXPLICITLY DECLINED with a recorded caller-visible reason (Python `categorical_array` retained, unchanged):** companion absent/ABI-incompatible (`index_extension_unavailable`); any column stage A declines (non-string categories `categorical_categories_not_all_string`, unbuildable/invalid/non-finite weights `categorical_weights_*`, missing namespace, etc.); a NON-STRING SOURCE column declined by stage B `source_is_string` (date32, decimal, timestamp incl. the tz-aware NaT-sentinel case, and any non-string source — all of which the native path would hash/select differently or raise `native_type_not_admitted` while the Python path succeeds) with a value-free reason `categorical_source_not_string:{col}:{type}`. Non-deterministic categorical is not reachable OOC (compat gate), so it is not a D1b-ii decline case.

**Also out:** hash (D1a, merged) and bucket_perturb (D1b-i, separate); the `native_categorical_positional` variant (position-keyed, not OOC-reachable); SEQ route (D2); any change to the companion crate / ABI / native-chunked route; any change to OOC admission/routing; any change to `native_categorical`, `prepare_categorical`, or the oracle `categorical_array` themselves.

## 3. Eligibility, prepared state, pinning, output-type parity
The per-column native/declined decision is computed ONCE at run/table-prep from (a) the companion-load result (index kernel loaded once per run via `load_compiled_index_kernel()`, raising `index_extension_unavailable`, mirroring `_dispatch.py:508`) and (b) `prepare_categorical(...)` — the one authority for both eligibility AND the prepared pool/CDF. When eligible, the returned `PreparedCategorical` (categories + cdf) AND the pinned parity-safe source type (`pa.string()`, per stage B) are captured at prep and threaded, with the loaded index kernel, into the per-batch `native_categorical` call. The decision + prepared artifact + pinned source type are immutable for the run; no mid-stream backend switch. The source TYPE matters even though the output is the fixed string pool, because the keyed index derives from the source value and the native canonicalization admits only `string` (a date/decimal/timestamp source selects differently or raises `native_type_not_admitted` natively while the Python path succeeds). So each native batch validates its incoming source type against the pinned `pa.string()` and ABORTS the run on drift; a missing pinned column is rejected rather than silently skipped; a kernel fault aborts (sink abort, nothing committed). Per-batch == whole-column because the prepared categories/CDF are fixed for the run and the keyed index is per-value deterministic.

**Output-type parity.** `native_categorical` returns pinned `pa.string()` (categories are all-string by admission). The oracle OOC `categorical_array`'s analytic type is the category values' type (`pa.array(categories, from_pandas=True).type`), which for all-string categories is `pa.string()`; an empty or entirely-null output the oracle function yields as null-typed. So D1b-ii reconciles the native output to match the oracle categorical function's OWN behavior: empty OR all-null output becomes `pa.nulls(len)`, otherwise `pa.string()` (this is the categorical function's data-dependent null-shape, NOT the separate bucket_perturb `_chunk_masking` rule). Applied on the OOC native path before resident assembly (sink reconciliation separate), preserving the existing field/schema assembly semantics so the strict D0 comparator (type_width + field_metadata + null-vs-NaN) sees byte-identical schema and cells. A null position restores to null; it is never label-aligned.

**NFC / accepted divergence (shared with hash).** The keyed index derives from the NFC-canonicalized SOURCE value (`derive_index_batch` canonicalizes like `derive`). For a source value containing a codepoint assigned in a Unicode version newer than the running Python's, the native (Rust) and Python canonicalizations can differ, so the selected category can differ — the SAME accepted difference as hash (Cam 2026-10-11): native is canonical, documented in `docs/strategies.md` (categorical) + the `compatibility-contract.md` 3.3 note, characterized and version-guarded by the same lock-test D1a added. Shared-version source text selects identically on both paths.

## 4. Caller-visible disposition (program §5)
Reuse the per-column disposition channel D1a added on `ExecutionResult.quality_metrics` (threaded through both drivers + resident/sink returns, visible via `run_pipeline`), extended to categorical: a per-column entry keyed by table + column, truthful executed backend + (when declined) reason. Native = `rust_companion`. The declined path runs the Python `categorical_array` loop (a per-value Python selection, neither the pandas oracle route nor an Arrow kernel); label it `python_scalar` (the token D1a added for the OOC Python per-value loop; the same shape applies here). Reason codes are value-free (strategy/column/type + the `prepare_categorical` coded reasons, which carry the column name only). `derive_index_batch` call accumulation is over the WHOLE column (an empty / all-null batch made zero calls and must not overwrite an earlier native execution with `none`); distinguish native-idle evidence from an executed declined path.

## 5. Behavior-preservation + parity contract
1. **Byte-identical output:** for every eligible categorical cell, native output is byte-identical to the Python `categorical_array` reference (same keyed index into the same pool/CDF), nulls restored to null at position, for shared-Unicode-version source input.
2. **Oracle parity:** OOC native categorical is strict-equal (D0 `_strict_compare`, modulo frozen D0 gaps) to the pandas oracle on a payload categorical column and an FK-chain table's categorical column, uniform AND weighted, with output-type reconciliation (§3).
3. **Per-batch == whole-column** (fixed prepared pool/CDF; per-value deterministic), **Never half-native** (pinned at prep; abort on fault/missing-column).
4. **No silent fallback (§5):** every categorical column is {native + witness + `rust_companion`} OR {`categorical_array` + `python_scalar` + a caller-visible reason}; no capability regression on a no-companion install.
5. **NFC accepted divergence** documented + lock-tested (§3), native canonical.
6. **Witness:** native categorical proves native-result-CONSUMED at the insertion boundary, spies ported to the ACTUAL categorical binding (not the hash/scalar entrypoint), using the kernel-call count to avoid a vacuous claim on an empty/all-null column; declined reports the Python path. No existing test weakened; `native_categorical`/`prepare_categorical`/`categorical_array` untouched.

## 6. Acceptance tests (land the contract test first)
- **Declined, companion absent (ci-mirror):** OOC categorical succeeds; output byte-identical to the pinned pre-D1b-ii Python baseline; disposition = `python_scalar` + `index_extension_unavailable`; witness = Python-path-only.
- **Declined, stage A config rejects (companion present):** a non-string-category column reports `categorical_categories_not_all_string` and stays Python; an invalid-weights column reports the matching `categorical_weights_*`; a NaN / infinite / overflowing-sum weight declines via the non-finite boundary (not a crash) and the oracle raises its identical error where it would (assert on the config-error path, NOT on a successful ExecutionResult).
- **Declined, stage B non-string source (companion present):** a `date32`, a `decimal128`, and a tz-aware `timestamp` source each report `categorical_source_not_string` and stay Python, matching the Python baseline (these are the cases the native path would select differently or raise `native_type_not_admitted` on); a source-type DRIFT between the pinned `pa.string()` prep and a later batch aborts the run with sink abort and no commit.
- **Native, companion present (abi-3 venv):** output strict-equal to the oracle (D0 comparator, with output-type reconciliation) AND equal to the Python reference, for BOTH uniform and weighted (incl. a weight distribution exercising the CDF/searchsorted path) categorical; nulls restore to null; per-batch == whole-column; disposition = `rust_companion`.
- **Accepted-divergence + stability (shared with hash):** a normalization-sensitive post-Python-version source value with a fixed key/pool CHOSEN so the two canonicalizations derive a DIFFERENT selected category (modulo reduction + weighted bands can otherwise mask a different derived index, so the fixture must expose it) asserts native != Python (the accepted difference), asserted SEPARATELY from a fixed native-selection lock; shared-version source selects identically on both paths; the dependency/table-version guard asserts the resolved Unicode-table version.
- **Boundary:** empty / all-null column reconciles to null-typed via the adapter short-circuit with ZERO kernel calls (truthful evidence, no `native_categorical` invocation); BOTH a populated batch followed by an all-null batch (the all-null must not overwrite the earlier native claim with `none`) AND an all-null batch followed by a populated batch; multi-batch column (multi-call attribution accumulates over the column); ABI-incompatible companion load declines with `index_extension_unavailable`; a missing pinned column is rejected; a kernel fault aborts with sink abort and no commit.
- **Witness:** insertion-boundary attribution on the categorical binding with table/column/call context; a negative control where the native result is DISCARDED and an equal-valued Python array emitted MUST FAIL the native-consumed assertion; loader self-test excluded.
- **Performance gate (program §8, PREDECLARED):** isolated-process micro-benchmark, native vs Python `categorical_array`, on a FROZEN seeded workload: 5,000,000 rows of a utf8 source column over a fixed 12-category weighted pool, fixed ~5% null fraction; batch 65,536; native threads = 4; 7 measured native rounds (1 warmup) + 3 Python rounds (coarse p95 disclosed); timing wraps the mask pass only; output fully consumed. Memory gate = TOTAL process peak RSS <= 1,024 MiB (baseline/delta separate). Acceptance = native p50 strictly less than Python p50 AND native total peak RSS <= 1,024 MiB. 100M/200M proofs remain D4c.
