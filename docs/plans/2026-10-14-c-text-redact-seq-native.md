# text_redact native on the sequential route

Rules consulted: dev-rules `00-universal.md`, `risk-and-exceptions.md`, `development-loop.md`, `autonomous-operation.md`, `architecture.md`; engine `CLAUDE.md` (established-methodology, module size, pre-GA hard delete, explain-why comments). Grounding: a 2026-10-14 FRAME (measured text_redact ~2.16x / ~450s per 10M on the realistic ASCII profile via the already-shipped compiled kernel, vs ~970s on the Python oracle); the maximize-Rust directive + the north-star bar "every mask/gen combo runs 10M rows in sub-10-min" ([[decoy-rust-fast-path-everything]]); the SEQ-native descriptor framework (hash/fpe/categorical/bucket_perturb/date_shift/faker). Base: engine `origin/main` @ `db0c74b3`.

## 0. Why + scope
The compiled text_redact kernel ALREADY exists and ships (`native/_text_redact_kernel.py` + `decoy-engine-native/src/text_redact.rs`): `native_text_redact(array, *, detectors, token, label_token) -> pa.Array` (`native/_kernels_scalar.py:137`) routes the 8 lookaround-free detectors through Rust for ASCII-safe cells and replays the 3 lookaround detectors / non-ASCII cells / companion-absent case in Python, byte-identical to the oracle's `iter_spans`+`_splice` always. It runs on the CHUNKED and FULL-FRAME routes today (`_chunk_masking.py:202`, `physical/_shadow_operators.py:363`), where it clears the 10M/<600s bar.

**The gap:** the SEQUENTIAL (SEQ / multi-table FK) route has NO text_redact descriptor — a text_redact PAYLOAD column on an FK job runs the Python oracle handler (`_strategies/_text_redact.py`, per-cell `iter_spans`+`_splice`, ~970s/10M → busts the bar). This slice wires the EXISTING kernel onto the SEQ seam as the 7th payload tenant. **No new Rust and the kernel is unchanged**, but it does introduce a new SEQ transport/assembly boundary (resolved-config transport + the Arrow→list→object-Series hand-off), which the acceptance harness covers — pure SEQ wiring + admission + byte-parity tests.

**In scope:** text_redact PAYLOAD columns on the SEQ route take `native_text_redact` when the companion is present and the config is native-eligible. text_redact is `DETERMINISTIC_NO_DRAW` and non-injective, so there is no native key derivation / REMAP path (unlike hash/fpe). text_redact is never admitted as a NATIVE FK key; a text_redact column configured ON an FK key hits the existing non-key-eligible decline path in `prepare_table` (`_sequential_native.py:241` `_key_declines`), exactly like categorical/bucket_perturb/date_shift — no new key machinery, and an acceptance fixture pins that decline (rev 2 MED: "never an FK key" was too absolute).
**Out of scope / DECLINE to the Python handler (byte-identical oracle output):** `ner: true/{...}` (`text_redact_ner_not_native` — spaCy per-cell, documented permanent Python exception), a non-string token (`text_redact_token_not_string`), malformed detectors (`text_redact_detectors_malformed`), a non-string source (`text_redact_source_type_not_string`), and no companion. NOT in scope (parity dead-ends the FRAME flagged, do NOT attempt): lookaround detectors in Rust (regex crate has no lookaround) and non-ASCII detection in Rust (Python `re` vs regex-crate Unicode-class dialect) — both already handled per-cell inside `native_text_redact` and must stay that way.

## 1. Risk
R2 (privacy-relevant masking). text_redact output must stay byte-identical to the Python oracle. The kernel + splice + merge are ALREADY byte-parity-proven on the chunked/full-frame routes (C6c-i/C6c-ii); this slice reuses `native_text_redact` unchanged, so SEQ parity is the same kernel vs the same oracle. Acceptance compares SEQ-native to the full-frame oracle on the strict 9-dimension contract + a SEQ-native witness.

## 2. The code change
- **TextRedactCall + the SEQ admission adapter** (`_sequential_native_ops.py`): a `TextRedactCall` payload carrying `detectors: tuple[str,...] | None`, `token: str`, `label_token: bool`. **CRITICAL config transport (rev 2 MED):** these are the handler's RESOLVED values — in particular `detectors=None` means ALL detectors (the handler resolves an empty/absent selection to `None` at `_text_redact.py:114`), whereas the kernel treats `()` as ZERO detectors. The seam MUST pass the handler's resolved `None` through as `None` and NEVER substitute `()` for "all", or a column silently masks nothing. No kernel object travels (`native_text_redact` self-loads).
  - A `text_redact_op` `NativeOp` (disposition `SEQ_TEXT_REDACT_DISPOSITION_KEY = "sequential_text_redact"`). **`load_kernel` is a thin adapter `_load_text_redact(native_threads)` (rev 2 HIGH):** the SEQ seam calls `op.load_kernel(self._native_threads)` with one arg (`_sequential_native.py:203`), but `load_text_redact_kernel` takes ZERO args (`_text_redact_kernel.py:101`), so a direct assignment raises `TypeError` and aborts table preparation. The adapter ignores `native_threads`, calls the zero-arg loader, and preserves its `None` (companion-absent) result — so `_admitted`'s `bound is None` check remains the companion-present gate, consistent with the other tenants.
  - `admit` composes the real predicates from the `ColumnSeed`: `text_redact_config_rejection(name, provider_config)` (NER / non-string-token / malformed-detectors) + `string_source_type_rejection("text_redact", column, schema)` for the source type.
  - `apply` returns `NativeResult(native_text_redact(array, detectors=call.detectors, token=call.token, label_token=call.label_token))` (rev 2 LOW: `NativeOp.apply` returns `NativeResult`, not a bare `pa.Array`, `_sequential_native_ops.py:104`).
- **bespoke `text_redact_column` method** (`_sequential_native.py`, mirroring `bucket_column`/`faker_column`): the handler resolves detectors/token/label_token and passes them in; `gate = self._admitted(ctx, column, TEXT_REDACT, len(df))`; on None return None (Python handler runs, byte-identical); else pin the column's Arrow array, call the op's apply, book `decision.native_calls += 1`, return `result.values.to_pylist()`. No preserve/row-error/key machinery. NOTE: `native_text_redact` internally re-loads the kernel (redundant with the `_admitted` gate's load, not a defect) and replays ineligible cells in Python within one column — the established byte-parity design; the SEQ path reports `rust_companion` whenever the kernel is loaded, exactly as the chunked route does.
- **handler seam** (`_strategies/_text_redact.py`): the hook sits AFTER the handler's own config-validation early-returns (non-string token `:68`, malformed detectors `:125`) and after detector resolution, just before the per-cell Python loop (around `col = df[column]`, `:127`), so those config-error returns keep their EXISTING handler behavior and never reach the SEQ seam (rev 2 MED-2: they are not SEQ-native declines and must not be asserted as `python_scalar`). Add `seq = getattr(ctx, "seq_native", None)` (mirroring `_faker.py`/`_categorical.py`): `if seq is not None: picked = seq.text_redact_column(ctx, df, column, detectors=<resolved>, token=<resolved>, label_token=<resolved>); if picked is not None: df[column] = pd.Series(picked, index=df.index, dtype=object); return df, []`. The `<resolved detectors>` is exactly the handler's resolved value (None = all, per `:114`). On None, fall through to the existing Python oracle loop unchanged.
- **register text_redact in `_OPS`.** NOT added to `_KEY_STRATEGIES` (payload-only; a text_redact FK key is not a real shape, but the key-eligibility gate already excludes it).
- **faker disposition-style evidence**: the text_redact entry reports `native_calls` so the witness and the empty/all-null evidence are truthful (reuse the faker rendering path in `_sequential_native_decisions.py`).

## 3. Acceptance matrix (the spec)
Each masking cell runs full-frame oracle vs SEQ-native (companion) vs SEQ-python-fallback (companion hidden), asserts `tests/parity/_strict_compare.compare_strict == _ALL_TRUE` (output tables), with a SEQ-native-specific witness (`native_calls > 0` under `SEQ_TEXT_REDACT_DISPOSITION_KEY`) and warnings on their own channel. Detector fixtures drawn from the real detector set (email, us_phone, pan/iban/ipv4/icd10/npi/url = Rust-eligible; ssn/us_zip/street_address = lookaround/Python).
- **T1 Rust-eligible detectors, ASCII payload** (email/phone/pan/etc.): SEQ-native byte-identical to the oracle; witness non-vacuous; across row counts incl. all-null and empty.
- **T2 lookaround detectors (ssn/us_zip/street_address)**: still runs the native path (kernel loaded) but replays these per-cell in Python inside `native_text_redact`; SEQ-native output byte-identical to the oracle.
- **T3 non-ASCII cells mixed with ASCII** (eligible-per-cell split): the ineligible cells replay in Python, eligible cells go Rust; whole-column byte-identical to the oracle (the C6c-ii per-cell domain gate, exercised on SEQ).
- **T4 SEQ-seam declines (reach the hook, decline to the Python oracle, byte-identical, `native_calls == 0`)**: (a) `ner:true` → admission reason `text_redact_ner_not_native`, disposition `python_scalar`; (b) non-string source → `text_redact_source_type_not_string`, `python_scalar`; (c) no companion (ci-mirror) → `_admitted` returns None via the `bound is None` gate, the Python handler runs byte-identical. Assert the disposition/reason for (a)(b) and the companion-absent path for (c).
- **T4b handler-level config errors (do NOT reach the SEQ seam; rev 2 MED-2)**: non-string token (`_text_redact.py:68`) and malformed detectors (`:125`) early-return in the handler BEFORE the hook. Assert their behavior is UNCHANGED from today (the handler's existing early-return output), NOT that they render a `python_scalar` SEQ decline — the seam is never consulted for them.
- **T5 nulls + empty/all-null**: nulls preserved (null-in/null-out), strict parity incl. `null_vs_nan`; an empty table and an all-null column report truthful evidence (native_calls 0 for empty, per the handler path).
- **T6 mixed job + §4 routing**: a text_redact payload column native beside a hash payload and a faker payload on one FK table → each reports under its own disposition key, no cross-contamination; AND the §4 routing dispositions for a text_redact-bearing table: estimate-FIT → **full-frame oracle (pandas; unified admission REJECTS relationships at `_unified_slice_admission.py:249`, so full-frame FK is NOT the native physical lane — rev 2 routing note)**, non-fit/unpriceable → SEQ (native witness), flag-off threshold routing, override.
- **T7 determinism**: text_redact is deterministic (no draw); same job twice → identical output (the kernel + splice are pure functions of text + detectors + token).
- **T8 config transport (rev 2 MED-3, the new seam's highest-risk cases)**: prove the resolved config reaches the kernel intact, with a SPY on the compiled candidate calls (not just the `native_calls` counter):
  - **absent / null / empty detector selection** with a payload that DOES contain PII the full set would catch → must mask ALL (resolved `None` = all detectors), NOT nothing (guards the `None`-vs-`()` trap);
  - a real detector SUBSET → masks only those detectors;
  - a **custom token** and an **empty token**;
  - **`label_token=True`**;
  - a **`when:`-gated selection with a gapped (non-contiguous) index** (`_when_gate.py:249` hands the handler a subset frame) → byte-identical to the oracle on the selected rows;
  - a **zero-match** column → unchanged output, witness still shows the kernel ran.
- **T_key text_redact on an FK key declines**: a text_redact column configured as an FK key records the existing non-key-eligible decline (`_key_declines`, `_sequential_native.py:241`); a text_redact PAYLOAD column on the same job still runs native. Proves text_redact did not leak into native key derivation.

## 4. Failure modes (reproduce, do not smooth)
- Passing `()` instead of the resolved `None` for an empty detector selection → the column masks NOTHING instead of everything → T8 (the `None`-vs-`()` trap, the single highest-risk defect).
- Assigning `load_text_redact_kernel` directly as `load_kernel` → `TypeError` on `op.load_kernel(native_threads)`, aborting table prep → the `_load_text_redact(native_threads)` adapter (rev 2 HIGH).
- A non-ASCII or lookaround cell silently diverging from the oracle → T2/T3 (the per-cell Python replay must be exact; the shipped kernel's own contract, re-asserted on SEQ).
- NER or a non-string source silently going native → T4 (must decline to the Python handler); a non-string token / malformed detectors wrongly routed as a SEQ decline instead of the handler's existing early-return → T4b.
- A companion-absent SEQ run diverging from the companion-present run → T4(c) (both must equal the oracle; `native_text_redact` self-falls-back).
- Null/empty-column type drift at the SEQ boundary → T5.
