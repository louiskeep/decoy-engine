# text_redact native on the sequential route

Rules consulted: dev-rules `00-universal.md`, `risk-and-exceptions.md`, `development-loop.md`, `autonomous-operation.md`, `architecture.md`; engine `CLAUDE.md` (established-methodology, module size, pre-GA hard delete, explain-why comments). Grounding: a 2026-10-14 FRAME (measured text_redact ~2.16x / ~450s per 10M on the realistic ASCII profile via the already-shipped compiled kernel, vs ~970s on the Python oracle); the maximize-Rust directive + the north-star bar "every mask/gen combo runs 10M rows in sub-10-min" ([[decoy-rust-fast-path-everything]]); the SEQ-native descriptor framework (hash/fpe/categorical/bucket_perturb/date_shift/faker). Base: engine `origin/main` @ `db0c74b3`.

## 0. Why + scope
The compiled text_redact kernel ALREADY exists and ships (`native/_text_redact_kernel.py` + `decoy-engine-native/src/text_redact.rs`): `native_text_redact(array, *, detectors, token, label_token) -> pa.Array` (`native/_kernels_scalar.py:137`) routes the 8 lookaround-free detectors through Rust for ASCII-safe cells and replays the 3 lookaround detectors / non-ASCII cells / companion-absent case in Python, byte-identical to the oracle's `iter_spans`+`_splice` always. It runs on the CHUNKED and FULL-FRAME routes today (`_chunk_masking.py:202`, `physical/_shadow_operators.py:363`), where it clears the 10M/<600s bar.

**The gap:** the SEQUENTIAL (SEQ / multi-table FK) route has NO text_redact descriptor — a text_redact PAYLOAD column on an FK job runs the Python oracle handler (`_strategies/_text_redact.py`, per-cell `iter_spans`+`_splice`, ~970s/10M → busts the bar). This slice wires the EXISTING kernel onto the SEQ seam as the 7th payload tenant. **No new Rust, no new parity surface** — pure SEQ wiring + admission + a byte-parity test harness.

**In scope:** text_redact PAYLOAD columns on the SEQ route take `native_text_redact` when the companion is present and the config is native-eligible. text_redact is `DETERMINISTIC_NO_DRAW`, non-injective, and NEVER an FK key, so there is no key/REMAP path (unlike hash/fpe) — the simplest tenant.
**Out of scope / DECLINE to the Python handler (byte-identical oracle output):** `ner: true/{...}` (`text_redact_ner_not_native` — spaCy per-cell, documented permanent Python exception), a non-string token (`text_redact_token_not_string`), malformed detectors (`text_redact_detectors_malformed`), a non-string source (`text_redact_source_type_not_string`), and no companion. NOT in scope (parity dead-ends the FRAME flagged, do NOT attempt): lookaround detectors in Rust (regex crate has no lookaround) and non-ASCII detection in Rust (Python `re` vs regex-crate Unicode-class dialect) — both already handled per-cell inside `native_text_redact` and must stay that way.

## 1. Risk
R2 (privacy-relevant masking). text_redact output must stay byte-identical to the Python oracle. The kernel + splice + merge are ALREADY byte-parity-proven on the chunked/full-frame routes (C6c-i/C6c-ii); this slice reuses `native_text_redact` unchanged, so SEQ parity is the same kernel vs the same oracle. Acceptance compares SEQ-native to the full-frame oracle on the strict 9-dimension contract + a SEQ-native witness.

## 2. The code change
- **TextRedactCall + the SEQ admission adapter** (`_sequential_native_ops.py`): a `TextRedactCall` payload carrying `detectors: tuple[str,...] | None`, `token: str`, `label_token: bool` (the handler's resolved config; no kernel object travels — `native_text_redact` self-loads). A `text_redact_op` `NativeOp` (disposition `SEQ_TEXT_REDACT_DISPOSITION_KEY = "sequential_text_redact"`) whose `load_kernel` is `load_text_redact_kernel` (so `_admitted`'s `bound is None` check becomes the companion-present gate, consistent with the other tenants) and whose `admit` composes the real predicates: `text_redact_config_rejection` (NER / token / detectors) + `string_source_type_rejection("text_redact", ...)` for the source type. `apply` calls `native_text_redact(array, detectors=call.detectors, token=call.token, label_token=call.label_token)` and returns the `pa.Array`.
- **bespoke `text_redact_column` method** (`_sequential_native.py`, mirroring `bucket_column`/`faker_column`): `gate = self._admitted(ctx, column, TEXT_REDACT, len(df))`; on None return None (Python handler runs, byte-identical); else pin the column's Arrow array, call the op's apply, book `decision.native_calls += 1`, return `result.to_pylist()`. No preserve/row-error/key machinery (text_redact has none). NOTE: `native_text_redact` internally re-loads the kernel and replays ineligible cells in Python within one column — that is the established byte-parity design; the SEQ path is "native" (disposition rust_companion) whenever the kernel is loaded, exactly as the chunked route reports it.
- **handler seam** (`_strategies/_text_redact.py`): after config resolution and before the per-cell Python loop (around the `col = df[column]` point, `:127`), add the `seq = getattr(ctx, "seq_native", None)` hook (mirroring `_faker.py`/`_categorical.py`): `if seq is not None: picked = seq.text_redact_column(ctx, df, column, <resolved detectors/token/label_token>); if picked is not None: df[column] = pd.Series(picked, index=df.index, dtype=object); return df, []`. On None, fall through to the existing Python oracle loop unchanged.
- **register text_redact in `_OPS`.** NOT added to `_KEY_STRATEGIES` (payload-only; a text_redact FK key is not a real shape, but the key-eligibility gate already excludes it).
- **faker disposition-style evidence**: the text_redact entry reports `native_calls` so the witness and the empty/all-null evidence are truthful (reuse the faker rendering path in `_sequential_native_decisions.py`).

## 3. Acceptance matrix (the spec)
Each masking cell runs full-frame oracle vs SEQ-native (companion) vs SEQ-python-fallback (companion hidden), asserts `tests/parity/_strict_compare.compare_strict == _ALL_TRUE` (output tables), with a SEQ-native-specific witness (`native_calls > 0` under `SEQ_TEXT_REDACT_DISPOSITION_KEY`) and warnings on their own channel. Detector fixtures drawn from the real detector set (email, us_phone, pan/iban/ipv4/icd10/npi/url = Rust-eligible; ssn/us_zip/street_address = lookaround/Python).
- **T1 Rust-eligible detectors, ASCII payload** (email/phone/pan/etc.): SEQ-native byte-identical to the oracle; witness non-vacuous; across row counts incl. all-null and empty.
- **T2 lookaround detectors (ssn/us_zip/street_address)**: still runs the native path (kernel loaded) but replays these per-cell in Python inside `native_text_redact`; SEQ-native output byte-identical to the oracle.
- **T3 non-ASCII cells mixed with ASCII** (eligible-per-cell split): the ineligible cells replay in Python, eligible cells go Rust; whole-column byte-identical to the oracle (the C6c-ii per-cell domain gate, exercised on SEQ).
- **T4 declines (stay Python handler, coded reason, output still oracle-parity)**: (a) `ner:true` → `text_redact_ner_not_native`; (b) non-string token → `text_redact_token_not_string`; (c) malformed detectors → `text_redact_detectors_malformed`; (d) non-string source → `text_redact_source_type_not_string`; (e) no companion (ci-mirror) → the column runs the Python handler (byte-identical). Assert disposition `python_scalar` + the coded reason (or companion-absent path) and `native_calls == 0`.
- **T5 nulls + empty/all-null**: nulls preserved (null-in/null-out), strict parity incl. `null_vs_nan`; an empty table and an all-null column report truthful evidence (native_calls 0 for empty, per the handler path).
- **T6 mixed job + §4 routing**: a text_redact payload column native beside a hash payload and a faker payload on one FK table → each reports under its own disposition key, no cross-contamination; AND the §4 routing dispositions for a text_redact-bearing table (estimate-FIT → full-frame oracle [already native there], non-fit/unpriceable → SEQ [native witness], flag-off threshold routing, override). text_redact is payload-only so there is no FK-key cell.
- **T7 determinism**: text_redact is deterministic (no draw); same job twice → identical output (the kernel + splice are pure functions of text + detectors + token).

## 4. Failure modes (reproduce, do not smooth)
- A non-ASCII or lookaround cell silently diverging from the oracle → T2/T3 (the per-cell Python replay must be exact; it is the shipped kernel's own contract, re-asserted on SEQ).
- NER or a non-string token silently going native → T4 (must decline to the Python handler).
- A companion-absent SEQ run diverging from the companion-present run → T4(e) (both must equal the oracle; `native_text_redact` self-falls-back).
- Null/empty-column type drift at the SEQ boundary → T5.
