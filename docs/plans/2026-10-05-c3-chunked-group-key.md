## 3. The group_key-specific decisions

**3a. Order-dependence gate (the key correctness piece): native admits only an UNMASKED-passthrough sibling.** The oracle reads the `group_by` column AT group_key's position in `order_work` (`_runner.py:179-195`), so it may read a POST-mask value if another node masks the sibling earlier. `_mask_chunk_native` masks from the raw `chunk` and never feeds a masked column back, so a masked sibling would silently diverge. Full-frame native already handles this by DECLINING when the sibling is masked by another non-passthrough node (`_unified_slice_admission.py:481`); the sibling must be an unmasked passthrough. C3 copies that exact gate to the chunked leg (decline -> oracle leg, which reads the effective post-mask value correctly). A self-anchor (`group_by` == the group_key column itself) is non-passthrough -> declines. DECISION: copy the full-frame gate (option a); do NOT model the effective-input dependency on the native leg (overbuild for v1). REASON SHAPE (the full-frame gate returns only a boolean, so C3 defines the codes): a masked sibling emits `group_key_masked_sibling_not_native_chunked_route:<target>:<sibling>` (both names, for diagnostics); a self-anchor emits a DISTINCT `group_key_self_anchor_not_native_chunked_route:<target>`. Both route to the oracle leg.

**3b. Type domain: native admits `{string, int64, bool}` (match full-frame native); wider oracle-safe types stay on the oracle leg. This narrow gate is a LOAD-BEARING collision-free precondition (BLOCKER 1), not a convenience.** The oracle chunked leg admits a wider `group_by_type_is_safe` set (EVERY integer width, bool, string, large_string, date, timestamp, safe dictionary value types; floats/decimals excluded by Trap E, `_chunked_group_key.py:95`). v1 matches the full-frame NATIVE domain `{string, int64, bool}` exactly (`_operator_config_rejections.py:184-196`) because that domain is provably collision-free for the raw-value cache; a wider oracle-safe group_by (int32, uint64, dictionary<string>, large_string, date, timestamp) DOWNGRADES to the oracle chunked leg (NOT fail-closed, the C1b-ii lesson), reproducibly. Widening the native domain is a deferred follow-up (C3-widen); not in C3. Real-type gate on the FIRST chunk + a group_key-SPECIFIC per-chunk drift check: it ACCEPTS either the first chunk's admitted sibling type OR a raw `pa.null()` chunk (per 3b-null, a later null-typed sibling MUST succeed), and lets the existing general schema check reject every OTHER non-null drift. Do NOT mirror `bucket_perturb_gate` literally -- that gate accepts only string/large_string and REJECTS raw `pa.null()` before casting (`_chunked_bucket_perturb.py:68,101`), which would contradict acceptance 5b.

**3b-null. Later null-typed sibling chunk: read the RAW pre-cast sibling (BLOCKER 2).** The native entry loop casts a later null-typed chunk to the first chunk's type before masking, which diverges from the oracle's raw-chunk stringification (`"<NA>"` vs `"None"`), and `cast_null_columns` strips the sibling's pandas metadata. FIX (strict parity, NO oracle change): the group_key branch reads the sibling from the RAW (pre-cast) chunk -- `native_group_key(raw_chunk.select([group_by]))` -- preserving the sibling's `b"pandas"` metadata even when an unrelated column requires casting, so null stringifies identically to the oracle (`"None"` for the raw object/null dtype). This requires threading the RAW chunk (not just the cast table) into the group_key branch of `_mask_chunk_native`. Do NOT alter the oracle leg.

**3c. Raw-hex kernel preflight probe, threaded + downgrade (group_key uses a different kernel).** group_key uses `load_compiled_raw_hex_kernel` (`_group_key_ext.py`), NOT the index kernel, so it does NOT go in `_INDEX_KERNEL_STRATEGIES` (`_dispatch.py:78`). Preflight (`_dispatch.py:431-445`) today loads only the crypto (hash) and index kernels, and `NativePreflight` carries only the index kernel (`_dispatch.py:293`); C3 adds a THIRD probe AND a new `NativePreflight.raw_hex_kernel` field, THREADED through `_native_route` -> `_mask_chunk_native` so the per-chunk operator does not reload/self-test it. On abi-mismatch/missing `derive_hex_raw_batch`, downgrade the TABLE to the oracle leg with a coded reason (`raw_hex_extension_unavailable`, mirror `index_extension_unavailable`). Native chunk call takes the RAW-chunk sibling slice `raw_chunk.select([group_by])` (per 3b-null; preserving field name + `b"pandas"` metadata), NOT `chunk.column(name)` (which `_mask_chunk_native` uses for every other branch); namespace is the synthesized `f"group_key/{name}"`; `length`/`prefix` from `provider_config`. No row-error channel (group_key cannot produce a format error). EMPTY-input handling: `native_group_key` runs the kernel unconditionally today (`_group_key_kernel.py:120`); add a backward-compatible optional `derive_calls` spy param (preserving the `pa.Array` return shape) AND short-circuit empty input BEFORE the raw-kernel call, so an empty chunk reports idle truthfully (`derive_calls == 0`, `arrow_python`).
