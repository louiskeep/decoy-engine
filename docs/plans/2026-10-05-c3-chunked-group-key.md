**NO new Rust, NO new kernel, NO cross-chunk state.** The research (2026-10-05 probe) is definitive: group_key is VALUE-KEYED. Each row's output is a pure function of `(mask_key, "group_key/<column>", str(group_by cell))` via `derive` (HKDF-SHA256/HMAC), with a per-call memoisation cache that is NOT accumulated state. Two rows in the same group get the same output because they hash the same bytes, so a per-chunk pass equals full-frame WITHOUT seeing other chunks. The program line "(cross-chunk sibling state)" is a misnomer: the only "sibling" is another column of the SAME row, always in the same chunk. The native kernel (`native/_group_key_kernel.py:86`, loaded via `native/_group_key_ext.py:load_compiled_raw_hex_kernel`) already exists and runs full-frame today.

**NOT a C1b-ii-class regression.** group_key already reaches the chunked route on the oracle leg: `CHUNK_SIBLING_KEYED_STRATEGIES = {"group_key"}` (`_chunked_group_key.py:~83`) feeds `_CHUNK_ADMITTED_STRATEGIES` (`_chunked.py:186-188`). C3 only moves the native-admissible case from the oracle leg to the native leg, with identical behavior. Per the C1b-ii lesson, C3 adds an auto-router end-to-end test to CONFIRM no success/failure change, and routes every non-native-admissible case to the oracle leg (never fail-closed).

## 1. Goal and scope

group_key is the ONLY strategy still in the native chunked-route veto set (`CHUNKED_ROUTE_VETOED_STRATEGIES == frozenset({"group_key"})`, `native/_requirements.py:151`), so a group_key column currently runs the pandas-ORACLE chunked leg. C3 makes native-admissible group_key run the native kernel per chunk, byte-and-type-identical to the oracle chunked leg, keyed by the row's own group_by-cell value.

Native-admissible group_key (match the full-frame native domain, `_operator_config_rejections.py:195-247`, `_unified_slice_admission.py:441-473`): `group_by` is a non-empty string naming another column; `length` even in [8,64]; `prefix` any; the group_by SIBLING column has Arrow type in `{string, int64, bool}` (the full-frame native domain, `_NATIVE_GROUP_KEY_SIBLING_TYPES`); the sibling is an UNMASKED passthrough (the order-dependence gate, §3a); no `when:`; group_key is not an FK key. Everything else (wider oracle-safe group_by types, masked sibling, self-anchor, when:, FK key) stays on its existing path (oracle leg or declined) unchanged.

Out of scope (unchanged): wider group_by types on the NATIVE leg (date/timestamp/large_string are oracle-safe and stay on the oracle leg in v1, §3b -- widening is a deferred follow-up); float/decimal group_by (Trap E rejects, `_chunked_oracle.py:201`); `when:` group_key (Trap D, `_chunked.py:304`); FK-key group_key (stays rejected, not in CHUNK_SAFE); multi-column group_by (not supported; group_by is a single string); the full-frame route; the out-of-core route (`out_of_core/_compat.py:24` `_CROSS_ROW_STRATEGIES`, untouched).

## 3. The group_key-specific decisions

**3a. Order-dependence gate (the key correctness piece): native admits only an UNMASKED-passthrough sibling.** The oracle reads the `group_by` column AT group_key's position in `order_work` (`_runner.py:179-195`), so it may read a POST-mask value if another node masks the sibling earlier. `_mask_chunk_native` masks from the raw `chunk` and never feeds a masked column back, so a masked sibling would silently diverge. Full-frame native already handles this by DECLINING when the sibling is masked by another non-passthrough node (`_unified_slice_admission.py:470-473`); the sibling must be an unmasked passthrough. C3 copies that exact gate to the chunked leg (decline -> oracle leg, which reads the effective post-mask value correctly). A self-anchor (`group_by` == the group_key column itself) is non-passthrough -> declines. DECISION: copy the full-frame gate (option a); do NOT model the effective-input dependency on the native leg (overbuild for v1).

**3b. Type domain: native admits `{string, int64, bool}` (match full-frame native); wider oracle-safe types stay on the oracle leg.** The oracle chunked leg admits a wider `group_by_type_is_safe` set (integer, bool, string, large_string, date, timestamp; floats/decimals excluded by Trap E). The kernel masks the wider set byte-identically, BUT v1 matches the full-frame NATIVE domain `{string, int64, bool}` (`_operator_config_rejections.py:195`) for route consistency; a wider oracle-safe group_by (large_string/date/timestamp) DOWNGRADES to the oracle chunked leg (NOT fail-closed, the C1b-ii lesson), reproducibly. Widening the native domain is a trivial deferred follow-up (C3-widen) flagged to the plan-gate. Plus a real-type gate on the FIRST chunk + a per-chunk drift check (mirror `bucket_perturb_gate` in `_chunked_entry.py`): an int64-with-nulls sibling stringifies identically every chunk via `to_pandas_fk_safe`, but a later `null`-typed chunk must be handled by `cast_null_columns`; bool with/without nulls must be probed against the oracle leg.

**3c. Raw-hex kernel preflight probe + downgrade (group_key uses a different kernel).** group_key uses `load_compiled_raw_hex_kernel` (`_group_key_ext.py`), NOT the index kernel, so it does NOT go in `_INDEX_KERNEL_STRATEGIES` (`_dispatch.py:78`). Preflight (`_dispatch.py:431-445`) today loads only the crypto (hash) and index kernels; C3 adds a THIRD probe for the raw-hex kernel and a downgrade mirroring `index_extension_unavailable`: an abi-mismatch companion without `derive_hex_raw_batch` DECLINES the table to the oracle leg (the existing whole-table decline policy). Native chunk call takes `chunk.select([group_by])` (the sibling SLICE, preserving field name + `b"pandas"` metadata), NOT `chunk.column(name)` (which `_mask_chunk_native` uses for every other branch); namespace is the synthesized `f"group_key/{name}"`; `length`/`prefix` from `provider_config`. No row-error channel (group_key cannot produce a format error).
