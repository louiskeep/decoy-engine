## 1. FRAME

**Problem.** The engine's `statistical` generation (`generation/statistical/`) samples each column
on its own from `distribution-snapshot/v1`. Columns come out with the right shape but rows are
nonsense: every correlation between columns is lost. V2-4 adds a Gaussian copula, which keeps
pairwise dependence while reusing the per-column marginals the engine already fits.

**Definition of done.**

1. `fit_gaussian_copula(frame, snapshot, *, seed)` returns a frozen `GaussianCopulaModel` for a
   table of numeric and categorical columns, with nulls in any column. `snapshot` is the
   `distribution-snapshot/v1` dict of the same frame; the marginals are copied from it and only
   the correlation is computed from the frame.
2. `sample_gaussian_copula(model, n, *, seed, start=0)` returns a `pandas.DataFrame` of `n`
   synthetic rows and reads only the model. Row `start + i` is a pure function of
   `(model, seed, start + i)`, so a window equals the same rows of a full draw.
3. `model.to_dict()` / `GaussianCopulaModel.from_dict(d)` round-trip through JSON
   (`json.dumps(..., allow_nan=False)`), schema `decoy-gaussian-copula/v1`. `from_dict` is strict
   and never repairs.
4. The model stores the snapshot's own marginal fields and a correlation matrix released under the
   disclosure floors of section 4.2, and nothing else (section 4.4 states the exact contents).
5. Acceptance (section 9) shows correlation fidelity within bounds taken from a 50-seed sweep,
   category frequencies and null rates within bounds, determinism across processes, windowed
   equality, the disclosure floors, and a fail-before proof: an independent sampler with the same
   marginals fails the correlation assertions.

**Non-goals.**

- No wiring: no `strategy: copula`, no config key, no `decoy fit` change, no pinned-generation or
  native draw-site entry (the native determinism protocol's draw-site catalogue gets an entry when
  a later slice wires this in).
- No change to `distribution-snapshot/v1` or to `quality/` (V2-4.1 decides the artifact; DPS
  owns the DP fit).
- Not differentially private. The floors in section 4.2 are disclosure controls, not a formal
  guarantee; V2-4.5 (or DPS-4) adds DP. The model is a sensitive artifact of the same class as the
  exact snapshot (section 4.4).
- No published fidelity measure. The pairwise measure (section 6) is a test helper only; V2-4.4
  publishes one under a `quality/` sub-package.
- No datetime or freetext columns: `fit` refuses them. Datetime needs a finer marginal than the
  snapshot's year bins; it is a follow-up.
- No DP snapshot input (`dps-marginal/v3` and carriers): `fit` accepts only
  `distribution-snapshot/v1`; the DP slice extends it.
- No conditional sampling, no constraints, no multi-table (V2-9).
- No new dependency, no scipy, no new reason code, no new exception class.

**Risk: R2.** New privacy-relevant artifact (a fitted model carrying the snapshot's real category
labels and bin edges plus a correlation release that links values within rows), a new statistical
primitive, and a new persisted format with a versioned reader. Nothing is persisted or run by the
engine itself (dark), so rollback is reverting the branch. Approver: independent plan and code
review (Dennis), then the owner; owner instruction 2026-11-07 is not to merge.

## 4. Design notes

### 4.1 Fit (`_fit.py`)

1. Validate arguments and the snapshot against the frame (section 3). Build each column's
   marginal from its snapshot entry only (`_marginals.from_snapshot_entry`).
2. Latent scores, at fit time only, never stored. Every latent variable is in normal-score space
   before any correlation is taken, because sampling feeds `Phi(Z)` to the marginal lookups:
   - numeric value variable: on non-null rows, average-tie ranks over `n_obs + 1`, mapped through
     `Phi^-1`; `NaN` on null rows;
   - numeric null indicator (when the column has both nulls and values): states `present` and
     `null` as frequency intervals (section 4.3); a uniform point inside the row's interval,
     mapped through `Phi^-1`;
   - categorical: the row's state interval (a top label, `null`, or the collapsed tail `other`); a
     uniform point inside it, mapped through `Phi^-1`.
   Uniform points come from a `PCG64` stream from `seed` with the label `fit`, drawn in row order.
   So the interval layout is independent of row order, but the fitted correlation is not: the same
   rows in another order get different uniform points and a slightly different matrix. The model
   is a deterministic function of `(frame including row order, snapshot, seed)`.
3. Suppression (section 4.2) is decided per latent VARIABLE, from the frame, before any
   correlation is computed: a suppressed variable's whole row and column are the identity (all its
   correlations 0), which is always consistent, so the repair of the remaining block is exactly the
   repair of the fit without that variable. Order: variable floors first (`zero_variance`,
   `distinguished_rows`, `rows_per_bin`), then pairs in latent order: a pair of unsuppressed
   variables with fewer than `MIN_PAIR_ROWS` shared rows suppresses the sparser variable (fewer
   non-null rows; on a tie, the later one in latent order), reason `pair_rows`. A pair whose shared
   rows have zero variance on one side suppresses that side, reason `zero_variance`.
4. Raw correlation of the unsuppressed variables: Pearson correlation of each pair on rows where
   both are present (pairwise-complete). A value variable and its own null indicator get 0: the
   indicator is constant where the value is present, so the pair has no estimate (a structural
   zero, as RDT models the indicator; not a suppression).
5. Repair the unsuppressed block (section 4.6) with an eigenvalue floor at the rounding bound
   `1e-6 + 0.0005 * sqrt(d (d - 1))`, so rounding the off-diagonal to 3 decimals cannot push the
   minimum eigenvalue below `1e-6` (the rounding error matrix has Frobenius norm at most that bound
   minus `1e-6`). Embed into the identity, round to 3 decimals, and, only if the minimum eigenvalue
   is still below `1e-6`, shrink toward the identity with the smallest `a` in `(0.001, 0.002,
   0.005, 0.01, 0.02, 0.05, 0.1, 0.2, 0.5, 1.0)` that reaches it (`a = 1` is the identity, so the
   ladder always ends).

### 4.2 Disclosure floors

The snapshot alone never links values within a row; the correlation does. With few rows the
release is close to the rows themselves: at `n = 2` the bin counts put one value in each end bin,
the end edges are those exact values, and every correlation is `+-1`, so both rows come back
exactly; for small `n` a normal-score correlation is a function of the rank permutation and, at 12
decimals, can be inverted by enumeration up to about `n = 10`. The floors below bound this. They
are heuristic disclosure controls in the small-cell tradition, not a formal guarantee.

| Floor | Value | Behavior | Why this number |
|---|---|---|---|
| `MIN_FIT_ROWS` | 100 | `fit` refuses a smaller frame; `from_dict` refuses a smaller `row_count` | at 100 rows the rank permutations number about `10^158` while a 3-decimal correlation takes at most 2,001 values, so a released correlation cannot single out a permutation; with the per-pair floor of 50 it also keeps two disjoint 50-row groups possible |
| `MIN_PAIR_ROWS` | 50 | a pair of variables with fewer pairwise-complete rows suppresses the sparser variable (section 4.1 step 3), reason `pair_rows`; the fit still succeeds | a correlation is one aggregate over the shared rows; 50 is above the small-cell thresholds in use (11 in the CMS policy) by a margin because one correlation mixes every shared row's two values. Refusing the whole fit would let one sparse column block a table; suppressing a single pair before the repair distorts the other entries (review probe: a chain at 0.9 with one pair zeroed moved to 0.743), so the whole variable is suppressed instead |
| `MIN_DISTINGUISHED_ROWS` | 11 | a frequency-interval variable (categorical, or a null indicator) whose non-modal states together hold fewer than 11 rows is suppressed, reason `distinguished_rows`; its marginal still holds | such a variable is nearly an indicator of a few rows: with one null, the indicator's correlation with `x` is roughly that row's normal score in `x` over `sqrt(n)`, which locates the row. 11 is the CMS cell-size threshold. It is applied to the non-modal SUM, not to each state: the exposure is the variable acting as an indicator of a small group set apart from the modal mass. A rare state among several large ones is one row's contribution inside an aggregate over all rows, the same exposure as an extreme value of a numeric column, which no floor suppresses either; a per-state rule would suppress nearly every real categorical (the snapshot's top 20 usually includes rare labels) |
| `ROWS_PER_BIN` | 10 | a numeric value variable whose snapshot has more bins than `non_null_count // 10` is suppressed, reason `rows_per_bin` | fine bins plus a correlation pin individual values; one bin per 10 observed values on average keeps each bin a group. Suppressing rather than refusing lets the caller keep one global bin count for the snapshot |
| zero variance | | a variable with zero variance (a constant column, or constant on the rows it shares with a partner) is suppressed, reason `zero_variance` | the correlation is undefined |
| `MAX_LATENT`, pair budget | 256; latent pairs at most `row_count // 2` | `fit` refuses above either | heuristics. Dinur and Nissim (PODS 2003, reconstruction from subset-sum queries answered too accurately) is the motivation, not a proof that applies to correlations: the rule keeps the number of released aggregates well below the number of rows. 256 also bounds the cost (section 4.6) |
| Release precision | 3 decimals | stored and validated | the sampling error of a correlation is about `1 / sqrt(n)`, at least 0.01 below 10,000 rows, so the 4th decimal and beyond carry information about individual rows rather than about the population; the 50-seed sweep (section 8) was run with 3-decimal rounding |

Suppression is recorded in the model (`suppressed`, section 4.4) so a reader can tell a released
0 from a suppressed variable. A suppressed variable's correlations are exactly 0 in the stored
matrix. Floors are computed from the frame (which equals the snapshot for v1).

### 4.3 Marginals (`_marginals.py`)

- Numeric: `bin_edges`, `bin_counts` from the snapshot. Inverse transform of `u` in [0, 1]:
  `t = u * total`, bin `k` = first bin with cumulative count `> t`, clamped to the last positive-
  count bin (the same guard as `statistical/_sample.py`'s `_numeric_row`, because `u * total` can
  round to `total` and `ndtr` returns exactly 1.0 for `z >= 8.3`); `u = 0` selects the first
  positive-count bin. Value `edges[k] + (t - cum[k-1]) / counts[k] * (edges[k+1] - edges[k])`,
  clamped into `[edges[k], edges[k+1]]`. A constant column (`edges = [c, c]`) returns `c`.
- Frequency intervals (categorical states and the numeric null indicator): states are the
  snapshot's `top_values`, plus `null` when `null_count > 0`, ordered by `(-count, kind, label)`;
  the collapsed tail `other` (`other_count > 0`) is always last. At sampling, `u` is scaled by
  `1 - p_other` before the lookup, so `other` mass is redistributed over the kept states in
  proportion (the `statistical` default `other_mode: redistribute`) and the mapping stays
  monotone. The state index is clamped to the last positive-count kept state, and `u = 0` maps to
  the first. `other` is never emitted; no label outside `top_values` can be produced.
- Integer dtype test mirrors `statistical/_sample._is_integer_dtype` (a one-line predicate copied
  rather than imported from a private module, catalog item 6).

### 4.4 What the model stores (`_model.py`)

`to_dict()` has exactly these keys:

- `schema_version`: `"decoy-gaussian-copula/v1"`.
- `row_count`.
- `columns`: list in frame order; each entry has `name`, `kind` (`numeric` | `categorical` |
  `empty`), `dtype`, `null_count`, `non_null_count`, and then either `bin_edges` and `bin_counts`
  (numeric) or `top_values` (`[{value, count}]`) and `other_count` (categorical). Each is the
  identical field of the caller's snapshot entry for that column.
- `correlation`: the strictly lower triangle of the released latent correlation matrix, row-major,
  each a float with at most 3 decimals. The latent variable order is derived from `columns` (not
  stored).
- `suppressed`: a list of `{"variable": <latent index>, "reason": <token>}` sorted by index, tokens
  from `pair_rows`, `distinguished_rows`, `rows_per_bin`, `zero_variance`. Value-free. `from_dict`
  checks each index is in range and unique, each reason is a known token, and every correlation
  entry in a suppressed variable's row and column is exactly 0.

So the model holds the snapshot's real values (bin edges, whose ends are the column min and max,
and up to 20 real category labels per column with the default snapshot) and nothing the snapshot
does not hold: no quantiles, mean, standard deviation, ranks, normal scores, row values or tail
labels. The correlation is the only new release, under section 4.2. It is a sensitive artifact in
the same class as the exact snapshot (`quality/snapshot.py` module docstring); a later wiring slice
must put it behind the same `allow_real_categories` consent as `statistical`. `__repr__` is
value-free (column names, kinds and the latent dimension only).

`from_dict` validates everything listed in section 3 with strict types (catalog items 2 and 4):
`int` fields refuse `bool`, float fields accept `int` or `float` but refuse `bool` and strings,
enum fields are checked tokens, unknown and missing keys are refused (v1 has no minor versions; a
v2 reader is a new schema). Consistency is checked, not trusted: bin counts sum to
`non_null_count`, category counts plus `other_count` sum to `non_null_count`,
`null_count + non_null_count == row_count`, the correlation length matches the derived latent
dimension, every entry equals its own 3-decimal rounding, and the matrix's minimum eigenvalue is at
least `1e-6` (`numpy.linalg.eigvalsh`; the same threshold in `fit` and `from_dict`, with margin so
validity does not hinge on the LAPACK build). `fit` and `from_dict` construct through the same
validator.

### 4.5 Sampling (`_sample.py`) and the RNG

- Seeds: `seed` is caller-supplied `bytes` (at least 16), never global state. The stream is
  `PCG64(SeedSequence(int.from_bytes(sha256(label || len(seed) || seed))))` with distinct labels
  for `fit` and `sample`, so the same bytes passed to both do not reuse a stream. A wiring slice
  derives a 32-byte subkey with HKDF and passes it here.
- Each row consumes exactly `d` raw 64-bit outputs (d = latent dimension), converted to doubles
  as `((x >> 12) + 0.5) * 2**-52`, which lies in `[2**-53, 1 - 2**-53]`: every value is exactly
  representable, so neither 0 nor 1 can occur and `ndtri` never sees an endpoint. A window at
  `start` calls `advance(start * d)`.
- `W = ndtri(U)`; `Z = W L^T` with `L` the Cholesky factor of the stored matrix; `U' = ndtr(Z)`,
  which can be exactly 0 or 1 in the far tails; the marginal lookups accept the closed interval
  (section 4.3). The product is accumulated column by column with elementwise numpy operations (no
  BLAS reduction), so a row's value does not depend on the batch size or BLAS threading. Numeric
  null indicator: the row is null when its `U'` falls in the `null` interval.
- Bit-identity holds for the same numpy build on the same CPU feature set (section 10).

### 4.6 Nearest correlation matrix (`_nearest_corr.py`)

Higham 2002, Algorithm 3.3 with W = I: `Y0 = A`, `dS0 = 0`; repeat `R = Y - dS`,
`X = P_S(R)` (eigenvalues clipped at 0), `dS = X - R`, `Y = P_U(X)` (unit diagonal, and since code
review round 1 also the structural zeros held at 0, the fixed-element form of the same iteration)
until the relative change is below `1e-12` or 500 iterations. Hitting the cap is not an error: the
result is then shrunk toward the identity, `(1 - a) Y + a I` with the smallest `a` that reaches
the floor (`1e-8` by default; `fit` passes the rounding bound of section 4.1 step 5), which keeps
the unit diagonal and every zero, so the result is always a valid correlation matrix, possibly not
the nearest one. (Revision 3 used an eigenvalue floor plus diagonal rescale here; that step does
not keep fixed zeros.) A valid input with minimum eigenvalue at least `1e-8` comes back within
`1e-12`.
Cost: one symmetric eigendecomposition (`O(d^3)`) per iteration; at the `MAX_LATENT` cap of 256 that
is a few milliseconds each, so the worst case is a few seconds. Fit's correlation step is
`O(n d^2)`.

### 4.7 Principles and structure

- Single responsibility per module: `_normal` (special functions), `_nearest_corr` (linear
  algebra), `_marginals` (one column's forward and inverse transform), `_model` (the artifact and
  its one validator), `_floors` folded into `_fit` (the section 4.2 rules, one table of constants),
  `_fit`, `_sample`. Each changes for one reason.
- Deep module: callers see two functions and one model type; latent layout, intervals, floors and
  RNG framing are hidden.
- One place per fact: kind rules, bins and top-K live in the snapshot; the latent layout is derived
  from `columns` in one function used by fit, sample and `from_dict`; the floors are module
  constants in one place, re-exported; the schema version is one constant.
- No registry or descriptor: two column kinds, no expected stream of new ones inside this package.
- DP direction: `fit` takes the marginals from the caller's snapshot and computes only the
  correlation from the frame; `sample` reads only the model. A DP slice therefore noises exactly
  one release (the correlation) and accepts a DP snapshot for the marginals.
- House style: typed frozen dataclasses, no flag arguments.
- Logging: none. This is a pure library function with no job, like `compute_distribution_snapshot`;
  the wiring slice adds job events. Errors are value-free.

## 6. Pairwise fidelity measure (test helper)

`tests/unit/generation/copula/_pairwise_fidelity.py`, not shipped. Its docstring cites SDMetrics
(method only). For every unordered pair of columns present in both frames:

- numeric with numeric: `pearson = 1 - |r_real - r_synth| / 2` and `spearman` the same with
  Spearman's rho, each on that frame's pairwise-complete rows (SDMetrics `CorrelationSimilarity`;
  both are reported because a rank copula preserves Spearman by construction while Pearson also
  depends on the histogram marginal). A pair constant on either side scores `None`.
- any pair with a categorical column: `1 - TVD` between the normalized joint frequency tables, null
  as its own category, numeric columns discretized into 10 equal-width bins over the real column's
  range with synthetic values clipped into it (SDMetrics `ContingencySimilarity`).

Kind comes from the dtype: numeric non-bool dtypes are numeric, everything else categorical.

## 10. Known limits

- **The floors are heuristic.** They block the small-table reconstructions above but give no
  formal bound; an attacker with auxiliary knowledge of most rows can still learn about the rest
  from a correlation. DP (V2-4.5 or DPS-4) is the formal answer.
- **Marginal resolution is the snapshot's.** Ten equal-width bins with uniform-within-bin sampling
  flatten skewed columns. This is the same marginal `statistical` produces; Pearson similarity is
  lower than Spearman for such columns for this reason.
- **Categorical dependence is captured only as far as it is monotone in the frequency order.**
  SDV's GaussianCopula has the same limit; a better model (for example one-hot latent variables)
  is a follow-up.
- **Missingness dependence is attenuated** by the uniform placement inside the indicator interval
  (prototype: real P(null | high x) 0.076, synthetic 0.120, independent 0.139).
- **Row order affects the fitted correlation** through the per-row uniform placement (section 4.1).
- **Bit-identity is per platform.** The sampler uses numpy elementwise `exp`, `log`, `sqrt` and
  LAPACK Cholesky; results are identical across processes on one machine and numpy build but may
  differ in the last bits across CPU feature sets or numpy versions. `statistical` avoids this by
  sampling in pure Python; the wiring slice decides whether pinned generation needs that.
- **Sampling memory** is `n x d` floats per call; large `n` should be drawn in windows (`start`).
- **Bool columns come back as `"True"`/`"False"` labels** (section 3).
- **Variable-level suppression is coarse.** A sparse column loses all its correlations even when
  only one partner is sparse. The alternative not chosen is a weighted nearest correlation matrix
  with zero weight on the missing cells (H-weighted NCM, Qi and Sun, SIAM J. Matrix Anal. Appl. 28
  (2006)), which keeps the other cells of that variable but needs a Newton solver this slice does
  not justify.
- **Value and own null indicator are a structural zero**, not an estimate (section 4.1 step 4).
  It is held at exactly 0 through the repair (fixed-element alternating projections) and the
  validator refuses a model that carries anything else.
- **Leverage of single values.** The floors bound small groups, not one high-leverage value in a
  continuous column or one row in a rare category. The established bound here is the rank-based
  score itself: a normal score is at most `Phi^-1(n / (n + 1))`, about `sqrt(2 ln n)` (3.09 at
  1,000 rows), so one row moves a released correlation by at most about `2 ln(n) / n` (about 0.01
  at 1,000 rows), however extreme its raw value; Pearson on raw values has no such bound. A rare
  category's interval sits at the end of the frequency order, so its scores obey the same bound.
  This bounds influence; it is not a guarantee against an attacker who knows every other row.
- **Integer draws are uniform over the integers inside a bin**, the same within-bin uniformity the
  continuous draw assumes.
- **Snapshot edges are rounded to 12 decimals.** An integer that sat exactly on a computed edge
  can fall on the other side after rounding; the positive-bin clamp keeps every draw inside an
  occupied bin, but that one value can move to the neighbouring bin.
- **Integer output is `int64`** (or `Int64` with nulls) for every integer source dtype, including
  unsigned and `int8`.
