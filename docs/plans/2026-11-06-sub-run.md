## 1. Guarantee

A `decoy run` (and `run_pipeline`) with a `subset:` block computes the referentially closed subset
of the sources first, then masks and generates only the subset rows, on every route that can take
the result. For the kept rows, a subset run gives the same masked values the full run would give,
within the scope in 4.4. An entry that cannot apply the subset refuses with a registered reason
code before it reads any source. No path runs a subset config on full sources without saying so.

Non-goals: chunked subset, readers in the standalone `decoy subset`, native closure, one temp
budget shared across scratch roots (section 16).

## 3. Established solutions

Tonic Condenser, Jailer and Redgate Subsetter compute the closure first, materialize the subset
to a staging area, and run the transform on the staged copy; none subsets per chunk. This plan
follows that shape: closure on keys only, one materialization step, then the normal run.

## 4. Behavior

### 4.1 E1 types and the input seam

New `subset/_scope.py` (about 90 lines):

- `SubsetRequest` (frozen): `relationships: tuple[Relationship, ...]`,
  `seeds: tuple[SeedSpec, ...]`, `policy: FanOutPolicy`. No sources, no paths.
- `SubsetScope` (frozen): `tables` (reachable from a seed) and `whole` (supplied, no path from a
  seed), both `frozenset[str]`, built by `scope_for(request, table_names)`, the one unlinked-table
  policy function (owner Q2: pass whole).
- `SubsetSelection` (frozen): `survivors: Mapping[str, frozenset[int]]` (row indices, in-scope
  tables only), `counts: Mapping[str, tuple[int, int]]` (source rows, kept rows), `scope`,
  `excluded_edges: tuple[str, ...]`, `estimate` (the existing estimate type).

New `subset/_inputs.py` (absorbs `_io.py`, which is deleted; about 150 lines):

- `TableInput` protocol: `name`; `polars_schema() -> pl.Schema`; `num_rows() -> int`;
  `key_frame(columns: Sequence[str]) -> pl.DataFrame`, the `RI` column plus the named columns in
  file order (no columns: an `RI`-only frame of `num_rows()` rows).
- `ResidentInput(name, table: pa.Table)`: schema from `pl.from_arrow(table.slice(0, 0))`;
  `key_frame` is `pl.from_arrow(table.select(cols)).with_row_index(RI)`.
- `LazyInput(name, source: LazySource, batch_rows)`: `source.schema()`, `source.num_rows()`;
  `key_frame` concatenates `source.iter_batches(batch_rows, columns=cols)` in file order and never
  reads `source.path`. `LazySource` comes from `decoy_engine.profile` (public).
- `ParquetPathInput(name, source: SubsetSource)`: the old `open_input` body and the only
  `scan_parquet` calls in `subset/`, plus `filtered_frame(indices)` for `materialize_subset`.
- `as_input(name, value)` dispatches on `pa.Table`, `LazySource`, `SubsetSource`; anything else is
  a `TypeError` (programming error, no reason code).
- Types are the real Arrow types. CSV is all text, so a CSV key against a Parquet int key refuses
  with the existing `subset.subset_relationship_type_mismatch`. There is no conversion.

Changed in E1. Every function name and coded raise site stays in its current function, so no key
moves in `tests/fixtures/f29/producer-inventory.json`, `tests/sentry/baselines/f29-*` or
`gcs-call-kwargs.json` (those baselines only shrink). New functions hold no coded raise.

- `run_subset_preflight(*, sources, relationships, seeds=(), file_access=None)`: values may be
  `SubsetSource`, `pa.Table` or `LazySource`, each through `as_input`; names and defaults are
  unchanged. The 5.0 Parquet gate applies to `SubsetSource` values only; 5.4 uses `key_frame`.
- `load_key_frames` takes `Mapping[str, TableInput]`; `key_columns_needed` is unchanged;
  `materialize_subset` reads through `ParquetPathInput.filtered_frame` and keeps its count check.
- `subset_request_from_config(config) -> SubsetRequest | None` is a refactor of
  `subset_inputs_from_config` (`_api.py:214-269`): the seeds, budget and policy body moves into
  it, raises nothing new, and returns `None` with no `subset:` block. `subset_inputs_from_config`
  keeps its two raises (`subset_config_missing`, `subset_source_type_unsupported`) in place and
  calls the new function for the rest.
- `select_subset(request, inputs: Mapping[str, pa.Table | LazySource], *, job_seed: bytes,
  file_access=None) -> SubsetSelection` is an `@entry_point` in `_api.py`. It shares `_compute`
  with `plan_subset` and `run_subset` (which build `ParquetPathInput`s), so the entry-point sentry
  sees it reach `fileaccess.current()`. Rule: `file_access` governs path inputs; a `LazySource`
  reads under the policy it captured when built (`profile/_readers.py:228-239`); resident inputs
  read nothing. `job_seed` uses the wiped pattern (`except BaseException: del job_seed; raise`).
- `subset/__init__.__all__` adds the three types, `select_subset` and
  `subset_request_from_config`. E1 ships no behavior change.

### 4.2 The split and the keyword (E2)

`split_subset_config(config) -> SubsetSplit` (new `subset/_split.py`) returns `run_config` (a
`PipelineConfig` copy with `subset=None`; the key stays, so hash and dump match a config that
never had a subset), `request` (`subset_request_from_config(config)`) and `fingerprint` (SHA-256
over the request's canonical dump, or `None`; no value beyond the seed keys already in the config
hash, FU-9). `run_pipeline` calls it first, in place of `refuse_unapplied_subset`, and every later
step (`build_run_context`, `prepare_declared_sources`, the routing probe) receives
`split.run_config`, so the CONFIG-EXPLICIT `id(config)` binding holds unchanged.

New keyword-only, additive parameter:
`run_pipeline(..., subset_request: SubsetRequest | Literal["config", "skip"] = "config")`.

- `"config"`: use `split.request`. `"skip"`: full sources; stamp
  `quality_metrics["subset"] = {"applied": false}` only when the config has a `subset:` block.
- A `SubsetRequest` replaces the config block (SAMPLE's switch point). It cannot cross
  `run_pipeline_isolated`'s JSON boundary (the existing `_reject_unserializable_kwargs` refusal);
  the two strings cross it. Any other value: `runtime.invalid_execution_knob` before any read.

Run identity is `(pipeline_config_hash, subset fingerprint or None)`. A subset run shares the
config hash with a full run on purpose (the hash covers masking semantics); `plan.profile_hash`
also differs. F23 resume and RESULT key on both, so a full run's tables are never reused.

### 4.3 The stage (E2)

`execution/pipeline/_subset_stage.py` holds `SubsetStageScope`, entered beside `AdmissionScope` in
`run_pipeline` and passed to `build_run_context` as one keyword. In `build_run_context`:

1. After `refuse_duplicate_run_sources`, before `profile_source` (hook line 1):
   `caller_sources, selection = stage.apply(request, caller_sources, run_config)`.
   - Per lazy input, `expected = source_facts(src)` (`execution/_chunked_input.py:115`) first;
     for CSV this also records the file identity `open_batches` checks.
   - `select_subset(request, inputs, job_seed=job_seed_for_config(run_config))`, the seed
     `decoy subset` uses, so the same rows are picked. Wiped pattern on `job_seed`.
   - Resident: `table.take(sorted(survivors))`.
   - Lazy (Parquet or CSV): `opened = src.open_batches(batch_rows)`; keep each batch's rows whose
     global index survives; write through `_write_staged` (4.5) as opaque `sNNNN.parquet`; then
     `check_opened(opened, expected, table=name)` (`_chunked_input.py:248`), so a file changed
     between the passes refuses with `runtime.lazy_source_changed`. Staged files re-wrap as
     `LazySource`, so the stream route keeps working.
   - Written rows must equal `counts[name][1]`, else `runtime.subset_materialize_count_mismatch`.
   - Tables in `scope.whole` pass through untouched.
2. After `profile_source`, before `compile_plan` (hook line 2):
   `profile = stage.restrict_profile(profile, selection)` (4.4). `ctx.profile` is that one profile
   on every route, including stream (`pipeline/_stream.py:215`). `routing_profile` is unchanged
   and swaps in the staged row counts, which agree.

After the route returns, `run_pipeline` stamps `quality_metrics["subset"]`: `{"applied": true,
"fingerprint", "tables": {name: {"source_rows", "kept_rows", "whole"}}, "excluded_edges"}`.

Zero rows: a table with no kept row is a typed empty file (lazy) or typed empty table (resident);
the run succeeds with typed empty outputs and `kept_rows` 0. FK cycles: the closure is a
semi-naive fixpoint and handles them (`subset/_closure.py:1-37`); masking keeps the V1 denial of
cross-table FK cycles with its automatic full-frame fallback.

### 4.4 What "the same masked values" means

- Kept from the full-source profile: dtypes, average and maximum lengths, PII and FK flags,
  `sampled`, `is_candidate_key_sampled`, and every fact of a table in `scope.whole`.
- Replaced for each in-scope table that is not whole: `TableProfile.row_count = kept`,
  `row_count_exact = True`; each `ColumnProfile.row_count = kept`,
  `null_count = min(null_count, kept)`, `distinct_count = min(distinct_count, kept)` when not
  `None`. The clamp keeps a sampled distinct count from exceeding the subset row count, satisfies
  `__post_init__`, and keeps `uniqueness_saturation_risk` (`_pipeline_routing_signals.py:474`) sane.
- Where: once, in `restrict_profile`, between `profile_source` and `compile_plan`.
- Why values match: compile reads counts only for refusals, warnings and `profile_hash`, so the
  plan differs from the full run's only in `profile_hash`, and a value-keyed strategy gives each
  kept row the full run's value.
- Not covered (valid masked output, but not the full run's values): `shuffle` (permutation over
  the row set), non-deterministic faker (`_faker_positional`, keyed on the row ordinal),
  non-deterministic categorical (ordinal), `windowed_date`, `grouped_series`, `derived_aggregate`,
  MATCH and SCALE cardinality (runtime `nunique`), UNIQUE pool assignment, generate tables and
  statistical generation. Uniqueness and pool checks see subset counts, so a subset run may refuse
  or warn where the full run did not, or the reverse.

## 8. Acceptance tests

Red first: each is written and run red against main (or the previous slice) before the code, and
asserts the reason code (for a refusal) and the observable result. "M:" is the mutation that must
turn it red.

### Engine, E1

- AT-1 Resident selection equals `plan_subset` on the same data as Parquet. M: off-by-one row
  index in `ResidentInput.key_frame`.
- AT-2 A `CsvLazySource` with text keys gives the survivors of the same data as text-key Parquet.
  M: `scan_parquet(source.path)` in place of `iter_batches`.
- AT-3 Only key columns are read (recording `iter_batches` and resident wrapper). M: `columns=None`.
- AT-4 A CSV text key against a Parquet int64 key refuses with
  `subset.subset_relationship_type_mismatch`, names only. M: cast the CSV key first.
- AT-5 An int-literal `keys:` seed on a CSV text key column refuses with

## 12. Design notes

- The split is in `run_pipeline` because CONFIG-EXPLICIT binds declared sources to `id(config)`.
  The stage follows the declaration and duplicate checks so header names are declared (AT-24).
- Compile from the full-source profile so kept rows get the full run's values (4.4).
- Lazy inputs stage to scratch Parquet, not resident, so a 10M-row source with a 1% subset never
  becomes a 10M-row table. Filtering by sorted index keeps source order (AT-12).
- Typed requests replace the four-tuple `subset_inputs_from_config` returns; the input protocol
  is one seam for three input kinds, so SAMPLE's head-N or a new reader adds one class.
- Quarantine row positions number subset rows (`docs/relationships.md`). CLI memory peak is full
  sources plus the copy, with Python-int survivors (FU-5); accepted for V1.
