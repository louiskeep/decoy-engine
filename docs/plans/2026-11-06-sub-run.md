## 1. Guarantee and non-goals

The change promises:

1. `run_pipeline` with a config that sets `subset:` masks exactly the FK-closed slice the subset core
   selects, on every layer-1 route (full_frame, sequential, out_of_core, mixed, the auto-chunk lane,
   the multi-table split and the unified slice). The selected rows equal the rows `run_subset`
   selects for the same config, seed and source data (same `job_seed_for_config`, same closure).
   The subset is applied once per run: after `apply`, every consumer (profile, compile, routing,
   the routing probe's isolated children, the lanes and validators) gets the run config without
   `subset`, so nothing downstream selects again.
2. The subset runs after the keyed-mask secret is admitted and before profiling, routing, transforms
   and masking (pipeline baseline order: source, subset, pre-scan, mask, post-scan, delivery). A
   preflight failure or a budget overrun raises before any masked row is produced and before any
   target is touched.
3. No unmasked subset leaves the engine. Resident inputs are filtered in memory; lazy Parquet inputs
   are staged into an engine-private 0700 scratch root that is removed on every exit path of the run
   (F04: "no standalone unmasked subset artifact").
4. The Parquet-only rule no longer applies to a run (Q1). A run subsets whatever the caller hands it:
   a resident Arrow table decoded by the caller's reader (CSV, fixed-width, delimited or Parquet) or
   a lazy Parquet `LazySource`. The standalone `run_subset` and `plan_subset`, which open files by
   path, keep their Parquet-only preflight.
5. Tables outside every seeded FK component pass through whole (Q2), in a run and in `run_subset`.
6. Every public engine callable that takes a config has one declared subset policy (section 11b).
   Entries that cannot apply a subset refuse it with `config.subset_run_unsupported`: the three
   chunked entries, `compile_plan` and `probe_peak_bytes` called on a subset config, and
   `run_pipeline` with a caller `source_loader`. The two estimators (`estimate_job_capacity`,
   `estimate_job`) return a fixed not-applicable result for a subset config before reading
   anything: capacity is decided inside the run, after the subset.
7. The engine owns how a run config is derived from a subset config: `split_subset_config` returns
   the run config, the `SubsetRequest` and a value-free subset fingerprint. `run_pipeline`,
   `validate_plan` and the CLI gate all use it; no caller strips the key itself.
8. The run result carries value-free subset evidence under `quality_metrics["subset"]` (counts,
   edges, budget outcome, scope, fingerprint; never a key value or a filter literal). A config
   without `subset:` runs byte-for-byte as today and gets no `subset` key.
9. The CLI half: `decoy validate` (the whole gate, capacity check included) accepts a subset
   config, `decoy run` applies it through the engine, maps subset errors to exit 1 (as
   `decoy subset` does), prints a per-table count summary and adds `subset` to `--json`.

Non-goals (a finding here is a follow-up, not a blocker):

- `decoy subset` never masks or generates data. It remains a raw-slice tool for cutting a related
  sample or manageable production slice. Masking happens only in a run, so a masked subset is a run
  whose config has a `subset:` block. The engine and CLI docs state plainly that `decoy subset`
  output is raw production data.
- SAMPLE (row 63). This plan leaves the seam SAMPLE uses (section 4, `SubsetRequest`); `--sample N`,
  the head-N rule for unlinked tables and the scratch output are SAMPLE's.
- The platform half (parked). Platform lanes that compile and run a plan themselves
  (`P:api/jobs/v2_sequential.py:171-205`) keep getting the `compile_plan` refusal.
- Subsetting on the chunked entries (`--chunked`). Owner Q4: not planned for V1 (rows 57 and 63
  do not name it); V2 follow-up FU-7.
- Non-Parquet input for the standalone `decoy subset` command (FU-1).
- Database sources for the standalone API (unchanged, `subset/_api.py:229-234`).
- Streaming materialization of a single huge lazy table beyond the existing per-table bound
  (`subset/_materialize.py:10-16`).
- Any change to the closure algorithm, seed modes or budget rules.

## 4. Design notes

- **The subset core becomes source-agnostic.** New `subset/_inputs.py` defines `SubsetInput`, a
  small protocol with `schema()`, `num_rows`, `collect(build)` (apply a polars lazy expression to
  the needed columns and collect) and `take(survivors)` (M3, below). Three implementations:
  `ParquetPathInput` (today's `open_input` plus `scan_parquet`, `SUBSET_INPUT` role),
  `LazyParquetInput` (a `LazySource`, read under the policy it carries) and `ArrowTableInput` (a
  resident `pa.Table`, `pl.from_arrow` over only the needed columns). `_keys`, `_preflight` and
  `_materialize` read only through it. Preflight 5.0 asks the input for its kind, so the Parquet
  rule stays where paths are opened (a `ParquetPathInput` built from a non-Parquet descriptor) and
  nowhere else. A key column polars cannot convert fails closed with a new code,
  `subset.subset_key_column_unconvertible` (identifiers only), registered in E1 with the input
  that raises it (M6).
- **One survivor take (M3).** `SubsetInput.take(survivors, batch_rows) -> Iterator[pa.RecordBatch]`
  is the only row filter by index. `ArrowTableInput` yields `table.take(sorted)` as batches of the
  resident slice; the two Parquet inputs stream `iter_batches` and keep, per batch, the survivors
  whose row index falls in that batch's range (a sorted index array and two `searchsorted` calls).
  `materialize_subset` writes those batches with one Parquet writer, and the run stage either
  concatenates them (resident input) or writes them to scratch (lazy input). The polars
  `filter(is_in)` collect (`subset/_materialize.py:63-79`) goes away, so a lazy table is never held
  whole.
- **Memory limit (M3, stated).** Peak of the selection is the key frames of every in-scope table
  (row index plus key and predicate columns, all rows, `subset/_keys.py:44-60`) plus the survivor
  sets, which are Python `set[int]` per table (`subset/_closure.py:139`, about 60 to 70 bytes per
  surviving row), plus one batch. Resident inputs add the subset copy on top of the caller's full
  tables. This is the existing subset core's bound; FU-5 tracks a compact survivor representation.
- **One request object.** `subset_request_from_config(config) -> SubsetRequest(relationships, seeds,
  policy)` is split out of `subset_inputs_from_config`, which keeps its signature and composes
  `ParquetPathInput`s with the request. SAMPLE later builds a capped request from the same object;
  it never edits the config.
- **One run-config derivation (H1, H2).** `subset/_split.py` `split_subset_config(config) ->
  SubsetSplit(run_config, request, fingerprint)`. `run_config` is a shallow copy of the validated
  dump without the `subset` key; `request` is `subset_request_from_config(config)`, checked with the
  config-only steps of the core (`build_subset_edges` and `resolve_edge_directions`, which raise
  `config.subset_unknown_edge`, `subset/_policy.py:44`; no data is read); `fingerprint` is SHA-256 over the canonical
  JSON (the `_hash_config` serialization rules, `plan/_compile.py:650-654`) of the value-free
  request: the redacted seed specs `_seed_spec_public` (`subset/_api.py:44-77`), edge directions,
  budget and `allow_dangling`. Key values and filter literals are left out, so the fingerprint
  carries no data value (class 1); two subsets that differ only in a literal or a key list share a
  fingerprint, and even their evidence counts can coincide. FU-9 adds a keyed digest when a secret
  is available. A config without `subset` returns
  `(config, None, None)` unchanged. `run_pipeline`, `validate_plan` and the CLI gate call it; it is
  the one place that knows the key name.
- **One scope rule.** `subset/_scope.py` `subset_scope(request, table_kinds) -> SubsetScope`:
  `in_scope` is every table in an undirected FK component that holds a seed table; `whole` is every
  other mask table; `excluded_edges` are edges with a generate-kind end (a generate parent has no
  source rows; a mask child of a generate parent keeps its FK through the generate pool,
  `execution/_pipeline.py:30-33`; a generate child of a mask parent is refused at schema validation,
  `execution/_pipeline.py:50-57`). `run_subset` and the run stage both use it (Q2, owner): `run_subset`
  copies `whole` tables to its output in full, and the evidence lists them.
- **`select_subset` does the work without writing.** `subset/_api.py` gains `select_subset(inputs,
  request, *, job_seed, engine_version, file_access=None) -> SubsetSelection(plan, manifest,
  survivors, scope)` (M6: an `@entry_point` must take `file_access=`,
  `fileaccess/_entry.py:268-271`), the existing `_compute` plus `build_manifest`. `run_subset`
  becomes `select_subset` plus `materialize_subset`. It joins `ENTRY_POINTS`
  (`fileaccess/__init__.py:53`).
- **The run stage lives in execution, in a named sub-package.** `execution/pipeline/_subset_stage.py`
  holds `SubsetStageScope`, a context manager entered by `run_pipeline` beside `AdmissionScope`
  (`execution/_pipeline.py:288-292`). Two steps (M1):
  - `apply(config, caller_sources, *, source_loader) -> AppliedSubset(run_config, sources,
    counts, evidence)`: refuses a caller `source_loader` with `config.subset_run_unsupported` (the
    stage cannot filter rows a loader produces later); calls `split_subset_config`; builds one
    `SubsetInput` per in-scope table from `caller_sources` (a missing table is the existing
    `subset.subset_unknown_table` preflight failure); calls `select_subset` with
    `job_seed_for_config(config)`; replaces each in-scope source through `SubsetInput.take`: a
    resident table by the concatenated batches, a `LazySource` by a Parquet copy written under the
    stage's scratch root with public `execution.out_of_core.open_private` and re-read as a
    `LazySource` with public `execution.out_of_core.scratch_access_for(root)` (the out-of-core
    stager's pattern, `execution/out_of_core/_stage.py:26-33`).
  - `swap_counts(profile, counts) -> Profile`: each in-scope table's `row_count` becomes its
    survivor count with `row_count_exact=True` (the `routing_profile` pattern,
    `execution/_transforms_admission.py:121-138`). Pure; no I/O.
  `__exit__` removes the scratch root on every path.
  `stamp(result)` writes `quality_metrics["subset"]` once, for every route, in `run_pipeline` (the
  declared-casting stamp pattern, `execution/_pipeline_route_dispatch.py:49`).
- **Where the stage runs, and what comes after it (H1).** `build_run_context` calls `apply` after
  secret admission (`execution/_pipeline_context.py:320`) and before `profile_source`
  (`execution/_pipeline_context.py:329`). From then on it uses `applied.run_config` everywhere it
  used `config`: `profile_source`, `compile_plan`, the graph builders, `prepare_sources`, and
  `PipelineRunContext.config`, which every route, lane, validator and the routing probe read. So
  the probe's `scaled.config` (`execution/_probe.py:256`) and every isolated child it spawns carry
  no `subset` and select nothing (AT-5b). Immediately after `profile_source` returns and before
  `compile_plan`, `build_run_context` calls `swap_counts` exactly once. Therefore `ctx.profile`, the
  plan, `plan.profile_hash`, routing, and the production live `PhysicalPlanInputs` snapshot
  (`physical/_live_inputs.py`) see the same table counts. `routing_profile` then layers transform
  counts on top, unchanged. Table-level `row_count` becomes the subset count, while every
  column-level `row_count` and `null_count` remains full-source. The DE-11 unique-capacity check
  (`plan/_checks.py:152-160`) is consequently conservative. The remaining profile statistics also
  come from the full source's bounded sample; re-profiling scratch copies would add a read.
- **Scratch root (M4, L4).** In a plain run the stage opens `engine_scratch_root(None)`
  (`execution/out_of_core/_scratch.py:45-65`), lazily, only when a lazy in-scope input exists. The
  isolated parent creates a fresh `work_root / "tmp"` with mode 0700 before entering the spawn
  cleanup scope. It does not use `exist_ok`; a caller-owned `staging_dir` with a pre-existing
  `tmp` entry refuses before spawn and is not deleted. `_spawn_and_classify` sets
  `TMPDIR=<work_root>/tmp` in the child environment beside `_CAPPED_ENV`
  (`execution/_isolated_run.py:446+`). Creating the directory first is required because Python's
  `tempfile` ignores a nonexistent `TMPDIR` candidate and falls back to system temp. The stage in
  every process still calls `engine_scratch_root(None)`: no payload key, worker change, stage
  branch, or cross-process root registration exists. The child's subset scratch, out-of-core
  `decoy-ooc-*` spill, and other temporary files therefore stay below `work_root/tmp`. The parent
  deletes `work_root` in `finally` when it owns it (`execution/_isolated_run.py:393-394`); when the
  caller supplied `staging_dir`, an `else` removes only the fresh `work_root / "tmp"` it created.
  Export `engine_scratch_root`, `open_private` and
  `scratch_access_for` from `decoy_engine.execution.out_of_core`, so the new pipeline sub-package
  never imports `execution.out_of_core._scratch` directly.
- **The guard becomes a registry (M2).** `config/_subset_run.py` (SUB-STOP's module) gains
  `SUBSET_ENTRY_POLICY: Mapping[str, EntryPolicy]`, one row per public config-taking callable
  (section 11b lists all 28 found today plus the new `split_subset_config` and
  `subset_request_from_config`: 30 rows). `EntryPolicy` kinds: `APPLIES`,
  `DELEGATES(target)`, `REFUSES`, `NOT_APPLICABLE` (estimators), `CONFIG_ONLY` (reads the config
  but never a config-declared source), `NO_SOURCE_READ` (works on data the caller passes, never the
  config's sources), `SPLITS_THEN_COMPILES` (`validate_plan` validates the subset request and then
  compiles the derived run config), `NOT_PIPELINE_CONFIG` (connector classes whose argument is not
  a pipeline config),
  `READS_DECLARED_SOURCES` (`profile_source`, which profiles what the config declares by design), and
  `SUBSET_API` (the standalone subset path). Each row carries a reason; a `DELEGATES` row names its
  target callable. The refusal text changes to "subset: is applied by run_pipeline; this entry does
  not apply it" (fixed, value-free). `config.subset_run_unsupported` stays live with the same
  summary; the SUB-STOP note in `docs/reasons.md` that it retires at SUB-RUN is corrected.
- **Refusal is unconditional on an unapplied config.** `refuse_unapplied_subset(config)` calls
  `split_subset_config(config)` and refuses whenever `split.request is not None`. There is no run
  marker or fingerprint exception. Every downstream consumer normally receives `run_config`, so a
  consumer that accidentally retains the original config fails loudly instead of selecting twice.
- **Estimators and validation (H2).** `estimate_job_capacity` and `estimate_job` call
  `split_subset_config` first; for a subset config they return, before any read,
  `_not_applicable("subset", SUBSET_CAPACITY_TEXT)` (`execution/capacity.py:196-204`) and
  `JobEstimate(route="subset", priceable=False, notes=(SUBSET_CAPACITY_TEXT,))`, where the fixed
  text is "capacity is decided in the run, after the subset". `validate_plan` validates the
  request (a `SubsetConfigError` becomes its `PlanCheckError`) and compiles `run_config`.
  `compile_plan` itself keeps refusing a subset config (Q3, owner), so a caller that compiles and
  then runs a plan itself cannot silently mask full sources.
- **Isolated run.** The parent-side guard (`execution/_isolated_run.py:214`) is removed; the child's
  `run_pipeline` applies the subset over its `LazySource`s, once. The governor inherits it.
- **Config validation.** `config/_pipeline.py:306-317` (the Parquet copy) is deleted (Q1, owner).
  Checks 1 and 3 of `_subset_stage_constraints` stay.
- **Design principles.** Single responsibility: the subset core keeps selection and the run-config
  split, the execution stage keeps run lifetime and residency. Open/closed: a fourth input kind (a
  database, SAMPLE's head-N) is a new `SubsetInput` or scope entry, not an edit to `_keys` or
  `_preflight`. One place per fact: the entry policy table is the only list of entries, the split is
  the only code that names the `subset` key, the scope rule is one function.
- **Layers.** `execution` now imports `decoy_engine.subset` (public names only). The subset package
  imports tiers 3 to 6 only (`plan`, `generation`, `determinism`, `fileaccess`, `reasons`, and
  `profile` for the public `LazySource`), so the LAYOUT contract moves `subset` from tier 1 to tier 3
  (a map change, stated in section 5).
- **House style.** Typed `SubsetInput`, `SubsetRequest`, `SubsetSplit`, `SubsetScope`,
  `SubsetSelection`, `AppliedSubset`, `EntryPolicy`; no flag arguments; `_pipeline.py` does not grow.

## 12. Pre-mortem

- Memory on the CLI path: the CLI holds every full source resident before the run
  (`C:src/decoy/cli/run.py:842`), and `take` adds the subset copy. Peak is the full sources plus the
  slice. Recorded; FU-2 lets the CLI pass Parquet sources lazily.
- A profile-dependent strategy (pool capacity, distribution sampling) uses the full source's bounded
  sample, so a pool capacity check can refuse a subset that would fit. AT-2 uses
  profile-independent strategies; a refusal found in use is a follow-up, not a skip.
- A key type a plain run masks but the subset preflight refuses (float keys, `"007"` against `7`) now
  stops a subset run. Same rule as `decoy subset`; the message names the fix.
- Two subset runs that differ only in a filter literal share a fingerprint (the price of keeping
  it value-free). Their counts usually differ; recorded.
- H-1 or LAYOUT moves a file E2a or E2b edits. Sequencing in section 9; rebase cost only.
- Q2 changes `decoy subset` output for anyone relying on empty unseeded tables. Pre-GA; CHANGELOG.
- The platform's compile-then-run lane silently ignoring subset: closed by the kept `compile_plan`
  refusal (AT-7).
- A future consumer re-reading the original config inside a run would select again. Closed by
  construction (the context carries only the run config) and by the run-config-key sentry.
