## 1. Guarantee and non-goals

The change promises:

1. `run_pipeline` with a config that sets `subset:` masks exactly the FK-closed slice the subset core
   selects, on every layer-1 route (full_frame, sequential, out_of_core, mixed, the auto-chunk lane,
   the multi-table split and the unified slice). The selected rows equal the rows `run_subset`
   selects for the same config, seed and source data (same `job_seed_for_config`, same closure).
2. The subset runs after the keyed-mask secret is admitted and before profiling, routing, transforms
   and masking (pipeline baseline order: source, subset, pre-scan, mask, post-scan, delivery). A
   preflight failure or a budget overrun raises before any masked row is produced and before any
   target is touched.
3. No unmasked subset leaves the engine. Resident inputs are filtered in memory; lazy Parquet inputs
   are staged into an engine-private 0700 scratch root that is removed on every exit path of the run
   (F04: "no standalone unmasked subset artifact").
4. The Parquet-only rule no longer applies to a run (Q1). A run subsets whatever the caller hands it:
   a resident Arrow table decoded by the caller's reader (CSV, fixed-width, delimited or Parquet) or
   a lazy Parquet `LazySource`. The standalone `run_subset` and `plan_subset`, which open files by
   path, keep their Parquet-only preflight.
5. Tables outside every seeded FK component pass through whole (Q2), in a run and in `run_subset`.
6. Entries that cannot apply a subset keep refusing it with `config.subset_run_unsupported`: the three
   chunked entries, `compile_plan` outside a run, and `run_pipeline` with a caller `source_loader`.
   Inside `run_pipeline`, after the stage applied the subset, the nested calls the lanes make to
   those entries pass.
7. The run result carries value-free subset evidence under `quality_metrics["subset"]` (counts,
   edges, budget outcome, scope; never a key value or a filter literal). A config without `subset:`
   runs byte-for-byte as today and gets no `subset` key.
8. The CLI half: `decoy validate` accepts a subset config, `decoy run` applies it through the engine,
   maps subset errors to exit 1 (as `decoy subset` does), prints a per-table count summary and adds
   `subset` to `--json`.

Non-goals (a finding here is a follow-up, not a blocker):

- SAMPLE (row 63). This plan leaves the seam SAMPLE uses (section 4, `SubsetRequest`); `--sample N`,
  the head-N rule for unlinked tables and the scratch output are SAMPLE's.
- The platform half (parked). Platform lanes that compile and run a plan themselves
  (`P:api/jobs/v2_sequential.py:171-205`) keep getting the `compile_plan` refusal.
- Subsetting on the chunked entries (`--chunked`) (Q4).
- Non-Parquet input for the standalone `decoy subset` command (FU-1).
- Database sources for the standalone API (unchanged, `subset/_api.py:229-234`).
- Streaming materialization of a single huge lazy table beyond the existing per-table bound
  (`subset/_materialize.py:10-16`).
- Any change to the closure algorithm, seed modes or budget rules.

## 3. Established solutions

Search run: web search "Tonic Structural subsetting lookup tables tables outside subset copied in
full", plus the repo (subset core, SUB-STOP, the transform prepare step, the out-of-core scratch).

- Tonic Structural builds the subset before it applies any transformation, copies lookup tables
  whole, and ignores relationships to lookup tables
  ([about subsetting](https://docs.tonic.ai/app/generation/subsetting/subsetting-about),
  [configure](https://docs.tonic.ai/app/generation/subsetting/subsetting-configure)).
- Tonic's open-source `condenser` and Jailer follow the same shape: closure over declared FKs from a
  seed, plus a named set of tables copied in full (recalled; not re-fetched).
- The closure already follows semi-naive Datalog evaluation (`subset/_closure.py:1-11`).
- In the engine: the transform prepare step is the pattern for "filter resident sources once, before
  routing, and make the filtered count authoritative" (`execution/_transforms_prepare.py:1-12`,
  `execution/_transforms_admission.py:121-138`); `secret_providers/_preflight.py:180` and
  `declared_casting/_refusals.py:20` are the pattern for a run-scoped `ContextVar`.

Followed: Tonic's order (subset, then transform and mask in one job) and its pass-through rule for
tables the closure does not reach (Q2); the engine's prepare-step pattern for the run seam. Custom
code left: an input seam over three input kinds (about 130 lines), a scope rule (about 70), the run
stage (about 230). No library subsets Arrow tables by FK closure.

## 4. Design notes

- **The subset core becomes source-agnostic.** New `subset/_inputs.py` defines `SubsetInput`, a
  small protocol with `schema()`, `collect(build)` (apply a polars lazy expression and collect) and
  `num_rows`. Three implementations: `ParquetPathInput` (today's `open_input` plus `scan_parquet`,
  `SUBSET_INPUT` role), `LazyParquetInput` (a `LazySource`, read under the policy it carries) and
  `ArrowTableInput` (a resident `pa.Table`, `pl.from_arrow` over only the needed columns). `_keys`,
  `_preflight` and `_materialize` read only through it. Preflight 5.0 asks the input for its kind, so
  the Parquet rule stays where paths are opened (a `ParquetPathInput` built from a non-Parquet
  descriptor) and nowhere else. A key column polars cannot convert fails closed with a new code,
  `subset.subset_key_column_unconvertible` (identifiers only).
- **One request object.** `subset_request_from_config(config) -> SubsetRequest(relationships, seeds,
  policy)` is split out of `subset_inputs_from_config`, which keeps its signature and composes
  `ParquetPathInput`s with the request. SAMPLE later builds a capped request from the same object; it
  never edits the config.
- **One scope rule.** `subset/_scope.py` `subset_scope(request, table_kinds) -> SubsetScope`:
  `in_scope` is every table in an undirected FK component that holds a seed table; `whole` is every
  other mask table; `excluded_edges` are edges with a generate-kind end (a generate parent has no
  source rows; a mask child of a generate parent keeps its FK through the generate pool,
  `execution/_pipeline.py:30-33`; a generate child of a mask parent is refused at schema validation,
  `execution/_pipeline.py:50-57`). `run_subset` and the run stage both use it (Q2): `run_subset`
  copies `whole` tables to its output in full.
- **`select_subset` does the work without writing.** `subset/_api.py` gains `select_subset(inputs,
  request, *, job_seed, engine_version) -> SubsetSelection(plan, manifest, survivors, scope)`, the
  existing `_compute` plus `build_manifest`. `run_subset` becomes `select_subset` plus
  `materialize_subset`. It is a file-access entry point, so it joins `ENTRY_POINTS`
  (`fileaccess/__init__.py:53`).
- **The run stage lives in execution, in a named sub-package.** `execution/pipeline/_subset_stage.py`
  holds `SubsetStageScope`, a context manager entered by `run_pipeline` beside `AdmissionScope`
  (`execution/_pipeline.py:288-292`). Its `apply(config, caller_sources, profile)`:
  1. refuses a caller `source_loader` with `config.subset_run_unsupported` (the stage cannot filter
     rows a loader produces later);
  2. builds one `SubsetInput` per in-scope table from `caller_sources` (a missing table is the
     existing `subset.subset_unknown_table` preflight failure);
  3. calls `select_subset` with `job_seed_for_config(config)`;
  4. replaces each in-scope source: a `pa.Table` by `table.take(sorted(survivors))`; a `LazySource`
     by a Parquet copy of its survivors written under `engine_scratch_root(None)` with
     `_scratch.open_private`, re-read as a `LazySource` with `scratch_access_for(root)` (the
     out-of-core stager's pattern, `execution/out_of_core/_stage.py:26-33`);
  5. returns the profile with each in-scope table's `row_count` set to its survivor count and
     `row_count_exact=True` (the `routing_profile` pattern); and
  6. marks the run as subset-applied in a `ContextVar` that `refuse_unapplied_subset` reads.
  `__exit__` resets the `ContextVar` token and removes the scratch root on every path.
  `stamp(result)` writes `quality_metrics["subset"]` once, for every route, in `run_pipeline` (the
  declared-casting stamp pattern, `execution/_pipeline_route_dispatch.py:49`).
- **Where the stage runs.** `build_run_context` calls `subset_scope.apply` after secret admission
  (`execution/_pipeline_context.py:320`) and before `profile_source`
  (`execution/_pipeline_context.py:329`), and uses the returned sources and profile from then on. The
  profile's statistics still come from the full source's bounded sample; only counts are replaced
  (technical call: the full-source sample is the population the user configured, and re-profiling
  scratch copies would add a read).
- **The guard becomes a registry.** `config/_subset_run.py` (SUB-STOP's module) gains
  `SUBSET_ENTRY_POLICY: Mapping[str, EntryPolicy]` with `EntryPolicy` in `{APPLIES, REFUSES,
  DELEGATES, CONFIG_ONLY}` and a reason per row, the `subset_applied()` scope, and the guard that
  passes inside that scope. `run_pipeline` and `run_pipeline_isolated` (its child runs
  `run_pipeline`) are `APPLIES`; `run_job_with_governor` is `DELEGATES`; the three chunked entries
  and `compile_plan` are `REFUSES`; `run_config_only_checks` is `CONFIG_ONLY`. The refusal text
  changes to "subset: is applied by run_pipeline; this entry does not apply it" (fixed, value-free).
  `config.subset_run_unsupported` stays live with the same summary; the SUB-STOP note in
  `docs/reasons.md` that it retires at SUB-RUN is corrected.
- **Isolated run.** The parent-side guard (`execution/_isolated_run.py:214`) is removed; the child's
  `run_pipeline` applies the subset over its `LazySource`s. The governor inherits it.
- **Config validation.** `config/_pipeline.py:306-317` (the Parquet copy) is deleted (Q1). Checks 1
  and 3 of `_subset_stage_constraints` stay.
- **Design principles.** Single responsibility: the subset core keeps selection, the execution stage
  keeps run lifetime and residency. Open/closed: a fourth input kind (a database, SAMPLE's head-N) is
  a new `SubsetInput` or scope entry, not an edit to `_keys` or `_preflight`. One place per fact: the
  entry policy table is the only list of run entries; the scope rule is in one function.
- **Layers.** `execution` now imports `decoy_engine.subset` (public names only). The subset package
  imports tiers 3 to 6 only (`plan`, `generation`, `determinism`, `fileaccess`, `reasons`, and
  `profile` for the public `LazySource`), so the LAYOUT contract moves `subset` from tier 1 to tier 3
  (a map change, stated in section 5).
- **House style.** Typed `SubsetInput`, `SubsetRequest`, `SubsetScope`, `SubsetSelection`,
  `EntryPolicy`; no flag arguments; `_pipeline.py` does not grow.

## 7. Acceptance tests

Each names the mutation that turns it red; red-first evidence is an assertion failure on the
SUB-STOP head plus E1.

- AT-1 (applies): the SUB-STOP two-table fixture (100 customers, 300 orders, seed `count: 5`):
  `run_pipeline` returns 5 customers and 15 orders, every output order's masked `customer_id` is in
  the masked customers, and `quality_metrics["subset"]` holds the counts. Replaces
  `test_run_pipeline_refuses_subset_before_any_read`. Mutation: skip `apply`.
- AT-2 (parity with the standalone step): for each FK shape in 11b, the rows a run keeps equal
  `run_subset`'s output rows for the same config (compared with `passthrough` columns). Mutation:
  seed the stage with a constant job seed.
- AT-3 (formats, Q1): the same data as CSV, fixed-width, delimited (`|`) and Parquet, loaded as the
  CLI loads it (resident tables), gives identical survivors and identical masked output. Mutation:
  apply the Parquet gate to `ArrowTableInput`.
- AT-4 (lazy input): the fixture as `LazySource`s with `execution_mode="out_of_core"`: same masked
  output as AT-1; during the run the scratch root exists with mode 0700; after return, and after a
  raised budget error, it does not. Mutation: drop the `rmtree` in `__exit__`.
- AT-5 (routes): AT-1's assertion on each forced or induced route: `full_frame`, `sequential`,
  `out_of_core`, a mixed generate plus mask config, auto-chunk on a one-table subset config
  (threshold lowered), the multi-table split (an FK-free two-table config), and the unified slice.
  Each cell also asserts the route recorded in `quality_metrics`. Mutation: apply the stage after
  `decide_route`.
- AT-6 (nested entries): the auto-chunk cell of AT-5 reaches `run_mask_chunked` and does not raise
  `config.subset_run_unsupported`. Mutation: make the guard ignore the scope.
- AT-7 (refusals kept): `run_mask_pipeline_chunked`, `run_mask_chunked`,
  `run_native_or_oracle_chunked` and `compile_plan` called directly with a subset config raise
  `config.subset_run_unsupported` with the new fixed text, before pulling a chunk;
  `run_pipeline(..., source_loader=f)` with a subset config raises the same code before `f` is
  called. Mutation: remove the `source_loader` refusal.
- AT-8 (order): with spies on `profile_source`, `compile_plan` and the adapter, a seed on a table
  whose child has a source orphan under `orphan_policy: fail` raises `SubsetPreflightError`
  (`subset.subset_source_orphans`) with zero spy calls; a budget overrun raises
  `SubsetBudgetExceededError` with zero spy calls and no target written; a missing secret still fails
  before the stage reads anything (spy on `SubsetInput.collect`). Mutation: run the stage after
  `compile_plan`.
- AT-9 (isolated): `run_pipeline_isolated` with `isolate=True` and `False`, and
  `run_job_with_governor`, produce AT-1's rows. Replaces `test_isolated_refuses_before_spawn` and
  `test_governor_refuses_before_any_rung`. Mutation: keep the parent guard.
- AT-10 (scope, Q2): a third table `countries` in no relationship and a second component
  `products -> inventory` with no seed: the run returns all `countries`, `products` and `inventory`
  rows; `run_subset` writes them whole; the evidence lists them under `scope.whole`. Mutation: put
  every table in `in_scope`.
- AT-11 (generate edges): a mask child of a generate parent with a seed on the child: the run
  completes, the edge is listed under `scope.excluded_edges`, and the child's FK values resolve
  against the generated parent as they do without subset. Mutation: keep the edge (preflight
  `subset_unknown_table`).
- AT-12 (unchanged without subset): the existing golden and compat-corpus suites, the SUB-STOP
  `test_no_subset_runs_unchanged` cell, and no `subset` key in `quality_metrics`. Mutation: always
  stamp `subset: None`.
- AT-13 (value-free): a `filter` seed whose literal is a marker and `keys` seeds holding a marker: the
  marker is in no `quality_metrics`, exception text, warning or progress event; errors the stage
  re-raises have `__cause__ is None and __context__ is None`. Mutation: stamp raw seed specs.
- AT-14 (unconvertible key): a resident child table whose FK column is an Arrow type polars cannot

## 12. Pre-mortem

- Memory on the CLI path: the CLI holds every full source resident before the run
  (`C:src/decoy/cli/run.py:842`), and `take` adds the subset copy. Peak is the full sources plus the
  slice. Recorded; FU-2 lets the CLI pass Parquet sources lazily.
- A profile-dependent strategy (pool capacity, distribution sampling) uses the full source's bounded
  sample, so a pool capacity check can refuse a subset that would fit. AT-2 uses
  profile-independent strategies; a refusal found in use is a follow-up, not a skip.
- A key type a plain run masks but the subset preflight refuses (float keys, `"007"` against `7`) now
  stops a subset run. Same rule as `decoy subset`; the message names the fix.
- The `ContextVar` scope could miss a nested entry that runs on another thread. No lane spawns a
  Python thread that calls an entry today; AT-6 pins the auto-chunk path.
- H-1 or LAYOUT moves a file E2 edits. Sequencing in section 9; rebase cost only.
- Q2 changes `decoy subset` output for anyone relying on empty unseeded tables. Pre-GA; CHANGELOG.
- The platform's compile-then-run lane silently ignoring subset: closed by the kept `compile_plan`
  refusal (AT-7).
