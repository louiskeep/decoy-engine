## 1. Guarantee

A `decoy run` (and `run_pipeline`) with a `subset:` block computes the referentially closed subset
of the sources first, then masks and generates only the subset rows, on every route that can take
the result. An entry that cannot apply the subset refuses with a registered reason code before it
reads any source. There is no path where a subset config runs on full sources without saying so.

## 3. Established solutions

Tonic Condenser, Jailer and Redgate Subsetter all compute the closure first, materialize the subset
to a staging area, and run the transform on the staged copy. None subsets per chunk. This plan
follows that shape: closure on keys only, then one materialization step, then the normal run.

## 4. Behavior

### 4.1 The split

`split_subset_config(config) -> SubsetSplit` (new `subset/_split.py`) returns:

- `run_config`: a `PipelineConfig` copy with `subset=None`. The key stays and is `None`, so the
  config hash and dump match a config that never had a subset.
- `request`: a `SubsetRequest` (seeds, budget, edge directions, allow_dangling, relationships,
  table kinds) or `None`.
- `fingerprint`: SHA-256 over the canonical dump of the request. Value-free.

`run_pipeline` calls the split before anything else, in place of `refuse_unapplied_subset`. Every
later step, including `build_run_context`, `prepare_declared_sources` and the routing probe,
receives `split.run_config`. The `id(config)` binding then holds without change.

### 4.2 The stage

`execution/pipeline/_subset_stage.py` holds `SubsetStageScope`, entered beside `AdmissionScope` in
`run_pipeline`. In `build_run_context` the stage runs after `refuse_duplicate_run_sources` and
before `profile_source`:

1. `select_subset(request, inputs, job_seed=..., file_access=...)` computes the closure on key
   columns only and returns a `SubsetSelection` (row indices per in-scope table, counts, excluded
   edges).
2. Resident inputs (`pa.Table`) are filtered in memory with `take`.
3. Lazy inputs (`LazySource`, Parquet or CSV) are materialized as scratch Parquet files with
   opaque names `sNNNN.parquet` and re-wrapped as `LazySource(path, field_key="engine.scratch")`.
   Lazy stays lazy, so the stream route keeps working.
4. Tables with no seed path (unlinked) pass whole (owner Q2).
5. `routing_profile(profile, sources, prepared)` wraps the profile so routing sees subset counts.

The hook in `_pipeline_context.py` is about 2 lines: one call that returns the replaced sources
mapping, one `routing_profile` wrap.

After the route returns, `run_pipeline` stamps `quality_metrics["subset"]`:
`{"applied": true, "fingerprint": ..., "tables": {name: {"source_rows", "kept_rows",
"whole": bool}}, "excluded_edges": [...]}`. Counts and names only, no values.

## 6. Parquet-only decision

Today a run with `subset:` is refused. SUB-STOP also kept a config-time rule that seed and
relationship sources are Parquet (check 2). Options:

- A. Keep Parquet-only for runs. SAMPLE (row 63) then cannot meet its "same behavior on
  delimited, CSV, fixed-width and Parquet" line.
- B. Lift it for runs only: the stage reads resident tables from any reader and lazy Parquet or
  CSV sources. Keep it for the standalone path-based `decoy subset`, `plan_subset`, `run_subset`.
- C. Lift it everywhere, including the standalone command (needs readers in the subset path).

Recommendation: B. The owner already chose B on 2026-11-06 (Q1), so this is not a new owner
decision. C stays V2-LOG (FU-1).

## 12. Design notes

- Why the split is in `run_pipeline`: CONFIG-EXPLICIT binds declared sources to `id(config)`.
  Splitting inside `build_run_context` after `prepare_declared_sources` would bind the wrong
  object and fail `profile_source`.
- Why the stage sits after the duplicate-source check: the closure must see distinct sources, and
  the declaration check should validate the original inputs before any copy.
- Why lazy inputs become scratch Parquet and not resident: memory. A 10M-row lazy source with a
  1% subset must not become a 10M-row table.
- Why `take` on indices: one row filter for every input kind, deterministic order, and the
  count check (F10) is one comparison.
- Quarantine row positions number subset rows, not source rows. Documented in
  `docs/relationships.md`.
- Memory peak for the CLI resident path is full sources plus the subset copy. Acceptable for V1;
  lazy CLI reads are V2-LOG.

## 13. What SAMPLE (row 63) needs from SUB-RUN

1. The stage takes `(run_config, SubsetRequest)`, not the raw config, so SAMPLE can build a
   request without a `subset:` block.
2. Public `SubsetRequest` and `SubsetScope` types exported from `decoy_engine.subset`.
3. The unlinked-table policy is one function (`scope.whole`) SAMPLE can swap for head-N.
4. A stable `quality_metrics["subset"]` shape SAMPLE extends with `"sample"`.
5. Output to scratch, never targets: SUB-RUN already stages to scratch; SAMPLE adds a scratch
   sink. A future additive `run_pipeline(..., subset_request=)` keyword is SAMPLE's change, not
   this plan's.
6. Format parity (AT-12) is the base for SAMPLE's "same behavior on every format" line.
