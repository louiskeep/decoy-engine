## 1. FRAME

**Problem.** The copula (V2-4.2/4.3) produces synthetic rows that keep pairwise dependence, but
the engine has no published way to say how well it did or how close the rows sit to real records.
`quality/` measures marginals and snapshot joints for masking output (`quality-report/v1`) and has
a privacy report for synthetic output (`synth-report/v1`: new-row synthesis, DCR, opt-in attacks),
but nothing scores pairwise dependence between real and synthetic columns, and the existing DCR
treats two nulls in a numeric column as maximally distant, which hides near-copies in exactly the
null-bearing tables the copula models. Every score in such a report is also a statistic of the real
data: a pair score for a pair the copula suppressed would release the very correlation the floors
withheld; a contingency score over near-unique cells is an exact-match count; a DCR percentile in
the tail is a distance between specific isolated real rows. The report must apply the copula's
floors to each of its own releases.

**Definition of done.**

1. `compute_copula_quality_report(real, synthetic, model, *, holdout=None, dcr_max_rows=5000,
   attack_extras=None) -> CopulaQualityReport`, exported from `decoy_engine.generation.copula`, a
   frozen dataclass whose `to_dict()` is JSON-safe (`json.dumps(..., allow_nan=False)`), schema
   `decoy-copula-quality-report/v1`.
2. `real` is tied to the model: its snapshot, recomputed with the model's parameters, must equal
   the model's marginals (section 4.1), as the fit requires of its snapshot.
3. Pairwise fidelity per SDMetrics' definitions: Spearman `CorrelationSimilarity` for every
   numeric/numeric pair, `ContingencySimilarity` for every pair with a categorical column, with
   numeric columns discretized by the model's own bin edges, nulls as their own state, and every
   state held by fewer than `MIN_DISTINGUISHED_ROWS` real rows folded into the side's `other`
   bucket (global recoding).
4. Marginal goodness of fit per column released only through the snapshot-only extras of the
   existing `compute_fidelity` (`ks_complement` on bin edges and counts, `chi_cramers_v` on label
   counts): functions of the model's marginals and the synthetic table, nothing else of `real`.
5. Privacy: a chunked Gower DCR with SDMetrics' null rule, a real-to-real baseline, and, with a
   holdout, SDMetrics' `DCROverfittingProtection` share; each percentile released only when enough
   rows lie beyond it. Plus the existing `compute_new_row_synthesis` and `compute_attack_metrics`
   run on canonicalized copula output and bundled through the existing `assemble_synth_report`.
6. Every pair score passes one gate (section 4.4); every DCR percentile passes one percentile
   floor (section 4.6); the released pair count is charged against the copula's release budget
   (section 4.4). The report holds scores, counts, column names and tokens only.
7. Acceptance (section 9) proves the definitions against independent oracles (the copula's test
   helper, a brute-force DCR, the existing `compute_dcr` where definitions coincide), each floor,
   value-freeness, immutability, determinism, and that V1 surfaces are unchanged.

**Non-goals.**

- No wiring: no config key, no CLI or platform surface, no job event, no persistence, no
  `checks_passed` entry, no strategy catalog row, proof manifest or capability matrix change.
- No reader (`from_dict`): nothing persists this report yet; a wiring slice adds a versioned
  reader with the strict-type rules of catalog items 2 and 4.
- No grade, threshold or pass/fail verdict on fidelity: numbers only. (The embedded
  `synth-report/v1` keeps its own `severity`, unchanged.)
- No Pearson score (decided in plan review), no datetime or freetext pairs (the copula refuses those
  columns), no multi-table, no conditional metrics, no ML attacks in the engine.
- No change to any `quality/` module: `_dcr.py`, `synth_report.py`, `fidelity.py` stay
  byte-identical (V1). Moving `synth-report/v1` onto the new DCR core is a recorded follow-up
  (section 10), not this slice.
- Not a privacy guarantee. DCR and the floors are heuristics; the copula is not differentially
  private (V2-4.5 / DPS-4).

**Risk: R2.** Privacy logic (new releases of statistics computed from real data, gated by the
copula's disclosure floors) and a new report schema. Dark and library-only, so rollback is

## 2. Established solutions

Searches run (2026-11-07, WebSearch plus source reads): "SDMetrics DCROverfittingProtection
DCRBaselineProtection distance to closest record missing values range normalized"; "SDMetrics
ContingencySimilarity CorrelationSimilarity formula total variation distance continuous discretize
bins". `docs.sdv.dev` does not resolve from this session; the method was read from the SDMetrics
source on `raw.githubusercontent.com` (`dcr_utils.py`, `dcr_overfitting_protection.py`,
`correlation_similarity.py`, `contingency_similarity.py`; method only, the library is under the
Business Source License and `tests/sentry/test_sdv_import_sentry.py` forbids importing it).
In-codebase: every `quality/` module listed in section 1, `verification/`, `validation/post/`,
the copula package and its plan.

| Part | Source followed | Deliberate deviations (with reason) |
|---|---|---|
| Correlation similarity | SDMetrics `CorrelationSimilarity`: `1 - |r_real - r_synth| / 2`, each correlation on that frame's rows where both columns are present (`dropna` per frame), `coefficient='Spearman'` | SDMetrics' default is Pearson; Spearman for its bounded per-row leverage (section 4.3). SDMetrics raises on a constant column; here that is a status token |
| Contingency similarity | SDMetrics `ContingencySimilarity`: `1 - TVD` between the normalized joint frequency tables (`groupby(..., dropna=False)`, so null is a category), numeric columns discretized into bins decided from the real data (default 10) | (a) the bins are the model's own `bin_edges`, so no new statistic of a column is used; (b) SDMetrics does not collapse rare states; here every state with fewer than `MIN_DISTINGUISHED_ROWS` real rows, and the model's tail labels, fold into `other`, because a cell of one or two rows makes `1 - TVD` an exact-match count over those rows (section 4.3); (c) high-cardinality columns are withheld |
| Small-cell control | global recoding (Hundepool et al., *Statistical Disclosure Control*, Wiley 2012, sec. 3.4 and 4.2: recode categories below a threshold into a combined category before tabulation); threshold the CMS cell size 11 via the copula's `MIN_DISTINGUISHED_ROWS` | |
| Pair coverage | SDMetrics `QualityReport` "Column Pair Trends": correlation for numeric/numeric, contingency otherwise, score = mean over pairs | |
| Marginal goodness of fit | the engine's `compute_fidelity` extras (SDV `QualityReport` column shapes: KSComplement on a binned CDF; chi-square Cramér's V on a common partition) | only the snapshot-only extras are released (section 4.5) |
| DCR distance | SDMetrics `calculate_dcr` (Gower 1971 mixed-type distance): numeric `min(|a - b| / range, 1)`, a zero range gives 0 if equal else 1; categorical 0 if equal else 1; both null 0, one null 1, in every kind; mean over columns; chunked | SDMetrics normalizes by each reference frame's own range; here the real column's span (the model's edges) is used for every reference, so synthetic-to-real and synthetic-to-holdout distances share one unit and no holdout statistic enters the scale |
| DCR baseline | real-to-real nearest-neighbour distance (each real row to its nearest other real row), the DCR comparison of table-GAN (Park et al., PVLDB 11(10), 2018) and CTAB-GAN (Zhao et al., ACML 2021) | |
| Overfitting share | SDMetrics `DCROverfittingProtection`: share of synthetic rows strictly closer to training than to holdout (`dcr_real < dcr_holdout`), score `min(2 (1 - share), 1)` | SDMetrics does not equalize training and holdout size (it warns below half and subsamples only with `num_rows_subsample`, randomly); a larger reference has smaller nearest distances, which biases the share toward "closer to training", so here both are cut to the same size, systematically |
| Percentile floor | the small-cell rule applied to order statistics: a percentile is released only when at least `MIN_DISTINGUISHED_ROWS` rows lie on each side of it, so it never describes a group smaller than a released cell may (Hundepool et al. 2012, sec. 4.3, threshold rules for magnitude tables) | |
| Sampling | systematic sampling (Cochran, *Sampling Techniques*, 3rd ed., 1977, ch. 8): rows `floor(i N / k)` for `i < k` | deterministic without a seed |
| Report hygiene | "high fidelity does not imply low privacy" (NIST IR 8336 sec. 5.3, as `synth_report.py` already cites) | through the reused disclaimers |

Why custom code is needed: SDMetrics is not an allowed dependency (BSL), the engine has no
pairwise real-versus-synthetic score, and the existing DCR's null and range rules and memory
profile do not fit (reuse table). Each new piece is a short published definition pinned by an
independent oracle.

## 3. Behavior

Public surface, added to `decoy_engine.generation.copula` (not to `decoy_engine.__all__`,
`generation.__init__` or `quality`):

- `compute_copula_quality_report(real, synthetic, model, *, holdout=None, dcr_max_rows=5000, attack_extras=None) -> CopulaQualityReport`
- `CopulaQualityReport`, `PairScore`, `MarginalFit`, `DcrSummary`, `DcrBlock`,
  `HoldoutComparison` (frozen dataclasses); `COPULA_QUALITY_REPORT_SCHEMA_VERSION`.

Example:

```python
from decoy_engine.generation.copula import (
    compute_copula_quality_report, fit_gaussian_copula, sample_gaussian_copula,
)

model = fit_gaussian_copula(real, snapshot, seed=fit_key)
synthetic = sample_gaussian_copula(model, len(real), seed=sample_key)
report = compute_copula_quality_report(real, synthetic, model)
report.pairwise_score        # mean of scored pairs, 3 decimals
report.to_dict()["pairs"][0] # {"columns": ["x", "y"], "metric": "spearman_correlation_similarity",
                             #  "status": "scored", "reason": None, "score": 0.991}
```

`to_dict()` has exactly these top-level keys: `schema_version`, `rows` (`real`, `synthetic`,
`holdout` or null), `marginal` (`columns`: each `column`, `gof_method`, `gof_value`), `pairs`
(each `columns`, `metric`, `status`, `reason`, `score`), `pairwise` (`score`,
`correlation_score`, `contingency_score`, `scored`, `withheld`, `undefined`), `dcr` (section 4.6),
`synth_report` (the `synth-report/v1` dict from `assemble_synth_report`, embedded unchanged,
section 4.7). Every float in the report's own blocks is rounded to `RELEASE_DECIMALS` (3);
undefined or withheld is `null`.

Pair status and reason tokens (closed sets):

| Status | Reason | When |
|---|---|---|
| `scored` | null | the gate passed and both sides are defined |
| `withheld` | `suppressed_in_model` | the model suppressed a latent variable this score depends on |
| `withheld` | `pair_rows` | a Spearman pair with fewer than `MIN_PAIR_ROWS` real rows where both are present |
| `withheld` | `distinguished_rows` | a side with fewer than `MIN_DISTINGUISHED_ROWS` real rows outside its largest group, counted on the rows the score uses (after recoding, for contingency) |
| `withheld` | `high_cardinality` | a contingency pair with a column the model holds with its full vocabulary (snapshot `high_cardinality`) |
| `undefined` | `empty_column` | either column is all null in the model (`kind == "empty"`) |
| `undefined` | `constant_in_synthetic` | Spearman with a constant synthetic side on its complete rows |
| `undefined` | `too_few_synthetic_rows` | Spearman with fewer than 2 synthetic complete rows |

DCR percentile tokens: a percentile is `null` with `percentile_rows` in the block's `withheld`
list when it fails the percentile floor (section 4.6).

Failure modes (all raised before any statistic is computed; messages name an argument, column or
field and the rule, never a value; raised after any `except` closes, so `__cause__` and
`__context__` are `None`):

| Failure | Behavior |
|---|---|
| `real`, `synthetic` or `holdout` not a DataFrame; `model` not a `GaussianCopulaModel` | `TypeError` |
| column names that collide after `str()`, or a frame whose columns are not exactly the model's | `ValueError` |
| `len(real) != model.row_count`, or `real`'s recomputed snapshot differs from the model's marginals in any field (section 4.1) | `ValueError` naming the column and field |
| a synthetic or holdout column whose dtype disagrees with the model kind (numeric non-bool for `numeric`) | `ValueError` naming the column |
| a non-finite numeric value in any frame | `ValueError` naming the column |
| empty `synthetic` | `ValueError` |
| `holdout` with fewer than `MIN_FIT_ROWS` rows or other columns | `ValueError` |
| the model's latent pairs plus the report's candidate pairs exceed `max_latent_pairs(row_count)` (section 4.4) | `ValueError` |
| `dcr_max_rows` not an `int` (bool refused) or outside `[MIN_FIT_ROWS, 20000]` | `TypeError` / `ValueError` |
| `attack_extras` not `None` or a dotted module name (`re.fullmatch` of `[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)*`) | `TypeError` / `ValueError` |

An attack extras module that raises is not a failure: the reused contract records
`extras_runtime_error` with the exception type only.

## 4. Design notes

### 4.1 Inputs, the tie to the model, canonical form (`_quality_inputs.py`)

- **Tie to the model.** The fit accepts a snapshot only if a recomputed snapshot of the frame
  equals it; the report holds `real` to the same rule against the model. Parameters come from the
  model's columns through the fit's own `_snapshot_parameters` (bin count from any non-constant
  numeric column, top-K from the collapsed or longest categorical). High-cardinality columns are
  not marked in the model, so they are found from the snapshot itself: a first recompute without
  any high-cardinality column; every column the model holds as `categorical` but the recompute
  classes as `freetext` (the snapshot's distinct-value cliff, which only a high-cardinality column
  crosses while staying categorical) is marked and the snapshot recomputed once more with those
  columns. Each recomputed entry goes through `from_snapshot_entry` and must equal the model's
  `ColumnMarginal` (dataclass equality: kind, dtype, counts, edges, labels). A frame with one
  column permuted still passes (same marginals), which is why the floors below run on `real`.
- Kinds come from the model, never re-inferred.
- Canonical frame per input (a copy; inputs are never mutated): numeric columns as `float64` with
  `NaN` for null (`Int64`/`<NA>` included); categorical columns as `object` holding `str(value)`
  (the snapshot's label rule, `snapshot.py` lines 279 to 289) or `None`.
- Discrete state per column for contingency: a numeric value to its bin index in the model's
  `bin_edges` (numpy histogram convention, `[e_k, e_k+1)`, last bin closed); the snapshot rounds
  edges to 12 decimals, so a value on a computed edge can fall just outside the rounded span, and
  such values clip to the end bins (the copula has the same rounding note). Null is its own state.
  A categorical label maps to its index in the model's `top_values`; any other label to `other`.
  Then **recoding**: every state (bin, label or null) held by fewer than `MIN_DISTINGUISHED_ROWS`
  real rows is merged into that column's `other` state, for both frames with the same mapping (the
  mapping is decided from real counts only). The merged `other` is itself just one more state; if
  it ends below the threshold it is still a combined group, and R3 (section 4.4) decides.
- Systematic sample `rows(N, k) = floor(arange(k) * N / k)` when `N > k`, else all rows.

### 4.2 Why the report lives in the copula package

Plan review placed it in `generation/copula/` as `_quality_*.py` modules. It needs the copula's
private facts (`_floors`, `latent_layout`, the role and kind tokens, the fit's snapshot
comparison), and inside the package these are ordinary imports, so nothing is exported only to
serve the report and no fact is restated. The dependency stays one-way: `generation.copula` imports
public `quality` modules (`snapshot`, `fidelity`, `synth_report`), and `quality` imports nothing
from `generation`. `quality/` (25 entries, at its fan-out limit) gets no new entry.

### 4.3 Pairwise fidelity (`_quality_pairwise.py`)

- Numeric/numeric: Spearman correlation on each frame's rows where both are present: average-tie
  ranks of the subset, then the Pearson correlation of the ranks (the definition `scipy.stats
  .spearmanr` and pandas use). Score `1 - |rho_real - rho_synth| / 2`. Ranks of null-free columns
  are computed once per column; a pair with a null on either side re-ranks its subset.
- Any pair with a categorical column (recoded discrete states, section 4.1): `1 - 0.5 *
  sum |p_real(cell) - p_synth(cell)|` over the union of cells, with cell counts from
  `numpy.unique` on the paired state codes. Equivalently `sum min(p_real, p_synth)`, which is why
  cells of one or two real rows must not exist: over near-unique cells the score is the share of
  real rows whose exact pair of values the synthetic table reproduces. After recoding, every real
  state of each column holds at least 11 rows or is the combined `other`.
- **Why Spearman only** (decided in review). A pair score next to the synthetic table gives
  `|rho_real - rho_synth|`, i.e. the real coefficient up to sign at 3-decimal resolution. Spearman
  is a function of ranks, so one row moves it by `O(1/n)` however extreme its value, the copula's
  own leverage argument (copula plan section 10). Pearson on raw values has no such bound.
- Aggregates: `correlation_score` and `contingency_score` are the means of scored pairs of each
  metric; `score` the mean of all scored pairs (SDMetrics Column Pair Trends). All `None` when
  nothing is scored. Means are taken over the rounded pair scores, then rounded.

### 4.4 The release gate (`_quality_gate.py`): the one choke point

Every pair goes through `withhold_reason(pair, ctx) -> str | None` before any real-side statistic
of that pair is computed; `_quality_pairwise.score_pairs` is the only caller and the only
constructor of `PairScore` (also guarded against `dataclasses.replace`, section 6). In order:

1. `empty_column` (status `undefined`, not a privacy rule).
2. **R1, model suppression.** The score's latent dependencies, derived from `latent_layout` by
   role: Spearman(a, b) depends on `value(a)` and `value(b)`; contingency(a, b) on every latent
   variable of `a` and of `b` (value and null indicator of a numeric column, the state variable of
   a categorical). If any is in `model.suppressed`, the pair is withheld `suppressed_in_model`.
   Without R1, the synthetic correlation of a suppressed variable is about 0 and the score would
   equal `1 - |rho_real| / 2`, releasing exactly what the floors withheld.
3. **R4, high cardinality** (contingency only). A column the tie step (section 4.1) found to be
   high-cardinality is withheld `high_cardinality`: its full vocabulary sits in the model, most
   states are near-unique, and recoding would leave an `other` that is most of the column, so the
   score would say little except about the few large labels. Spearman is unaffected (such columns
   are categorical).
4. **R2, Spearman rows (on `real`).** Rows where both are present at least `MIN_PAIR_ROWS` (else
   `pair_rows`); each side's distinguished rows (rows outside its largest tied-value group)
   counted on those rows at least `MIN_DISTINGUISHED_ROWS` (else `distinguished_rows`). This also
   covers a constant real side.
5. **R3, contingency rows (on `real`, after recoding).** Each side's distinguished rows on all
   rows, counted over its recoded states, at least `MIN_DISTINGUISHED_ROWS` (else
   `distinguished_rows`). Counting bins is stricter than the copula's tied values.

R2 and R3 run on `real` because the tie in section 4.1 checks marginals, not pair overlaps. The
constants come from `_floors`; the "rows outside the largest group" count reuses the fit's
`_distinguished` (same package).

**Release budget.** The copula caps released correlations at `max_latent_pairs(row_count)`
(half the row count, Dinur and Nissim as motivation). The report's pair scores are further
aggregates of the same rows, so they are charged against the same budget: the report refuses when
`d (d - 1) / 2` (the model's latent pairs) plus `c (c - 1) / 2` (candidate column pairs among the
`c` non-empty columns) exceeds `max_latent_pairs(row_count)`. Candidate pairs are counted, not
scored pairs, so the refusal does not depend on which pairs the floors withhold. Marginal fits and
DCR percentiles are not charged: the marginal fit is a function of the model's own marginals and
the synthetic table (section 4.5), and DCR percentiles have their own floor (section 4.6).

### 4.5 Marginals (`_quality_report.py`)

`compute_fidelity(real_snapshot, synthetic_snapshot)` with both snapshots computed with the
model's parameters (section 4.1). Only `extra_metrics` is released: `ks_complement` for numeric
columns (it reads `bin_edges` and `bin_counts`, which for `real` equal the model's after the tie)
and `chi_cramers_v` for categorical columns (it reads `top_values` and `other_count`, likewise),
as `gof_method` and `gof_value`, rounded to 3 decimals; `empty` columns give `null`. The primary
`similarity` (`quantile_rmse` over real p05 to p95 and min/max, `fidelity.py` lines 366 to 401)
is computed by the reused call but not released: the model holds no quantiles.

### 4.6 DCR (`_quality_dcr.py`)

- Columns: every model column except `empty` ones. With no column left the block is `null`.
- Encoding: numeric columns as `float64` (`NaN` null); categorical columns as integer codes over
  the union of the frames' canonical labels, as `float64` with `NaN` for null, compared by
  equality. Range per numeric column: `bin_edges[-1] - bin_edges[0]` from the model (the real
  span, already released); synthetic or holdout values beyond it clip to distance 1.
- Distance per cell (SDMetrics `calculate_dcr`): numeric `min(|a - b| / range, 1)`, or
  `0 if a == b else 1` when the range is 0; categorical `0 if a == b else 1`; both null 0; exactly
  one null 1. Row distance: the mean over columns. DCR of a row: the minimum over reference rows.
- Samples: synthetic `k_s = min(len(synthetic), dcr_max_rows)`, real `k_r = min(len(real),
  dcr_max_rows)`, both systematic.
- Passes and outputs (all rounded to 3 decimals):
  1. synthetic to real (`k_s x k_r`): `synthetic_to_real` percentiles; `exact_match_share` (share
     of sampled synthetic rows at distance exactly 0; NRS already releases the exact-match count).
  2. real to real (`k_r x k_r`, own index excluded; true duplicates count as 0): `real_to_real`
     percentiles.
  3. with a holdout, `k_h = min(len(real), len(holdout), dcr_max_rows)`; real and holdout each
     cut to `k_h` rows systematically; synthetic to holdout (`k_s x k_h`), and, when `k_h < k_r`,
     a fourth pass synthetic to the `k_h`-row real sample (`k_s x k_h`; when `k_h == k_r` pass 1 is
     reused). `closer_to_real_share` (strict `<`), `protection_score = min(2 (1 - share), 1)`,
     `synthetic_to_holdout` percentiles, `rows_compared`.
  Each block also has `rows`, and `columns`, `real_rows_sampled`, `synthetic_rows_sampled` sit at
  block level.
- **Percentile floor.** Percentiles `q` in `(0.05, 0.25, 0.5, 0.75, 0.95)` (numpy `quantile`,
  linear). `q` is released only when `min(q, 1 - q) * rows >= MIN_DISTINGUISHED_ROWS`, where
  `rows` is the number of distances in that block; otherwise it is `null` and `percentile_rows`
  is listed for it in the block's `withheld` map. So `p05`/`p95` need 220 rows, `p25`/`p75` 44,
  the median 22. The floor applies to all three distance blocks: `real_to_real` is a pure set of
  real order statistics (at 100 rows, `p95` sits among the five most isolated real rows, typically
  the rare group the model suppressed), and the other two are distances to specific real or
  holdout rows. The shares and `protection_score` are means over all synthetic rows and are kept.
- Memory: synthetic (or real, for the baseline) rows are processed in blocks of 256; per block one
  `256 x k_ref` accumulator and a bounded number of same-size temporaries: about 42 MB measured at
  `k_ref = 5000` (prototype, tracemalloc, 5 and 20 columns), about 170 MB at the `20000` cap,
  independent of the column count and of the number of query rows.
- Time: `O(k_q * k_ref * columns)` per pass, about 0.2 s per column per 25 million row pairs on
  the build machine (prototype: 0.98 s for 5 columns, 3.8 s for 20 at 5000 x 5000). Two passes
  without a holdout, three or four with one. At `dcr_max_rows = 20000` and 20 columns one pass is
  about 60 s (16 times the 5000-row pass), so a four-pass report is about 4 minutes; the default
  5000 keeps a pass near 4 s at 20 columns.
- Determinism: no RNG; fixed column order, fixed block order, float64; the minimum over a block is
  exact, so the result does not depend on the block size (acceptance A4 checks 1, 7, 256).

### 4.7 Existing checks on copula output (`_quality_report.py`)

- `compute_new_row_synthesis(real_canon, synthetic_canon)` on the canonical frames: an `Int64`
  synthetic integer column and its `float64`-with-`NaN` real column would otherwise hash as `"5"`
  against `"5.0"` and `"<NA>"` against `"nan"`, so a copied row would never match. With the
  canonical form a null and the label `"None"` hash alike; that errs toward reporting a match.
- `compute_attack_metrics(real, synthetic, enable_attacks=attack_extras is not None,
  extras_module=attack_extras or <default>, holdout=holdout)`: the caller names the extras module
  instead of passing a flag. When the extras ran, its `results` are kept only if they are a flat
  mapping of keys matching `[a-z][a-z0-9_]{0,63}` to bools or finite numbers in `[0, 1]`; kept
  numbers are rounded to 3 decimals. Anything else (a string, a nested value, a number outside
  `[0, 1]`, which could be a raw value or count) drops `results` and sets `results_status:
  "withheld_not_value_free"`.
- `assemble_synth_report(new_row_synthesis=..., dcr=None, attacks=...)`, embedded as `synth_report`
  unchanged: its own fields keep their own contract (`fraction_new` rounded to 4 decimals by
  `compute_new_row_synthesis`; it equals `new_rows / output_row_count`, both released counts, so
  the extra digit adds nothing). Its disclaimers apply (DCR is not a guarantee, no DP claim, high
  fidelity is not privacy, attacks off unless opted in). Its `dcr` is null; the copula report's DCR
  is in its own block.

### 4.8 Frozen, value-free report (`_quality_report.py`)

- Frozen dataclasses with tuple fields; the embedded synth report is deep-frozen (mappings to
  `MappingProxyType`, lists to tuples) and thawed by `to_dict()`, which returns new objects each
  call. `__repr__` shows counts and the three aggregate scores only.
- Value-free: column names, counts, rounded scores and closed tokens. No label, bin edge, quantile,
  per-row distance or row index.

### 4.9 Principles and structure

- Single responsibility: `_quality_inputs` (validation, the tie, canonical form, recoding,
  sampling), `_quality_gate` (pair release gate and budget), `_quality_pairwise` (two SDMetrics
  definitions), `_quality_dcr` (one distance, its summaries and the percentile floor),
  `_quality_report` (types, assembly, reuse calls). The gate changes for privacy reasons, the
  metrics for method reasons; they are kept apart so a metric change cannot skip the gate.
- Deep module: one function and one report type; dependency mapping, canonical form, recoding and
  chunking are hidden.
- One place per fact: floors, precision, kinds, roles, layout and the snapshot comparison are the
  copula's own; marginals and the synth report come from their existing modules.
- No registry: two metrics, a closed set. Logging none (pure library, as the copula).

## 7. Fail-before proofs

- R1: with the gate removed (M1), the score of a suppressed pair equals `1 - |rho_real| / 2` to 3
  decimals, i.e. the withheld correlation is readable from the report.
- Recoding: on a 200-row table with a near-unique categorical paired with a 2-state column, the
  unrecoded contingency score equals the share of real rows whose exact pair the synthetic table
  holds (the `sum min` identity); recoded, the score no longer depends on which rare pairs were
  reproduced.
- Percentile floor: at 100 real rows with a 5-row isolated group, the unfloored `real_to_real`
  `p95` equals a distance within that group; floored, it is null.
- NRS: raw copula output against the raw real frame finds 0 of 10 planted copied rows in a table
  with a nullable integer column; the canonical path finds 10.
- DCR: the existing `compute_dcr` reports a nonzero median for a synthetic table that copies real
  rows containing numeric nulls; the copula report's DCR gives `exact_match_share` 1.0 and median 0.

## 8. Thresholds

The report has no pass/fail threshold. The fidelity acceptance cells reuse the copula's measured
bounds for the same metric (copula plan section 13 rerun: Spearman similarity at least 0.97 per
numeric pair on the numeric and mixed fixtures; independent baseline below 0.97), on its three
pinned seed sets. The contingency cells reuse the copula's "copula minus baseline at least -0.03 per
pair, mean gap at least 0.015" bounds; the fixture's states all hold well over 11 rows, so recoding
does not change them. If the library score disagrees with the copula's helper beyond rounding (A1),
that is a finding, not a reason to loosen a bound.

## 10. Known limits

- **The scores are new releases about the real data.** A pair score with the synthetic table in
  hand gives the real Spearman coefficient up to sign at 3 decimals; a contingency score is one
  total-variation number over the recoded real joint table (one row moves it by at most `1/n`);
  DCR percentiles are distances between specific rows, released only behind the percentile floor.
  They are gated by the copula's heuristic floors, not by a formal bound, and an attacker who knows
  every other row can still learn about the rest. Recorded in `docs/what-we-cannot-prove.md`. DP
  (V2-4.5) does not cover this report; a DP report is its own follow-up.
- **Differencing across pairs, calls and releases.** The copula's differencing limit applies to the
  scores; in addition, reports computed on neighbouring tables (a row added or removed between
  runs, or two overlapping extracts) can be differenced: one row moves a Spearman coefficient by
  about `1/n`, far above the 0.001 resolution at `n <= 1000`, so two reports can reveal that row's
  rank position. Nothing in a library function can count releases across calls; a wiring slice
  that publishes reports must charge them to a release budget (or DP).
- **The release budget is shared, not doubled.** The report refuses when the model's latent pairs
  plus its candidate column pairs exceed `row_count // 2`, so a table whose model already spends
  most of the budget gets no report: the caller fits more rows or reports on fewer columns.
- **Over-withholding.** A numeric column with 1 to 10 nulls has its null indicator suppressed, so
  every contingency pair with it is withheld even though its Spearman pairs are scored.
  High-cardinality columns get no contingency score at all. Recoding merges rare states, so the
  contingency score does not see whether rare combinations were reproduced.
- **No Pearson.** SDMetrics' default coefficient is not reported (section 4.3).
- **No primary marginal similarity.** Only the snapshot-only goodness-of-fit extras are released;
  the quantile-based `similarity` of `quality-report/v1` is not.
- **Two DCRs exist until a follow-up.** `synth-report/v1`'s `compute_dcr` keeps its own rules
  (null/null 1.0, `None` versus `NaN`, zero-range 1.0; the orchestrator raises this as a V1 row).
  Follow-up: move `synth-report/v1` onto this DCR core so one definition remains; until then the
  same data gives different DCRs in the two reports when numeric nulls or constant columns occur.
- **DCR is a sample statistic.** Above `dcr_max_rows` the percentiles describe a systematic sample;
  a periodic row order aligned with the stride could bias it.
- **The holdout is the caller's.** The report cannot check that holdout rows were not in the fit.
- **Cost.** Pairs are `O(P (n_real + n_synth) log n)` time with `P` pairs (bounded by the budget,
  so at most `row_count / 2`); DCR as section 4.6, up to about 4 minutes at the 20,000-row cap and
  20 columns with a holdout.
- **The tie checks marginals, not rows.** A frame with the same marginals as the model's table but
  different rows passes; R2 and R3 still apply to it.
- **Canonical null equals the label `"None"` in NRS**, which can only add matches.
- **Attack extras results** are released only as bools and numbers in `[0, 1]` at 3 decimals; an
  extras module that returns other scores gets them withheld (recorded in
  `docs/what-we-cannot-prove.md`).
