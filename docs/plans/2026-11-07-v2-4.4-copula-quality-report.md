## 1. FRAME

**Problem.** The copula (V2-4.2/4.3) produces synthetic rows that keep pairwise dependence, but
the engine has no published way to say how well it did or how close the rows sit to real records.
`quality/` measures marginals and snapshot joints for masking output (`quality-report/v1`) and has
a privacy report for synthetic output (`synth-report/v1`: new-row synthesis, DCR, opt-in attacks),
but nothing scores pairwise dependence between real and synthetic columns, and the existing DCR
treats two nulls in a numeric column as maximally distant, which hides near-copies in exactly the
null-bearing tables the copula models (null is a sampled state there). A pairwise score also has a
privacy trap specific to the copula: a pair score is a function of the real correlation, so a
score for a pair the copula suppressed would release the very correlation the floors withheld.

**Definition of done.**

1. `compute_copula_quality_report(real, synthetic, model, *, holdout=None, dcr_max_rows=5000,
   attack_extras=None) -> CopulaQualityReport`, a frozen dataclass whose `to_dict()` is
   JSON-safe (`json.dumps(..., allow_nan=False)`), schema `decoy-copula-quality-report/v1`.
2. Pairwise fidelity per SDMetrics' definitions: Spearman `CorrelationSimilarity` for every
   numeric/numeric pair, `ContingencySimilarity` for every pair with a categorical column, with
   numeric columns discretized by the model's own bin edges and nulls as their own category.
3. Marginal similarity per column by calling the existing `compute_fidelity` on the two frames'
   snapshots (no new marginal metric).
4. Privacy: a chunked Gower DCR with SDMetrics' null rule, a real-to-real baseline, and, with a
   holdout, SDMetrics' `DCROverfittingProtection` share; plus the existing
   `compute_new_row_synthesis` and `compute_attack_metrics` run on canonicalized copula output and
   bundled through the existing `assemble_synth_report`.
5. Every pair score passes one gate (section 4.3) that withholds it when the model suppressed a
   latent variable the score depends on, or when the score's own rows fail the copula's floors on
   the frame passed in. The report holds scores, counts, column names and tokens only.
6. Acceptance (section 9) proves the definitions against independent oracles (the copula's test
   helper, a brute-force DCR, the existing `compute_dcr` where definitions coincide), the gate on
   each floor, value-freeness, immutability, determinism, and that V1 surfaces are unchanged.

**Non-goals.**

- No wiring: no config key, no CLI or platform surface, no job event, no persistence, no
  `checks_passed` entry, no strategy catalog row, proof manifest or capability matrix change.
- No reader (`from_dict`): nothing persists this report yet; a wiring slice adds a versioned
  reader with the strict-type rules of catalog items 2 and 4.
- No grade, threshold or pass/fail verdict on fidelity: numbers only. (The embedded
  `synth-report/v1` keeps its own `severity`, unchanged.)
- No Pearson score (section 4.2, open question 1), no datetime or freetext pairs (the copula
  refuses those columns), no multi-table, no conditional metrics, no ML attacks in the engine.
- No change to `quality/_dcr.py`, `synth_report.py`, `fidelity.py` or any existing `quality/`
  module (V1 byte-identity; `synth_report.py` is 451 lines on this base, well under the cap, but it
  is not touched either).
- Not a privacy guarantee. DCR and the floors are heuristics; the copula is not differentially
  private (V2-4.5 / DPS-4).

**Risk: R2.** Privacy logic (a new release of statistics computed from real data, gated by the
copula's disclosure floors), a new report schema, and a new cross-package dependency
(`quality.copula` imports the public `generation.copula` surface). Dark and library-only, so
rollback is reverting the branch. Approver: independent plan and code review (Dennis), then the
owner; owner instruction 2026-11-07: do not merge.

## 2. Established solutions

Searches run (2026-11-07, WebSearch plus source reads): "SDMetrics DCROverfittingProtection
DCRBaselineProtection distance to closest record missing values range normalized"; "SDMetrics
ContingencySimilarity CorrelationSimilarity formula total variation distance continuous discretize
bins". `docs.sdv.dev` does not resolve from this session; the method was read from the SDMetrics
source on `raw.githubusercontent.com` (`dcr_utils.py`, `dcr_overfitting_protection.py`,
`correlation_similarity.py`, `contingency_similarity.py`; method only, the library is under the
Business Source License and `tests/sentry/test_sdv_import_sentry.py` forbids importing it).
In-codebase: every `quality/` module listed in section 1, `verification/`, `validation/post/`,
the copula package and its plan.

| Part | Source followed | Notes |
|---|---|---|
| Correlation similarity | SDMetrics `CorrelationSimilarity`: `1 - |r_real - r_synth| / 2`, each correlation on that frame's rows where both columns are present (`dropna` per frame), `coefficient='Spearman'` | SDMetrics' default is Pearson; Spearman is chosen for its bounded per-row leverage (section 4.2). SDMetrics raises on a constant column; here that is a status token |
| Contingency similarity | SDMetrics `ContingencySimilarity`: `1 - TVD` between the normalized joint frequency tables (`groupby(..., dropna=False)`, so null is a category), numeric columns discretized into bins decided from the real data (default 10) | the bins are the model's own `bin_edges` (the snapshot's 10 equal-width bins by default), so no new statistic of a column is used; the real tail labels the model collapsed into `other` stay one bucket |
| Pair coverage | SDMetrics `QualityReport` "Column Pair Trends": correlation for numeric/numeric, contingency otherwise, score = mean over pairs | |
| Marginal similarity | the engine's `compute_fidelity` (SDV `QualityReport` column shapes: KSComplement / TVComplement as its `ks_complement`, quantile-RMSE / TVD as primary) | reused unchanged |
| DCR distance | SDMetrics `calculate_dcr` (Gower 1971 mixed-type distance): numeric `min(|a - b| / range, 1)`, a zero range gives 0 if equal else 1; categorical 0 if equal else 1; both null 0, one null 1, in every kind; mean over columns; chunked over both frames | the range is the real column's (the model's edge span) for every reference frame, so synthetic-to-real and synthetic-to-holdout distances share one unit; SDMetrics uses each reference frame's own range |
| DCR baseline | real-to-real nearest-neighbour distance (each real row to its nearest other real row), the comparison of DCR distributions used by table-GAN (Park et al., "Data synthesis based on generative adversarial networks", PVLDB 11(10), 2018) and CTAB-GAN (Zhao et al., ACML 2021) | gives an interpretation without a holdout |
| Overfitting share | SDMetrics `DCROverfittingProtection`: share of synthetic rows strictly closer to training than to holdout (`dcr_real < dcr_holdout`), score `min(2 (1 - share), 1)`; training and holdout of equal size | sizes equalized by systematic sampling, not SDMetrics' random `sample` |
| Sampling | systematic sampling (Cochran, *Sampling Techniques*, 3rd ed., 1977, ch. 8): rows `floor(i N / k)` for `i < k` | deterministic without a seed, unlike `compute_dcr`'s `head()` not biased toward the first rows of an ordered table |
| Disclosure floors | the copula's floors (CMS cell size 11; Sweeney 2002 minimum group; copula plan section 4.2), applied to each released statistic | constants imported from `generation.copula`, never restated |
| Report hygiene | "high fidelity does not imply low privacy" (NIST IR 8336 sec. 5.3, as `synth_report.py` already cites) | through the reused disclaimers |

Why custom code is needed: SDMetrics is not an allowed dependency (BSL), the engine has no
pairwise real-versus-synthetic score, and the existing DCR's null rule and memory profile do not
fit (reuse table). Each new piece is a short published definition pinned by an independent oracle.

## 3. Behavior

Public surface (`decoy_engine.quality.copula`; not added to `quality.__all__`, `_LAZY_EXPORTS` or
`decoy_engine.__all__`):

- `compute_copula_quality_report(real, synthetic, model, *, holdout=None, dcr_max_rows=5000, attack_extras=None) -> CopulaQualityReport`
- `CopulaQualityReport`, `PairScore`, `MarginalScore`, `DcrSummary`, `DcrBlock`,
  `HoldoutComparison` (frozen dataclasses); `COPULA_QUALITY_REPORT_SCHEMA_VERSION`.

Example:

```python
from decoy_engine.generation.copula import fit_gaussian_copula, sample_gaussian_copula
from decoy_engine.quality.copula import compute_copula_quality_report

model = fit_gaussian_copula(real, snapshot, seed=fit_key)
synthetic = sample_gaussian_copula(model, len(real), seed=sample_key)
report = compute_copula_quality_report(real, synthetic, model)
report.pairwise_score        # mean of scored pairs, 3 decimals
report.to_dict()["pairs"][0] # {"columns": ["x", "y"], "metric": "spearman_correlation_similarity",
                             #  "status": "scored", "reason": None, "score": 0.991}
```

`to_dict()` has exactly these top-level keys: `schema_version`, `rows` (`real`, `synthetic`,
`holdout` or null), `marginal` (`score`, `columns`: each `column`, `method`, `similarity`,
`gof_method`, `gof_value`), `pairs` (each `columns`, `metric`, `status`, `reason`, `score`),
`pairwise` (`score`, `correlation_score`, `contingency_score`, `scored`, `withheld`,
`undefined`), `dcr` (section 4.5), `synth_report` (the `synth-report/v1` dict from
`assemble_synth_report`). Every float is rounded to `RELEASE_DECIMALS` (3); undefined is `null`.

Pair status and reason tokens (closed sets):

| Status | Reason | When |
|---|---|---|
| `scored` | null | the gate passed and both sides are defined |
| `withheld` | `suppressed_in_model` | the model suppressed a latent variable this score depends on (section 4.3) |
| `withheld` | `pair_rows` | a Spearman pair with fewer than `MIN_PAIR_ROWS` real rows where both are present |
| `withheld` | `distinguished_rows` | a side with fewer than `MIN_DISTINGUISHED_ROWS` real rows outside its largest group, counted on the rows the score uses |
| `undefined` | `empty_column` | either column is all null in the model (`kind == "empty"`) |
| `undefined` | `constant_in_synthetic` | Spearman with a constant synthetic side on its complete rows |
| `undefined` | `too_few_synthetic_rows` | Spearman with fewer than 2 synthetic complete rows |

Failure modes (all raised before any statistic is computed; messages name an argument or column
and the rule, never a value; raised after any `except` closes, so `__cause__` and `__context__`
are `None`):

| Failure | Behavior |
|---|---|
| `real`, `synthetic` or `holdout` not a DataFrame; `model` not a `GaussianCopulaModel` | `TypeError` |
| column names that collide after `str()`, or a frame whose columns are not exactly the model's | `ValueError` |
| `len(real) != model.row_count` (the model describes another table) or `len(real) < MIN_FIT_ROWS` | `ValueError` |
| a real or synthetic column whose dtype disagrees with the model kind (numeric non-bool for `numeric`) | `ValueError` naming the column |
| a non-finite numeric value in any frame | `ValueError` naming the column |
| empty `synthetic` | `ValueError` |
| `holdout` with fewer than `MIN_FIT_ROWS` rows, other columns, or kinds that disagree | `ValueError` |
| `dcr_max_rows` not an `int` (bool refused) or outside `[MIN_FIT_ROWS, 20000]` | `TypeError` / `ValueError` |
| `attack_extras` not `None` or a dotted module name (`fullmatch` of `[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)*`) | `TypeError` / `ValueError` |

An attack extras module that raises is not a failure: the reused contract records
`extras_runtime_error` with the exception type only.

## 4. Design notes

### 4.1 Inputs and canonical form (`_inputs.py`)

- Kinds come from the model (`numeric`, `categorical`, `empty`), never re-inferred, so the report
  and the copula agree on what a column is.
- Canonical frame per input (a copy; inputs are never mutated): numeric columns as `float64` with
  `NaN` for null (`Int64`/`<NA>` included); categorical columns as `object` holding `str(value)`
  (the snapshot's own label rule, `snapshot.py` lines 279 to 289) or `None`.
- Discrete state per column for contingency: numeric value to its bin index in the model's
  `bin_edges` (numpy histogram convention: `[e_k, e_k+1)`, last bin closed; values outside the
  edges, possible only for a frame that is not the model's, clip to the end bins, as SDMetrics'
  `discretize_column` does), null to its own state; categorical label to its index in the model's
  `top_values`, any other label to the single `other` state, null to its own state.
- Systematic sample `rows(N, k) = floor(arange(k) * N / k)` when `N > k`, else all rows.

### 4.2 Pairwise fidelity (`_pairwise.py`)

- Numeric/numeric: Spearman correlation on each frame's rows where both are present: average-tie
  ranks of the subset, then the Pearson correlation of the ranks (the definition `scipy.stats
  .spearmanr` and pandas use). Score `1 - |rho_real - rho_synth| / 2`. Ranks of null-free columns
  are computed once per column; a pair with a null on either side re-ranks its subset.
- Any pair with a categorical column (numeric side discretized, section 4.1): `1 - 0.5 *
  sum |p_real(cell) - p_synth(cell)|` over the union of cells, with cell counts from
  `numpy.unique` on the paired state codes.
- **Why Spearman only.** A pair score released next to a synthetic table the reader holds gives
  `|rho_real - rho_synth|`, i.e. the real coefficient up to sign at 3-decimal resolution. Spearman
  is a function of ranks, so one row moves it by `O(1/n)` however extreme its value, the same
  bounded-leverage argument the copula plan makes for its normal-score release (copula plan section
  10, "Leverage of single values"). Pearson on raw values has no such bound: one outlier can set
  the coefficient. Pearson is therefore not published (open question 1).
- Aggregates: `correlation_score` and `contingency_score` are the means of scored pairs of each
  metric; `score` the mean of all scored pairs (SDMetrics Column Pair Trends). All `None` when
  nothing is scored. Means are taken over the rounded pair scores, then rounded.

### 4.3 The release gate (`_withhold.py`): the one choke point

Every pair goes through `withhold_reason(pair, ctx) -> str | None` before any real-side statistic
of that pair is computed; `_pairwise.score_pairs` is the only caller and the only constructor of
`PairScore`. In order:

1. `empty_column` (status `undefined`, not a privacy rule).
2. **R1, model suppression.** The score's latent dependencies, derived from `model.latent` by
   role: Spearman(a, b) depends on `value(a)` and `value(b)`; contingency(a, b) depends on every
   latent variable of `a` and of `b` (value and null indicator of a numeric column, the state
   variable of a categorical). If any is in `model.suppressed`, the pair is withheld
   `suppressed_in_model`. Without R1, the synthetic correlation of a suppressed variable is about
   0 and the score would equal `1 - |rho_real| / 2`, releasing exactly what the floors withheld.
3. **R2, Spearman rows (on the frame passed in).** Rows where both are present at least
   `MIN_PAIR_ROWS` (else `pair_rows`); each side's distinguished rows (rows outside its largest
   tied-value group) counted on those rows at least `MIN_DISTINGUISHED_ROWS` (else
   `distinguished_rows`). This also covers a constant real side (0 distinguished).
4. **R3, contingency rows.** Each side's distinguished rows on all rows, counted over its discrete
   states (bin, label, `other`, null), at least `MIN_DISTINGUISHED_ROWS` (else
   `distinguished_rows`). Counting bins is stricter than the copula's tied values for a numeric
   column (the largest bin holds at least the largest tied group), matching the coarser statistic.

R2 and R3 are evaluated on `real` itself because nothing ties `real` to the frame the model was
fit on beyond the row count and columns: a frame with one column permuted has the same snapshot
and model-level facts but different pair overlaps. R1 makes the report never say more than the
model about a suppressed variable; R2 and R3 make every released score obey the copula's floors on
the rows it is computed from. The constants are imported from `generation.copula`; the "rows
outside the largest group" count is a two-line function (the copula's own is private; catalog item
6), pinned by the same boundary cells as the copula's (10 and 11 rows).

The withheld status itself says only that a count floor was hit, as the model's `suppressed` list
already does.

### 4.4 Marginals (`_report.py`)

`compute_fidelity(compute_distribution_snapshot(real_canon), compute_distribution_snapshot(
synthetic_canon))["marginal"]`, projected to `column`, `method`, `similarity`, and the nested
goodness-of-fit (`ks_complement` for numeric, `chi_cramers_v` for categorical) as `gof_method`,
`gof_value`, each rounded to 3 decimals; `empty` columns keep `similarity: null` with the
fidelity method token. `marginal.score` is the mean of comparable similarities. The marginals are
of the snapshot class the model already holds; no floor beyond `MIN_FIT_ROWS` is added.

### 4.5 DCR (`_dcr.py`)

- Columns: every model column except `empty` ones (all null on both sides: a constant 0 that would
  only dilute the mean). With no column left the block is `null`.
- Encoding: numeric columns as `float64` (`NaN` null); categorical columns as integer codes over
  the union of both frames' canonical labels, as `float64` with `NaN` for null, compared by
  equality. Range per numeric column: `bin_edges[-1] - bin_edges[0]` from the model (the real
  column's span, already released); synthetic values beyond it clip to distance 1.
- Distance per cell (SDMetrics `calculate_dcr`): numeric `min(|a - b| / range, 1)`, or
  `0 if a == b else 1` when the range is 0; categorical `0 if a == b else 1`; both null 0; exactly
  one null 1. Row distance: the mean over columns. DCR of a row: the minimum over reference rows.
- Samples: synthetic `k_s = min(len(synthetic), dcr_max_rows)` rows, real `k_r = min(len(real),
  dcr_max_rows)` rows, both systematic (section 4.1).
- Outputs, all rounded to 3 decimals:
  - `synthetic_to_real`: `p05`, `p25`, `median`, `p75`, `p95` (numpy `quantile`, linear) and
    `rows`; `exact_match_share`: share of sampled synthetic rows at distance exactly 0.
  - `real_to_real`: the same percentiles for each sampled real row's nearest OTHER sampled real
    row (its own index excluded; true duplicates count as 0, which is the natural duplication the
    synthetic distances are read against).
  - `holdout` (only when given): real and holdout each systematically sampled to
    `k_h = min(len(real), len(holdout), dcr_max_rows)` rows; `closer_to_real_share`: share of
    synthetic rows with `dcr_real < dcr_holdout` (strict, SDMetrics); `protection_score`:
    `min(2 (1 - share), 1)`; `synthetic_to_holdout` percentiles; `rows_compared`.
  - `columns`, `real_rows_sampled`, `synthetic_rows_sampled`.
- Memory: synthetic rows are processed in blocks of 256; per block one `256 x k_r` accumulator and
  a bounded number of same-size temporaries, so peak memory is `O(256 * k_r)`: about 42 MB measured
  at `k_r = 5000` (prototype, tracemalloc, 5 and 20 columns), independent of the column count and
  of `k_s`. Time: `O(k_s * k_r * columns)` per reference frame, about 0.2 s per column at
  5000 x 5000 on the build machine (prototype: 0.98 s for 5 columns, 3.8 s for 20); the report runs
  two (real, baseline) or three (with holdout) such passes. `dcr_max_rows <= 20000` caps one pass at
  16 times that.
- Determinism: no RNG anywhere; fixed column order, fixed block order, float64; the minimum over a
  block is exact, so the result does not depend on the block size (acceptance A4 checks blocks 1,
  7, 256).

### 4.6 Existing checks on copula output (`_report.py`)

- `compute_new_row_synthesis(real_canon, synthetic_canon)` on the canonical frames: an `Int64`
  synthetic integer column and its `float64`-with-`NaN` real column would otherwise hash as `"5"`
  against `"5.0"` and `"<NA>"` against `"nan"`, so a copied row would never match. With the
  canonical form a null and the label `"None"` hash alike; that errs toward reporting a match
  (more risk), never toward hiding one.
- `compute_attack_metrics(real, synthetic, enable_attacks=attack_extras is not None,
  extras_module=attack_extras or <default>, holdout=holdout)`: the caller names the extras module
  instead of passing a flag. When the extras ran, its `results` are kept only if they are a flat
  mapping of keys matching `[a-z][a-z0-9_]{0,63}` to finite numbers, bools or null; otherwise
  `results` is dropped and the block gets `results_status: "withheld_not_value_free"`.
- `assemble_synth_report(new_row_synthesis=..., dcr=None, attacks=...)`, embedded as `synth_report`
  unchanged (its disclaimers: DCR is not a guarantee, no DP claim, high fidelity is not privacy,
  attacks off unless opted in). Its `dcr` is null because the copula report's DCR has different
  null semantics and lives in the report's own `dcr` block.

### 4.7 Frozen, value-free report (`_report.py`)

- Frozen dataclasses with tuple fields; the embedded synth report is deep-frozen (mappings to
  `MappingProxyType`, lists to tuples) and thawed by `to_dict()`, which returns new objects each
  call. `__repr__` shows counts and the three aggregate scores only.
- Value-free: column names, counts, rounded scores and closed tokens. No label, bin edge, quantile,
  per-row distance or row index. The synth report's NRS block carries counts, a fraction and column
  names; the attacks block passes the filter above.

### 4.8 Principles and structure

- Single responsibility: `_inputs` (validation, canonical form, sampling), `_withhold` (the release
  gate), `_pairwise` (two SDMetrics definitions), `_dcr` (one distance and its summaries),
  `_report` (types, assembly, reuse calls). The gate changes for privacy reasons, the metrics for
  method reasons; they are kept apart so a metric change cannot silently skip the gate.
- Deep module: one function and one report type; dependency mapping, canonical form and chunking
  are hidden.
- One place per fact: floors, release precision, kinds and roles come from `generation.copula`;
  marginals and the synth report from their existing modules; the snapshot label rule is `str()`
  in both.
- Dependency direction: `quality.copula` imports only `generation.copula`'s public names (an AST
  guard, A9); `generation.copula._fit` imports `quality.snapshot`. The package-level two-way edge
  is recorded; no module cycle exists (the sub-packages are leaves on each side), and an
  import-layer contract does not exist in the engine yet.
- No registry: two metrics, a closed set; logging none (pure library, as the copula).

## 5. Placement

The engine CODEMAP has no "Where things go" section (map gap, recorded as the copula plan did), so

## 7. Fail-before proofs

- R1: with the gate removed (M1), the score of a suppressed pair equals `1 - |rho_real| / 2` to 3
  decimals, i.e. the withheld correlation is readable from the report. The test asserts the leak
  identity on the ungated helper and the withholding on the real path.
- NRS: raw copula output against the raw real frame finds 0 of 10 planted copied rows in a table
  with a nullable integer column; the canonical path finds 10.
- DCR: the existing `compute_dcr` reports a nonzero median for a synthetic table that copies real
  rows containing numeric nulls; the copula report's DCR gives `exact_match_share` 1.0 and median 0.

## 8. Thresholds

The report has no pass/fail threshold. The fidelity acceptance cells reuse the copula's measured
bounds for the same metric (copula plan section 13 rerun: Spearman similarity at least 0.97 per
numeric pair on the numeric and mixed fixtures; independent baseline below 0.97), on its three
pinned seed sets. The contingency cells reuse the copula's "copula minus baseline at least -0.03 per
pair, mean gap at least 0.015" bounds. If the library score disagrees with the copula's helper
beyond rounding (A1), that is a finding, not a reason to loosen a bound.

## 10. Known limits

- **The scores are new releases about the real data.** A pair score with the synthetic table in
  hand gives the real Spearman coefficient up to sign at 3 decimals; a contingency score is one
  total-variation number over the real joint table (one row moves it by at most `1/n`); DCR and
  baseline percentiles are distances between specific real and synthetic (or two real) rows,
  rounded. They are gated by the same heuristic floors as the model, not by a formal bound, and an
  attacker who knows every other row can still learn about the rest. Recorded in
  `docs/what-we-cannot-prove.md`. DP (V2-4.5) does not cover this report; a DP report is its own
  follow-up.
- **Differencing across pairs** (the copula's first known limit) applies to the scores too.
- **Over-withholding.** A numeric column with 1 to 10 nulls has its null indicator suppressed, so
  every contingency pair with it is withheld even though its Spearman pairs are scored.
- **No Pearson.** SDMetrics' default coefficient is not reported (section 4.2).
- **The DCR null rule differs from `synth-report/v1`'s.** The same data gives a different DCR in
  the two reports when numeric columns hold nulls; the copula report's is SDMetrics'.
- **DCR is a sample statistic.** Above `dcr_max_rows` the percentiles describe a systematic sample;
  a periodic row order aligned with the stride could bias it.
- **The holdout is the caller's.** The report cannot check that holdout rows were not in the fit.
- **Cost.** Pairs are `O(P (n_real + n_synth) log n)` time with `P` pairs (up to 32,640 at the
  copula's 256-variable cap); DCR as section 4.5. A wiring slice may add row sampling for pairs.
- **The report trusts the model for kinds and bins** and checks only row count, columns and dtype
  kinds against `real`; a different frame of the same shape is scored under R2/R3 on its own rows,
  but its marginal-to-model consistency is not checked.
- **Canonical null equals the label `"None"` in NRS**, which can only add matches.
