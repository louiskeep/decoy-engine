## 2. Established solutions

- Least-privilege evaluation context: simpleeval's own API takes an explicit `names` mapping and resolves identifiers only from it (the pattern `expressions/_safe_eval.py:46-95` already follows); Jinja2's sandbox and `ast.literal_eval` follow the same "closed namespace supplied by the caller" rule. The fix moves the closed namespace to `apply_derived`, where the compiled references are already known (`_get_column_refs`, `derived.py:180-197`).
- Positional access is the defect: pandas documents `itertuples(name=None)` as plain tuples with no renaming, and `DataFrame.__getitem__` with a list of names as the exact-name projection; both are used instead of `namedtuple(rename=True)` aliases.
- Value-free exception translation: raising the translated error outside the `except` block so neither `__cause__` nor `__context__` links the value-bearing original (PEP 3134 chaining; `from None` only suppresses display), and an exact-type table of translatable exception classes rather than `type(exc).__name__` (DEFECT-CATALOG class 1, "exact-type tables, never read `__name__`"); F31's closed typed events are the eventual boundary, and this plan's translation is an F31 input.
- Duplicate field names: pyarrow allows duplicate field names in a schema (and `pq.write_table` writes them; `pq.ParquetFile.schema_arrow` reads them back, probed); the repo's registered refusal `duplicate_source_field_names` (`reasons/runtime/_part3.py:195`, declared under `_catalog.runtime("TransformError")` at `:185`; pinned in `tests/fixtures/f29/reason-manifest-v1.json` with `"owner": "TransformError"`) is reused as the one code with its pinned owner. A frozen identity keeps its owner (the F29 manifest is append-only; `docs/compatibility-contract.md` 3.4 treats a reason identity as a consumer contract), so the shared refusal raises `TransformError`, not a new family.
- Duplicate CSV headers: pandas documents that `read_csv` renames duplicate columns to `X`, `X.1`, ... `X.N` (the `mangle_dupe_cols` behavior, always on since pandas 2.0, when the keyword was removed); Arrow's own CSV reader keeps the duplicates. The engine's profile readers and the CLI read CSV through pandas, while the engine's bounded streaming reader reads it through `pyarrow.csv` and keeps duplicates (section 1), so the plan narrows its guarantee to the readers that preserve duplicates, covers the streaming reader through the chunked entries, and measures each reader instead of adding a raw-header pre-parser (owner ruling, round 4). Placement follows the F13 admission pattern already in this repo: one check at the public entry, before any stage that can fail on the same input, with the later stages keeping a cheap re-check (`admit_mask_key` at `_pipeline_context.py:304` ahead of `profile_source` at `:313`; `_oracle_preflight` at `_chunked_oracle.py:113-116` ahead of the first `next()` at `:197`). A guard placed at a later stage is beaten by whichever earlier lookup fails first; three rounds found three such lookups (section 13), so the structure is the earliest point, not the next-earlier one.

## 3. Guarantee (invariants as properties)

- **P1 (visibility).** When an expression is evaluated, the context it can observe contains exactly the column references compiled from its expression (`_get_column_refs`), no more, no fewer, keyed by the real column name.
- **P2 (identity).** Each visible value is read from the live frame column of that exact name; no positional or renamed access exists on the path. On every public entry that takes a table (`run_pipeline`; `run_pipeline_isolated` with `isolate=False` in process and with the default `isolate=True` inside the child, whose failure is reported in `IsolatedRunResult.reason`; `run_mask_pipeline_chunked`; `run_mask_chunked`), every source table whose reader preserves duplicate field names (a caller `pa.Table`, a `LazySource` footer, a `source_loader` table, a declared Parquet descriptor read by pyarrow locally or from S3/GCS, a chunk from any iterator, which includes the engine's `pyarrow.csv` and Parquet streaming readers in `decoy_engine.io`, the platform's copies of them and the CLI's chunked Parquet reader), with or without derived work, is refused with `duplicate_source_field_names` (owner `TransformError`) on its Arrow schema names at the earliest point that entry knows the table, before routing signals, probe routing, profiling, plan compile, FK key building and every pandas conversion, so before any column-name lookup can raise uncoded, before any handler runs and before any output is published. Out of the guarantee, by measurement and not by assertion (T12): CSV read through pandas (the engine's local and cloud CSV profile readers and the CLI loader rename a repeated header, so the engine never sees a duplicate; the rename is silent existing behavior, section 15), and headerless CSV and fixed-width sources (a repeated declared name is refused by config validation before any read). The only refusals that may pre-empt the duplicate refusal are config-only or route-only ones that read no table (the T10 admissibility table names each). A duplicate that first appears in a later chunk is refused by the same function in the innermost wrapper of the chunk iterator, installed at the first-chunk statement, so it runs before every per-chunk wrapper and validator. `run_chunk_ingest_guards` and the handler re-check with the same shared function (defense in depth).
- **P3 (post-mask where declared).** A visible value for a masked sibling is its masked value (unchanged; `order_work` guarantees it) and for an unmasked sibling its source value.
- **P4 (missing is loud, mask execution).** In mask execution a declared reference absent from the frame at run time raises one registered code before any row is evaluated, never a per-row uncoded error. Generation keeps its per-row behavior (section 4, non-goal).
- **P5 (value-free failure).** A per-row evaluation failure, in mask and in generation mode, carries only the column name, the row index and a fixed reason word from a closed table in `str(exc)`, `exc.args`, `__notes__`, `__cause__` and `__context__`; no cell value and no exception `__name__`.
- **P6 (no behavior change for valid names).** For identifier names without a leading underscore and expressions that evaluate, outputs are byte-identical to main.

## 4. Design (smallest structural fix)

- `transforms/derived.py::apply_derived` (`:255-299`) becomes the visibility choke point: it already computes `col_refs`; it now evaluates against `{ref: row_context[ref] for ref in col_refs}` built inside the guarded block and never passes the caller's dict through. A reference missing from `row_context` raises the same translated per-row error with reason `missing_reference` and the reference name (a schema name, an owner result), so generation's per-row behavior keeps its shape. One seam serves both callers (mask handler and `synthesize.py:371-372`).
