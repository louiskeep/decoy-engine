Status: plan (revision 2: folds Codex plan-gate round 1 by patch)

Date: 2026-10-01. Program: `docs/plans/2026-09-30-rust-engine-program.md`, Phase B, item B1 (gap R1 in `docs/records/2026-09-30-rust-coverage-evidence-audit.md`). Branch `feat/dispatcher-production-contract`, off `rust-program/integration` (engine main `8dc559e5` plus the approved A7, A6 and A5a slices; merges are on hold, so Phase B builds on that integration branch).

## Problem

The compiled chunked dispatcher `execution/native/_dispatch.run_native_or_oracle_chunked` masks a 1M-row hash, redact, truncate and passthrough table 5.9x faster at 1 thread and 8.4x faster at 4 threads than the pandas chunked oracle, with byte-identical values (R074, R075). No production code calls it. Its signature lacks what production callers pass to the oracle `execution/_chunked.run_mask_pipeline_chunked` (`registry`, `adapter`, `vault_writer`, `chunk_result_sink`, `base_row_offset`); its oracle branch drops those and `pool_cache`/`native_threads`; its native branch skips `check_chunked_compatibility`, emits no `ExecutionResult` (no timings, warnings or per-column evidence), carries no vault support, yields chunks without the oracle's pandas schema metadata, and in two degenerate shapes yields different column types than the oracle (an all-null string-output column: oracle `null`, native `string`; a zero-row chunk: oracle `float64`, native `string`). Schema drift on a later chunk raises `NativeChunkSchemaDriftError`, a `DecoyError` with no `.message` that callers cannot map. The thread budget is an untyped optional.

B1 makes the dispatcher a complete, public, production-shaped entry point. Wiring callers to it is B2 (engine auto-chunk), B7 (multi-table), B3 (platform Phase 1) and B4 (CLI).

## Guarantee (pinned) and non-goals

Guarantee: `decoy_engine.run_mask_chunked(...)` accepts everything the oracle `run_mask_pipeline_chunked` accepts, plus `native_threads` and an evidence sink, and for the same config and chunks:
1. Values: the concatenated output equals the oracle's concatenated output value for value (nulls and row order included), on whichever route it takes.
2. Schema: for columns masked with hash, redact or truncate (string-output strategies) or passed through (configured passthrough and unconfigured columns kept under the passthrough policy), every yielded chunk of one call has the same type for that column, independent of route and of chunk contents: `string` for the string-output strategies, and exactly the first chunk's source field type for passthrough. No yielded chunk carries pandas schema metadata.
3. Validation: the same config errors are raised, with the same codes, on both routes, before any chunk is yielded (`check_chunked_compatibility` and the oracle's eager checks run first on every call).
4. Side channels: `vault_writer` receives the same source-to-masked pairs on both routes; `chunk_result_sink` receives one `ExecutionResult` per chunk on both routes, with per-column `timings`; `base_row_offset` is validated and advanced identically on both routes.
5. Evidence: per column, the route records `planned_backend` (the per-column capability decision before any whole-table veto) and `executed_backend` (what actually ran) from {`rust_companion`, `rust_pool_select`, `arrow_python`, `pandas_oracle`}, a call count and elapsed time, so a column planned for Rust that ran on pandas (missing or incompatible companion, schema veto, a `when:` veto, a mixed table) is visible. Evidence is JSON-safe (primitive dicts and lists).
6. Threads: `native_threads` is an `int >= 1`, default 1; output bytes do not depend on it.
7. Errors: schema drift on a later chunk raises an `ExecutionError` with code `native_chunk_schema_drift` and a message naming the table, chunk index and detail.

Non-goals: honoring a non-pandas `adapter` on the native route (a call with any adapter other than `None` or the pandas adapter takes the oracle route, reason `adapter_requested`); cross-chunk type stability for columns masked by strategies that only run on the oracle route (categorical, bucket_perturb, group_key, date_shift and the rest keep the oracle's per-chunk types, as today; Phase C pins each one when it becomes native); wiring any caller (B2, B7, B3, B4); widening native admission (categorical, bucket_perturb, group_key, date_shift, FK stay on the oracle route; Phase C and D widen it); incremental output sinks or lazy input (B6); quarantine (the oracle chunked route has none; native emits no row errors); changing the oracle `run_mask_pipeline_chunked`'s own behavior or signature; the 100M and timing benchmarks (Phase E).

## Design

New module `execution/native/_chunked_entry.py` (the dispatcher module is at 535 lines; the size cap is 600), exported as `decoy_engine.run_mask_chunked` and from `decoy_engine.execution`, and added to the compatibility contract's public surface:

```
run_mask_chunked(config, chunks, *, table, engine_version, registry=None, adapter=None,
    vault_writer=None, chunk_result_sink=None, key_provider=None, base_row_offset=0,
    native_threads=1, route_evidence_sink=None, pool_cache=None) -> Iterator[pa.Table]
```

1. **Eager preflight, both routes.** Validate `native_threads` (`int`, not `bool`, `>= 1`; otherwise `ExecutionError(code="invalid_native_threads")`). Extract the oracle's whole eager section of `run_mask_pipeline_chunked` (`_chunked.py` ~412-548: `validate_base_row_offset`, `check_chunked_compatibility`, first-chunk or `empty_input_profile` profiling, compile, key resolution, `assert_vault_writer_keyed`, registry default, code-set corpus pinning, bucket namespace checks, projection and namespace registry, the schema-dependent strategy gates, the FK passthrough and dtype sets, pool warming) into one private `_oracle_preflight(...)` returned as a state object; the public oracle calls it unchanged (same order, same errors, same zero-chunk fail-closed behavior), and `run_mask_chunked` calls the same function before choosing a route, so both routes raise the same errors before any chunk is yielded and a rejected zero-chunk call produces no output, result, evidence or vault entry. Then route choice: `plan_native_route`, extended so that any column with a nonblank `when:` predicate vetoes the whole table to the oracle (reason `when_predicate_not_native:<column>`), and any `adapter` other than `None` or the pandas adapter does too (reason `adapter_requested`).
2. **Oracle route.** Run the oracle's per-chunk loop from the shared preflight state (a private `_oracle_masked(state, ...)` the public oracle also uses), with `registry`, `adapter`, `vault_writer`, `key_provider` and `base_row_offset` as given and an internal result sink. For each chunk: normalize the output with the schema rule (step 5), then build one enriched `ExecutionResult` whose `outputs[table]` is exactly the yielded table and whose `quality_metrics` adds the route evidence, and append that once to the caller's `chunk_result_sink`.
3. **Native route.** The existing `_mask_native` path, extended: `registry` is the one used for Faker pools; `vault_writer` receives `collect_vault_entries(config, {table: source_chunk}, {table: masked_chunk})` per chunk, exactly as the oracle does; per chunk, an `ExecutionResult` with `outputs` (the yielded table), per-column `timings` built from the kernel elapsed time the native path already measures per column (one `StrategyTimingRecord` per column per chunk, `peak_memory_delta_kb=0`; no second timer and no RSS sampling in the hot loop), `warnings=()`, `row_errors=()`, `boundary_conversion_ms=0.0` and the evidence (step 6) in `quality_metrics` is appended to `chunk_result_sink` only when a sink is given; `base_row_offset` is advanced by the chunk's row count (inert for admitted strategies, which are value-keyed, but the domain check runs).
4. **Pool cache.** The shared preflight takes an optional `PoolCache`, so one cache (the given one or a fresh one) serves both routes; the public oracle's signature is unchanged (it passes none, as today). `native_threads` reaches the compiled kernels on the native route.
5. **Schema rule.** Before the first yield, compute the declared type for each hash, redact, truncate and passthrough column (including unconfigured columns kept under the passthrough policy) from the plan and the first chunk's source schema: `string` for the first three; exactly the source field's type for passthrough. On both routes, each yielded chunk's column of those kinds is cast to its declared type when the cast is lossless (null type, zero-row `float64`, and every pandas widening or narrowing of a passthrough column: integer width or signedness, bool, `large_string`, dictionary index width, decimal precision, date, timestamp unit and time zone, duration, binary, list), verified by comparing the cast values with the oracle values; a cast that would lose data raises `ExecutionError(code="chunked_schema_mismatch")`. Columns of other strategies are yielded as the oracle produces them. Schema metadata is dropped from every yielded chunk.
6. **Evidence.** `route_evidence_sink` keeps receiving one `NativeRouteEvidence` (existing behavior). Per-column evidence goes into each chunk's `ExecutionResult.quality_metrics["chunked_route"]` as plain JSON-safe data: `{"table", "native_admitted", "reroute_reason", "columns": [{"column", "strategy", "planned_backend", "executed_backend", "calls", "elapsed_ms"}]}`; `aggregate_chunked_route_evidence(results)` sums calls and time across chunks. `planned_backend` comes from the per-column capability decision before any whole-table veto (hash `rust_companion`, deterministic-REUSE Faker `rust_pool_select`, redact, truncate and passthrough `arrow_python`, anything not natively capable `pandas_oracle`); `executed_backend` is the planned backend on the native route and `pandas_oracle` for every column on the oracle route. `_downgrade_to_oracle` keeps the planned value instead of overwriting it.
7. **Errors.** `NativeChunkSchemaDriftError(ExecutionError, DecoyError)`: dual inheritance, with an explicit constructor that sets `code="native_chunk_schema_drift"`, a `.message` naming table, chunk index and detail, `str()` equal to that message, and the existing `.table`, `.chunk_index` and `.detail` attributes; both `except ExecutionError` and `except DecoyError` catch it.
8. **Physical adapter and sentries.** `physical/drivers/_chunked.NativeOrOracleChunkedAdapter.run` forwards the new parameters unchanged (lossless-forwarding test extended). The seam stays disconnected from production routes; the exact-diff sentry `tests/sentry/test_physical_seam_disconnection.py` gets `_chunked_entry.py`, `_chunk_schema.py`, `_dispatch.py`, `_chunked.py` and any other touched execution module added to its permitted list with a justification, while its import-direction and disconnection assertions stay unchanged.
10. **Release bookkeeping.** The `__all__` snapshot test, a `[Unreleased]` CHANGELOG entry, the README public API summary, CODEMAP ownership for the new module, and the compatibility-contract §3.4 note and preflight checklist.
9. `run_native_or_oracle_chunked` stays as the internal implementation (or a thin wrapper over the new module); its existing tests keep passing.

## Acceptance tests (written first; behavioral tests record red-before)

0. **Conditional masking**: for every admitted strategy, a multi-chunk input with `when:` predicates evaluating true, false and null routes to the oracle (reason `when_predicate_not_native:<column>`) and equals the oracle's output; red-before: the current dispatcher masks every row.

1. **Parameters accepted and forwarded**: every oracle parameter is accepted; on the oracle route each reaches `run_mask_pipeline_chunked` (spy); on the native route `registry` reaches pool resolution and `adapter` is unused (documented).
2. **Values**: across the native kernel set (hash, redact, truncate, passthrough, deterministic-REUSE Faker) and a vetoed strategy (categorical, oracle route), multi-chunk inputs (including uneven last chunk) concatenate to values equal to the oracle's concatenation and to full-frame `run_pipeline`.
3. **Schema**: for hash, redact, truncate and passthrough columns (configured and unconfigured-passthrough), one type for all chunks of a call, equal across routes, with passthrough exactly the source type, for: an all-null string column; a zero-row chunk first, middle and last; all-null and mixed passthrough chunks of int8 through int64, uint64, bool, `large_string`, dictionary (int8 and int32 indices), decimal128 with non-default precision, date32, timestamp with unit and time zone, duration, binary and list columns; no pandas metadata on any yielded chunk; a lossy case raises `chunked_schema_mismatch`. A categorical column on the oracle route keeps the oracle's per-chunk types (pinned characterization).
4. **Validation parity**: each `check_chunked_compatibility` rejection and each eager oracle check raises the same code on a config the native route would otherwise admit, before any chunk is consumed (poisoned chunk iterator after the first); zero-chunk calls with a keyed strategy and no key, an invalid code-set corpus, an invalid namespace, and a mismatched vault writer fail the same way on both entry points with no output, result, evidence or vault entry.
5. **Vault**: with `vault: true` columns on the native route, the vault writer receives the same entries as the oracle route; a vault writer keyed differently from the mask key is rejected on both routes.
6. **Chunk results**: one `ExecutionResult` per chunk on both routes, appended exactly once, with `outputs[table]` equal (schema and metadata included) to the yielded table; native per-column timings have one record per configured column per chunk, `elapsed_ms >= 0`, built from the existing kernel timer (a spy shows no RSS sampling on the native hot path); the aggregate equals the sum; no sink, no result objects built.
7. **Row offset**: an out-of-domain `base_row_offset` raises `chunked_row_offset_out_of_domain` on both routes; the offset advances by each chunk's rows (spy on the domain check).
8. **Evidence**: native-route columns report the documented planned and executed backends with call counts equal to the chunk count; missing companion, incompatible companion, schema veto, `when:` veto, adapter veto and a mixed table (one natively capable and one vetoed column) each report the natively capable columns as planned `rust_companion`/`arrow_python`/`rust_pool_select` and executed `pandas_oracle`, with the reroute reason; evidence passes `json.dumps(..., allow_nan=False)` and round-trips, for single results and the aggregate.
8b. **Pool cache**: a given `PoolCache` is reused across both routes and across two calls (spy shows one pool build).
8c. **Adapter**: a polars or other non-pandas adapter forces the oracle route (`adapter_requested`) and is used by it.
9. **Threads**: `native_threads` 0, -1, `True` and `"2"` raise `invalid_native_threads`; 1 and 4 give byte-identical output.
10. **Drift error**: a later chunk with a changed type or a missing column raises an error caught by an actual `except ExecutionError` clause and, separately, by `except DecoyError`, with code `native_chunk_schema_drift`, `.message` and `str()` naming the chunk index, and the old attributes.
11. **Public surface and bookkeeping**: `from decoy_engine import run_mask_chunked` works; it is in `__all__` (snapshot test), `decoy_engine.execution.__all__`, the compatibility contract §3.4, the CHANGELOG, the README API summary and CODEMAP; `tests/sentry/test_physical_seam_disconnection.py` passes with the updated permitted list.
12. **Oracle unchanged**: `run_mask_pipeline_chunked`'s existing tests pass unchanged; `test_phase2_gate.py` and the native parity suites pass, with the two degenerate allowlist entries now unnecessary for the new entry point (a new gate test asserts exact type equality through `run_mask_chunked`).

Tests needing the compiled companion carry `@_NEEDS_COMPANION` and run in the companion venv locally and the native-companion CI job.
