# Chunked dispatcher production contract (Rust engine program B1)

Status: plan (revision 7: revision 5 pinned Arrow-type admission, shared ingest guards and one drift contract after the first code gate; revision 6 settled a leading all-null chunk and the guard order; revision 7 removes guard suppression by casting only where it is safe, and makes Faker pool identity include the effective provider binding, after the final gate)

Date: 2026-10-01. Program: `docs/plans/2026-09-30-rust-engine-program.md`, Phase B, item B1 (gap R1 in `docs/records/2026-09-30-rust-coverage-evidence-audit.md`). Branch `feat/dispatcher-production-contract`, off `rust-program/integration` (engine main `8dc559e5` plus the approved A7, A6 and A5a slices; merges are on hold, so Phase B builds on that integration branch).

## Problem

The compiled chunked dispatcher `execution/native/_dispatch.run_native_or_oracle_chunked` was measured masking a 1M-row hash, redact, truncate and passthrough table 5.9x faster at 1 thread and 8.4x faster at 4 threads (benchmark runs R074, R075) than the pandas chunked oracle, with byte-identical values (R074, R075). No production code calls it. Its signature lacks what production callers pass to the oracle `execution/_chunked.run_mask_pipeline_chunked` (`registry`, `adapter`, `vault_writer`, `chunk_result_sink`, `base_row_offset`); its oracle branch drops those and `pool_cache`/`native_threads`; its native branch skips `check_chunked_compatibility`, emits no `ExecutionResult` (no timings, warnings or per-column evidence), carries no vault support, yields chunks without the oracle's pandas schema metadata, and in two degenerate shapes yields different column types than the oracle (an all-null string-output column: oracle `null`, native `string`; a zero-row chunk: oracle `float64`, native `string`). Schema drift on a later chunk raises `NativeChunkSchemaDriftError`, a `DecoyError` with no `.message` that callers cannot map. The thread budget is an untyped optional.

B1 makes the dispatcher a complete, public, production-shaped entry point. Wiring callers to it is B2 (engine auto-chunk), B7 (multi-table), B3 (platform Phase 1) and B4 (CLI).

## Guarantee (pinned) and non-goals

Guarantee (for calls that complete; a call whose output cannot be made schema-stable without losing data raises `chunked_schema_mismatch` instead): `decoy_engine.run_mask_chunked(...)` accepts everything the oracle `run_mask_pipeline_chunked` accepts, plus `native_threads` and an evidence sink, and for the same config and chunks:
1. Values: the concatenated output equals the oracle's concatenated output value for value (nulls and row order included), on whichever route it takes, with one stated exception: a passthrough column is the source column itself (design item 5), so where the oracle's pandas round trip rounds a nullable integer above 2^53, this entry returns the exact source value. Admission is decided from the first chunk's real Arrow types and each provider's output type, and every per-chunk ingest guard the oracle's adapter runs (for example `reject_null_bearing_int`) runs on both routes, so an input the oracle masks or refuses is masked or refused the same way. A source column whose Arrow type changes after the first chunk raises `native_chunk_schema_drift` on both routes, except that a later all-null (`null`-typed) chunk is cast to the first chunk's type. The per-chunk ingest guards run on the chunk as the source produced it, before that cast, so the cast never creates a refusal the oracle would not make (an all-null chunk of an int column passes `reject_null_bearing_int` on both routes, as it does on the oracle). A first chunk whose column is `null`-typed while a later chunk of that column is typed raises `ExecutionError(code="chunked_leading_null_type")` on both routes, naming table, column and the later type, with a message saying the source must supply a fixed schema: the stream's type is fixed by its first chunk, and a writer opened on a `null` field cannot accept the later type, so masking it would only move the failure to the writer. This narrows the oracle, which masks such input into a schema-unstable stream. Sources that produce one schema for the whole stream (resident tables sliced into chunks, the Parquet reader, pyarrow's streaming CSV reader) never hit it; a reader that infers types per page does, and must declare its schema.
2. Schema: every yielded chunk of one call has the same type, independent of route and of chunk contents, for (a) hash, truncate, and redact with a string (or default) `redact_with`, on columns without a `when:` predicate: `string`; and (b) passthrough columns (configured passthrough and unconfigured columns kept under the passthrough policy): exactly the first chunk's source field type. Columns with a `when:` predicate and redact with a non-string `redact_with` keep the oracle's per-chunk types (they always run on the oracle route, and their unmasked or numeric values must not be converted). No yielded chunk carries pandas schema metadata.
3. Validation: the same config errors are raised, with the same codes, on both routes, before any chunk is yielded (`check_chunked_compatibility` and the oracle's eager checks run first on every call).
4. Side channels: `vault_writer` receives the same source-to-masked pairs on both routes; `chunk_result_sink` receives one `ExecutionResult` per chunk on both routes, with per-column `timings`; `base_row_offset` is validated and advanced identically on both routes.
5. Evidence: per column, the route records `planned_backend` (the per-column capability decision before any whole-table veto) and `executed_backend` (what actually ran) from {`rust_companion`, `rust_pool_select`, `arrow_python`, `pandas_oracle`}, a call count and elapsed time, so a column planned for Rust that ran on pandas (missing or incompatible companion, schema veto, a `when:` veto, a mixed table) is visible. Evidence is JSON-safe (primitive dicts and lists).
6. Threads: `native_threads` is an `int` in `1..=1024` (the compiled kernels' ceiling, `threads.rs` `MAX_NATIVE_THREADS`), default 1; output bytes do not depend on it.
7. Errors: schema drift on a later chunk raises an `ExecutionError` with code `native_chunk_schema_drift` and a message naming the table, chunk index and detail.

Non-goals: honoring a non-pandas `adapter` on the native route (a call with any adapter other than `None` or the pandas adapter takes the oracle route, reason `adapter_requested`); cross-chunk type stability for columns masked by strategies that only run on the oracle route (categorical, bucket_perturb, group_key, date_shift and the rest keep the oracle's per-chunk types, as today; Phase C pins each one when it becomes native); wiring any caller (B2, B7, B3, B4); widening native admission (categorical, bucket_perturb, group_key, date_shift, FK stay on the oracle route; Phase C and D widen it); incremental output sinks or lazy input (B6); quarantine (the oracle chunked route has none; native emits no row errors); changing the oracle `run_mask_pipeline_chunked`'s own behavior or signature; the 100M and timing benchmarks (Phase E).

## Design

Revision 7 design rules (they override any earlier design item they conflict with):
- **No guard suppression.** Drift validation and casting are separate steps. On both routes every chunk is first checked against the reference schema (type change raises `native_chunk_schema_drift`; leading null-typed then typed raises `chunked_leading_null_type`). The oracle route then gives the adapter the chunk exactly as the source produced it, so whatever adapter runs (stock, subclass, or a custom adapter that delegates to the stock one) runs the ingest guards once on the same chunk the public oracle would see, and no private signal or keyword is passed to any adapter. A later null-typed passthrough column is brought to the reference type by the schema rule on the masked output, after the adapter. The native route runs `run_chunk_ingest_guards` on the raw chunk and only then casts null-typed columns for its own kernels. The private `ingest_guards_run` keyword, `_accepts_ingest_guards_run`, and any suppression path are removed.
- **Pool identity includes the provider binding.** A Faker pool's cache identity includes a token for the provider adapter the effective registry resolves (its class module and qualified name, plus the identity of the adapter object for an in-process cache; if a cache can outlive the process, a binding that cannot be named stably is not cached across processes). This lives in `PoolBuilder.identity_for`, which both routes already share, so a `PoolCache` reused with a rebound provider never returns the old binding's pool on either route. Admission then inspects the pool actually used.

New module `execution/native/_chunked_entry.py` (the dispatcher module is at 535 lines; the size cap is 600), exported as `decoy_engine.run_mask_chunked` and from `decoy_engine.execution`, and added to the compatibility contract's public surface:

```
run_mask_chunked(config, chunks, *, table, engine_version, registry=None, adapter=None,
    vault_writer=None, chunk_result_sink=None, key_provider=None, base_row_offset=0,
    native_threads=1, route_evidence_sink=None, pool_cache=None) -> Iterator[pa.Table]
```

1. **Eager preflight, both routes.** Validate `native_threads` (`int`, not `bool`, `1..=1024`; otherwise `ExecutionError(code="invalid_native_threads")`). Extract the oracle's eager section of `run_mask_pipeline_chunked` into one private `_oracle_preflight(...)` returning a state object, preserving its exact order and its empty-input boundary: checks for every call including zero chunks (`validate_base_row_offset`, `check_chunked_compatibility`, the first-chunk pull, first-chunk or `empty_input_profile` profiling, compile, key resolution, `assert_vault_writer_keyed`, registry default, code-set corpus pinning, bucket namespace checks; then the zero-chunk return), checks for non-empty calls only (projection and namespace registry, the group_key dtype guard, the text_mask, code_set and bucket_perturb schema gates, the FK passthrough and dtype sets, adapter default, pool warming), and per-chunk checks that stay in the loop. The public oracle calls it unchanged (same order, same errors, same zero-chunk behavior), and `run_mask_chunked` calls the same function before choosing a route, so both routes raise the same errors before any chunk is yielded and a rejected zero-chunk call produces no output, result, evidence or vault entry. Then route choice: `plan_native_route`, extended so that any column with a nonblank `when:` predicate vetoes the whole table to the oracle (reason `when_predicate_not_native:<column>`), and any `adapter` other than `None` or the pandas adapter does too (reason `adapter_requested`).
2. **Oracle route.** Run the oracle's per-chunk loop from the shared preflight state (a private `_oracle_masked(state, ..., on_chunk=None)` the public oracle also uses with `on_chunk=None`), with `registry`, `adapter`, `vault_writer`, `key_provider` and `base_row_offset` as given. Per chunk the order is fixed: run the adapter and build the internal `ExecutionResult`; if it has row errors, append that result unnormalized to the caller's sink (as the public oracle does today) and raise `RowErrorsFailedError`, with no normalization attempted; otherwise call `on_chunk(result)` (the public oracle instead appends to its own sink here, as today); fail closed on row errors (`RowErrorsFailedError`, as today, so a failing chunk is reported to the sink before the raise on both entry points); advance the row offset; add vault entries; yield. In `run_mask_chunked`, `on_chunk` normalizes the output with the schema rule (step 5), builds one enriched `ExecutionResult` (same timings, `boundary_conversion_ms`, warnings, code-set metrics and row errors; `outputs[table]` is the normalized table; `quality_metrics` adds the route evidence), appends it once to the caller's `chunk_result_sink`, and the loop yields that normalized table.
3. **Native route.** The existing `_mask_native` path, extended (per chunk: mask, build the result, append it to the sink, add vault entries, yield): `registry` is the one used for Faker pools; `vault_writer` receives `collect_vault_entries(config, {table: source_chunk}, {table: masked_chunk})` per chunk, exactly as the oracle does; per chunk, an `ExecutionResult` with `outputs` (the yielded table), per-column `timings` built from the kernel elapsed time the native path already measures around each column (`_chunk_masking.py` ~171-227 is extended to return that sample per column as well as adding it to the per-strategy aggregate; one `StrategyTimingRecord` per column per chunk, `peak_memory_delta_kb=0`; no second timer and no RSS sampling in the hot loop), `warnings=()`, `row_errors=()`, `boundary_conversion_ms=0.0` and the evidence (step 6) in `quality_metrics` is appended to `chunk_result_sink` only when a sink is given; `base_row_offset` is advanced by the chunk's row count (inert for admitted strategies, which are value-keyed, but the domain check runs).
4. **Pool cache.** The shared preflight takes an optional `PoolCache`, so one cache (the given one or a fresh one) serves both routes; the public oracle's signature is unchanged (it passes none, as today). `native_threads` reaches the compiled kernels on the native route.
5. **Schema rule.** Passthrough columns (guarantee 2b) are taken directly from the chunk's source Arrow table on both routes: a passthrough column is unchanged by definition, so the yielded column is the source column itself, which avoids the pandas round trip that rounds nullable integers above 2^53 (no cast and no comparison is involved). For guarantee 2a columns, before the first yield compute the declared type `string`. On both routes, each yielded chunk's 2a column whose type differs is converted with `pyarrow.compute.cast(column, declared_type, safe=True)`; a raised `ArrowInvalid` or `ArrowNotImplementedError` maps to `ExecutionError(code="chunked_schema_mismatch")` naming table, column, chunk index and both types. Arrow's safe cast refuses overflow, truncation and precision loss for the 2a cast (null type and zero-row `float64` to `string`). Columns of other strategies are yielded as the oracle produces them. Schema metadata is dropped from every yielded chunk.
6. **Evidence.** `route_evidence_sink` keeps receiving one `NativeRouteEvidence` with its existing meaning unchanged (`NodeRouteRecord.route` is the route that ran; `_downgrade_to_oracle` still retags it `oracle`); a valid zero-chunk call still reports `native_admitted=False`, `reroute_reason="empty_input"`. Planned-versus-executed backends live only in the new evidence below. Per-column evidence goes into each chunk's `ExecutionResult.quality_metrics["chunked_route"]` as plain JSON-safe data: `{"table", "native_admitted", "reroute_reason", "columns": [{"column", "strategy", "planned_backend", "executed_backend", "calls", "elapsed_ms"}]}`; `aggregate_chunked_route_evidence(results)` sums calls and time across chunks. `planned_backend` comes from the per-column capability decision before any whole-table veto (hash `rust_companion`, deterministic-REUSE Faker `rust_pool_select`, redact, truncate and passthrough `arrow_python`, anything not natively capable `pandas_oracle`); `executed_backend` is the planned backend on the native route and `pandas_oracle` for every column on the oracle route. Per-column planning runs before any table-wide veto is stamped, and its result is kept separately from `NodeRouteRecord`. The evidence lists configured plan columns; unconfigured columns kept under the passthrough policy are not listed (they keep the existing uncovered-column veto to the oracle, which enforces `unconfigured_column_policy` and returns its warning). JSON safety applies to the `quality_metrics["chunked_route"]` payload and its aggregate; the legacy `NativeRouteEvidence` dataclass is unchanged.
7. **Errors.** `NativeChunkSchemaDriftError(ExecutionError, DecoyError)`: dual inheritance, with an explicit constructor that sets `code="native_chunk_schema_drift"`, a `.message` naming table, chunk index and detail, an explicit `__str__` returning that message (so `str()` has no `[code]` prefix), and the existing `.table`, `.chunk_index` and `.detail` attributes; both `except ExecutionError` and `except DecoyError` catch it.
8. **Physical adapter and sentries.** `physical/drivers/_chunked.NativeOrOracleChunkedAdapter.run` forwards the new parameters unchanged (lossless-forwarding test extended). The seam stays disconnected from production routes; the exact-diff sentry `tests/sentry/test_physical_seam_disconnection.py` gets `_chunked_entry.py`, `_chunk_schema.py`, `_dispatch.py`, `_chunked.py` and any other touched execution module added to its permitted list with a justification, while its import-direction and disconnection assertions stay unchanged.
9. `run_native_or_oracle_chunked` stays as the internal implementation (or a thin wrapper over the new module); its existing tests keep passing.
10. **Release bookkeeping.** The `__all__` snapshot test, a `[Unreleased]` CHANGELOG entry, the README public API summary, CODEMAP ownership for the new module, and the compatibility-contract §3.4 note and preflight checklist.

## Acceptance tests (written first; behavioral tests record red-before)

0. **Conditional masking**: for every admitted strategy on string columns, and for passthrough and type-compatible strategies on numeric columns, a multi-chunk input with `when:` predicates evaluating true, false and null routes to the oracle (reason `when_predicate_not_native:<column>`) and equals the oracle's output values and types (false and null rows keep their original values); red-before: the current dispatcher masks every row. A string-output strategy (hash, redact, truncate) with `when:` on a numeric column raises the oracle's existing error on both entry points (characterization; the oracle cannot put a string into an integer column, tracked as roadmap item §WHEN-NUMERIC).

1. **Parameters accepted and forwarded**: every oracle parameter is accepted; on the oracle route each reaches the shared `_oracle_preflight` / `_oracle_masked` state (spy); on the native route `registry` reaches pool resolution; the existing public-oracle characterization tests pass unchanged.
2. **Values**: across the native kernel set (hash, redact, truncate, passthrough, deterministic-REUSE Faker) and a vetoed strategy (categorical, oracle route), multi-chunk inputs (including uneven last chunk) concatenate to values equal to the oracle's concatenation and to full-frame `run_pipeline`.
3. **Schema**: for hash, redact, truncate and passthrough columns (configured and unconfigured-passthrough), one type for all chunks of a call, equal across routes, with passthrough exactly the source type, for: an all-null string column; a zero-row chunk first, middle and last; all-null and mixed passthrough chunks of int8 through int64, uint64, bool, `large_string`, dictionary (int8 and int32 indices), decimal128 with non-default precision, date32, timestamp with unit and time zone, duration, binary and list columns; no pandas metadata on any yielded chunk; a nullable `uint64`/`int64` passthrough column holding values above 2^53 (and the type maximum) with nulls comes back exactly equal to the source on both routes; a non-string `redact_with` (e.g. `0`) keeps the oracle's value and type. A categorical column on the oracle route keeps the oracle's per-chunk types (pinned characterization).
4. **Validation parity**: each `check_chunked_compatibility` rejection and each eager oracle check raises the same code on a config the native route would otherwise admit, before any chunk beyond the first is consumed (poisoned chunk iterator after the first) and before any chunk is yielded; zero-chunk calls with a keyed strategy and no key, an invalid code-set corpus, an invalid namespace, and a mismatched vault writer fail the same way on both entry points with no output, result, evidence or vault entry.
5. **Vault**: with `vault: true` columns on the native route, the vault writer receives the same entries as the oracle route; a vault writer keyed differently from the mask key is rejected on both routes.
6. **Chunk results**: one `ExecutionResult` per chunk on both routes, appended exactly once, before the yield; a chunk with row errors is appended unnormalized and then raises `RowErrorsFailedError` on both entry points, including when the same chunk also has a column the schema rule could not convert; enriched results keep the oracle's timings, `boundary_conversion_ms`, warnings, code-set metrics and row errors; with `outputs[table]` equal (schema and metadata included) to the yielded table; native per-column timings have one record per configured column per chunk, including two columns sharing a strategy (each with its own elapsed time), `elapsed_ms >= 0`, built from the existing kernel timer (a spy shows no RSS sampling on the native hot path); the aggregate equals the sum; no sink, no result objects built.
7. **Row offset**: an out-of-domain `base_row_offset` raises `chunked_row_offset_out_of_domain` on both routes; the offset advances by each chunk's rows (spy on the domain check).
8a. **Legacy evidence unchanged**: `NativeRouteEvidence` and `NodeRouteRecord.route` keep their current values on every route, including `empty_input` for a valid zero-chunk call.
8. **Evidence**: native-route columns report the documented planned and executed backends with call counts equal to the chunk count; missing companion, incompatible companion, schema veto, `when:` veto, adapter veto and a mixed table (one natively capable and one vetoed column) each report the natively capable columns as planned `rust_companion`/`arrow_python`/`rust_pool_select` and executed `pandas_oracle`, with the reroute reason; evidence passes `json.dumps(..., allow_nan=False)` and round-trips, for single results and the aggregate.
8b. **Pool cache**: a given `PoolCache` is reused across both routes and across two calls (spy shows one pool build).
8c. **Adapter**: a polars or other non-pandas adapter forces the oracle route (`adapter_requested`) and is used by it.
9. **Threads**: `native_threads` 0, -1, `True` and `"2"` raise `invalid_native_threads`; 1 and 4 give byte-identical output.
10. **Drift error**: a later chunk with a changed type or a missing column raises an error caught by an actual `except ExecutionError` clause and, separately, by `except DecoyError`, with code `native_chunk_schema_drift`, `.message` and `str()` naming the chunk index, and the old attributes.
11. **Public surface and bookkeeping**: `from decoy_engine import run_mask_chunked` works; it is in `__all__` (snapshot test), `decoy_engine.execution.__all__`, the compatibility contract §3.4, the CHANGELOG, the README API summary and CODEMAP; `tests/sentry/test_physical_seam_disconnection.py` passes with the updated permitted list.
12. **Oracle unchanged**: `run_mask_pipeline_chunked`'s existing tests pass unchanged; `test_phase2_gate.py` and the native parity suites pass, with the two degenerate allowlist entries now unnecessary for the new entry point (a new gate test asserts exact type equality through `run_mask_chunked`).

13. **Leading null and guard order**: on `run_mask_chunked` (both routes; the public oracle `run_mask_pipeline_chunked` stays unchanged under test 12), for passthrough and hash columns, a `null`-typed first chunk followed by a `string` chunk raises `chunked_leading_null_type` before the second chunk is yielded, with no sink append or vault entry for it; a `null`-typed column in every chunk is yielded as `null`; an int64 hash or truncate column whose later chunk is `null`-typed is masked (not refused) and equals the oracle's values. The parity matrix also records which route each cell took and asserts `native_admitted` for the cells that must run natively (string hash, truncate, redact, and first-name Faker over string).
14. **Delegating adapter and rebound cache**: (a) truncate over an int64 first chunk and a later `pa.nulls` chunk, with a custom adapter whose `run(*args, **kwargs)` delegates to `PandasExecutionAdapter.run`, succeeds and equals the public oracle; (b) a `PoolCache` first populated with the default `person_first_name` and then reused with `person_first_name` rebound to a date-returning poolable adapter gives the same values and route as a fresh cache, on `run_mask_chunked` and on the public oracle; (c) no adapter receives an `ingest_guards_run` keyword (a custom adapter whose `run` accepts no `**kwargs` works on the oracle route).

Known issue (rev8): legacy `run_native_or_oracle_chunked` now accepts a later null-typed chunk (it refused one before this slice), and with `enforce_schema_rule=False` its native route yields the cast type while its oracle route yields null; callers are tests only.

Tests needing the compiled companion carry `@_NEEDS_COMPANION` and run in the companion venv locally and the native-companion CI job.
