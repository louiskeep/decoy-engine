## 1. Guarantee

`decoy run pipeline.yaml --sample N` runs the whole pipeline (gate, subset, mask, generate,
post-scan) on a linked sample and writes every output table and the quarantine file into one
private scratch folder. It never writes, creates, truncates or renames a declared target, the
declared quarantine path, the vault, the run folder `out/<name>/`, `LATEST` or `current`. FK
links hold inside the sample because the rows are chosen by the same subset closure a `subset:`
run uses (SUB-RUN), never by cutting a linked table at N rows. The same command picks the same
rows on delimited, CSV, fixed-width and Parquet sources.

Non-goals: a statistically representative draw; resume; a run record before LIB L3b; the
chunked route; isolated runs (`run_pipeline_isolated`); s3 or gcs sources (refused as `run`
refuses them).

## 2. Answers to Q1 to Q7

- Q1 (what N means): N is the number of head rows per seed table, 1 to 1000 (owner Q9). The seeds
  are the first N rows in file order. With no `subset:` block and no `--sample-root`, every
  child-free table is seeded and every retained edge is upward-only. A table is child-free when
  it is the child of every retained edge it takes part in, or has no retained edge. A pure cycle
  seeds its first table in config order. Linked parent tables get only the rows those child rows
  need. Upward closure can still keep more than N rows in one table through a self-reference or
  an upward cycle. The kept-row ceiling bounds the result. With `--sample-root T`, T uses
  both-way traversal in its component. That explicit choice can keep far more than N rows,
  bounded only by the kept-row ceiling. Generate tables are scaled so the largest gets N, except
  Q-S4 refuses a generated parent of a masked child.
- Q2 (switch point and mechanism): one mechanism, the SUB-RUN keyword
  `run_pipeline(..., subset_request=SubsetRequest)`. SAMPLE builds that request with
  `subset.sample_request(...)`, which puts a `SampleSpec` on it. Nothing else selects rows.
- Q3 (scratch): `.decoy/scratch/sample-<invocation_id>/` from LIB L1d
  `library.scratch("sample", invocation_id, ttl=timedelta(hours=24))` (PR #214), placed
  by P4 as merged on CLI main's `RunLayout.out_dir(scratch)` and gated by `layout_issues(...,
  OutputPlacement.fixed(scratch))`. Engine staging lives under `SubsetStageScope` and is removed
  when it exits. The user sees per-table counts, the scratch path, the approximate columns and,
  on a TTY only, source rows beside output rows. The no-target sentry is AT-C6.
- Q4 (format parity): a sample reads its sources exactly as `decoy run` does (4.4, D6). Head rows
  and seed rows are row indices in file order, so every format picks the same rows (AT-11).
- Q5 (interactions): section 4.6.
- Q6 (memory bound per format): section 4.7.
- Q7 (halves and release): row 63 ships engine SE1 and SE2 on train R-d, then CLI SC0, SC1, SC2
  and SC3. SE3a and SE3b belong to RUN-STREAM and are not needed to close row 63.

- `SAMPLE_ROWS_MIN = 1`, `SAMPLE_ROWS_MAX = 1000`, `SAMPLE_KEPT_CEILING = 1_000_000`.
- `SampleSpec` (frozen): `rows: int`, `roots: tuple[str, ...]`, `display_rows: int = 0`. Its

- `sample_request(config, *, rows, root=None, use_config_subset=True, display_rows=0) ->
  SubsetRequest`:
  1. `rows` and `display_rows` first require `type(value) is int`. Booleans, floats, numeric
     strings and `None` are refused with `runtime.invalid_execution_knob`, before any comparison.
     Values outside `SAMPLE_ROWS_MIN..SAMPLE_ROWS_MAX`, `display_rows` outside 0 to 20, or `root`
     with a `subset:` block and `use_config_subset` use the same code. An unknown or generate
     `root`: `subset.subset_unknown_table`.
  2. Edges: inspect the retained declarations before the generate-edge drop. A generated parent
     with a masked child is returned by `sample_refusal_edge(config)`, the one public structural
     check used by `refuse_sample` and this builder. Otherwise
     `relationships, excluded = mask_relationships(config)` (below), the same helper
     `subset_request_from_config` calls.
  3. Seeds. With a `subset:` block and `use_config_subset`: the config seeds from
     `subset_request_from_config`, each given `cap=rows`. Otherwise, with `root`: one
     `SeedSpec(table=root, mode="head", count=rows)`.
  4. Default head seeds: take the linked components of the mask tables over `relationships` as
     an undirected graph (the reach rule `scope_for` uses). With no `subset:` block and no root,
     add `SeedSpec(mode="head", count=rows)` for every child-free table in config order. A table
     is child-free when it is the child of every retained edge it takes part in, or has no edge.
     A component with no child-free table is a cycle and gets its first table in config order.
     Set every retained edge in these components to `"upward"`. `resolve_edge_directions` allows
     `"upward"` without `allow_dangling` because parent completeness is preserved.
  5. With `root`, seed T and set every retained edge in T's component to `"both"`. This can pull
     in far more rows than N and stops only at the kept-row ceiling. Other unseeded components
     get the child-free seeds and upward directions from step 4. With a `subset:` block, keep its
     configured seed components and directions; unseeded components get the step 4 defaults.
  6. An edgeless head seed is represented on the request but `scope_for` puts it in `head`, so
     the stage can read N rows without a count pass or a call to `select_subset`.

### 4.7 Memory bound per format
