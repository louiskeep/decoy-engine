## 1. Guarantee

`decoy run pipeline.yaml --sample N` runs the whole pipeline (gate, subset, mask, generate,
post-scan) on a linked sample and writes every output table into one private scratch folder.
It never writes, creates, truncates or renames a declared target, the vault, the run folder
`out/<name>/`, `LATEST` or `current`. FK links hold inside the sample because the rows are
chosen by the same subset closure a `subset:` run uses (SUB-RUN), never by cutting each table at
N rows. The same command picks the same rows on delimited, CSV, fixed-width and Parquet sources.

Non-goals: a statistically representative draw; resume; a run record before LIB L3b; the
chunked route; s3 or gcs sources (refused as `run` refuses them).

## 2. Answers to Q1 to Q7

- Q1 (what N means): N is the number of seed rows per root table, 1 to 1000 (owner Q9). The seeds
  are the first N rows in file order. Linked tables get the rows the closure needs, so their
  count is not N. Unlinked mask tables get their first N rows. Generate tables are scaled so the
  largest gets N, the rule `--rows` uses (`cli/gen/_preview.py:38`).
- Q2 (switch point and mechanism): one mechanism, the SUB-RUN keyword
  `run_pipeline(..., subset_request=SubsetRequest)`. SAMPLE builds that request with
  `subset.sample_request(...)`, which puts a `SampleSpec` on it. Nothing else selects rows.
- Q3 (scratch): `.decoy/scratch/sample-<invocation_id>/` from LIB L1d `allocate(...)` with a 24h
  TTL, placed by `RunLayout.fixed(scratch)`. Engine staging lives under `SubsetStageScope` and is
  removed when it exits. The user sees per-table counts, the scratch path, the approximate
  columns and, on a TTY only, source rows beside output rows. The no-target sentry is AT-C6.
- Q4 (format parity): the CLI passes lazy sources for Parquet, CSV and delimited, and a
  `FixedWidthLazySource` (SE3) for fixed-width. Head rows and seed rows are row indices in file
  order, so every format picks the same rows (AT-11).
- Q5 (interactions): section 4.6.
- Q6 (memory bound per format): section 4.7.
- Q7 (halves and release): engine SE1, SE2, SE3 on train R-d; CLI SC1, SC2 after the repin.

## 4. Behavior

### 4.1 Engine request (SE1)

New `subset/_sample.py` (about 150 lines):

- `SampleSpec` (frozen): `rows: int` (1 to 1000), `roots: tuple[str, ...]`,
  `display_rows: int = 5`.
- `sample_request(config, *, rows, root=None, use_config_subset=True) -> SubsetRequest`.
  - With a `subset:` block and `use_config_subset`: the config request
    (`subset_request_from_config`) with every seed given `cap=rows`, so the sample is a subset of
    the full subset run.
  - Otherwise roots are `(root,)` when given, else each mask table with no parent edge among
    mask tables, in config order. A component that is only a cycle takes its first table in
    config order. Each root gets `SeedSpec(mode="head", count=rows)`.
  - Edges with an endpoint that is not a mask table are dropped from the request, so SUB-RUN F5
    does not refuse a generate parent.
  - Budget: the config budget when set, and a ceiling of 1,000,000 kept rows in total.
  - `rows` outside 1 to 1000, or `root` with a `subset:` block and `use_config_subset`:
    `runtime.invalid_execution_knob`. An unknown or generate `root`: `subset.subset_unknown_table`.
- `SubsetRequest` gains `sample: SampleSpec | None = None` (SUB-RUN E1 type, additive).
- `subset/_seed.py`: mode `"head"` selects indices `0..min(count, n) - 1` with no key read; `cap`
  keeps the first `cap` selected indices by row index, after any mode. `SeedSpec` gains
  `cap: int | None = None`. Neither reaches YAML: `SeedModeLiteral` and the config schema are
  unchanged, so the config hash is unchanged.
- `scope_for` (SUB-RUN 4.1): with `request.sample` set, unlinked tables go to a new
  `SubsetScope.head` set instead of `whole`.

Keyed bottom-k (the existing `sample` mode) was rejected for the root: it needs a full key pass,
and the owner asked for "the first N".

### 4.2 Engine stage (SE2)

In SUB-RUN's `SubsetStageScope.apply` (`execution/pipeline/_subset_stage.py`):

- Head tables: resident `table.slice(0, N)`; a lazy input reads batches until N rows and stops,
  with no `source_facts` count pass, and writes them through SUB-RUN's `_write_staged` as one
  staged Parquet file. A lazy input stays lazy, so the stream route still accepts it.
- Seeded and linked tables: SUB-RUN's path, unchanged.
- `quality_metrics["subset"]["sample"] = {"rows", "roots", "head_tables": {name: kept_rows},
  "approximate_columns": [...]}`. Head tables are not in `tables`, so `source_rows` never needs a
  CSV count.
- `ExecutionResult.sample_source_rows: dict[str, pa.Table] | None = field(default=None,
  repr=False)`: the first `display_rows` kept source rows per table, for the TTY view only.
- `approximate_columns(config) -> list[tuple[str, str]]` (new `execution/pipeline/_sample.py`):
  the SUB-RUN 4.4 not-covered list (shuffle, non-deterministic faker and categorical,
  `windowed_date`, `grouped_series`, `derived_aggregate`, MATCH and SCALE cardinality, UNIQUE
  pools) plus every column of a generate table. One frozenset, `SUBSET_APPROXIMATE`; a test
  checks it is disjoint from `CHUNK_SAFE_STRATEGIES`.
- `RunResult.sample: SampleMarker | None = None` (rows, roots, head table counts, scratch as a
  `RelPath`). Delivery outcome `not_applicable`; table state `"none"`.

### 4.3 Fixed-width lazy source (SE3)

New `profile/_lazy_fixed_width.py` (about 160 lines): `FixedWidthLazySource(LazySource)` reads
through `read_fixed_width_handle` in batches; `num_rows` uses the file-size count of
`FixedWidthFileSource`; `iter_batches` stops when the caller stops. Blank lines are skipped as
in the resident reader, so row indices match (AT-11). Taken as the technical choice; the owner
may overturn it, which leaves fixed-width resident with a named memory limit.

### 4.4 CLI command (SC1, SC2)

- Options: `--sample N` (`click.IntRange(1, 1000)`, exit 2 outside) and `--sample-root TABLE`.
- Refused with `--sample` (exit 2, fixed text): `--rows`, `--chunked`, `--chunk-size`, `--vault`,
  `--evidence-out`, `--notify`, `--duckdb-source`, and `--sample-root` with a `subset:` block
  unless `--no-subset` is also given.
- `prepare_sample`: the run gate on `gen.scale_row_counts(ctx.raw, N)`, then
  `sample_targets(config_dict)`. Every output table maps to a relative `<table>.<ext>` in its
  declared file format, else Parquet; database and cloud targets become Parquet; quarantine maps
  to `quarantine.parquet`. The declared targets are never placed.
- Scratch: `library.allocate(owner="sample", invocation_id, ttl=24h)` (L1d), then
  `RunLayout.fixed(scratch)`. `open_run_layout` is not called, so no claim, no `out/<name>/`, no
  `LATEST` and no `current`.
- Sources: lazy through `cli/io/_lazy.py` (RUN-STREAM C1a's interface); fixed-width through SE3.
- `execute_sample`: `run_pipeline(..., subset_request=sample_request(...), vault_writer=None)`,
  then writes through DELIV's sink, fixed-folder kind A rooted at scratch (every file directly in
  it). If DELIV C2a has not merged, `write_targets(sample_config, outputs, layout)`; both stay
  inside G-ONE-TARGET-WRITE and G-ONE-OUTPUT-PLACE with no allowlist change.
- Output: one line per table (kept rows, head or linked), the scratch path, the approximate
  columns marked "approximate in a sample", and on a TTY only the source rows beside the output
  rows (UX map). `--json` carries a `sample` object.

### 4.5 Cleanup

Engine staging is removed at `SubsetStageScope` exit on every path. Sample scratch is kept 24h.
On a failed sample the CLI deletes the scratch folder (`delete_tree`) before it exits. LIB L3b
adds the `sample-run/v1` record, replace-on-next-sample and TTL reaping. Until L3b,
`decoy library clean` (L4b #219) is the only reaper of old samples: a named limit.

### 4.6 Interactions

| With | Behavior |
|---|---|
| `subset:` block | config seeds capped at N; budget kept; the sample is a subset of the full subset |
| `--no-subset` | `use_config_subset=False`: head roots, the block ignored |
| generate tables | scaled by `scale_row_counts`; edges to them dropped; their columns approximate |
| post-scan | the same verdict as a run on the sample rows; on a block, owner Q-S1 |
| vault | never written; `--vault` refused; tokens computed as with no vault |
| records and RESULT | no run folder; `RunResult.sample` marker; L3b adds the record |
| exit codes | as `run`: 0, 1, 3, 5; 4 and 6 once DELIV ships |
| `--rows` | refused together; kept separate in V1 (owner Q-S2) |
| chunked route | refused (SUB-RUN 4.6) |

### 4.7 Memory bound per format

| Table role | Parquet | CSV and delimited | Fixed-width | Archive CSV |
|---|---|---|---|---|
| head (root or unlinked) | row groups covering N | first N records, no count | first N records | resident |
| seeded from `subset:` | key column chunks | full parse, key columns kept | full parse, keys kept | resident |
| linked by the closure | key column chunks | full parse, key columns kept | full parse, keys kept | resident |
| kept rows staged | one batch at a time | one batch at a time | one batch at a time | resident |

Profiling and the gate stay bounded at 10,000 rows (`profile/_source.py:54`). Kept rows in total
stay under the 1,000,000 ceiling, so outputs are bounded by it.

## 5. Established solutions

Search run: Jailer, condenser, Tonic and Synthesized subsetting docs; DuckDB and Polars `head`
and `LIMIT`; the codebase (`subset/`, `cli/gen/_preview.py`, LIB 4.13).

- Linked samples by closure from root rows: Jailer and condenser walk FKs out from seed rows of a
  root table. SUB-RUN already does this (`subset/_closure.py`); SAMPLE adds no closure code.
- "First N rows" as seeds is what `head` and `LIMIT` give; DuckDB and Polars stop reading after N,
  which is why head tables skip the count pass.
- Scratch output with a TTL: LIB 4.13's layout on `protected_scratch_dir`.

The only custom code is the request builder, the head and cap modes, and the CLI target rewrite.

## 8. Enumerations

### Exit paths

- Success: outputs in scratch; staging removed at `SubsetStageScope` exit; exit 0.
- Engine error (S3 to S8): staging removed (`execution/_chunked_input.py:248` for S7); scratch
  deleted by the CLI; exit by the engine outcome (`run/_errors.py:140`).
- Write error (S11): partial scratch deleted; exit 3.
- Post-scan block (S12): nothing written under option (a); exit 4.
- Interrupt: the `finally` at `run/_flow.py:78` deletes scratch on the sample branch.

### Routes

- In-memory, auto-chunk, out-of-core and stream: through SUB-RUN's stage (its route table 4.6).
- Native kernels: run config and staged inputs, as in SUB-RUN.
- Chunked (`--chunked`, `execution/_chunked.py`): refused (S9).
- `--rows` generate preview (`run/_execute.py:286`): a separate path, refused together.

### FK shapes

- Single and composite keys, self references and cycles: SUB-RUN closure (`subset/_closure.py:1`).
- Edge to a generate table: dropped from the sample request; the generate side is approximate.
- Root from `--sample-root`: tables not reachable from it are head tables.

### Fields

- `SampleSpec`: `rows`, `roots`, `display_rows`; `SeedSpec.cap` (`subset/_types.py:44`).
- `quality_metrics["subset"]["sample"]`: `rows`, `roots`, `head_tables`, `approximate_columns`.
- `RunResult.sample` (`run_result/_model.py:362`): `rows`, `roots`, `head_tables`, `scratch`.
- `ExecutionResult.sample_source_rows` (`execution/_adapter.py:40`).

### Output surfaces

- Scratch files in the 0700 folder from L1d; the `--json` `sample` object; the human summary.
- TTY source rows: shown only when stdout is a TTY, never written or logged.
- Refusal texts and `ReasonRecord`s; logs carry counts only.
