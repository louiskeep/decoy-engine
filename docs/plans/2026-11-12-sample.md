## 1. Guarantee

`decoy run pipeline.yaml --sample N` runs the whole pipeline (gate, subset, mask, generate,
post-scan) on a linked sample and writes every output table and the quarantine file into one
private scratch folder. It never writes, creates, truncates or renames a declared target, the
declared quarantine path, the vault, the run folder `out/<name>/`, `LATEST` or `current`. FK
links hold inside the sample because the rows are chosen by the same subset closure a `subset:`
run uses (SUB-RUN), never by cutting a linked table at N rows. The same command picks the same
rows on delimited, CSV, fixed-width and Parquet sources.

Non-goals: a statistically representative draw; resume; a run record before LIB L3b; the
chunked route; isolated runs (`run_pipeline_isolated`); s3 or gcs sources (refused as `run`
refuses them).

## 2. Answers to Q1 to Q7

- Q1 (what N means): N is the number of seed rows per root table, 1 to 1000 (owner Q9). The seeds
  are the first N rows in file order. Linked tables get the rows the closure needs, so their
  count is not N. Tables with no retained edge get their first N rows. Generate tables are
  scaled so the largest gets N, the rule `--rows` uses (`cli/gen/_preview.py:38`).
- Q2 (switch point and mechanism): one mechanism, the SUB-RUN keyword
  `run_pipeline(..., subset_request=SubsetRequest)`. SAMPLE builds that request with
  `subset.sample_request(...)`, which puts a `SampleSpec` on it. Nothing else selects rows.
- Q3 (scratch): `.decoy/scratch/sample-<invocation_id>/` from LIB L1d `allocate(library,
  "sample", invocation_id, ttl=timedelta(hours=24))` (PR #214 `cli/library/_scratch.py`), placed
  by P4's `RunLayout.out_dir(scratch)` and gated by `layout_issues(...,
  OutputPlacement.fixed(scratch))`. Engine staging lives under `SubsetStageScope` and is removed
  when it exits. The user sees per-table counts, the scratch path, the approximate columns and,
  on a TTY only, source rows beside output rows. The no-target sentry is AT-C6.
- Q4 (format parity): a sample reads its sources exactly as `decoy run` does (4.4, D6). Head rows
  and seed rows are row indices in file order, so every format picks the same rows (AT-11).
- Q5 (interactions): section 4.6.
- Q6 (memory bound per format): section 4.7.
- Q7 (halves and release): engine SE1, SE2, SE3a, SE3b on train R-d; CLI SC0, SC1, SC2, SC3.

- `sample_request(config, *, rows, root=None, use_config_subset=True, display_rows=0) ->

  6. Budget: `max_total_rows = min(config budget, SAMPLE_KEPT_CEILING)`;
     `max_table_seed_multiple` and the other policy fields as the config gives them.

### 4.2 Engine stage (SE2)

In SUB-RUN's `SubsetStageScope.apply` (`execution/pipeline/_subset_stage.py`), when
`request.sample` is set:

1. `scope = scope_for(request, caller_sources)` first.
2. Head tables (`scope.head`): resident `table.slice(0, N)`; a lazy input reads
   `src.iter_batches(N)` once, takes the first batch and closes the iterator. No `source_facts`,
   no `num_rows`, no `_count_pass`. The kept rows go through SUB-RUN's `stage_lazy_batches` (4.5)
   as one staged Parquet file and re-wrap as a `LazySource`, so the stream route accepts it.
3. `select_subset(request, {name: caller_sources[name] for name in scope.tables}, job_seed=...)`.
   Only in-scope tables reach `select_subset`, so no head table is counted or key-loaded.
4. Seeded and linked tables: SUB-RUN's path, unchanged, with its exact key check during
   materialize.
5. `quality_metrics["subset"]["sample"] = {"rows", "roots", "head_tables": {name: kept_rows},
   "approximate_columns": [...]}`. Head tables are not in `tables`, so `source_rows` never needs
   a CSV count.
6. When `request.sample.display_rows > 0`: `ExecutionResult.sample_source_rows` holds the first
   `display_rows` kept source rows per table. Otherwise it stays `None` (D3).

### 4.7 Memory bound per format

Sources are what `decoy run` builds (4.4). Before RUN-STREAM C1a every format is resident in a
sample as in a run. After C1a, Parquet and plain CSV are lazy; fixed-width stays resident until
RUN-STREAM's switch takes `FixedWidthLazySource` (section 18); archive CSV stays resident.

| Table role | Parquet (lazy) | CSV and delimited (lazy) | Fixed-width (after the switch) | Resident |
|---|---|---|---|---|
| head (no retained edge) | row groups covering N | first N records, no count | first N records, no count | `slice(0, N)` |
| head root of a linked component | its edge key columns, full | full parse, edge key columns kept, one count pass | full parse, keys kept, one count pass | key columns of the table |
| seeded from `subset:` | key column chunks | full parse, key columns kept | full parse, keys kept | key columns |
| linked by the closure | key column chunks | full parse, key columns kept | full parse, keys kept | key columns |
| kept rows staged | one batch at a time | one batch at a time | one batch at a time | `take` |

A head root reads its full key column because the closure joins on it (`subset/_keys.py:27-59`).
Profiling and the gate stay bounded at 10,000 rows (`profile/_source.py:54`). Kept rows in total
stay under the 1,000,000 ceiling, so outputs are bounded by it.

## 8. Enumerations

### Exit paths

- Success: outputs in scratch; staging removed at `SubsetStageScope` exit; exit 0.
- Usage refusal (S1, S2, S9, S13, S16): before any engine call or read; exit 1; scratch deleted
  if made.
- Engine error (S3 to S8, S14, S15): staging removed (`execution/_chunked_input.py:248` for S7);
  sink aborted; scratch deleted by the CLI; exit by the engine outcome (`run/_errors.py:140`).
- Write error (S11): sink aborted; partial scratch deleted; exit 3.
- Post-scan block (S12): nothing written under option (a); exit 4 after DELIV C5.
- Interrupt: the `finally` at `run/_flow.py:78` aborts the sink and deletes scratch on the
  sample branch.

### Routes

- In-memory, auto-chunk, out-of-core and stream: through SUB-RUN's stage (its route table 4.6).
- Native kernels: run config and staged inputs, as in SUB-RUN.
- Chunked (`--chunked`, `execution/_chunked.py`): refused (S9).
- Isolated (`run_pipeline_isolated`): refused by SUB-RUN F17; never called by the CLI.
- `--rows` generate preview (`run/_execute.py:286`): a separate path, refused together.

### FK shapes

- Single and composite keys, self references and cycles: SUB-RUN closure (`subset/_closure.py:1`).
- A component with no parent-free table (a cycle plus a child): its first table in config order
  is the head root (AT-4c).
- Several components: each gets its own roots (AT-4a, AT-4b).
- Edge to a generate table: dropped by `mask_relationships`, listed in `excluded_edges`; the
  generate side is approximate.
- A mask table whose only edges go to generate tables: edgeless after the drop, so a head table.

### Fields

- `SampleSpec`: `rows`, `roots`, `display_rows`; `SeedSpec.cap` (`subset/_types.py:44`).
- `SubsetScope.head` (E1 `subset/_scope.py`).
- `quality_metrics["subset"]["sample"]`: `rows`, `roots`, `head_tables`, `approximate_columns`.
- `RunResult.sample` (`run_result/_model.py:362`): `rows`, `roots`, `head_tables`, `scratch`.
- `ExecutionResult.sample_source_rows` (`execution/_adapter.py:40`).

### Output surfaces

- Scratch files and `quarantine.jsonl` in the 0700 folder from L1d; the `--json` `sample` object;
  the human summary.
- TTY source rows: requested only when stdout is a TTY, never written, logged or put in `--json`.
- Refusal texts and `ReasonRecord`s; logs carry counts only.
