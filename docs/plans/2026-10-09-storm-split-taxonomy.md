# STORM split: rename the prototype `storm` package into detection / profiling / verification

Program: refactor track (`decoy-platform/docs/ROADMAP.md`), scheduled **before Phase D**. Owner decision (Cam, 2026-10-09): retire `storm` as an internal name and split it by concern into descriptive packages; `storm` stays only as a product/marketing label on user-facing + wire surfaces. **Risk: R2** (architectural + public-compatibility refactor spanning THREE repos — engine, decoy-platform, and the `decoy` CLI), wide but mechanical, no behavior change, pre-GA hard rename (no shims). Independent review + exact-artifact evidence required.

## 1. Goal and scope

Move `src/decoy_engine/storm/` into three concern-scoped packages, rename the public symbols, and migrate all three consumers in lockstep. **Names and module locations move; behavior, output, config keys, schema strings, and telemetry event names do NOT.**

**In scope:**
- **`detection/`**: `detectors.py`, `_patterns.py`, `_validators.py`, `ner.py`, `domains.py`, `name_hints/`, detection types (`Span`, `DetectorMatch`, `CustomDetectorSpec`, `DetectionSignal`).
- **`profiling/`**: `profiler.py`, `_classification.py`, `_distributions.py`, `sentinels.py`, `recommendations.py`, `model_pack/`, `features/`, `eval/`, profile types (`StormProfile`->`ColumnProfile`, `FieldStats`, `Distribution`, `TopValue`, `SentinelFlag`).
- **`verification/`**: `postmask/` (`run_storm_post_mask`->`run_post_mask`, `StormPostMaskReport`->`PostMaskReport`; keep the `SCHEMA_VERSION` string value).
- **Engine-internal storm-named symbols OUTSIDE the storm package (survey §E.3):** `walks/cross_file.py`, `profile/_pii.py`, and `profile/_walk.py` consume storm types and carry "storm"-named internal symbols. Retarget their imports to the new type paths. RENAME the engine function `storm_profiles_to_snapshot` → `profiles_to_snapshot` (`walks/cross_file.py:85`; public in `walks.__all__`, imported by platform `helpers.py` via `run_cross_file_walk`, so it is a consumer-transition item) and the internal `_run_storm_inner` → `_profile_columns_inner` (`profiler.py:525`). **`storm_run_group_id` is NOT renamed (finding 2, rev 4): KEEP** — the only engine occurrence is a docstring (`walks/cross_file.py:7`); the real identifier is a persisted platform column (`api/storm/models.py:30,200`) and API response field (`api/storm/schemas.py:147` et al.), a wire field under 3b. Update the engine docstring's vocabulary without touching the field name.
- Public re-exports in `decoy_engine/__init__.py`: `run_storm`->`profile_columns`, `StormProfile`->`ColumnProfile`; `DetectorMatch`/`FieldStats`/`SentinelFlag` keep their names, new import path.
- Cross-repo migration of ALL THREE consumers (section 3d): engine, decoy-platform, and the `decoy` CLI.

**Out of scope (KEEP `storm`, per the keep-vs-rename table 3b):** the `run_storm` config field (engine `PipelineConfig`, platform `Pipeline`/`PipelineCreate`, web, CLI `_native_gate`), the `"storm-post-mask/v1"` schema string VALUE, the `"storm.scan"` telemetry event + the platform `queue_worker` mode and UI, the `storm.read_samples` permission, platform `/storm/...` routes + `web/src/storm/...`, and the CLI's own `storm` product surface (`storm_app`, `ui/storm_animation.py`). Also out of scope: wiring the lgbm classifier into a live path (separate feature); any behavior/output/algorithm change.
