# D3b: token vault on the bounded out-of-core route

## 0. Why + scope

A relationship-bearing (FK) pure-mask job that requests a token vault (`vault_writer`) is disqualified from the bounded routes (`_pipeline_routing.py` `_sequential_eligible` -> `(False, "vault_writer_requested")`), so it runs full-frame if the byte estimate fits and is rejected (`fk_full_frame_oom_risk_rejected`) when too big. This slice lets such a job run on the out-of-core (OOC) route, collecting the vault in bounded memory, with vault side effects matching the full-frame oracle except the accepted native-vs-Python NFC divergence the masked output already carries (Option A, Cam 2026-10-15; no OTHER divergence).

Scope: the **out-of-core route only**, for jobs whose vaulted columns all use a **reviewed-safe strategy** (allowlist: `hash`, `categorical` with string categories, `truncate`, `redact` with a string token, `passthrough` of a string) on a **string/binary column (parent keys allowed; only incoming-FK child keys excluded) with a string masked output** (details in §2). Hash/categorical qualify; their vault inherits the accepted NFC envelope (Option A). Any OTHER vaulted strategy (`bucket_perturb`, `text_redact`, `text_mask`, `code_set`, `fpe`), a numeric/float/temporal/decimal column, a non-string masked output (e.g. a numeric redact replacement or numeric categorical categories), or an incoming-FK child-key column keeps the job on full-frame. SEQ has no vault collector, so a SEQ-eligible-but-not-OOC-compatible vault job stays full-frame (SEQ-native vault is a follow-on). Validators (D3a), `fidelity_report`, `post_validation` stay disqualified (unchanged). No change to the vault format, DE-02, orphan handling, or any masked output.

## 1. What exists to build on

- **Vault collector:** `vault.py` -- `collect_vault_entries(config, sources, outputs)` (`:171`) pairs `source[i]` with `masked[i]` positionally per vaulted column, SKIPS rows where either side is `None`, returns `(namespace, str(masked), str(source))` triples. It stringifies with `str()` and skips only `None` (NOT float NaN). `VaultWriter.add(entries)` dedups; it DROPS ambiguous keys (same masked -> different source) and tracks `ambiguous_dropped`. `iter_vault_columns(config)` enumerates `(table, column, namespace)` for `vault: true` columns. `write()` Fernet-encrypts in bounded chunks and is **caller-owned** (see §4).
- **Config check:** `plan/_checks.py:519` `check_vault_columns` -- `fpe` with `vault: true` is REJECTED (`vault_strategy_reversible`). So fpe is never a vaulted strategy (it is a negative compile test, not a runtime case).
- **Chunked precedent:** `_chunked_oracle.py:393` -- per chunk, `vault_writer.add(collect_vault_entries(config, {table: chunk}, {table: masked}))`, source batch + masked batch in the same order.
- **OOC runner -- TWO drivers (plan-gate HIGH-2):** `out_of_core/_runner.py run_fk_out_of_core:112` dispatches a table to EITHER `_runner._stream_table:303` (in-memory reassembly) OR `_stream_driver.stream_table` (`:254`, sink/reorder path, selected at RUNTIME by parent-key cardinality + budget). BOTH must collect the vault. Both mask per batch (element-wise, source order preserved) before any join reorder/staging; the reorder driver checks total orphans AFTER its mask/staging pass. `skip_columns = union of incoming edges' child_columns` are present with RAW values at the mask step and remapped at the join (`_batch_join.py`) -- they are NOT the masked value there.
- **DE-02 keyed-vault guard:** `_pipeline_context.py:309` `assert_vault_writer_keyed`, runs in context construction BEFORE routing (so it already applies to an OOC-routed job). Confirmed by the plan gate.
- **Routing:** `_pipeline_routing.py` `_sequential_eligible:172-228` (disqualifier `:224`); `decide_execution_route:275`; a fitting vault job currently returns at the full-frame-fit branch BEFORE the bounded block, so admitting OOC vault needs a new branch there (not just the final OOC branch). `fk_ooc_dtype_hazard`, cycles, compat still apply.
- **Parity:** `tests/parity/test_out_of_core_fk_parity.py` (D0 baseline) + `tests/parity/SEMANTIC_DIFFERENCES.md` -- D0 is NOT strict byte-identity with full-frame; it RECORDS OOC diffs (NaN-vs-null, int64-vs-float64, metadata). **The build MUST read SEMANTIC_DIFFERENCES.md.** These documented diffs are exactly why numeric/float vaulted columns are declined (§2).

## 2. Byte-identity: why string/binary-only, and the declines (plan-gate HIGH-1)

The vault stores `(namespace, str(masked), str(source))` as a deduped set. `collect_vault_entries` uses `str()` and skips only `None`. The documented OOC-vs-full-frame divergences therefore LEAK into the vault strings:
- **int64-vs-float64:** a nullable-int column is float-widened on full-frame (`to_pandas_fk_safe`) but stays int64 on OOC, so `str(source)`/`str(masked)` differ (`"7.0"` vs `"7"`). Verified counterexample: numeric redact replacement `7` with a null elsewhere -> full-frame `("payload","7.0","secret")` vs OOC `("payload","7","secret")`.
- **NaN-vs-null:** a float NaN is skipped-as-null on one route but stringified `"nan"` on the other -> an extra `("ns","nan","nan")` triple. Verified counterexample: a passthrough parent key column containing NaN.

Both survive dedup. **Admission rule (explicit strategy ALLOWLIST + avoidable-divergence declines):** admit a job only when every vaulted column satisfies ALL of: (a) its strategy is in the REVIEWED-SAFE allowlist; (b) its SOURCE dtype is string/binary (`utf8`/`large_utf8`/`binary`/`large_binary`) -- not numeric/float/temporal/decimal (which float-widen or NaN-diverge); (c) its masked OUTPUT is a string (plan-gate rev2 HIGH-1: a string source with a NUMERIC redact replacement `redact_with: 7` still gives `"7.0"` vs `"7"`, so the resolved replacement/token must be a string); (d) it is not an incoming-FK child-key (skip) column.

The **reviewed-safe vaulted strategy allowlist is EXACTLY:** `hash`, `categorical` (ONLY when its resolved categories are strings -- categories can be numeric, so check the RESOLVED output type, not just the source dtype; plan-gate rev3), `truncate`, `redact` (string `token`/replacement only), `passthrough` (string source). **Every OTHER OOC-compatible strategy is DECLINED to full-frame when vaulted** (plan-gate rev3 NEW-MED): `bucket_perturb` (native-vs-Python NFC divergence on Unicode `date_format`, `tests/parity/test_phase_d_d1b1_bucket_native.py:370`), `text_redact`, `text_mask`, `code_set` (not reviewed for route-stable vault parity), and `fpe` (already config-rejected). The explicit allowlist bounds the reviewed surface: a strategy not on it cannot reach the OOC vault. The admission check: strategy in the allowlist; source dtype string/binary; resolved masked output/replacement (incl. categorical resolved categories) is a string; and `(table,column)` is not an INCOMING-FK child-key component of any edge (composite/overlap/multi-parent/self-ref; parent-key columns ARE allowed -- vaulting the parent key to recover IDs is the common case).

**OPTION A (Cam 2026-10-15) -- the one ACCEPTED divergence:** `hash` and `categorical` carry the documented native-vs-Python NFC/Unicode divergence (`tests/parity/test_phase_d_d1a_hash_native.py:202`, `..._d1b2_categorical_native.py:250`) for post-runtime-Unicode text. This is the SAME divergence the masked OUTPUT already carries (Cam-approved for masking) and is data-dependent (cannot be declined at config). Cam chose Option A: ADMIT hash/categorical string vaulted columns; the OOC vault key for such a row equals the OOC run's OWN masked value, so the vault is internally consistent and recovers correctly. The vault differs from a full-frame-built vault ONLY where the masked output itself diverges (the accepted NFC envelope) -- no NEW divergence class, and NOT a new SEMANTIC_DIFFERENCES entry (it is the existing masked-output envelope reflected in the vault side effect).

This keeps D3b byte-identical to the oracle EXCEPT the accepted NFC envelope (hash/categorical), covering the common vault case (reversible recovery of masked string IDs / hashed pseudonyms). Numeric vaulted columns stay out of scope (would need a route-stable numeric representation policy).

## 3. The change

- **New module `out_of_core/_vault_collect.py`:** `collect_batch_vault(config, table, source_batch, masked_batch, vault_writer)` -> `vault_writer.add(collect_vault_entries(config, {table: source_batch}, {table: masked_batch}))`, collecting the admitted (string, non-skip) vaulted columns present in the masked batch. Thin; mirrors `_chunked_oracle.py:393`.
- **Hook BOTH drivers (HIGH-2):** call `collect_batch_vault` at the mask step in `_runner._stream_table` AND `_stream_driver.stream_table`, after `mask_batch` and after that driver's existing fail-closed checks, when `vault_writer is not None`. Thread `vault_writer` + `config` through `run_fk_out_of_core` and `_pipeline_route_dispatch`/`_pipeline_route_exec` to both drivers. One shared helper, two call sites.
- **Routing admission:** add a `vault_ooc_safe` signal = `vault_writer is not None` AND every vaulted column's strategy is in the reviewed-safe allowlist (`hash`/`categorical`-string-cats/`truncate`/`redact`-string/`passthrough`-string) AND is string/binary-typed AND has a string masked output AND is not an incoming-FK child key. (hash/categorical qualify -- their NFC divergence is the accepted Option-A envelope, not a decline; bucket_perturb/text_redact/text_mask/code_set are NOT on the allowlist and decline.) In `decide_execution_route`, add an OOC-vault admission branch BEFORE the full-frame-fit return so a `vault_ooc_safe` job that is otherwise OOC-compatible (passes compat, not cyclic, not `fk_ooc_dtype_hazard`, all other disqualifiers clear) AND **FITS the full_frame estimate (`full_frame_fits_estimate is True`)** routes to OUT-OF-CORE with its normal reason. The fit gate is load-bearing (Codex final HIGH): the vault accumulates O(distinct triples) in PYTHON memory, OUTSIDE the OOC spill budget, so a NON-fitting or UNPRICEABLE (`None`) vault job cannot be bounded on OOC -- it is NOT admitted and falls through to the reject (`fk_full_frame_oom_risk_rejected`), exactly as a too-big vault job is today (a spillable-vault follow-on could lift this). D3b thus extends GAP6's faster/lower-memory bounded route to FITTING vault jobs; too-big vault jobs still reject. This branch it must NOT enable SEQ vault (SEQ-only-eligible vault jobs stay full-frame) and must NOT admit a child-key / numeric vault job. Keep the `use_byte_estimate_routing=False` rollback. `_sequential_eligible` stays as-is for its SEQ purpose.
- No change to `mask_batch`, the join, the vault format/`write()`, orphan handling, or masked output.

## 4. Transactional contract (plan-gate MED-3) + parity

- **Persistence is caller-owned.** The engine never calls `VaultWriter.write()`; the CLI caller owns it (`decoy/src/decoy/cli/run.py:685`, post-success; `_pipeline_generate_mask.py:296` is the `add()` site, not `write()`). OOC masking failures RAISE directly (no `row_errors` result object like the chunked route). The build MUST confirm the caller calls `write()` ONLY after the OOC run returns successfully, so a raised run persists NOTHING even though earlier batches already called `vault_writer.add(...)` (the writer object is discarded with the failed run). If the caller's `write()` is not strictly success-gated, that is a BLOCKER to fix (no partial reversible-plaintext persist). Specify the contract explicitly: **a failed run persists no vault.**
- **Vault side effects match full-frame within the accepted NFC envelope** (Option A) for an admitted job: for NFC-agnostic rows the decrypted triple sets + `ambiguous_dropped` are IDENTICAL (dedup drops ambiguous keys, so repeated/colliding sources must match); for hash/categorical on NFC-divergent Unicode the OOC vault key equals the OOC run's OWN masked output and differs from full-frame exactly as the masked output does -- no more. Null-skip identical. DE-02 keyed-vault fail-closed identical (guard is pre-routing).
- **Masked outputs unchanged** from the existing OOC baseline (D0 strict comparator) -- NOT "byte-identical to full-frame" (D0 records OOC diffs). The vault hook must not perturb masking or order.
- **No new SEMANTIC_DIFFERENCES.md entry.** The only divergence is the pre-existing masked-output NFC envelope reflected in the vault (Option A); everything else is byte-identical-or-decline.

## 5. Acceptance matrix

- **T1 admission + declines:** a fitting OOC-compatible pure-mask FK job vaulting only allowlist string columns (parent keys OK; incoming child keys declined) routes `("out_of_core", ...)`; jobs that (a) vault a numeric/float/temporal/decimal column, (b) vault an incoming-FK child-key column, (c) are SEQ-eligible but not OOC-compatible, (d) are too-big, (e) vault a NON-allowlist strategy (`bucket_perturb`, `text_redact`, `text_mask`, `code_set`), (f) vault a `categorical` column with NUMERIC resolved categories -- each stays full-frame/reject with the unchanged reason. `use_byte_estimate_routing=False` rolls back. Mutants: dropping the allowlist check, dropping the string-source/output check, dropping the child-key check, admitting SEQ vault -- each killed.
- **T2 vault parity (Option A envelope):** admitted job on OOC vs full-frame. (a) NFC-AGNOSTIC data: identical decrypted triple sets + `ambiguous_dropped` -- cover a vaulted string parent-key column, string payload (hash/categorical/truncate/redact-token), multiple columns, nulls (skipped), all-null (no entries), repeated + conflicting-source collisions (ambiguous drop). (b) NFC case: a hash/categorical vaulted column on NFC-divergent Unicode text -> the OOC vault key equals the OOC run's OWN masked output (within the accepted envelope) and recovery against the OOC output succeeds; assert NO divergence beyond the masked-output NFC. (c) DECLINES (assert full-frame, not an OOC vault): numeric redact `7`/`7.0` on a string source (non-string masked output), a numeric/float source column, a passthrough NaN parent key, a `bucket_perturb` vaulted column with a Unicode `date_format` (rev3 NEW-MED), a `text_redact`/`text_mask`/`code_set` vaulted column (non-allowlist), and a `categorical` vaulted column with NUMERIC resolved categories -- proving the non-allowlist + avoidable-divergence cases never reach the OOC vault.
- **T3 child-FK-key vault declines:** vaulting an incoming-FK child-key column (incl. composite / overlapping-parent-and-child / multi-parent) stays full-frame; assert route + reason; mutant dropping the all-edge-component check killed.
- **T4 both drivers collect:** force the reorder/sink driver (`_stream_driver.stream_table`, threshold forced) AND the in-memory driver; both produce the byte-identical vault. A mutant hooking only one driver is killed (the other driver's vault would be incomplete). Witness which driver ran.
- **T5 fail-closed persists nothing:** a late masking failure and a reorder-path total-orphan failure each abort the run and persist NO vault; assert via instrumenting `add` + the caller's `write()` (not file-absence alone) -- a mutant that persists after a late failure is killed.
- **T6 masked output unchanged:** admitted job's masked outputs == the existing OOC baseline (D0 strict comparator); the vault hook did not perturb masking.
- **T7 memory (narrowed, accurate):** the collector is called per batch and the writer dedups, so storage is O(DISTINCT triples) -- which can be O(rows), NOT a fixed bound; the RAM-fitting routing restriction is what bounds it. Assert per-batch collection + dedup; no full-table source/output materialization for the vault. No 10M run.
- **T-neg fpe+vault:** remains a config-reject (`vault_strategy_reversible`) -- a negative compile test, not an OOC case.

## 6. Failure modes (reproduce, do not smooth)

- Avoidable (numeric source/output, NaN) vault divergence silently admitted -> T1/T2 declines. A NEW divergence BEYOND the accepted NFC envelope on hash/categorical -> T2(b).
- A vaulted column collected via only one of the two drivers -> T4.
- Child-FK-key vault admitted + mis-collected -> T3.
- Vault persisted on an aborted run (reversible-plaintext leak) -> T5.
- The vault hook perturbing masked output/order -> T6.
- DE-02 keyed-vault guard bypassed on OOC -> assert it still fires.
