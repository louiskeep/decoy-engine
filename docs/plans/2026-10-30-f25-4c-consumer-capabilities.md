## 2. Invariants

- I1. No producer in section 3 creates a scratch directory or a Python-written scratch file except through a `ScratchArena` (`StageDir` protocol, `fileaccess/_types.py:179`).
- I2. Internal producers take `arena: ScratchArena` as a required argument: no default, no `None`, no `getattr` fallback. Public entry points create the arena themselves; an internal caller that already holds one hands it on (`_arena=`, 4.1).
- I3. An arena root is made by L0.1's allocator (in the temp root, or a fresh child of a caller directory, ambient only) under a pending name, checked as 4.2, marked, locked, renamed to its `decoy-arena-v1-` name (4.1), registered in the allocator's live issued-root set, and held by descriptor. The arena module creates no directory and no file except through `_protected_dir` and `_output`'s two creators (4.2).
- I4. `flock(LOCK_SH)` on the root descriptor from before the rename to reclaim; an isolated child inherits it (`pass_fds`).
- I5. Reclaim is descriptor-relative (A-4 `_rmtree_fd`, `_output.py:80`). A failure is reported as `Disposition.RETAINED`, never as success.
- I6. Validation never mutates: descriptor checks raise and change nothing. Reports are frozen dataclasses.

### 4.2 Two creation choke points (the root fix) and the descriptor checks

Modes are set by the creator, never inherited, and the arena never creates anything itself. Two owning modules create, and nothing else in the arena path does:

- Directories by path: L0.1's allocator. The root and each missing `under=` level come from `_protected_dir._create_level` (as `protected_scratch_dir` uses today: `mkdir` 0700, `chmod` 0700, `lstat` check, removed on failure).
- A-4's creators, named. Every raw creation in `_output.py` happens inside one of five named functions, with the shared creation flags defined once at module scope. Each keeps A-4's errno-only failures (`_call`, `:55-63`): a `mkdir`, `open`, `fstat` or needed `fchmod` failure (`ENOSPC`, `EDQUOT`, `EACCES`, `EEXIST`) passes through as `OSError(errno)`, unchanged in class, and nothing that existed before the call is removed. The five raw functions, two private entry points over one core, and one flag definition are:
  - `make_stage_dir_at(parent_fd, name) -> int`: `mkdir(name, 0o700, dir_fd=)`, open `_DIR_FLAGS`; if that open fails `EACCES` (born 0000 under umask 0777), `chmod(name, 0o700, dir_fd=)` and open again; then, if `fstat` shows an owner bit missing (umask `0o200` gives 0500), `fchmod(fd, 0o700)`. No read-back refusal. Used by `_StageDir.create_dir` (`:171`) and the directory stage (`:228`), public and private labels alike, so they behave as today except that owner bits the umask stripped are restored (the only A-4 behaviour change; a filesystem that ignores modes, vfat or CIFS, never reaches the chmod because its owner bits are present).
  - `_create_private_core(dir_fd, name, restore_fn) -> int` owns the one `os.open(name, _FILE_CREATE, 0o600, dir_fd=)`, `fstat`, close and created-name cleanup sequence. Its two module-private entry points name the two contracts and pass one of two single-purpose restorers, `_restore_always` or `_restore_missing_owner_bits`; there is no boolean or mode flag. The restorer owns the only `fchmod`. On a needed `fchmod` failure the core closes the descriptor and unlinks the name this call created, never after an `EEXIST`, which created nothing.
  - `create_private_at(dir_fd, name) -> int` keeps `RootedOutputTxn.create_file`'s existing unconditional private-stage `fchmod` (`:240-253`) and is the arena and marker creator. The arena then performs its own exact-mode refusal below.
  - `create_private_child_at(dir_fd, name) -> int` is used only by `_StageDir.create_file` when its mode is 0600 (`:159-161`, which today has no `fchmod`). It calls `fchmod` only when `(S_IMODE(st_mode) & 0o600) != 0o600`, restoring owner read and write bits stripped by the umask without adding a chmod refusal on a filesystem that already reports them. It has no exact-mode refusal, so A-4 child stages keep today's mode-emulating-filesystem behavior.
  - `create_output_file_at(dir_fd, name, mode) -> int`: today's public `os.open(name, _FILE_CREATE, mode, dir_fd=)`, moved out of `:161` and `:240-246` unchanged (umask-governed output mode, L8).
  - `_open_parent` (`:328`) and `ensure_dir` (`:365`): output parents, unchanged (`0o777` at the umask; group-shared output trees keep working).
  - `_FILE_CREATE` (`:52`) is referenced only inside these functions.
- The arena's refusal lives in the arena, not in A-4. `fileaccess/_scratch.py` calls `make_stage_dir_at` and `create_private_at`, then checks the new descriptor with `fstat` through `_protected_dir._owned_private(st)` plus the exact mode (0700, 0600) and type; on a mismatch it removes the entry it just created (`rmdir` or `unlink` by `dir_fd`) and raises `ProtectedDirUnsafe`. Errno failures from the creators reach the arena unchanged, so a disk-full at arena creation is still a resource errno (G3). `_output.py` imports nothing from `_protected_dir.py`, which keeps `fileaccess/__init__.py` -> `_entry` -> `_local` -> `_output` free of a cycle through `_protected_dir.py:40`. Each arena `create_dir` child and each level `_adopt` makes take this path; `_adopt` walks from the deepest existing ancestor, opened `_DIR_FLAGS` by path under the ambient policy only (it is the transitional `Path` arm).
- One ownership predicate: `_protected_dir._owned_private(st) -> bool` (`st_uid == geteuid()` and no group or other bits), used by L0.1's `_check` (`:159-160`, which reads `os.getuid()` today; the engine never runs set-uid, so the two agree; S1a-0's CHANGELOG line records the switch) and by the arena.

Because `_output.py` is a capability module (`tests/sentry/file_access_modules.toml` `capability_modules`), these sites need no new D9 registry row and no `private-file-sinks.json` growth; G-ONE-PROTECTED-DIR already judges them as descriptor-relative. Not folded, logged in 11: the ambient `_local.py:247-251` `mkstemp` then `fchmod` (path-based, a caller directory) and `declared_casting/_quarantine_local.py:217-239`.

Guard: `tests/sentry/scratch/test_scratch_arena_prefix.py::[create_choke_point]`, built on `tests.sentry.fa.scan` (which resolves aliases), fails on any `os.mkdir`, `os.makedirs`, `mkdtemp`, `Path.mkdir`, `os.chmod`, `os.fchmod` or `O_CREAT` in `fileaccess/_scratch.py` or `fileaccess/_scratch_sweep.py`, and on any `O_CREAT`, `_FILE_CREATE` or `os.mkdir` in `_output.py` outside the five raw functions above (`make_stage_dir_at`, `_create_private_core`, `create_output_file_at`, `_open_parent`, `ensure_dir`) and the one `_FILE_CREATE` definition. The same test asserts that `create_private_at` and `create_private_child_at` are the only callers of `_create_private_core`, with the fixed restorer for each. G-ONE-PROTECTED-DIR (L0.1) already fails a `protected_root` creator outside the allocator. Mutations that must turn it red: an `os.mkdir(name, 0o700, dir_fd=fd)` in `ScratchArena.create_dir`; a bare `os.mkdir` in `RootedOutputTxn.begin`; a second `os.open(..., _FILE_CREATE, ...)` in `_StageDir.create_file`; swapping either private entry point's restorer. A new creation site cannot forget the mode, because it has no way to create except through a named entry point whose behavior the guard fixes.

The checks. At `open`: `fstat` on the root descriptor must show `S_ISDIR`, `st_uid == geteuid()` and `S_IMODE == 0o700`, else `ProtectedDirUnsafe`, nothing changed. After each arena `create_dir`, `_adopt` level, `create_file` and the marker: type, owner and exact mode (0700, 0600) on the new descriptor, before use, in `_scratch.py`. Inside the arena a swap between `mkdir` and `chmod` needs the same UID, the arena being 0700 (L6, as L0.1's own named limit); for an A-4 directory stage in a caller's output directory, a different user who can write there could swap a symlink in before the `EACCES`-only chmod, whose only effect is a 0700 chmod on a path the engine user owns (L6, no read); the `O_NOFOLLOW` open refuses a symlink. A directory the engine did not create (an existing `_adopt` leaf, a swept entry) is checked strictly, never chmodded; a caller's `temp_dir` keeps its mode (Q8), as `protected_scratch_dir(parent=)` leaves an existing parent today.

### 4.4 Sweep (S5)

`fileaccess.sweep_scratch() -> SweepReport`, no parameters. It scans only `tempfile.gettempdir()` at call time, the directory `ScratchArena.open()` uses with no `under=`. For each entry, opened by descriptor:

1. Only names for which `re.fullmatch(r"decoy-arena-v1-[0-9a-f]{16}", name)` holds (not `re.match` with `$`, which accepts a trailing newline) (never `decoy-arena-pending-*`, platform `decoy-job-*`, `decoy-preflight-*`, `decoy-src-fd-*`, engine `decoy-ooc-*`, `decoy-isolated-run-*`); a directory (`O_NOFOLLOW`), owned by `geteuid()`, mode 0700.
2. Ownership proof: `.decoy-arena`, opened by `dir_fd` `O_RDONLY|O_NOFOLLOW`, is a regular file owned by `geteuid()`, mode 0600, with the magic and a token equal to the entry's name token. Any failure in steps 1-2 is `retained_unknown`, never deleted.
3. `flock(LOCK_EX | LOCK_NB)` on the entry; `EWOULDBLOCK` is `retained_live`.
4. Lock held: remove every top-level entry except `.decoy-arena` (`_rmtree_fd` alone goes in `scandir` order, `_output.py:82`), then unlink the marker, then `rmdir` the entry. A kill before that leaves a provable arena; a failure is `failed`. `reclaim()` uses the same helper.

Pattern: `flock(2)` on the open file description, inherited across `fork`/`exec`; an ownership marker checked before any delete (exact target). Pending-then-rename closes the `open` window; the lock-to-`rmdir` window is L6. The same lock is what `systemd-tmpfiles` honours: its age-based cleanup of `/tmp` skips a directory, and everything below it, while a shared or exclusive BSD lock is held on it (`systemd-tmpfiles(8)`), so a live arena also survives the distribution's `/tmp` aging. L0.1's own roots (`protected_scratch_dir`, default prefix `decoy-` plus 16 hex) never match the step 1 pattern.

### 4.5 Windows (win32 arm)

The CLI V1 matrix includes Windows x86_64 subject to WIN-FEAS (roadmap 5.5, which supersedes F22's Linux-and-macOS-only note). The descriptor design (`dir_fd`, `fchmod`, `O_NOFOLLOW`, `flock`) is POSIX. Today, after L0.2, Windows scratch roots are L0.1 DACL directories (`D:P`, owner and SYSTEM, inherited by children through `OICI`), so the arena must not regress them. On win32, `open` uses the same `_parent_base` and `_allocate` (the DACL branch), names the root `ARENA_PREFIX + token` directly (no pending rename, no marker, no lock), and registers it. Every arena object stores its checked root plus relative components. After the same `validate_component` call the POSIX arm makes, `create_dir` calls `_create_level`; `create_file` calls `_protected_dir._win_create_file(path)`, beside `_win_create`: `CreateFileW(GENERIC_WRITE, share=0, CREATE_NEW, FILE_ATTRIBUTE_NORMAL)` with the same protected owner-and-SYSTEM descriptor passed explicitly, so the file never exists without it, then `msvcrt.open_osfhandle(handle, os.O_WRONLY | os.O_BINARY)` so Arrow and Parquet bytes are not newline-translated. `open_file` uses `os.O_RDONLY | os.O_BINARY` on the checked child path. `remove` uses L0.1's `lstat` and reparse-point refusal before `unlink` or `rmdir`; `rename` uses `os.rename` between two children of that same stored root. `reclaim()` removes by path and reports `RETAINED` on failure; `sweep_scratch()` returns an empty `SweepReport` and deletes nothing. The 4.2 descriptor checks are replaced by L0.1's `_win_state` read-back on every directory and file the arm creates, as `_create_level` already reads directories back (`_protected_dir.py:177-197`, `:377-399`).

`ScratchAccess` remains one class, moved from `out_of_core/_scratch.py:122-153`. Its POSIX branch keeps the held-root descriptor. Its win32 branch keeps the checked arena root and, for the same SOURCE read and stat requests, normalizes the locator, proves it is at or below that live issued root through `_protected_dir._vet_live` (`_protected_dir.py:80-92`), and returns the existing engine-owned path handle. It never constructs a `LocalFileAccess` and never accepts a caller root. This is the same containment and reparse-point rule as the allocator, not a second path resolver. T02 and T18 therefore keep their reader on Windows (`declared_casting/_stream.py:79-143`). Named limit L9: on win32 a killed run's arena is never reclaimed and check-then-use is path-based (L0.1's own limit). POSIX-only, refused on win32 with `FileAccessUnavailable`, are the isolated `pass_fds` hand-off (S3a, and the isolated route already fails there at `import resource`, `execution/_isolated_common.py:28`), `flock` and the sweep. The arm is about 120 lines in `fileaccess/_scratch.py` behind one `sys.platform` branch, plus `_win_create_file` (about 25) in `_protected_dir.py`'s win32 block. `CreateFileW` through `ctypes` is not in the D9 sink set, the same stated limit as L0.1's `CreateDirectoryW`. `test_win32_arena` and the plain and declared T-PLAIN OOC cells run by hand on L0.1w's Windows host (WIN-RUNNER, roadmap row 6; there is no engine Windows CI job). Until then the arm is unverified, as L0.1's Windows branch is.

### 4.7 Design notes

- New structure: one capability type (`ScratchArena`) and one sweep. Principles from `architecture.md`: one place per fact (prefix, marker name, issued-root set, creation modes each defined once), and capabilities over ambient paths (the arena hands out descriptors; `local_path` is the single, allowlisted release). The change pain addressed: before this, every producer chose its own directory, mode and cleanup (section 3's eighteen rows); after it, a new producer gets all three by taking an arena.
- Where each fact lives: directory creation, the issued-root set and the win32 DACL in `fileaccess/_protected_dir.py` (L0.1); descriptor-relative directory and private file creation in A-4's `fileaccess/_output.py`; the arena, prefix and marker in `fileaccess/_scratch.py`; reports in `fileaccess/_scratch_reports.py`; the sweep in `fileaccess/_scratch_sweep.py`; the native-failure mapping in `scratch_native` beside the arena, reusing `_errors.py`'s classifiers.
- House style: producers take one typed `arena` argument rather than `temp_dir` plus flags; no flag argument switches arena behaviour (owning versus adopted is a separate constructor, `_adopt`).

### 9.1 Open question: guarded connection at the choke point

The idea. `connect_duckdb` (T05), which every scratch connection already passes, returns a guarded connection. Each method call runs through `scratch_native`. A result whose type is `DuckDBPyConnection`, `DuckDBPyRelation` or `pyarrow.RecordBatchReader` comes back guarded too, and iteration runs through `scratch_native_iter`. Every flow shape is then value-free by construction: returns, attributes, parameters, containers and callbacks. The sentry shrinks to one structural rule: no `duckdb.connect` outside the adapter, and `connect_internal` called only from `_duckdb.py` and `postgres_snapshot.py`.

What `main` uses (`296d8f9e`; the 11 sites in the 9 pending modules, read by grep). Connection methods: `execute`, `register`, `unregister`, `close`. Result methods: `fetchone`, `fetchall`, `to_arrow_reader`. Readers are only iterated in Python (`_join.py:160`, `_batch_join.py:262`, `_stream_join.py:372`, `:449`). No `sql()`, no relation API, no reader handed to a C API, no connection passed to a `duckdb` function. DuckDB's `execute` returns the connection itself, so `conn.execute(q).fetchone()` stays guarded.

Can a thin proxy avoid a per-method list? Mostly. `__getattr__` wraps any callable attribute, and return wrapping is by the three types above, not by method name. Python looks up special methods on the type, not through `__getattr__`, so the proxy defines a fixed set itself: `__iter__`, `__next__`, `__enter__`, `__exit__`. That set follows Python's protocols, not DuckDB's API, so it does not rot as DuckDB adds methods.

What it replaces:

- S1b: the scanner extension (parameters, returns, attributes, annotated assignments, call-edge reuse), the lazy-read cells and most derived-membership cells. About 330 lines become about 60 of structural sentry.
- In S2a-1c-ii, S2a-1c-iii, S2a-2, S2b-2 and S4b-0: the per-call `scratch_native` rewrites and most native-text cells. About 400 lines. Each slice stays, because it also moves its module onto the arena.
- `SCRATCH_NATIVE_PENDING` keeps only the read-scope modules. Scratch file reads (R1) are not connection calls, so S2a-1c-r and `read_footer` stay.
- Net: about 450 to 500 lines fewer. No slice is removed.

What it costs: the proxy, about 120 lines in fa `_scratch.py`, plus about 150 lines of tests (each wrapped type, chaining, iteration, the context manager, and a structural sentry cell per evasion). It also changes `connect_duckdb`'s public return type (section 8, pre-GA, CHANGELOG). Typing must `cast` the proxy to `DuckDBPyConnection`, so mypy no longer checks calls through it.

What #500 and #522 keep: all of `scratch_native`, `scratch_native_iter` and their mapping cells (the proxy calls them); #522's arena connect as built. Thrown away: #500's name-based key test and the native part of `scratch_release_evasions.py` (its `local_path` part stays), plus the 8.4 and 8.5 scanner work, which is not built yet.

Unverified: that no site hands a guarded object to native code that needs the real type (the grep above covers `main` only); DuckDB replacement scans and `register` of Arrow objects through a proxy; the per-call and per-batch overhead (one Python frame each, unmeasured); `connect_internal` left raw for `postgres_snapshot.py`, which keeps its own `except duckdb.Error` mapping.

Recommendation: take it, as a plan revision before S2a-1c-ii is built. Reason: it closes the class at the one choke point, while derived membership has needed a new flow shape at every review (opt-in names, then parameters and attributes, then returns, local attributes and annotated assignments).
