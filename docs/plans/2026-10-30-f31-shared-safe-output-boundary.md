## 1. Guarantee (invariants as properties)

**Threat model (V1, binding).** Self-hosted, single-org; the engine process is trusted. The leak is ACCIDENTAL: a source value or path in exception text, `args`, `__notes__`, a normal `__cause__`/`__context__` chain, a log line, a `repr`, a progress message, a result field, a serialized report, or a local variable of an engine frame rendered by traceback-locals capture. Canaries are ordinary shapes (str, int, list, dict, a dataclass with a marker in its repr, an ordinary exception raised by a callee). Hostile in-process objects (forged instances, hostile dunders, `BaseException` from dunders, frame and `gc` games, descriptor aliasing) are V2 (last paragraph of this section).

| Class | Shows | Never shows | Surfaces |
|---|---|---|---|
| (a) operational | registry prose, closed enums, bounded integers, positions, the run UUID, aliases `table-N` / `field-N` / `node-N` / `artifact-N` | any schema name, path, DSN, credential, exception text or dynamic class name, cell value, free prose | engine and server logs, `Job.log`, diagnostics, metrics, support bundles, CLI stderr |
| (b) owner result | everything (a) may show plus real schema names (table, column, node id, repository-relative config pointer) and identifiers the owner created (job id, pipeline id, file id) | any source or masked CELL VALUE, sample, statistic computed from values, path outside the owner's project, credential, exception text or dynamic class name | progress views, results and reports, evidence, `scan --json`, API success and error bodies, audit, node runs, the alias legend |
| (c) data plane | the data itself | n/a: written only by the exact writer manifest; read only by data-plane routes | masked and subset output, vault, quarantine rows, raw profile artifact, discovery rows |

**G1 (operational).** For every (a) surface S and every value v of the classes in the threat model, the bytes S emits contain no derivative of v. The only producers of (a) bytes are `safe_output.to_line`, `safe_output.render_text` and the Platform OBS-3 formatters (3.5).

**G2 (owner result).** No SERIALIZED (b) surface carries a cell value, a value-derived statistic, exception text or a dynamic class name. Names appear as the owner declared them. The fields in 5.4 marked (c) are absent from every (b) projection. A serialized (b) surface is any (b) value that leaves the call that produced it as data: an engine result or report dataclass field, a progress or phase record, an envelope, a Platform response body, an audit row, a database column. G2 at completion covers every engine (b) surface and the Platform surfaces S13-S17, S19, S22 (section 5.5); the Platform residual named in owner question O2 is outside G2 until the owner answers it.

**G3 (data plane).** A data-plane writer is an exact function in the generated writer manifest; no (a) or (b) renderer accepts a data-plane object.

**G4 (re-ingest).** A `Job.log` line is replayed only after `from_line(line, expected_run=job.run_uuid)` accepts it; a line that fails is counted and withheld. Server logs are not replayed as events (3.5).

**G5 (exception types).** Exception type labels come only from `safe_error_type(exc)`, an exact-type lookup `_ALLOWED_EXCEPTION_TYPES.get(type(exc), SafeErrorType.EXCEPTION)`. No production code reads `__name__`, `__qualname__` or `__class__` of an exception.

**G6 (entry frames).** When a public engine entry (the census in 3.7) raises, no frame in the raised exception's traceback or in any traceback of its `__cause__`/`__context__` chain, from the entry's own frame downward, holds a local whose `repr` carries a path, a config object or a value the caller passed. The caller's own frames are the caller's.

**In-process exception boundary (states what G2 does not cover).** An exception RAISED to an SDK caller is not a serialized surface: its type and message are the in-process contract of the 27 public exception classes, the caller wrote the input, and the message may name schema objects and config pointers. G2 starts where exception text would be copied into a serialized (b) surface or any (a) surface: rule R7 (6.5) bans that copy, and the 5.4 slices remove the existing copies. F31 does not claim that the 1080 f-string `raise` sites (280 files) are value-free; 79 of them interpolate an except-bound name, which can carry a foreign library's text into an engine exception. That residual is owner question O1, and until it is answered the operator guidance in `docs/security/error-reporting-and-data-exposure.md` (keep exception text out of shared logs) is the documented control.

Non-goals: no new encryption or hashing; regex scrubbing (`api/logging/redaction.py`) stays a backstop; no `--unsafe-debug-log`. V2 note (hostile in-process hardening, recorded, not planned): provenance tokens, sealed payloads, forged-instance detection past `__post_init__`, hostile dunder defenses, process-wide stream ownership, child fd bootstrap, sentries over aliases and descriptors.

Added, `SafeEvent` (`safe_output/_event.py`): an ordinary frozen dataclass validated in `__post_init__` and again in `to_dict`, with exact-type checks on nested groups exactly as `_V1Fields` does (`_progress_events.py:262-270`). Fields: `run: uuid.UUID | None`, `seq: int`, `ts_ms: int`, `sev: reasons.Severity`, `kind: EventKind` (closed enum), `phase: reasons.Phase | None`, `op: reasons.Operation | None`, `outcome: reasons.Outcome | None`, `reason: ReasonRef`, `err: SafeErrorType | None`, `loc: SafeLocation | None` (component enum plus integer `line`, `column`, `row`, `chunk`, `ordinal`), `counts: tuple[tuple[str, int], ...]` under `COUNT_KEYS` (`_record.py:34-36`, extended additively), `aliases: tuple[SafeAlias, ...]`, `edges: tuple[SafeEdge, ...]`, `ver: tuple[SafeVersion, ...]`, `flags: frozenset[Flag]`. There is no `str`, `Any`, mapping or extension field. `operational_view(progress_event, scope)` projects an F29 progress event onto a `SafeEvent` with names replaced by aliases; that projection, not the progress dict, is what logs receive.

Serializers (`safe_output/_wire.py`), the only producers of (a) bytes:

- `to_dict(event) -> dict`: the `decoy-safe-output/v1` record, closed keys `s`, `rv`, `run`, `seq`, `ts`, `sev`, `kind`, `phase`, `op`, `outcome`, `reason`, `err`, `loc`, `counts`, `aliases`, `edges`, `ver`, `flags`.
- `to_line(event) -> bytes`: `json.dumps(sort_keys=True, separators=(",", ":"), ensure_ascii=True, allow_nan=False)` plus `\n`. Limits, both checked on the encoded record before it is returned: at most 4096 bytes excluding the newline, and JSON nesting depth at most 3 (the record object is depth 1, a list in it depth 2, an object in that list depth 3). A record over either limit is NOT truncated: `to_line` returns instead the registered `safe_output.invalid` event for the same `run` and `seq` with a closed `cause` count (`oversize` or `too_deep` or `invalid_field`). If building or encoding that substitute raises, `to_line` returns the module constant `_FAILED_LINE = b'{"kind":"failed","s":"decoy-safe-output/v1"}\n'`, an ASCII literal built at import with no runtime input. `to_line` never raises and never returns bytes derived from the rejected event. `from_line` rejects `_FAILED_LINE` (no `run`), so a reader counts it as withheld.
- `render_text(record) -> str`: `ISO_TS  LEVEL  STEP  MSG`, STEP is `node-N` or `job`, MSG is the registry summary plus closed facts.
- `from_line(line: bytes, *, expected_run: uuid.UUID) -> SafeEvent | None`: rejects before parsing a line over 4097 bytes; bounded parse with an object-pairs hook that rejects depth over 3 and duplicate keys; closed keys; every field re-checked; `rv` minor not newer than the reader; reason known via `require_known`; `run` equal to `expected_run`; anything else is `None`.
- `metric_labels(event) -> dict[str, str]` yields closed-enum values only.

### 3.2 Exception boundary

`SafeErrorType` is a closed `str` enum built once at import from exact classes: every builtin exception class (enumerated from `builtins` as `_safe_error_names` does today, `_progress_events.py:69-81`), the engine families in `reason_adapter._CODED` (`reason_adapter.py:39-85`) and the exception classes of `decoy_engine.errors`, plus `EXCEPTION`; `_ALLOWED_EXCEPTION_TYPES` maps each exact class to its member and the member's label is that class's name as engine code recorded it. The label set therefore equals today's `_SAFE_NAMES` set, and `phase._ERROR_KINDS` (`phase.py:555-570`, 15 builtins) is a subset of it. `safe_error_type(exc)` is the one lookup (G5). Consumers migrated: `phase.error_result` (`phase.py:594`; its `error_type` domain widens from 15 labels to the closed table, an additive change recorded in section 7), `_progress_events.safe_error_class` (`:86-98`, deleted; the `error_class` sanitizer becomes `SafeErrorType.from_label`, so the progress value domain is unchanged), `progress.run_scope` (`progress.py:445`), `exception_error_text` and `commit_error_text` (`src/decoy_engine/execution/_isolated_common.py:246`, `:253`), the six `postgres_snapshot` `cause_type` sites (`src/decoy_engine/connectors/postgres_snapshot.py:242`, `:256`, `:327`, `:408`, `:491`, `:515`; `cause_type` becomes the label), Platform `api/observability/metrics.py:391`.

`safe_event_from_exception(exc, *, reason=None, loc=None) -> SafeEvent` takes the reason from `reason_from_exception` (`reason_adapter.py:146`) and the label from `safe_error_type`; it stores nothing of `exc`. `contain(fn)` lifts `phase._contained` (`phase.py:168-181`) into `safe_output._exception`; `phase` keeps the `__phase_contained__` mark so its sentry is unchanged. Frame contract for a CONTAINED boundary, "no original or data-owning frames": a `SafeBoundaryError` is raised outside the handler after the boundary deletes its own arguments, with `__cause__` and `__context__` `None`, `__suppress_context__` set, no `__notes__`; its `__traceback__` starts at the boundary frame. Uncontained public entries keep their exception (type, message, chain) and get the frame construction of 3.7 instead. No ordinary path calls `traceback.format_exc`, `print_exception`, `TracebackException`, `logger.exception` or passes `exc_info` (the engine has zero such sites at `ab29ef0c`; `tests/sentry/test_log_interpolation.py:23-71` already lists the risky names).

### 3.3 Run identity, scope, aliases, legend

- Run: one run is one job. Platform mints `uuid.uuid4()` in one function `api/jobs/run_identity.py:mint_run_uuid` at job creation and stores it in `jobs.run_uuid` (`String(36)`, unique, not null after backfill) beside `Job.id` (`api/models.py:329`). DB-boundary enforcement: the column default is `mint_run_uuid`, so each of the 8 `Job(...)` constructions at `00e55c27` gets one without naming it; a SQLAlchemy `@validates("run_uuid")` accepts only the canonical form of a version-4 UUID; a CHECK constraint enforces length 36, version nibble `4` and variant `[89ab]`; an AST sentry forbids any explicit `run_uuid=` argument or `.run_uuid` assignment outside `mint_run_uuid`; every request schema excludes the field (a body that carries `run_uuid` is rejected, test T11). The CLI mints one UUID per invocation in `main`. The engine never sees `Job.id`.
- Scope: `SafeOutputScope.for_run(run)` accepts only `type(run) is uuid.UUID and run.version == 4`, binds a `ContextVar`, owns the alias table and the event sequence. `SafeOutputScope.current()` returns the bound scope or the process scope (`run=None`). A record with `run=None` is process-scoped (allowed in engine and server logs, never storable in `Job.log`).
- Aliases: identity is `(run, kind, ordinal)`, kinds `table`, `field`, `node`, `artifact`; each kind caps at 4096 (`kind-0` plus `alias_overflow`). The coordinator pre-registers every static name in canonical plan order before execution; later names are appended in first-seen order.
- Alias table lifecycle, per JOB (replaces revision 2's "frozen after the first child handoff", which left a second isolated child, a governor reroute (`execution/_governor.py:532`, `:567`) or table 2 of the independent multi-table split (`execution/_pipeline_multi_table.py:260`) unable to name what it discovers). States: `OPEN` (the coordinator thread may allocate; any other thread gets `kind-0` plus `alias_unknown`), `LENT(epoch k)` and `FROZEN`. `scope.lend()` moves `OPEN` to `LENT(k)` and returns an immutable snapshot (entries plus the next ordinal per kind) that `_isolated_run._write_payload` (`src/decoy_engine/execution/_isolated_run.py:368-406`) adds to the payload. While `LENT`, the child is the only allocator: it allocates from the snapshot's next ordinals and reports its new entries, in allocation order, in the result envelope as `aliases_added` (names are (b) content of the envelope, bounded by the per-kind cap); every coordinator allocation attempt while `LENT` returns `kind-0` plus `alias_unknown` and is counted. `scope.merge(k, aliases_added)` validates that the added entries start exactly at the snapshot's next ordinals and are contiguous, appends them, and moves to `OPEN`; a child that died without an envelope is `scope.merge_lost(k)`: the table returns to `OPEN` at the snapshot's ordinals and the next terminal event carries flag `alias_epoch_lost`. A second `lend()` while `LENT` raises `AliasTableBusy` (children are sequential at `ab29ef0c`: the governor awaits each child, the multi-table split runs one table at a time); scope exit moves any state to `FROZEN`. Because only one allocator exists at a time and the merge appends in the child's order, child ordinals equal parent ordinals by construction, and a retry of the same job on the same input reproduces them (T9, T15).
- Legend: `scope.legend()` is `tuple[(kind, ordinal, name)]`, an owner result, handed to the sink's `on_legend(legend)` on every scope exit path before the terminal event. Platform caches it on the job's sink context and stores it in a new `job_alias_legend` table (`job_id`, `kind`, `ordinal`, `name`) when `job_log.append` receives the terminal event (`EventKind.TERMINAL`). Transaction boundary: the legend insert runs inside its own SAVEPOINT (`with db.begin_nested():`), the same pattern the terminal manifest uses (`api/jobs/job_terminal_cas.py:151-155`); if the savepoint fails (any `Exception`, including a database-level error that would otherwise abort the outer transaction on Postgres), only the legend insert rolls back, the terminal event gains flag `legend_unavailable`, and `append` then writes the terminal line in the outer transaction, which the caller commits with the status change. Without the savepoint, a database-level legend error poisons the outer transaction and Postgres turns its COMMIT into a silent rollback, losing the terminal line and the status (the failure mode documented at `job_terminal_cas.py:117-133`). The legend is read only by `GET /api/jobs/{id}/alias-legend` behind `require_job_owner_or_404`. A crash before terminal (reaper paths, another process) leaves no legend; the UI shows raw aliases with flag `legend_unavailable`. F32 bundles never include it.

### 3.6 Exception text versus serialized output (R7)

The boundary stated in section 1 is enforced by rule R7: inside an `except ... as NAME` handler, production code may not read `str(NAME)`, `repr(NAME)`, `NAME.args`, `NAME.message`, or interpolate `NAME` (f-string, `%`, `.format`) in any expression that is not the argument of a `raise`. ### 3.7 Entry frames: one construction at the public-entry boundary

Problem (A-4 round-3 Codex FINAL, recorded in `docs/records/2026-11-01-a4-f13-reconcile-evidence.md:241-262` on `d171f778`): A-4 boxed the WRAPPER frames of the 42 `fileaccess.ENTRY_POINTS` members (`fileaccess/__init__.py:52-95`, `fileaccess/_entry.py` `entry_point` and `_Arguments`) and the admission entries (`secret_providers/_preflight.py:160-232`, `_OpaqueBox`, `_call_closed`), but the entry function's OWN frame holds its parameters, so `TracebackException(capture_locals=True)` over an engine frame renders paths (`iter_csv_chunks`, `read_fixed_width`, `run_subset(output_dir)`, `unmask_pipeline(vault_path)`, ...) and configs that carry `mask_secret_ref` (`run_pipeline`, `compile_plan`, `validate_plan`, ...). Patching 41 entries one by one would be a third patch of one class (class 1, value-bearing traceback locals), so F31 replaces it with one construction.

Construction, `safe_output/_frames.py:closed_entry(fn)`, applied at ONE choke point per entry shape:

1. Arguments are boxed exactly as A-4 does: the wrapper moves `args` and `kwargs` into `_Arguments` (fixed `repr`, unpicklable) and deletes them before anything can raise, unpacking only inside the call expression. `_Arguments` moves from `fileaccess/_entry.py` into `safe_output/_frames.py` and `fileaccess/_entry.py` imports it (one definition).
2. On any `BaseException` leaving `fn`, the wrapper walks the exception and its `__cause__`/`__context__` chain (cycle-safe by `id`, at most 64 links) and calls `traceback.clear_frames(link.__traceback__)` on each. `clear_frames` clears the locals of every finished frame (the entry's own frame and every frame below it) and skips executing frames (the wrapper and the caller's frames), so the caller's frames are untouched. Suspended generator frames in the chain are closed by `frame.clear()` on 3.10-3.12 and skipped with `RuntimeError` on 3.13; both are covered by the test matrix.
3. The wrapper re-raises the SAME exception object outside the handler. Type, message, `args`, chain and stack lines (`file:line:function`) are preserved, so the SDK contract of the 27 public exception classes is unchanged; only frame locals are gone. Consequence: a debugger's post-mortem on an engine exception shows no locals in engine frames (owner question O3).
4. Generators: `fileaccess._entry._BoundIterator._run` (the single iteration choke point A-4 built) applies the same clearing on each `__next__`/`send`/`throw` failure; non-`ENTRY_POINTS` generator entries use `closed_entry`'s generator form, which binds the iterator through the same `_run`.

Choke points: `fileaccess.entry_point` calls `closed_entry` (one edit covers all 42 `ENTRY_POINTS`); every other census entry with frame risk is decorated `@closed_entry` at its definition. The census (`tools/safe_output_inventory.py --entries`, committed as `tests/sentry/public_entries.json`) enumerates the functions in `decoy_engine.__all__`, the public methods and constructors of exported non-exception classes, and `fileaccess.ENTRY_POINTS`, and classifies each `closed` (wrapped), `value-ctor` (a dataclass `__init__` whose fields are the value itself; out of scope, listed) or `no-frame-risk` (no parameter annotated as a path, `os.PathLike`, `Mapping`/`dict`, a config dataclass, `bytes` or `Any`). At `d171f778` the census by parameter NAME (a lower bound; the annotation census replaces it in E8a) finds 232 public entries, 76 taking a path or config parameter, 43 of them outside `ENTRY_POINTS` in 21 definition sites, 5 of which are dataclass `__init__` (`value-ctor`).

Sentries: F1 (static) fails when a census entry classified neither `value-ctor` nor `no-frame-risk` lacks the `__decoy_closed_frames__` mark, when a public entry is missing from the census, or when a classification changed without the census file changing. F2 (runtime, generated per entry): installs a `sys.settrace` local tracer on the entry's code object that raises `RuntimeError("probe")` at the entry's first line event (so the entry's frame exists with its parameters bound, whatever the entry does), calls the entry with marker-bearing path and config arguments (a path whose name is a marker, a config dict whose `mask_secret_ref` and locator values are markers, a dataclass config with a marker field), renders `TracebackException(capture_locals=True)` over the whole chain, and asserts no marker. Positive control in the same cell: with `closed_entry` monkeypatched to the identity, the marker IS present. Seeded violation: `tests/sentry/fixtures/entry_frames/leaky_entry.py` defines `def leaky(path, config)` unwrapped and registers it in a fixture census; `test_entry_frames.py::test_seeded_unwrapped_entry_is_red` runs F1 and F2 over the fixture and asserts both fail.

## 11. Slices
