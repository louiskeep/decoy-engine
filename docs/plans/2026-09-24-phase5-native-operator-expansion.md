## Parked build-time items (Codex round-4), resolved 2026-09-26 on `feat/native-date-shift`

The date_shift-native design below is confirmed coherent; two small wiring items were parked for build time (to resolve under the build's own dennis+Codex gate).

1. `RowErrorRecord` requires a `table` field (`_row_errors.py:47`) which the proposed operator constructor omits — return a batch-local `RowError` from `run_operator` and have the coordinator add the table + offset (or pass the table into the operator); AND the failure-parity test must assert the NATIVE `ShadowRunResult.row_errors` index BEFORE the oracle reroute (after reroute the oracle recomputes the index, so the current test cannot prove native rebasing) — keep the dropped-record regression guard.
2. The index-kernel wiring: changing the coordinator condition from `pool_binding` to `uses_index_kernel` would also run POOL RESOLUTION for a no-pool date_shift binding (`_shadow_coordinator.py:354`) — kernel-load and pool-resolution need SEPARATE conditions. AND the companion-absent oracle fallback needs an INDEX-COMPANION ADMISSION check: a load failure currently becomes `ShadowDifference` -> `UnifiedSliceInvariantError` which is RE-RAISED, not rerouted (`_unified_slice_admission.py:408`, `_unified_slice.py:243`) — add the admission check + an absent-companion test.

Resolution (for the build gate to verify):

- Item 1: `run_operator` returns `(out, tuple[RowError, ...])` with BATCH-LOCAL indices and no table. The coordinator rebases each record by the batch's running row offset and builds the `RowErrorRecord` with the table, mirroring `drain_row_errors`' adapter-attributes-the-table split. `ShadowRunResult.row_errors` carries them. Tests assert the native `ShadowRunResult.row_errors` (row 3 in the second batch of 2) directly on the coordinator result, and in production by spying the coordinator before the reroute; the dropped-record guard is kept.
- Item 2: main already separated the two conditions: kernel load reads `ExecutionBinding.needs_index_kernel`, pool resolution reads `pool_binding`. date_shift sets `date_shift_date_format` (which `needs_index_kernel` reads) and no `pool_binding`; a test proves one kernel load and zero pool resolutions. The index-companion admission check also exists on main (`_OPERATOR_REQUIRED_KERNEL` + `native_kernel_availability()` in `resident_contract_admission`); `native_date_shift` is registered there as needing the `index` kernel, so an absent index kernel declines at admission instead of raising `UnifiedSliceInvariantError` from the coordinator. An absent-index-kernel test covers it.

## Redact/truncate re-baseline (2026-09-26, shared 4-core devbox, load ~6, median of 5)

Serial native kernel vs a 4-thread `array.slice` fan-out prototype, string column with 5% nulls:

| rows | op | serial | fan-out x4 | speedup |
|---|---|---|---|---|
| 10M | redact | 0.24 s | 0.33 s | 0.72x |
| 10M | truncate (head) | 0.30 s | 0.21 s | 1.45x |
| 10M | truncate (mask_char) | 2.86 s | 1.80 s | 1.59x |

Decision: do not build the fan-out now. redact gets slower and plain truncate saves about 0.1 s per 10M rows. Only truncate with `mask_char` (about 29 s at 100M serial) shows a real gain, and that is better addressed by vectorizing its mask path than by threading. Re-measure on the reference host before revisiting.

## FRAME

### Problem

ROADMAP Stage B item 6 ("Phase 5 native operator expansion") asks to parallelize the native redact/truncate operators and add native implementations of `date_shift`, `bucketize`, `code_set`, and `categorical`, folding in the held NER batched-inference port. Since that item was written, the ground truth changed and the gate corrected two of my earlier assumptions:

1. `categorical` is already natively ported and green-but-unmerged on `feat/phase5-categorical` (`src/decoy_engine/execution/native/_categorical_ext.py`): deterministic mode, string categories, full-frame route only, reusing the compiled `derive_index_batch` kernel with NO new Rust. `bucket_perturb` (a distinct date-snap strategy, NOT numeric `bucketize`) is likewise built on `feat/native-bucket-perturb` (`_bucket_perturb_ext.py`). Both are chunked-route-vetoed (`CHUNKED_ROUTE_VETOED_STRATEGIES`, a new constant on that stack) and both extend the single contested allowlist `NATIVE_KERNEL_STRATEGIES` in `src/decoy_engine/execution/native/_requirements.py`.
2. The standalone redact/truncate parallel fan-out was explicitly VOIDED on that same stack (commit `7b8907a4 docs(plan): void Track A fan-out (stale-baseline premise)`); only a thread-budget clamp landed (`decoy-engine-native/src/threads.rs`, `DEFAULT_NATIVE_MASK_THREAD_KNEE=4`). So "parallelize redact/truncate" is a measure-first question, not a settled build.
3. The NER batch helper `iter_ner_spans_batch` (`src/decoy_engine/storm/ner.py`) is BUILT, wired into all four callsites, double-gated, and HELD on `feat/phase5-hard-tail` (`docs/plans/2026-09-08-p5-ner-batch-helper.md`). It is a pure throughput refactor with no route/model/allowlist change.

Two constraints the gate surfaced, both verified in code, bound the design:

- `code_set` mask selection is NOT `derive_index_batch`. The oracle (`transforms/code_set.py:_pick_mask`/`_pick_from_seq`, `_codeset_index.py:hole_candidate_count`/`hole_resolve`) EXCLUDES the input code from the candidate set, derives a SECRET-salted HMAC key (`derive(mask_key, namespace, _KEYED_SALT)`, DE-02), reduces the HMAC digest modulo the REMAINING candidate count (`len(rows) - 1` when the input is a corpus member), and maps the result PAST the excluded hole. `derive_index_batch` uses the HKDF→HMAC `derive` envelope with a 64-bit reduction over the full pool and no exclusion. No gather adjustment makes these equal, and a derive-index KAT would assert the wrong identity. Native `code_set` therefore stays on the oracle in v1.
- The unified-slice full-frame coordinator (the Task 4.5/4.6 production owner of the native full-frame route) declines any binding whose requirements carry `required_prepasses` or `diagnostic_obligations` (`_unified_slice_admission.py:378`), hard-rejects prepasses at binding (`_shadow_bindings.py:160-169`), and declines any job configured with `quarantine`/`validators`/`run_storm` (`_unified_slice_admission.py:172`). The row-error→quarantine plumbing exists (`_unified_slice.py:335-370` threads `shadow_result.row_errors` into `finalize_validators_and_quarantine`) but is inert today because every admitted strategy is diagnostic-free. `date_shift` emits `format_error` row errors and, without an explicit `date_format`, declares a `format_detect` prepass — so it cannot be admitted by allowlist entry alone.

Genuinely unbuilt on any branch: native `date_shift`, native `bucketize`, native `code_set`, a native non-FK text handler. Today `date_shift`/`code_set`/`bucketize` resolve to `fallback_policy == "native"` capability-wise (`_capabilities.py`: row-local, static output type) but are rejected by `native_kernel_rejection` (not in `NATIVE_KERNEL_STRATEGIES`), so they always run on the oracle.

The oracle handler is already numpy-vectorized (no per-row Python loop), so a native port's value is low; build a thin Arrow-compute operator only if a re-baseline shows measurable benefit on the target host, otherwise leave it on the oracle with the finding documented.

### Applicable rulebooks

`feature-dev`, `architecture` (new backend + a scoped relaxation of the unified-slice diagnostic gate), `api-and-compatibility` (routing table + admission), `testing`, `verification`, `security` (the operators are re-identification-relevant; the keyed reduction and the redacted-error contract must be preserved). Engine `CLAUDE.md` established-methodology rule: cite the reused pattern in each new module's docstring (HKDF-SHA256→HMAC keyed derivation via the shared `derive_index_batch` family; pandas as the parse/format authority, mirroring `_bucket_perturb_ext.py`).

### Risk rationale

R2 because this widens the native routing table, reuses the keyed crypto kernel, and RELAXES a coordinator admission gate to carry a diagnostic obligation (date_shift row errors) that the current unified slice declines. A byte-parity or quarantine-routing failure is a silent wrong-output or a PII-leak (a mis-gathered category, a date offset that breaks intra-entity joinability, or an unparseable date leaking into the main output instead of quarantining). Mitigation: no new derivation math (the keyed step is the audited `derive_index_batch`; the post-step is the oracle's own pandas code over Arrow batches), and the coordinator relaxation is scoped to a single row-error obligation routed through plumbing that already exists.

## Approach

The unifying insight, re-verified against the operator source after the gate: `categorical` and (no-group_by, explicit-format) `date_shift` reduce to the compiled `derive_index_batch` plus a vectorized post-step; `code_set` does NOT and is deferred; `bucketize` is not keyed and is already vectorized. `derive_index_batch(col, mask_key, namespace, pool_size)` computes exactly `u64_be(derive(mask_key, namespace, canonical(value))[:8]) % pool_size`, null-in/null-out, thread-invariant, over the native-hash admitted type set (string/large_string/bool/int widths; NOT float, NOT tz-naive timestamp). Its canonicalization matches Python `_canonicalize_source` (the faker native path already relies on this equivalence).

- `categorical` (built, land it): uniform = `derive_index_batch(source, pool_size=len(categories))` then Arrow gather `categories[idx]`; weighted = `derive_index_batch(source, pool_size=_WEIGHTED_CDF_RES=1_000_000)` then `np.searchsorted` over the CDF (reproducing the oracle's `bisect_right`) then gather. This is exactly `_categorical_ext.native_categorical`. It is zero-diagnostic (no `ctx.row_errors`), so it needs no coordinator diagnostic route.
- `date_shift` (v1: explicit format, string source, no group_by) — new, structurally a near-clone of `_bucket_perturb_ext.py`: the per-row offset is `min_days + (int.from_bytes(derive(mask_key, namespace, canonical(anchor))[:8], "big") % range_size)`, which for the no-group_by case (anchor = the source value) is `derive_index_batch(source, pool_size=range_size) + min_days`. The parse/shift/format post-step reuses the oracle's own authority verbatim: `pd.to_datetime(col, format=date_format, errors="coerce")`, `+ pd.to_timedelta(offsets, unit="D")`, `dt.strftime(date_format)`. A non-null row that fails `strptime` under the explicit format is a `format_error` row error (identical record to the oracle) and is routed to quarantine/job-fail; the offset computed for such a row is discarded because the row never reaches the main output, so main-output byte-parity is unaffected. Timezone directives (`%z`/`%Z`) decline to the oracle, adopting `_bucket_perturb_ext.has_timezone_directive`.
- `code_set` (DEFERRED — why): the oracle's `_pick_mask` excludes the input value, derives a secret-salted HMAC key, reduces the digest modulo the remaining candidate count, and maps past the hole. That is a different derivation, a different reduction width, and a different domain (exclusion) from `derive_index_batch`. A native `code_set` must reimplement THAT reduction exactly (a separate keyed batch kernel and its own KAT), plus route the corpus-provenance evidence (`ctx.code_set_corpora`) and the pinned-across-invocations `_CorpusRecord`, plus the `mask_error` row errors. None of that fits the v1 `derive_index_batch` reuse, so `code_set` stays on the oracle and is called out as a distinct future item.
- `bucketize` (measure-first): `floor(pd.to_numeric(value)/width)*width` formatted lower/range/midpoint. The oracle handler is already numpy-vectorized with no per-row loop (only a `np.flatnonzero` scan to record `format_error` row-errors), so a native port removes almost no per-row Python cost. If a re-baseline justifies it, it is a pure Arrow-compute operator (no key, no `derive_index_batch`) whose only real risk is matching pandas' `.astype(str)`/`Int64` string formatting exactly, AND it carries the same `format_error` diagnostic obligation as date_shift (so it would ride the same coordinator route). Default: leave on the oracle.

Coordinator route for diagnostic obligations (resolves P1-2). Today the per-node coordinator collects NO row errors: `run_operator` (`physical/_shadow_operators.py:66`) returns only a `pa.Array`, the batch loop (`_shadow_coordinator.py:372-389`) appends those arrays to `parts`, and `_run` builds `ShadowRunResult(outputs, route_evidence, warnings)` at `:427` while leaving the dataclass's `row_errors` field (`:132`, defaulted `()`) empty; finalization/quarantine only starts AFTER the result exists (`_unified_slice.py:335`). So a native `format_error` produced inside a batch has nowhere to go. The mechanism v1 must build, end to end:

1. Operator returns records. Change `run_operator`'s return to `(pa.Array, tuple[RowErrorRecord, ...])`. The `date_shift` branch computes its `format_error` records for non-null-unparseable rows with BATCH-LOCAL 0-based indices (the batch it was handed); every other (zero-diagnostic) operator returns an empty tuple, so the signature change is inert for categorical/redact/truncate/hash/faker.
2. Coordinator rebases to table-global. The batch loop tracks a running `row_offset` (initialized 0; the batch is `source.slice(offset, batch_size_rows)`, so `row_offset` IS that slice `offset`, equivalently `row_offset += batch.num_rows` after each batch). For each returned record it sets `row_index += row_offset` — making the index table-global, correct for an error in the SECOND-or-later batch — and extends a per-table `row_errors` accumulator. This equals the oracle's own index: `_date_shift.py` records `row_index=i` over the whole column `col`, and `batch_local + row_offset == i` by construction.
3. Result carries them. `_run` passes `row_errors=tuple(accumulated)` into `ShadowRunResult` at `:427` (the field already exists at `:132`), instead of the empty default.
4. Existing tail raises, and the reroute is the intended benign failure path (P1, option B). `_unified_slice.py:335-370` threads `shadow_result.row_errors` into `finalize_validators_and_quarantine`, which raises `RowErrorsFailedError` (`_pipeline_finalize.py:239`) on a non-empty set; the unified-slice handler catches that at `_unified_slice.py:372` and REROUTES the whole table to the oracle. In v1 we ACCEPT that reroute rather than fight it: a `format_error` is rare, and on reroute the oracle re-runs the table and produces the IDENTICAL job-fail with the IDENTICAL `RowError`, so failure parity holds. The native fast path is for the SUCCESS case (the overwhelmingly common one); a job that hits a format_error falls back to the oracle for an equivalent outcome, which is fine single-org. Steps 1-3 are still REQUIRED even though the row error triggers a reroute: without collecting it, the native path would emit a value for the unparseable row and SUCCEED silently (a leak) instead of surfacing the error that forces the (benign) reroute. So the collection mechanism is what makes the native path fail-safe; option B only means we do not add wiring to make the native path fail the job WITHOUT the reroute.

Admission is narrowed to exactly this obligation: relax `_unified_slice_admission.py:378` so a binding whose ONLY diagnostic obligation is `reduce_row_error:format_error` (a row-local, quarantine-routable row error) is admitted; warning reducers (e.g. geo cascade) and any multi-obligation binding stay declined. The job-level decline for `quarantine`/`validators`/`run_storm` config (`_unified_slice_admission.py:172`) stays AS-IS: a date_shift job WITH quarantine configured never takes native (declined at `:172`) and the oracle quarantines; a date_shift job WITHOUT quarantine takes native for the success case and, on a format_error, reroutes to the oracle for an identical job-fail.

Prepass resolution (resolves P1-3): v1 admits `date_shift` ONLY with an explicit `date_format`, so `_required_prepasses` never adds `format_detect` and `_shadow_bindings`' prepass rejection never fires. A missing `date_format` (detected-format) declines to the oracle, preserving `_detect_format`'s whole-column 200-row sampling and its multi-format warning behavior. Binding a single detected format from the full source up front is a later slice, not v1.

Established methodology reused, not reinvented (engine CLAUDE.md rule): the keyed derivation is the reviewed HKDF-SHA256→HMAC envelope in `decoy-engine-native/src/derive.rs`; the gather is the faker/categorical pattern; the date parse/format is pandas via the `_bucket_perturb_ext.py` template.

### Which to parallelize vs newly native-ize, and order

Parallelize (measure-first, likely no build): redact/truncate. Their native entry points (`_kernels_scalar.native_redact`/`native_truncate`) already call the pyarrow-compute-vectorized `redact_array`/`truncate_array` (GIL-releasing C on the string fast path). The prior fan-out was voided as stale-baseline. Re-baseline on current main first; if the serial cost still justifies it, the right-sized parallelization is a `ThreadPoolExecutor` fan-out over zero-copy `array.slice(lo, n)` windows bounded by the `native_threads` budget and the landed thread-knee (=4), concatenating results — byte-parity is trivial. Do NOT build a Rust redact/truncate kernel: truncate's `str(value)[:length]` codepoint/mask_char semantics are a byte-parity hazard in Rust for no gain over vectorized pyarrow.

Newly native-ize / land, in order:
1. C0 — land the reviewed stack (`categorical` + `bucket_perturb` + seam edits) to `main`, re-running its acceptance + parity suite against the FINAL ASSEMBLED operator output. Prerequisite for everything else.
2. S1 — native `date_shift` v1 on fresh `main` (`_date_shift_ext.py`): keyed offset via `derive_index_batch` + pandas date post-step (bucket_perturb template) + the coordinator diagnostic-route relaxation + explicit-format-only admission.
3. N1 — land the held NER helper (`feat/phase5-hard-tail`), independent of 1–2.
4. Measure/defer — redact/truncate re-baseline; `bucketize` re-baseline. Build only on evidence.
5. Deferred (recorded, not built) — native `code_set` (needs its own excluding-salted-HMAC kernel); native non-FK text handler consuming `iter_ner_spans_batch`.

### Flag / opt-in and byte-parity strategy

Opt-in: no new user-facing flag. Wiring `date_shift` onto the native full-frame route touches EVERY seam a keyed operator needs, not just the two allowlists — the full list, each named at its site:

1. Allowlists / admission: add `"date_shift"` to `NATIVE_KERNEL_STRATEGIES` and `CHUNKED_ROUTE_VETOED_STRATEGIES` (`_requirements.py`); add `native_date_shift` to `_unified_slice_admission.ALLOWED_OPERATOR_IDS`; add `{pa.string()}` to `_ADMITTED_RESIDENT_TYPES["date_shift"]`.
2. Config gate: add `date_shift_config_rejection` (mirroring `truncate_config_rejection`) that declines a missing/empty `date_format`, a `group_by`, or a `%z`/`%Z` directive, so a v1-ineligible date_shift resolves `fallback_policy != "native"` and stays on the oracle.
3. Shadow binding: add `"date_shift"` to `SLICE_STRATEGIES` and `OPERATOR_ID_BY_STRATEGY["date_shift"] = "native_date_shift"` (`_shadow_bindings.py:156,220`), and add a `date_shift` branch to `execution_binding_for_slice_node` (`:188-217`) that builds a `KeyBinding(key_source=caps.key_source, namespace=plan_slice.namespace)` — date_shift is keyed (`caps.key_source == "mask_key"`), so like hash it needs mask_key + namespace, and returns `None` if the namespace is absent (enforced upstream). It sets NO `pool_binding` (it derives directly over the source via `derive_index_batch`, it is not pool-backed).
4. Index-kernel load: the coordinator loads the compiled index kernel today ONLY when `binding.pool_binding is not None` (`_shadow_coordinator.py:355`); date_shift has no pool_binding. Add a `uses_index_kernel: bool` field to `ExecutionBinding` (True for faker AND date_shift), and change the coordinator's load condition from `pool_binding is not None` to `binding.uses_index_kernel`, so a date_shift node triggers the one-time `load_compiled_index_kernel()` and the verified wrapper is threaded into `run_operator` (already a parameter). Companion-absent downgrades the whole table to the oracle exactly as it does for hash/faker.
5. Operator signature: `run_operator` (`_shadow_operators.py:66`) currently takes no column identity and returns only a `pa.Array`; change it to `run_operator(array, *, binding, column, ctx, evidence, pool, index_kernel) -> tuple[pa.Array, tuple[RowErrorRecord, ...]]`. The `date_shift` branch reads `mask_key = ctx.mask_key`, `namespace = binding.key_binding.namespace`, calls `derive_index_batch(array, mask_key, namespace, pool_size=range_size, native_threads=ctx.native_threads)`, applies `min_days` + the pandas parse/shift/`strftime`, and builds `RowErrorRecord(column=column, row_index=<batch-local>, trigger="format_error", reason=...)` for non-null-unparseable rows; every existing (zero-diagnostic) branch returns `(out, ())`.
6. Diagnostic-gate relaxation: relax `_unified_slice_admission.py:378` for the `reduce_row_error:format_error`-only obligation (as specified in Approach).

A job outside the v1 gate reroutes the whole table to the oracle with a coded reason.

Byte-parity proof (native == oracle, the load-bearing gate):
- Keyed step: `derive_index_batch` parity to Python `derive_index` is already pinned by the existing KAT family. `date_shift` adds a KAT vector (`date_shift_kat.json`) asserting ONLY the operator reduction — `offset == derive_index_batch(source, range_size) + min_days` for explicit-format string sources. No `code_set` KAT (deferred; a derive-index KAT would test the wrong identity).
- Post-step + assembly: `date_shift` joins `_TOKENIZING_STRATEGIES` (`_shadow_coordinator.py:108`, which post-stack-merge already holds redact/truncate/hash/faker/categorical), so its `_assemble_column` shape matches the oracle's pandas round-trip. A per-operator differential asserts `native_<op>(...)` equals the oracle handler's FINAL ASSEMBLED column output (`_shadow_coordinator._assemble_column:172-213`), element for element, over empty, all-null, value-bearing, and error-bearing columns — including null positions AND the assembled Arrow type PER SHAPE, which for the tokenizing family is NOT string uniformly: value-bearing → `pa.string()` (as produced), zero-row/empty → `pa.float64()` (`:194-195`), all-null → `pa.null()` (`:196`). The test asserts whatever the oracle+assembly actually produce for each shape, not "string" across all three. It also asserts the exact `format_error` row-error set with quarantine routing. `date_shift` additionally asserts same source date → same offset within a namespace (intra-table interval/FK joinability preserved).
- Determinism/thread invariance rides `derive_index_batch`'s guarantee; the differential re-runs at thread counts {1,4} to confirm the post-step is order-independent.

## Observable behavior

1. Companion present, v1-eligible `categorical` or explicit-format `date_shift` column, full-frame job with no quarantine/validators/storm config: native route selected, output byte-identical to the oracle final-assembled output, job report records the native operator and a real `derive_index_batch` call count (positive evidence, never inferred).
2. `date_shift` with a non-null unparseable date (explicit format): the native path records a `format_error` identical to the oracle's, which raises `RowErrorsFailedError` and reroutes the table to the oracle (`_unified_slice.py:372`); the oracle produces the identical job-fail with the identical row error (raw date never in any output). The reroute is benign — both paths fail identically — and the native fast path is for the success case.
3. v1-ineligible config (detected-format/missing `date_format`, `group_by`, timezone directive, numeric/tz-naive source, non-deterministic categorical, `code_set`, quarantine/validators/storm configured, unadmitted resident type): whole table reroutes to the oracle with a coded reason; output unchanged.
4. Companion absent or ABI-incompatible: whole table reroutes to the oracle (no partial native output).
5. redact/truncate: unchanged output; if the fan-out is built, identical bytes at every thread count with lower wall time on wide string columns; if not, unchanged and serial.
6. NER helper landed: text_mask/text_redact/OOC group-b/c produce identical spans, faster; no route/model/default change.

## Known failure modes

- A native gather indexes the wrong category order (silent wrong output / re-identification risk). Mitigated: the gather order is the oracle's own `categories` list order, asserted by the differential and the categorical parity suite; reuse `sample_faker_array`'s runtime invariants (uint64 result, length match, null-mask match, in-bounds index), coded and fail-closed.
- date_shift row error DROPPED by the native path → an unparseable date is emitted with a value and the job SUCCEEDS silently (PII leak). This is the real risk under option B: the collection mechanism (Approach steps 1-3) is what raises `RowErrorsFailedError` and forces the benign oracle reroute. Mitigated by the failure-parity test AND its companion (a dropped record would let the native path succeed and emit the row — caught).
- date_shift string-format parity: `dt.strftime(date_format)` vs the oracle must match on the explicit format; `%z`/`%Z` decline to the oracle (adopt `has_timezone_directive`).
- Resident-type drift admitting a value `derive_index_batch` cannot canonicalize surfacing on a later chunk = partial native output. Mitigated by full-frame-only v1 and the `{string}` resident-type gate (this is why date_shift is chunked-vetoed).
- Accidentally treating `code_set` as a `derive_index_batch` pool-select (the exact P1-1 error): guarded by keeping `code_set` off `NATIVE_KERNEL_STRATEGIES` and documenting the excluding-salted-HMAC reduction as the bar for any future native code_set.
- bucketize `.astype(str)`/`Int64` vs float formatting divergence (`"1990"` vs `"1990.0"`, midpoint half-integer rounding). Mitigated: only relevant if built; then differential-tested across int/float widths and all three formats; otherwise deferred.
- Allowlist / `CHUNKED_ROUTE_VETOED_STRATEGIES` merge contention: build on merged `main` (after the stack lands) and extend the same frozensets rather than forking them.

## Acceptance tests (define behavior before build; no later contributor weakens them)

Per operator (categorical re-verified; date_shift new; bucketize only if built):
- Differential parity (primary gate): `native_<op>(corpus)` equals the oracle handler's FINAL ASSEMBLED column output — not just the operator's raw Arrow array — element for element, over EMPTY, ALL-NULL, value-bearing, and ERROR-BEARING columns. Assert values, null positions, the assembled Arrow type PER SHAPE (value-bearing → `pa.string()`; empty → `pa.float64()`; all-null → `pa.null()` for the tokenizing family — whatever the oracle+assembly produce, not "string" uniformly), and the recorded row-error set. Fixtures PIN selected OUTPUT VALUES and the exact ERROR records (column, row_index, trigger, reason), not only indices; force distinct pool positions (categorical: values landing on different `categories` slots), weighted-CDF boundary buckets (a value hashing to a CDF threshold edge), parse failures (date_shift: a non-null string that fails the explicit format), and empty/all-null assembly. Fails on main-without-wiring for the leak/format case, passes after.
- Operator KAT (date_shift only): `date_shift_kat.json` asserting `offset == derive_index_batch(source, range_size) + min_days` for explicit-format string sources, anchored on the existing derive_index_batch KAT family.
- Determinism / joinability: same source value → same output within a namespace; date_shift: same source date → same offset, so intra-table interval/FK joinability is preserved; asserted across thread counts {1,4}.
- Native-route-taken proof (date_shift SUCCESS case): a clean explicit-format date_shift column (no parse failures) over a table with more than one batch. Assert a BOUND `native_date_shift` node exists (`node.execution.operator_id == "native_date_shift"`), that the operator actually executed with an ACTUAL `derive_index_batch` invocation (positive evidence: `OperatorCallEvidence.executed` + `compiled_kernel_executed`, companion present, no reroute), and that the assembled output is byte-identical to the oracle. This proves the native route was taken, not assumed — so the wiring in items 1-5 above is exercised end to end.
- Failure parity + cross-batch global index (date_shift format_error, the P1-2 gate, option B): with `batch_size_rows` small (e.g. 2) and a non-null unparseable date at a table-global row BEYOND the first batch (e.g. row 3, in the second batch), assert the job FAILS with a `RowError`/`RowErrorRecord(column, row_index=3, trigger="format_error", reason=...)` byte-identical to the oracle's — proving the batch offset is added so the index is table-global, not batch-local — and the identical downstream outcome (job-fail, raw value absent from any output), whether the run went native-then-reroute or oracle-direct. The assertion is on the FAILURE parity (same error, same outcome), NOT on the route: a format_error on the native path is expected to raise `RowErrorsFailedError` and reroute to the oracle (`_unified_slice.py:372`), which is benign because both paths fail identically. A companion test asserts that WITHOUT the row-error collection (steps 1-3) the native path would instead SUCCEED and emit a value for the unparseable row — i.e. the collection is what prevents the leak — so a regression that drops the record is caught.
- Route/admission: each v1-ineligible case (detected/missing format, group_by, timezone directive, numeric/tz-naive source, non-deterministic categorical, code_set, quarantine/validators/storm config, unadmitted resident type) reroutes the whole table to the oracle with the expected coded reason; companion-absent reroutes; full-frame vs chunked-veto honored.
- Evidence: native operator + `derive_index_batch` call counts recorded as positive evidence.
- Throughput expectation: native wall <= oracle wall at the target tier; record median/variance on the reference host. No throughput claim ships as "fast" until measured (consolidation §3.1 discipline).
- Mutation targets: the routing/dispatch and admission predicates — `native_kernel_rejection`, `date_shift_config_rejection`, the relaxed diagnostic-obligation gate, the `CHUNKED_ROUTE_VETOED_STRATEGIES`/`ALLOWED_OPERATOR_IDS`/`_ADMITTED_RESIDENT_TYPES` reads, and the gather-bounds invariants — with the bar "zero non-equivalent value/type/error/arbitration survivors." A silent-skip, a mis-gather, or a dropped row error there is the costly defect.
- redact/truncate: if the fan-out is built, byte-identity at thread counts {1,2,4} over wide string columns with nulls, plus a small-batch non-regression check; if not built, record the re-baseline numbers that justify deferral.
- NER: the held suite in `docs/plans/2026-09-08-p5-ner-batch-helper.md` re-run green on the merge base.
