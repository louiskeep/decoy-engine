# D3a: validators on the bounded out-of-core route

## 0. Why + scope

A relationship-bearing (FK) pure-mask job that declares a `validators:` block is disqualified from the bounded routes today (`_pipeline_routing.py` `_sequential_eligible` -> `(False, "validators_present")` at :219), so it runs full-frame if the byte estimate fits and is rejected (`fk_full_frame_oom_risk_rejected`) when too big. This slice lets such a job run on the out-of-core (OOC) route, evaluating validators in bounded working memory, with the `ValidationReport`, fail-closed behavior, and `quality_metrics["validation"]` telemetry matching the full-frame oracle. It extends the same GAP6 win D3b extended (the bounded route is measured faster and lower-memory than the full-frame oracle for RAM-fitting FK jobs) to validator-bearing jobs.

Scope: the **out-of-core route only**, for jobs whose validators are ALL **per-cell** checks (validator allowlist, §2a) targeting **route-stable string-output columns** (column allowlist, §2b, inherited from D3b) in the **fail-closed (raise) mode only** (§4), on a **RAM-fitting** job (§3 fit-gate). Any cross-row / cross-table validator, any validated column that is an incoming-FK child key or carries an avoidable OOC-vs-full-frame output divergence, any job coupling a validator to **quarantine** row-removal, a SEQ-eligible-but-not-OOC-compatible job, or a too-big / unpriceable job keeps the job on full-frame (or its existing reject). No change to validator semantics, the `ValidationReport` contract, quarantine, the vault, orphan handling, or any masked output. D3b (vault) shipped; this is its direct sibling and the D3b plan was written to leave D3a next.

## 1. What exists to build on

- **Validators run full-frame ONLY today:** `execution/_pipeline_finalize.py::finalize_validators_and_quarantine` (`:374`) runs on the branch that did NOT take a routed early return; its docstring (`:1-21`) states these are POST-mask, full-frame-only concerns and that `run_sequential_route` / `run_out_of_core_route` own their own telemetry and never reach it. So OOC runs NO validators today. It calls `validators._registry.validate(outputs, config, sources=caller_sources)` on the whole `outputs: dict[str, pa.Table]`, then (on failure + quarantine trigger) `apply_quarantine` rebinds `outputs`.
- **Registry + report assembly (the exact contract to reproduce -- Codex HIGH-3):** `validators/_registry.py::validate` (`:75`, dispatch at `:113`). The report is deterministic: ONE finding per failing CONFIGURED column occurrence, carrying WHOLE-TABLE row positions and a total-count detail string. Finding order = validator-ENTRY order, then configured table/column order (NOT execution / FK-topological order). Repeated validator entries stay SEPARATE findings; only `validators_run` deduplicates validator NAMES. The report carries `elapsed_ms` (a measured clock value). Build MUST read `_registry.py` + `_catalog.py:60` and reproduce this exactly.
- **Per-cell check implementations:** `validators/_catalog.py` check-digit family (luhn/npi/iban/vin, `_check_digit_validator` does `col.to_pylist()` -- the full-column materialization the bounded path must avoid), `validators/_generic.py` `regex_match` (`:67`) + `column_in_set` (`:49`,`:131`). PARAMETER VALIDATION (invalid regex, missing allowed-values list) runs BEFORE table iteration and RAISES even with empty/zero-row output (Codex MED-4); `column_in_set` with `allow_null: false` FAILS every null (so all-null is NOT "no findings").
- **Validator classification (Codex MED-5 corrected):**
  - **Per-cell, row-local, verdict independent of other rows/tables:** `luhn`, `npi`, `iban`, `vin`, `regex_match`, `column_in_set`. Admit (subject to §2b output constraints).
  - **Declined to full-frame:** `fk_intact` (reads parent keys), `reconciliation_holds` + `parent_window_respected` (parent windows/aggregates), `leak_check` (whole-column ratios + minimum-row thresholds, NOT merely positional). `no_orphan_children` is ALSO row-local (`_fk_validators.py:235`: checks each child FK tuple for null using only that child row + relationship config; it does NOT materialize a parent-PK set) but is DEFERRED from D3a: it needs post-FK-rewrite evaluation and relationship-level aggregation, so folding it in safely is a follow-on, not rev-2 scope.
- **OOC drivers -- TWO mask sites (Codex "driver coverage" check):** `out_of_core/_runner.py run_fk_out_of_core:112` dispatches a table to EITHER `_runner._stream_table:303` OR `_stream_driver.stream_table`, selected exclusively per table by parent-key cardinality + budget. These are the ONLY two `mask_batch` call sites; hooking both covers masking PROVIDED validation runs once at the correct value boundary. (`_runner._stream_table` also serves sinks; it is not exclusively an in-memory driver.) **Incoming FK child-key columns are RAW at the mask step and REWRITTEN afterward** (`_runner.py:461`, `_stream_driver.py:407`): a validator reading a child-key column at the mask step would see the raw value, not the emitted masked value (Codex HIGH-1).
- **Persistence boundary (Codex "persistence" check):** validators must finalize INSIDE `run_fk_out_of_core`, BEFORE the sink publish at `_runner.py:290`; the runner's exception handler aborts an uncommitted transactional sink. Finalizing in the route wrapper AFTER the runner returns is too late. "Nothing persisted" means nothing PUBLISHED -- private staging occurs during execution and is aborted on raise.
- **Routing:** `_pipeline_routing.py` `_sequential_eligible:172` (disqualifier `:218-219`); `decide_execution_route:275`; a fitting validator job returns at the full-frame-fit branch BEFORE the bounded block, so admitting OOC validators needs a NEW branch there (where D3b added `vault_ooc_safe`, next to `vault_writer_requested` at :224). Fit signal: `resolve_full_frame_fits_estimate` (:117) via `_pipeline_routing_signals.byte_estimate_full_frame_fits` (:280). Note (Codex MED-6): the router can RECOVER full-frame through `probe_recovers_full_frame`; "False/None always rejects" is wrong -- both probe outcomes must be preserved and tested, and NEITHER admits D3a OOC without the required static full-frame fit.
- **Parity:** `tests/parity/test_out_of_core_fk_parity.py` (D0 baseline) + `tests/parity/SEMANTIC_DIFFERENCES.md`. D0 is NOT strict byte-identity with full-frame; it RECORDS OOC diffs (NaN-vs-null, int64-vs-float64, metadata). **The build MUST read SEMANTIC_DIFFERENCES.md** -- these diffs change validator verdicts (§2b) and are why validated columns need a route-stable-output allowlist, not just a validator-name allowlist.

## 2. Admission (two allowlists + declines)

A job is admitted to the OOC validator path only when BOTH hold for EVERY declared validator AND its target column(s), plus the quarantine + fit conditions (§3/§4):

### 2a. Validator allowlist (per-cell, row-local) -- EXACTLY:
`luhn`, `npi`, `iban`, `vin`, `regex_match`, `column_in_set`. Each evaluates a single cell independently of any other row or table, so batch-by-batch evaluation yields the same per-cell verdicts as the full-frame run. Any other validator (`fk_intact`, `no_orphan_children`, `leak_check`, `reconciliation_holds`, `parent_window_respected`) DECLINES the job to full-frame (unchanged reason `validators_present`).

### 2b. Validated-column output allowlist (route-stable string output -- Codex HIGH-2) -- the validated column must satisfy ALL of:
Verdict parity requires the validator to see the SAME value on OOC as on full-frame. The allowlisted validators stringify / compare values, so OOC-vs-full-frame output divergences (int64-vs-float64 "7" vs "7.0", NaN-vs-null, native-vs-Python NFC category selection) would flip verdicts. Admit a validated column only when:
- (a) its masked OUTPUT is a string produced by a **route-stable** strategy from D3b's reviewed-safe set -- `hash`, `truncate`, `redact` (string token), `passthrough` (string source), `categorical` with string resolved categories -- EXCEPT where the strategy carries the native-vs-Python NFC divergence on post-runtime Unicode (`hash`/`categorical`): for a VALIDATOR (unlike D3b's vault, whose key tracks its own output) that divergence can flip a normalization-sensitive regex/set verdict, so a `hash`/`categorical` validated column is admitted ONLY when its values are NFC-agnostic for the configured check, else DECLINE. D3b's accepted vault divergence does NOT automatically transfer to validators (Codex HIGH-2);
- (b) its SOURCE dtype is string/binary (not numeric/float/temporal/decimal, which float-widen or NaN-diverge);
- (c) the resolved masked output / replacement / categories are strings (a numeric `redact_with: 7` on a string source gives "7" vs "7.0" -> DECLINE);
- (d) it is NOT an incoming-FK child-key component of any edge (composite / overlapping / multi-parent / self-ref) -- a child-key column is raw at the mask step and rewritten at the join (Codex HIGH-1), so a validator targeting it DECLINES to full-frame. Parent-key columns ARE allowed (final at the mask step).

Any validated column failing 2b keeps the whole job on full-frame. The reviewed strategy/type combinations are fixed here BEFORE build; a combination without established verdict parity declines (Codex HIGH-2 remediation). Target: **no new SEMANTIC_DIFFERENCES entry.**

## 3. The change

- **New module `out_of_core/_validate_batch.py`:** holds ALL the validator plumbing (so the two large driver/routing files gain only thin call sites -- Codex LOW-7, `_runner.py` has 9 LOC headroom to 700). It provides:
  - `admitted_validators(config, relationships) -> list[spec] | None`: the admission computation (§2a+§2b); `None` (or empty) means not-admitted.
  - A per-table batch evaluator that runs each admitted validator's per-cell check over the masked batch's target columns, accumulating into a findings accumulator keyed by **(validator-entry ordinal, configured table, column occurrence)** with TABLE-RELATIVE batch offsets translated to whole-table row positions.
  - `assemble_report(accumulator, config) -> ValidationReport`: merges per-occurrence indices, regenerates the aggregate total-count detail strings, and EMITS findings in validator-entry-then-configured-column order, preserving duplicate validator entries and recording every configured validator in `validators_run` even when it found no rows (Codex MED-4). It MUST reproduce `_registry.validate`'s report exactly EXCEPT measured `elapsed_ms` (which tests must exclude from equality or control via a fixed clock -- Codex HIGH-3). Parameter validation (invalid regex / missing allowed-values) runs at admission/assembly time independent of batch presence, so an invalid-parameter job raises even with zero-row output (Codex MED-4).
- **Hook BOTH drivers, validate FINAL output:** call the batch evaluator at the mask step in `_runner._stream_table` AND `_stream_driver.stream_table`, after `mask_batch` and that driver's fail-closed checks. Because §2b(d) declines any validated child-key column, every ADMITTED validated column is final at the mask step (payload + parent keys are not rewritten), so mask-step evaluation sees the emitted value. Thread the accumulator + admitted-spec through `run_fk_out_of_core` and the route dispatch; keep each driver edit to a SINGLE call (plumbing lives in `_validate_batch.py`). Assemble + raise at run end INSIDE `run_fk_out_of_core` before the sink publish (`_runner.py:290`), so a failed validation publishes nothing.
- **Routing admission:** add a `validators_ooc_safe` signal (computed via `_validate_batch.admitted_validators`) = validators present AND every validator in 2a AND every validated column in 2b AND not quarantine-coupled (§4). In `decide_execution_route`, add an OOC-validator admission branch BEFORE the full-frame-fit return so a `validators_ooc_safe` job that is otherwise OOC-compatible (compat ok, not cyclic, not `fk_ooc_dtype_hazard`, all disqualifiers clear) AND **FITS the full-frame estimate (`full_frame_fits_estimate is True`, with `probe_recovers_full_frame` still routing to FULL-FRAME, never OOC)** routes to OUT-OF-CORE. Must NOT enable SEQ validators and must NOT admit a cross-row / child-key / quarantine job. Keep the `use_byte_estimate_routing=False` rollback. `_sequential_eligible` unchanged for its SEQ purpose.
- No change to `mask_batch`, the join, validator semantics, the `ValidationReport` contract, quarantine, or masked output.

## 4. Quarantine boundary + fit-gate (bounded working memory, honest) + persistence

- **Quarantine on OOC is OUT OF SCOPE (Codex confirmed correct).** `finalize_validators_and_quarantine` couples a failed validator to quarantine row-removal (`apply_quarantine`); the OOC route has NO row-error / quarantine channel (`out_of_core/_compat.py` excludes row-error strategies). A job with `quarantine.enabled` AND `"validation_fail"` in its triggers DECLINES to full-frame. Only fail-closed (raise, no quarantine) is admissible on OOC. Never retro-filter a streamed sink.
- **Fit-gate = conservative restriction, NOT a findings-memory bound (Codex MED-6).** `byte_estimate_full_frame_fits` receives TABLE sizes, not validator declarations; repeated validators or many validated columns grow retained failing-row indices without changing the estimate, and a single finding can hold millions of indices (plus report-serialization allocations). The honest statement: OOC validator memory = per-batch working storage + retained failing indices across all validator occurrences. D3a RETAINS the full-frame-fit gate (a non-fitting / unpriceable job is NOT admitted and rejects as today) because it keeps the job within a RAM envelope, but the plan does NOT claim the gate proves bounded findings residency. A bounded / spillable findings representation is a follow-on if a hard budget is later promised. Too-big validator jobs still reject (`fk_full_frame_oom_risk_rejected`).
- **Fail-closed persists nothing PUBLISHED.** Assemble + raise `ValidatorFailedError(report)` inside `run_fk_out_of_core` before the publish at `_runner.py:290`; the runner's exception handler aborts the uncommitted transactional sink. Private staging during execution is fine; nothing is PUBLISHED on a raise. Stamp exactly `quality_metrics["validation"] = {"validators": dataclasses.asdict(report)}` on success (Codex HIGH-3).
- **Validator parity + masked output:** for an admitted job the OOC `ValidationReport` equals the oracle's (findings content + order, `passed`, `validators_run`, `quality_metrics["validation"]`), excluding `elapsed_ms`; fail-closed raises `ValidatorFailedError(report)` identically; nulls handled identically (incl. `column_in_set` `allow_null: false` failing nulls). Masked outputs unchanged vs the existing OOC D0 baseline (strict comparator); the hook must not perturb masking/order (validation never mutates). No new SEMANTIC_DIFFERENCES entry.

## 5. Acceptance matrix

- **T1 admission + declines:** a fitting OOC-compatible pure-mask FK job whose validators are ALL 2a + target only 2b-safe columns routes `("out_of_core", ...)`; each of these stays full-frame/reject with the unchanged reason: (a) a cross-row/cross-table validator (`fk_intact`/`no_orphan_children`/`leak_check`/`reconciliation_holds`/`parent_window_respected`); (b) a validated column that is an incoming-FK child-key (incl. composite / overlapping / multi-parent / self-ref); (c) a validated numeric/float/temporal/decimal source or a numeric resolved output/replacement/categories; (d) a quarantine-coupled (`enabled` + `validation_fail`) job; (e) a SEQ-eligible-but-not-OOC-compatible job; (f) a too-big / unpriceable job; (g) a MIXED job (one allowlisted + one declined validator) -> declines as a whole. `use_byte_estimate_routing=False` rolls back; `probe_recovers_full_frame` routes full-frame, never OOC. Mutants killed: dropping 2a, dropping 2b-type, dropping child-key check, dropping quarantine decline, admitting SEQ, dropping the fit-gate.
- **T2 report parity:** admitted job on OOC vs full-frame yields an IDENTICAL `ValidationReport` (findings content + ORDER, `passed`, `validators_run`, `quality_metrics["validation"]`), excluding `elapsed_ms` (fixed/removed in the comparison). Cover each allowlisted validator; multiple validators incl. DUPLICATE entries with different parameters (kept separate); multiple columns/tables with CONFIG order differing from FK-topological order (findings emit in config order); a parent-key column and a payload column; nulls skipped; `column_in_set allow_null:false` failing nulls; all-null column (findings per the oracle, NOT "none"); zero-row table + absent target column (configured validator still recorded in `validators_run`); invalid regex / missing allowed-values list raising at admission even on empty output; failures SPANNING batches (indices merged to whole-table positions, aggregate detail regenerated).
- **T3 both drivers evaluate (mixed-driver multi-table):** a multi-table job that forces the reorder/sink driver on one table and the in-memory driver on another; both evaluate; the assembled report is identical to the oracle. A mutant hooking only one driver is killed. Witness which driver ran per table.
- **T4 fail-closed publishes nothing:** a validator failure on OOC (and separately a late masking failure) raises `ValidatorFailedError` and PUBLISHES nothing even after EARLIER tables have privately staged output -- assert `commit == 0` and `abort == 1` on the transactional sink (not file-absence alone). A mutant that publishes after a failed validation is killed.
- **T5 masked output unchanged:** admitted job's masked outputs == the existing OOC D0 baseline (strict comparator); the hook did not perturb masking/order.
- **T6 bounded working memory (narrowed, honest):** assert per-batch evaluation + NO full-column `to_pylist` on the OOC path; findings accumulate as (ordinal,column)-keyed index lists (O(failing rows), bounded by the RAM-fit gate, NOT a fixed budget). No 10M run.
- **T7 verdict parity under OOC type/normalization divergence:** numeric replacement / numeric categorical categories / nullable-numeric payload / NaN-bearing / NFC-normalization-sensitive outputs each DECLINE (full-frame), proving 2b excludes verdict-flipping cases; an admitted string job's verdicts are identical OOC vs full-frame. No new SEMANTIC_DIFFERENCES entry.

## 6. Failure modes (reproduce, do not smooth)

- A validator reading a raw child-key value at the mask step instead of the emitted masked value -> T1(b)/§2b(d) decline.
- A verdict flipped by int-vs-float / NaN-vs-null / NFC divergence silently admitted -> T7.
- The OOC report diverging from the oracle (missing/extra/mis-ordered findings, duplicate entries merged, wrong whole-table indices, wrong `validators_run`, missing config-order) -> T2.
- A cross-row/cross-table or quarantine-coupled validator admitted -> T1.
- Only one of the two drivers evaluating -> T3.
- A sink PUBLISHED after a failed validation -> T4.
- The hook mutating masked output/order -> T5.
- Parameter validation skipped because output was empty -> T2.
