## 1. FRAME

### Problem

The engine already has two ML detectors, and neither reaches a user through a pipeline.

- The lgbm column classifier (`lgbm-v1`, version `0.1.0`) is merged and off the run path: nothing in
  `src/` calls `classify_fields` outside its own package (`profiling/model_pack/__init__.py:6`,
  `profiling/model_pack/classify.py:102`). The profiler runs regex detectors only
  (`profiling/profiler.py:405`), and the detection trail hard-codes `ml=False`
  (`detection/types.py:78`, "ML detection phases ... will append `ml=True` rows").
- spaCy NER (`detection/ner.py`, default model `en_core_web_sm`, `ner.py:42`) is used only inside the
  `text_redact` and `text_mask` strategies. The post-scan residual-PII check runs regex detectors only
  (`verification/postmask/residual_pii.py:172`).
- There is no config to pick detectors. `PostScanConfig` has one field, `integrity`
  (`config/_post_scan.py:17`); there is no pre-scan section at all.
- The classifier's packages sit in the `ml` extra (`pyproject.toml:305`), so a default install cannot
  run it. The `ner` extra lists only spaCy (`pyproject.toml:214`), and spaCy no longer imports on a
  fresh install: Typer stopped depending on Click and vendors it, but spaCy still imports Click
  (spaCy v3.8.15 release notes). That is NER-CLICK, which this plan absorbs. No CI leg installs
  `ner` at all; only `ml-gate` installs `ml` (`.github/workflows/ci.yml:176`).
- No log line names a detector or a model version; the only model log lines name the pack path
  label (`profiling/model_pack/loader.py:215`).
- `decoy run` never saves the post-scan report: the engine keeps it in memory at
  `execution_result.quality_metrics["post_scan_integrity"]` (`execution/_pipeline_finalize.py:503`),
  and the CLI does not read it. IW's findings review needs that report on disk.

### Guarantee (what V1 promises)

1. **Regex is the default; ML is opt-in per pipeline, per phase.** A pipeline with no `pre_scan` and
   no `post_scan.detectors` runs exactly the regex detectors it runs today. `pre_scan.detectors` and
   `post_scan.detectors` are chosen separately from `regex`, `classifier`, `ner`; `regex` is always in
   the list (V1).
2. **The classifier ships in every install.** scikit-learn and lightgbm become base dependencies of
   the engine; the `lgbm-v1` pack is already in the wheel (`pyproject.toml:354`). Where the platform
   cannot load it (macOS without the OpenMP runtime, `DECOY_ML_DISABLED=1`), asking for the
   classifier fails before any row is read, naming the cause; it never silently falls back to regex.
3. **spaCy and its model are opt-in.** `decoy models install ner` installs spaCy and the model from
   the package index, or from a copied wheel file or a directory of wheels with no network
   (`--from`). `decoy setup` offers the same step. Nothing downloads anything at scan or run time.
4. **ML only suggests.** A classifier or NER suggestion never sets a column's strategy in the
   starter config (IW 4.6, `live` is false for them); the user confirms it in `decoy init`.
5. **NER post-scan findings warn by default.** `post_scan.ner_findings: fail` is the opt-in: an NER
   finding at or over the warning rate is then `fail`, `decoy run` exits 4 and publishes no output.
   Classifier post-scan findings are never above `warning`.
6. **Logs and records name what ran.** Every scan and run logs which detectors ran, on how many
   tables and columns, and each model's id and version. The scan record, the integrity report and
   the run's `--json` carry the same facts. No log, record or error contains a cell value or text a
   model read.
7. **Dismissals are exact.** A `post_scan.dismissed` entry lowers only the warning-severity finding
   whose table, column, detector, source, model id, model version and configured strategy all match
   (IW 4.6, dismissal rule). It never lowers a `fail` or a source-identity finding.

### Non-goals (V1)

- Other NER models or languages beyond a validated spaCy package name; transformer models.
- Training or retraining the classifier, or a user-supplied classifier pack on the run path (the
  loader's untrusted-pack path stays platform-only).
- Making regex post-scan `fail` findings block a run (today report-only, `_pipeline_finalize.py:481`).
  Only the new `ner_findings: fail` opt-in blocks. Recorded as follow-up SCAN-ML-2.
- Resource settings (memory, threads). RUN-STREAM (63a) owns those sections of `decoy setup`.
- A settings file. SCAN-ML needs no persisted user setting: detectors are per pipeline.

### Failure modes

| Case | Behavior |
|---|---|
| `pre_scan.detectors` or `post_scan.detectors` without `regex`, or with a duplicate | Config validation fails (`config.detectors_invalid`, naming the field path). Exit 1 from `decoy validate`, `ci check`, `run`, `scan --config`. |
| `post_scan.detectors` other than `[regex]`, `ner_findings: fail` or a non-empty `dismissed` while `post_scan.integrity` is false | Config validation fails (`config.post_scan_inactive`, naming the field). Silently ignoring a chosen detector would hide that no check ran. |
| `ner_model` not a plain package name (a path, a URL, upper case) | Config validation fails (`config.ner_model_invalid`); the value is not echoed. `spacy.load` also loads directories, so a path would load arbitrary files. |
| Classifier asked for and the pack cannot load (`DECOY_ML_DISABLED=1`, lightgbm missing, `libomp` missing on macOS, hash mismatch) | Refused before any row is read (`provider.classifier_unavailable`, naming the cause class: disabled, import, pack). Gate compile layer: exit 1. `decoy scan`: exit 1. |
| NER asked for and spaCy or the model is missing | Existing codes `provider.ner_spacy_not_installed` and `provider.ner_model_not_installed` (`reasons/provider/_part1.py:49`), raised by the gate's compile layer as `plan/_compile.py:195` does for `text_redact`; exit 1 with the hint `decoy models install ner`. |
| Installed model was built for another spaCy minor | Refused (`provider.ner_model_incompatible`, naming model, model version and spaCy version); exit 1 with the install hint. |
| The model version changes between compile and post-scan | The post-scan finding records the version it ran with; dismissals keyed to the old version stop applying (Guarantee 7). The mask path keeps its own fail-closed check (`enforce_ner_model_version`, `_ner_config.py:62`). |
| A model raises while classifying a table | Pre-scan: exit 3, naming the table and the exception class only. Post-scan: the existing per-check wrapper turns it into an `error` finding (`verification/postmask/runner.py:91`); the run continues as today. |
| `decoy models install ner` with no network | Exit 3 (`models.install_failed`, naming pip's exit code), with the hint to use `--from`. |
| `--from` names something that is not a `.whl` file or a directory holding only `.whl` files | Exit 1 (`models.source_invalid`). Source distributions run code at install time; wheels do not. |
| `ner_findings: fail` and an NER finding fails | `decoy run` exits 4; no target is written; the integrity report is still written so the user can review it (IW W3.2). |
| A dismissal no longer matches (strategy or model version changed) | The finding reports at its own severity; the run log counts stale dismissals by table. |
| `decoy run` cannot write the integrity report | Exit 3 (`run.integrity_write_failed`), after the outputs were written; the message names the path. |

## 2. Established solutions

Surveyed before designing; the chosen pattern is cited in each module docstring.

- **Microsoft Presidio** (analyzer). Detectors are "recognizers" of three kinds (pattern, NER, ML),
  each tagged with its source and run through one registry; the NLP engine is configured by name
  (`nlp_engine_name: spacy`, `models: [{lang_code, model_name}]`) and the model must be installed in
  the same environment. Offline hosts install the model wheel from a local path with pip
  (`pip install .../en_core_web_lg-3.8.0-py3-none-any.whl`, Presidio Fabric sample). Adopted: one
  detector registry with a `source` per finding, models named by package name, offline install from
  a wheel. Not adopted: Presidio itself (a second regex catalog beside STORM's).
- **spaCy.** `python -m spacy download <model>` resolves the model version compatible with the
  installed spaCy and pip-installs it; models are pip packages whose `meta.json` carries a
  `spacy_version` range. The engine's probes already use this (`ner.py:72` to `ner.py:96`). Adopted:
  the online path calls spaCy's own download; the offline path is pip with `--no-index`; the
  compatibility check reads the installed model's `spacy_version` range.
- **Hugging Face Hub offline mode** (`HF_HUB_OFFLINE=1`, a local cache). Considered for a Decoy model
  cache; rejected for V1 because the engine's version pinning (`ner_model_version` stamped on the plan,
  `plan/_types.py:115`) reads package metadata, and a second store would need a second probe.
- **Google Cloud DLP / AWS Macie.** Findings carry an info type, a likelihood band and the detector
  that produced them, never the value. Adopted: a finding carries source, model id and version and a
  band or rate, never a value.
- **Model loading failure policy.** The pack loader already has a strict `load()` and a lenient
  `load_with_fallback()` that logs and returns `None` (`loader.py:172`, `loader.py:205`). A pipeline
  that asked for the classifier must not get regex-only results silently, so the run path uses the
  strict load (same rule as fail-closed NER, `ner.py:99`).
- **LightGBM packaging.** macOS wheels are built with Apple Clang and need a separate OpenMP runtime
  (`brew install libomp`, LightGBM python-package README). Adopted: a status probe that names this
  cause, and a macOS lane in the bundling part; owner question Q2 covers whether a missing `libomp`
  is acceptable for "every install".

## 3. Design notes

- **One detector registry, three sources.** `regex`, `classifier`, `ner` are values of one
  `DetectorSource` literal. Every suggestion and every finding carries `source` and, for models, a
  `ModelRef(id, version)` (IW 4.6). Label to detector id goes through one table (4.4).
- **Strict availability, one probe.** `ModelStatus` answers "can this model run here, and which
  version" for both models. The gate, `decoy scan`, `decoy models list`, `decoy setup` and IW's
  detector step all read it; none probes on its own.
- **No hidden downloads.** Model installs happen only in `decoy models install` and `decoy setup`.
- **Pre-scan reuses SCAN-MULTI.** The classifier and NER passes run inside `scan_sources` on the same
  bounded sample frame `profile_columns` reads (SCAN-MULTI S1a), so no second read of the source.
- **Post-scan reuses the residual-PII check.** The model passes produce `ResidualPIIFinding`s through
  the same strategy-group severity logic (`residual_pii.py:56` to `residual_pii.py:123`); a source
  cap and the `ner_findings` switch are the only differences.
- **The CLI writes the report.** The engine stays caller-agnostic; `decoy run` writes the in-memory
  report it already gets and stamps `config_sha256` from the YAML bytes it read.

## 4. Behavior

### 4.1 Config fields (engine part M1)

```yaml
pre_scan:                         # new section; omitted = regex only
  detectors: [regex, classifier, ner]
  ner_model: en_core_web_sm       # optional; default en_core_web_sm
post_scan:
  integrity: true                 # existing (config/_post_scan.py:20)
  detectors: [regex, ner]         # new; default [regex]
  ner_model: en_core_web_sm       # new; optional
  ner_findings: warn              # new; warn (default) | fail
  dismissed:                      # new; default []; shape owned by IW 4.6
    - {table: customers, column: notes, detector_id: person_name, source: ner,
       model_id: en_core_web_sm, model_version: '3.8.0', strategy: text_redact}
```

```python
DetectorSource = Literal["regex", "classifier", "ner"]

class PreScanConfig(BaseModel):         # config/_pre_scan.py
    model_config = ConfigDict(extra="forbid", hide_input_in_errors=True)
    detectors: tuple[DetectorSource, ...] = ("regex",)
    ner_model: str = DEFAULT_NER_MODEL

class Dismissal(BaseModel):             # config/_post_scan.py
    model_config = ConfigDict(extra="forbid", hide_input_in_errors=True, frozen=True)
    table: str; column: str; detector_id: str; source: DetectorSource
    model_id: str | None = None; model_version: str | None = None; strategy: str

class PostScanConfig(BaseModel):        # config/_post_scan.py, extended
    integrity: bool = False
    detectors: tuple[DetectorSource, ...] = ("regex",)
    ner_model: str = DEFAULT_NER_MODEL
    ner_findings: Literal["warn", "fail"] = "warn"
    dismissed: tuple[Dismissal, ...] = ()
```

- Validators: `regex` present and no duplicates (`config.detectors_invalid`); `ner_model` matches
  `^[a-z][a-z0-9_]{1,63}$` (`config.ner_model_invalid`); a `Dismissal` has `model_id` and
  `model_version` exactly when `source` is not `regex` (`config.dismissal_invalid`); the
  `post_scan_inactive` rule from section 1. Dumps keep the list order `regex`, `classifier`, `ner`.
- `PipelineConfig.pre_scan: PreScanConfig = Field(default_factory=PreScanConfig)` beside
  `post_scan` (`config/_pipeline.py:85`).
- `post_scan_integrity_requested` (`_post_scan.py:23`) is unchanged; the native gate and the chunked
  sink keep reading it (`_chunked_output_sink.py:124`).
- The gate's compile layer checks model availability for every model named in `pre_scan` or
  `post_scan`, beside the existing `check_text_redact_ner_available` call (`plan/_compile.py:195`).
  `pre_scan` is checked only by commands that scan (`decoy scan --config`, `decoy init`); `decoy run`
  checks `post_scan` only.

### 4.2 Model status and loading (engine part M1)

```python
@dataclass(frozen=True)
class ModelRef:                          # detection/types.py; IW 4.6 uses this one
    id: str
    version: str

@dataclass(frozen=True)
class ModelStatus:                       # detection/_model_status.py
    source: Literal["classifier", "ner"]
    model_id: str                        # "lgbm-v1" or the spaCy package name
    available: bool
    version: str | None                  # installed version when available
    runtime_version: str | None          # spaCy or lightgbm version
    reason: str | None                   # reason identity when not available

def classifier_status() -> ModelStatus
def ner_status(model: str = DEFAULT_NER_MODEL) -> ModelStatus
def load_detectors(sources: Sequence[DetectorSource], *, ner_model: str,
                   file_access: FileAccess | None = None) -> DetectorSet
```

- `classifier_status` loads the default pack through `ModelPackLoader(...).load()` once per process
  and caches the result; the reason is `provider.classifier_unavailable` with a cause class
  (`disabled`, `import`, `pack`) in a fixed field, never the exception text.
- `ner_status` uses `spacy_installed`, `model_installed`, `installed_model_version`
  (`ner.py:72` to `ner.py:96`) and checks the model's `spacy_version` range against the installed
  spaCy (`provider.ner_model_incompatible`). It does not load the pipeline.
- `load_detectors` raises `ModelUnavailableError(DecoyError)` with the reason identity when a
  requested model is not available; it never returns a partial set. The classifier uses the strict
  load path, never `load_with_fallback`.
- `ModelRef` lives in `detection/types.py` (one definition). IW E1 imports it from there; whichever
  of M1 and IW E1 merges first adds it, with the fields above.

### 4.3 Pre-scan (engine part M3)

- `scan_sources(..., pre_scan: PreScanConfig | None = None)` (SCAN-MULTI S1a's signature gains one
  keyword). `None` means regex only. `load_detectors` runs once before the first table.
- Per table, on the sample frame `profile_columns` read:
  - classifier: `classify_fields(frame)` through the loaded pack. A column whose label is not `None`
    and whose band is `high` or `review` (`profiling/eval/bands.py:69`) yields one classifier hit; a
    `low` band yields none and one count in the log.
  - NER: for each string column, the first `_NER_SCAN_CELLS = 2_000` non-null cells of the sample go
    through `iter_ner_spans_batch` (`ner.py:190`); for each detector id in `NER_ENTITY_MAP`
    (`ner.py:54`) the hit rate is the share of scanned cells with at least one span of that id. A
    rate at or over `_NER_MIN_RATE = 0.05` (the residual-PII warning rate, so one number means
    "enough to look at" in both phases) yields one NER hit.
- `TableScan` per field gains `model_hits: tuple[ModelHit, ...]`, where `ModelHit` is
  `{source, detector_id, model: ModelRef, band: "high"|"review"|None, rate_bucket: str|None}`. Rates
  are bucketed (`<10%`, `10-50%`, `>=50%`), as `confidence_bucket` is for regex; no raw text, span or
  cell count per value. `ScanSet` gains `detectors: tuple[DetectorRun, ...]` (`{source, model}`). Both
  are additive fields of `scan-set/v1` (SCAN-MULTI's tag, frozen when S1a merges; if S1a has merged,
  `ScanSetCore` gains them as optional fields and the read variant ignores unknown keys already).
- `starter_config` turns each model hit into one `ColumnSuggestion` (IW 4.6) with `source`,
  `detector_id`, `model`, `band`, `live=False` and an `entry`:
  - classifier: `column_entry(default strategy of detector_id)` from the detector descriptor
    registry, the same entry a regex suggestion of that id gets.
  - NER: `column_entry("text_redact", column, options={"ner": {"model": <ner_model>, "entities":
    [detector_id]}})`. NER finds names inside text, so the entry redacts the spans, not the column.
    The option shape is the existing one (`execution/_strategies/_ner_config.py:36`).
- A label with no row in the mapping (4.4) yields no suggestion and one count in the scan log.

|---|---|---|---|
| classifier | `ssn`, `pan`, `iban`, `email`, `icd10`, `iso_date`, `npi`, `mrn`, `health_plan_id`, `cvv` | the same id (each exists in `DEFAULT_STRATEGY_BY_DETECTOR`, `profiling/recommendations.py:32`) | the descriptor default |
| classifier | `none` | no suggestion | |
| ner | `PERSON`, `PER` | `person_name` (`ner.py:54`) | `text_redact` with `ner` |
| ner | `GPE`, `LOC`, `FAC` | `location` | `text_redact` with `ner` |

- The classifier's labels come from the pickled model (`classify.py:203`), not a constant. M3 adds

  `set(clf.classes_) == CLASSIFIER_LABELS | {"none"}`, so a new pack with a new label fails a test
  instead of silently dropping suggestions.
- NER labels keep `NER_ENTITY_MAP` as their one table; the registry reads it.

### 4.5 Post-scan (engine part M4)

- `run_post_mask(source_frames, output_frames, *, config, detectors: DetectorSet | None = None)`
  (`verification/postmask/runner.py:38`). `compute_post_scan_integrity`
  (`_pipeline_finalize.py:470`) builds the set with `load_detectors(post_scan.detectors)`. `None`
  keeps today's regex-only behavior for platform callers.
- Classifier pass: `classify_fields` on each output frame; a column labelled with band `high` or
  `review` becomes a finding with `source="classifier"`, `match_rate=None`, and the severity the regex
  path's strategy-group logic gives for that detector (`_classify`, `residual_pii.py:344`), capped at
  `warning`.
- NER pass: the same cell sample and rate as the pre-scan (4.3) on each string output column. A rate
  under `_LEAK_WARN_RATE` (`residual_pii.py:122`) is `info`; at or over it is `warning`, or `fail`
  when `ner_findings: fail`. A column whose configured strategy produces PII-like values by design
  (`_PRODUCES_PII_LIKE_VALUES`, `residual_pii.py:56`, for example `faker` with a name provider) is
  `info` in both modes: names there are fake by design.
- Source identity: the existing escalation (`_escalate`, `residual_pii.py:254`) applies to model
  findings too; it is detector-independent and never lowered by a dismissal.
- Dismissals apply last: a `warning` finding whose fields equal a `Dismissal` and whose column's
  configured strategy equals the dismissal's `strategy` becomes `info` with `dismissed: true`.
  Dismissals that matched nothing are counted per table in the log (`post_scan.dismissed_stale`).
- `ResidualPIIFinding` (`types.py:24`) gains `source: DetectorSource = "regex"`,
  `model_id: str | None = None`, `model_version: str | None = None`, `band: str | None = None`,
  `dismissed: bool = False`; `match_rate` widens to `float | None` (`None` only for the classifier).
  `PostMaskReport` gains `detectors` (the runs), `tables_checked: tuple[str, ...]` (every output
  table the residual-PII check read, clean tables included, so a reader never infers coverage from
  finding rows; IW 4.5 needs it) and `config_sha256: str | None = None`, set by the caller. The tag stays `post-scan-integrity/v2`: every field is additive, the platform stores the
  dict as opaque JSON (`api/storm/post_mask_service.py`, `payload_json=json.dumps(report)`), and the
  CLI only dumps it (`src/decoy/cli/report.py:2093`).

### 4.6 Install and setup (CLI part C1)

```text
decoy models list [--json]
decoy models install ner [--model NAME] [--from PATH] [--yes] [--json]
decoy setup [--ner install|skip] [--ner-from PATH] [--yes] [--json]
```

- `models list` prints one row per model from `classifier_status()` and `ner_status(model)`:
  source, model id, available, version, runtime version, and the reason code when not available.
- `models install ner`:
  - online: `sys.executable -m pip install "decoy-engine[ner]==<pinned engine version>"` (spaCy and
    Click), then `sys.executable -m spacy download <model>`; both as argument lists, never a shell.
  - offline: `--from FILE.whl` or `--from DIR` (a wheelhouse, only `.whl` files):
    `sys.executable -m pip install --no-index --only-binary :all: --find-links DIR spacy click <model>`
    (a file is installed by path with the same flags).
  - after either: `ner_status(model)` must report available and compatible, else exit 3
    (`models.install_failed`, naming the status reason).
  - before installing, it prints what it will install and where (the interpreter path) and asks;
    `--yes` or a non-TTY skips the question only when `--yes` is given (no `--yes` off a TTY: exit 1).
- `decoy setup` is a command with an ordered list of sections, each a small object with `name`,
  `status()`, `run(prompter, answers)`. SCAN-ML adds the `models` section (calls the same install
  code). RUN-STREAM (63a) adds its resources section to the same list. The section list lives in
  `cli/setup/_sections.py`, and the prompts use IW's `Prompter` when IW W1.1 has merged, else
  `typer.confirm` behind a two-method shim that W1.1 replaces.
- The managed runtime (`~/.decoy/versions/<v>/`, `distribution/layout.py:29`) is a separate
  environment per version; `decoy upgrade` does not carry NER over. `models list` says "not
  installed" after an upgrade, and `decoy doctor` gains the two model rows.

### 4.7 Scan, run and report surfaces (CLI parts C2a, C2b)

- `decoy scan --config FILE` uses the config's `pre_scan`; without a config, `--detectors
  regex,classifier,ner` and `--ner-model NAME` set it (C2b, after SCAN-MULTI S1c). The human card
  gains one line, `Detectors: regex; classifier lgbm-v1 0.1.0; ner en_core_web_sm 3.8.0`, and
  `--json` gains `detectors: [{source, model_id, model_version}]`. The note "STORM pattern matching"
  (`scan.py:536`) becomes "pattern matching" plus the model list.
- `decoy run` (C2a), when `post_scan.integrity` is true:
  - writes the report the engine returns to `--integrity-out PATH`, default
    `<config dir>/<config stem>.post-scan.json`, through `_atomic.write_local_target`, after setting
    `config_sha256` to the SHA-256 of the YAML bytes the run read;
  - prints `Post-scan: regex; ner en_core_web_sm 3.8.0. 2 warnings, 0 fail. Report: <path>`;
  - adds `post_scan: {detectors, counts, report}` to `--json` (paths and counts only);
  - with `ner_findings: fail` and a `fail` NER finding: skips `_write_mask_outputs` (`run.py:906`),
    writes the report, exits 4.
- `decoy report integrity --config FILE` (C2a) stamps the same `config_sha256` and passes the

### 5.3 FK shapes

The model passes never change a key column's entry. A suggestion on a key column of a declared
relationship stays a suggestion; SCAN-MULTI forces `hash` with the relationship namespace there, and

other; a dismissal on it changes no config entry. Shapes (from IW 5.3), each covered by AT-M3e:

- a unary key (`parent.columns: [id]`, one child);
- a composite key (`parent.columns: [region, id]`);
- one parent with two children;

## 9. Owner questions (each answerable alone; recommended answer first)

- **Q1. Should `ner_findings: fail` withhold the masked output?** Recommended: yes. The run exits 4,
  writes the integrity report and writes no target, so data with names the model still finds does
  not leave the box. The alternative writes the outputs and only exits 4, which matches how regex
  `fail` findings are report-only today.
- **Q2. Is the classifier "in every install" when macOS needs `brew install libomp`?** LightGBM's
  macOS wheels need the OpenMP runtime. Recommended: yes for V1; `decoy models list`, `decoy doctor`
  and the refusal name `brew install libomp`, and the CLI installer docs list it. The alternative is
  converting the model to a dependency-free evaluator, which is a model change (follow-up SCAN-ML-3).
- **Q3. Must `regex` always be on in V1?** Recommended: yes. Dropping regex would make the classifier
  the only detector for structured types it does not cover (phone, address, IP). The alternative
  allows any non-empty set.

- Write the generated tests first (canary corpora, hostile config and `--from` corpora, the install
  matrix) and record them red, as assertion failures against stubs.
- Before pushing, attack your own diff: mutate each new mechanism once (section 7 names them) and
  show its test goes red, then revert. Never commit with a mutation applied.
- Run baselines with `uv.lock` in the same environment as the branch (`scripts/dev/gates.sh

- Never widen a threshold, skip a test, raise a size pin or reduce a budget to make a part pass. The

- If a new defect of a class already in the catalog appears, stop and report it. Do not patch a third
  time.
- Commit messages: Conventional Commits, at most 72 characters, final line `cam`, no em-dashes.

## 15. Pre-mortem

Assume it shipped and failed. The likely causes, and what in this plan prevents each:

- **The base install breaks on a platform because of lightgbm.** M2's three lanes (AT-M2a) and a
  status probe that never raises; owner question Q2.
- **spaCy breaks again on a dependency change.** The `ner-gate` leg installs `ner` alone on every PR.
- **NER makes post-scan too slow on large outputs.** A fixed cell sample per column
  (`_NER_SCAN_CELLS`), and post-scan already keeps outputs resident (`_chunked_output_sink.py:124`);
  RUN-STREAM is told that integrity forces the resident route.
- **A suggestion masks a column without the user's say.** `live=False` for every model suggestion
  (AT-M3b, AT-M3e) and IW's confirm step.
- **A log or report carries a name the model read.** Counts and buckets only, canary corpora on both
  passes (AT-M3c, AT-M4d).
- **Dismissals hide new leaks.** Exact match including model version and strategy (AT-M4c).
- **Users upgrade Decoy and NER disappears.** `models list` and `doctor` say so; the gate refusal
  names `decoy models install ner`.
- **IW and SCAN-ML disagree on a shape.** Every shared shape is defined once in IW 4.6 or in 4.1 and
  4.2 here, and each plan cites the other's section.
