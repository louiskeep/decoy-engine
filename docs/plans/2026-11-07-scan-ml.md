## 1. FRAME

### Problem

The engine already has two ML detectors, and neither reaches a user through a pipeline.

- The lgbm column classifier (`lgbm-v1`, version `0.1.0`) is merged and off the run path: nothing in
  `src/` calls `classify_fields` outside its own package (`profiling/model_pack/__init__.py:6`,
  `profiling/model_pack/classify.py:102`). The profiler runs regex detectors only
  (`profiling/profiler.py:405`), and the detection trail hard-codes `ml=False`
  (`detection/types.py:87`, "ML detection phases ... will append `ml=True` rows").
- spaCy NER (`detection/ner.py`, default model `en_core_web_sm`, `ner.py:42`) is used only inside the
  `text_redact` and `text_mask` strategies. The post-scan residual-PII check runs regex detectors only
  (`verification/postmask/residual_pii.py:172`).
- There is no config to pick detectors. `PostScanConfig` has one field, `integrity`
  (`config/_post_scan.py:17`); there is no pre-scan section at all.
- The classifier's packages sit in the `ml` extra (`pyproject.toml:305`), so a default install cannot
  run it. The `ner` extra lists only spaCy (`pyproject.toml:214`), and spaCy no longer imports on a
  fresh install: Typer stopped depending on Click and vendors it, but spaCy still imports Click
  (spaCy v3.8.15 release notes). That is NER-CLICK, which this plan absorbs. No CI leg installs
  `ner` at all; only `ml-gate` installs `ml` (`.github/workflows/ci.yml:176`).
- No log line names a detector or a model version; the only model log lines name the pack path
  label (`profiling/model_pack/loader.py:215`).
- `decoy run` never saves the post-scan report: the engine keeps it in memory at
  `execution_result.quality_metrics["post_scan_integrity"]` (`execution/_pipeline_finalize.py:503`),
  and the CLI does not read it. IW's findings review needs that report on disk.

### Guarantee (what V1 promises)

1. **Regex is the default; ML is opt-in per pipeline, per phase.** A pipeline with no `pre_scan` and
   no `post_scan.detectors` runs exactly the regex detectors it runs today. `pre_scan.detectors` and
   `post_scan.detectors` are chosen separately from `regex`, `classifier`, `ner`; `regex` is always in
   the list (V1).
2. **The classifier ships in every install.** scikit-learn and lightgbm become base dependencies of
   the engine; the `lgbm-v1` pack is already in the wheel (`pyproject.toml:354`). Where the platform
   cannot load it (macOS without the OpenMP runtime, `DECOY_ML_DISABLED=1`), asking for the
   classifier fails before masking starts (before any row is read on the CLI), naming the cause; it never silently falls back to regex
   (inference runs on the strictly loaded pack, 4.2).
3. **spaCy and its model are opt-in.** `decoy models install ner` installs spaCy and the model from
   the package index, or from a copied wheel file or a directory of wheels with no network
   (`--from`). `decoy setup` offers the same step. Nothing downloads anything at scan or run time
   (AT-M3f runs scans and runs with sockets blocked). Installing NER adds packages to the
   environment, which takes it off a certified DP row (owner decided 2026-11-07, Q4: no shared
   environment in V1).
4. **ML only suggests.** A classifier or NER suggestion never sets a column's strategy in the
   starter config (IW 4.6, `live` is false for them); the user confirms it in `decoy init`.
5. **NER post-scan findings warn by default.** `post_scan.ner_findings: fail` is the opt-in: an NER
   finding that would be `warning` is then `fail` (severity table, 4.5), and so is an `error` from
   the NER pass. The engine run then raises `PostScanBlockedError` before returning outputs, so no
   caller (CLI `decoy run`, the Python API `decoy.mask()`, the platform runner) can publish them;
   `decoy run` exits 4 and writes the report. Every engine entry point that does not run the
   post-scan (sequential, chunked, native chunked, out-of-core) refuses a config that asks for model
   post-scan detectors or `ner_findings: fail` (`route.post_scan_models_unsupported`, 4.5), so no
   route publishes unchecked output. The platform threads its raw config into the engine's direct
   sequential and out-of-core entries, so those calls reach the same guard. Classifier post-scan
   findings are never above `warning`.
6. **Logs and records name what ran.** Every scan and run logs which detectors ran, on how many
   tables and columns, and each model's id and version, through the engine logger
   `decoy_engine.detectors` at INFO and, when a platform context is bound, the step events (4.8). The scan record, the integrity report and
   the run's `--json` carry the same facts. No log, record or error contains a cell value or text a
   model read.
7. **Dismissals are exact.** A `post_scan.dismissed` entry lowers only the warning-severity finding
   whose table, column, detector, source, model id, model version and configured strategy all match
   (IW 4.6, dismissal rule). It is matched against the warn-mode severity, before the `fail`
   promotion (4.5), so a reviewed NER finding stays dismissed under `ner_findings: fail`. It never
   lowers a regex `fail`, an NER-pass `error`, or a source-identity finding (a regex finding whose
   `source_identity_rate` is at least `_LEAK_WARN_RATE`, `residual_pii.py:122`).
8. **NER reads free text only.** In both phases a column is NER-scored only when it is free text
   (median of at least 3 whitespace tokens per sampled cell, 4.3). Any other column sends no cell to
   spaCy and yields no NER hit, suggestion or finding; regex and the classifier still cover it.

### Non-goals (V1)

- Other NER models or languages beyond a validated spaCy package name; transformer models.
- Training or retraining the classifier, or a user-supplied classifier pack on the run path (the
  loader's untrusted-pack path stays platform-only).
- Making regex post-scan `fail` findings block a run (today report-only, `_pipeline_finalize.py:481`).
  Only the new `ner_findings: fail` opt-in blocks. Recorded as follow-up SCAN-ML-2.
- Resource settings (memory, threads). RUN-STREAM (63a) owns those sections of `decoy setup`.
- A settings file. SCAN-ML needs no persisted user setting: detectors are per pipeline.

## 2. Established solutions

Surveyed before designing; the chosen pattern is cited in each module docstring.

- **Microsoft Presidio** (analyzer). Detectors are "recognizers" of three kinds (pattern, NER, ML),
  each tagged with its source and run through one registry; the NLP engine is configured by name
  (`nlp_engine_name: spacy`, `models: [{lang_code, model_name}]`) and the model must be installed in
  the same environment. Offline hosts install the model wheel from a local path with pip
  (`pip install .../en_core_web_lg-3.8.0-py3-none-any.whl`, Presidio Fabric sample). Adopted: one
  detector registry with a `source` per finding, models named by package name, offline install from
  a wheel. Not adopted: Presidio itself (a second regex catalog beside STORM's).
- **spaCy.** `python -m spacy download <model>` resolves the model version compatible with the
  installed spaCy and pip-installs it; models are pip packages whose `meta.json` carries a
  `spacy_version` range. The engine's probes already use this (`ner.py:72` to `ner.py:96`). Adopted:
  models stay pip packages and the compatibility check reads the installed model's `spacy_version`
  range. Not adopted: `spacy download` itself, which resolves the version at run time without a
  hash; Decoy installs one pinned model wheel by URL and SHA-256 (4.6), the same pin CI uses.
- **pip safety.** `--only-binary :all:` (no build step runs), `--no-index --find-links` for offline
  wheelhouses, `--require-hashes` for pinned URLs, and `--constraint` to keep installed packages at
  their versions are pip's documented controls; all four are used (4.6).
- **Hugging Face Hub offline mode** (`HF_HUB_OFFLINE=1`, a local cache). Considered for a Decoy model
  cache; rejected for V1 because the engine's version pinning (`ner_model_version` stamped on the plan,
  `plan/_types.py:115`) reads package metadata, and a second store would need a second probe.
- **Google Cloud DLP / AWS Macie.** Findings carry an info type, a likelihood band and the detector
  that produced them, never the value. Adopted: a finding carries source, model id and version and a
  band or rate, never a value.
- **Model loading failure policy.** The pack loader already has a strict `load()` and a lenient
  `load_with_fallback()` that logs and returns `None` (`loader.py:172`, `loader.py:205`), and
  `classify_fields` always takes the lenient path (`classify.py:180`). A pipeline that asked for the
  classifier must not get regex-only results silently, so M1 splits inference into
  `classify_frame(pack, frame)` over a strictly loaded pack; `classify_fields` stays a thin wrapper
  for its platform caller (same rule as fail-closed NER, `ner.py:99`).
- **LightGBM packaging.** macOS wheels are built with Apple Clang and need a separate OpenMP runtime
  (`brew install libomp`, LightGBM python-package README). Adopted: a status probe that names this
  cause, and a macOS lane in the bundling part; the owner decided 2026-11-07 (Q2) that the
  classifier still counts as in every install and macOS names `brew install libomp`.

## 3. Design notes

- **One detector registry, three sources.** `regex`, `classifier`, `ner` are values of one
  `DetectorSource` literal. Every suggestion and every finding carries `source` and, for models, a
  `ModelRef(id, version)` (IW 4.6). Label to detector id goes through one table (4.4).
- **Strict availability, one probe.** `ModelStatus` answers "can this model run here, and which
  version" for both models. The gate, `decoy scan`, `decoy models list`, `decoy setup` and IW's
  detector step all read it; none probes on its own.
- **No hidden downloads.** Model installs happen only in `decoy models install` and `decoy setup`.
- **Pre-scan reuses SCAN-MULTI.** The classifier and NER passes run inside `scan_sources` on the same
  bounded sample frame `profile_columns` reads (SCAN-MULTI S1a), so no second read of the source.
- **Post-scan reuses the residual-PII check's strategy groups** (`residual_pii.py:56` to `:123`) but
  not its rate rules: a model finding's severity comes from one table per source (4.5), because the
  NER rate is a detection rate and `_LEAK_WARN_RATE` is a positional source-identity rate.
- **Enforcement where the outputs are made.** The `fail` opt-in is enforced inside the engine run,
  so every caller is covered; the CLI only maps the error to exit 4 and writes the report.
- **One NER sampling helper.** `detection/_ner_rate.py` (M1) holds the cell sample, the per-detector
  rate, the bucket and the constant `NER_MIN_RATE`; the pre-scan and post-scan passes both call it.
- **Legacy configs keep their hashes.** New config fields are omitted from the dump when unset, the
  precedent of `config/_global_settings.py:265` to `:277`, so `_hash_config` (`plan/_compile.py:641`)
  and the pinned F06 baseline (`tests/acceptance/test_f06_declared_casting.py:808`) are unchanged.
- **The CLI writes the report.** The engine stays caller-agnostic; `decoy run` writes the in-memory
  report it already gets and stamps `config_sha256` from the YAML bytes it read.

## 4. Behavior

### 4.1 Config fields (engine part M1)

```yaml
pre_scan:                         # new section; omitted = regex only
  detectors: [regex, classifier, ner]
  ner_model: en_core_web_sm       # optional; default en_core_web_sm
post_scan:
  integrity: true                 # existing (config/_post_scan.py:20)
  detectors: [regex, ner]         # new; default [regex]
  ner_model: en_core_web_sm       # new; optional
  ner_findings: warn              # new; warn (default) | fail
  dismissed:                      # new; default []; shape owned by IW 4.6
    - {table: customers, column: notes, detector_id: person_name, source: ner,
       model_id: en_core_web_sm, model_version: '3.8.0', strategy: text_redact}
    - {table: customers, column: memo, detector_id: email, source: regex, strategy: null}
```

```python
DetectorSource = Literal["regex", "classifier", "ner"]

class PreScanConfig(BaseModel):         # config/_pre_scan.py
    model_config = ConfigDict(extra="forbid", hide_input_in_errors=True)
    detectors: tuple[DetectorSource, ...] = ("regex",)
    ner_model: str = DEFAULT_NER_MODEL

class Dismissal(BaseModel):             # config/_post_scan.py
    model_config = ConfigDict(extra="forbid", hide_input_in_errors=True, frozen=True, strict=True)
    table: str; column: str; detector_id: str; source: DetectorSource
    model_id: str | None = None; model_version: str | None = None
    strategy: str | None                # None: the column had no configured strategy

class PostScanConfig(BaseModel):        # config/_post_scan.py, extended
    integrity: bool = False
    detectors: tuple[DetectorSource, ...] = ("regex",)
    ner_model: str = DEFAULT_NER_MODEL
    ner_findings: Literal["warn", "fail"] = "warn"
    dismissed: tuple[Dismissal, ...] = ()
```

- Validators: `regex` present and no duplicates (`config.detectors_invalid`). One
  `validate_ner_model_name` function in `detection/types.py` owns
  `re.fullmatch(r"[a-z][a-z0-9_]{1,63}", value)` (`config.ner_model_invalid`; `fullmatch`, because
  `$` accepts a trailing newline). Both config models and the top of `ensure_ner_available`
  (`ner.py:99`) call that function. `ensure_ner_available` is the one function every NER caller
  passes through before `spacy.load`: the compile
  check (`plan/_checks.py:405`) calls it with `provider_config.ner.model` (`_ner_config.py:53`)
  before the sink is reached, `_pipeline` calls it (`ner.py:154`), and `ner_status` (4.2) is built
  on it. Its message names the model today (`ner.py:113`), so the check runs before that message is
  built; a `Dismissal` has `model_id` and
  `model_version` exactly when `source` is not `regex` (`config.dismissal_invalid`); the
  `post_scan_inactive` rule from section 1, which also refuses `ner_findings: fail` or a set
  `ner_model` (in `model_fields_set`) when `ner` is not in that phase's `detectors`. Dumps keep the
  list order `regex`, `classifier`, `ner`.
- `PipelineConfig.pre_scan: PreScanConfig = Field(default_factory=PreScanConfig)` beside
  `post_scan` (`config/_pipeline.py:85`).
- Hash stability: `PipelineConfig` already has one wrap `model_serializer`
  (`_omit_unset_protected_quarantine`, `config/_pipeline.py:116` to `:123`) and Pydantic allows one
  per model, so M1 extends it to drop `pre_scan` when it equals the default, and adds one on
  `PostScanConfig` that drops each new field when it equals its default. Value equality, not
  `model_fields_set`, follows `config/_global_settings.py:272` to `:273`, so writing a default
  explicitly does not move the hash. A config that predates SCAN-ML keeps its exact dump,
  `pipeline_config_hash` and plan hash (AT-M1a asserts the F06 baseline,
  `tests/acceptance/test_f06_declared_casting.py:808`). A config that sets a non-default value
  changes its hash, which is correct: its checks changed.
- `_hash_config` (`plan/_compile.py:641`) leaves out `pre_scan`, in the way it leaves out
  `_NON_SEMANTIC_GLOBAL_SETTINGS` (`_compile.py:632`): pre-scan changes suggestions, not what the run
  masks or blocks on. `post_scan.dismissed` stays in the plan hash because, under
  `ner_findings: fail`, it changes whether a finding blocks. `post_scan.detectors`, `ner_model` and
  `ner_findings` also stay in the plan hash. Reviewing a finding in IW W3.2 therefore changes the

### 4.2 Model status and loading (engine part M1)

```python
@dataclass(frozen=True)
class ModelRef:                          # detection/types.py; IW 4.6 uses this one
    id: str
    version: str

@dataclass(frozen=True)
class ModelStatus:                       # detection/_model_status.py
    source: Literal["classifier", "ner"]
    model_id: str                        # "lgbm-v1" or the spaCy package name

    reason: str | None                   # reason identity when not available

def ner_status(model: str = DEFAULT_NER_MODEL) -> ModelStatus      # detection/_model_status.py
def classifier_status() -> ModelStatus                             # profiling/model_pack/_detectors.py
def load_detectors(sources: Sequence[DetectorSource], *, ner_model: str,
                   file_access: FileAccess | None = None) -> DetectorSet
```

- `classifier_status` first checks `DECOY_ML_DISABLED` (`disabled`), then imports `lightgbm` and
  `sklearn` on their own (`import`, which is where a missing `libomp` surfaces), then loads the
  default pack with `ModelPackLoader(...).load()` (`pack`). `ModelPackLoadError` gains a `cause`
  field set at each raise site (the disabled check at `loader.py:190`, the hash check at `:198`,
  `_deserialise` at `:404`),
  so the cause is read from a field, never parsed from the message. Result cached per process.
- `classify_frame(pack, frame) -> dict[str, ClassifierHit]` (new, `model_pack/classify.py`) runs
  inference on an already loaded pack. `classify_fields` becomes a thin wrapper (its lenient load
  stays for its platform caller). The run and scan paths only call `classify_frame` on the pack
  `load_detectors` loaded strictly, so the pack is hashed and unpickled once per process, and a
  load failure can never turn into a silent `None`.
- The classifier was trained on 40-row and 60-row fixtures (`profiling/eval/fixtures.py` `_ROWS`,
  `eval/_corpus_base.py` `_EXT_ROWS`), and its features include absolute counts
  (`model_pack/featurizer.py:62`). `classify_frame` therefore classifies a deterministic 60-row
  subsample of each column's non-null values (`_CLASSIFIER_ROWS = 60`, seeded), never the 10,000-row
  sample or a full output; AT-M3g checks that a fixture tiled to 10,000 rows gets the labels of its
  60-row source.
- `ner_status` calls `ensure_ner_available` (one availability rule, 4.1), then
  `installed_model_version` (`ner.py:96`). The spaCy-compatibility check (the model's
  `spacy_version` range against the installed spaCy, `provider.ner_model_incompatible`) is added
  inside `ensure_ner_available`, so it applies to `text_redact` `ner` columns too, not only to
  detectors; a mismatched model fails at load anyway, and this names the cause first. It does not
  load the pipeline.
- `load_detectors` raises `ModelUnavailableError(DecoyError)` with the reason identity when a
  requested model is not available; it never returns a partial set. The underlying exception is
  reduced to the reason and cause first, and the new error is raised after the `except` block
  closes, so `__cause__` and `__context__` are both `None` (the loader's message carries a pack path
  label; AT-M1b asserts this).
- `DetectorSet` caches by (source, model id, installed version), so a model upgrade inside a
  long-lived worker is a new key (class row 3). The spaCy pipeline cache `_PIPELINES`
  (`ner.py:148`), keyed by model name today, is re-keyed by (model, installed version), and the
  version a finding records is read from the loaded pipeline (`nlp.meta["version"]`), so a finding
  never names a version other than the one that ran.
- `ModelRef` lives in `detection/types.py` (one definition). IW E1 imports it from there; whichever

### 4.3 Pre-scan (engine part M3)

- `scan_sources(..., pre_scan: PreScanConfig | None = None)` (SCAN-MULTI S1a's signature gains one
  keyword). `None` means regex only. `load_detectors` runs once before the first table.
- Per table, on the sample frame `profile_columns` read:
  - classifier: `classify_frame(pack, frame)` (4.2). A column whose label is not `None` and whose
    band is `high` or `review` (`classify_band`, `profiling/eval/bands.py:82`) yields one classifier
    hit; a `low` band yields none and one count in the log.
  - NER: `detection/_ner_rate.py` (M1, shared with the post-scan): for each string column, the
    first `NER_SCAN_CELLS = 2_000` non-null, non-empty string cells form the sample. The column is
    free text when the median of `len(cell.split())` over that sample is at least
    `FREE_TEXT_MIN_TOKENS = 3` (`is_free_text`, the one predicate; an empty sample is not free
    text). A column that is not free text is not scored: no cell reaches spaCy, every rate is
    reported over zero scanned cells, and it yields no NER hit. `ner_rates` applies the predicate
    and is the only NER scoring entry: `_model_pass.py` (M3) and `_model_findings.py` (M4) call it,
    never `iter_ner_spans_batch` directly, and decide a hit only through `NerRate.hit`
    (`scanned_cells > 0 and rate >= NER_MIN_RATE`). Free-text samples go through
    `iter_ner_spans_batch` (`ner.py:190`);
    for each detector id in `NER_ENTITY_MAP` (`ner.py:54`) the rate is the share of scanned cells
    with at least one span of that id, and `hit_cells` is that count. A rate at or over
    `NER_MIN_RATE` yields one NER hit. Spans are counted inside the helper and dropped; it
    returns counts only.
  - `NER_MIN_RATE` is measured, not borrowed from `_LEAK_WARN_RATE`. It is calibrated on
    known-negative columns, with the false-positive bound set first (Neyman-Pearson
    classification, Tong, Feng and Li 2018). M1 runs `en_core_web_sm` over free-text negative
    fixture columns only (each passes `is_free_text`): redacted notes, Faker-generated text, and
    realistic non-name prose that mentions company, product, city and street names in sentences.
    A sentence column that names places is a negative for `person_name` only. Freeze before
    measuring: the calibration corpus (generators, seed, column membership) and a separate
    held-out negative corpus (its own seed, never used in the threshold) are committed with a
    digest test over their cells before the first measurement run. The commit that sets the
    constant changes neither corpus nor digest. If the frozen corpus gives a value outside 0.02 to
    0.10, the builder stops and the owner decides; fixtures are not edited to move the result
    (Revision 6). For each column the false-hit rate is the share of sampled cells with a hit of that
    detector id. `NER_MIN_RATE = max(2 * highest observed false-hit rate, highest one-sided 95%
    Clopper-Pearson upper bound of the false-hit rate across those columns, 0.01)`. The rule acts
    on that cell share, never on spaCy's per-entity score: spaCy NER scores are not calibrated
    probabilities (Presidio discussion #1997). The same share-of-cells threshold is how AWS Glue
    sensitive data detection (`ThresholdFraction`) works. M1 records each fixture's counts, sample
    size and the resulting threshold in its evidence and in the module docstring. The owner decided
    this rule on 2026-11-07 (Q7) and the free-text scope the same day (Revision 6).
- The field record of `ScanSetCore` (SCAN-MULTI S1a's per-field model; `TableScan` is per table)
  gains `model_hits: tuple[ModelHit, ...]`, where `ModelHit` is
  `{source, detector_id, model: ModelRef, band: "high"|"review"|None, rate_bucket: str|None}`. Rates
  are bucketed (`<10%`, `10-50%`, `>=50%`), as `confidence_bucket` is for regex; no raw text, span or
  cell count per value. `ScanSet` gains `detectors: tuple[DetectorRun, ...]` (`{source, model}`). Both
  are additive fields of `scan-set/v1` (SCAN-MULTI's tag, frozen when S1a merges; if S1a has merged,
  `ScanSetCore` gains them as optional fields and the read variant ignores unknown keys already).
- `starter_config` turns each model hit into one `ColumnSuggestion` (IW 4.6) with `source`,
  `detector_id`, `model`, `band`, `live=False` and an `entry`:
  - classifier: `column_entry(default strategy of detector_id)` from the detector descriptor
    registry, the same entry a regex suggestion of that id gets.
  - NER: `column_entry("text_redact", column, options={"ner_model": <ner_model>, "ner_entities":
    [every NER detector id hit on this column]})`. The catalog (IW 4.6, `StrategyOption`) declares
    `ner_model` (`str`) and `ner_entities` (`str_list`, choices from `NER_ENTITY_MAP` values) for
    `text_redact` and `text_mask` with location `provider_config.ner`, which `column_entry` writes as
    the existing nested shape `provider_config: {ner: {model, entities}}`
    (`execution/_strategies/_ner_config.py:36`). Every NER suggestion of one column carries the same
    entry, so confirming either `person_name` or `location` redacts both. NER finds names inside text,
    so the entry redacts the spans, not the column.
  - NER suggestions carry their rate bucket in `confidence_bucket` (IW 4.6), so the wizard can show
    how strong the hit was.
- `DetectionSignal.ml` (`detection/types.py:87`) stays unused: that trail explains why one regex
  detector won a column, while model hits are separate suggestions with their own identity (IW 4.6).
  Writing them into the trail would make one column's explanation list detectors that did not win.
- A label with no row in the mapping (4.4) yields no suggestion and one count in the scan log.

### 4.5 Post-scan (engine part M4)

- `run_post_mask(source_frames, output_frames, *, config, detectors: DetectorSet | None = None)`
  (`verification/postmask/runner.py:38`). `compute_post_scan_integrity`
  (`_pipeline_finalize.py:470`) passes the set `load_detectors` built at run start. `None` keeps

- Each model pass runs in its own `try` inside `run_post_mask`, after the regex pass. An exception
  adds one `error` finding with `source` and `model` set and the exception class name only, and

  (4.3, `is_free_text`) is not scored and gives no NER row. `match_rate` is the NER rate and
  `sample_match_count` is `hit_cells` (cells actually scanned, not scaled to the column length as the

  `text_redact` with a surviving match `fail` (`residual_pii.py:386`), and `_escalate` needs a regex
  detector confidence and a positional identity rate, neither of which a model finding has. Source
  identity stays on the regex path, unchanged. A column with `hit_cells == 0` (or no classifier
  label in `high`/`review`) gives no row at all; the table covers columns with at least one hit.
  The model table, with `R = NER_MIN_RATE`:

  | Configured strategy of the column | 0 < NER rate < R | NER rate >= R | Classifier hit (`high`/`review`) |
  |---|---|---|---|
  | none (column not configured) | `info` | `warning`; `fail` under `ner_findings: fail` | `warning` |

  | `_PRODUCES_PII_LIKE_VALUES`, `_REUSES_SOURCE_VALUES` | `info` | `info` (fake or re-emitted by design) | `info` |
  | `text_redact` or `text_mask` with `ner` on | `info` | `warning`; `fail` under `fail` | `info` |

- `models install ner`. Every installer call is an argument list (no shell) with
  `--only-binary :all:` and `--constraint <file>`, where `<file>` holds one `name==version` line per

  installed package (numpy, pandas, faker: proof-critical or output-determinism pins) can move.

  also means the install check and DP certification count the same set.
  - installer: `[sys.executable, "-m", "pip", ...]` when `python -m pip --version` succeeds; else,
    when `uv` is on `PATH`, `["uv", "pip", "install", "--python", sys.executable, ...]` with the
    same flags (uv accepts `--only-binary`, `--constraint`, `--require-hashes`, `--no-index`,
    `--find-links`). This covers the venvs `uv tool install decoy-cli` creates (README
    `README.md:32`), which have no pip. With neither, exit 1 (`models.pip_missing`) naming the route

    (`~/.decoy/versions/<v>/`, `distribution/layout.py:29`; `models.managed_runtime`), because that
    slot is a signed bundle checked at install. The owner decided on 2026-11-07 (Q5) that V1 refuses it there.
  - requirements: the `ner` extra's requirement strings, read from the installed engine's metadata
    (`importlib.metadata.requires("decoy-engine")`, entries with marker `extra == "ner"`). The
    command never names `decoy-engine` itself: it is not on PyPI (CLI `pyproject.toml:105`), and
    asking pip for it could resolve a public package of that name.
  - the model: one pinned wheel per supported model, `NER_MODEL_WHEELS` in the engine
    (`{("en_core_web_sm", "3.8.0"): (url, sha256, spacy_range)}`, the GitHub release asset of
    `spacy-models`, with the spaCy range from that wheel's `meta.json`, `>=3.8.0,<3.9.0`),
    installed from a temporary requirements file with `--require-hashes --no-deps`. The `ner`
    extra allows any spaCy 3.x, so the install also passes `spacy<range>` as a requirement; without
    it an online install takes the newest spaCy and the pinned model refuses to load. A unit test
    checks each row's range against the wheel's `meta.json`. CI's `ner-gate` reads the same table.
  - online: the requirement strings plus the spaCy range, then the pinned model wheel. `--model
    NAME` with no row in `NER_MODEL_WHEELS` is refused online (`models.model_unpinned`, exit 1,
    pointing to `--from`).
  - offline, `--from FILE.whl` or `--from DIR`: every entry must be a regular `.whl` file (no
    symlinks, no other files); the checked files are copied into a private 0700 temporary directory
    and pip runs `--no-index --find-links <tmp>` over that copy, so a file added to or swapped in the
    user's directory after the check is never installed. A single file must be the selected model
    wheel and is accepted only when every requirement in the `ner` extra is already satisfied by the
    constrained environment; it then installs that model with `--no-deps`. A directory must contain
    wheels for the unsatisfied `ner` requirements and the selected model, so it supports a fresh
    offline environment. The temporary directory is removed on every exit.
  - after either: `ner_status(model)` must report available and compatible, else exit 3
    (`models.install_failed`); a second `installed_distribution_set()` must equal the first plus
    only new packages, else exit 3 (`models.env_changed`, naming the changed packages). pip installs are not rolled
    back; the message says how to restore (reinstall Decoy).
  - before installing, it prints what it will install, the interpreter path, that `--from` content
    is trusted, and that NER makes this environment uncertified for DP fits (owner decided Q4), and
    asks; off a TTY it needs `--yes` (else exit 1).
  - every `pip` or `uv pip` subprocess captures stdout and stderr. Raw resolver output is never
    replayed or placed in an exception because configured index URLs can contain credentials. The
    command emits its own package-name progress records; failure output is the fixed
    `models.install_failed` text plus the integer subprocess exit code. The safe wrapper error is
    raised after the subprocess exception's `except` block, with no cause or context.
- `decoy setup` is a command with an ordered list of sections, each a small object with `name`,
  `status()`, `run(prompter, answers)`. SCAN-ML adds the `models` section (calls the same install
  code). RUN-STREAM (63a) adds its resources section to the same list. The section list lives in
  `cli/setup/_sections.py`, and the prompts use IW's `Prompter` when IW W1.1 has merged, else
  `typer.confirm` behind a two-method shim that W1.1 replaces.
- A pip-installed Decoy keeps NER across Decoy upgrades only if the upgrade does not replace the
  environment. `models list` says "not installed" whenever it is missing, and `decoy doctor` gains
  the two model rows plus one row saying whether this environment is on a certified DP row.

## 9. Owner questions (each answerable alone; recommended answer first)

- **Q1. Should `ner_findings: fail` withhold the masked output?** Owner decided 2026-11-07: yes, enforced in the
  engine so every caller is covered: `decoy run` exits 4 and writes only the report,
  `decoy.mask()` raises, a platform full-frame job fails instead of publishing, and every route
  that runs no post-scan refuses the setting up front (4.5 route guard). The
  alternative writes the outputs and only exits 4, which matches how regex `fail` findings are
  report-only today, and leaves the platform and the API publishing.
- **Q2. Is the classifier "in every install" when macOS needs `brew install libomp`?** LightGBM's
  macOS wheels need the OpenMP runtime. Owner decided 2026-11-07: yes for V1; `decoy models list`, `decoy doctor`
  and the refusal name `brew install libomp`, and the CLI installer docs list it. The alternative is
  converting the model to a dependency-free evaluator, which is a model change (follow-up SCAN-ML-3).
- **Q3. Must `regex` always be on in V1?** Owner decided 2026-11-07: yes. Dropping regex would make the classifier
  the only detector for structured types it does not cover (phone, address, IP). The alternative
  allows any non-empty set.
- **Q4. Can NER and certified DP fits share one environment?** Installing NER adds spaCy, Click and
  their dependencies, and the DP gate fingerprints every installed distribution
  (`quality/dp_provenance.py:130`), so DP fits in that environment then refuse with
  `dp_stack_uncertified`. Owner decided 2026-11-07: no shared environment in V1; `models install`,
  `models list` and `doctor` say so, and users who need both keep NER in a second environment. The
  extra certified row for the NER closure is not built.
- **Q5. How do managed-runtime users get NER?** Owner decided 2026-11-07: recommended. The managed runtime (`~/.decoy/versions/<v>/`) is a
  signed bundle slot, so V1 refuses `models install` there. Recommended: refuse in V1 with a message
  naming the pip-installed route, and plan a managed "NER bundle" with the distribution work. The
  alternative installs into the slot and drops its signature check for those files.
- **Q6. Under `ner_findings: fail`, does a finding the user dismissed in `decoy init` stay
  dismissed?** Owner decided 2026-11-07: recommended (yes). Dismissals are matched against the warn-mode severity before the
  `fail` promotion (4.5), so a reviewed finding does not block every later run. The alternative
  ("never lowers a fail") makes `fail` ignore the review, and the user's only way out is to change
  the column's strategy.
- **Q7. What NER rate should count as a finding?** Owner decided 2026-11-07: recommended (refined
  2026-11-07, 4.3): calibrate on known-negative columns, including realistic non-name text, and set
  the threshold to the largest of twice the highest observed false-hit rate, the highest one-sided
  95% Clopper-Pearson upper bound across those columns, and 0.01. It acts on the share of sampled
  cells with a hit, never on spaCy's entity score. M1 records the counts and the threshold. The
  alternative is a fixed 0.05, which lets a column with 4.9% of sampled cells still holding names
  pass as `info` under `fail`.

## 14. Worker evidence rules

Copied from the plan contract section 5; they go into every build handoff for these parts.

- Name the class of every finding and fix the class (the structure in section 6), not only the listed
  instance.
- Write the generated tests first (canary corpora, hostile config and `--from` corpora, the install
  matrix) and record them red, as assertion failures against stubs.
- Before pushing, attack your own diff: mutate each new mechanism once (section 7 names them) and
  show its test goes red, then revert. Never commit with a mutation applied.
- Run baselines with `uv.lock` in the same environment as the branch (`scripts/dev/gates.sh
  --baseline`). State what you did not run.
- Never widen a threshold, skip a test, raise a size pin or reduce a budget to make a part pass. The
  constants `NER_MIN_RATE`, `NER_SCAN_CELLS`, `FREE_TEXT_MIN_TOKENS` and `_CLASSIFIER_ROWS` change
  only with an owner note.
- If a new defect of a class already in the catalog appears, stop and report it. Do not patch a third
  time.
- Commit messages: Conventional Commits, at most 72 characters, final line `cam`, no em-dashes.

## 15. Pre-mortem

Assume it shipped and failed. The likely causes, and what in this plan prevents each:

- **The new base dependencies uncertify DP fits.** M2 adds the new fingerprint row in the same
  release and AT-M2c runs a real fit on the closure; C1 changes the CLI file only after that release.
- **The base install breaks on a platform because of lightgbm.** M2's three lanes (AT-M2a) and a
  status probe that never raises; owner decided Q2 (still "every install" on macOS with `libomp`).
- **spaCy breaks again on a dependency change.** The `ner-gate` leg installs `ner` alone on every PR.
- **NER makes post-scan too slow on large outputs.** A fixed cell sample per column
  (`NER_SCAN_CELLS`), and post-scan already keeps outputs resident (`_chunked_output_sink.py:124`);
  RUN-STREAM is told that integrity forces the resident route.
- **A suggestion masks a column without the user's say.** `live=False` for every model suggestion
  (AT-M3b, AT-M3e) and IW's confirm step.
- **A log or report carries a name the model read.** Counts and buckets only, canary corpora on both
  passes (AT-M3c, AT-M4d).
- **Dismissals hide new leaks.** Exact match including model version and strategy (AT-M4c).
- **Installing NER silently breaks DP fits.** Owner decided Q4 (no shared environment in V1);
  `models install`, `models list` and `doctor` say so.
- **A legacy config's plan hash moves.** Hash-stable serializers and AT-M1a against the F06 baseline.
- **Users upgrade Decoy and NER disappears.** `models list` and `doctor` say so; the gate refusal
  names `decoy models install ner`.
- **IW and SCAN-ML disagree on a shape.** Every shared shape is defined once in IW 4.6 or in 4.1 and
  4.2 here, and each plan cites the other's section.
