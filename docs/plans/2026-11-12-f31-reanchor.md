**What changed since revision 9 and the 2026-11-03 handoff.** LIB L1a (engine #444, 2026-11-10) added `decoy_engine.records`, with "the one canonical JSON form" `canonical_bytes` (`src/decoy_engine/records/_canonical.py:18-26`, `ensure_ascii=False`) and "the one strict JSON-object parse for records, export lines and job logs" `json_object` (`src/decoy_engine/records/_codec.py:161-185`: refuses duplicate keys, `NaN` and non-objects, returns `None`, never raises). **Guarantee.** E0b adds three functions and changes no existing behavior. `to_line` never raises, and every line it returns is canonical UTF-8 JSON that ends with exactly one newline. `from_line` never raises: it returns a validated `SafeEvent` or `None`, and never one built from a key, type, version or reason outside the closed contract. `render_text` gives the line format Platform parses today. `records` keeps the same bytes and names. Non-goals: any Platform change; DEBUG lines; escaping spaces in step names (erratum N3, V2-LOG); folding the other canonical-JSON copies in the engine (section 8).

**Design (revision 9 section 3.1 and the vault handoff `p1-f31-e0b-build-handoff.md` errata N1, M1, H1, N2, N3, with the changes below).**

- New leaf `src/decoy_engine/_canonical_json.py`: `canonical_bytes` (unchanged bytes) and `json_object` (unchanged behavior), moved from `records`. `records/_canonical.py` and `records/_codec.py` import them from the leaf, so every `records` name and byte stays the same.
- `_wire.to_line(event) -> bytes` is `canonical_bytes(event.to_dict()) + b"\n"` when the result is at most `MAX_LINE_BYTES = 4096`. Otherwise it returns the `safe_output.invalid` substitute for the same `seq` and `ts_ms`, with `counts=(("errors", 1),)`. If building that raises, it returns `_FAILED_LINE`. It never raises.
- Changed from erratum L5: the line is canonical UTF-8, not ASCII, because one canonical form outranks an ASCII-only line. The guarantee becomes: every return decodes as UTF-8, ends with exactly one `\n`, and holds no other `\n` or `\r` (JSON escapes control characters). Platform P1 decodes it as UTF-8. The 4096 cap counts UTF-8 bytes.
- `_wire.from_line(line) -> SafeEvent | None` refuses more than 4097 bytes before parsing, then parses with `json_object`. It refuses: nesting deeper than 3; a missing `s` tag or any tag other than `decoy-safe-output/v1` (recurring-defect class 4); an unknown key; a wrong or subclassed type (class 2); an unknown reason (`require_known`); and the `_FAILED_LINE` record. It rebuilds `ReasonRef(ns, code)` positionally (erratum H1) and rebuilds `counts` as sorted pairs (erratum M1).
- `_wire.render_text(event) -> str`: `ISO_TS  LEVEL  STEP  MSG`, with LEVEL one of `INFO `, `WARN `, `ERROR` (erratum N2). STEP is the approved step name, or `job` when there is none. An `ERROR` line ends with `(error_class=<namespace>.<code>, node_id=<step>)`.

**Design notes.** One new structure: the foundation leaf. The principle is one place per fact: the canonical form and the strict parse each have one home, and the change pain it removes is two encoders that drift. No flag arguments: `canonical_bytes` keeps its one form, and `_wire` adds no ASCII switch.

**Established solutions.** Revision 9 section 2 holds the survey for the event design: RFC 9457 identity versus occurrence, the OWASP Logging Cheat Sheet, OpenTelemetry `error.type`, and "parse, don't validate". For the line form, the line is JSON Lines framing (one UTF-8 JSON value per line, newline-terminated, jsonlines.org). The encoder is the engine's existing canonical form, a sorted-key subset in the spirit of RFC 8785 JCS. The parser is the stdlib `json` with `object_pairs_hook`, which `records` already uses. No new parser or encoder is written. No fresh online search was run for this re-anchor; the sources are the ones revision 9 and LIB L1a cited.
