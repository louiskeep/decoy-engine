## BLOCKER: format-stage quarantine of a parent row orphaned its children

Reproduced before touching `src/`: `tests/acceptance/test_f06_parent_quarantine.py` (parent `id` hash in namespace `ns`; declared integer `amt` with `error_policy: quarantine` and `integer/zero-pad/v1` width 2; child `pid` references `id` with `orphan_policy: fail`; parent row 1 has `amt` "123", which overflows the width). Run against `426f40a0` (`f06-r5/red-r5-on-r4-head.txt`):

| Stage | full_frame | sequential | chunked | unified_slice |
|---|---|---|---|---|
| parse (`amt` "x", no `output_format`) | `orphan_fk_violation` | same | same | same |
| format (`amt` "123", width 2) | **published**, parent has 1 row | **published** | **published** | **published** |

Dennis's expectation held: chunked and unified_slice have the same defect, not only full_frame and sequential. `auto` mode was also unguarded (`test_auto_mode_refuses_before_any_read` red).

Fix (option a, the smaller true one). `_eligibility.py` adds the requirement `post_mask_parent_row_quarantine`, needed when a declared column has `error_policy: quarantine` and an `output_format` on a table that is the parent of any relationship (`relationship_parent_tables`). No route lists it in `ROUTE_CAPABILITIES`, so the existing refusal path answers with the registered `declared_cast_route_unsupported` and `missing` naming the requirement. Forced routes are refused by the per-table evaluation in `preflight_declared_casting`; under `auto`, where route choice is left to the router, preflight refuses a requirement that no route provides (`_refuse_unprovided`), so there is no silent fallback. Both happen before any source is read.

Consequences worth stating plainly:

* The refusal is decided from config, not data. A parent table with a format-stage quarantine column is refused even if no row would fail. That is the point of option (a); a data-dependent refusal would reintroduce the silent-publication risk.
* A parse-stage quarantine of a parent row is unchanged and correct: the row never reaches the key maps, `orphan_policy` applies (`fail` raises `orphan_fk_violation` on all four routes). The test therefore declares no `output_format` for the parse case.
* A format-stage quarantine on a child-only table stays admitted (`test_format_quarantine_on_a_child_only_table_stays_admitted`).
* Option (b) (re-run the orphan policy on the children after `post_mask`/`render_table`) is not done; it would touch the full-frame and sequential publication paths and is a larger change than the refusal.

Capability truth: `tests/unit/declared_casting/test_route_capabilities.py::test_no_route_provides_parent_row_quarantine` pins that no route claims the requirement (it passes on the old code too, since the requirement did not exist; the acceptance tests are what went red). `docs/declared-casting.md` states the rule and the parse-stage/format-stage difference. The pinned matrix `tests/fixtures/f06/route-format-matrix-v1.json` is unchanged: it has no relationship parents, so no cell moved.

Result: 10 passed in `test_f06_parent_quarantine.py` (8 stage x route cells, `auto`, child-only control). On the old code: 5 failed, 5 passed.

## MEDIUM: out-of-core staging copy ignored the temp root and the disk budget

`run_staged` now creates its staging directory under `call["temp_dir"]` when the caller gave one (so the runner's own `check_temp_disk_budget(root)` walk counts the copy), and otherwise in a private system temp dir. `stage_typed_sources` takes `max_bytes` and calls `check_temp_disk_budget` after every written batch and after each table, so an over-budget copy stops while it is being written and the route never runs over it. The staging directory is removed on every exit; the caller's `temp_dir` itself is left alone. The docstring no longer claims a root it did not use.

Tests (`tests/unit/declared_casting/test_stream_staging.py`), red on `426f40a0` with the reasons below, green now:

* copy lives under the caller's `temp_dir` and only the staging dir is removed (was: `/tmp/decoy-ooc-cast-*`);
* a 1 KiB budget raises `out_of_core_temp_disk_exceeded`, the route function never runs, nothing is left behind (was: did not raise);
* the budget applies with no `temp_dir` (was: did not raise).

Limit: the tests drive `run_staged` with a stub cast run. The pipeline does not pass `temp_dir` to the out-of-core route today (it sizes `temp_disk_budget_bytes` from the default temp root), so there is no end-to-end `run_pipeline` path that exercises a caller `temp_dir` here.
