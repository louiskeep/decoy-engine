## HIGH: parse-stage quarantine of a relationship parent (classes 5 and 1)

**Class.** Referential integrity (catalog 5): the engine itself made the orphans by dropping a parent row before the key maps were built. Value-bearing output (catalog 1): the child then published the raw source key of that parent.

**Fix.** It uses the same config-only shape as r5. `_eligibility._requirements` adds the requirement `pre_mask_parent_row_quarantine` when a declared column with `error_policy: quarantine` is on a table that is the parent of any relationship whose `orphan_policy` is not `fail`. The new `orphan_tolerant_parent_tables` decides which tables those are. A missing policy counts as tolerant, so an under-specified edge can only be refused. No route lists that capability in `ROUTE_CAPABILITIES`, so the capability table stays true. The table is unchanged and `test_no_route_provides_parent_row_quarantine` now pins both parent-row capabilities. The refusal therefore comes from `preflight_declared_casting` before route selection: from `_refuse_unprovided` under `auto`, and from `evaluate_declared_casting` on a forced mode. The code is the registered F29 reason `declared_cast_route_unsupported`. The message names only the route and the capability, never a value. The format-stage refusal `post_mask_parent_row_quarantine`, the cleanup outcome, the fallback recordings and the runner split are untouched.

**Wider than r6 reported.** The r6 evidence said that only `preserve` leaks the raw key. The seeded-marker test shows that `warn` leaks it too: the child output carries the quarantined parent's raw key on all 45 runnable `warn` cells. `remap` re-hashes the orphan, so its key is not raw, but the child still publishes orphaned. The refusal covers all three policies.

### Generated matrix (`tests/acceptance/test_f06_parent_quarantine_matrix.py`, axes in `_f06_relational_matrix.py`)

Axes are read from the code:
* Route lanes come from `_eligibility.ROUTES` (6) plus the multi-table split.
* Forced modes come from `run_pipeline`'s `execution_mode` `Literal`: `sequential`, `full_frame`, `out_of_core`.
* Orphan policies come from `OrphanPolicyLiteral`: `preserve`, `remap`, `warn`, `fail`. There is no cascade.

That gives 10 requests: 7 lanes under `auto` and 3 forced. There are 5 FK shapes: single column, composite, self-referencing, a child that is itself a declared-casting table, and a child row in a later batch or chunk than its parent. `test_shapes_express_every_fk_shape` derives all five from the job configs, so a missing shape fails. There are 2 stages.

* **Executed route.** It is read from the run's own `RouteEvent` and `quality_metrics`, never from the request label. `test_valid_control_runs_on_the_recorded_lane` (50 cells) runs each request and shape with the same quarantining contract on valid data and pins the lane to an explicit table:
  * all 7 `auto` requests run `sequential`;
  * forced `full_frame` runs `full_frame`;
  * forced `sequential` runs `sequential`;
  * forced `out_of_core` is refused before routing (it lacks `row_quarantine`).

  Chunked, unified slice, mixed and the multi-table split decline relational jobs, as r6 found, so their `auto` requests are recorded as running `sequential` and cannot pass under a false label.
* **Each cell** (`test_quarantined_parent_cell_refuses_or_raises_orphan`, 400 cells) has exactly one expected outcome, written from the rule:
  * the registered refusal naming `post_mask_parent_row_quarantine` (format stage), `pre_mask_parent_row_quarantine` (parse stage, non-`fail`) or `row_quarantine` (forced out-of-core), with no route event;
  * or `orphan_fk_violation` (parse stage, `fail`), raised on the lane the control pinned. This is the non-vacuity check that data was read.

  The code must be registered, the message must not contain the seeded key or the bad cell, and no target file may exist.
* **Seeded marker** (`test_no_surface_carries_the_quarantined_parent_key`, 400 cells). The raw key of the quarantined parent row is `SEEDPKQ7`. The test scans every surface: progress events, DEBUG logs, the exception (`str`, `repr`, notes), `quality_metrics`, warnings, every output table, and every file the run wrote, including the protected quarantine store and the out-of-core temp root. `test_marker_scan_sees_a_published_raw_key` is the non-vacuity control: a genuine source orphan under `preserve` is published verbatim by design, and the same scan finds it.

The total is 853 tests: 1 axes + 1 shapes + 50 controls + 400 cells + 400 marker cells + 1 marker control.

## MEDIUM: one disk budget for the staged copy and the spill (class 4 budget parity, r6 carry)

**Fix by construction.** `_stream.run_staged` now creates one private per-run root, under the caller's `temp_dir` when one is given and under the system temp directory otherwise. It stages the typed copy in that root and passes the same root on as the route's `temp_dir`. Every footprint check measures that one root against the one `temp_disk_budget_bytes`: the copy's check per written batch, and `run_fk_out_of_core`'s check per table boundary. The root is removed on every exit. The runner no longer makes a second `mkdtemp` root for a staged run, so the budget can no longer be granted twice.
