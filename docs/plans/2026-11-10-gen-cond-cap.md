## 1. Goal and guarantee

If a fitted categorical pair has more than 25 combinations, the user can keep all of them, and fit
says when some were dropped. If generation draws a child for a parent value that has no fitted
cell, the run says so, with counts. With no cap set, fit bytes and generated bytes stay the same as
today.

Non-goals: conditioning on a renamed parent (M1); a cap per pair; a YAML key; warnings from
windowed reads (`generate_rows`) or from pinned-plan execution (`_pinned_execute.py`); a
count-of-one rule for joint cells (OQ1, row 24f); changing how the sampler falls back (it still
uses the child's overall counts, and now it says so).

## 2. Current behavior (engine `1a5b36e5`)

- Cap: `quality/snapshot.py:111` `DEFAULT_CONTINGENCY_TOP_K = 25`. `compute_distribution_snapshot`
  already takes `contingency_top_k` (`:134`) and passes it to `_joint_snapshot` (`:214`), which
  sorts cells by count, keeps the head and writes `cell_count` and `other_count` (`:543-581`).
  Nothing checks the bound: 0 keeps no cells, and a negative number slices from the end.
  `_normalize_joint_pair` (`:530-540`) accepts any two distinct columns of any kind, so a joint can
  pair a numeric, datetime or freetext column, with its raw values cast to strings.
- Writer: `distribution_snapshot_document` forwards the keyword (`profiling/_snapshot_values.py:157`,
  `:182`) and, when `include_values` is False, withholds every joint that touches a sensitive
  column (`:190-198`), then stamps `value_policy` and `redacted_columns` (`:199`;
  `_value_redaction.py:325-334`). No caller passes a cap.
- CLI: `decoy fit` calls `compute_distribution_snapshot(df, joint_columns=...)` with no cap and no
  redaction (`C:src/decoy/cli/fit.py:422`). Row 24f's CLI half moves it to
  `distribution_snapshot_document`. There is no cap flag and no truncation message (`:505-527`).
- Generation: `_conditional_tables` builds parent-to-child tables from the kept cells
  (`generation/statistical/_sample.py:249-266`). `sample_column` filters them with
  `_positive_weight_only` (`:355-359`), takes `parent_values[i]` or None when `i` is out of range
  (`:365`), looks up `str(parent)`, and on a miss draws from the child's overall counts with no
  signal (`:366`). In a run, the column is drawn by `synthesize._generate_tables_from_config`
  through `_generate_column` (`synthesize.py:174`), whole-column, because `statistical` cannot
  stream (`generation/_admission.py:44`). `_pinned_execute._run` (`_pinned_execute.py:192-221`)
  also calls `_generate_column`, and `window.generate_rows` (`window.py:203-209`) calls
  `sample_column` once per chunk.
- Warnings: generation has no structured warning channel today. The fidelity gate only logs
  (`synthesize.py:214`). GEN-CLI E1 (plan `E:plan/gen-cli`, row 24o) adds an `on_warning` sink on
  `run_generation` that reaches `_generate_tables_from_config` and feeds
  `ExecutionResult.warnings`. This row uses that sink and adds no second channel.

## 3. Established solutions

Search run (2026-11-10): synthpop conditional categorical synthesis, unseen parent levels,
small-cell disclosure. synthpop's saturated methods (`syn.catall`, `syn.ipf`) sample from a full
cross-tabulation and handle empty cells with an explicit prior (`nprior`), not a silent fallback.
Its disclosure guidance names small cells as the main risk and offers merging small categories
([syn.catall](https://search.r-project.org/CRAN/refmans/synthpop/html/syn.catall.html),
[disclosure vignette](https://bnowok.r-universe.dev/synthpop/doc/disclosure.Rnw)). The engine's
sampler already follows synthpop's sequential conditional scheme (`_sample.py:25-27`). What we
take: keep the full table when it is affordable and categorical (the raised cap), say when it is
not (the warnings), and leave small-cell handling to the redaction rules (OQ1). We do not adopt a
prior: it would change output bytes for every conditional column.

## 4. The knob

- Engine: the existing keyword `contingency_top_k` on `compute_distribution_snapshot` and
  `distribution_snapshot_document`. No YAML key and no new snapshot field.
- Bounds: an `int` from 1 to `MAX_CONTINGENCY_TOP_K = 1000`; `bool` is refused. The constant sits
  beside `DEFAULT_CONTINGENCY_TOP_K` (`snapshot.py:111`), and a short check at the top of
  `compute_distribution_snapshot`, which both writers call, raises `DistributionSnapshotError` with
  the new code `quality.contingency_top_k_invalid`. The message gives the bounds and the type it
  got, never a frame value. `snapshot.py` stays at or under 600 lines: the same number of lines
  comes out of the long `compute_distribution_snapshot` docstring (`:143-176`). No census entry,
  no new module.
- Kind refusal (disclosure): in `distribution_snapshot_document`, when `include_values` is False
  and `contingency_top_k > DEFAULT_CONTINGENCY_TOP_K`, every requested joint whose two columns are
  not both plain categorical is refused. Refused kinds: numeric, datetime, freetext, empty, and a
  categorical column with `high_cardinality`. The check reads the fitted `kind` from the computed
  document before anything is returned, and raises `DistributionSnapshotError` with the new code
  `quality.contingency_top_k_kind_unsupported`. The message carries the column name and kind only.
  At the default cap nothing changes, so default bytes are untouched. `include_values=True` is the
  explicit raw opt-in and is not refused.
- Why 1,000: the bound covers categorical-by-categorical pairs only. An ordinary categorical column
  has at most 30 distinct values (`quality/snapshot.py:118`), so such a pair has at most
  30 x 30 = 900 cells, and 1,000 keeps it whole. A pair with any other kind cannot use a raised cap
  in a plain snapshot (the kind refusal), because there a cell would hold a raw number, date or
  free-text string, and a larger cap would keep more of them.
- Disclosure, remaining: each categorical cell is a real label pair with an exact count. Raising
  the cap keeps rarer pairs, and rare pairs identify people. In V1 this is held by three rules:
  the kind refusal above, the withholding of every joint that touches a sensitive column (engine
  #420, `_snapshot_values.py:196-198`), and generation's refusal of `condition_on` on a withheld
  joint. Labels with a count of one belong to rows 24f and 24c (OQ1).
- CLI: `decoy fit --joint-max-cells N`, absent by default (the engine default of 25 applies). The
  CLI does not keep its own copy of the bounds or kinds: it maps `contingency_top_k_invalid` and
  `contingency_top_k_kind_unsupported` to exit 1 with that code. Usage order (L5):
  `--joint-max-cells` without `--joint` fails first, right after `--joint` parsing (`fit.py:326-335`),
  with the CLI code `fit_joint_max_cells_needs_joint`. That holds with or without `--epsilon`. With
  `--joint` and `--epsilon`, the existing `dp_mode_joint_unsupported` (`fit.py:362-368`) wins as
  today.

## 5. The two warnings

Both codes go in the engine reason registry (warning namespace, `QualityWarning` catalog). Their
`since` is the unreleased registry version, `1.22.0` (no `UNRELEASED` marker exists);
`REGISTRY_VERSION` is not bumped and E1b extends the v1.22 manifest fixture. Engine messages carry table names, column names and counts only, never a cell value or label, and
never a CLI flag name (L1). The CLI builds its own text from `code` and `detail`.

| Code | Slice | Raised by | `detail` | CLI text built from detail |
|---|---|---|---|---|
| `warning.fit_joint_cells_truncated` | E1 | `snapshot_joint_warnings(doc, *, contingency_top_k)` in `profiling/_snapshot_values.py`, exported from `decoy_engine`. One record per joint with `cap_dropped > 0`, skipping withheld joints | `columns`, `cell_count`, `cells_kept` = `len(joint["cells"])` (what the file holds), `cap_dropped` = `max(0, cell_count - contingency_top_k)`, `policy_dropped` = `min(contingency_top_k, cell_count) - cells_kept`, `other_count` | "joint parent x kid: 36 combinations, 25 kept; 11 dropped by the cell cap, 366 rows in all fall outside the kept ones. A parent value with no kept combination is generated from the child's overall counts. Raise --joint-max-cells (at most 1000) to keep the 11." When `policy_dropped > 0` the CLI adds "N more were left out by the value policy", with no advice to raise the cap for those. |
| `warning.generation_condition_parent_unseen` | E1b | `_generate_tables_from_config` (`synthesize.py`), right after a conditional statistical column is drawn, through the GEN-CLI `on_warning` sink. One record per conditional column per run, only when `rows > 0` | `table`, `column`, `condition_on`, `rows`, `rows_null_parent`, `rows_total`, `parent_values` | "table t, column kid (condition_on parent): 61 of 6000 rows (0 of them with an empty parent) had one of 1 parent values with no fitted combination and drew from the column's overall counts." |

- Withheld joint (M2): a joint is withheld when `doc["value_policy"] == "flagged-redacted/v1"` and
  `set(doc["redacted_columns"]) & set(joint["columns"])` is non-empty. Such a joint gets no
  truncation record; #420 already governs it.
- Cap versus policy (Codex H2): `cell_count` counts every nonzero cell, and `_joint_snapshot` picks
  its head before the writer applies any redaction, so `cap_dropped` is exactly what the cap cut.
  `cells_kept` reads the file, so it stays true when row 24f folds singleton cells into
  `other_count` after the head is chosen; that difference is reported as `policy_dropped` and never
  as a reason to raise the cap.
- One table selection (Codex H1): today the sampler picks each row's table inline
  (`_sample.py:364-366`): `parent_values[i]`, or None past the end of the list, then
  `conditional.get(str(parent), marginal)`. E1b moves exactly that into one helper,
  `_select_table(conditional, marginal, parent_values, i) -> (values, weights, fell_back)`, and
  both `sample_column` and the counter call it. `conditional` is built once by one helper,
  `_conditional_lookup(spec)` (`_conditional_tables` then `_positive_weight_only`, as at
  `:355-359`), also shared. The lookup key stays `str(parent)` for every parent, None included, so
  generated bytes do not change (AT-14).
- Counter: `conditional_fallback_counts(spec, parent_values, n) -> FallbackCounts(rows,
  rows_null_parent, parent_values)` in `_sample.py` loops `i` over `range(n)` and counts every row
  where `_select_table` reports `fell_back`. That includes a None parent and a row past the end of
  a short parent list, since the sampler draws those from the overall counts too.
  `rows_null_parent` is the subset whose parent was None or missing, so a reader can tell a
  nullable parent from an unfitted value. `parent_values` is the number of distinct `str(parent)`
  keys that fell back. A literal string "None" and a real None share the key "None", exactly as in
  the sampler: if the joint has a cell for the label "None", neither falls back and neither is
  counted. A parent equal to the `other_mode: emit` token is counted. The counter never draws and
  never touches the RNG.
- Emission point (M3): `_generate_tables_from_config` already holds `data`, the spec map and (after
  GEN-CLI E1) `on_warning`. After `data[cname] = _generate_column(...)` (`synthesize.py:174`), for a
  `statistical` column whose spec has `condition_on`, it calls the counter on `data[condition_on]`,
  which is the list the sampler read, and emits one record if `rows > 0`. The sink is not threaded
  through `_generate_column`.
- `_pinned_execute._run` emits nothing: it has no sink and pinned execution is not a V1 CLI route.
  AT-12 proves it does not crash and its bytes do not change. `generate_rows` emits nothing either;
  `GeneratedWindow` has no warning field.
- Fit output (C1): each record prints on stderr as `warning:` in human mode (not with `--quiet`).
  `fit --json` gains `"warnings": [{"code", "message", "detail"}]`, present even when empty. Exit
  stays 0.
- Run output (C1): the generation record goes through `ExecutionResult.warnings` to the run
  summary, `run --json` and the evidence manifest `quality_summary`, rendered the way GEN-CLI C1
  renders warnings. C1 adds the code's text to GEN-CLI's table of known codes.

Design notes: no new module and no new abstraction. One fact sits in one place: the bound beside
the default in `quality/snapshot.py`, the kind refusal in the writer that applies redaction, the
lookup key and the key set in `_sample.py`, the codes in the registry.

Choke points: every fit goes through `compute_distribution_snapshot` (bound) and every plain
snapshot write through `distribution_snapshot_document` (kind refusal). Guard: AT-4 and AT-13.
Mutations: drop the bound check; drop the kind check. The counter and the sampler share
`_conditional_lookup` and `_select_table`. Guard: AT-3b, AT-3s, AT-3n. Mutation: have the counter
look up the raw parent instead of calling `_select_table`.

## 7. Acceptance tests (red first)

Fixture `cond.csv`, built without an RNG: 6,000 rows. Parents `SENTP01` to `SENTP12` have weights
20, 15, 12, 10, 9, 8, 7, 6, 5, 4, 3, 1 (each weight x 60 rows). Parent i allows the children
`SENTK{(i+j) mod 6 + 1}` for j = 0, 1, 2, with weights 6, 3, 1. That gives 36 pairs. At cap 25 the
snapshot keeps 25, `other_count` is 366, and `SENTP12` (60 source rows) has no kept cell.

E1 (fit side):
- AT-1 Default unchanged: both writers on the fixture with no cap argument give bytes equal to a
  digest recorded at the base commit.
- AT-2a Cap raised: `contingency_top_k=36` keeps 36 cells, `other_count` 0, and
  `snapshot_joint_warnings(doc, contingency_top_k=36)` returns nothing.
- AT-3a At the default, `snapshot_joint_warnings` returns one record: `cell_count` 36,
  `cells_kept` 25, `cap_dropped` 11, `policy_dropped` 0, `other_count` 366.
- AT-4 Bounds: 0, -1, 1001, `True` and 2.5 raise `contingency_top_k_invalid`; 1 and 1000 work.
- AT-5 A pair with a profiler-flagged column under `distribution_snapshot_document` gives no
  truncation record at cap 25 or 1000.
- AT-13 Kind refusal: a numeric parent paired with `kid` is refused with
  `contingency_top_k_kind_unsupported` at cap 26 and fits at the default; a datetime column and a
  `high_cardinality` column, a freetext column (more than 30 distinct strings) and an all-null
  (`empty`) column are refused the same way; with `include_values=True` cap 26 fits.
- AT-6 (E1 part) No message from AT-1 to AT-13 contains `SENTP` or `SENTK`.

E1b (generation side):
- AT-2b With the cap-36 snapshot, generating 6,000 rows of `kid` with `condition_on: parent` gives
  zero pairs absent from the source and no generation warning.
- AT-3b With the default snapshot, generating 6,000 rows gives exactly one
  `generation_condition_parent_unseen` record. Its `rows` equals the number of generated rows with
  parent `SENTP12`, counted by the test, and `parent_values` is 1.
- AT-3s The same fixture with integer parent labels 1 to 12 (a parent column the sampler sees as
  ints) gives the same `rows` as AT-3b's independent count.
- AT-3n Separate unit fixtures on `conditional_fallback_counts` and `sample_column` together, each
  checked against a per-row replay of the sampler's choice: (1) parents with 10% None: `rows`
  includes them and `rows_null_parent` equals the None count; (2) a parent list shorter than `n`:
  the missing rows count as fallbacks and as `rows_null_parent`; (3) a joint with a cell for the
  label "None": a "None" string and a real None parent both use that cell and neither is counted.
- AT-6 (E1b part) No warning text, detail or captured log line contains `SENTP` or `SENTK`.
- AT-7 The output bytes of AT-3b are the same with and without an `on_warning` sink.
- AT-8 Route matrix (the GEN-CLI AT-8 cells): resident, full-frame and mixed, including the
  runtime-decline handoff, each carry exactly one record in `ExecutionResult.warnings`.
- AT-16 (row 24f integration; owned by whichever of this row's E1 and 24f's singleton-fold slice
  lands second): a pair with 30 combinations where two singleton cells sit inside the top 25.
  With the fold active, `cells_kept` is 23, `cap_dropped` 5, `policy_dropped` 2.
- AT-12 Pinned execution of the AT-3b config does not crash and its bytes equal a base digest.
- AT-14 Generated output of AT-2b and AT-3b equals digests captured at the base commit.

C1 (CLI):
- AT-9 `decoy fit cond.csv --joint parent,kid` exits 0, prints one `warning:` line on stderr with

## 10. Owner questions

- OQ1. Should categorical joint cells with a count of one follow row 24f's count-of-one rule, and
  be folded into `other_count` in a plain snapshot unless values are opted in? Recommended: yes,
  built in 24f's engine extension through the existing `("joint", "cells")` registry rule, not in
  this row. A raised cap lets those cells through on small data. This row does not wait on the
  answer. If that rule removes a parent's only cells, the generation warning reports it.
