## 0. Why + scope
faker masks a column by generating pool-backed values. On the sequential route its index derivation is ALREADY native (`PoolSampler._deterministic` / `positional_pool_indices` both call `derive_index_batch`), but the assembly is per-cell Python: the deterministic leg does `values = list(sampled)` then `df[column] = [None if na_mask[i] else values[i] for i in range(n)]` (`_strategies/_faker.py:131-132`), and the positional leg the same at `:110-111`. That per-row loop bottlenecks the Rust columns in a mixed job. This slice moves both assemblies onto the native Arrow path, making faker the 6th SEQ-native payload tenant.

The native Arrow apply, the index kernel, and the admission predicates already exist and are shared with the chunked route:
- **apply**: `native/_operator_step.py:72` `sample_faker_array` (deterministic: `derive_index_batch` over the source array keyed on `mask_key`, null-safe gather into `pool.values`, source-validity null mask), `:134` `sample_faker_array_positional` (non-det REUSE by global row position keyed on `job_seed`, taking `row_offset`, `namespace`, `gate_positions`, `missing_mask`).
- **index kernel**: the SAME `BoundIndexKernel` the categorical/bucket/date_shift tenants already load on SEQ; pass its `.kernel` and `.native_threads` (`_sequential_native.py:158`, confirmed by the gate).
- **admission predicates** (the real ones, corrected from rev 1): the deterministic precondition logic lives in `_requirements.py:195` `faker_pool_precondition_met`, but that function takes a WORKNODE and reads `node.plan_slice` (`:208`) — `NativeOp.admit` receives a bare `ColumnSeed`, which has no `plan_slice` (rev 2 HIGH: calling it with a seed raises `AttributeError`). So this slice extracts a shared **ColumnSeed-level** predicate `faker_pool_precondition_met_seed(seed: ColumnSeed) -> bool` (`isinstance` check dropped; checks `seed.deterministic`, `seed.cardinality_mode == "reuse"`, truthy `seed.namespace`, `seed.pool_size is not None`) and leaves the existing node-level `faker_pool_precondition_met` as a thin wrapper that delegates (`return faker_pool_precondition_met_seed(node.plan_slice)` after the `ColumnSeed` isinstance guard) so current chunked callers are unchanged. SEQ admission calls the seed-level predicate. The provider gate is `_real_type_admission.py:54` `C1_PROVIDER_ALLOWLIST` (= `OPERATORS["faker"].provider_allowlist`, `{person_first_name, person_last_name}`); the built-pool output-type guard is `_chunk_masking.py:286` `pool_values_are_strings`, applied by the chunked route on the RESOLVED pool at `_chunked_entry.py:413`, NOT inside any admission module. (rev 1 wrongly named `_faker_deterministic_admission.py` — that module is the non-string bool/int/uint chunked admission — and `_faker_positional_admission.py` as the reusable gates; the real reusable predicates are the three just listed.) The positional leg's selection namespace is NOT an admission concern: `resolve_selection_namespace(ctx, column, namespace)` needs the context and is resolved in the handler/seam, not in `NativeOp.admit` (which gets no context).
- **pool identity**: `resolve_faker_pool_identity` (`generation/pool/_identity.py`), the one place the pool_size/locale/build_config/identity split lives, shared with both other routes.

The OOC deferral (`_compat.py` `_DEFERRED_GROUP_B["faker"]`, cross-batch pool cache) does NOT apply: SEQ loads each table whole (`_sequential.py:373`), and the handler already holds `ctx.registry` + `ctx.pool_cache` + `ctx.row_offset` + `ctx.gate_positions` (the existing Python positional leg reads all four, `_faker.py:104,108`).

**In scope (native):** two legs, STRING-output pool only, provider allowlist only.
- **Deterministic REUSE** (`plan.deterministic=True` AND the chunked precondition `faker_pool_precondition_met`): source-keyed on `mask_key`, via `sample_faker_array`.
- **Non-det REUSE / positional** (`not plan.deterministic AND cardinality_mode is REUSE`): position-keyed on `job_seed`, via `sample_faker_array_positional`, forwarding `ctx.row_offset`, the resolved selection namespace, and `ctx.gate_positions`.

**Out of scope / explicit DECLINE to Python (coded reason, output still oracle-parity):** the non-det UNIQUE / MATCH / SCALE cardinality modes (whole-column RNG state); any deterministic non-reuse variant not matching `faker_pool_precondition_met`; non-allowlisted providers; a built pool whose values are not strings (`pool_values_are_strings` false — e.g. a caller-overridden registry binding of an allowlisted name); non-string sources; and no-companion. A decline keeps the already-built pool in `ctx.pool_cache` so the Python fallback is a cache hit (mirrors `_chunked_entry._resolve_admitted_pools`). faker as an FK KEY is non-injective (pool-select) and auto-declines through the existing `{hash,fpe}` key-eligibility gate (the fpe-key slice's `sequential_fk_key_injectivity_not_guaranteed` path); this slice adds no key support, only an acceptance test that it declines.

**NOT a native→Python graceful fallback:** an out-of-`when:`-grammar predicate is invalid config and is rejected by the pandas `when:` gate for BOTH routes (`_when_gate.py`), not something the native leg catches and reroutes. The in-scope `when:` behavior is: the gate hands the handler a subset frame plus its full-table positions as `ctx.gate_positions` (C8-iii-d), and the positional native leg reproduces the whole-frame draw by keying local row `i` on `row_offset + gate_positions[i]`.

## 1. Risk
R2 (privacy-relevant masking; determinism/joinability matter). faker output must be byte-identical to the Python handler (same pool identity, same index draw, same null placement, same positional keying under a gate). Acceptance compares SEQ-native to the pandas oracle on the strict 9-dimension contract + a SEQ-native-specific witness; the chunked route already ships both kernels (C5a/b/c), so the pool/identity/kernel are proven — this is the SEQ wiring and its admission adapter.

## 2. The code change
- **FakerCall + the SEQ admission adapter** (`_sequential_native_ops.py`): a `FakerCall` payload carrying the BUILT pool, its identity, the leg (`deterministic` | `positional`), the resolved namespace, and the keying seed; `ctx.registry` stays OUT of the descriptor. A `faker_op` `NativeOp` (disposition `SEQ_FAKER_DISPOSITION_KEY = "sequential_faker"`). The admission is a thin SEQ adapter composed of the real reused predicates, NOT the mis-named modules from rev 1:
  - provider ∈ `C1_PROVIDER_ALLOWLIST`;
  - deterministic leg: `faker_pool_precondition_met_seed(seed)` (the extracted ColumnSeed-level predicate: deterministic + `cardinality_mode == "reuse"` + namespace + pool_size);
  - positional leg: `not deterministic AND cardinality_mode is REUSE`, and `resolve_selection_namespace(ctx, column, namespace)` resolves (it fails closed with `faker_positional_table_unknown` on an unstamped table; every dispatch path stamps `ctx.current_table`);
  - source type is `string` (reuse `string_source_type_rejection` semantics);
  - companion present.
  `NativeOp.admit` receives a `ColumnSeed`; the adapter reads the seed's own fields (it does not call the chunked modules' raw-config signatures).
- **bespoke `faker_column` method** (`_sequential_native.py`, mirroring `categorical_column:312` / `bucket_column:335`): gate via `self._admitted(ctx, column, FAKER, len(df))` (books the row count, honors nested/REMAP/zero-row/undecided), then:
  1. build/fetch the pool in the handler path (`PoolBuilder(ctx.registry)`, `resolve_faker_pool_identity`, `ctx.pool_cache`), identical to the oracle;
  2. **output-type guard**: if `not pool_values_are_strings(pool)` → set `decision.backend/reason = PYTHON_SCALAR, f"faker_provider_output_not_string:{column}:{provider}"`, leave the pool cached, return `None`;
  3. pick the leg; call `sample_faker_array(array, pool=pool, namespace=plan.namespace, mask_key=ctx.mask_key, index_kernel=bound.kernel, native_threads=bound.native_threads)` (deterministic) OR `sample_faker_array_positional(array, pool=pool, row_offset=ctx.row_offset, job_seed=ctx.job_seed, namespace=resolve_selection_namespace(ctx, column, plan.namespace), index_kernel=bound.kernel, native_threads=bound.native_threads, missing_mask=None, gate_positions=getattr(ctx, "gate_positions", None))` (positional). `missing_mask=None` is correct for the in-scope string source (Arrow validity = the oracle's answer, `_operator_step.py:164`);
  4. book `decision.native_calls`, return `result.to_pylist()`. NOTE (rev 3 LOW): unlike `native_date_shift` (which takes a `derive_calls` out-param), `sample_faker_array` / `sample_faker_array_positional` return ONLY a `pa.Array` (`_operator_step.py:80,145`) — each makes exactly one `derive_index_batch` batch call. So `faker_column` records the call itself after a successful helper invocation (`decision.native_calls += 1`); do not expect a count from the helper.
- **faker disposition evidence** (`_sequential_native_decisions.py`): today the rendering (`:55-71`) uses call counts to pick a backend but does not emit the numeric count. Extend it so the faker key SERIALIZES its numeric `native_calls` as caller-visible evidence, so the SEQ-native witness (and the F8 evidence: 0 for an empty table, 1 for all-null) is truthful rather than inferred.
- **faker handler seam** (`_strategies/_faker.py`): after the pool build + `na_mask` (line 98), route the two in-scope legs through `seq.faker_column(...)` (like the fpe/categorical handlers); on a `None` return fall through to the existing Python assembly. The non-det UNIQUE/MATCH/SCALE path (lines 119-132 with `mode is not REUSE`) is never offered to the seam.
- **register faker in `_OPS`** (and `FAKER` in the strategy constants if not already imported).
- faker is NOT added to `_KEY_STRATEGIES`; a faker FK-key column hits the existing decline path unchanged.

## 3. Acceptance matrix (the spec)
Each masking cell runs full-frame oracle vs SEQ-native vs SEQ-python-fallback (companion hidden), asserts `tests/parity/_strict_compare.compare_strict == _ALL_TRUE` (output tables), with warnings asserted on their own channel. The witness is SEQ-NATIVE-SPECIFIC: `decision.native_calls > 0` under `SEQ_FAKER_DISPOSITION_KEY` for the column (merely observing `derive_index_batch` is insufficient — the Python handler reaches that kernel too, Codex MED-3).

- **F1 deterministic REUSE, allowlisted provider, string source** (person_first_name, person_last_name): byte-identical to the oracle; SEQ-native witness; across a range of pool_size and row counts.
- **F2 positional (non-det REUSE), no `when:` gate** (row_offset 0): byte-identical to the oracle on the whole-table positional draw; SEQ-native witness.
- **F2b positional UNDER a `when:` gate**: accepted predicates selecting a **partial, non-contiguous** subset, an **all-rows** subset, and a **zero-match** subset; with nulls in the source. Byte-identical to the oracle, proving `ctx.gate_positions` + `ctx.row_offset` are forwarded (the keying Codex HIGH-1 flagged: positions `[1,3,7]` must draw the oracle's values, not the offset-0 values).
- **F3 null handling**: a source column with nulls (deterministic and positional) → nulls preserved positionally (null-in/null-out), strict parity incl. `null_vs_nan`.
- **F4 determinism + keying**: same job twice → identical output; the deterministic draw is f(mask_key, namespace, canonicalized source), the positional is f(job_seed, selection_namespace, full-table position) — pin both. Include the shared/default selection namespace (namespace unset → `faker_selection_namespace` default) vs an explicit namespace, proving they key differently.
- **F4b thread-count invariance**: the native output is identical for `native_threads` 1 vs >1 (the gather is order-stable).
- **F5 declines (stay Python, coded reason, output still oracle-parity)**: (a) UNIQUE / MATCH / SCALE cardinality modes; (b) a non-allowlisted provider; (c) a non-string source; (d) no companion (ci-mirror); (e) **incompatible built pool** — an allowlisted provider name whose caller-overridden registry binding yields non-string values → `faker_provider_output_not_string` decline, pool retained in cache; (f) **missing `pool_size`** — a deterministic faker lacking only the explicit pool_size precondition declines to Python and still produces oracle-parity OUTPUT (a successful Python run).
- **F5c missing namespace is a REJECTION, not a successful fallback**: a deterministic faker with `namespace=None` does not decline-and-succeed — the oracle raises `deterministic_requires_source_and_namespace` (`generation/pool/_sampler.py:234`). Assert the SEQ path surfaces the SAME error (error-parity), never an invented successful fallback.
- **F5b invalid `when:` predicate**: an out-of-grammar predicate is REJECTED by the `when:` gate (matching the pandas rejection) — assert the rejection, NOT a successful native→Python fallback (Codex HIGH-1).
- **F6 faker as an FK key declines**: a faker FK-key column records the existing `sequential_fk_key_injectivity_not_guaranteed` decline (payload faker on the same job still native), proving faker did not leak into `_KEY_STRATEGIES`.
- **F7 mixed job + routing dispositions** (§4): faker payload native beside a hash payload and a categorical payload → each reports under its own disposition key, no cross-contamination; AND the §4 routing cases for a faker-bearing table, asserting route + backend + visible reason each:
  - estimate-FIT → full-frame oracle (no SEQ-native witness);
  - non-fit/unpriceable → SEQ (native witness);
  - OOC route → faker declines/reroutes (OOC incompatibility preserved);
  - explicit route override honored.
- **F7b byte-estimate-disabled threshold routing** (§4, distinct from companion fallback): with the byte-estimate flag OFF, routing falls to the row-threshold path (`_pipeline_routing.py:533`), which can still select SEQ. Assert BOTH threshold sides — below-threshold and at-or-above-threshold — and that a SEQ-selected faker payload stays NATIVE when the companion is present (the flag disables byte-estimate ROUTING, not native EXECUTION). Keep this separate from the F5(d) companion-unavailable fallback assertion; name the flag in the test.
- **F8 empty vs all-null (truthful evidence, split by shape)**:
  - an **empty table** (zero rows) → `_admitted` returns None on `rows == 0`, so `native_calls == 0`: truthful no-execution evidence, output empty-parity.
  - an **all-null populated source** → the native path DOES run (both helpers call `derive_index_batch` once on all-null input; `_admitted` skips only zero-row, `_sequential_native.py:390`), so `native_calls == 1` and the output is all-null parity. Do NOT assert zero calls for this case (rev 2 MED); assert the one call and the rendered evidence.

## 4. Failure modes (reproduce, do not smooth)
- Picking the wrong leg (deterministic vs positional) silently changes the keying → F1/F2/F4 pin each.
- Dropping `ctx.gate_positions` under a `when:` gate → the positional draw reverts to offset-0 keys and diverges from the oracle → F2b (the exact Codex HIGH-1 consequence).
- A pool-identity mismatch between SEQ and the oracle → different values; reuse `resolve_faker_pool_identity`, pin byte-parity.
- An incompatible built pool failing AFTER admission instead of declining cleanly → F5(e) (the `pool_values_are_strings` guard before native commit, Codex HIGH-2).
- Calling the node-level `faker_pool_precondition_met` with a bare `ColumnSeed` → `AttributeError` on `.plan_slice` (rev 2 HIGH): the seed-level predicate is the SEQ contract.
- Inventing a successful fallback for a missing namespace instead of surfacing the oracle's `deterministic_requires_source_and_namespace` → F5c (error-parity, not output-parity).
- Asserting zero native calls for an all-null populated source (it runs once) → F8.
- Null placement drift → F3.
- A non-allowlisted provider or cardinality mode silently going native → F5 (must decline).
