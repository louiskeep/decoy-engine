## 1. FRAME

**Problem.** QA engineers want masked or test data that contains the awkward values that break
software: empty and whitespace strings, quotes, inert injection text, Unicode normalization and
bidi cases, emoji, integer width limits, negative zero, leap days, daylight-saving instants. The
engine can only produce realistic values today (Faker, Mimesis, identifiers). Nothing emits a
curated, reproducible set of edge cases.

**Execution path (the same route V1P-2.3 uses).** A config column `strategy: faker`,
`provider: <name>` always builds a pool (`FakerStrategyHandler` to `PoolBuilder.build`), and
`plan/_checks.py::check_non_poolable_provider_with_pool_backend` refuses a provider that declares
`poolable=False`. Config reaches a provider only through the pool builder: `PoolBuilder.build`
passes `ProviderSpec(seed=pool_seed, extra=build_config)` to `adapter.generate_batch`. So the new
adapter declares `poolable=True` and implements a **seeded** `generate_batch`; the column then
samples the pool with the existing keyed `derive_index` (deterministic) or the positional and
whole-column samplers (non-deterministic), exactly as for `person_name`. No new strategy, no new
reason code, no planner check, no config key.

**Routes.** Three routes can run such a column:

- Full-frame pandas (`run_pipeline`): always.
- Native and native-chunked: never. Their faker allowlist names only `person_first_name` and
  `person_last_name`; the column falls back with the existing coded route-decline reason.
- Python chunked (`execution/_chunked.py`, `run_mask_pipeline_chunked`, and the auto-chunk lane):
  `_conditional_admission_failures` admits any non-composite faker provider with
  `deterministic: true`, a `namespace` and an explicit `pool_size` (the end-to-end config in
  section 8). Each chunk is converted by pandas inference, so the output type must not depend on
  which values a chunk drew. Section 4 states per provider that it does not, except nullable
  integer columns (a known failure tied to the shared null assembly, F46-7, pinned by a test).

**Definition of done.**

1. Six `decoy_native` providers, each with one stated output type and a curated catalogue of
   named categories (section 3):

   | Provider | Output type (Python, then Arrow) |
   |---|---|
   | `edge_case_string` | `str`, ASCII only, `string` |
   | `edge_case_unicode` | `str`, every value has a non-ASCII code point, `string` |
   | `edge_case_integer` | `int` (never `bool`), within signed 64-bit, `int64` |
   | `edge_case_float` | `float`, finite, never NaN, `double` |
   | `edge_case_date` | `datetime.date` (exactly, never `datetime`), `date32` |
   | `edge_case_datetime` | `datetime.datetime`, time-zone aware, UTC, inside the pandas nanosecond range, `timestamp[ns, tz=UTC]` |

2. A `strategy: faker` column with each provider compiles and runs through `run_pipeline` and
   through the Python chunked route; every output value is a catalogue value; the output column
   has the stated Arrow type whatever values were drawn (whole column and every chunk); equal
   sources give equal outputs in deterministic mode; a rerun with the same seed gives identical
   output.
3. Pools are reproducible: same job seed, provider, locale and config give the same pool in a new
   process. A pool of size at least the catalogue size contains every catalogue value.
4. Every emitted string survives the writers the CLI uses: pandas `to_csv`/`read_csv` and
   pyarrow Parquet, byte for byte (section 4).
5. Dark: no default config, disguise or starter template names these providers. They do appear
   in registry listings (CLI cockpit, capability matrix, proof manifest); that is the owner's
   exception for this slice.

**Non-goals.**

- The `mix` option (rate of edge cases among realistic values). Needs config surface; follow-up
  F46-1 (section 10).
- Category selection per column (for example "only bidi strings"). Needs a `provider_config` key;
  follow-up F46-2. The provider takes no options.
- Schema-aware choice (max length from a declared `VARCHAR(n)`, integer width from the column
  type). Belongs with V2-5.1 (DDL) and F46; follow-up F46-3.
- `generate:` mode. Its `faker` columns resolve through the legacy reflection pool
  (`generation/_faker_pool.py`), not the registry, so these providers are masking-only, as the
  V1P-2.3 providers are. Follow-up F46-4.
- Naive (wall-clock) datetimes, including local times that do not exist or are ambiguous on a
  daylight-saving day. A naive column and an aware column are different Arrow types; this slice
  ships the aware UTC provider only. Follow-up F46-5.
- NaN and infinities (section 3, float), unsigned 64-bit values above the signed maximum, `Decimal`,
  `time`, `bytes`, and NUL or other control characters (section 4).
- Datetimes outside the pandas nanosecond range (year 1, year 9999, the "just outside" library
  bound). Inside pandas, one such value turns the column from `datetime64[ns, UTC]` into
  `object`, and Arrow then infers `timestamp[us, tz=UTC]` instead of `timestamp[ns, tz=UTC]`, so
  the output type would depend on the draw. They need a declared-type route; follow-up F46-9.
- Vendoring the Big List of Naughty Strings (section 2).

**Risk: R2.** New public provider names and capability rows, read by the CLI cockpit, the
capability matrix, the proof manifest and the platform capability registry; deliberately hostile
text reaching downstream consumers (section 4, safety rules). Rollback: revert the commit;
nothing is persisted.

## 3. Catalogues (per provider)

Each catalogue is a tuple of `EdgeCase(category, value)` entries. Values are distinct within a
provider (floats compared by bit pattern, so `0.0` and `-0.0` are distinct). Exact lists are
written in the build; the counts below are targets (about 20 to 80 values per provider).

**`edge_case_string`** (ASCII; the only control characters are TAB, LF, and CR immediately
followed by LF):

- `empty`: `""`.
- `whitespace`: one space, three spaces, a lone TAB, leading and trailing spaces.
- `line_breaks`: `"a\nb"`, `"a\r\nb"`, `"\n"`, a trailing newline, `"a\tb"`.
- `quotes_and_delimiters`: `O'Brien`, `"quoted"`, `it''s`, backslash, `C:\path\file`, `a,b`
  (`;`, `|`, `&` and backticks are refused by the safety rule: in shell text they end, chain or
  substitute the consumer's command).
- `null_like_tokens`: `null`, `NULL`, `None`, `nil`, `undefined`, `NaN`, `N/A`, `NA`, `#N/A`,
  `-`, `\N`, `true`, `FALSE`, `0`, `-0`, `1e3`, `0x1A`, `007`, `1,000`, `+1`.
- `injection_text` (exactly these 13 values, pinned by a test; section 4): always-false SQL
  predicates `' AND '1'='2`, `" AND "1"="2`, `1 AND 1=2`; `<img onerror=alert(1)>` (no `src`:
  under the HTML Living Standard's "update the image data" algorithm (cited from the standard's
  text as known; html.spec.whatwg.org is not reachable from this session, so it was not
  re-fetched), an `img` with no `src` and no `srcset` selects no source, sets the request to
  broken and fires no `error` event because the element has no `src` attribute; nothing is
  fetched and the handler never runs); template text `{{7*7}}`, `${7*7}`, `#{7*7}`; a literal
  percent `100%%` (no printf conversion specifier); traversal `../../../../decoy-nonexistent`;
  spreadsheet formula text `=1+1`, `+1+1`, `-1+1`, `@SUM(1,1)`. (`<script>alert(1)</script>`,
  `$(echo decoy)` and `` `echo decoy` `` were dropped in code review: script tags and command
  substitution are refused classes.)
- `length_boundaries`: lengths 1, 255, 256, 4000, 4001, 32767, 32768 (a repeating
  `abcdefghij` pattern so truncation is visible; letters rather than digits so the length-1
  value `a` does not duplicate the null-like token `0`).

**`edge_case_unicode`** (valid Unicode scalar values; no Cc or Cs code points, no noncharacters,
no private use):

- `accented_latin`: `café`, `Zoë`, `Łódź`, `naïve`.
- `normalization_variants` (UAX #15): `café` precomposed and decomposed; U+00C5, `A`+U+030A and
  U+212B; `ﬁle` (U+FB01); full-width `ＡＢＣ１２３`; Hangul syllable U+AC00 and its jamo
  U+1100 U+1161; `x²`.
- `combining_marks`: stacked marks on one base, a short "Zalgo" string, a Devanagari conjunct.
- `case_mapping` (length changes): `Straße`, `İ` (lowercases to two code points), dotless `ı`,
  final sigma `σας`, titlecase digraph `ǅ`.
- `bidi` (UAX #9): Hebrew, Arabic, mixed `abc שלום 123`, an RLO override closed by POP
  DIRECTIONAL FORMATTING `\u202eabc\u202c` (an unterminated override would reverse the rest of a
  CSV or terminal line), RLM, an isolate `\u2067abc\u2069`, Arabic-Indic digits `١٢٣`. Every
  embedding or override is closed by U+202C and every isolate by U+2069 (checked by the safety
  rule).
- `invisible`: ZWSP inside and alone, ZWNJ, ZWJ, a BOM inside text, word joiner, soft hyphen,
  NBSP, ideographic space U+3000, LINE SEPARATOR U+2028 and PARAGRAPH SEPARATOR U+2029 inside
  text.
- `emoji_and_astral` (4-byte UTF-8): `😀`, a skin-tone modifier, a ZWJ family sequence, a flag
  (regional indicators), mathematical fraktur letters, CJK Extension B `𠜎`, a hieroglyph.
- `scripts`: Japanese, Chinese, Korean, Thai, Greek, Cyrillic, Hindi.
- `homoglyphs` (UTS #39): `аdmin` with Cyrillic `а`, Greek `Α` for `A`, U+2212 minus sign,
  U+2010 hyphen, smart quotes `O’Brien`, full-width apostrophe.
- `replacement`: U+FFFD.

**`edge_case_integer`** (Python `int`, within [-2^63, 2^63-1]):

- `zero_and_unit`: 0, 1, -1.
- `signed_width_bounds` (two-value BVA): int8 -128, 127, -129, 128; int16 -32768, 32767, -32769,
  32768; int32 -2147483648, 2147483647, -2147483649, 2147483648; int64 -2^63, 2^63-1 (no
  outside neighbour fits).
- `unsigned_width_bounds`: 255, 256, 65535, 65536, 4294967295, 4294967296.
- `float_precision`: 2^24+1 (first int float32 cannot hold), 2^53-1, 2^53, 2^53+1 and their
  negatives (JavaScript and float64 exactness).
- `decimal_digits`: 9, 10, 99, 100, 999999999, 1000000000, 10^18-1, 10^18.

**`edge_case_float`** (finite, never NaN):

- `zeros`: `0.0`, `-0.0`. The engine compares values with Python `==` (the pool's distinct count,
  `pd.unique` in UNIQUE mode, the leakage scan), and `0.0 == -0.0`; so UNIQUE mode sees one
  fewer distinct float than the catalogue holds, and a source `0` or `0.0` counts as leaked
  when `-0.0` is emitted. Documented in `docs/strategies.md`.
- `subnormal`: `5e-324`, `-5e-324`, the largest subnormal, the smallest normal.
- `extremes`: float64 max and its negative, float32 max, float32 smallest normal, float16 max
  (65504.0).
- `precision`: machine epsilon, `1 + eps`, `0.1`, `0.1 + 0.2`, `2^53`, `2^53 + 2`.
- `rounding`: 0.5, 1.5, 2.5, -2.5, 0.125, 1.005, 2.675.
- `display`: `1e-07`, `1e16`, `1e21`, `123456789.12345679`, `100.0`.

NaN is excluded because pandas treats it as null, so it would silently become a null in the
masked output; infinities are excluded because JSON has no literal for them and several targets
refuse them. Both are follow-up F46-6 under an explicit option.

**`edge_case_date`** (`datetime.date`):

- `epoch`: 1970-01-01, 1969-12-31.
- `leap_years`: 2000-02-29, 2024-02-29, 1900-02-28, 1900-03-01 (1900 is not a leap year;
  spreadsheets disagree), 2100-02-28, 2100-03-01.
- `period_ends`: 2023-02-28, 2023-04-30, 2023-12-31, 2024-01-01.
- `rollovers`: 1999-12-31, 2000-01-01, 2038-01-19, 2038-01-20, 1899-12-30 (spreadsheet serial
  day 0), 1899-12-31.
- `calendar_history`: 1582-10-04, 1582-10-15 (Gregorian adoption; Python is proleptic),
  1752-09-02, 1752-09-14 (British adoption), 1753-01-01 (SQL Server `datetime` minimum).
- `library_bounds` (two-value BVA on the pandas nanosecond range): 1677-09-21 (outside),
  1677-09-22 (inside), 2262-04-11 (inside), 2262-04-12 (outside).
- `type_bounds`: 0001-01-01, 9999-12-31.

  The date type is stable across this whole range, unlike datetimes. Probe (pandas 2.3.3,
  pyarrow, 2026-11-07): assigning a list of `datetime.date` values to a column, with or without
  `None`, and with 1970-01-01 alone, 1677-09-22 and 2262-04-11, or 0001-01-01 and 9999-12-31,
  always gives pandas dtype `object` and Arrow `date32[day]`; pandas never converts `date`
  objects to `datetime64`. So the date bounds stay, and acceptance test 6 asserts `date32` for
  draws that include and exclude them (whole frame and per chunk). If the re-check prefers the
  stricter rule, the two outside values and `type_bounds` move to F46-9 with no other change.
- `dst_days`: 2024-03-10, 2024-11-03 (US changes), 2011-12-30 (skipped in Pacific/Apia).

**`edge_case_datetime`** (aware, `tzinfo is datetime.timezone.utc`):

- `epoch`: 1970-01-01T00:00:00Z and one microsecond before.
- `rollovers`: 2038-01-19T03:14:07Z and 03:14:08Z (signed 32-bit seconds); 2106-02-07T06:28:15Z
  and 06:28:16Z (unsigned 32-bit).
- `day_boundaries`: leap-day midnight and 23:59:59.999999; 2016-12-31T23:59:59.999999Z (a leap
  second followed; `:60` is not representable in Python, so the catalogue stops one microsecond
  short).
- `subsecond`: .000001, .5 and .999999 past a second.
- `dst_transitions` (two-value BVA: the transition instant and one microsecond before):
  America/New_York 2024-03-10T07:00Z and 2024-11-03T06:00Z; Europe/London 2024-03-31T01:00Z and
  2024-10-27T01:00Z; Australia/Lord_Howe (30-minute change) 2024-04-06T15:00Z and
  2024-10-05T15:30Z; Pacific/Apia 2011-12-30T10:00Z (the skipped day); America/Sao_Paulo
  2018-11-04T03:00Z (midnight change). Each was derived from `zoneinfo` on 2026-11-07 and is
  re-checked by a test.
- `library_bounds` (inside values only): 1677-09-21T00:12:43.145225Z and
  2262-04-11T23:47:16.854775Z, the first and last microseconds inside the pandas nanosecond
  range.

Every datetime value lies inside the pandas nanosecond range, so pandas stores the column as
`datetime64[ns, UTC]` and Arrow as `timestamp[ns, tz=UTC]` whatever is drawn, with or without
nulls (probe 2026-11-07). The outside values and `type_bounds` (year 1, year 9999) are follow-up
F46-9. The safety rule refuses a datetime outside the range.

## 4. Behavior and failure modes

**Adapter behavior** (`EdgeCaseAdapter`, one instance per spec):

| Call | Behavior |
|---|---|
| `generate_batch(spec)` with `spec.seed` (the pool builder always passes one) | `rng = np.random.default_rng(int.from_bytes(seed, "big"))`; block `k` (k = 0, 1, ...) is the catalogue in the order of the `k`-th call `rng.permutation(n)` on that one generator (a fresh permutation per block, not one permutation repeated); blocks are concatenated and cut at `count`. A pool of `count >= n` holds every value; `count < n` gives a seeded subset without repeats. This order rule is part of `backend_version` `edge_case/v1` and pinned by a test that rebuilds the expected order with numpy. |
| `generate_batch` without a seed | same, with an unseeded generator (the S4 random-by-default contract, as Faker). |
| `generate(spec, deterministic=False)` | one value drawn by the same generator construction. |
| `generate(spec, deterministic=True)` | `ProviderError(provider.capability_violation)`, as `FakerAdapter`; deterministic columns go through the pool. |
| `generate_batch(spec, deterministic=True)` | `ProviderError(provider.batch_deterministic_unsupported)`. |
| wrong provider name for this adapter | `ProviderError(provider.unknown_provider)`. |
| any `spec.locale` | accepted and ignored: output does not depend on locale. The locale still enters the pool seed (as for every provider), so two locales give the same values in a different order. |
| `spec.extra` (column `provider_config`) | ignored; still part of the pool's config hash (same limit as V1P-2.3; the pool builder passes the whole column config, so unknown keys cannot be refused here). |
| draw sites | one generator construction, written `np.random.default_rng(...)` so the static scan's token matches, plus `rng.permutation(`. Seeded use (every pool build) is catalogued as a mirror of `gen.pool_build_faker`; unseeded use (direct library calls without a seed) as a mirror of `gen.identifier_nondeterministic` (entropy root `none`, not partitionable), whose notes are amended to name the edge-case adapter. |

Error messages name the provider and the problem, never a value.

**Value safety rules** (enforced at spec construction, section 6):

- Text: every value is a valid Unicode scalar sequence (encodes as UTF-8 with `strict`), with no
  Cc code point except TAB, LF, and CR immediately followed by LF; no surrogates, no
  noncharacters, no private-use code points. `edge_case_string` values are ASCII.
- Format characters (category Cf) only from an allowlist: U+00AD, U+200B to U+200F, U+202A to
  U+202E, U+2060, U+2066 to U+2069, U+FEFF. This excludes tag characters (U+E0000 to U+E007F),
  the deprecated U+206A to U+206F and the interlinear annotation characters U+FFF9 to U+FFFB.
- Bidi controls are balanced within each value: every embedding or override opener (U+202A LRE,
  U+202B RLE, U+202D LRO, U+202E RLO) is closed by U+202C PDF, and every isolate opener (U+2066
  LRI, U+2067 RLI, U+2068 FSI) by U+2069 PDI, with no closer before its opener, so no value
  changes the direction of text after it.
  - Why no lone CR: the CLI writes CSV with pandas `to_csv`, which quotes a field containing LF
    but not one containing only CR; a lone CR then splits the row on read (checked 2026-11-07,
    pandas 2.3.3). CRLF and LF are quoted and round-trip.
  - Why no NUL or other controls: PostgreSQL `text` refuses NUL; C-string consumers truncate;
    terminal escapes act on the viewer's terminal.
- **What the injection text guarantees, and what it cannot.** Guarantee: no value adds a read,
  write, delete or network operation of its own. That guarantee rests on review of the shipped
  `injection_text` values (and of the other string values), which a test pins value for value:
  any change to the set fails until it is reviewed again. Not guaranteed, and not possible for
  any catalogue: a value spliced unquoted into a consumer's statement can change that statement.
  Even `""` or `" "` can cut a template short; a quote can end the consumer's string early; an
  always-false predicate narrows the consumer's `WHERE`; in shell text `<` and `>` redirect the
  consumer's own command and a space splits its arguments. These effects act on the consumer's
  own statement, and they are the bugs these values exist to expose.
- The safety predicate is a **backstop for named classes**, not a proof of the guarantee. On every
  text value of both providers it applies NFKC first (so full-width `ＤＲＯＰ` or `；` are
  caught), matches case-insensitively, and refuses: `\bor\b` (tautology-shaped disjunction);
  `'1'\s*=\s*'1'`, `"1"\s*=\s*"1"`, `\b1\s*=\s*1\b`, `""\s*=\s*""` (tautologies); `;`, `|`, `&`
  (statement end, pipe, chaining); `--`, `/*`, `['"]\s*#` (comments); `\b(select|union)\b`
  (query keywords); `into outfile`/`into dumpfile` and `copy ... program` (file export);
  `xp_cmdshell` and `\bexec(ute)?\b` (command execution); `$(` and backtick (command
  substitution); `<script` (script tags); `src`, `href`, `action`, `srcset`, `data`, `formaction`,
  `poster`, `background`, `srcdoc` followed by `=` (resource-loading attributes); `url(` (CSS);
  `fetch(`; `//` (host-relative paths and URLs); `\\` (UNC paths); `IMPORT*(`, `WEBSERVICE(`,
  `IMAGE(`, `HYPERLINK(` (network spreadsheet functions); `jndi`; `drop`, `delete`, `truncate`,
  `update`, `insert`, `alter`, `grant`, `rm`, `curl`, `wget`, `nc` as words; and any `%` left
  after removing `%%` pairs (printf conversions). A test seeds one value per pattern (including
  full-width variants) and expects refusal (section 6).
- Integers: `type(v) is int` and within signed 64-bit. Floats: `type(v) is float`, finite.
  Dates: `type(v) is datetime.date`. Datetimes: `type(v) is datetime.datetime` and
  `v.tzinfo is datetime.timezone.utc`.
- Values are distinct within a provider; every category has at least one value.

**Writer behavior.** Every text value round-trips byte for byte through pandas `to_csv` and
`read_csv(keep_default_na=False, dtype=str)` in a two-column frame, and through pyarrow
Parquet. Known reader-side artefacts, documented rather than avoided (they are the bugs these
values exist to find): `read_csv` with default options reads `null`, `NA`, `NaN` and the empty
string as missing; in a one-column CSV a whitespace-only value is read as a blank line and
skipped; Excel evaluates `=1+1`. Float values written to CSV by pandas use `repr` and are
exact, but `read_csv`'s default float parser is not round-trip exact (`0.30000000000000004` reads
back as `0.3`); the acceptance test reads with `float_precision="round_trip"`, and
`docs/strategies.md` lists the default-parser artefact.

**Failure modes in a run.**

| Failure | Behavior |
|---|---|
| Catalogue value breaks a safety rule | import of the package fails (construction check), so no registry can be built; caught by every test |
| A source value equals an emitted edge case (likely for `0`, `1`, `""`, `2024-02-29`) | with the opt-in post-run validation (`run_pipeline(post_validation=True)`), the leakage scan hard-fails with `source_value_leak` (it treats any source value in a `faker` output as leakage) and records it in `quality_metrics["failed_checks"]`; the job itself is not failed unless the consumer enforces it (`post_validation_enforce`). This is the scan working as designed (not softened, per review). It compares with Python `==`, so `0`, `0.0`, `-0.0` and `False` cross-match. `docs/strategies.md` says so and the end-to-end test uses disjoint string sources |
| `cardinality_mode: unique` with more rows than catalogue values | existing `uniqueness_impossible` at run time (UNIQUE dedups the pool first, `_sampler.py` near line 305) |
| `cardinality_mode: match_source_cardinality` or `scale_source_cardinality` | silently under-delivers: the sampler checks the target distinct count against the raw `pool.size` and draws pool indices (`_sampler.py` near lines 410 to 433), but these pools repeat a 20 to 80 value catalogue, so a column with 100 distinct sources gets at most `n` distinct outputs and no error. ## 5. Design notes

- **One adapter, a table of specs** (the V1P-2.3 shape). `EdgeCaseSpec(provider, output_type,
  cases)` is data; one `EdgeCaseAdapter` serves all six; the registry binds every spec in
  `EDGE_CASE_SPECS` in a plain loop (no `dict.update`: the outbound-client sentry treats any
  `.update(` call as a possible GCS call). A new provider is a new spec; nothing branches on the
  provider name (`architecture.md`, open/closed).
- **One admission predicate per output type**, in `_spec.py`, run by `EdgeCaseSpec.__post_init__`.
  The safety rules live there once; catalogues cannot bypass them.
- **One generator construction** (`_rng(spec)`) used by `generate` and `generate_batch`, so the
  draw-site catalogue has one physical site to name.
- **Where facts live.** Values and categories: the two catalogue modules. Safety rules: `_spec.py`.
  Capability row: `capability_row()` in `_adapter.py`. Registry membership: `EDGE_CASE_SPECS`.
  Docs (`capability-matrix.md`, `proof-manifest.json`) are generated from the registry.
- **House style.** Frozen dataclasses for spec and case; no flag arguments; comments explain why.
- **Principles not applied.** No new abstraction beyond the spec table; no category-selection
  machinery (non-goal).

## 8. Acceptance tests (written first)

1. **Catalogue contract** (`test_catalogues.py`): for every spec in `EDGE_CASE_SPECS`, every value
   has the declared exact type and passes the safety rules; values are distinct (floats by
   `struct.pack('<d')`); each category named in section 3 exists and is non-empty; integer
   bounds equal the computed width limits (for example `-(2**31)`); normalization pairs are
   canonically or compatibility equal and differ as strings; bidi values contain a code point
   whose `bidirectional()` is `R`, `AL`, `RLO` or `RLI`; astral values contain a code point above
   U+FFFF; floats in `subnormal` are below `sys.float_info.min`; every DST instant passes the
   `zoneinfo` check.
2. **Seeded construction refusals**: the bad values listed in section 6 each raise `ValueError`;
   the message names the provider and the rule, and does not contain the value's `repr`.
3. **Writers**: every text value round-trips through pandas CSV (two-column frame, UTF-8,
   `keep_default_na=False`, `dtype=str`) and pyarrow Parquet; every non-text provider's full
   catalogue converts to its stated Arrow type via `pa.array` and round-trips through Parquet.
4. **Adapter** (`test_adapter.py`): seeded batch identical across two calls and in a subprocess;
   different seeds (8 and 32 bytes) give different orders; pools of size `n` and `3n` contain
   every value and size `n - 1` has no repeats; the order equals a numpy rebuild of
   "fresh permutation per block"; unseeded calls work; deterministic `generate` and
   deterministic batch raise the named codes; wrong provider raises `unknown_provider`; a pool
   builds through `PoolBuilder` with locale `None` and with `en_US`; errors carry no value.
5. **Registry and capability rows**: the six names are registered with the pinned row (every
   field in section 4); the count and exact-set pins updated.
6. **End to end** (`test_end_to_end.py`), per provider: a `strategy: faker` column,
   `deterministic: true`, a `namespace`, `pool_size` equal to the catalogue size, 2,000 string
   source rows with 200 distinct values disjoint from every catalogue (no nulls), run with
   `run_pipeline` twice: output equals on rerun, equal sources give equal outputs, every output
   value is a catalogue value, and the output column has the stated Arrow type. The same config
   through `run_mask_pipeline_chunked` with chunks of 50 rows (so different chunks draw different
   value mixes) gives the same values as the full-frame run and the same type on every chunk.
   One non-deterministic (`cardinality_mode: reuse`) run per provider also checks type and
   membership. Pinned known behaviors: a nullable `edge_case_integer` column on the chunked route

## 9. Known limits

- Masking-only; `generate:` mode does not reach the registry (F46-4).
- No mix rate and no category choice: a column gets only edge cases (F46-1, F46-2).
- A source value that equals an edge case fails the opt-in post-run leakage scan (section 4).
- Nullable integer columns lose precision above 2^53 in the shared faker handler (F46-7).
- Deterministic sampling from a pool does not guarantee every catalogue value appears in a given
  output; a small table may miss some categories.
- Pool order rests on numpy's PCG64 `permutation`, which NEP 19 does not promise stable across
  numpy versions; the pool sampler has the same exposure and the lock pins numpy.
- `supported_locales=()` is a label; nothing enforces locales for any provider.
- Unsigned 64-bit values above 2^63-1, NaN, infinities, naive datetimes, `Decimal` and `time`
  are not covered (F46-5, F46-6); datetimes outside the pandas nanosecond range are not covered
  (F46-9).
- `match_source_cardinality` and `scale_source_cardinality` deliver at most `n` distinct values
  without an error (F46-8).
- The Python chunked route fails on nullable `edge_case_integer` columns (F46-7).
- `0.0` and `-0.0` compare equal in the engine's distinct counts and leakage scan.
- Deterministic masking needs string, integer or aware-datetime sources (existing
  canonicalization rule).
- Catalogue strings are curated, not exhaustive; BLNS has far more. The categories are the
  contract, not a claim of completeness.
