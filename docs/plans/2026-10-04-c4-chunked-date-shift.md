## 1. Goal and scope

`date_shift` is vetoed from the native chunked leg (`CHUNKED_ROUTE_VETOED_STRATEGIES = {"group_key", "date_shift"}`, `native/_requirements.py:153`), so a date_shift column currently runs the pandas-ORACLE chunked leg. C4 makes native-admissible date_shift run the native kernel per chunk, byte-and-type-identical to the oracle chunked leg, keyed by the row's own value via `derive_index_batch`.

Native-admissible date_shift (the existing full-frame domain, `_operator_config_rejections.py:135-181`): STRING source, explicit non-empty `date_format` (no autodetect/prepass), no `group_by`, namespace present, no `%z/%Z`/pandas-special format, int in-range min/max bounds. Everything else stays on its existing path (oracle or declined) unchanged.

Out of scope (unchanged): `group_key` (stays vetoed, C3); autodetect/formatless date_shift (the format_detect PREPASS, kept off the native/chunked-native domain by the explicit-format requirement + the upstream `_planner._whole_column_state_rejections` gate); `group_by` date_shift (sibling-anchor whole-column state, native-rejected); the full-frame route.

## 3. The two date_shift-specific decisions

**3a. Output type: C1-style string pin (date_shift is `_TOKENIZING`, all-string output).** Pin native-admissible date_shift to `pa.string()` on BOTH chunked legs (the categorical/C1 pattern), via the `_chunked_schema_rule` mechanism (extend the categorical-style conditional pin, or an analogous date_shift-admissible param). Rationale (same as C1): date_shift output is always `strftime` strings; empty->float64 / all-null->null are pandas inference artifacts; a column's Arrow type must not depend on chunk boundaries. This creates the SAME accepted route-dependent diff C1 recorded (chunked `string` vs full-frame empty->float64), under ROUTE-OUTPUT-CONTRACT; record it. Parity: native chunked == oracle chunked (both string-pinned); whole-frame empty->float64 is the accepted route diff; values parity holds everywhere.

**3b. format_error -> fail-closed parity on the native leg.** The native branch must collect `native_date_shift`'s per-chunk `format_error_positions`, rebase batch-local -> table-global (via the per-chunk `base_row_offset`/`row_offset` already maintained in `_chunked_entry`), surface them as the engine's row-errors, and reproduce the oracle chunked leg's fail-closed `RowErrorsFailedError` byte-for-byte (same error type, same row_errors payload/locations). Since the oracle chunked leg already fails closed on date_shift format errors, the native leg matching it is PARITY, not a behavior change. Net-new: `_mask_chunk_native` gains row-error plumbing for this branch (bucket_perturb needed none). Must match the oracle's RowError trigger/reason/location exactly.
