## 1. FRAME

**Problem.** The engine can coarsen single columns (`bucketize`, `truncate`, `geo_generalize`,
`bucket_perturb`), but each is a one-shot masking strategy with one fixed coarseness. Enforcing
k-anonymity, l-diversity or t-closeness by full-domain generalization (V2-3.3) needs, per
quasi-identifier, an ordered set of coarseness levels where each level is a pure function of the
value, each coarser level only merges classes of the finer one, and the top level is full
suppression. Nothing in the engine models that, so V2-3.3 has no search space and V2-3.2's
measures have nothing to measure against.

**Definition of done.**

1. A new package `decoy_engine.anonymize.hierarchies` exports:
   - builders: `interval_hierarchy(widths)`, `band_hierarchy(cuts)`,
     `prefix_hierarchy(length, *, keep=None)`, `date_hierarchy(levels=("month", "quarter", "year"))`,
     `category_hierarchy(rows)`; each returns a frozen `Hierarchy`;
   - `Hierarchy.generalize(column, level)` for a `pandas.Series`, `pyarrow.Array` or
     `pyarrow.ChunkedArray`;
   - `check_hierarchy(hierarchy, column) -> HierarchyCheck` (frozen, value-free; never mutates);
   - `Lattice(hierarchies)` with `columns`, `heights`, `size`, `bottom`, `top`, `contains`,
     `successors`, `predecessors`, `nodes()`, and `apply(table, node)` for a `pandas.DataFrame` or
     `pyarrow.Table`.
2. Every hierarchy has levels `0..height`: level 0 returns the column unchanged; the top level
   returns `"*"` for every row, nulls included; levels in between are string labels, with nulls
   kept null. Enforced once, in the base class (section 5).
3. Monotone: for every hierarchy and every column it covers, two values with the same label at
   level `i` have the same label at level `i + 1`. Builders refuse configurations that cannot be
   monotone; `check_hierarchy` measures it on the data.
4. Deterministic and per-value: a value's label, and whether it is covered, depend only on the
   value (its type family and its value, section 4 "Value identity"), the hierarchy and the
   level, never on row order, other rows, chunking, or the pandas/Arrow route. In particular
   `1`, `1.0` and `True` are three values, as in V2-3.2.
5. Errors and reports carry no cell value, and errors carry no exception chain
   (`__cause__` and `__context__` are `None`).
6. Dark: no change to any existing source module; no config key, strategy, catalog row, planner
   check, validator, reason code, CLI change, dependency or lock change. `import decoy_engine`
   does not import the new package.

**Non-goals (recorded follow-ups, not blockers).**

- Config declaration, strategy wiring, reason codes (V2-3.3 / V2-3.1b; see the deviation above).
- The search, suppression budget and information-loss metrics (V2-3.3), microaggregation
  (V2-3.4), risk report (V2-3.5).
- Local (cell-level) recoding and data-dependent cascades such as `geo_generalize`'s k-threshold
  ZIP cascade: a cascade's output depends on other rows, so it is not a hierarchy level.
- Parsing date strings (callers parse; `bucket_perturb`'s `date_format` handling is not reused).
- Variable-length codes for prefix levels (UK postcodes): use `category_hierarchy`, or a derived
  outward-code column (section 9).
- HIPAA Safe Harbor ZIP3 restricted prefixes (`"000"`): stays in `geo_generalize`; a user can
  express it as a category hierarchy.
- Hierarchy fingerprints for evidence, serialisation of hierarchies, loading ARX CSV files from
  disk (the in-memory row form matches ARX's table layout, so a later loader is a thin reader).
- Wiring the profiler's quasi-identifier candidates to hierarchies.

**Risk: R2.** Privacy logic that a later slice will use to decide whether a release is
anonymous, plus a new public import path (API surface). Not R3: nothing is persisted, deployed or
irreversible. Rollback: revert the build commit; nothing calls the package.

## 2. Established solutions

Searches run (2026-11-07, WebSearch): "ARX anonymization hierarchy builder interval-based
order-based redaction-based"; "sdcMicro globalRecode generalization categorical
groupAndRename"; "Sweeney 2002 achieving k-anonymity generalization and suppression domain
generalization hierarchy value generalization hierarchy"; "ARX HierarchyBuilderIntervalBased
lower upper bound top bottom coding range javadoc"; "Samarati 2001 protecting respondents
identities microdata release generalization lattice distance vector; Kohlmayer Flash 2012
lattice". Fetched: ARX source `HierarchyBuilderIntervalBased.java` and
`HierarchyBuilderRedactionBased.java` (github.com/arx-deidentifier/arx, master); the PyARXaaS
user guide "creating and using hierarchies". Codebase: `grep bucketize|truncate|geo_generalize|
quasi` over `src/`, the V2-3.2 package.

Findings:

- **Hierarchies (DGH/VGH).** Sweeney 2002 ("Achieving k-anonymity privacy protection using
  generalization and suppression", IJUFKS 10(5)) and Samarati 2001 ("Protecting respondents'
  identities in microdata release", IEEE TKDE 13(6)) define a domain generalization hierarchy as
  a chain of domains D0 < D1 < ... < Dh with a generalization function from each domain to the
  next, and a value generalization hierarchy as the tree it induces; the top is a single
  suppressed value. Full-domain generalization maps a whole column to one level; the space of
  solutions is the lattice of distance vectors (one level per attribute), ordered componentwise.
- **ARX hierarchy table.** A hierarchy is a table: one row per value, then its label at each
  level, last column `*`. ARX checks that every data value has a row and that the table is a
  hierarchy (each label maps to one coarser label).
- **ARX interval builder.** Half-open intervals `[min, max[`, repeated by offset over the range;
  labels from the bounds; out-of-range values are bottom/top coded as `<bound` / `>=bound` or
  raise. Higher levels group adjacent intervals ("fanout"), so each coarse interval is a union
  of finer ones.
- **ARX redaction builder.** Level j masks j characters from the right; shorter values are padded
  to the longest value in the input; `*` is the default redaction and padding character.
- **ARX order-based / date builders.** Order-based groups ordered values; the date builder offers
  fixed granularity chains (for example day -> month -> year).
- **sdcMicro global recoding.** `globalRecode` (breaks and labels for numeric keys) and
  `groupAndRename` (merge factor levels) recode every row of a key variable the same way, not
  only rows at risk.
- **Flash / Incognito** (Kohlmayer et al. 2012; LeFevre, DeWitt, Ramakrishnan 2005) walk the
  same componentwise lattice using successors (one coordinate + 1) and predecessors, relying on
  monotonicity of k-anonymity under generalization.

**Followed.** Sweeney/Samarati DGH with a suppressed top; ARX's builder families (interval,
redaction, date, table-form categorical) and ARX's table layout for categorical rows; ARX
interval semantics (`[lo, hi)`, open ends at the outer cut points); sdcMicro's global recoding
(every row recoded the same way); the Samarati/Flash lattice of level vectors.

**Where this departs, and why.**

- Redaction pads to a **declared** `length` and refuses other lengths, instead of padding to the
  longest value seen. ARX's rule makes a label depend on other rows, which breaks per-value
  determinism and chunk independence (definition of done 4).
- Interval levels use widths that must each divide the next, instead of ARX's arbitrary fanout
  over custom intervals: one rule that keeps `bucketize` semantics and is monotone by
  construction. Arbitrary interval boundaries are covered by `band_hierarchy` (cut points, each
  coarser level a subset of the finer one: the fanout rule in another form).
- Out-of-range handling: bands always have open outer ends (ARX bottom/top coding with the outer
  cut points as bounds); there is no "raise above the label bound" mode.
- Custom code is needed because no allowed dependency implements hierarchies (ARX is Java; no new
  dependencies). It is small: each builder is a label function over distinct values.

## 3. Behaviour

**Level layout (all hierarchies).** `height = len(builder levels) + 1`. Level 0: input unchanged.
Levels `1..height-1`: the builder's labels, `str`, null stays null. Level `height`: `"*"` for
every row, null included (so the top is one class, as Sweeney's suppression requires).

| Builder | Input values | Level `i` label (1 <= i < height) | Builder refuses |
|---|---|---|---|
| `interval_hierarchy(widths=(5, 10, 20))` | int, float (pandas numeric, nullable or object of int/float; Arrow int, uint, float) | `"[lo, hi)"` with `lo` the multiple of `w_i` such that `lo <= v < lo + w_i` exactly (section 4 "Exact binning"), `hi = lo + w_i`, both Python ints printed as integers | empty widths; a width not `int` (bool, float, `np.int64`, `np.float64` refused), `< 1`; a width that is not a multiple `>= 2` of the previous one |
| `band_hierarchy(cuts=((0, 18, 30, 45, 65), (18, 65), (65,)))` | as above | `"[a, b)"` for the band holding v; `"[-inf, c0)"` and `"[cN, inf)"` for the open ends; numbers printed as ints when integral, else `repr(float)` | empty levels; a level with no cuts; a cut not `int`/`float` (bool refused) or not finite; cuts not strictly increasing; a level whose cut set is not a proper subset of the previous level's |
| `prefix_hierarchy(length=5, keep=(3, 1))` (default `keep`: `length-1 .. 1`) | `str` of exactly `length` characters | first `keep_i` characters, then `"*"` up to `length` (`"021**"`) | `length` not `int` or `< 2`; a keep not `int`, outside `1..length-1`, or not strictly decreasing |
| `date_hierarchy(levels=("month", "quarter", "year"))` | pandas datetime64 (naive or tz-aware), object of `date`/`datetime`/`Timestamp`; Arrow date32, date64, timestamp | formatted per value from its wall-time year and month: `"2024-03"`, `"2024Q1"`, `"2024"` (years zero-padded to 4 digits; equal to pandas `Period` strings for years 1000-9999); a typed tz-aware column uses its zone's wall time | empty levels; a token outside `{"month", "quarter", "year"}` (so `"week"` is refused); tokens not in that order or repeated |
| `category_hierarchy(rows=[("flu", "respiratory", "infectious"), ...])` | `str` or `int` keys (not bool, not float); a data value matches a key only in the same type family (`True` and `1.0` do not match key `1`; `np.int64(1)` does) | the row's label at column `i` | no rows; rows of different lengths or length 1; a key not `str`/`int`; a label not `str`; a key in two rows; a label at level `i` that appears with two different labels at level `i + 1` (not monotone) |

**Failure modes.**

| Situation | `generalize` | `check_hierarchy` | `Lattice.apply` |
|---|---|---|---|
| level not an `int` in `0..height` (bool refused) | `TypeError` / `ValueError` | n/a | node checked by `Lattice` first |
| column of the wrong kind (not Series/Array/ChunkedArray) | `TypeError` | `TypeError` | table not DataFrame/Table: `TypeError` |
| a non-null value the hierarchy does not cover (text in a numeric column, `inf`, a 4-char ZIP, a date string, a category key not in the rows) | `ValueError("... values the hierarchy does not cover: <count> rows")`, no value | counted in `rows_not_covered`, `covers_column = False` | `ValueError` naming the column (an identifier), count only |
| float `NaN`, `None`, `pd.NA`, `NaT`, Arrow null | null below top, `"*"` at top | counted in `rows_null`; null is its own class | same as `generalize` |
| Arrow dictionary column | decoded first, same labels as the plain column | same | same |
| Arrow float column with `NaN` | `NaN` turned to null before encoding (Arrow keeps the two apart; V2-3.2's `null_mask` does the same) | counted in `rows_null` | same |
| object column with `1`, `1.0`, `True` (any order) | three values: for `interval_hierarchy` `1` and `1.0` are covered and `True` is not, in every row order | same counts in every row order | same |
| object column holding tz-aware datetimes in more than one zone, or naive mixed with aware | `TypeError` ("mixed time zones"), in every row order | same error | same error, with the column name |
| a QI column missing from the table, or present twice | n/a | n/a | `ValueError` naming the column |
| node wrong length, not ints, out of range | n/a | n/a | `ValueError` / `TypeError` |
| empty column | empty output of the right kind | all counts 0, `monotone = True` | empty table |

`check_hierarchy` returns `HierarchyCheck(height, rows, rows_null, rows_not_covered,
covers_column, classes_per_level, monotone, first_split_level)`: `classes_per_level[i]` is the
number of distinct labels at level `i` over covered rows (null counted as one class), and
`first_split_level` is the smallest `i` where a level-`i` class maps to more than one level-`i+1`
class (`None` when monotone). Counts and booleans only.

## 4. Design notes

**Principles that apply.**

- *Open/closed, one descriptor per variant.* Hierarchy kinds will keep arriving (order-based,
  H3 cells, ZIP3 Safe Harbor). Each kind is one subclass that implements a single hook,
  `_labels(uniques, level) -> list[str | None]`, for levels `1..height-1` on distinct non-null
  values. Everything shared lives once in the base: level checking, level 0, top `"*"`, null
  handling, pandas/Arrow conversion, coverage counting, error wording. Adding a kind touches one
  new module and the package `__init__`.
- *Single responsibility.* `_base.py` (contract and column I/O), one module per builder family,
  `_check.py` (validation, never mutates), `_lattice.py` (level vectors and table application).
- *Deep module.* The public surface is five builders, one method, one check, one class.

**Pattern followed.** DGH/VGH full-domain generalization (Sweeney 2002, Samarati 2001); ARX
hierarchy builders; sdcMicro global recoding; Flash/Incognito lattice (section 2).

**API sketch.**

```python
from decoy_engine.anonymize.hierarchies import (
    Lattice, band_hierarchy, category_hierarchy, check_hierarchy,
    date_hierarchy, interval_hierarchy, prefix_hierarchy,
)

age = interval_hierarchy(widths=(5, 10, 20))         # height 4: value, 5s, 10s, 20s, *
zip_ = prefix_hierarchy(length=5)                     # height 5: 02134, 0213*, 021**, 02***, 0****, *
seen = date_hierarchy()                               # height 4: date, month, quarter, year, *
dx = category_hierarchy(rows=[("flu", "respiratory"), ("asthma", "respiratory"),
                               ("eczema", "skin")])  # height 2

report = check_hierarchy(age, df["age"])              # HierarchyCheck(..., covers_column=True, monotone=True)
age.generalize(df["age"], 2)                          # "[20, 30)", ...

lattice = Lattice({"age": age, "zip": zip_, "seen": seen})
lattice.heights   # (4, 5, 4); lattice.size == 5 * 6 * 5
node = (2, 3, 1)
out = lattice.apply(df, node)                         # new DataFrame; df unchanged
lattice.successors(node)   # ((3, 3, 1), (2, 4, 1), (2, 3, 2))
```

**Where each fact lives.** The level layout (identity, labels, `"*"`, nulls): `_base.Hierarchy.
generalize` only. Each kind's label rule and build-time refusals: its builder module only. The
column-to-level alignment of a node: `Lattice` only (`columns` is the mapping's insertion order,
stated in the docstring and fixed at construction). The suppressed token `"*"`: one constant in
`_base.py`, exported as `SUPPRESSED`.

**Routes.** pandas: `Series` in, `Series` out (same index and name; object dtype with `None` for
null at levels >= 1; level 0 returns a copy). Arrow: `Array` or `ChunkedArray` in, `pa.Array`
out (`pa.string()` at levels >= 1; chunks combined). Both routes compute labels on the same
Python list of distinct values, so they agree by construction; a test proves it.

**Value identity (one grouping rule, in `_base.py`).** Distinct values are found by
(type family, value), never by plain equality, because pandas `factorize` on an object column
merges `1`, `1.0` and `True` into whichever comes first, which made labels and coverage depend on
row order. The rule:

- Typed columns (pandas numeric, bool, datetime64, string, nullable and `ArrowDtype` columns;
  every Arrow type) hold one family, so plain factorizing is exact there.
- pandas `object` columns: each non-null cell is keyed `(type_family(cell), cell)` and the keys
  are factorized. `type_family` uses the same family table as V2-3.2's `_classes.type_family`
  (timedelta, datetime, bool, int, float, complex, decimal, str, bytes, date, time, else the
  qualified type name; Python and numpy scalars of one kind are one family). It is copied, not
  imported, because V2-3.2 is not on main; a test pins the table literally, and a recorded
  follow-up makes whichever of V2-3.1 and V2-3.2 merges second import the other's single copy.
- Time zones: in an object column, all tz-aware cells must share one zone and naive and aware
  cells must not mix; otherwise `TypeError("... mixed time zones ...")`. The check runs over every
  non-null cell before any labelling, so the outcome does not depend on row order. With one zone,
  same instant means same wall time, so V2-3.2 (which merges same-instant values) and this module
  agree on level-0 classes and level 1 never splits one of them.

**Exact binning.** Interval and band bounds are found with exact comparisons. Integers (Python
and numpy, converted with `int()` first) use Python int floor division: `lo = (v // w) * w`, no
int64 overflow for `lo + w`. Floats take a candidate `lo = math.floor(v / w) * w` (a Python int)
and then step it by `w` until `lo <= v < lo + w`, comparing the int bound to the float directly
(Python int/float comparison is exact). This fixes the cases where float division rounds across
a bound (values above 2^53, negative subnormals such as `-1.5e-323`), which would otherwise put
`v` outside its own label and split classes across levels. Bands use `bisect` over the cut tuple
with the same exact comparisons.

**Nulls.** `None`, float `NaN`, `pd.NA`, `NaT` and Arrow null are null. On the Arrow route a
float column's `NaN` is turned to null (`pc.is_nan`) before `dictionary_encode`, which would
otherwise keep `NaN` as a value.

**Determinism and memory.** `generalize` finds distinct values by the rule above (pandas
`factorize`, or Arrow `dictionary_encode` after decoding any dictionary and nulling `NaN`),
labels the distinct values in a Python loop, and takes labels back by code. Time
O(rows + distinct), plus one Python pass over the cells of an object column for the family keys;
memory one code array plus the distinct values and their labels. No RNG, no key, no dict-order
dependence: label lookups only.

**Dates.** Labels are formatted per distinct value from its own year and month
(`f"{y:04d}-{m:02d}"`, `f"{y:04d}Q{q}"`, `f"{y:04d}"`), not with `to_period`, so a tz-aware
value never triggers pandas' "dropping timezone" `UserWarning` (tests run with `-W error`), and
years below 1000 are zero-padded consistently. A typed tz-aware column (pandas or Arrow) is read
in its own zone's wall time. Values outside Python's `datetime` range are uncovered.

**Public fields for V2-3.3.** Each kind is a frozen dataclass with `kind` (a fixed token:
`"interval"`, `"band"`, `"prefix"`, `"date"`, `"category"`), `height`, and its defining fields:
`IntervalHierarchy.widths`, `BandHierarchy.cuts`, `PrefixHierarchy.length` and `.keep`,
`DateHierarchy.levels`, `CategoryHierarchy.rows`. These are documented public attributes, so
V2-3.3's information-loss metrics (for example interval width at a level, group size in a tree)
read the hierarchy and not the labels. `Lattice.hierarchies` is a read-only
`MappingProxyType` of column name to hierarchy, in `columns` order.

**Requirement handed to V2-3.3 (not built here).** The search must cache generalized columns per
(column, level): every node shares columns with its neighbours, and `generalize` costs one pass
over the column. `Lattice.apply` stays uncached and stateless here.

**Immutability.** Builders return frozen dataclasses (`slots=True`) holding tuples; the category
lookup is a `MappingProxyType` built once. `check_hierarchy` and `generalize` never write to
their input; `Lattice.apply` returns a new table (pandas: `copy(deep=False)` then column
assignment on the copy; Arrow: `set_column`).

**Errors.** `TypeError` and `ValueError` (as V2-3.2), messages fixed text plus counts, level
numbers, row counts and, in `Lattice.apply` only, the column name. Raised after any `except`
block closes (recurring defect 3). No reason codes in this slice (nothing reaches a run).

**Public surface and compatibility.** New import path `decoy_engine.anonymize.hierarchies`, not
added to `decoy_engine.__all__` (pre-GA; the top-level contract is unchanged). Consumers: V2-3.3
and the V2-3.1b config slice. The package docstring states the contract (levels, nulls, labels,
value identity). Published docs: Sphinx autoapi (`docs/conf.py`, `autoapi_dirs =
["../src/decoy_engine"]`, ignoring `*/_*.py`) will publish `anonymize/__init__.py` and
`anonymize/hierarchies/__init__.py`, including the re-exported names; their docstrings are
written as reference text. The build phase runs the docs build (`make -C docs html` with `-W`)
if the venv has Sphinx and the build fits in disk and time, and otherwise records it as skipped.

## 5. Choke points

| Rule | Choke point (by construction) | Guard test | Mutation that turns it red |
|---|---|---|---|

## 9. Known limits

- Prefix levels need fixed-length codes; variable-length postcodes need a category tree or a
  derived column.
- Dates must be typed (no string parsing); ISO weeks are not offered (not nested in months).
  Year labels are zero-padded to four digits, so years below 1000 differ from pandas `Period`
  strings (which do not pad); dates outside Python's `datetime` range are uncovered.
- An object column mixing time zones is refused rather than normalised; callers convert to one
  zone first.
- The type-family table exists twice until V2-3.1 and V2-3.2 are both on main (recorded
  follow-up: the second to merge imports the first's copy).
- Interval and band labels are strings, so the generalized column is categorical; numeric order
  is not kept in the type (V2-3.3 information-loss metrics read the hierarchy, not the labels).
- Decimal columns are refused as uncovered (Arrow `decimal128` and Python `Decimal`).
- Distinct values are labelled in a Python loop: fine for quasi-identifiers (low to medium
  cardinality); a million-distinct float column takes about a second per level. Vectorising is
  a follow-up if V2-3.3 measurement shows it matters.
- Hierarchies are data-independent by design; a level that is monotone may still be useless
  (one class). `classes_per_level` shows it; nothing refuses it.
- Generalization alone proves nothing about linkage with outside data; that limit is already
  stated for the V2-3.2 measures and is restated in the package docstring. No new entry in
  `docs/what-we-cannot-prove.md` (no accepted leak).
