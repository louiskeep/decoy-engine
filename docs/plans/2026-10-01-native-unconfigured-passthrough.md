## Problem

`run_mask_chunked` admits a table to the native route only when the source's columns are exactly the compiled plan's columns. `plan_native_route` (`execution/native/_dispatch.py` 349-367) compares `set(first_schema.names)` with the planned columns, and any difference downgrades the whole table to the oracle route with reason `uncovered_columns:[...];missing_configured_columns:[...]`. A partial-mask config is the normal shape of a real job, so most real tables run wholly on the oracle route even when every configured column has a native kernel. B2 and B7 inherit this.

What happens today with an unconfigured column on `run_mask_chunked` (code read and probes on `0bb196fa`):

- **Policy.** `unconfigured_column_policy` (DE-03, `execution/_output_projection.py`) has exactly two values, `warn` and `error`. An explicit `global_settings.unconfigured_column_policy` wins; otherwise it is `warn` while `release.is_pre_ga()` is true and `error` at GA (`resolve_unconfigured_column_policy`). `_oracle_preflight` resolves it once into `state.projection_policy`, and the stock adapter enforces it per chunk through `enforce_output_projection` (`_pandas_adapter.py` 316-324), after masking and before `Table.from_pandas`.
- **`warn`.** Each chunk's `ExecutionResult.warnings` ends with one `QualityWarning(code="undeclared_output_columns", provider="output_projection", column=None, detail={"table": ..., "undeclared_columns": <sorted>})`. The column is carried (placeholder into the adapter, source column out). No timing record and no vault entry exist for it.
- **`error`.** The adapter raises `ExecutionError(code="undeclared_output_columns")` at the first `next()`, after chunk 0's node masking and before any sink append or vault entry (B1 test 18 pins this against the public oracle).
- **"Unconfigured".** A source column absent from the table's `columns:` list (a listed column without a strategy is a config `ValidationError`). The undeclared set is `source columns - known_output_columns(plan, table)`.
- **Output.** Already the source column on both routes, with the first chunk's field, in source order (B1 guarantee 2(b)).
- **The native masker cannot take one.** `_mask_chunk_native` (`_chunk_masking.py` 176-178) indexes `col_seed_by_name[name]` for every column of the chunk, so an unconfigured column would raise `KeyError` once admitted. The native loop builds `ExecutionResult(warnings=())` (`_chunked_entry.py` 224), so it never emits the DE-03 warning.
- **Admission crash waiting behind the veto (new finding).** `real_type_rejection` (`_real_type_admission.py` 53) builds `first_schema.empty_table()` over the whole schema. `Schema.empty_table` raises `ArrowNotImplementedError` for a `dense_union` or `sparse_union` field and for `run_end_encoded<string_view>` (`b8r2_probe_trace.out` traces `dense_union` and `run_end_encoded<string_view>` to that line; `b8r2_probe_types.out` shows the same error for `sparse_union`). Today an unconfigured column never reaches it (the veto comes first), and the oracle route carries such a column exactly (`b8r2_probe_types.out`). Lifting the veto without a fix would turn those working calls into a raw exception at call time. The same line is why a configured union passthrough column raises on `run_mask_chunked` today (B1 known issue L3).
- **Read-set false positive on a native table (new finding).** B1 rule R2(b) puts a passthrough column in the read set when its name equals any string value in another configured column's entry (a deliberate over-approximation, B1 known issue rev9.1). On a native-admitted table nothing reads it, so the native route returns the source column, while the oracle route converts it through pandas. Probe `b8r2_probe_readfp.out`: configured passthrough `redact` beside `redact("s")`, with a `time64[ns]` value that is not a whole microsecond in chunk 1, completes on the native route and raises `chunked_passthrough_value_unrepresentable` at chunk 1 when the oracle route is forced. This divergence exists in B1 today for configured passthrough; lifting the veto would extend it to unconfigured columns (today an unconfigured `redact` column takes the oracle route and raises). Codex reran the probe at the revision 2 gate: the divergence exists only for the false-positive column. A genuine `when:` reader never runs natively, so it has no native-completes, oracle-raises case. Design 4 removes the false positive at its source.
- **Composite writers outside the column entry's own fields (revision 4 finding).** `CompositeHandler` (`execution/_strategies/_composite.py`) is not in `SCALAR_HANDLERS`; the stock adapter dispatches it for every work node of kind `composite`, which `build_work_list` assigns whenever the provider is a composite (`provider_is_composite`), whatever the `strategy` string says. It writes every column of the generator's bundle (`_composite.py` 132-144). Two shapes write columns that no `coherent_with` names. (1) `composite_custom` writes every `provider_config.bundle[*].column`, and `composite_wiring_consistent` skips the group-versus-outputs check for it (`generation/composite/_validate.py` 54-57): with coherent group `a,b` and bundle `a,b,c`, the full-frame pipeline replaces an unconfigured or configured-passthrough `c = "SECRET"` with a generated phone number (Codex round 2; `b8r4_probe_carry.out`). (2) A fixed composite on a lone column with no `coherent_with` skips `composite_wiring_consistent` entirely (it only checks entries with a nonempty `coherent_with`, 72-74) and still writes every canonical output column: `composite_name_email` on `first_name` alone overwrites unconfigured `last_name` and `email`; `composite_city_state_zip` on `city` alone overwrites `state` and `zip` (`b8r4_probe_fixed_lone.out`). Today's broad `read_set` catches (1) (`bundle[*].column` is a string value) but not (2) (no entry names `last_name`). Revision 3's narrowed scan would miss both, carry the column and let `CarryPlan.reattach` (`_chunked_carry.py` 142) put the source value back over the generated one: silent cleartext. Reachability today, as corrected by revision 4.4 (the earlier text said neither shape completes, which was false): strategy `<composite>` is refused by `check_chunked_compatibility` with `strategy_not_chunk_safe`; strategy `faker` with a composite provider may fail during pool warming with a raw `CompositeError`; a composite provider on `redact`, `hash` or `passthrough` currently passes the strategy-string check, completes, and can leak the other bundle columns as source values through `normalize_chunk` (dennis BLOCKER, reproduced on main `d438e47a`). The hazard is therefore live on main for the third case; Design 12 closes it at the source (12.1) and in both carry paths (12.2).
- **Feasibility.** A probe-only prototype (`b8r2_probe_prototype.py`: `plan_native_route` sees the configured fields only, and the masker passes every other column through) admits every one of the 134 catalogue cases (67 types, with and without a null) as an unconfigured column beside redact, truncate and hash, with a zero-row middle chunk, and every yielded chunk `equals` today's oracle-route chunk with `check_metadata=True`. Only the warnings differ (none on the prototype's native route), which Design 6 fixes.

## Guarantee (pinned) and non-goals

For every `run_mask_chunked` call, with the same config and chunks:

1. **Routing by policy.** Under the resolved policy `warn`, a table whose only obstacle to native admission was unconfigured source columns (every configured column natively admitted, no configured column missing from the source, cross-check passes (Design 5)) runs on the native route with `reroute_reason` null. Under `error` the routing is unchanged (oracle route, reason byte for byte as today) and the call raises `undeclared_output_columns` exactly as today. A configured column missing from the source vetoes with the unchanged reason. The policy comes from `state.projection_policy`, the value the oracle route uses, so explicit settings and the pre-GA default route identically, and at GA the admission switches off without a code change.
2. **Output identity with the oracle route.** On a table B8 admits, every yielded chunk equals the chunk the oracle route of `run_mask_chunked` yields for the same input (the oracle route forced by a missing companion with a hash column present, or by B1's `categorical("cat_force")` column, which is dropped before comparing): `Table.equals(..., check_metadata=True)`, so values, nulls, row order, Arrow types, field nullability and field metadata, column order, and no schema metadata.
3. **Warnings.** Each chunk's `ExecutionResult.warnings` on the native route equals the oracle route's for the same chunk: the same `QualityWarning` values in the same order, one DE-03 warning per chunk under `warn`. The native route produces it by calling `enforce_output_projection` itself, never a copy of its logic.
4. **Side channels.** Vault entries, `chunk_result_sink` appends (one per chunk, before the yield), `timings` (no record for an unconfigured column on either route), `base_row_offset` and `route_evidence_sink` behave as B1 guarantees 4 to 6 state. An unconfigured column is never listed in `quality_metrics["chunked_route"]["columns"]` (B1 design item 6); an admitted table reports `native_admitted: true`, `reroute_reason: null` and `pandas_read_passthrough: []`.
5. **Errors.** Drift (`native_chunk_schema_drift`), leading null type (`chunked_leading_null_type`) and the per-chunk ingest guards apply to unconfigured columns exactly as B1 pins them, on both routes, at the same chunk, with the same sink appends before the raise. A later all-null chunk of a type with no cast from `null` (list views, run-end-encoded) raises the same raw `ArrowNotImplementedError` on both routes with one sink append before it (`b8r2_probe_nullcast.out`; pinned, not changed by B8).
6. **Evidence of the route.** Every test that compares outputs also asserts the route each side took (`NativeRouteEvidence.native_admitted` and `reroute_reason`), so a case cannot pass with both sides on the oracle.

Non-goals: a `drop` policy or any new policy value; native execution under `error`; per-column evidence entries for unconfigured columns (the warning names them, and B2 pinned the evidence keys); the legacy `run_native_or_oracle_chunked` (callers are tests only; it keeps the veto); the public oracle changes only through the shared composite-provider refusal and stored-index preflight (Design 12.1, 12.4); its masking semantics and DE-03 warning remain unchanged; any change to the route, reason or coded errors of a genuine reader (a `when:` predicate or a sibling-reference field); widening native admission for any configured strategy; platform or CLI wiring (B3, B4); the Phase E 100M gate.

## Design

### 1. Policy routing (pinned)

| Resolved policy | Table shape | Route | Reason | Outcome |
|---|---|---|---|---|
| `warn` (explicit, or unset pre-GA) | unconfigured columns only | native, when every other admission check passes | `null` | source columns carried, one warning per chunk |
| `warn` | unconfigured columns and a configured column missing from the source | oracle | `uncovered_columns:[...];missing_configured_columns:[...]` (unchanged) | as today |
| `error` (explicit, or unset at GA) | unconfigured columns | oracle | `uncovered_columns:[...];missing_configured_columns:[]` (unchanged) | `undeclared_output_columns` at the first `next()`, as today |
| any | no unconfigured columns | as B1 | as B1 | as B1 |

`error` keeps the oracle route: the oracle raises inside `adapter.run` after node masking, so a handler error on chunk 0 takes precedence over the projection error. Reproducing that ordering on the native route gains nothing, since the call fails on chunk 0 either way.

### 2. Admission (`plan_native_route`)

`plan_native_route` gains a keyword `unconfigured_policy: Literal["warn", "error"] | None = None`. `None` keeps today's behavior, so admission-only callers, the legacy entry point and the existing `plan_native_route` tests are unaffected. With `first_schema` given:

- `stored = stored_index_fields(first_schema)` (revision 4.2); `uncovered = [n for n in first_schema.names if n not in covered and n not in stored]` (source order); `missing = covered - set(first_schema.names)`. A stored index field is neither covered nor unconfigured: like the oracle route, where pandas consumes it as the index, the native route never yields it (Design 6). A config that references a stored index field already fails with the existing `config_references_stored_index` code; B8 does not change that path.
- If `missing` is non-empty, or `uncovered` is non-empty and `unconfigured_policy != "warn"`: downgrade with today's reason string, byte for byte.
- Otherwise the table stays admitted, and `NativePreflight` gains `unconfigured_passthrough: tuple[str, ...] = ()` holding `uncovered`. `NativeRouteEvidence` and `NodeRouteRecord` are unchanged (B1 test 8a).
- The faker source-type check, `real_type_rejection` (Design 3) and the companion probes then run as today.

`_run_chunked` passes `unconfigured_policy=state.projection_policy` when `enforce_schema_rule=True` (`run_mask_chunked`) and `None` for the legacy entry.

### 3. `real_type_rejection` reads only the columns it checks

`real_type_rejection` builds its resident table from the hash nodes' fields only: `pa.schema([first_schema.field(n.column) for n in node_routes if n.strategy == "hash"]).empty_table()`. `hash_config_rejection` resolves the input type of the one column it is given (`resolve_input_arrow_type(table, name, ...)`); the build confirms by reading it that no other column of the resident table is consulted, and a unit test pins equal reasons before and after for every hash source type in `tests/native/test_chunked_entry_parity_matrix.py` (string, dictionary, date32, decimal128 and the rest of its sources). This removes the crash for union and `run_end_encoded<string_view>` passthrough columns, configured or unconfigured, at its source instead of adding a type list in front of it.

No passthrough type allowlist is added. Evidence: on `0bb196fa` the native route returns the source column exactly for every catalogue type as configured passthrough apart from the three crashing types (`b8r2_probe_types.out`), and the prototype returns oracle-equal chunks for all 67 as unconfigured columns (`b8r2_probe_prototype.out`). The native route never inspects a carried column's values, so the type cannot change the output. Acceptance test 3 runs the whole catalogue on both routes; a type that diverges there stops the build for a plan revision, it is not filtered out.

Consequence for B1: a configured union or `run_end_encoded<string_view>` passthrough column on `run_mask_chunked` stops raising `ArrowNotImplementedError` and runs natively, returning the source column (B1 known issue L3 resolved for passthrough). A union hash column still reaches `empty_table` for its own field and raises as today.

### 4. The read set holds actual references only

The revision 2 veto is withdrawn. The divergence in the "read-set false positive" finding comes from B1 rule R2(b) collecting strings that are not column references, so B8 fixes `read_set` (`execution/_chunked_carry.py` 102-123) and `_predicate_names` (66-88) instead of rerouting tables around them. No reroute reason is added for read columns. Genuine readers keep exactly the route, reason and coded errors they have today: a nonblank `when:` vetoes native admission (`when_predicate_not_native:<column>`, `_dispatch.py` 334), and every sibling-reading strategy is vetoed or has no admitted kernel on `run_mask_chunked`.

**Predicates.** `_predicate_names` keeps pandas' tokenizer and NFKC normalization and collects `NAME` tokens and backtick-quoted spans only. A `STRING` token no longer contributes its contents: `s == 'x'` does not read `x`. A string token that is not a plain `str` literal (`ast.literal_eval` fails or yields a non-`str`, for example an f-string prefix) still returns `None`, as does any tokenizer failure, so every passthrough column of the table is read. Under-collecting a predicate name would hand the predicate a null placeholder and leave the masked column silently unmasked, so the conservative cases stay conservative.

**Config fields: one declaration per dispatch surface.** `read_set` stops walking every string value of every entry. Instead, every pandas-route surface that can read or write a DataFrame column declares which columns it touches, and `read_set` takes the union of those declarations. This is the second finding of the class "a handler reads or writes a column the scanner did not know about" (round 1: the scalar sibling fields; round 2: composite outputs), so the fix is structural rather than another field added to a list.

The shared function is `column_access(entry: Mapping[str, Any]) -> ColumnAccess`, a free function in a new module `execution/_column_access.py`. `ColumnAccess` is a frozen dataclass with `reads: frozenset[str]`, `writes: frozenset[str]` and `everything: bool` (true when the declaration cannot be computed, for example an unparsable expression or a malformed bundle; the caller then treats every passthrough column as read). `column_access` first determines whether the provider is composite, exactly as `build_work_list` does. For a composite provider it returns the composite declaration; `_dispatch_mask_node` does not invoke `run_with_when_gate` for composite nodes, so a `when:` value does not replace or narrow that declaration. Otherwise it obtains the scalar-handler declaration and, when `when:` is nonblank, unions the predicate declaration with the scalar declaration because `run_with_when_gate` evaluates the predicate and then invokes that handler on the matching subset. Malformed predicate parsing keeps `everything=True`. Each surface's declaration is a free function registered in one table, `SURFACE_DECLARATIONS`, keyed by surface name. `read_set` becomes: for every other configured entry (the entry's own `name` excluded), `access = column_access(entry)`; if `access.everything`, every passthrough column is read; otherwise `access.reads | access.writes` is added to the read set. A written column counts as read because carrying it would let `CarryPlan.reattach` overwrite the handler's output with the source value. The module holds `SIBLING_REFERENCE_KEYS` (`group_by`, `order_by`, `anchor`, `reference_column`), moved from the inline tuple in `_required_input_columns` (`execution/native/_requirements.py` 286-299), which now iterates the imported constant so the two cannot drift. (`_requirements.py` is at its 648-line baseline in the module-size sentry; replacing the inline tuple with an import keeps it there.)

### 5. Cross-check against the oracle's own definition

Before committing the native route, `_run_chunked` checks that `set(first.schema.names) - known_output_columns(state.plan, table) - stored_index_fields(first.schema)` equals `set(preflight.unconfigured_passthrough)`. If not, the table downgrades with reason `unconfigured_set_mismatch:<sorted oracle set>:<sorted native set>`. It is kept because the two sets drive different things: the native masker passes through the columns it has no plan node for, while the warning (and, under `error`, the refusal) is computed from `known_output_columns`. If they ever disagree (an FK group's coherent columns, which `known_output_columns` includes and the node list does not), a column could be passed through unmasked with no warning. FK tables veto earlier today, so production cannot reach the branch; a test reaches it by patching `known_output_columns`. It is one set comparison per call.

### 6. Native masking and warnings

- `_native_route` passes `unconfigured=frozenset(preflight.unconfigured_passthrough)` to `_mask_chunk_native`. In its loop over `chunk.schema.names` (source order), a name in `unconfigured` gets `arrays[name] = chunk.column(name)`: no kernel, no timer, no `kernel_calls` entry, no `column_elapsed_s` entry, no `col_seed_by_name` lookup. A name in `stored_index` (the first chunk's `stored_index_fields`, passed as `stored_index=frozenset(...)`, revision 4.2) is skipped: it gets no array and is absent from the yielded chunk, exactly as on the oracle route, so `enforce_output_projection` never sees it and no warning names it. The docstring precondition becomes "every column name is planned, listed in `unconfigured`, or listed in `stored_index`". `normalize_chunk` then takes the source column and the first chunk's field, as on the oracle route.
- Per chunk, after `normalize_chunk` and before the sink append, the native route computes `warnings = tuple(enforce_output_projection(table, out.column_names, state.plan, state.projection_policy))` and puts it in the chunk's `ExecutionResult.warnings`. It is computed whether or not a sink is given, so the function stays the single enforcement point (under `warn` it cannot raise; the call is also the backstop if a later change ever admitted a table under `error`).
- Native-admitted strategies are not expected to emit handler warnings on the oracle route; acceptance test 2 compares whole warning tuples across routes for every admitted strategy, and a mismatch is a finding to stop on, not something to filter.

**12.2 Defense in depth: no handler-written column is ever a carry or schema-rule passthrough column (revision 4.4, Codex).** Add one registry-bound helper, `handler_written_columns(entries, registry) -> frozenset[str] | None`, derived from each entry's `column_access(...).writes`; `None` means every source field is potentially written, and it is returned only when some declaration has `writes_unknown` (Design 12.8); an unknown read never empties the passthrough sets. Both `passthrough_columns(..., registry)` and `build_schema_rule(..., registry)` (`native/_chunked_schema_rule.py` 55, which today marks every unconfigured or configured-passthrough field as passthrough independently of `passthrough_columns`) consume this same result. `passthrough_columns` excludes every declared or potentially written field from `CarryPlan.carried`; `build_schema_rule` excludes the same fields from `SchemaRule.passthrough_types` and `passthrough_fields`. `_run_chunked` passes `state.registry` to both paths. Consequently neither `CarryPlan.reattach`, including its row-error sink path, nor `normalize_chunk` can restore a source value over a handler-written value. `touched_columns` also retains an entry's own name when that declaration writes columns beyond its own field.

**12.3 One registry for declarations (HIGH 1).** `column_access(entry, registry)`, `read_set(..., registry)`, `touched_columns(..., registry)`, `handler_written_columns(..., registry)`, `passthrough_columns(..., registry)`, `build_schema_rule(..., registry)` and `plan_carry(..., registry)` take the resolved registry that `build_work_list` receives; `_chunked_oracle.py` resolves it before `plan_carry`. No call uses `get_default_registry()` implicitly. The composite branch also unions the entry's `when:` predicate names when `has_when(entry)`, so the declaration stays conservative.

**12.4 Configured stored-index column (HIGH 2; revision 4.4, Codex).** Resolve the caller/default registry at the start of `_oracle_preflight`, before `check_chunked_compatibility`. After pulling the first chunk, but before `plan_carry`, `first_chunk_profile`, `compile_plan`, pool warming, or route selection, call a shared `reject_config_references_stored_index(config, table, first.schema, resolved_registry)`. It raises `TransformError(code="config_references_stored_index")` when a stored-index field matches a configured column name or a registry-bound `column_access` read. Matching uses the same NFKC treatment as `read_set`; an `everything` declaration rejects when any stored-index field exists. Because both public chunked entries use `_oracle_preflight`, both fail with the coded error before masking, output, or sink append. (Revision 4.3 placed this in `_run_chunked`, after profiling, where `to_pandas()` already consumed the index and compilation could raise a raw `KeyError` first.)

**12.5 Stored-index drift (MEDIUM 1).** `validate_chunk_schema` compares `stored_index_fields(chunk.schema)` with the first chunk's and raises `native_chunk_schema_drift` on a mismatch. Both routes share `validated_rest`, so the error, chunk index and sink appends before it are equal on both routes.

**12.7 Guard corpus (MEDIUM 3, LOW 1).** G5's corpus adds a composite provider on each of `redact`, `hash` and `passthrough`, and an accepted scalar sibling-reading strategy combined with `when:`. **12.8 Reads-unknown versus writes-unknown, and the round-2 items (revision 4.5).**
- `ColumnAccess.everything` is replaced by two flags. `reads_unknown`: the declaration cannot name what the entry reads (an unparsable `when:` predicate, an unparsable sibling expression). `writes_unknown`: it cannot name what the entry writes (an undeclared strategy, a malformed bundle, a composite provider whose bundle cannot be resolved). A composite with an unparsable `when:` sets both only if its bundle is also unresolvable; otherwise it sets `reads_unknown` and declares its writes. Every place that read `everything` is rewritten to the flag it means.
- `handler_written_columns` returns `None` only when some declaration has `writes_unknown`. `reads_unknown` keeps every passthrough candidate in the carry and schema-rule passthrough sets and puts all of them in `read` (today's broad behavior for an unparsable predicate, restored), so `normalize_chunk` still restores the source column and `pandas_read_passthrough` reports them.
- `reject_config_references_stored_index` refuses only on a positive reference: a configured column name or a declared read that names a stored index field. A `reads_unknown` declaration does not refuse (the predicate runs on the oracle route exactly as before B8); a `writes_unknown` declaration does not refuse either, because 12.1 already refuses every unresolvable composite.
- Required registry (dennis MEDIUM-1): `check_chunked_compatibility`, `composite_provider_offenders` and `_legacy_route_evidence` take `registry` as a required keyword with no default. Only the public `run_*` entry points default to `get_default_registry()`. The direct test call sites pass `registry=get_default_registry()` explicitly (additive, not a weakening).
- Public-entry drift (dennis MEDIUM-2, pre-existing): the stored-index drift check of 12.5 runs for later chunks on `run_mask_pipeline_chunked` too, through the shared preflight state, so both public entries raise `native_chunk_schema_drift` at the same chunk.
- Route evidence registry (dennis LOW-1): `plan_native_route` and `_chunked_evidence` use `state.registry`, so a rebound composite name is reported with the route it actually runs.
- Docs (dennis LOW-2): the CHANGELOG sentence saying composite-written columns are in the read set is corrected (they are excluded from the passthrough candidates, so never carried); acceptance 6(c)(ii) and (iii) below are updated to the 12.1/12.2 contract: a faker-strategy composite raises `strategy_not_chunk_safe`, and composite-written columns are not in `carry.read` because they are never passthrough candidates.

## Known issues (tech debt, not blockers)

- The read set depends on the per-surface declarations of Design 4. G1 to G4 fail when a strategy, composite provider, dispatch branch, node kind or frame-setup helper appears without a declaration, and G5 runs the handlers to catch an undeclared access, but a strategy that gains a new sibling field inside an existing declaration is caught only by G5's corpus, so the corpus is extended with any such field.
- After Design 12.1, every registry-classified composite provider is refused by both public chunked entries regardless of strategy string. (Before revision 4.3 this item claimed every composite was already refused; that was false, see Design 12.)
- A lone composite with `when:` silently ignores the predicate on the pandas route: the compiler accepts it, and `_dispatch_mask_node` sends composite nodes to `CompositeHandler` without `run_with_when_gate`, so every canonical output is written whatever the predicate says. B8 declares the full composite read set so the carry cannot restore source values; a separate follow-up should either honor the predicate or reject the combination at compile time.
- A fixed composite on a lone column with no `coherent_with` passes `composite_wiring_consistent` and writes columns the config never names. B8 only stops the carry from undoing that; whether the compiler should reject it is a separate follow-up.
- A later all-null chunk of a type with no cast from `null` (`list_view`, `large_list_view`, `run_end_encoded`) raises a raw `ArrowNotImplementedError` on both routes (B1 behavior, now reachable natively for unconfigured columns). Coding it as `chunked_schema_mismatch` would be a separate B1 follow-up.
- A union hash column still raises `ArrowNotImplementedError` from `real_type_rejection`'s resident table for its own field.
- Under `error`, a table with unconfigured columns still pays the oracle's chunk-0 masking before raising.
- The legacy `run_native_or_oracle_chunked` keeps the veto for unconfigured columns (tests only). Since revision 4.2 a stored pandas index field is not an unconfigured column on either entry, so a legacy-entry table whose only extra field is a stored index field is admitted natively and drops the field, as the oracle does (acceptance test 18 pins it).
- The B8 benchmark measures the dispatcher directly; the `run_pipeline` effect arrives through B2 and B7 and is measured there.
