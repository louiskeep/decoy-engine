# Native admission for unconfigured passthrough columns (Rust engine program B8)

Status: plan (revision 1)

Date: 2026-10-01. Program: `docs/plans/2026-09-30-rust-engine-program.md`, Phase B, item B8. Branch `feat/native-unconfigured-passthrough`, created at the B1 final head `7aab160f` (B1 plan revision 7 plus the rev8 notes, `docs/plans/2026-10-01-dispatcher-production-contract.md`). B8 composes with B2 (`docs/plans/2026-10-01-dispatcher-auto-chunk.md` rev3.1, branch `feat/dispatcher-auto-chunk`) and B7 (`docs/plans/2026-10-01-multi-table-dispatch.md` rev2, branch `feat/multi-table-dispatch`); both name B8 as the fix for their `uncovered_columns` known issue. The program orders B8 after B2 and B7 and before B3 and B4 activation.

## Problem

`run_mask_chunked` (B1) admits a table to the native route only when the source's columns are exactly the columns of the compiled native plan. `plan_native_route` (`execution/native/_dispatch.py` ~351) compares `set(first_schema.names)` with the planned scalar columns, and any difference downgrades the whole table to the pandas oracle route with reason `uncovered_columns:[...];missing_configured_columns:[...]`. A partial-mask config (mask four columns, leave the other twenty alone) is the normal shape of a real job, so most real tables run wholly on pandas even when every configured column has a native kernel. B2 and B7 inherit this: their dispatched tables carry `uncovered_columns` and get none of the speedup.

What the oracle does with an unconfigured column today (code read and probes on 2026-10-01, pyarrow 25.0.1, pandas 2.3.3, companion venv; scripts and output in the session scratchpad, `b8_probe_types.py`, `b8_probe_edges.py`, `b8_probe_roundtrip.py`, `b8_probe_chunk0.py`, `b8_probe_missing.py`):

- **Policy.** `unconfigured_column_policy` (DE-03, `execution/_output_projection.py`) has exactly two values, `warn` and `error`. There is no `drop`. An explicit `global_settings.unconfigured_column_policy` wins; otherwise it resolves to `warn` while `release.is_pre_ga()` is true and to `error` at GA (`resolve_unconfigured_column_policy`). `_oracle_preflight` resolves it once (`state.projection_policy`) and the pandas adapter enforces it on every chunk through `enforce_output_projection`, after masking every node and before `Table.from_pandas`.
- **`warn`.** The column passes through. Each chunk's `ExecutionResult.warnings` gets exactly one `QualityWarning(code="undeclared_output_columns", provider="output_projection", column=None, detail={"table": <table>, "undeclared_columns": <sorted names>})`, appended after any handler warnings. No timing record and no vault entry exist for the column.
- **`error`.** The adapter raises `ExecutionError(code="undeclared_output_columns")` on chunk 0, at the first `next()`, after the ingest guards and node masking ran and before anything is appended to the sink or the vault.
- **"Unconfigured".** Config validation requires a `strategy` on every listed column (a strategy-less entry is a `ValidationError`), so an unconfigured column is exactly a source column absent from the table's `columns:` list. The undeclared set is `source columns - known_output_columns(plan, table)`.
- **Values, types and order on `run_mask_chunked`.** B1's schema rule (guarantee 2(b), `_chunked_schema_rule.py`) already yields an unconfigured column as the source column itself on both routes, with the first chunk's field (type, nullability, field metadata), so the vetoed route's output is the source column, in source column order, with no schema metadata. The public oracle `run_mask_pipeline_chunked` gives the pandas round-trip type instead (int8 with nulls to `double`, uint64 maximum to a rounded `double`, `large_string` to `string`, `time32` to `time64[us]`, `date64` to `date32`, `decimal128(38,10)` to `decimal128(28,10)`, `decimal256` to `decimal128`, `fixed_size_binary` to `binary`, dictionary int32 indices to int8). That difference is B1's, and B8 does not change it.
- **Value-dependent oracle refusals (new finding).** The oracle's per-chunk `to_pandas` raises for some values of some types: `time64[ns]` with a value that is not a whole microsecond (`ArrowInvalid: ... has non-zero nanoseconds`), and `date32` or `date64` outside Python's `date` range, years 1 to 9999 (`ValueError: year 5881580 is out of range`), including such a value anywhere in a dictionary's value array. On chunk 0 the same conversion runs in `first_chunk_profile`, so both entry points raise the same uncoded error in preflight. On a later chunk, the oracle route raises before that chunk is yielded, while B1's native route, which admits configured passthrough of these types, yields every chunk (`b8_probe_edges.py` case A, `b8_probe_chunk0.py`). That is a pre-existing break of B1 guarantee 1 ("an input the oracle masks or refuses is masked or refused the same way") for configured passthrough. Admitting unconfigured columns natively without fixing it would spread the break to every table with an unconfigured date column.
- **Nested types (known issue from B1).** A `list`, `large_list`, `fixed_size_list`, `struct`, `map` or `list<struct>` column with any non-null value in chunk 0 makes `first_chunk_profile` raise an uncoded `TypeError` ("unhashable type") in the shared preflight, on both entry points, configured or not, before any route is chosen or any evidence is emitted. When chunk 0 is all null the profile passes and the oracle route masks the table.

## Guarantee (pinned) and non-goals

For every `run_mask_chunked` call, with the same config and chunks:

1. **Routing by policy.** Under the resolved policy `warn`, a table whose only obstacle to native admission is unconfigured source columns (every configured column natively admitted, no configured column missing from the source, every passthrough column's type in the admitted set of Design 3) runs on the native route. Under `error` the routing is unchanged from B1 (oracle route, reason unchanged) and the call raises the oracle's `undeclared_output_columns` error exactly as today. A configured column missing from the source still vetoes with the unchanged reason. The policy is read from the same resolver the oracle uses (`state.projection_policy`), so explicit settings and the pre-GA default route identically, and at GA the native admission switches off by itself.
2. **Output identity with the oracle route.** On a table B8 admits, the yielded chunks equal, chunk by chunk, what B1's oracle route of `run_mask_chunked` yields for the same input: `Table.equals(..., check_metadata=True)` (values, nulls, row order, Arrow types per B1 rule 2(b), field nullability and field metadata, column order, no schema metadata). The comparison with the public oracle `run_mask_pipeline_chunked` is B1's: equal values, with B1's stated exception for nullable integers above 2^53, and B1's types.
3. **Warnings.** Each chunk's `ExecutionResult.warnings` on the native route equals the oracle route's for the same chunk: same `QualityWarning` objects (code, provider, column, detail including the sorted undeclared list), same count (one per chunk), same position. The native route produces it by calling the same `enforce_output_projection` function, never a copy.
4. **Side channels.** Vault entries, `chunk_result_sink` appends (one per chunk, before the yield), `timings` (no record for an unconfigured column on either route), `base_row_offset` handling and `route_evidence_sink` behave as B1 guarantees 4 to 6 state, on both routes. An unconfigured column is never listed in `quality_metrics["chunked_route"]["columns"]` on either route (B1 design item 6, unchanged); admitted tables report `native_admitted: true` and `reroute_reason: null`.
5. **Refusals.** A passthrough value the oracle's pandas conversion refuses (Design 4) raises `ExecutionError(code="chunked_passthrough_value_unrepresentable")` on both routes of `run_mask_chunked`, configured or unconfigured, at the same chunk index, with the same number of chunks yielded, sink appends and vault entries before it as the public oracle's uncoded refusal. Drift (`native_chunk_schema_drift`), leading null type (`chunked_leading_null_type`) and the per-chunk ingest guards apply to unconfigured columns exactly as B1 pins them.
6. **Evidence of the route.** Every acceptance test that compares outputs also asserts the route each side took (`NativeRouteEvidence.native_admitted` and `reroute_reason`), so a case cannot pass by quietly running both sides on the oracle.

Non-goals: a `drop` policy or any new policy value; changing the oracle `run_mask_pipeline_chunked`, `_oracle_preflight`, `first_chunk_profile` or the DE-03 warning; native execution under the `error` policy; per-column evidence entries for unconfigured columns (the warning already names them, and B2 pinned the evidence keys); the legacy `run_native_or_oracle_chunked` (callers are tests only; it keeps the veto); fixing the nested-type `TypeError` in `first_chunk_profile` (Design 8); widening native admission for any configured strategy; platform or CLI wiring (B3, B4); the Phase E 100M gate.

## Design

### 1. Policy routing (pinned)

| Resolved policy | Table shape | Route | Reason | Outcome |
|---|---|---|---|---|
| `warn` (explicit, or unset while pre-GA) | unconfigured columns only | native, when every other admission check passes | `null` | source columns passed through, one warning per chunk |
| `warn` | unconfigured columns and a configured column missing from the source | oracle | `uncovered_columns:[...];missing_configured_columns:[...]` (unchanged) | as today |
| `error` (explicit, or unset at GA) | unconfigured columns | oracle | `uncovered_columns:[...];missing_configured_columns:[]` (unchanged) | `undeclared_output_columns` raised on chunk 0, as today |
| any | no unconfigured columns | as B1 | as B1 | as B1 |

`error` keeps the oracle route because the two routes are not trivially identical there: the oracle raises inside `adapter.run`, after node masking, so a handler error on chunk 0 takes precedence over the projection error. Raising the projection error from the native route would need that ordering reproduced, for no throughput gain (the call fails on chunk 0 either way).

### 2. Admission (`plan_native_route`)

`plan_native_route` gains a keyword `unconfigured_policy: Literal["warn", "error"] | None = None`. `None` keeps today's behavior (admission-only callers, the legacy entry point and existing `plan_native_route` tests are unaffected). With `first_schema` given:

- `uncovered = [n for n in first_schema.names if n not in covered]` (source order) and `missing = covered - set(first_schema.names)`.
- If `missing` is non-empty, or `uncovered` is non-empty and `unconfigured_policy != "warn"`: downgrade with today's reason string, byte for byte.
- Otherwise the table stays admitted, and `NativePreflight` gains `unconfigured_passthrough: tuple[str, ...] = ()` holding `uncovered`. `NativeRouteEvidence` and `NodeRouteRecord` are unchanged (B1 test 8a).
- The faker source-type check, `real_type_rejection` and the new passthrough type check (Design 3) then run as today, followed by the companion probes.

`_run_chunked` passes `unconfigured_policy=state.projection_policy` when it runs for `run_mask_chunked` (`enforce_schema_rule=True`), and `None` for the legacy entry.

**Cross-check against the oracle's own definition.** Before committing the native route, `_run_chunked` asserts that `set(first.schema.names) - known_output_columns(state.plan, table)` equals `set(unconfigured_passthrough)`. If they differ (an FK group's coherent columns, or any future way the seed envelope and the native plan disagree), the table downgrades with reason `unconfigured_set_mismatch:<sorted oracle set>:<sorted native set>`. Today FK tables are vetoed earlier, so this branch is unreachable in production; a test reaches it by patching `known_output_columns`.

### 3. Passthrough type admission (configured and unconfigured alike)

`real_type_rejection` reads only planned nodes, so an unconfigured column never reaches the hash or faker checks, and nothing in B1 vetoes it by type. B8 adds one rule in `_real_type_admission.py`, `passthrough_type_rejection(first_schema, passthrough_columns)`, over every passthrough column the schema rule classifies (configured passthrough without `when:`, and unconfigured), in source order. The first column whose type is not admitted returns `passthrough_type_not_native:<column>:<type>`, and the table takes the oracle route.

Admitted (narrower, never wider; the characterization fixture of acceptance test 0 is the specification and these are the expected entries): `null`; `bool`; int8 to int64 and uint8 to uint64; float16, float32, float64; `string`, `large_string`, `string_view`; `binary`, `large_binary`, `fixed_size_binary`, `binary_view`; decimal128 and decimal256 (decimal32 and decimal64 if the installed pyarrow has them and the fixture covers them); `date32`, `date64`, `time32`, `time64` (value guard, Design 4); `timestamp` in every unit, with and without a time zone; `duration` in every unit; `month_day_nano_interval`; `dictionary` whose value type is admitted, with any integer index type.

Not admitted: `list`, `large_list`, `list_view`, `large_list_view`, `fixed_size_list`, `struct`, `map`, dense and sparse `union`, `run_end_encoded`, every extension type (`arrow.uuid`, `arrow.json`, opaque, tensors, user extensions), the other interval types, and any type the fixture does not cover. Nested types mostly never get here (Design 8); extension types pass through the oracle with a changed type today, and their value space is not characterized.

This also narrows B1 for configured passthrough of a non-admitted type (B1 admits it natively today). The rule is one rule because the schema rule treats both kinds of passthrough column identically.

### 4. Representability guard (both routes)

New free function `reject_unrepresentable_passthrough(chunk, guarded, *, table, chunk_index)` in `_chunk_schema.py`, next to the drift contract both routes already share. `guarded` maps each passthrough column whose type (or dictionary value type) is `date32`, `date64`, `time32` or `time64` to its check. The expected predicates, to be confirmed exactly by acceptance test 0:

- `date32`: every non-null value in days `[-719162, 2932896]` (0001-01-01 to 9999-12-31).
- `date64`: every non-null value in ms `[-719162 * 86400000, 2932896 * 86400000 + 86399999]`.
- `time64[ns]`: every non-null value divisible by 1000.
- `time32` and `time64`: every non-null value inside one day in its unit, if the fixture shows the oracle refuses values outside it.
- A dictionary column is checked on its whole value array (`chunk.column(name).chunks[i].dictionary`), referenced or not, because `to_pandas` converts the full dictionary into categories.

Checks use `pyarrow.compute` (`min_max`, a modulo) on the column, so the cost is one vectorized pass over guarded columns only. A failure raises `ExecutionError(code="chunked_passthrough_value_unrepresentable")` naming table, column, chunk index, Arrow type, and the offending value's position or the failed bound.

Placement: `validated_rest` calls it on every chunk after the first, right after `validate_chunk_schema` and before the chunk reaches either route's loop; `_run_chunked` calls it on the first chunk right after preflight and before route choice. A chunk-0 value the oracle refuses already raises in `first_chunk_profile`, so the chunk-0 call is defense in depth. Because the guard sits before the oracle adapter and before the native ingest guards, the refused chunk is never yielded, appended or vaulted, on either route, which matches the public oracle's counts. The guard runs for both public entry points that share `_run_chunked`; only `run_mask_chunked` is under the B8 contract.

### 5. Native masking of unconfigured columns

`_native_route` passes `unconfigured=frozenset(preflight.unconfigured_passthrough)` to `_mask_chunk_native`. In its loop over `chunk.schema.names` (source order), a name in `unconfigured` gets `arrays[name] = chunk.column(name)`: no kernel, no timer, no `kernel_calls` entry, no `column_elapsed_s` entry, no `col_seed_by_name` lookup. The docstring's precondition ("every column name is present in `col_seed_by_name`") becomes "every column name is planned or listed in `unconfigured`". `normalize_chunk` then replaces the column with the (null-cast) source column and the first chunk's field, exactly as on the oracle route, so the output is a zero-copy reference to the source buffers.

### 6. Warnings

Per chunk, after `normalize_chunk` and before the sink append, the native route computes `warnings = tuple(enforce_output_projection(table, out.column_names, state.plan, state.projection_policy))`. Under `warn` with unconfigured columns this is the single DE-03 warning; with none it is empty. It goes into the chunk's `ExecutionResult.warnings`. It is computed whether or not a sink is given, so the function stays the single enforcement point.

Native-admitted strategies are not expected to emit handler warnings on the oracle route; acceptance test 2 compares whole warning tuples across routes for every admitted strategy, and a mismatch there is a finding to stop on, not something to filter out.

### 7. Interaction with B1's contracts

- **Real-type admission.** Unaffected for configured columns. An unconfigured column of any admitted type passes; a non-admitted type routes to the oracle (Design 3).
- **Leading null.** An unconfigured column `null`-typed in chunk 0 and typed later raises `chunked_leading_null_type` on both routes (`validated_rest` runs before either loop). A column `null`-typed in every chunk is yielded as `null`.
- **Drift.** An unconfigured column added, removed or retyped after chunk 0 raises `native_chunk_schema_drift` on both routes; a later all-null `null`-typed chunk is cast to the first type after the guards.
- **Ingest guards.** `run_chunk_ingest_guards` walks plan nodes only, so it ignores unconfigured columns on both routes.
- **Vault.** `collect_vault_entries` reads configured `vault: true` columns only; unconfigured columns contribute nothing on either route.
- **Pool cache, threads, adapter.** Unchanged. A non-pandas adapter still vetoes with `adapter_requested`, a `when:` predicate with `when_predicate_not_native`.

### 8. Nested types: decision

B8 does not handle the nested-type `TypeError`. It is raised by `first_chunk_profile` inside `_oracle_preflight`, which runs before route choice on both entry points, so B8 neither creates nor widens its reach: probe D shows the same exception on both entry points, with no route evidence emitted. When chunk 0 is all null the profile passes and Design 3 routes the table to the oracle with `passthrough_type_not_native:<column>:<type>`, which masks it as today. Coding the `TypeError` (for example `ExecutionError(code="unsupported_source_type")` from the profiler) changes the public oracle's error type for every caller; it is a separate engine slice, listed under Known issues, and acceptance test 9 pins today's behavior so that slice has to update the test deliberately.

### 11. Merge evidence: performance and memory

The standing Rust merge rule needs "faster, within its declared memory ceiling". B8 adds a bounded local benchmark next to B2's: `scripts/bench-unconfigured-passthrough`, calling `run_mask_chunked` directly (the dispatcher, no `run_pipeline`).

- **Workload.** B2's generator exactly (`rng = numpy.random.default_rng(20261001)`, `k` 1,000,000 int64, built element-wise, no pandas): the four configured string columns `email` (hash, namespace `bench_ns`), `secret` (redact), `zip` (truncate, length 3), `ref` (passthrough), plus N = 8 unconfigured columns appended in this order: `u_int` int64 = `k`; `u_float` float64 = `k / 7`; `u_str` string = `f"u{v:09d}"`; `u_date` date32 = `k % 2932896` days; `u_ts` timestamp[us, UTC] = `k` microseconds; `u_bool` bool = `k % 2 == 0`; `u_dec` decimal128(18,2) = `k / 100`; `u_dict` dictionary<int32, string> over 64 values `f"cat{v % 64}"`. Every fifth row of `u_int`, `u_str` and `u_date` is null. Chunks are zero-copy slices of 50,000 rows (20 chunks). Policy `warn` set explicitly. The record states `Table.nbytes`.
- **Configurations.** (a) before: the same call on the B1 head `7aab160f` (a detached scratch checkout, oracle route, `uncovered_columns`); (b) after, `native_threads=1`; (c) after, `native_threads=4`; (d) regression check: the four configured columns only (N = 0), before and after, `native_threads=1`; (e) the N = 8 workload with `unconfigured_column_policy: error`, after only, confirming the oracle route raises `undeclared_output_columns` (correctness only, not timed).
- **Method.** B2 section 11's method: each trial a fresh subprocess under `/home/cam/bin/pytest-one`'s lock or a single script holding the same lock, no other heavy process; `OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`; one discarded warmup per configuration, then seven measured rounds, each round running every configuration once in a seeded shuffled order (seed and order recorded); per configuration all seven wall times of draining the iterator, p50 and max-of-seven, and each trial's whole-process peak RSS (`ru_maxrss`, captured as soon as the iterator is drained). The record names the CPU and the pyarrow, pandas, engine and companion versions.
- **Correctness-oracle isolation.** The reference is configuration (a)'s output, produced in a separate unmeasured subprocess. Each measured subprocess writes its concatenated output (Arrow IPC) and its per-chunk warnings and evidence as JSON; the parent checks `Table.equals(..., check_metadata=True)` against the reference, equal warnings per chunk, and `native_admitted` true with `reroute_reason` null for (b) and (c), outside every measured process.
- **Declared memory ceiling (before measuring).** 2.0 GiB peak RSS (2 x 1024^3 = 2,147,483,648 bytes) for every measured trial process of (b), (c) and (d)-after, whole process, imports and source construction included. An absolute safety ceiling for this 1M-row, 12-column workload, not a scaling claim. Working default; Cam may adjust.
- **Bars.** (b) and (c) have lower p50 and lower max-of-seven than (a). (d)-after p50 is at most 1.05 times (d)-before p50 (the cost of the guard, the policy check and the warning call on tables B8 does not change). Every measured trial stays under the ceiling. Peak RSS for (a) to (c) is reported, not gated. Missing a bar stops for Cam.
- **Recording.** The run gets the next benchmark run ID and a row in the sprint and testing ledger. This plan states no B8 speed or memory figure; any figure quoted later says "measured" and cites the run ID.

## Acceptance tests (written first; behavioral tests record red-before)

**Test protection.**

- The acceptance tests are committed before any implementation commit, and the build record cites that commit's SHA. Implementation commits come after it.
- Without a new plan gate, nobody deletes an acceptance test, adds a skip or xfail outside `@_NEEDS_COMPANION`, reduces a cross-product, replaces `check_metadata=True` with a values-only or types-only comparison, drops a route or `reroute_reason` assertion, or drops a warnings comparison. The only existing assertions B8 may rewrite are the ones Design 9 lists, in the way it lists. A failing acceptance test is a defect in the code or a finding for the plan, never a reason to edit the test.
- Coverage and mutation in the build record: branch coverage for each changed unit, and a mutmut run over the admission change in `plan_native_route`, `passthrough_type_rejection`, `reject_unrepresentable_passthrough`, the unconfigured branch of `_mask_chunk_native`, the native warnings call and the cross-check. Logic to be graded lives in free functions (mutmut 3.7 skips decorated-class bodies). A surviving mutant that can change the route, a reason, a warning, an output value or type, or a refusal is build work: a new test kills it, or the build record argues it equivalent and dennis accepts that.

0. **Characterization (before any B8 code).** Through the public oracle `run_mask_pipeline_chunked`, for every Arrow type in Design 3's admitted and not-admitted lists, as an unconfigured column next to a redact column, two chunks (benign chunk 0, then the case in chunk 1): record whether the oracle yields chunk 1 or raises, and the exception type. Value cases per type: nulls; the type's minimum and maximum; for `date32` and `date64` the bounds 0001-01-01 and 9999-12-31 and one step outside each; for `date64` a sub-day value; for `time32` and `time64` zero, the last value of the day, and one past it; for `time64[ns]` an aligned and a non-aligned value; for dictionaries an out-of-range date only in the unreferenced part of the value array. Checked in as a fixture. A test asserts, against the live pandas and pyarrow, that `reject_unrepresentable_passthrough` raises exactly for the cases where the oracle raises, and that every type the oracle converts without error for every value case is either in the admitted set or in the not-admitted list with a reason, so an upgrade that changes conversion behavior fails CI.
1. **Routing by policy.** For an admissible table (redact, truncate, hash, passthrough and deterministic-REUSE Faker configured, plus unconfigured columns): explicit `warn` routes native with reason `None` (red-before: `uncovered_columns`); explicit `error` routes to the oracle with today's exact reason string and raises `undeclared_output_columns` before any yield, with no sink append, no vault entry, and the same exception message as the public oracle; unset policy with `is_pre_ga` patched true routes native, and patched false behaves as `error`. A configured column missing from the source (with and without unconfigured columns) keeps today's reason. `plan_native_route` called without `unconfigured_policy` keeps today's veto (existing tests pass unchanged), and so does `run_native_or_oracle_chunked`.
2. **Output identity with route.** Each case runs `run_mask_chunked` twice: as configured (must be native, asserted) and with B1's forced-oracle column (`categorical("cat_force")`, must be oracle, asserted; the force column is dropped before comparison). Chunk by chunk: `Table.equals(..., check_metadata=True)`, equal `warnings` tuples, equal timing column sets (no record for an unconfigured column), equal vault entries, equal sink lengths. ## Known issues (tech debt, not blockers)

- Nested source types (`list`, `struct`, `map` and their variants) with a non-null value in chunk 0 raise an uncoded `TypeError` from `first_chunk_profile` on every chunked entry point, configured or not. B8 leaves it as is (Design 8). Follow-up engine slice: code it in the profiler, or profile nested columns without hashing their values.
- The new `chunked_passthrough_value_unrepresentable` narrows `run_mask_chunked`'s oracle route from the public oracle's uncoded `ValueError` or `ArrowInvalid` to a coded error, at the same chunk. The public oracle keeps the uncoded error. On B2's lane this means a later-chunk `date32` outside years 1 to 9999 raises a different exception type on the dispatcher lane than on today's legacy lane; B2 test 0 does not cover that value shape. Either B2 accepts the coded error as an improvement or its type gate routes `date32` and `date64` columns to the legacy lane (which would keep most date-bearing tables off the dispatcher). Open question for Cam.
- B8 fixes a B1 parity gap for configured passthrough (later-chunk `time64[ns]` sub-microsecond and out-of-range dates yield natively where the oracle refuses). B1 is not merged; whether the fix belongs in B1 rev9 instead of B8 is an open question for Cam. The plan as written carries it in B8, because B8 is what makes the gap common.
- Configured passthrough of a non-admitted type (nested with an all-null chunk 0, extension types) moves from the native route to the oracle route. Output is unchanged; only speed.
- Under `error`, a table with unconfigured columns still pays the oracle's chunk-0 masking before raising.
- The legacy `run_native_or_oracle_chunked` keeps the veto for unconfigured columns (tests only).
- The B8 benchmark measures the dispatcher directly; the `run_pipeline` effect arrives through B2 and B7 and is measured there.
