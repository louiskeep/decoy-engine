## Already covered by B1 revision 9 (removed from this plan)

Probes for this revision are in the session scratchpad: `b8r2_probe_types.py`, `b8r2_probe_nullcast.py`, `b8r2_probe_readfp.py`, `b8r2_probe_prototype.py`, `b8r2_probe_trace.py`, each with its `.out` (companion venv, pyarrow 25.0.1, pandas 2.3.3).

- **Value-domain guard.** Revision 1's `reject_unrepresentable_passthrough` and the `chunked_passthrough_value_unrepresentable` code for carried columns are dropped. On the stock-adapter path an unconfigured column is a carried column (B1 rule R1: the schema rule's passthrough columns minus the read set), so it never reaches pandas on either route, and its output is the source column (B1 rules R3, R4, design item 5). Dictionary nulls, duplicates and NaN, `uint64` indices, time-zone timestamps, `-2^63` sentinels, out-of-range dates and sub-microsecond `time64[ns]` are therefore yielded exactly on both routes (B1 test 15). The fixture-based characterization (revision 1 test 0) and the refusal tests (revision 1 test 5) go with it.
- **Read columns.** A passthrough column a `when:` predicate or a sibling-reading strategy reads still goes to pandas with coded refusals (B1 rules R2, R6). Every true reader vetoes the native route already (`when_predicate_not_native`, or a strategy with no native kernel), so B8 adds nothing for them, apart from the false-positive case in Design 4.
- **Nested types.** Revision 1 Design 8 and test 9 are dropped. B1 rule R3 profiles carried columns from Arrow, so a `list`, `struct` or `map` unconfigured column with values in chunk 0 no longer raises the profile's `TypeError` (`b8r2_probe_types.out`: every catalogue type, configured and unconfigured, completes with the source column).
- **FK guard.** B1 rule R6 already sets the FK passthrough guard to the FK passthrough keys minus the carried set. FK tables still veto the native route before B8's change is reached.
- **Arrow-native profile.** B1 rule R3. B8 adds no profiling.
- **Passthrough type allowlist.** Revision 1 Design 3 proposed one. Re-probing shows it is not needed (Design 3 below): the native route already returns the source column for every type in B1's 67-type catalogue, and the only failures were an admission crash that B8 fixes at its source.
- **Open questions from revision 1** (whether the configured-passthrough value-domain fix belongs in B1, and B2's coded-versus-raw date error) are settled by revision 9 and are removed.

## Problem

`run_mask_chunked` admits a table to the native route only when the source's columns are exactly the compiled plan's columns. `plan_native_route` (`execution/native/_dispatch.py` 349-367) compares `set(first_schema.names)` with the planned columns, and any difference downgrades the whole table to the oracle route with reason `uncovered_columns:[...];missing_configured_columns:[...]`. A partial-mask config is the normal shape of a real job, so most real tables run wholly on the oracle route even when every configured column has a native kernel. B2 and B7 inherit this.

What happens today with an unconfigured column on `run_mask_chunked` (code read and probes on `0bb196fa`):

- **Policy.** `unconfigured_column_policy` (DE-03, `execution/_output_projection.py`) has exactly two values, `warn` and `error`. An explicit `global_settings.unconfigured_column_policy` wins; otherwise it is `warn` while `release.is_pre_ga()` is true and `error` at GA (`resolve_unconfigured_column_policy`). `_oracle_preflight` resolves it once into `state.projection_policy`, and the stock adapter enforces it per chunk through `enforce_output_projection` (`_pandas_adapter.py` 316-324), after masking and before `Table.from_pandas`.
- **`warn`.** Each chunk's `ExecutionResult.warnings` ends with one `QualityWarning(code="undeclared_output_columns", provider="output_projection", column=None, detail={"table": ..., "undeclared_columns": <sorted>})`. The column is carried (placeholder into the adapter, source column out). No timing record and no vault entry exist for it.
- **`error`.** The adapter raises `ExecutionError(code="undeclared_output_columns")` at the first `next()`, after chunk 0's node masking and before any sink append or vault entry (B1 test 18 pins this against the public oracle).
- **"Unconfigured".** A source column absent from the table's `columns:` list (a listed column without a strategy is a config `ValidationError`). The undeclared set is `source columns - known_output_columns(plan, table)`.
- **Output.** Already the source column on both routes, with the first chunk's field, in source order (B1 guarantee 2(b)).
- **The native masker cannot take one.** `_mask_chunk_native` (`_chunk_masking.py` 176-178) indexes `col_seed_by_name[name]` for every column of the chunk, so an unconfigured column would raise `KeyError` once admitted. The native loop builds `ExecutionResult(warnings=())` (`_chunked_entry.py` 224), so it never emits the DE-03 warning.
- **Admission crash waiting behind the veto (new finding).** `real_type_rejection` (`_real_type_admission.py` 53) builds `first_schema.empty_table()` over the whole schema. `Schema.empty_table` raises `ArrowNotImplementedError` for a `dense_union` or `sparse_union` field and for `run_end_encoded<string_view>` (`b8r2_probe_trace.out`). Today an unconfigured column never reaches it (the veto comes first), and the oracle route carries such a column exactly (`b8r2_probe_types.out`). Lifting the veto without a fix would turn those working calls into a raw exception at call time. The same line is why a configured union passthrough column raises on `run_mask_chunked` today (B1 known issue L3).
- **Read-set false positive on a native table (new finding).** B1 rule R2(b) puts a passthrough column in the read set when its name equals any string value in another configured column's entry (a deliberate over-approximation, B1 known issue rev9.1). On a native-admitted table nothing reads it, so the native route returns the source column, while the oracle route converts it through pandas. Probe `b8r2_probe_readfp.out`: configured passthrough `redact` beside `redact("s")`, with a `time64[ns]` value that is not a whole microsecond in chunk 1, completes on the native route and raises `chunked_passthrough_value_unrepresentable` at chunk 1 when the oracle route is forced. This divergence exists in B1 today for configured passthrough; lifting the veto would extend it to unconfigured columns (today an unconfigured `redact` column takes the oracle route and raises).
- **Feasibility.** A probe-only prototype (`b8r2_probe_prototype.py`: `plan_native_route` sees the configured fields only, and the masker passes every other column through) admits every one of the 134 catalogue cases (67 types, with and without a null) as an unconfigured column beside redact, truncate and hash, with a zero-row middle chunk, and every yielded chunk `equals` today's oracle-route chunk with `check_metadata=True`. Only the warnings differ (none on the prototype's native route), which Design 6 fixes.

## Guarantee (pinned) and non-goals

For every `run_mask_chunked` call, with the same config and chunks:

1. **Routing by policy.** Under the resolved policy `warn`, a table whose only obstacle to native admission was unconfigured source columns (every configured column natively admitted, no configured column missing from the source, no read passthrough column (Design 4), cross-check passes (Design 5)) runs on the native route with `reroute_reason` null. Under `error` the routing is unchanged (oracle route, reason byte for byte as today) and the call raises `undeclared_output_columns` exactly as today. A configured column missing from the source vetoes with the unchanged reason. The policy comes from `state.projection_policy`, the value the oracle route uses, so explicit settings and the pre-GA default route identically, and at GA the admission switches off without a code change.
2. **Output identity with the oracle route.** On a table B8 admits, every yielded chunk equals the chunk the oracle route of `run_mask_chunked` yields for the same input (the oracle route forced by a missing companion with a hash column present, or by B1's `categorical("cat_force")` column, which is dropped before comparing): `Table.equals(..., check_metadata=True)`, so values, nulls, row order, Arrow types, field nullability and field metadata, column order, and no schema metadata.
3. **Warnings.** Each chunk's `ExecutionResult.warnings` on the native route equals the oracle route's for the same chunk: the same `QualityWarning` values in the same order, one DE-03 warning per chunk under `warn`. The native route produces it by calling `enforce_output_projection` itself, never a copy of its logic.
4. **Side channels.** Vault entries, `chunk_result_sink` appends (one per chunk, before the yield), `timings` (no record for an unconfigured column on either route), `base_row_offset` and `route_evidence_sink` behave as B1 guarantees 4 to 6 state. An unconfigured column is never listed in `quality_metrics["chunked_route"]["columns"]` (B1 design item 6); an admitted table reports `native_admitted: true`, `reroute_reason: null` and `pandas_read_passthrough: []`.
5. **Errors.** Drift (`native_chunk_schema_drift`), leading null type (`chunked_leading_null_type`) and the per-chunk ingest guards apply to unconfigured columns exactly as B1 pins them, on both routes, at the same chunk, with the same sink appends before the raise. A later all-null chunk of a type with no cast from `null` (list views, run-end-encoded) raises the same raw `ArrowNotImplementedError` on both routes with one sink append before it (`b8r2_probe_nullcast.out`; pinned, not changed by B8).
6. **Evidence of the route.** Every test that compares outputs also asserts the route each side took (`NativeRouteEvidence.native_admitted` and `reroute_reason`), so a case cannot pass with both sides on the oracle.

Non-goals: a `drop` policy or any new policy value; native execution under `error`; per-column evidence entries for unconfigured columns (the warning names them, and B2 pinned the evidence keys); the legacy `run_native_or_oracle_chunked` (callers are tests only; it keeps the veto); the public oracle `run_mask_pipeline_chunked`, `_oracle_preflight` and the DE-03 warning, all unchanged; narrowing the R2(b) read-set scan (B1 known issue rev9.1); widening native admission for any configured strategy; platform or CLI wiring (B3, B4); the Phase E 100M gate.

## Design

### 1. Policy routing (pinned)

| Resolved policy | Table shape | Route | Reason | Outcome |
|---|---|---|---|---|
| `warn` (explicit, or unset pre-GA) | unconfigured columns only | native, when every other admission check passes | `null` | source columns carried, one warning per chunk |
| `warn` | unconfigured columns and a configured column missing from the source | oracle | `uncovered_columns:[...];missing_configured_columns:[...]` (unchanged) | as today |
| `error` (explicit, or unset at GA) | unconfigured columns | oracle | `uncovered_columns:[...];missing_configured_columns:[]` (unchanged) | `undeclared_output_columns` at the first `next()`, as today |
| any | no unconfigured columns | as B1 | as B1 | as B1 |

`error` keeps the oracle route: the oracle raises inside `adapter.run` after node masking, so a handler error on chunk 0 takes precedence over the projection error. Reproducing that ordering on the native route gains nothing, since the call fails on chunk 0 either way.

### 2. Admission (`plan_native_route`)

`plan_native_route` gains a keyword `unconfigured_policy: Literal["warn", "error"] | None = None`. `None` keeps today's behavior, so admission-only callers, the legacy entry point and the existing `plan_native_route` tests are unaffected. With `first_schema` given:

- `uncovered = [n for n in first_schema.names if n not in covered]` (source order); `missing = covered - set(first_schema.names)`.
- If `missing` is non-empty, or `uncovered` is non-empty and `unconfigured_policy != "warn"`: downgrade with today's reason string, byte for byte.
- Otherwise the table stays admitted, and `NativePreflight` gains `unconfigured_passthrough: tuple[str, ...] = ()` holding `uncovered`. `NativeRouteEvidence` and `NodeRouteRecord` are unchanged (B1 test 8a).
- The faker source-type check, `real_type_rejection` (Design 3) and the companion probes then run as today.

`_run_chunked` passes `unconfigured_policy=state.projection_policy` when `enforce_schema_rule=True` (`run_mask_chunked`) and `None` for the legacy entry.

### 3. `real_type_rejection` reads only the columns it checks

`real_type_rejection` builds its resident table from the hash nodes' fields only: `pa.schema([first_schema.field(n.column) for n in node_routes if n.strategy == "hash"]).empty_table()`. `hash_config_rejection` resolves the input type of the one column it is given (`resolve_input_arrow_type(table, name, ...)`); the build confirms by reading it that no other column of the resident table is consulted, and a unit test pins equal reasons before and after for every hash source type in `tests/native/test_chunked_entry_parity_matrix.py` (string, dictionary, date32, decimal128 and the rest of its sources). This removes the crash for union and `run_end_encoded<string_view>` passthrough columns, configured or unconfigured, at its source instead of adding a type list in front of it.

No passthrough type allowlist is added. Evidence: on `0bb196fa` the native route returns the source column exactly for every catalogue type as configured passthrough apart from the three crashing types (`b8r2_probe_types.out`), and the prototype returns oracle-equal chunks for all 67 as unconfigured columns (`b8r2_probe_prototype.out`). The native route never inspects a carried column's values, so the type cannot change the output. Acceptance test 3 runs the whole catalogue on both routes; a type that diverges there stops the build for a plan revision, it is not filtered out.

Consequence for B1: a configured union passthrough column on `run_mask_chunked` stops raising `ArrowNotImplementedError` and runs natively, returning the source column (B1 known issue L3 resolved for passthrough). A union hash column still reaches `empty_table` for its own field and raises as today.

### 4. Read passthrough columns veto the native route

In `_run_chunked`, after `plan_native_route` and before faker pool resolution, when the decision is native and `state.carry` is not `None` and `state.carry.read` is non-empty, the table downgrades with reason `pandas_read_passthrough:<sorted list>`. On a native-admitted table every read column is a false positive (true readers veto earlier), and on the oracle route that column goes through pandas, so only the veto keeps the two routes equal for a value pandas refuses. This applies to configured and unconfigured passthrough alike, because the carry plan treats them alike. It narrows B1: a configured passthrough column whose name equals a config string value (for example a column named `redact` or a namespace value) moves from the native route to the oracle route. Output changes only where pandas refuses a value in that column, which then raises the coded error on both routes instead of on the oracle route only. The legacy entry (`state.carry` is `None`) is unaffected.

### 5. Cross-check against the oracle's own definition

Before committing the native route, `_run_chunked` checks that `set(first.schema.names) - known_output_columns(state.plan, table)` equals `set(preflight.unconfigured_passthrough)`. If not, the table downgrades with reason `unconfigured_set_mismatch:<sorted oracle set>:<sorted native set>`. It is kept because the two sets drive different things: the native masker passes through the columns it has no plan node for, while the warning (and, under `error`, the refusal) is computed from `known_output_columns`. If they ever disagree (an FK group's coherent columns, which `known_output_columns` includes and the node list does not), a column could be passed through unmasked with no warning. FK tables veto earlier today, so production cannot reach the branch; a test reaches it by patching `known_output_columns`. It is one set comparison per call.

### 6. Native masking and warnings

- `_native_route` passes `unconfigured=frozenset(preflight.unconfigured_passthrough)` to `_mask_chunk_native`. In its loop over `chunk.schema.names` (source order), a name in `unconfigured` gets `arrays[name] = chunk.column(name)`: no kernel, no timer, no `kernel_calls` entry, no `column_elapsed_s` entry, no `col_seed_by_name` lookup. The docstring precondition becomes "every column name is planned or listed in `unconfigured`". `normalize_chunk` then takes the source column and the first chunk's field, as on the oracle route.
- Per chunk, after `normalize_chunk` and before the sink append, the native route computes `warnings = tuple(enforce_output_projection(table, out.column_names, state.plan, state.projection_policy))` and puts it in the chunk's `ExecutionResult.warnings`. It is computed whether or not a sink is given, so the function stays the single enforcement point (under `warn` it cannot raise; the call is also the backstop if a later change ever admitted a table under `error`).
- Native-admitted strategies are not expected to emit handler warnings on the oracle route; acceptance test 2 compares whole warning tuples across routes for every admitted strategy, and a mismatch is a finding to stop on, not something to filter.

### 7. Interaction with B1's contracts

- **Carry and profile.** Unchanged. An unconfigured column is in the carried set unless it is read (Design 4 then vetoes the native route).
- **Leading null and drift.** `validated_rest` runs before either loop and covers every source column, so unconfigured columns raise `chunked_leading_null_type` and `native_chunk_schema_drift` on both routes at the same chunk. A later all-null `null`-typed chunk is cast by `cast_null_columns` on the native route and by `normalize_chunk` on the oracle route, with equal output, and equal raw errors for the types with no cast from `null` (guarantee 5).
- **Ingest guards.** `run_chunk_ingest_guards` walks plan nodes only and ignores unconfigured columns on both routes.
- **Vault.** `collect_vault_entries` reads configured `vault: true` columns only.
- **Transforms (A8).** A transform-bearing table is still refused before any chunk is read; B8 does not touch that path.
- **Pool cache, threads, adapter.** Unchanged. A non-stock adapter vetoes with `adapter_requested`, a `when:` predicate with `when_predicate_not_native`, both before B8's checks.

### 11. Merge evidence: performance and memory

The standing Rust merge rule needs "faster, within its declared memory ceiling". B8 adds `scripts/bench-unconfigured-passthrough`, calling `run_mask_chunked` directly.

- **Workload.** `rng = numpy.random.default_rng(20261001)`; `k` is 1,000,000 int64 built element-wise, no pandas. Four configured string columns: `email` (hash, namespace `bench_ns`), `secret` (redact), `zip` (truncate, length 3), `ref` (passthrough). Then N = 8 unconfigured columns, in this order: `u_int` int64 = `k`; `u_float` float64 = `k / 7`; `u_str` string = `f"u{v:09d}"`; `u_date` date32 = `k % 2932896` days; `u_ts` timestamp[us, UTC] = `k` microseconds; `u_bool` bool = `k % 2 == 0`; `u_dec` decimal128(18,2) = `k / 100`; `u_dict` dictionary<int32, string> over 64 values `f"cat{v % 64}"`. Every fifth row of `u_int`, `u_str` and `u_date` is null. Chunks are zero-copy slices of 50,000 rows (20 chunks). Policy `warn` set explicitly. No column name equals a config string value (so Design 4 does not veto). The record states `Table.nbytes`.
- **Configurations.** (a1) and (a4): before, at `0bb196fa` in a detached scratch checkout (oracle route, `uncovered_columns`), `native_threads` 1 and 4; (b1) and (b4): after, `native_threads` 1 and 4; (d-before) and (d-after): the four configured columns only (N = 0), `native_threads=1`; (e): N = 8 with `unconfigured_column_policy: error`, after only, confirming the oracle route raises `undeclared_output_columns` (correctness only, not timed).
- **Method.** Each trial is a fresh subprocess under `/home/cam/bin/pytest-one`'s lock (or a single driver holding the same lock), with no other heavy process; `OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`. One discarded warmup per configuration, then seven measured rounds, each round running every timed configuration once in a seeded shuffled order (seed and orders recorded). Per configuration: all seven wall times of draining the iterator, p50 and max-of-seven, and each trial's whole-process peak RSS (`ru_maxrss`, read as soon as the iterator is drained). The record names the CPU and the pyarrow, pandas, engine and companion versions.
- **Correctness isolation.** The reference is (a1)'s output, produced in a separate unmeasured subprocess. Each measured subprocess writes its concatenated output (Arrow IPC) and its per-chunk warnings and evidence as JSON; the parent checks `Table.equals(..., check_metadata=True)` against the reference, equal warnings per chunk, and `native_admitted` true with `reroute_reason` null for (b1) and (b4), outside every measured process.
- **Declared memory ceiling (FROZEN).** 2.0 GiB peak RSS (2,147,483,648 bytes) for every measured trial process of (b1), (b4) and (d-after), whole process, imports and source construction included. An absolute safety ceiling for this 1M-row, 12-column workload, not a scaling claim.
- **Bars.** (b1) has lower p50 and lower max-of-seven than (a1); (b4) likewise against (a4). (d-after) p50 is at most 1.05 times (d-before) p50 (FROZEN): the cost of the policy check, the read-set and cross-checks and the warning call on a table B8 does not reroute. Every measured trial stays under the ceiling. Peak RSS for (a) and (b) is reported, not gated. Missing a bar stops for Cam; the bars and the ceiling are not adjusted after measuring.
- **Recording.** The run gets the next benchmark run ID and a row in the sprint and testing ledger. This plan states no B8 speed or memory figure; any figure quoted later says "measured" and cites the run ID.

## Acceptance tests (written first; behavioral tests record red-before)

**Test protection.**

- The acceptance tests are committed before any implementation commit, and the build record cites that commit's SHA. Implementation commits come after it.
- Without a new plan gate, nobody deletes an acceptance test, adds a skip or xfail outside `@_NEEDS_COMPANION`, reduces a cross-product or the type catalogue, replaces `check_metadata=True` with a values-only or types-only comparison, drops a route or `reroute_reason` assertion, or drops a warnings comparison. The only existing assertions B8 may rewrite are those in Design 9, in the way it states. A failing acceptance test is a defect in the code or a finding for the plan, never a reason to edit the test.
- Coverage and mutation in the build record: branch coverage for each changed unit, and a mutmut run over the admission change in `plan_native_route`, the `real_type_rejection` resident schema, the read-set veto, the cross-check, the unconfigured branch of `_mask_chunk_native` and the native warnings call. Logic to be graded lives in free functions (mutmut 3.7 skips decorated-class bodies). A surviving mutant that can change the route, a reason, a warning, an output value or type, or an error is build work: a new test kills it, or the build record argues it equivalent and dennis accepts that.
