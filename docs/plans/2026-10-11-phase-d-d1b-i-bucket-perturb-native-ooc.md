## 1. Why + what
The out-of-core route masks `bucket_perturb` by BRIDGING to pandas: `_mask_group_c._bucket_perturb_array` (`:395`) runs `apply_bucket_perturb` on a pandas Series and returns `pa.array(perturbed, from_pandas=True)`. Program §5 names this pandas payload bridge as a thing to replace with Rust/Arrow. The compiled companion already carries the index kernel (`derive_index_batch`), and an existing native ext `native/_bucket_perturb_ext.native_bucket_perturb` already perturbs a date-string column through it (used by the native-chunked route). D1b-i routes the OOC seam's `bucket_perturb` compute through that SAME existing ext when the companion is present and the source is eligible, so admitted OOC bucket_perturb runs on the compiled index kernel instead of the pandas bridge. No new Rust, no ABI change; `apply_bucket_perturb` and `native_bucket_perturb` are untouched.

This is the second native-OOC slice; it reuses D1a's proven mechanism (per-column decision pinned at prep, kernel loaded once and threaded, declined-with-reason + caller-visible disposition, insertion-boundary witness, abort-on-drift, predeclared perf). It is scoped to `bucket_perturb` ALONE; categorical (prepared CDF state) follows as D1b-ii. Unlike hash, bucket_perturb has NO text-normalization surface (it parses dates, it does not NFC-normalize text), so the native/Python parity is exact with no accepted-divergence carve-out.

## 2. Scope
The OOC bucket_perturb compute has one entrypoint: `_mask_group_c._bucket_perturb_array`, reached from the Group-(c) mask dispatch (`:170`) in both streaming drivers' `mask_batch`/`mask_column` path.

**IN (routed native when eligible):** route `_bucket_perturb_array` through `native/_bucket_perturb_ext.native_bucket_perturb(array, bucket, date_format, mask_key=job_seed, namespace, index_kernel, native_threads, derive_calls)` when ALL hold (decided once at prep, immutable for the run): (a) the companion loads and `load_compiled_index_kernel()` succeeds (abi-3); (b) the source column Arrow type is `pa.string()`/`large_utf8` (the eligible date-STRING domain `apply_bucket_perturb` + the native ext operate on); (c) an explicit `date_format` is configured (already required: absent/empty raises `out_of_core_bucket_perturb_autodetect_unsupported`). The native ext parses with pandas, snaps parseable rows to a keyed within-bucket offset via `index_kernel.derive_index_batch`, strftimes back, passes null/unparseable rows through unchanged, and returns pinned `pa.string()`. Whole column takes ONE path, never half-native.

**OUT for D1b-i, EXPLICITLY DECLINED with a recorded caller-visible reason (Python `apply_bucket_perturb` bridge retained, unchanged):** companion absent/ABI-incompatible (`index_extension_unavailable`); a NON-string source column (`bucket_perturb_source_not_string:{col}:{type}`) — `apply_bucket_perturb` ingests `series.astype(str)` and a non-string Arrow source (e.g. an int64 chunk with nulls) renders differently, the unsafe-schema case the native-chunked gate `_chunked_bucket_perturb` already rejects. A missing/empty `date_format` remains the existing hard error (not a decline).

**Also out:** categorical native-OOC (D1b-ii); SEQ route (D2); any change to the companion crate / ABI / native-chunked route; any change to OOC admission/routing; any change to `apply_bucket_perturb` or `native_bucket_perturb` themselves.

## 3. Eligibility, pinning, output-type parity (reuses D1a's mechanism)
The per-column native/declined decision is computed ONCE at run/table-prep from (a) the companion-load result (loaded once per run; `load_compiled_index_kernel()` -> `IndexDerivationKernel`, raising `index_extension_unavailable`, mirroring `_dispatch.py:508`) and (b) the up-front source Arrow type (eligible = string/large_utf8). The loaded index kernel is threaded into the per-batch native call; the decision is immutable and there is no mid-stream backend switch. Each native batch validates its incoming source type against the pinned expectation and ABORTS the run on drift or on a kernel fault (sink abort, nothing committed); a missing pinned column is rejected rather than silently skipped. The explicit-`date_format` invariant (no whole-column format autodetect) is what makes the per-batch native result equal the whole-column result, same invariant the pandas path already relies on.

**Output-type parity.** The pandas path returns `pa.array(perturbed, from_pandas=True)`, whose type is inferred (date strings -> `pa.string()`; an all-null batch infers null-typed). The native ext returns pinned `pa.string()`. D1b-i reconciles the native output to the SAME analytic type the oracle/pandas path produces (resolved by the existing `group_c_output_type`), so the strict D0 comparator (type_width + field_metadata + null-vs-NaN dims) sees byte-identical schema and cells. The reconciliation mirrors what the native-chunked route already does after `native_bucket_perturb` (pinned string then null-shape reconcile). This is the central correctness nuance of the slice (the analog of D1a's REMAP effective-type care) and gets its own tests.

## 4. Caller-visible disposition (program §5)
Reuse the per-column disposition channel D1a added on `ExecutionResult.quality_metrics` (threaded through both drivers + resident/sink returns, visible via `run_pipeline`), extended to bucket_perturb: a per-column entry keyed by table + column, carrying the truthful executed backend and (when declined) the reason. Native = `rust_companion`. The declined path runs `apply_bucket_perturb` (a pandas-series transform, NOT the full pandas-oracle route and NOT the per-value python-scalar loop); label it truthfully (`python_pandas` token in `_operator_registry.py`, distinct from `pandas_oracle`/`python_scalar`/`arrow_python`/`rust_companion`). Reason codes (value-free; strategy/column/type only): `index_extension_unavailable`, `bucket_perturb_source_not_string:{col}:{type}`. An empty / all-null / all-unparseable batch made zero compiled calls (`native_bucket_perturb`'s `derive_calls` out-param is 0): report `executed_backend: none` for that column, never a native claim. Nothing silently falls back.

## 5. Behavior-preservation + parity contract
1. **Byte-identical output:** for every eligible bucket_perturb cell, native output is byte-identical to the pandas `apply_bucket_perturb` reference (same keyed within-bucket offset: `derive_index_batch` reproduces `int.from_bytes(derive(...)[:8],"big") % bucket_size`), including null/unparseable pass-through unchanged.
2. **Oracle parity:** OOC native bucket_perturb is strict-equal (D0 `_strict_compare`, modulo the frozen D0 known gaps) to the pandas oracle on a parent-key-free payload date column and an FK-chain table's date column, across the bucket kinds (month/quarter/year and any others `validate_bucket_perturb_config` admits, incl. a leap-year quarter), with output-type reconciliation (§3).
3. **Per-batch == whole-column** (explicit date_format; no autodetect), **Never half-native** (pinned at prep; abort on drift/fault).
4. **No silent fallback (§5):** every bucket_perturb column is {native + witness + `rust_companion`} OR {`apply_bucket_perturb` + `python_pandas` + a caller-visible reason}; no capability regression on a no-companion install.
5. **Witness:** native bucket_perturb proves native-result-CONSUMED at the insertion boundary and uses `derive_calls > 0` to avoid a vacuous claim on an all-null/unparseable column; declined reports the pandas path. No existing test weakened; `apply_bucket_perturb`/`native_bucket_perturb` untouched.

## 6. Acceptance tests (land the contract test first)
- **Declined, companion absent (ci-mirror):** OOC bucket_perturb succeeds; output byte-identical to the pinned pre-D1b-i pandas baseline; disposition = `python_pandas` + `index_extension_unavailable`; witness = pandas-path-only.
- **Declined, non-string source (companion present):** a bucket_perturb column whose source is non-string reports `bucket_perturb_source_not_string` and stays on the pandas path, output matching the pandas baseline.
- **Native, companion present (abi-3 venv):** output strict-equal to the oracle (D0 comparator, with output-type reconciliation) AND equal to the `apply_bucket_perturb` reference, across month/quarter/year + a leap-year quarter + an explicit `date_format`; per-batch == whole-column; disposition = `rust_companion`; `derive_calls > 0`.
- **Pass-through + boundary:** null rows and unparseable date strings pass through UNCHANGED on both paths; an empty / all-null / all-unparseable batch reports `executed_backend: none` (zero derive calls) with truthful evidence; typed all-null batch followed by a populated batch; multi-batch column (multi-call attribution); ABI-incompatible companion load declines with `index_extension_unavailable`; a source-type drift between prep and a later batch aborts with sink abort and no commit; a missing pinned column is rejected.
- **Witness:** insertion-boundary attribution with table/column/call context; a negative control where the native result is DISCARDED and an equal-valued pandas array emitted MUST FAIL the native-consumed assertion; loader self-test excluded.
- **Performance gate (program §8, PREDECLARED):** isolated-process micro-benchmark, native vs pandas-bridge, on a FROZEN seeded workload: 5,000,000 rows of `pa.string()` dates in a fixed `date_format`, a fixed ~5% null + ~2% unparseable fraction, bucket = month; batch 65,536; native threads = 4; 7 measured native rounds (1 warmup) + 3 pandas rounds (coarse p95 disclosed); timing wraps the mask pass only; output fully consumed. Memory gate = TOTAL process peak RSS <= 1,024 MiB (baseline/delta reported separately). Acceptance = native p50 strictly less than pandas p50 AND native total peak RSS <= 1,024 MiB. 100M/200M proofs remain D4c.
- **Must pass unchanged:** the full D0 parity suite + `tests/parity/test_out_of_core_fk_parity.py` + the OOC route's existing tests + the D1a hash disposition/witness suites + module-size/import-boundary sentries. No existing test weakened.
