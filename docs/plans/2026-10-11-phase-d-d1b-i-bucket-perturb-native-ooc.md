## 1. Why + what
The out-of-core route masks `bucket_perturb` by BRIDGING to pandas: `_mask_group_c._bucket_perturb_array` runs `apply_bucket_perturb` on a pandas Series and returns `pa.array(perturbed, from_pandas=True)`. Program §5 names this pandas payload bridge for replacement. The compiled companion already carries the index kernel (`derive_index_batch`), and the existing native ext `native/_bucket_perturb_ext.native_bucket_perturb` already perturbs a date-string column through it (used by the native-chunked route). D1b-i routes the OOC bucket_perturb compute through that SAME ext when the companion is present and the column is eligible, so admitted OOC bucket_perturb runs on the compiled index kernel instead of the pandas bridge. No new Rust, no ABI change; `apply_bucket_perturb`, `native_bucket_perturb`, and the oracle seam are untouched (dispatch lives in the adapter/seam, not inside `_bucket_perturb_array`).

Third native-OOC slice; reuses the merged mechanism (per-column decision pinned at prep, index kernel loaded once and threaded via `_hash_run`'s run object, declined-with-reason + caller-visible disposition, insertion-boundary witness, abort-on-drift, predeclared perf) and the D1b-ii gate lessons (reuse the single config/source resolver; the chunked null-type reconciliation rule; witness on the actual operator binding; accumulate kernel calls over the whole column). It is scoped to `bucket_perturb` ALONE.

**NFC basis (corrects rev-1's wrong "no NFC surface" claim).** The keyed within-bucket offset derives from the canonicalized source value (`derive_index_batch` canonicalizes like `derive`, which NFC-normalizes strings), so bucket_perturb shares the same canonicalization basis as hash/categorical. In practice it cannot diverge here: an eligible value is a date STRING in the configured `date_format` (ASCII digits + separators), and NFC on ASCII is a no-op, so the accepted native-vs-Python Unicode-version divergence has no reachable input. Stated correctly rather than claimed absent.

## 2. Scope
The OOC bucket_perturb compute has one entrypoint: `_mask_group_c._bucket_perturb_array`, reached from the Group-(c) dispatch in both streaming drivers' `mask_batch`/`mask_column` path.

**IN (routed native when eligible):** dispatch to `native_bucket_perturb(array, bucket, date_format, mask_key=job_seed, namespace, index_kernel, native_threads, derive_calls)` when ALL hold (decided ONCE at prep, immutable for the run): (a) the companion loads and `load_compiled_index_kernel()` succeeds (abi-3); (b) the column is admissible per the SINGLE existing resolver `native/_operator_config_rejections.bucket_perturb_config_rejection(...)` returning None — it admits ONLY the string-source, explicit-`date_format`, TZ-FREE, valid-bucket (`_VALID_BUCKET_PERTURB_BUCKETS` = **week/month/quarter**), namespaced variant (both native boundaries already call this one resolver, so OOC never diverges from the chunked route). The native ext parses with `pd.to_datetime(errors="coerce")`, snaps parseable rows to a keyed within-bucket offset via `index_kernel.derive_index_batch`, strftimes back, passes null/unparseable rows through UNCHANGED, and returns pinned `pa.string()`. Whole column takes ONE path, never half-native.

**OUT, EXPLICITLY DECLINED with a recorded caller-visible reason (Python `apply_bucket_perturb` retained, unchanged):** companion absent/ABI-incompatible (`index_extension_unavailable`); any column `bucket_perturb_config_rejection` declines — a non-string source, a tz-directive (`%z`/`%Z`) format, an unsupported bucket, a missing namespace — keeps the Python path with that coded reason. A missing/empty `date_format` remains the existing hard error (the config gate), not a native-eligibility decline.

**Also out:** categorical (D1b-ii, merged) + hash (D1a); SEQ route (D2); the program-plan's separate D1b remaining-ops slice; any change to the companion crate / ABI / native-chunked route; any change to OOC admission/routing; any change to `apply_bucket_perturb` or `native_bucket_perturb`.

## 3. Eligibility, pinning, output-type, and the date-range limitation
**Pinning.** The per-column decision is computed once at prep from the companion-load result (index kernel loaded once per run, raising `index_extension_unavailable`, mirroring `_dispatch.py:508`) + `bucket_perturb_config_rejection`. The loaded kernel is threaded into the per-batch native call; the decision is immutable, no mid-stream switch. Each native batch validates its incoming source type against the pinned `pa.string()` and ABORTS the run on drift or kernel fault (sink abort, nothing committed); a missing pinned column is rejected. The explicit-`date_format` invariant (no whole-column autodetect) makes the per-batch native result equal the whole-column result, the invariant the pandas path already relies on.

**Output-type reconciliation (folds #1).** The pandas path returns `pa.array(perturbed, from_pandas=True)`: perturbed date strings infer `pa.string()`, but an EMPTY or entirely-NULL output infers null-typed. `group_c_output_type` alone cannot reproduce that (it always returns string). So D1b-i reconciles the native output to the oracle function's own data-dependent shape, the same rule the native-chunked route applies (`_chunk_masking.py:244`): an empty OR all-null output becomes `pa.nulls(len)`, otherwise `pa.string()`; an all-unparseable-but-present batch stays `pa.string()` (the values passed through). Applied before resident assembly (sink reconciliation separate), preserving the existing field/schema assembly so the strict D0 comparator (type_width + field_metadata + null-vs-NaN) sees byte-identical schema and cells.

**Date-range limitation (folds #3; Cam-accepted 2026-10-12).** `native_bucket_perturb`'s bucket arithmetic uses pandas Timestamps, whose range is 1677-09-21..2262-04-11. Two cases, both now defined:
- A date OUTSIDE that range (e.g. the sentinel `9999-12-31`, `2299-01-01`) is coerced to NaT by `pd.to_datetime(errors="coerce")` on BOTH the oracle and native paths, so BOTH pass it through UNCHANGED (verified by probe). No divergence; sentinels are safe.
- A date that PARSES in-range but whose bucket start/offset arithmetic steps just outside the range (within ~1 bucket of 1677-09 or 2262-04) overflows on the native path while the oracle's Python-date arithmetic succeeds. Cam accepted the pandas range as the native domain (2026-10-12): the native path FAILS CLOSED on such a value with a coded, caller-visible reason (`out_of_core_bucket_perturb_date_out_of_native_range:{col}`), never a silent wrong result; the full historical/future range remains maskable on the Python (no-companion) path. This is a documented, accepted native-domain limitation for an essentially-never-occurring input, not an unhandled fault. (The forthcoming D1c sentinel-preserve feature additionally lets users pass chosen dates through untouched.)

Reason codes value-free (strategy/column/type only): `index_extension_unavailable`, `bucket_perturb_source_not_string:{col}:{type}`, `bucket_perturb_config_declined:{col}:{code}` (carrying the resolver's coded reason), `out_of_core_bucket_perturb_date_out_of_native_range:{col}`. An empty/all-null/all-unparseable batch made zero compiled calls (`derive_calls` 0); the whole-column call count accumulates so a trailing zero-call batch cannot overwrite an earlier native claim; a column that made no native call reports `executed_backend: none`. Nothing silently falls back.

## 5. Behavior-preservation + parity contract
1. **Byte-identical output:** for every eligible bucket_perturb cell, native is byte-identical to the `apply_bucket_perturb` reference (same keyed offset: `derive_index_batch` reproduces `int.from_bytes(derive(...)[:8],"big") % bucket_size`), null/unparseable/out-of-range passed through unchanged.
2. **Oracle parity:** OOC native bucket_perturb strict-equal (D0 `_strict_compare`, modulo frozen D0 gaps) to the pandas oracle on a payload date column and an FK-chain table's date column, across week/month/quarter (incl. a leap-year quarter), with output-type reconciliation (§3).
3. **Per-batch == whole-column** (explicit date_format), **Never half-native** (pinned at prep; abort on drift/fault).
4. **No silent fallback (§5):** every bucket_perturb column is {native + witness + `rust_companion`} OR {`apply_bucket_perturb` + `python_pandas` + a caller-visible reason}; no capability regression on a no-companion install (the Python path keeps the full date range).
5. **Witness:** native bucket_perturb proves native-result-CONSUMED at the insertion boundary, spied on the ACTUAL bucket_perturb binding (not hash/categorical/scalar), using `derive_calls`/native-call accumulation so an empty/all-null column does not read as native. Declined reports the pandas path. No existing test weakened; the oracle + native ext untouched.

## 6. Acceptance tests (land the contract test first)
- **Declined, companion absent (ci-mirror):** output byte-identical to the pinned pre-D1b-i pandas baseline; disposition = `python_pandas` + `index_extension_unavailable`; witness = pandas-only.
- **Declined via the resolver (companion present):** a non-string source (`bucket_perturb_source_not_string`), a `%z`/`%Z` tz-directive format, and an unsupported bucket each stay on the pandas path with the matching coded reason, output == pandas baseline.
- **Native, companion present (abi-3 venv):** output strict-equal to the oracle (with output-type reconciliation) AND equal to the reference, across WEEK / MONTH / QUARTER + a leap-year quarter + an explicit `date_format`; per-batch == whole-column; disposition = `rust_companion`; derive_calls > 0.
- **Date-range boundary (folds #3):** out-of-range dates (`9999-12-31`, `2299-01-01`) pass through UNCHANGED and identically on both paths; an in-range date whose bucket arithmetic overflows the pandas range (near 1677-09 / 2262-04) fails closed natively with `out_of_core_bucket_perturb_date_out_of_native_range` and the same column masks successfully on the Python path.
- **Pass-through + boundary:** null + unparseable rows pass through unchanged on both paths; empty / all-null / all-unparseable batch reports `executed_backend: none` (zero derive calls); BOTH populated-then-all-null and all-null-then-populated batch orders (the trailing zero-call batch must not overwrite an earlier native claim); multi-batch column; ABI-incompatible load declines `index_extension_unavailable`; source-type drift aborts with sink abort + no commit; missing pinned column rejected.
- **Witness:** insertion-boundary attribution on the bucket binding with table/column/call context; a discarded-native + equal-valued-pandas control MUST FAIL the native-consumed assertion; loader self-test excluded.
- **Performance gate (program §8, PREDECLARED):** isolated-process micro-benchmark, native vs pandas-bridge, FROZEN seeded workload: 5,000,000 `pa.string()` dates in a fixed `date_format`, ~5% null + ~2% unparseable, bucket = month, all in-range; batch 65,536; native threads = 4; 7 measured native rounds (1 warmup) + 3 pandas rounds (coarse p95 disclosed); timing wraps the mask pass only; output fully consumed. Memory gate = TOTAL process peak RSS <= 1,024 MiB (baseline/delta separate). Acceptance = native p50 < pandas p50 AND native total peak RSS <= 1,024 MiB. 100M/200M proofs remain D4c.
- **Must pass unchanged:** the full D0 parity suite + `test_out_of_core_fk_parity.py` + the OOC route's existing tests + the D1a/D1b-ii disposition/witness suites + module-size/import-boundary sentries. No existing test weakened.
