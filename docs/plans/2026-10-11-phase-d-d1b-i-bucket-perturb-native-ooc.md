## 1. Why + what
The out-of-core route masks `bucket_perturb` by BRIDGING to pandas: `_mask_group_c._bucket_perturb_array` runs `apply_bucket_perturb` on a pandas Series and returns `pa.array(perturbed, from_pandas=True)`. Program §5 names this pandas payload bridge for replacement. The compiled companion already carries the index kernel (`derive_index_batch`), and the existing native ext `native/_bucket_perturb_ext.native_bucket_perturb` already perturbs a date-string column through it (used by the native-chunked route). D1b-i routes the OOC bucket_perturb compute through that SAME ext when the companion is present and the column is eligible, so admitted OOC bucket_perturb runs on the compiled index kernel instead of the pandas bridge. No new Rust, no ABI change; `apply_bucket_perturb`, `native_bucket_perturb`, and the oracle seam are untouched (dispatch lives in the adapter/seam, not inside `_bucket_perturb_array`).

Third native-OOC slice; reuses the merged mechanism (per-column decision pinned at prep, index kernel loaded once and threaded via `_hash_run`'s run object, declined-with-reason + caller-visible disposition, insertion-boundary witness, abort-on-drift, predeclared perf) and the D1b-ii gate lessons (reuse the single config/source resolver; the chunked null-type reconciliation rule; witness on the actual operator binding; accumulate kernel calls over the whole column). It is scoped to `bucket_perturb` ALONE.

**NFC / accepted divergence (corrects rev-1's "no NFC surface" AND rev-2's "unreachable" claims).** The keyed within-bucket offset derives from the canonicalized source value (`derive_index_batch` canonicalizes like `derive`, which NFC-normalizes strings), so bucket_perturb shares the same canonicalization basis as hash/categorical. It IS reachable: the shared resolver admits Unicode literals in `date_format`, so a format with a Unicode suffix (and a value carrying it) can make native and Python select a different offset for a codepoint newer than the running Python's Unicode version (gate-reproduced: oracle 2024-02-08 vs native 2024-02-05). So bucket_perturb carries the SAME accepted native-vs-Python Unicode-version divergence as hash (Cam 2026-10-11): native is canonical, parity is byte-identical for shared-Unicode-version input, and the difference is documented (`docs/strategies.md` bucket_perturb + `compatibility-contract.md` 3.3), characterized by a bucket-specific selection-exposing fixture, and version-guarded by the same lock-test. Ordinary ASCII date formats (the common case) never diverge.

## 2. Scope
The OOC bucket_perturb compute has one entrypoint: `_mask_group_c._bucket_perturb_array`, reached from the Group-(c) dispatch in both streaming drivers' `mask_batch`/`mask_column` path.

**IN (routed native when eligible):** dispatch to `native_bucket_perturb(array, bucket, date_format, mask_key=job_seed, namespace, index_kernel, native_threads, derive_calls)` when ALL hold (decided ONCE at prep, immutable for the run): (a) the companion loads and `load_compiled_index_kernel()` succeeds (abi-3); (b) the column is admissible per the SINGLE existing resolver `native/_operator_config_rejections.bucket_perturb_config_rejection(...)` returning None — it admits ONLY the string-source, explicit-`date_format`, TZ-FREE, valid-bucket (`_VALID_BUCKET_PERTURB_BUCKETS` = **week/month/quarter**), namespaced variant (both native boundaries already call this one resolver, so OOC never diverges from the chunked route). **Authoritative source-type binding (folds rev-2 #3):** that resolver returns None when it cannot resolve the source type (its resident path expects a `pa.Table`, not a bare schema or lazy source), so `None` alone does NOT prove a string source. Prep therefore hands the resolver the captured source schema as an authoritative zero-row table (`source_schema.empty_table()`), so a non-string / lazy / profile-vs-schema-disagreeing source DECLINES AT PREP rather than being admitted and then failing the per-batch string check. The native ext parses with `pd.to_datetime(errors="coerce")`, snaps parseable rows to a keyed within-bucket offset via `index_kernel.derive_index_batch`, strftimes back, passes null/unparseable rows through UNCHANGED, and returns pinned `pa.string()`. Whole column takes ONE path, never half-native.

**PRECEDENCE PRINCIPLE (the root of the decline-vs-error classification; folds rev-2/3/4 config findings).** D1b-i changes the COMPUTE PATH only; it does NOT change config validation, its errors, or their precedence. The engine's existing pipeline runs unchanged and FIRST: OOC-compatibility check -> config preflight (`validate_bucket_perturb_config` + namespace + explicit-`date_format` gate) -> masking. Any config that errors today errors IDENTICALLY after D1b-i, with the companion present or absent — an unsupported bucket (`bucket_perturb_invalid_config`), a missing namespace (`bucket_perturb_requires_namespace`), a missing/empty OR otherwise-invalid `date_format` incl. a tz-directive on an invalid format or a special format like `mixed`/`ISO8601` (`bucket_perturb_invalid_config` / `out_of_core_bucket_perturb_autodetect_unsupported`). D1b-i never turns a hard-error config into a "successful decline" and never claims a disposition for one.

**Native selection is a post-preflight FILTER, applied ONLY among configs that already mask SUCCESSFULLY on Python.** For such a config, the native-eligibility resolver (`bucket_perturb_config_rejection`) + the companion-load + the string-source check decide native vs the retained Python path; a `None` from the resolver is a subset filter, never a replacement for preflight. The cases that pass preflight (Python succeeds) but DECLINE native, dispositioned with a caller-visible reason: companion absent/ABI-incompatible (`index_extension_unavailable`); a non-string source (`bucket_perturb_source_not_string`); a tz-directive (`%z`/`%Z`) on an OTHERWISE-VALID format (the one format case that validates yet declines native). Whole column takes ONE path, never half-native.

**Also out:** categorical (D1b-ii, merged) + hash (D1a); SEQ route (D2); the program-plan's separate D1b remaining-ops slice; any change to the companion crate / ABI / native-chunked route; any change to OOC admission/routing; any change to `apply_bucket_perturb` or `native_bucket_perturb`.

## 3. Eligibility, pinning, output-type, and the date-range limitation
**Pinning.** The per-column decision is computed once at prep from the companion-load result (index kernel loaded once per run, raising `index_extension_unavailable`, mirroring `_dispatch.py:508`) + `bucket_perturb_config_rejection`. The loaded kernel is threaded into the per-batch native call; the decision is immutable, no mid-stream switch. Each native batch validates its incoming source type against the pinned `pa.string()` and ABORTS the run on drift or kernel fault (sink abort, nothing committed); a missing pinned column is rejected. The explicit-`date_format` invariant (no whole-column autodetect) makes the per-batch native result equal the whole-column result, the invariant the pandas path already relies on.

**Output-type reconciliation (folds #1).** The pandas path returns `pa.array(perturbed, from_pandas=True)`: perturbed date strings infer `pa.string()`, but an EMPTY or entirely-NULL output infers null-typed. `group_c_output_type` alone cannot reproduce that (it always returns string). So D1b-i reconciles the native output to the oracle function's own data-dependent shape, the same rule the native-chunked route applies (`_chunk_masking.py:244`): an empty OR all-null output becomes `pa.nulls(len)`, otherwise `pa.string()`; an all-unparseable-but-present batch stays `pa.string()` (the values passed through). Applied before resident assembly (sink reconciliation separate), preserving the existing field/schema assembly so the strict D0 comparator (type_width + field_metadata + null-vs-NaN) sees byte-identical schema and cells.

**Date-range limitation (folds #3; Cam-accepted 2026-10-12).** `native_bucket_perturb`'s bucket arithmetic uses pandas Timestamps, whose range is 1677-09-21..2262-04-11. Two cases, both now defined:
- A date OUTSIDE that range (e.g. the sentinel `9999-12-31`, `2299-01-01`) is coerced to NaT by `pd.to_datetime(errors="coerce")` on BOTH the oracle and native paths, so BOTH pass it through UNCHANGED (verified by probe). No divergence; sentinels are safe.
- A date that PARSES in-range but whose bucket start/offset arithmetic steps just outside the range (within ~1 bucket of 1677-09 or 2262-04) is unsafe on the native path. CRITICAL (folds rev-2 #1): the native ext's `normalize()` can SILENTLY WRAP here (producing a wrong date with NO exception, e.g. `1677-09-21 12:00:00` week-bucket -> a 2262 date), so exception-translation alone is insufficient and would be silent corruption, which Cam's accepted limitation does NOT permit. So the OOC adapter GUARDS explicitly BEFORE consuming the native result: it computes the unsafe boundary zone (any parseable date within one `bucket` window of `pd.Timestamp.min`/`.max`) and, if any batch row falls in it, FAILS CLOSED with a coded, caller-visible reason (`out_of_core_bucket_perturb_date_out_of_native_range:{col}`) and sink abort / no commit, rather than trusting the possibly-wrapped kernel output. The full historical/future range remains maskable on the Python (no-companion) path. Documented accepted native-domain limitation (Cam 2026-10-12), fail-closed never silent. (The forthcoming D1c sentinel-preserve feature additionally lets users pass chosen dates through untouched.)

Reason codes value-free (strategy/column/type only): `index_extension_unavailable`, `bucket_perturb_source_not_string:{col}:{type}`, `bucket_perturb_config_declined:{col}:{code}` (carrying the resolver's coded reason), `out_of_core_bucket_perturb_date_out_of_native_range:{col}`. An empty/all-null/all-unparseable batch made zero compiled calls (`derive_calls` 0); the whole-column call count accumulates so a trailing zero-call batch cannot overwrite an earlier native claim; a column that made no native call reports `executed_backend: none`. Nothing silently falls back.

## 5. Behavior-preservation + parity contract
1. **Byte-identical output (shared-Unicode-version input):** for every eligible bucket_perturb cell whose input is within the shared Unicode version, native is byte-identical to the `apply_bucket_perturb` reference (same keyed offset: `derive_index_batch` reproduces `int.from_bytes(derive(...)[:8],"big") % bucket_size`), null/unparseable/out-of-range passed through unchanged. For a post-version Unicode codepoint reachable via a Unicode `date_format`, the accepted divergence applies (native canonical, documented + locked).
2. **Oracle parity:** OOC native bucket_perturb strict-equal (D0 `_strict_compare`, modulo frozen D0 gaps) to the pandas oracle on a payload date column and an FK-chain table's date column, across week/month/quarter (incl. a leap-year quarter), with output-type reconciliation (§3).
3. **Per-batch == whole-column** (explicit date_format), **Never half-native** (pinned at prep; abort on drift/fault).
4. **No silent fallback (§5):** every bucket_perturb column is {native + witness + `rust_companion`} OR {`apply_bucket_perturb` + `python_pandas` + a caller-visible reason}; no capability regression on a no-companion install (the Python path keeps the full date range).
5. **Witness:** native bucket_perturb proves native-result-CONSUMED at the insertion boundary, spied on the ACTUAL bucket_perturb binding (not hash/categorical/scalar). A zero-compiled-call ("idle") batch is accepted as part of a native column ONLY when independently verified to be genuinely empty, all-null, OR all-unparseable-under-the-pinned-format with output == input (not merely `derive_calls == 0`): zero calls proves native did not run, not that it was unnecessary. A populated PARSEABLE batch that returns a result with no compiled call stays UNKNOWN and fails the whole-column native proof (the categorical verified-idle lesson, applied to bucket). Declined reports the pandas path. No existing test weakened; the oracle + native ext untouched.

## 6. Acceptance tests (land the contract test first)
- **Declined, companion absent (ci-mirror):** output byte-identical to the pinned pre-D1b-i pandas baseline; disposition = `python_pandas` + `index_extension_unavailable`; witness = pandas-only.
- **Declined to working Python (companion present):** a non-string source (`bucket_perturb_source_not_string`) and a `%z`/`%Z` tz-directive format each stay on the pandas path with the matching coded reason, output == pandas baseline.
- **Config hard errors preserved (folds rev-3 #1 + rev-4 #1):** an unsupported bucket, a missing namespace, a missing/empty `date_format`, an INVALID format (`%z` alone, `%H:%M`, `mixed`, `ISO8601`, `123`), AND a tz-directive-on-an-invalid-format each RAISE the existing error identically with the companion present AND absent, no sink commit — asserted as errors, NOT as successful output or a disposition. A tz-directive on an OTHERWISE-VALID format is the one case that validates and DECLINES native (Python succeeds), dispositioned `python_pandas`. Confirms the existing OOC-compat -> config-preflight -> masking precedence is unchanged (not replaced by resolver ordering).
- **Native, companion present (abi-3 venv):** output strict-equal to the oracle (with output-type reconciliation) AND equal to the reference, across WEEK / MONTH / QUARTER + a leap-year quarter + an explicit `date_format`; per-batch == whole-column; disposition = `rust_companion`; derive_calls > 0.
- **Date-range boundary (folds rev-2 #1+#3):** out-of-range dates (`9999-12-31`, `2299-01-01`) pass through UNCHANGED and identically on both paths (passthrough, not "masking"); a SILENT-WRAP boundary date (the gate's `1677-09-21 12:00:00` week-bucket case, which the native ext wraps without raising) is caught by the adapter guard and fails closed with `out_of_core_bucket_perturb_date_out_of_native_range` + sink abort / no commit; lower (near 1677-09) and upper (near 2262-04) bound cases likewise; the same columns mask successfully on the Python path.
- **NFC accepted divergence (folds rev-2 #2):** a bucket-specific selection-exposing fixture — a Unicode `date_format` suffix with a post-Python-version codepoint — asserts native != Python (the accepted difference), kept SEPARATE from a fixed native-output lock; the dependency/table-version guard asserts the Unicode-table version; an ordinary ASCII date format selects identically on both paths.
- **Source-type binding (folds rev-2 #3):** fed `source_schema.empty_table()`, the resolver makes the Arrow source type authoritative over the profile: a non-string source (resident OR lazy) declines at prep with `bucket_perturb_source_not_string`, a lazy STRING source qualifies, and a profile-vs-schema disagreement resolves to the schema. A missing field (resolver returns None for an absent column) is established separately by the pinned-column presence check, not treated as eligible.
- **Pass-through + boundary:** null + unparseable rows pass through unchanged on both paths; empty / all-null / all-unparseable batch reports `executed_backend: none` (zero derive calls); BOTH populated-then-all-null and all-null-then-populated batch orders (the trailing zero-call batch must not overwrite an earlier native claim); multi-batch column; ABI-incompatible load declines `index_extension_unavailable`; source-type drift aborts with sink abort + no commit; missing pinned column rejected.
- **Witness:** insertion-boundary attribution on the bucket binding with table/column/call context; a discarded-native + equal-valued-pandas control MUST FAIL the native-consumed assertion; loader self-test excluded.
- **Witness verified-idle (folds rev-3 #2):** an idle (zero-compiled-call) batch is accepted as part of a native column only when independently verified empty / all-null / all-unparseable-under-the-pinned-format with output == input. A bucket-specific laundering control — a later PARSEABLE batch returning equal-valued Python output with zero compiled calls, in BOTH orders (after and before a native batch) — MUST FAIL the whole-column native-consumed assertion.
- **Performance gate (program §8, PREDECLARED):** isolated-process micro-benchmark, native vs pandas-bridge, FROZEN seeded workload: 5,000,000 `pa.string()` dates in a fixed `date_format`, ~5% null + ~2% unparseable, bucket = month, all in-range; batch 65,536; native threads = 4; 7 measured native rounds (1 warmup) + 3 pandas rounds (coarse p95 disclosed); timing wraps the mask pass only; output fully consumed. Memory gate = TOTAL process peak RSS <= 1,024 MiB (baseline/delta separate). Acceptance = native p50 < pandas p50 AND native total peak RSS <= 1,024 MiB. 100M/200M proofs remain D4c.
