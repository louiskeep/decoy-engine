## 1. Goal and scope

Deterministic `categorical` never runs on the chunked route today: it is in `CHUNKED_ROUTE_VETOED_STRATEGIES` (`execution/native/_requirements.py:151`), so any table carrying a categorical column is vetoed whole to the pandas oracle (every sibling column too). C1 makes **native-admissible deterministic categorical** a first-class chunked-native operator, executed per chunk through the compiled kernel that already exists, with byte parity against the pandas oracle, so a categorical column no longer forces its table off the native route.

In scope: deterministic categorical that is **native-admissible** = `is_deterministic_categorical` (either `deterministic: true` or `allow_collisions: true`) AND a namespace AND non-empty all-string categories AND buildable weights/CDF AND a **string source column** (the config gate `categorical_config_rejection`, `execution/native/_operator_config_rejections.py:44-86`, covers the config half; the source-type half is section 4).

Out of scope (explicit, each stays on its current path, unchanged by C1):
- Non-deterministic categorical (unseeded whole-column RNG): slice **C1b**. It currently fails chunked PREFLIGHT (section 2); C1 keeps it failing, with a distinct C1b-owned reason code, and does NOT define a per-chunk oracle execution for it.
- Deterministic categorical that is NOT native-admissible (numeric/non-string categories, non-string source, bad weights): stays on the pandas oracle with its existing value/type behavior. C1 must not change it, and in particular must not string-pin it (HIGH 2).
- The full-frame / unified-slice route: unchanged. The output-type pin is applied only on the two CHUNKED legs (section 3).

## 2. Established facts (engine HEAD f8c8bf36)

- **Kernel exists, full-frame parity-tested; C1 builds no new Rust.** `native_categorical` (`execution/native/_categorical_ext.py:38-123`) wraps `IndexDerivationKernel.derive_index_batch` + a NumPy gather; weighted path does `np.searchsorted(cdf, bucket, side="right")` with a clamp. Runs full-frame via `execution/physical/_shadow_operators.py:228-243`; covered by `tests/native/test_categorical_ext.py`, `test_derive_index_kat.py`, `tests/physical/test_shadow_categorical.py`. Caveat: existing full-frame native admission is **string-source only** (`execution/_unified_slice_admission.py:155`).
- **Deterministic categorical is row-local; no cross-chunk state.** Each row maps from its own canonicalized source value + `(mask_key, namespace)` via `derive_index` (`_strategies/_categorical.py:~187`); nulls -> None. Cross-chunk consistency is automatic (`execution/native/_capabilities.py:214`, row-local). No prepass, no sibling state.
- **FIVE gate/decision sites, not four.** The veto/admission for chunked categorical lives at:
  1. `execution/native/_requirements.py:151` -- `CHUNKED_ROUTE_VETOED_STRATEGIES` (the set).
  2. `execution/native/_dispatch.py:238` -- `_static_route_decision` emits `categorical_not_native_chunked_route:<col>`.
  3. `execution/native/_chunked_evidence.py:45` -- plans `PANDAS_ORACLE` for the vetoed column.
  4. `execution/native/_phase3_eligibility.py:116-122` -- eligibility mirror.
  5. **`execution/_chunked.py:189` (`_conditional_admission_failures`), reached via `execution/_chunked_oracle.py:113` (`_oracle_preflight` -> `check_chunked_compatibility`), runs BEFORE native/oracle routing.** It rejects non-deterministic categorical at preflight, and today it tests only `col_entry["deterministic"]` (it does NOT recognize `allow_collisions`). This is an upstream admission dependency, not a fifth mirror of the veto set.
- **Non-deterministic categorical fails at chunked PREFLIGHT** (site 5 above), before `plan_native_route`, before route evidence, before either leg executes. It does NOT currently "veto its table to the oracle" (revision 1 said this; it was wrong). The native config gate `categorical_config_rejection` also rejects it, as defense in depth behind the earlier preflight rejection.
- **Data-dependent output TYPE is the one hard problem.** Categorical output type depends on contents: empty -> float64, all-null -> null, else -> string (`execution/native/_shadow_assembly.py:20-53`, categorical in `_TOKENIZING_STRATEGIES`). Full-frame resolves it once at `assemble_column`; the chunked route has no assembly point (`execution/native/_chunked_entry.py:155-263` emits each chunk eagerly; the native kernel pins `pa.string()` per batch). The oracle chunked leg yields per-chunk content types today, flagged provisional by the characterization test `tests/native/test_chunked_entry_values_schema.py:474` ("until a later phase pins them"). C1 is that phase.
- **Source-type admission is NOT enforced for categorical past the veto.** The shared ingest guard rejects null-bearing int for categorical (`null_bearing_int_unsupported`, `execution/_guards.py:34`), but `real_type_rejection` (`execution/native/_real_type_admission.py:44`) has no categorical source-type check. So simply removing the veto would admit ANY Arrow source type past preflight and fail only when the kernel runs. C1 must add a source-type admission (section 4).
- **Preflight loads the index kernel only for faker** (`_dispatch.py` ~`:422-430`), downgrading with `index_extension_unavailable`. Categorical needs it (`KernelAvailability.index`, `execution/native/_companion_status.py:~353`).
- **`_mask_chunk_native` has no categorical branch and no per-column handler-state object** (`execution/native/_chunk_masking.py:~160-230`); it receives `ColumnSeed` values per chunk. Full-frame categorical inputs are `binding.categorical_categories` + `binding.categorical_cdf` (`_shadow_operators.py:228-238`).
- **Module sizes safe today:** `_chunk_masking.py` 319, `_dispatch.py` 504, `_chunked_schema_rule.py` 129. Keep touched files under the 600 cap.

## 3. The output-type decision (core choice), now CONDITIONAL

**Decision: on the chunked route, native-admissible deterministic categorical output is pinned to `pa.string()` on BOTH chunked legs, and the characterization test is updated to assert the pinned type -- but the pin is CONDITIONAL, applied only to categorical configurations that are native-admissible.** Rationale as revision 1 (all-string categories make string the intrinsic type; empty->float64 / all-null->null are pandas inference artifacts; a column's Arrow type must not depend on chunk boundaries; pinning both chunked legs keeps native == oracle).

HIGH 2 correction: `build_schema_rule` (`execution/native/_chunked_schema_rule.py:56`) classifies raw config and applies on the oracle leg too. Adding `categorical` UNCONDITIONALLY to `_STRING_OUTPUT_STRATEGIES` would also pin deterministic-but-numeric-category categorical (which native rejects and the oracle executes), changing its values/types outside C1's scope. So the schema-rule pin must reuse the SAME native-admissibility predicate as the route decision (prefer calling `categorical_config_rejection` / `is_deterministic_categorical` + all-string-categories, not a duplicated condition). A deterministic categorical with non-string categories must remain on the oracle with its existing per-chunk behavior and must NOT be cast to string (regression test, section 5).

**Cross-route note (Codex MEDIUM 6):** C1 CREATES a route-dependent difference for the all-null native-admissible categorical column: it was oracle-inferred `null` on the chunked route and becomes pinned `string`, while the full-frame route keeps `null` via `assemble_column`. This is acceptable to defer under the current pre-GA compatibility contract, which already permits route-dependent schema (`ROUTE-OUTPUT-CONTRACT`); a B7 multi-table split job CAN carry both shapes across different tables simultaneously (so do not claim a single job never sees both). C1 records this new case in `docs/compatibility-contract.md` and `CHANGELOG.md`, runs the Barry documentation pass with an exact-HEAD gate receipt (section 6), and leaves full-frame alignment as a tracked follow-up.

## 4. Implementation

1. **Upstream preflight gate (`execution/_chunked.py:189`, BLOCKER).** Change `_conditional_admission_failures` so native-admissible deterministic categorical PASSES chunked preflight, using the shared `is_deterministic_categorical` (so `allow_collisions: true` is recognized, not just `deterministic: true`). Non-deterministic (and config-ineligible) categorical stays REJECTED at preflight with a distinct, C1b-owned code **`categorical_nondeterministic_not_chunk_safe`** (neither chunked leg is valid for it yet; C1b lifts this after defining chunking semantics). Do NOT claim non-deterministic reroutes to the per-chunk oracle.
2. **Remove the veto** at sites 1-4 (section 2), conditioned on native-admissibility (not a blanket un-veto): a non-native-admissible categorical column still routes its table to the oracle through the normal non-native fallback policy, exactly as today.
3. **Source-type admission (HIGH 3).** C1's input-type domain is **string source only**, matching the proven full-frame route (`_unified_slice_admission.py:155`). Add a categorical source-type admission in preflight (`real_type_rejection` / the route decision) so a non-string source reroutes to the oracle BEFORE masking, never failing from the kernel after admission. Integer-with-nulls stays rejected (`null_bearing_int_unsupported`) and is a fail-closed parity case, not a positive one.
4. **Prepared categorical mapping (MEDIUM 4).** Build the categories + optional CDF ONCE after preflight and before `_native_route`, as a prepared per-column mapping object, and thread it through `_native_route` into `_mask_chunk_native`'s new categorical branch. `_build_cdf` must run once per column, never per chunk (assert in a test).
5. **`_mask_chunk_native` categorical branch** (`_chunk_masking.py`): call `native_categorical(index_kernel, prepared_mapping, chunk)` per chunk; nulls restore positionally (kernel null-masks).
6. **Preflight index-kernel load** (`_dispatch.py` ~`:422-430`): widen the guard to `any(n.strategy in {"faker", "categorical"} ...)`; keep `index_extension_unavailable` downgrade (companion-absent -> categorical reroutes to the oracle).
7. **Output-type pin** per section 3 (conditional, both chunked legs, `_chunked_schema_rule.py`).
8. **Evidence/backend (MEDIUM 5).** Native-admitted categorical reports backend **`rust_companion`** explicitly (`_chunked_evidence.py` `_planned_backend`), with `compiled_kernel_executed is True` and `kernel_calls["categorical"] == number_of_chunks`; planned `rust_companion` + executed `rust_companion` when admitted, planned `rust_companion` + executed `pandas_oracle` when the index companion is unavailable. The oracle leg (non-admissible or companion-absent) stays `pandas_oracle`.
9. **Fixture migration (MEDIUM 5).** Exhaustive `rg` inventory of categorical used as an oracle-forcing fixture; each occurrence classified as (a) a genuine new categorical acceptance test, or (b) an oracle-forcing fixture migrated to a still-vetoed `bucket_perturb` column. Known sites to start: `tests/native/_b8_support.py`, `test_chunked_entry_evidence.py`, `test_chunked_entry_side_channels.py`, `test_chunked_entry_parity_matrix.py`, `test_chunked_entry_values_schema.py`, `test_unconfigured_passthrough.py` (plus any the inventory turns up).

## 5. Acceptance tests (written before implementation; red-before recorded)

Parity contract: native chunked == pandas-oracle chunked, byte-for-byte on values AND Arrow field type AND metadata, row/column order, warnings, errors, evidence. Extend `tests/native/_chunked_entry_support.py` (has a deterministic `categorical(name)` fixture) and the `test_chunked_entry_*` suite.

1. **Parity matrix (corrected domain, HIGH 3).** Native-admissible deterministic categorical (uniform and weighted), **string source only**, over chunk shapes {empty, all-null, single-row, ragged last chunk, all-null chunk beside a valued chunk}, chunk sizes {1, 7, 50_000}, native_threads {1, 4}. Assert native == oracle per chunk and across the reassembled column (values + Arrow type + metadata). Non-string / integer-with-null source is a FAIL-CLOSED parity case (reroutes to the oracle before masking; `null_bearing_int_unsupported` holds), NOT a positive native case.
2. **Determinism across chunks.** Same source value in different chunks -> same category; equals the full-frame deterministic result for the same `(mask_key, namespace)`.
3. **Output-type pinning (conditional).** All-null and empty chunks both yield a `string` column on native AND oracle legs for native-admissible categorical (rewritten `test_chunked_entry_values_schema.py:474`). Chunk-count invariance: same data split 1 vs N ways -> identical Arrow type. **Regression:** a deterministic categorical with NON-string (numeric) categories stays on the oracle with its existing value/type behavior and is NOT string-cast (HIGH 2).
4. **Determinism alias + non-deterministic (BLOCKER).** `deterministic: true` and `allow_collisions: true` are each admitted to the native chunked route (tested separately); absent/false determinism fails at chunked preflight with `categorical_nondeterministic_not_chunk_safe` BEFORE any chunk is yielded.
5. **Veto lift for admissible, hold otherwise.** A native-admissible categorical column lets its table run native (sibling redact/hash columns run native, not forced to the oracle); a non-admissible categorical column still routes the table to the oracle. Update `test_chunked_entry_evidence.py:254-258` to the native backend + lifted veto for the admissible case.
6. **Evidence (MEDIUM 5).** Assert backend `rust_companion`, `compiled_kernel_executed is True`, `kernel_calls["categorical"] == number_of_chunks`, and the planned/executed label pairs (admitted vs companion-unavailable).
7. **Companion-absent.** No compiled companion -> categorical reroutes to the oracle (native-result assertions gated `@NEEDS_COMPANION`; oracle-leg parity runs regardless).
8. **Config-gate rejections unchanged** (the eight `categorical_*` codes still fire on the chunked route).
9. **`_build_cdf` built once per column**, not per chunk (MEDIUM 4).
10. **Thread-count invariance** (`tests/native/test_thread_clamp_parity.py` pattern), GIL-release unaffected.

Full-frame categorical suite (`tests/physical/test_shadow_categorical.py`) stays green unchanged except its `test_chunked_route_declines_categorical` seam (`:148-167`), updated so native-admissible deterministic categorical is now admitted on the chunked route (non-deterministic / non-admissible still declines).
