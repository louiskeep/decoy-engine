## 1. FRAME

### 1.1 Problem, guarantee, and boundaries

The MASTER F25 contract supplied with this task is authoritative. F25 is PARTIAL. Existing protections are useful but distributed: some directories are private, some writes stage before rename, and OOC has memory limits plus a periodic disk check. None creates one enforceable resource boundary.

The root cause is independent path allocation and independent lifecycles. A new `mkdtemp`, Arrow writer, SQL `COPY`, or library-managed spill can bypass both protection and capacity policy. Deleting directories named like scratch cannot prove ownership or distinguish a checkpoint from garbage.

**Guarantee:** before any engine-controlled temporary data write, one engine ScratchManager registers the resource under a job/attempt-owned restrictive arena and an enforced byte quota. Protection remains effective during native-library writes, cancellation, crash, restart, and publication. Every actual temporary path in the inventory below must migrate. An unsupported storage capability fails before data is written; it never silently becomes ordinary `/tmp` storage.

The shared ResourceLedger is the enforcement record for allocations, ownership, reservations, retention, and transitions. It is a new deliverable, not an existing class assumed by this plan. Filesystem quota counters remain the authority for actual usage. F25 does not implement a parallel Python disk-accounting algorithm.

Scope includes engine connectors, low-level exported primitives, output staging, subset intermediates, and isolated execution. Permanent inputs and successfully published outputs have their own retention policies; their temporary representations remain in scope. Dependencies F13, F23-F24, F26, and F45 come from the supplied MASTER contract. Their feature numbers do not prove that a specific engine interface exists. Resolve their actual contracts at the cross-surface gate without inventing prerequisite implementations.

Non-goals: a new cipher, a userspace encrypted random-access filesystem, a distributed lock service inside this library, general mid-query resume, changed masking results, a rewrite of memory routing, or protection against arbitrary code running with the engine's own privileges. F25's checkpoint support is a safe storage/retention contract. It does not make DuckDB query state or current operators resumable.

### 1.5 Scratch manager, registration API, and quota construction

Proposed new package: `src/decoy_engine/scratch/`. Public types and operations are provisional names to freeze at plan gate:

```text
ScratchPolicy(job_id, attempt_id, quota_bytes, quota_inodes, retention, storage_profile)
ScratchManager.open_attempt(policy, storage_provider, ownership_authority)
Arena.allocate_file(kind, opaque_name) -> RegisteredFile
Arena.allocate_native_dir(kind, writer_id) -> NativeDirectory
Arena.allocate_publication(destination, retention_owner) -> PublicationStage
Arena.checkpoint(resource, recovery_descriptor, validator_or_manifest) -> CheckpointRef
Arena.release(resource) -> CleanupReport
ScratchManager.sweep(scope, authority) -> SweepReport
```

Pass a narrow typed arena capability through execution context and into each low-level producer. It contains attempt identity, fence generation, approved roots, quota assignment, and resource kind. A raw `Path` does not authorize writing. Registration is durable before a writable path/FD is returned. Opaque DB directories register their whole inherited namespace before connect; a bounded directory-level record is sufficient for filenames controlled by DuckDB. Python-created files have individual records. No retrospective `register(existing_path)` for arbitrary data. A subprocess child receives the arena capability and the liveness-lock file descriptor only through a dedicated restricted pipe or an inherited file descriptor cleared after a single read, never through argv, environment, or a discoverable path; A04 asserts this transport security.

Use generated opaque resource components, not table names or tenant strings as filesystem traversal. Reject symlinks, unexpected owner/mode, hard-link aliases, mount substitution, and path escape. Resolve beneath approved root directory descriptors. Never chmod, adopt, or recursively delete an arbitrary caller root. All child creation inherits an already verified encryption and quota domain. A crash during creation leaves a registered CREATING resource or a conservatively retained unknown object, not an unowned data directory.

**Capability contract (corrected: identity-bound handles, use-time verification).** *Provenance: argon 2026-10-30 plan-remediation after the 3-round publication-TOCTOU cap.* The original contract specified the choke-point as a provenance and static-analysis boundary and defined `unwrap_path(cap) -> pathlib.Path` / `unwrap_dir(cap) -> pathlib.Path` as pure getters that returned a stored path. A getter leaves a TOCTOU window: between the `Path` it returns and the moment the caller (`open()`, DuckDB, libpq) hands that string to the kernel, a co-process on the same principal can swap the parent or the target for a symlink or a different inode. Verifying only at allocation does not close it. The corrected contract is:

1. A capability is an **identity-bound handle**, not a wrapper around a `pathlib.Path`. Pinned at allocation it carries `_parent_identity` and `_identity` as `(st_dev, st_ino)` tuples and `_expected_mode` (the full `S_IFMT | perm`). It stays a frozen value object and holds no long-lived file descriptor.
2. `unwrap_path`, `unwrap_dir`, `open_capability_fd` and `Arena.release` **re-verify at use time**. Each opens the parent `O_RDONLY|O_NOFOLLOW|O_DIRECTORY`, asserts the parent `(st_dev, st_ino)` still equals `_parent_identity`, opens the child relative to that pinned parent fd `O_NOFOLLOW` (`O_DIRECTORY` for a directory), and asserts the child `(st_dev, st_ino)`, owner and mode are unchanged. Any mismatch or `OSError` (a swapped-in symlink trips `O_NOFOLLOW`) fails closed with `ScratchPathUnsafe` before the caller touches the path. `open_capability_fd` returns an `fstat`-verified descriptor so a Python writer does FD-relative I/O with no path re-resolution after the check; native libraries that need a `char*` use the re-verified `unwrap_path`, whose residual window is now reduced to the verified-identity seam.
3. The parent is **not** required to be owned by this principal (a publication destination is a caller-owned directory); the pinned `(st_dev, st_ino)` identity, not parent ownership, is what defeats a parent swap. The target itself must still be owned by this principal with its expected type and mode. The arena ROOT, which the engine created, is additionally owner-checked when a child is allocated under it.
4. Reclaim is **guaranteed**: `Arena.release` re-verifies identity from its own recorded `(st_dev, st_ino)` before the provider deletes, and the stage-reclaim primitive removes under the pinned parent fd and CONFIRMS the entry is gone (`lstat` under the fd raises `FileNotFoundError`), raising `ScratchPathUnsafe` rather than returning as if clean when removal cannot be confirmed.

This use-time guarantee is the production `Arena` path's. The pre-activation `LocalArena` and the `_seam` adopted-path fallbacks pin no identity (`None`) and keep their prior path-getter behavior. **Superseded for production by Slice 4c:** omission of an arena is currently reachable from production entrypoints, so `None` identities are not merely a dev/unit condition. Slice 4c removes that reachability and makes unmanaged allocation an explicit dev/test-only context.

**No lifecycle or provider API takes a bare `Path` for an existing resource (argon class-fix, 2026-10-30).** The original contract made the capability model a producer-write boundary but left the internal `StorageProvider` protocol, the lifecycle operations (qualification, arena creation, quota observation/probing, release/reclaim), and the verification helper path-based, so a verified check was followed by a path-string operation that re-resolved through the ambient namespace. The corrected rule:

1. Verification is never a `-> None` check that precedes a path operation. It is a context manager (`open_verified_dir` / `open_verified_target`) that yields an open, `fstat`-verified descriptor handle (`VerifiedDir` / `VerifiedChild`), and the operation that inspects or mutates the filesystem runs on that descriptor (or a single-component `*at(..., dir_fd=...)` anchored to it) while it is held open.
2. Every `StorageProvider` method for an existing resource takes a `VerifiedDir` or `VerifiedChild`, not a `Path`: `qualify`, `verify_quota`, `observe`, `probe_exhaustion` take `VerifiedDir`; `reclaim` takes `VerifiedChild`; `create_arena` takes a `VerifiedDir` and returns the child path plus its pinned identity. The provider reads fsxattr and mount options from the fd, walks usage with `os.fwalk`, probes and deletes with `dir_fd`-relative calls, and branches reclaim on file vs directory (a plain file is unlinked, never `shutil.rmtree`'d).
3. The manager pins the root identity once (opening it `O_NOFOLLOW` through `open_verified_dir`) and threads that identity through qualification, arena creation, quota verification, ledger registration and `Arena`, so there are no repeated unverified `os.stat` re-resolutions.
4. This invariant is enforced by construction: an AST build sentry (`tests/scratch/test_fd_only_filesystem_sentry.py`) fails the build on any path-string filesystem operation in `decoy_engine.scratch`, with a pinned allowlist for the control-plane SQLite bootstrap and the pre-activation `_seam` fallbacks.

The selected first deployment profile is Linux local ext4 with verified fscrypt v2 and enforced project quotas. This is a **qualification target**, not an assertion about the current host. A deployment-owned provisioning adapter supplies privileged setup; the engine does not acquire root or mount volumes. Pin tool/kernel/filesystem/library versions in the qualification evidence. Other platforms require equivalent independently proven adapters. Ordinary memory-only operations may continue; operations requiring temporary storage reject with `scratch_backend_unavailable` if no qualified profile exists. This is an intentional compatibility change requiring coordinated release, not an optional safety toggle.

Quota semantics:

1. The declared byte cap bounds filesystem-allocated data blocks charged to the attempt's project quota, including native spill, file tails, metadata files charged by that filesystem, and open-but-unlinked files. Report logical lengths separately. Round an unrepresentable requested cap down to the provider's enforcement unit, expose the effective cap, and reject a cap below the minimum usable allocation. Bound inode count separately and reserve filesystem metadata headroom.
2. On one filesystem, all attempt arenas share one project quota domain. On several filesystems, immutable sublimits sum to at most the attempt cap. Initial V1 does not dynamically rebalance them. Do not allocate the whole cap independently to each sink/connection/worker.
3. Host admission reserves these hard limits plus an explicit control-plane/metadata margin transactionally before allocation. All Decoy jobs on the managed volume use that allocator. A shared volume with uncontrolled writers cannot promise remaining free space; use a dedicated managed pool or reject that capacity guarantee. `statvfs` preflight is advisory, not a reservation.
4. Set/verify project inheritance and hard limits before any writer starts. Quota accounting comes from the kernel through maintained provisioning tools. The ledger stores allocation reservations and kernel observations, not a running sum of intercepted Python writes. Keep DuckDB memory/thread caps and add its temp-size limit as a second backstop only after testing the selected versions.
5. Quota/ENOSPC failures during write, writer close, footer flush, fsync, or SQL execution stop the attempt and prohibit publication. Return typed failure with effective cap, observed usage, arena/resource IDs, and retained-resource disposition. Preserve the primary failure if cleanup also fails. The shared failure reason is `scratch_quota_exceeded`; existing public wrappers retain their documented error code where required, including `out_of_core_temp_disk_exceeded`, and attach the shared report. Freeze other adapter mappings at Slice 0. Do not identify EDQUOT by parsing potentially sensitive native exception strings; use errno where preserved and provider quota evidence otherwise, with an explicit unknown-I/O classification.
6. Release capacity only after writers and descriptors close and the quota provider confirms reclamation or durable-output ownership transfer. A failed cleanup retains its charge and inventory. Never report zero just because a pathname disappeared.

ResourceLedger records: format version, opaque job/attempt/arena/resource IDs, root device/inode identity, resource kind, owner principal, monotonic fence generation, lease reference, quota-domain ID/limit, encryption-policy/key-version reference, recovery/retention classification, and lifecycle state. No DSNs, source values, raw keys, or user-derived filenames in control records.

For standalone local use, a proposed SQLite transactional ownership adapter uses the standard library, short `BEGIN IMMEDIATE` transactions, and conditional updates that verify affected-row counts. Select durable rollback journaling with full synchronization for V1; bound busy waits and treat timeout as unavailable authority. Do not disable journaling to avoid accounting for it. Use one durable control database per managed local pool, not one independent authority per process. Its DB/journal/WAL/SHM and bounded lock records live in a provider-provisioned, encrypted, quota-reserved control arena. That bootstrap arena has an explicit control-job owner, 0700 directory, finite byte/inode quota and durable retention policy, and is registered in the provisioning inventory before opening SQLite. Its temporary sidecars are owned by that control job; bootstrap is not an unregistered scratch exemption. Failure to reserve control space rejects admission; it must still be possible to record a data-quota breach. Set query temporary storage to memory for the bounded metadata workload; this does not eliminate durable rollback journals. Reject operations that can create uncontrolled auxiliary databases, including online VACUUM. Any remaining SQLite temporary storage must stay in a registered native directory. Test its actual files. The platform adapter must bind to its existing durable ownership authority, not run competing local lease decisions. The control arena's reservation is sized so it can always record a terminal failure (for example `scratch_quota_exceeded`) for every other active arena even when near its own limit: recording a data-quota breach can never itself fail on a control-quota limit, and a new acceptance test proves it. The control-arena bootstrap verifies its DB, journal/WAL, and liveness-lock paths all resolve to one device and filesystem, failing otherwise (covered by A13).

Design notes: one resource descriptor is the source of truth for identity and retention; policy is separated from storage capabilities because Linux provisioning and platform lease authority have different owners. Typed contexts avoid long path/key/limit argument lists. Small focused modules hide crypto and quota mechanics from producers. Avoid a universal resource framework for unrelated memory/CPU budgets; expose the scratch ledger seam for the named carrier features to consume.

### 1.6 At-rest protection and publication

The package already depends on `cryptography` (`pyproject.toml:157`). `src/decoy_engine/vault.py:128` uses Fernet and domain-separated derivation; `src/decoy_engine/keyprovider.py:123` validates real secrets. `src/decoy_engine/context.py:348` delegates HKDF to the canonical implementation. Reuse these dependencies and derivation practice, not vault private functions, its seed fallback, or its file format.

Data-path encryption is transparent filesystem encryption, so Arrow IPC, Parquet random access, native DuckDB spills, JSON, and temporary fixed-width files remain ordinary library formats inside the protected mount. Use a fresh OS-CSPRNG arena data key of the size required by the approved fscrypt policy. The key provider supplies entropy and purpose-separated wrapping material; no seed-derived or masking-output-derived scratch key is allowed. Protect a resumable arena's small recovery envelope with PyCA Fernet under a separately versioned scratch wrapping key derived using the existing HKDF. Authenticate the arena/job/policy/version binding inside that envelope and verify it against the trusted ledger. Do not invent chunk framing, nonce management, or an encrypted random-access file protocol.

The fscrypt source documents inherited file/name encryption, visible filesystem metadata, lack of protection against root with loaded keys, policy restrictions on rename, and potentially incomplete key removal. These limits constrain the design. Content authentication for mutable scratch is not claimed by filesystem encryption; authenticated key envelopes do not turn it into tamper-proof storage. Cross-host or hostile-storage checkpoint integrity needs the checkpoint owner's validated format and is outside this local profile.

**Publication must not break encryption or atomicity.** Ephemeral scratch and durable publication stages are different retention classes under the same manager. A publication stage is allocated on the destination filesystem under the destination's approved persistent encryption policy and a per-attempt quota domain. Its key lifetime is owned by the durable destination, not the ephemeral arena. The manager verifies same-filesystem and compatible encryption policy before data production. Unsupported destinations fail before staging; there is no plaintext sibling or copy fallback. Where a copy from ephemeral scratch is necessary, it goes only to another registered, quota-charged protected stage, then the existing single rename publishes it.

Before rename: seal/close writers, fsync data and stage directory, and durably record PUBLISHING with source/destination identity and retention owner. After rename: fsync affected parents, then record PUBLISHED and transfer quota/retention ownership. A crash between rename and ledger completion is reconciled under the publication lock using recorded identities. The sweep always retains ambiguous publication state. Promotion must not remove encryption keys needed by final output or allow quota transfer to exceed the durable storage budget. F25 preserves each existing publisher's transaction boundary; it does not promise one atomic transaction across independently published output and quarantine artifacts.

### 1.7 Threat model and key recovery

Assets include raw source columns, source-to-masked mappings, credentials in isolated payloads, raw quarantine rows, and checkpoint state. Private directories protect against other Unix users; encryption protects storage when keys are unavailable. Neither protects against root, a compromised engine process, or another job sharing that principal and key access. Strong inter-tenant isolation requires the worker's process/identity boundary.

| Policy | Custody and crash behavior | Cleanup/resume rule |
|---|---|---|
| Ephemeral, non-resumable | Fresh arena key, no durable recovery envelope. Worker/key custodian holds it only for the attempt. A process crash may leave a kernel-loaded key, so “lost on crash” is a recovery promise, not instant cryptographic erasure. | Never advertise resume. After fencing and closing users, attempt key removal and record busy/incomplete removal. A host restart without retained keys cannot recover the arena. Authorized orphan cleanup can still delete it. |
| Resumable storage | Persist and fsync the authenticated recovery envelope under a durable approved wrapping-key reference before marking a checkpoint valid. Keep the versioned wrapping key accessible across worker/host restart through the caller's key service. | A new owner must obtain a new fence, authorize unwrap, authenticate identity, and validate checkpoint format/completeness before resume. Unsupported key-provider recovery refuses checkpoint creation. |
| Durable publication | Persistent destination policy and key custody, established before publication. | Survives attempt cleanup. It is not swept or rendered unreadable when ephemeral keys are removed. |

Checkpoint validity is a committed state, never a filename convention. Register a fresh checkpoint generation as WRITING; write its payload and recovery envelope, close and fsync both, then atomically publish and fsync the checkpoint manifest that binds their identities and the consumer format/version. Only then CAS the durable ledger to CHECKPOINT_VALID under the current owner fence. Keep the previous valid generation until this transition completes. A crash leaves the previous checkpoint valid and the new generation incomplete or ambiguous, which startup retains for reconciliation. Resume requires the consumer to validate the complete format before returning a usable checkpoint handle. `Arena.checkpoint` accepts a validator callable or an expected-contents manifest (files, sizes, checksums); after `CHECKPOINT_VALID` the manager can run `verify()` to distinguish a structurally complete but encrypted checkpoint from a corrupted or partially written one, so provably broken checkpoints can be garbage-collected rather than retained forever. A09 exercises this verification step.

Missing, revoked, wrong-version, or unavailable wrapping keys produce `scratch_recovery_key_unavailable`; authentication failure produces `scratch_recovery_invalid`. Both retain the checkpoint and emit a safe diagnostic. Key failure is never evidence that the checkpoint is disposable. Rotation preserves old versions while referenced, or rewraps and durably verifies envelopes before retiring them. Rewrap failure leaves the old valid envelope. Never place key bytes in configs, manifests, argv, environment dumps, or the isolated JSON payload; use an inherited restricted channel or caller key service.

Swap, core dumps, hibernation and backups are deployment controls: disable them for the worker or independently encrypt/protect them with documented custody. Filesystem encryption does not cover plaintext RAM or an application-level backup taken while unlocked. Exclude ephemeral arenas from backups; align checkpoint backup retention with key retention. Ordinary unlink is not secure erasure on SSDs, snapshots, journaled storage or backups. Key removal cannot erase copied keys, unlocked backups, page caches, or busy kernel users. Reports must distinguish deleted, retained, key-removal-pending, and unknown; no unconditional “securely erased” claim.

### 1.8 Lease-checked orphan sweep

The engine exports a bounded sweep operation; the CLI/worker decides when to call it. No engine background daemon or import-time recursive cleanup.

Ownership authority operations must atomically compare `(owner, attempt, generation, lease, state)` and advance the fence. Local leases use one transactional authority and conservative clock handling: expiry is only candidate selection. Clock jumps, authority outage, unverifiable schema/ownership, and partial manifests retain resources. PID existence, PID absence, mtime, and a directory prefix are never deletion authority.

A writer holds an arena liveness lock for the complete lifetime of open native/Arrow handles. The local profile uses kernel advisory locks with verified single-host filesystem semantics. Every child that can write must hold or inherit the liveness lock independently of parent survival; an untracked subprocess is inadmissible. Inherited lock descriptors close only after that participant stops writing; do not issue a shared-description unlock while another participant still writes. Lock files have stable identities in the control arena and are never replaced while referenced. A sweep must obtain the exclusive lock as well as a successful authority CAS. This closes the stale-native-writer gap: changing a database fence cannot revoke an already open native file descriptor. If an expired worker is paused but still holds its lock, retain the arena. Worker lifecycle may first stop and reap its isolated execution group, then retry. Cross-host shared filesystems are unsupported until equivalent storage-level fencing is proven.

Sweep sequence:

1. Enumerate only registered arenas under provisioned roots; validate device/inode, ownership and format without following links. Unknown entries are reported for reconciliation, not deleted by prefix.
2. Read retention/publication/checkpoint state from the durable authority. Active lease, valid checkpoint, resumable hold, PUBLISHING, PUBLISHED, or unknown state is ineligible. An expired lease alone does not cancel checkpoint retention.
3. Acquire exclusive liveness lock; transactionally recheck lease, retention, identity and generation, then claim REAPING with a new generation. Renewal/resume and the reaper race through the same CAS; only one wins.
4. Hold the lock through deletion. Fence all new allocations, checkpointing and publishing. Revalidate immediately before destructive work. No caller may recreate the same arena identity.
5. Delete only the owned arena. Close/revoke keys as applicable, fsync removal, query quota reclamation, then mark REAPED. Partial deletion stays REAPING with remaining charges and bounded retries. A second sweep is idempotent.

Startup runs reconciliation or this same conservative sweep, never unconditional `rmtree`. Old unregistered directories require a separate authorized legacy-inventory procedure. They cannot be retroactively attributed from their names. This composes with platform orphaned-lock recovery through one authority adapter; its exact integration is **asserted, verify before build**.

## 2A. Slice 4c amendment: consumer capabilities are exclusive

### 2A.1 FRAME

**Problem:** Slice 4a made the scratch package's provider and top-level capability operations descriptor-relative, but the consumer seam still returns a `Path`. The capability is verified, its descriptor is closed, and the consumer opens, writes, renames, links, walks, or deletes by pathname. A same-principal process can replace the stage, its parent, or a descendant between those events. Qualified consumers also pass raw paths through `as_native_dir` and `native_dir_path`, producing adopted capabilities with `_parent_identity` and `_identity` set to `None`. The current sentry scans only the scratch package, and its function-wide allowlists conceal qualified branches inside fallback helpers.

**Invariant:** no consumer of a qualified scratch capability may operate on a path string re-resolved after verification. The verified directory or child descriptor must stay open through the operation, or the operation must use a single-component name relative to that open descriptor. A qualified capability must never be downgraded to an identity-less adopted capability.

**Guarantee:** for every T01-T17 engine-controlled create, open, read, write, stat, list, rename, link, unlink, rmdir, and recursive reclaim operation, the syscall is bound to an `fstat`-verified descriptor for the same operation lifetime. The build fails if a qualified flow reaches an ambient path operation or an identity-`None` capability. A native dependency that accepts only a character path receives an identity-bound native-path lease that keeps the verified descriptor open and uses an fd-anchored path where the pinned platform and library preserve it. If that is not supported, the call is an enumerated residual only: it receives a 0700 principal-owned stage, is re-verified immediately before and after the native call, and cannot be represented as a general consumer allowance.

**Definition of done:** all C00-C22 inventory rows below have RED-first use-time swap evidence, their stated neutering control fails, and the fixed test passes. The exclusivity sentry scans every production consumer and passes every seeded evasion test. Production entrypoints cannot reach `LocalArena`, `scratch_arena=None`, `_ADOPTED`, or an identity-`None` capability. T09 asserts its exact evidence mechanism. The SQLite and native-only residuals are measured on the pinned versions and recorded. The final exact commit passes local targeted and project checks plus the real-kernel suite on `decoy-f25-dev` as an unprivileged user.

**Boundaries and non-goals:** Slice 4c changes scratch consumer contracts and the minimum code necessary to use them. It does not implement Slice 4b encryption, Slice 5 orphan policy, F31's public safe-output schema, a new database engine, general hostile-same-UID isolation, or a portable substitute for Linux `dir_fd`. It preserves data results, schemas, ordering, transaction boundaries, quota classification, and publication semantics. It does not claim that a native dependency which accepts only a character path has the same zero-window guarantee as an fd-aware writer unless the fd-anchored path is proven on the pinned build.

### 2A.3 Established solutions and the consumer contract

The established pattern is descriptor-relative traversal, not a custom pathname sanitizer. Linux documents that a directory fd is a stable reference even if the directory is renamed, and that `openat`-style calls avoid prefix-swap races: [open(2), rationale for dirfd](https://man7.org/linux/man-pages/man2/open.2.html). Python exposes the same model through `dir_fd` and accepts directory fds in `os.scandir`, but the returned `os.DirEntry` is itself `PathLike` and its `.path` is only a name when the input was an fd. No raw `DirEntry` may cross the scratch boundary. Python also provides an fd-based, symlink-resistant `shutil.rmtree` where supported: [Python os.scandir](https://docs.python.org/3.11/library/os.html#os.scandir), [Python shutil.rmtree](https://docs.python.org/3/library/shutil.html#shutil.rmtree). Slice 4c reuses the descriptor patterns, wraps the unsafe result shape, and rejects a backend lacking the required fd-relative operations.

The consumer-facing contract is one typed context, `ScratchDirectoryHandle`, opened from `NativeDirectory` or `PublicationStage`. It owns the verified directory fd for the complete context lifetime and exposes only validated single-component operations: `create_file`, `open_file`, `create_directory`, `open_directory`, `scandir`, `stat`, `unlink`, `rmdir`, `link_to`, `rename_to`, `replace_to`, `reclaim_tree`, and `fsync`. Its `scandir()` calls `os.scandir(self._fd)` internally and immediately copies only the validated single-component `name`, inode, and file-type hint into a frozen `ScratchDirEntry`. `ScratchDirEntry` has no `.path`, `__fspath__`, fd-opening method, or delegated `DirEntry`; every later stat or open goes back through the same `ScratchDirectoryHandle` with the entry name. Raw `os.scandir` is forbidden outside this implementation.

A created child is an identity-bound `ScratchChild` containing its single-component name, parent identity, child identity, full expected mode, and resource record. It is never represented to engine code as `stage / child`. `ScratchDirectoryHandle`, `ScratchChild`, and `ScratchFileHandle` store no full path as `str` or `Path`, implement no `__fspath__`, and expose no diagnostic path property. Their `__str__` and `__repr__` contain only an opaque resource ID and non-secret identity fields, never a filesystem path. Publication opens the verified source and destination parent handles together and uses fd-relative link or rename as the sink contract requires. Cross-device and policy checks still precede data production.

`ScratchFileHandle` is the sole owner of its raw fd and follows an explicit state machine: `OPEN -> BORROWED_WRAPPER -> WRITER_CLOSED -> SYNCED -> CLOSED`, with `ABORTED -> CLOSED` for an incomplete writer. It creates at most one `io.FileIO(fd, ..., closefd=False)` wrapper at a time. Python documents that closing this form leaves the supplied fd open: [Python `io.FileIO`](https://docs.python.org/3/library/io.html#io.FileIO). The Arrow, PyArrow, or Polars writer closes first so its native buffers and footer reach the Python wrapper; the wrapper is then flushed and closed, which marks only the wrapper closed. The handle verifies that state, applies any mode change, calls `os.fsync` on the still-owned raw fd, invalidates its stored fd field, and calls `os.close` exactly once on the saved integer. No consumer may use `os.fdopen(..., closefd=True)` or close the raw integer. If a pinned library is proven to close a supplied wrapper despite this contract, the adapter uses `os.dup`: the library owns and closes only the duplicate, while the original handle fd remains open for the ordered post-writer `fsync` and sole final close. Constructor failure and writer-close failure enter `ABORTED`, close every wrapper before the raw fd, and prohibit publication. The handle never performs an operation on an fd integer after ownership is invalidated, which prevents both `EBADF` and recycled-fd operations.

The qualified helpers no longer return `(Path, capability)`. `ensure_native_dir`, `ensure_publication_stage`, `ensure_publication_file`, `ensure_scratch_file`, `edge_work_dir`, and `_spill_path` either return the capability/handle types above or are split into an explicitly unmanaged dev/test API. `as_native_dir` and `adopt_file` cannot accept a path reached from a qualified capability. Runtime constructors reject a qualified capability whose identities are `None`, and type checking keeps `QualifiedArena` separate from `UnmanagedScratchContext`.

For libraries that accept file objects, the sanctioned route is the fd-backed object. Polars `DataFrame.write_parquet` accepts a writable binary file-like object: [Polars write_parquet](https://docs.pola.rs/api/python/stable/reference/api/polars.DataFrame.write_parquet.html). PyArrow `ParquetWriter` accepts a path or file-like object, and its filesystem inference is skipped for file-like input: [PyArrow ParquetWriter](https://arrow.apache.org/docs/python/generated/pyarrow.parquet.ParquetWriter.html). T02, T06-T12, T14-T16 therefore use an fd-backed Python or Arrow file object and have no path-only exception. Repeatable readers reopen the single-component child through the still-verified parent handle and compare the opened identity before yielding a file object.

DuckDB `temp_directory`, `COPY TO`, and path-based `read_parquet` accept character paths, not arbitrary Python file objects. The preferred adapter is `NativePathLease`: it holds the verified directory fd open for the entire connection/query and presents an fd-anchored Linux path such as a child beneath `/proc/self/fd/<fd>` only after a real-kernel probe proves the pinned DuckDB version does not canonicalize back to an ambient path. Linux resolves `/proc/self/fd/<dir_fd>/<single_name>` from the open directory file description unless the native library first canonicalizes it, so the probe covers both the kernel behavior and the pinned DuckDB call path. If the probe fails, the explicit residual is a principal-owned 0700 native stage, immediate pre-call and post-call identity verification, no engine path operation between them, and syscall tracing proving every created file remains on the expected device and project.

After every successful DuckDB `COPY TO`, and before any read, publication, or cleanup, `NativePathLease.adopt_created_child(single_name)` opens the output relative to the held directory fd with `O_RDONLY | O_NOFOLLOW | O_CLOEXEC`. It compares the preceding no-follow stat with `fstat`, requires the arena device and project, `S_ISREG`, `st_uid == geteuid()`, `st_nlink == 1`, the expected 0600 mode, and then returns an identity-pinned `ScratchChild` plus a file handle. A missing, replaced, linked, wrong-owner, wrong-type, wrong-device, or wrong-project output fails closed and remains registered for reconciliation. DuckDB documents `temp_directory` as a pathname used for spill: [DuckDB temporary tables and temp_directory](https://duckdb.org/docs/stable/sql/statements/create_table.html#temporary-tables). This residual is call-site-specific for T03-T05, T08, T13, and T17; it is not a reusable path allowlist.

SQLite is a separate control-plane residual. Python `sqlite3.connect` accepts a path-like database name, not an existing fd: [Python sqlite3.connect](https://docs.python.org/3/library/sqlite3.html#sqlite3.connect). SQLite's C open API is also filename-based, while its established extension point for controlling opens, journals, and WAL files is the VFS `xOpen`/`xDelete`/`xAccess` interface: [SQLite open](https://www.sqlite.org/c3ref/open.html), [SQLite VFS](https://www.sqlite.org/c3ref/vfs.html). SQLite also warns that unlinking or renaming a live database, or opening it under multiple names, can corrupt journal coordination: [SQLite corruption guidance](https://www.sqlite.org/howtocorrupt.html#_unlinking_or_renaming_a_database_file_while_in_use).

Slice 4c chooses a buildable standard-library SQLite profile and does not depend on APSW, a private C shim, or a hypothetical maintained VFS binding. `ScratchManager` transfers the verified control-directory fd into `ResourceLedger`, which holds it until the SQLite connection closes. While that fd is held, bootstrap pre-creates or reopens `ledger.db` and `ledger.db-journal` with fd-relative `O_NOFOLLOW | O_CLOEXEC`, requires regular files owned by the effective UID with `st_nlink == 1`, mode 0600, the control-arena device and project, and pins their `(st_dev, st_ino)`. The connection calls `sqlite3.connect("file:/proc/self/fd/<fd>/ledger.db?mode=rw", uri=True)` so SQLite cannot create a different main file, then sets and verifies `PRAGMA main.locking_mode=EXCLUSIVE`, `PRAGMA main.journal_mode=PERSIST`, and `PRAGMA main.synchronous=FULL`. SQLite documents `mode=rw`, PERSIST journal retention, and exclusive lock lifetime: [SQLite URI filenames](https://www.sqlite.org/uri.html), [SQLite PRAGMA](https://www.sqlite.org/pragma.html). WAL and SHM are disabled for this profile; appearance of either is a qualification failure.

Before `sqlite3.connect`, `ResourceLedger` serializes connection creation in the process and snapshots `/proc/self/fd`. Immediately after connect, before any schema or state-changing statement, it identifies the unique newly opened SQLite main-db fd, `fstat`s it, and requires its identity to equal the fd-relative pinned `ledger.db` identity. During each write transaction it likewise verifies the actual journal fd, when open, against the pinned `ledger.db-journal`, and rechecks the main file, journal, control directory, device, project, owner, mode, and link counts immediately before commit and after commit. An ambiguous fd delta, missing `/proc` visibility, unexpected sidecar, identity change, or parent/child replacement rolls back, closes the connection, and retains the control arena for reconciliation. RED tests prove that a textual `/proc/self/fd` path that SQLite canonicalizes cannot satisfy the live-fd identity checks after redirection. This profile is selected because it is implementable with the existing Python standard library and the required Linux deployment, adds no C dependency, and verifies the files SQLite actually opened. It is still an enumerated filename residual, not a VFS-backed zero-window claim. If the pinned standard-library build cannot pass these tests, Slice 4c stops for a plan revision; there is no automatic VFS or unmanaged-path fallback.

### 2A.4 Sentry as an exclusivity proof

`tests/scratch/test_fd_only_filesystem_sentry.py` becomes a source-reachability and call-resolution sentry, not a spelling denylist. Its scan root is all `src/decoy_engine`. It starts from capability classes, allocation methods, qualified helper returns, fd-backed wrappers, and the `scratch_arena`/execution-context fields, then follows imports, assignments, arguments, returns, attributes, container elements, and branch merges into quarantine, subset, profile, connectors, discovery, and all execution writers. The checked property is that no capability-derived value is coerced into a string or reaches a path-bearing operation unless it enters the exact `NativePathLease` residual adapter.

The resolver must recognize direct and aliased imports, literal `getattr` dispatch, aliased bound methods, `Path.open`, `builtins.open`, `io.open`, every `os.path` filesystem query or normalizer, path arguments to `os.listdir` and `os.scandir`, all `tempfile` constructors, `glob` and `fnmatch` based path enumeration, `subprocess` path/argv handoff, `shutil.copy`, `copy2`, `move`, `copytree`, and `rmtree`, serializers and database connectors, and SQL strings that name output paths. Raw `os.scandir` is a violation outside `ScratchDirectoryHandle.scandir`; consumers receive only `ScratchDirEntry`. A `dir_fd` is accepted only when static control flow proves it is non-`None`; an optional variable, conditional expression, default `None`, or branch merge is a finding.

Capability taint cannot be sanitized by coercion. Access to `.name` on a capability-derived file wrapper stays tainted. An f-string, `%` formatting, `.format`, `str`, `bytes`, `os.fspath`, `Path`, path joining, container packing/unpacking, return, or helper argument that consumes a capability-tainted expression is itself tainted and is an immediate violation outside the exact `NativePathLease` implementation. The capability types have no full-path field for code to extract. Their opaque `repr` is tested and cannot be used as a path. The sentry does not attempt to recover soundness after arbitrary string construction.

Any two- or three-argument `getattr(target, attr_expr, ...)` whose target resolves to `os`, `os.path`, `pathlib`, `shutil`, `io`, `tempfile`, `glob`, `sqlite3`, a capability type, a handle, or a capability-derived wrapper is an immediate violation when `attr_expr` is not a string literal. Literal attributes are resolved and checked as ordinary calls or accesses. `eval`, `exec`, dynamic import, and registry/dictionary dispatch of filesystem operations on capability-tainted arguments are prohibited in production scratch consumers. This deliberate restriction makes the proof decidable; a new dynamic call form requires a reviewed sentry rule and RED seed before use.

Allowlists are call-site or branch-level records keyed by file, qualified function, line, normalized call AST fingerprint, reason, residual owner, and acceptance witness. No complete function is allowlisted. The unmanaged dev/test branch and qualified branch of one helper are analyzed separately, so a fallback exemption cannot hide the qualified branch. A changed line or call shape invalidates the record.

Non-vacuity tests seed one violation for each evasion class named above, including `from os import stat as s`, literal and non-literal `getattr`, an aliased `Path.open`, an aliased bound method, `io.open`, an unlisted `os.path` call, raw `scandir(fd)`, `DirEntry.path`, `os.fspath(entry)`, wrapper `.name`, `str(capability)`, f-strings, `%` formatting, `.format`, `Path(capability)`, container round-trips, dynamic registry dispatch, `eval`, `exec`, each `tempfile`/`glob`/`fnmatch`/`subprocess` family, `shutil.copy`/`copy2`/`move`, and a conditional `dir_fd`. Each seed must fail for the intended reason before sentry implementation is changed. Positive controls cover `ScratchDirectoryHandle.scandir()` returning non-`PathLike` entries, a dominated non-`None` `dir_fd` inside the handle implementation, an fd-backed file object whose `.name` is not consumed, opaque path-free representations, and each exact native residual record.

### 2A.5 Fail-closed production and value-free boundaries

Production chooses the strict option: every workflow that can allocate scratch requires a real `Arena`. `run_pipeline` opens one attempt through the configured `ScratchManager` while building its run context and fails with `ScratchBackendUnavailable` before the first temporary byte if the provider is absent or unqualified. Standalone top-level entrypoints `materialize_subset`, `discover_data`, and `postgres_snapshot` take a required keyword-only `scratch_arena: Arena`; omission is an intentional coordinated API break and Python rejects the call before its body can write. Their public contract tests pin this signature and the migration note. Internal producers, including `_materialize`, `_stage`, `_relation`, `_transactional_sink`, `write_jsonl_staged`, native quality, OOC runners, and publication helpers, take a required non-optional `Arena`, `ScratchDirectoryHandle`, or `PublicationStage` selected to their narrow need. No internal signature has `scratch_arena: Arena | None = None`, and no top-level or helper auto-selects `LocalArena` or an unmanaged temporary directory.

`run_pipeline` threads its arena through every route, sink, subset, quarantine, fixed-width, discovery, snapshot, and isolated invocation. The out-of-core calls at `execution/_pipeline_route_exec.py:414-430` and `execution/physical/drivers/_out_of_core.py:66-80` must pass it. Compatibility inventory covers direct CLI, platform, and test callers of the three standalone entrypoints before their signature changes; each consumer either passes the attempt arena or fails its contract test. There is no compatibility shim that accepts `None`.

The isolated parent keeps verified `work_root` and `staging_output` directory handles open and starts the Linux child with `close_fds=True` plus `pass_fds=(work_root_fd, staging_output_fd, liveness_lock_fd, bootstrap_pipe_fd)`. Python documents `pass_fds` as the POSIX mechanism that preserves only the listed descriptors across exec: [Python subprocess](https://docs.python.org/3/library/subprocess.html#popen-constructor). The single-use bootstrap message contains opaque attempt/resource IDs and expected `(st_dev, st_ino)` pairs, never a path. The child calls `fstat` on each inherited fd, verifies the expected identity, owner, mode, device, project, and liveness lock, and constructs `ScratchDirectoryHandle` directly from the inherited integers. It opens `payload.json`, the `sources` child directory and each source child, output Parquet, `row_errors.json`, and the result envelope only by single-component operations relative to those handles. The result envelope carries single-component child names, resource IDs, and `(st_dev, st_ino)`, never an ambient or `/proc` path. The parent reopens and verifies each returned child relative to its own still-open handles before commit or reclaim. Descriptor loss at exec, identity mismatch, a path-bearing payload/envelope field, or a platform without the qualified `pass_fds` route fails isolated execution before a child write. The in-process fallback uses the same handles and envelope schema rather than reconstructing paths.

`LocalArena` remains available only through a separately named `UnmanagedScratchContext.for_tests(...)` constructor in test/dev support. It is not an `ArenaLike` accepted by production entrypoints and is never selected by `None`. A build-failing reachability test begins at `run_pipeline`, each standalone public entrypoint, and production-private execution entrypoints and proves no path reaches `LocalArena`, `_ADOPTED`, `as_native_dir(Path)`, `adopt_file(Path)`, or a capability with either identity `None`. Direct low-level tests must opt into the unmanaged context explicitly, so fallback coverage remains deliberate.

Value-free fixes ride with Slice 4c because the touched failure paths cross the same boundary:

* T14 records only the typed classification while handling the Polars/native exception, leaves that exception handler, discards the native exception, and then raises `ScratchQuotaExceeded` with only the typed `QuotaReport`. Raising inside the handler merely `from None` is insufficient because Python still retains the suppressed exception in `__context__`. Tests require both `__cause__` and `__context__` to be `None`, and the public message contains no native text.
* Quarantine logs only fixed operation, stable code, and exception type. It does not log staged/final paths or `str(exc)`. Caller-facing errors use a stable code and safe summary, not output paths or OS error text.
* Numeric `QuotaReport.errno` remains an internal control-plane fact for classification and exact tests, but it is excluded from exception text, logs, public serialization, and progress/event output. Public projection carries bounded fields such as dimension, evidence token, effective cap, observed usage, and disposition. This is a deliberate narrowing even though errno is not a source value.
* All three use the existing typed `ScratchQuotaExceeded.report` boundary and the safe-summary foundation at `execution/_isolated_common.py:266-288`, consistent with `docs/security/error-reporting-and-data-exposure.md:25`. The planned F31 contract will absorb the typed projection as `producer -> typed occurrence -> safe boundary -> serializer`; Slice 4c does not create a competing redactor. The F31 implementation artifact remains asserted and must be grounded before public integration.

### 2A.6 RED-first acceptance and test-strength requirements

Every swap test pauses after capability allocation or helper return, replaces the stage or relevant parent name with a different inode, resumes the consumer, and asserts `ScratchPathUnsafe`, no write/delete outside the registered quota domain, and conservative retention. Tests use only disposable fixtures owned by the test. Each test includes a neutering control that disables the new handle use or identity comparison and demonstrates that the same test fails before the fix. A test that never reaches the intended writer, rename, or recursive descent is invalid.

Recursive reclaim uses only the handle-owned `ScratchDirEntry` records. For a directory child it performs a no-follow fd-relative stat, opens the child with `O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC`, compares `fstat(sub_fd)` with the preceding identity and type, and keeps `sub_fd` open through removal. Immediately before `rmdir(name, dir_fd=parent_fd)`, it repeats the no-follow stat and requires the same identity. After a successful `rmdir`, it requires `fstat(sub_fd).st_nlink == 0` on the qualified ext4 profile before closing the fd. `ENOTEMPTY` permits only a bounded rescan of that same open `sub_fd`; every newly observed entry receives the full checks. Identity change, unexpected link count, continued mutation, or exhaustion of the retry budget raises `ScratchPathUnsafe`, stops that branch, and retains a reportable charged resource. There is no unbounded retry loop and no attempt to delete a replacement name after a mismatch.

#### Slice 4c residual risk and gates

Native code that accepts only a character path remains a narrower guarantee than fd-aware code.
