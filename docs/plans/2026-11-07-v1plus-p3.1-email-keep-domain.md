## 1. FRAME

**Problem.** Masked email columns today lose everything: `hash` emits a 64-hex token, `faker`
(`person_email`) emits a synthetic address at a Faker domain, `text_mask` redacts. QA and
analytics teams need the domain mix to survive (dashboards by email provider, routing rules on
corporate versus free-mail, tests that branch on `.edu`).

**Property kept (the whole guarantee).** For every non-null output row of an `email_mask`
column:

1. The output is an addr-spec `L@D` where `L` is 20 lower-case hex characters, the first 20 of
   `derive(mask_key, namespace, NFC(value).encode("utf-8")).hex()`. The source local part never
   appears.
2. `keep: domain`: `D` is the source domain, byte for byte as written.
3. `keep: domain_class`: `D` is the list's canonical lower-case spelling of the source domain
   when it is in the committed free-mail list (so source casing is not kept), otherwise one fixed reserved domain per class: `gov.example`, `edu.example`,
   `corporate.example` (RFC 2606 reserves the `.example` top-level domain, so none of these can
   be a real organisation).
4. A value that is not a parseable address (section 3.2) becomes `L@unknown.invalid` (RFC 2606
   reserves `.invalid`), with `L` derived as above, in both modes. Nothing of the source survives.
5. Null in, null out. Equal inputs give equal outputs under the same mask key and namespace.

**Leak accepted (documented in `docs/what-we-cannot-prove.md`).** `keep: domain` reveals the
employer or organisation of every row, and the domain frequency table. A small domain (a family
or vanity domain, a ten-person company) can narrow a row to one person; a personal domain such as
`jane@janedoe.name` identifies her outright. `keep: domain_class` reveals which rows use a
listed free-mail provider and which provider, and whether the rest are government, education or
other. A kept free-mail domain that is a national ISP or provider (`orange.fr`, `t-online.de`,
`naver.com`) also reveals the likely country. Both modes keep row-level linkage within a
namespace, as `hash` does. The local part is only as strong as the mask secret: a run without an
admitted secret is refused (section 4.5), because a seed-keyed local part next to a kept domain
would let anyone holding the config confirm a guessed `first.last@domain`. Outputs in
`keep: domain` mode are routable addresses at real domains: a test system must not send mail.

**Definition of done.**

1. A new mask strategy `email_mask` with one required option `provider_config.keep`
   (`domain` | `domain_class`) produces the property above on every route that accepts it, and
   every other route falls back to one that does (section 4.3).
2. Plan compile refuses a bad config with a coded, value-free reason (section 3.3), for a
   top-level column and for a `nested` column whose child is `email_mask`; a run without an
   admitted mask secret is refused before any source is read.
3. Acceptance tests in section 7 pass, including a Hypothesis property test and a route-parity
   test; T1 gates green; `registry_renumber.py --check` consistent.
4. Docs: `docs/strategies.md` (the strategy), `docs/what-we-cannot-prove.md` (the leak),
   `docs/methodology-registry.yaml` (the citation), the proof manifest and capability matrix
   (section 4.7), the keyed-surface map, CHANGELOG `[Unreleased]` entry.
5. Dark: a config without `email_mask` gives byte-identical `checks_passed` and an identical
   serialised plan to main (section 4.8).

**Non-goals.**

- Anything keeping more than the stated property: no per-domain pseudonym in class mode (it would
  keep the organisation partition and its sizes), no kept top-level domain in class mode, no
  realistic (name-like) local parts, no kept local-part length or shape.
- No detector, disguise, starter-config or default change; no wizard offer (section 4.6).
- No native kernel, no chunked or out-of-core port (section 4.3).
- No small-domain suppression (a k-threshold that falls back to the class): recorded follow-up.
- `email_mask` as a `nested` child: refused at compile (section 3.3), not supported.
- No email validation service: the parse rule in 3.2 decides only "domain usable or not".

**Risk: R2.** Privacy logic (a new masking primitive whose leak is accepted by design), a
reason-registry minor bump, and additions to shared registries. Rollback: revert the commits;
nothing is persisted and no default changes.

## 2. Established solutions

**Searches run (2026-11-07):** "Presidio anonymizer email keep domain custom operator"; "Tonic.ai
email generator preserve domain option"; "SDV RDT DomainBasedMapper email transformer"; "Delphix
masking email algorithm preserve domain secure lookup"; "Gretel / Neosync transform email
preserve domain"; "ARX email attribute generalization hierarchy"; "free email domains list github
license MIT Kikobeats"; "Faker free_email_domain safe_email RFC 2606". `docs.tonic.ai` and
`docs.sdv.dev` were blocked by this session's network, so their content is from search
summaries. In the codebase: `hash`, `tokenize`, `faker`/`person_email`,
`composite_name_email`, `text_mask` (its `email` detector), `derived`, `formula`, the Faker
`free_email_domains` lists in the lock (Faker 40.23).

**Findings.**

| Tool | Domain handling | Local part | Malformed input |
|---|---|---|---|
| Delphix Email framework | "Mask Domain With: Preserve Value" keeps the domain; "Replacement Text" sets a fixed domain (example: `example.com`) | secure lookup from a file, or "Unique Value" (SHA-256, Base32) | per-segment error handling |
| Tonic Email generator | scrambles by default; an excluded-domains list keeps listed domains; Textual can keep the original domain | scrambled / synthesised | not stated in summaries |
| SDV RDT `DomainBasedMapper` (Enterprise) | `preserved_domain='full'` keeps everything after `@` | realistic names by default, random strings with `obfuscate_emails=True`; the docs warn realistic names can coincide with real addresses | not stated |
| Neosync email transformer | `PreserveDomain` flag | generated | not stated |
| Presidio | no built-in; `custom` operator lambda, e.g. replace text before the last `@` | user code | user code |
| ARX | no email type; user-built generalisation hierarchies (value to class to suppressed) | n/a | n/a |
| Faker | `safe_email()` uses RFC 2606 reserved domains; `free_email_domain()` draws from per-locale free-mail lists (MIT) | names | n/a |

**Design follows.**

- Structure from Delphix's Email framework: split at the domain, mask the name part with a keyed
  deterministic function, and for the domain either preserve it or replace it with a fixed value.
  Tonic's excluded-domains list is the precedent for keeping only listed (free-mail) domains
  while replacing the rest.
- Local part: the engine's own HMAC-SHA256 `derive` (the `hash`/`tokenize` keyed path, HKDF root),
  a hex token, as Delphix's "Unique Value" and SDV's `obfuscate_emails=True` do. A name-like local
  part is refused as a design choice: next to a real kept domain it can be a real mailbox, the
  hazard SDV's own documentation warns about.
- Replacement domains: RFC 2606 section 2 reserved names (`.example`, `.invalid`), the same choice
  as Faker's `safe_email()`.
- Domain class: a value-to-class generalisation step in ARX's sense, with the classes named in the
  sprint outline (free-mail, education, government, other).
- Parsing: RFC 5321 section 4.1.2 / RFC 5322 section 3.4.1 (the domain follows the last `@`; a
  domain cannot contain `@`); hostname label rules RFC 1035 section 2.3.1 / RFC 1123 section 2.1
  (letters, digits, hyphen, 1 to 63 characters, no edge hyphen, 253 total); RFC 6531 permits
  UTF-8 (U-label) domains, so non-ASCII alphanumerics are accepted in a label.
- Free-mail list: a small, committed, cited list (section 4.4), not a dependency.

**Reuse check (the sprint rule: does `derived` or `formula` already express it?).**

- `derived` (closed Lark grammar): has `concat` and `slice` but no find, split or index, and no
  keyed function. It cannot locate `@`, so it cannot express this.
- `formula` (simpleeval): `re.sub(r"^.*@", ..., value)` can keep the domain, but its only
  randomness is a `random.Random` seeded from the formula text and column name, not the secret
  mask key and not the source value. A local part built that way is not keyed: anyone with the
  config can recompute it, so it is not a masking primitive. No other keyed function is in scope.
- `hash` carries the right keyed derivation, but its option surface is implemented separately in
  the native unified route, the native chunked route, the sequential native descriptor, the
  out-of-core kernel (payload and parent-key paths), the chunked FK self-mask gate and the
  physical shadow operators (`_operator_params.HashParams`, `hash_config_rejection`,
  `_sequential_native_ops`, `out_of_core/_compat.py`, `_chunked_fk_vocab.py`). A new `hash` option
  must be honoured or declined at every one of them: a scattered rule with six sites and no
  natural guard. A missed site would silently emit a plain hash.
- `faker`/`person_email`: pool built from the job seed (output changes with the run seed), name-
  like local parts (refused above), and the same native-route spread as `hash`.
- `composite_name_email`: a generator, not a mask.

**Why custom code is needed.** No existing strategy carries a keyed local part plus a domain rule.
The slice therefore adds a small new strategy, `email_mask`, with one option. It is Python only,
and every native, chunked and out-of-core route already refuses or falls back for a strategy it
does not list (section 4.3), so the "honour or refuse" rule is enforced by construction rather
than by six new declines. The remaining custom code is a last-`@` split, a label-syntax check,
a three-rule classifier and a frozen list: small, and each piece follows a cited source.

## 3. Behaviour

### 3.1 Output

| Input | `keep: domain` | `keep: domain_class` |
|---|---|---|
| `alice@acme.com` | `<L>@acme.com` | `<L>@corporate.example` |
| `Bob@Gmail.com` | `<L>@Gmail.com` (kept as written) | `<L>@gmail.com` (listed; the list's canonical spelling) |
| `x@cs.stanford.edu` | `<L>@cs.stanford.edu` | `<L>@edu.example` |
| `y@ox.ac.uk` | `<L>@ox.ac.uk` | `<L>@edu.example` |
| `z@agency.gov`, `z@dwp.gov.uk`, `z@army.mil` | domain kept | `<L>@gov.example` |
| `"john doe"@acme.com` (quoted local part) | `<L>@acme.com` | `<L>@corporate.example` |
| `a@b@acme.com` (unquoted second `@`) | `<L>@acme.com` | `<L>@corporate.example` |
| `ü@bücher.de` (U-label domain) | `<L>@bücher.de` | `<L>@corporate.example` |
| malformed (3.2) | `<L>@unknown.invalid` | `<L>@unknown.invalid` |
| null / NaN / `pd.NA` | null | null |

`<L>` is always keyed on the whole source value, so `a@acme.com` and `a@globex.com` get different
local parts, and in class mode two corporate addresses never collapse to one output.

Classification order in class mode: free-mail list (exact match on the lower-cased domain), then
government, then education, then corporate. Government: the last label is `gov` or `mil`, or the
second-to-last label is one of `gov`, `gouv`, `govt`, `gob`, `go`, `mil` and the last label is a
two-letter country code. Education: the last label is `edu`, or the second-to-last label is `ac`
or `edu` and the last label is a two-letter country code. Comparisons are on ASCII-lower-cased
labels; a U-label never matches a list or rule, so it classifies as corporate (conservative).

### 3.2 Parse rule (value-free; never raises per value)

A non-null value is an address when all hold; otherwise it takes the malformed path:

- it is a `str` (a non-string value in an object column is malformed);
- it contains `@`; the domain is the text after the LAST `@`; the local part (everything before)
  is non-empty. The local part is not otherwise validated: it is replaced whole, so quoted forms,
  dots and a stray `@` cannot leak;
- the domain full-matches the label rule: labels separated by `.`, at least two labels, each 1 to
  63 characters of ASCII letters, digits, `-`, or non-ASCII alphanumerics (`str.isalnum()`), no
  leading or trailing `-`, the last label contains a letter (excludes dotted IPv4), total length
  at most 253. `re.fullmatch`, never `$` (recurring defect 1): `a@acme.com\n` is malformed.
  Address literals (`a@[192.0.2.1]`), comments, a trailing dot, whitespace and an empty label are
  malformed.

An all-null column passes the dtype guard whatever its dtype (an all-null column read as
`float64` is common) and stays all-null: there is nothing to mask or leak.

The malformed path keys `L` on the canonical bytes of the value (`str(value)` NFC for a
non-string, consistent with `tokenize`'s string rule) and emits `L@unknown.invalid`. The handler
counts malformed rows and returns one `QualityWarning` (`email_mask_malformed_values`) carrying
the count only, never a value or row content.

### 3.3 Failure modes

| Failure | Where | Behaviour |
|---|---|---|
| `keep` missing or not `domain`/`domain_class` (including a non-string) | plan compile and `run_config_only_checks` | `PlanCompileError` `plan.email_mask_keep_invalid`, path `tables.<t>.columns.<c>.provider_config.keep` |
| any other `provider_config` key (a typo such as `keep_domain`) | same | `plan.email_mask_option_unknown`, path names the key |
| no `namespace` on the column | same | `plan.email_mask_requires_namespace` |
| a `nested` column whose `provider_config.strategy` is `email_mask` | same | `plan.email_mask_unsupported_in_nested` (precedent: `top_code_unsupported_in_nested`, `_checks_top_code.py`). Fail closed rather than validate the child: nested runs the child per flattened leaf, outside the parse and dtype rules this plan tests |
| no admitted mask secret (no `run(key_provider=...)` and no `global_settings.mask_secret_ref`) | run admission, before any source read (`secret_providers.admit_mask_key`) | existing `runtime.keyed_strategy_requires_secret`, every release phase, because `email_mask` is in `ALWAYS_KEYED_STRATEGIES` |
| handler driven directly with a context whose `mask_key` is shorter than the 32-byte mask root (the `job_seed` default of a hand-built `StrategyContext`) | runtime, handler | `StrategyError` `runtime.keyed_strategy_requires_secret` (defence in depth; no new code) |
| source column dtype is not string/object (int, float, datetime, bool) and the column is not all-null | runtime, handler | `StrategyError` `runtime.email_mask_requires_string_dtype` (fail closed, as `tokenize`) |
| handler driven with a bad config that bypassed compile (direct handler call) | runtime, handler | `StrategyError` `runtime.email_mask_config_invalid` (defence in depth, as `truncate`) |
| malformed value | runtime, per value | masked to `L@unknown.invalid`; warning with a count |
| `execution_mode="out_of_core"` forced | routing | the route's existing coded refusal for an unsupported strategy (no new code); never a different output |

All messages name the table, column, option and allowed values; none carries a source value or a
configured value beyond the option name (the `keep` value is echoed only as its type when it is
not one of the two tokens). Errors are raised after the `except` block closes, so `__cause__` and
`__context__` are `None` (recurring defect 3).

Strictness of the option schema: `keep` must be the exact string (`True`, `1`, `"Domain"` are
refused; recurring defect 2). `PipelineConfig` keeps `provider_config` free-form, as for every
other strategy; the compile check is the choke point.

## 4. Design notes

### 4.1 Config shape

```yaml
tables:
  - name: users
    columns:
      - name: email
        strategy: email_mask
        namespace: user_email      # required: the local-part token is keyed on it
        provider_config:
          keep: domain_class       # or: domain
```

One fact per place: `keep`'s two values live once, as a module constant in the strategy's address
module; the compile check, the handler and the catalog `choices` read it.

### 4.2 Structure

New sub-package `src/decoy_engine/execution/_strategies/_email_mask/`:

- `_address.py`: the pure core. `parse_domain(value) -> str | None`, `classify(domain) -> class`,
  `masked_domain(domain, keep) -> str`, `KEEP_CHOICES`, `RESERVED_DOMAINS`. No key material, no
  pandas. Carries the `Pattern:` docstring line (methodology registry).
- `_freemail.py`: the frozen free-mail list with its provenance and licence note.
- `_handler.py`: `EmailMaskStrategyHandler` (thin, like `TokenizeStrategyHandler`): dtype guard,
  namespace and config backstop, one pass computing tokens with `derive(ctx.mask_key, ...)` inline
  (no local binding of the key, so the secret-material census gains no entry), malformed count,
  warning.
- `__init__.py`: exports the handler.

Principles (`architecture.md`): open/closed, by registering one new handler in `SCALAR_HANDLERS`
and one row in each per-strategy registry rather than editing `hash`'s six route branches; deep
module, since callers see one handler and the core hides parsing and classification. Registry
rows are tied together by the existing drift sentries over `SCALAR_HANDLERS` (section 5).

House style: typed, single-purpose functions; no flag arguments (the two modes are one `keep`
value passed to `masked_domain`, which dispatches on a two-entry table); comments say why.

### 4.3 Routes

| Route | What happens to an `email_mask` column | Evidence in build |
|---|---|---|
| Full-frame oracle (pandas adapter, `SCALAR_HANDLERS`) | handler runs; the reference output | property test |
| Native unified full-frame (`unified_slice_enabled`) | no entry in `OPERATORS`: the node runs the Python handler (coded reject to the Python path, as `tokenize`) | parity test, both values of `unified_slice_enabled` |
| Auto-chunk single table | not in `CHUNK_SAFE_STRATEGIES`: `strategy_not_chunk_safe`, table runs full-frame | parity test with `auto_chunk_threshold_rows=1` |
| Sequential FK route (`execution_mode="sequential"`) | no native descriptor: dedicated Python handler | parity test on a two-table FK job (email is a payload column) |
| Native chunked | no operator: reroutes to the full-frame oracle | covered by the auto-chunk row |
| Out-of-core FK | not in `_SUPPORTED_WORK_STRATEGIES`: MISS, falls back under `auto`; forced mode gives the existing coded refusal | parity under `auto` with `out_of_core_threshold_rows=1`; forced-mode refusal test |
| Chunked FK self-mask gate | not chunk-safe: the existing gate refuses the edge | guard test (membership) |
| Generate mode | not a generate type; `config._tables` rejects it as today | none needed |

Keeping it out of the chunked lane is a known limit: a very large single table masks full-frame.
Making it chunk-safe later is a one-line set change plus parity cells (it is row-local).

### 4.4 Free-mail list

About 50 high-population consumer providers, committed in `_freemail.py` as a `frozenset` of
lower-case ASCII domains, for example `gmail.com`, `googlemail.com`, `yahoo.com` (and its main
country variants), `ymail.com`, `outlook.com`, `hotmail.com` (and variants), `live.com`,
`msn.com`, `aol.com`, `icloud.com`, `me.com`, `mac.com`, `proton.me`, `protonmail.com`,
`gmx.com`, `gmx.de`, `gmx.net`, `web.de`, `mail.com`, `zoho.com`, `yandex.ru`, `yandex.com`,
`mail.ru`, `qq.com`, `163.com`, `126.com`, `naver.com`, `hanmail.net`, `daum.net`, `libero.it`,
`orange.fr`, `free.fr`, `laposte.net`, `t-online.de`, `rediffmail.com`, `fastmail.com`.

- Provenance, not licence: domain names are facts and the selection is ours, so nothing is
  copied under a licence. The module docstring cites where each entry was confirmed as a free-mail
  provider. Most entries are in Faker 40.23's per-locale `free_email_domains`. Fifteen are not:
  `msn.com`, `aol.com`, `me.com`, `mac.com`, `proton.me`, `gmx.com`, `gmx.net`, `mail.com`,
  `zoho.com`, `qq.com`, `163.com`, `126.com`, `t-online.de`, `rediffmail.com`, `fastmail.com`.
  For those the cited source is the npm `free-email-domains` package (Kikobeats, MIT; its README
  says it is built from HubSpot's blocked-domains list, whose own terms are not stated). The build
  checks each of the fifteen against a pinned version of that package and drops any entry it
  cannot find there; the result goes in the build record.
- Conservative on purpose: a false "free-mail" match keeps an exact, possibly identifying domain
  (a leak); a false "corporate" match only replaces a domain (no leak). So the list holds only
  providers with millions of users, not the full 4,000-entry list, and drops Faker's oddities
  (`gov.ua` is a government domain in Faker's `uk_UA` list).
- Stability: a digest test pins the list. A list change changes outputs for class mode, so it is a
  documented behaviour change (CHANGELOG), never a silent one. Update plan: reviewed additions
  only, each with a source, no automatic refresh.
- Output spelling: in class mode a matched free-mail domain is emitted in the list's canonical
  lower-case spelling, not as written, so source casing (a per-user fingerprint) is not kept.

### 4.5 Determinism, keys, collisions, uniqueness

- Key: `derive(ctx.mask_key, namespace, NFC(value).encode("utf-8"))`, the HMAC-SHA256 draw under
  the HKDF-derived root that `hash` and `tokenize` use. No new key, no new secret-named
  parameter, no secret-material census entry (the handler passes `ctx.mask_key` inline).
- Secret required, in every phase. `email_mask` is keyed by the registry's fail-closed default
  already (`column_is_keyed` ends `return strategy not in KNOWN_UNKEYED_STRATEGIES`); the
  `ALWAYS_KEYED_STRATEGIES` entry states that classification explicitly over that default, and
  AT-11 asserts `column_is_keyed("email_mask", ...)` is true. The classification lives in
  `secret_providers/_requirements.py`, the one registry the pre-read admission
  (`admit_mask_key`) and the compiled-plan check (`assert_plan_requirements_admitted`) share.
  Main already refuses keyed work without an admitted secret in both release phases
  (`KEY_REQUIRED_GUIDANCE`: "No job_seed fallback exists in any release phase";
  `tests/unit/test_de02_keyprovider.py::test_no_secret_fails_closed_in_both_phases`). The
  `job_seed` default of `ctx.mask_key` (`_adapter.py`, `StrategyContext.__post_init__`) is
  reachable only by a hand-built context, so the handler also refuses a `mask_key` shorter than 32
  bytes with the same code. Why not a plan-compile refusal: `compile_plan` and
  `run_config_only_checks` cannot see a programmatic `run(key_provider=...)`, so refusing a config
  without `mask_secret_ref` would reject valid callers. The refusal sits at run admission, which
  runs before any source is read; this deviates from the reviewer's "plan refusal" wording and is
  flagged for re-review (section 9). The keyed-surface map in
  `docs/archive/discussions/2026-07-14-de02-keyprovider-design.md` section 1.2 gains a row, kept in
  lockstep as the registry comment requires.
- Draw site: a new catalogue entry `mask.email_mask` (family `source_keyed_hmac`, entropy root
  `mask_key`, identity `source_value`, partitionable) appended in its own data module
  `native/_draw_sites_email_mask.py`, spliced last into `DRAW_SITES`, and
  `MASK_STRATEGY_TO_SITE["email_mask"]`. The pinned catalogue test
  (`tests/native/test_draw_sites_catalogue_pinned.py`) is updated for the append: length 35, the
  new id last, its entry digest, and the new catalogue and map digests. Existing entries' digests
  do not change (the test proves it). V1P-3.3 and V1P-3.4 may append sites too: the slice merged
  second recomputes the digests by hand at merge (recorded in section 9).
  The site's primitive association (`_draw_site_providers.py` `_SOURCE_KEYED_PRIMITIVE`) gains
  `{"mask.email_mask": "derive"}` from a sibling constant, as `TOKENIZE_PRIMITIVE` does.
- Determinism: same mask key, namespace and value give the same output across runs, processes and
  routes; a different namespace gives a different local part.
- Cross-column linkage: under one namespace the 20-hex local part is the prefix of the `hash`
  token of the same value (same derivation). Namespaces are the engine's joinability boundary, so
  this is the intended semantics; documented.
- Collisions: distinct inputs share an output only if their 80-bit token prefixes collide AND they
  share an output domain. Birthday bound for n distinct addresses in one output domain: about
  n^2 / 2^81 (1e8 addresses: about 4e-9). Not collision-resolved, like `hash` and `tokenize`;
  documented. A unique index on the masked column holds with that probability.
- Case: the token is keyed on the value as written (RFC 5321 local parts are case-sensitive), so
  `Alice@acme.com` and `alice@acme.com` give different outputs, as under `hash`.
- Catalog facts: `namespace_required=True`; `join_safe=False` (the join-safe set is pinned to the
  native key strategies `hash` and `fpe`, and email is not offered as an FK key); technique class

## 7. Acceptance tests (written first)

1. **Property test (Hypothesis, fixed seed, a few hundred examples per strategy).** Generators:
   addresses built from random local parts (including quoted, dotted, with `@`), domains from the
   free-mail list, `.edu`/`.ac.xx`/`.gov`/`.gov.xx`/`.mil`, random LDH domains and U-label
   domains, plus arbitrary text and non-strings for the malformed path. For every row through the
   real `run_pipeline` (full-frame): output full-matches `[0-9a-f]{20}@D`; `D` equals the source
   domain (`domain`) or the expected class domain (`domain_class`); a malformed input gives
   `D == "unknown.invalid"`; the source local part is not a substring of the output local part
   when it is at least 8 characters (a 20-hex string can contain a short hex-only local part by
   chance; at 8 characters the chance is negligible over the fixed-seed example set);
   nulls stay null.
2. **Determinism and keying.** Same seed and namespace: identical outputs across two runs. Another
   namespace or mask key: every local part differs. The local part equals
   `derive(...).hex()[:20]` computed independently in the test (an oracle, not the handler).
3. **Collision and uniqueness.** `a@acme.com`, `a@globex.com` (class mode): two distinct outputs.
   10,000 distinct addresses in one domain: 10,000 distinct outputs. A repeated input maps to one
   output.

5. **Value-free errors.** dtype error on int, float, datetime and bool columns; message excludes

## 8. Known limits

- Keeping the exact domain is a real disclosure (section 1); class mode is the mitigation. No
  small-domain suppression yet (follow-up: a `min_domain_count` that falls back to the class).
- The classifier is a short rule set, not the Public Suffix List: a government or university
  domain outside the listed patterns (`gc.ca`, a `.museum` university) classifies as corporate,
  which only replaces it (safe direction). A U-label domain is always corporate in class mode.
- Free-mail list is deliberately short; a small consumer provider is treated as corporate.
- Python only: large single tables do not chunk and FK-key use is not offered.
- A U-label longer than 63 characters in its A-label form passes the character-count rule.
- Output addresses in `domain` mode are routable at real domains.
- Not collision-resolved (80-bit token); the bound is in 4.5.
