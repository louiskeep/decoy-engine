## 0. Architecture correction (rev 1 was mis-framed; Codex gate + kernel survey)
Rev 1 said the native/`_dispatch.py:233` FK reroute (`fk_relationship_not_native_route`) was "the entire Phase D gap" and that Rust FK kernels existed as shadow proofs. Both are wrong:
- **FK jobs never reach the native-chunked lane** -- but not because layer-2 classification is skipped. Layer-1 `_pipeline_routing.py::decide_execution_route:275` selects the route in this precedence: (0) an EXPLICIT `execution_mode` override (`out_of_core`/`sequential`/`full_frame`) is honored first (`override_out_of_core` etc.); then for `auto`, TWO modes -- (a) DEFAULT byte-estimate/probe routing: a conservative FIT picks **full_frame FIRST** (`:478` `byte_estimate_full_frame_fits` / `probe_recovered_full_frame`) before bounded, else bounded by eligibility; (b) the FLAG-OFF path (byte-estimate disabled): the row-count-threshold logic below it (`out_of_core` at/above `out_of_core_threshold_rows`, else `sequential`, else full_frame). A large FK job no bounded route can take is reject-before-read (`fk_full_frame_oom_risk_rejected`) on both. Post-R3, `_pipeline_context.decide_route` DOES call `decide_chunk_route` for relationship jobs (`_pipeline_context.py:439`), but FK is kept out of the chunked lane by `_planner.classify_job` (FK -> `sequential_relationship`/`out_of_core_relationship`, never `chunked`, `_planner.py:16-18`) and by the executor dispatch, and the unified-slice fast lane declines on `profile.relationships` (`_unified_slice_admission.py:249`). The native/_dispatch FK predicate (`:233`) is a THIRD defense-in-depth guard on the chunked coordinator (which carries empty relationships), not the operative gate. Flipping it alone changes nothing for production FK jobs.
- **There is no Rust FK/join/orphan kernel today** — greenfield. The `decoy-engine-native` crate exports only scalar payload kernels (`derive_batch` hash, `derive_index_batch` faker-pool, `fpe_transform_batch`, `text_redact`, raw-hex). Shadow OOC-FK delegates to the DuckDB `run_fk_out_of_core`; shadow mixed-FK resolves FK in Python via `execution/physical/_shadow_fk.py` -> `_fk_resolve.resolve_fk_keys`.

**What FK masking actually runs on today:** sequential + full-frame = PANDAS (`_sequential.py::run_sequential:207` driving `PandasExecutionAdapter._dispatch_mask_node`/`_parent_map`); out-of-core = DuckDB + pyarrow (`out_of_core/_runner.py::run_fk_out_of_core:114`, masking in `out_of_core/_mask.py::mask_batch`/`mask_column`, join via SQL/`_batch_join.py` -- NO `_fk_resolve`). FK key resolution via the shared `_fk_resolve.resolve_fk_keys:50` is used by SEQ + FF only; OOC resolves keys through its SQL joins.

**So Phase D = make the PAYLOAD masking on these FK routes run on Rust kernels** (OOC: Rust payload kernels inside the DuckDB route, DuckDB keeps scan/join/reorder; SEQ: Rust payload kernels replacing the pandas-adapter dispatch), with byte-parity; plus the bounded validator/vault extensions, the external-reorder work, and platform activation. It is NOT a new native-chunked FK lane. The native/_dispatch predicate is narrowed only as a belt-and-braces reflection of what the real routes admit; it is not where the work lives.

## 5. No-legacy transition + audit slice (Cam requirement 2)
"No pandas on admitted production routes" is defined by the program as: the MASKING COMPUTE runs on Rust companion kernels or named Arrow kernels (redact/truncate/passthrough) -- it is about the masking, not the route's bounded orchestration. So for FK:
- **The audit checks the masking COMPUTE backend, not merely that "a dispatch ran":** for each admitted (shape x operator x route) cell, a compiled-call WITNESS proves the Rust kernel ran for Rust-owned operators, or a named-Arrow-kernel witness for redact/truncate/passthrough. On SEQ this means D2 moves even redact/truncate/passthrough off `PandasExecutionAdapter._dispatch_mask_node` to named-Arrow/Rust; the pandas MASKING path for an admitted operator is then unreachable.
- **SEQ's bounded orchestration pandas is RETAINED and is NOT a violation:** `_sequential.py` ingests table-at-a-time via `to_pandas_fk_safe` (`:377`), holds `frames` (`:403`), builds the parent map (`:470` `adapter._parent_map`), and converts out via `pa.Table.from_pandas` (`:483`). This is bounded (one table at a time), not the whole-dataset OOM-risk pandas the rule targets; it stays. Making SEQ fully Arrow-native (no pandas orchestration at all) is a larger separate effort, explicitly OUT of Phase D (note it; not required by the program's definition).
- OOC: DuckDB/Arrow owns orchestration (scan/join/reorder), but some payload compute currently BRIDGES to pandas (e.g. `bucket_perturb` -> `apply_bucket_perturb` then `pa.array(..., from_pandas=True)`, `_mask_group_c.py:435-443,497`). D1/D1b replace that pandas payload bridge with Rust too, so admitted OOC payload compute is Rust/Arrow, not pandas.
Every (shape x operator x tier) is exactly {Rust/Arrow-admitted + parity + compute-witness} or {declined with a caller-visible reason}; nothing silently falls back; a replaced pandas masking path for an admitted cell is hard-deleted (pre-GA) only after graphify-trace shows no remaining caller.
- **Audit slice (D-audit, mandatory, own gate):** proves by test that no admitted FK cell routes through the replaced pandas/legacy payload path and that each removed path has no caller. Graphify-trace before deleting. The R3 reorder-liveness record is the reachability baseline for the OOC reorder paths (confirm the live P4-A lane, not an OOC-B remnant). Guards against re-introducing the reverted OOC-B O(rows) regression.
- **D-audit qualification (2026-10-16):** the Rust/Arrow-only wording above applies to the strategies that have a kernel on the route. It is not a universal-kernelization claim. code_set, NER, faker's declined and FK-key cells, non-injective strategies as SEQ FK keys, the other shared SEQ handlers and out-of-core text_mask run dedicated Python handlers and are classified, not hidden. Matrix and fences: `docs/records/2026-10-16-d-audit-compute-matrix.md`.
- The native/_dispatch FK predicate (`:233`) is defense-in-depth, not the gap; the audit confirms it stays narrower-never-wider and no admitted cell depends on it.
