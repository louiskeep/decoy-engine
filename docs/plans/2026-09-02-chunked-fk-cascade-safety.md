# Chunked-FK admission soundness: close the manual self-mask byte-parity holes

Status: plan (authored 2026-09-02, Opus; plan-gate round 1 NO-GO remediated,
re-gate in progress). Held target branch `feat/native-phase3`; merges with the
Phase-4 bundle. CORRECTNESS fix, independent of the FK reorder-route work
(Task 4/6/7) and of the deferred FK-4a fast path.

## 1. The bug

The public/manual self-mask entry `run_mask_pipeline_chunked`
(`execution/_chunked.py:347`) runs with an EMPTY relationship graph
(`_chunked.py:449`), so its per-chunk adapter never FK-resolves a child column;
it self-masks the child by the child's declared strategy. It admits FK-child
configs through `gate_fk_child_edges` (`execution/_chunked_fk.py:212`) whenever
the parent key uses a chunk-safe deterministic strategy and the child declares
the same one. That is byte-identical to the join oracle ONLY when the parent's
declared key strategy is exactly the value that actually masks the parent key,
AND the child self-mask reproduces that value. Five config shapes break the
assumption and make the route emit a valid-looking WRONG value with no error (a
byte-parity / advertised-contract violation, not a raw-data leak):

1. **Parent key is itself an FK child on the SAME column (multi-hop cascade).**
   Chain A -> B -> C where B's key column `b_id` is the child of A and also the
   parent of C. In the oracle `b_id` is FK-**resolved** against A (its declared
   strategy is overridden, `_pandas_adapter.py:366`). If A's key errors on value
   X, the oracle cascades `b_id=X` to None; that cascade RowError excludes X from
   C's parent map (`_pandas_adapter.py:305-312,628-645`,
   `_strategies/_orphan.py:127-138`), so `c_fk=X` cascades to None. The manual
   route masking C alone computes `F(X)` and raises nothing.
2. **Parent-key `when`.** A when-gated parent key leaves some parent values raw;
   the oracle's parent map carries those raw identity entries and the child
   resolves to the RAW value (`_orphan.py:113-126`). The chunked route
   self-masks the child unconditionally -> `F(X)` instead of raw `X`.
3. **Child-key `when`.** The oracle FK-resolves the child column and never
   consults the child's own `when` (`_pandas_adapter.py:366-379`). The
   empty-graph route treats the child as a scalar and DOES honor its `when`
   (`_pandas_adapter.py:410`), leaving non-matching child rows raw.
4. **Composite / provider-bundled endpoint.** Work-node kind derives from the
   resolved provider capability, not the declared strategy
   (`provider_is_composite(provider, registry)`, `_runner.py:88`). A key column
   declaring a chunk-safe strategy but carrying a composite `provider` is
   bundle-generated by the oracle (`_pandas_adapter.py:380`,
   `_strategies/_composite.py:117`), while the scalar child self-masks ->
   divergence. The gate checks strategy/namespace/provider_config/dtype but not
   the provider / resulting work-node kind (`_chunked_fk.py:329,458`).
5. **FPE default-column-tweak.** FPE's Feistel tweak is `(fpe_join_group or
   column_name)` (`_strategies/_fpe.py:130-131`). Absent a shared
   `fpe_join_group`, parent `id` and child `parent_id` use DIFFERENT tweaks and
   produce DIFFERENT masked values under otherwise-matching config -> RI break.
   The gate does not compare the resolved tweak.

The AUTOMATIC `run_pipeline` chunk route is unaffected: it rejects every
relationship-bearing job before reaching this gate (`_planner.py:375-379`).

## 2. The fix

Add admission predicates to `gate_fk_child_edges`, each a read over
`config["relationships"]` and the resolved column entries the gate already
handles (`col_index` at `_chunked_fk.py:275`). Keep every existing condition and
its fail-closed error unchanged. For an FK edge (parent table P, parent key
column `pcol`, child table `table`, child key column `ccol`):

- **8. Parent KEY NODE is not itself an FK child.** Reject if the exact endpoint
  `(P, (pcol,))` appears as a `(child_table, child_columns)` in any edge of
  `config["relationships"]`. New code `chunked_fk_parent_not_root`. This is the
  EXACT complement of "pcol is masked by its declared scalar strategy": the FK
  override keys on the exact `(child_table, child_columns)` tuple
  (`_pandas_adapter.py:366`, `relationships/_graph.py:112`), so a TABLE-wide
  check would wrongly reject the legitimate distinct-column self-FK
  `employees.id -> employees.manager_id` (child is `manager_id`; `id`
  self-masks) and `A.id->B.a_id` + `B.id->C.b_id` (the incoming FK on `B.a_id`
  is unrelated to `B.id`). Closes shape 1.
- **9. Parent key column has no effective `when`.** Reject when `pcol`'s `when`
  is a non-blank string, mirroring the compiler's normalization
  (`plan/_seed_envelope.py:245`: `when_raw if isinstance(when_raw, str) and
  when_raw.strip() else None`), so a blank/whitespace `when` does not
  over-reject. New code `chunked_fk_parent_when_unsupported`. Closes shape 2.
- **10. Child key column has no effective `when`.** Same normalization on
  `ccol`. New code `chunked_fk_child_when_unsupported`. Closes shape 3.
- **11. Both FK endpoints self-mask as SCALAR nodes.** Reject if either `pcol`
  or `ccol` carries a `provider` that could route it through composite dispatch.
  Composite recognition needs the resolved registry (`provider_is_composite`,
  `_runner.py:88`), which the gate does not hold; use the conservative,
  registry-free form: reject any non-null `provider` on either FK key endpoint.
  New code `chunked_fk_endpoint_not_scalar`. This is a fail-closed
  over-rejection (a non-composite provider on an FK key is rejected too);
  acceptable because an FK KEY carrying a generation provider is out of the
  supported self-mask surface. Closes shape 4. (Threading the registry for a
  precise composite-only check is a documented future refinement.)
- **12. FPE endpoints share an identical resolved tweak.** When the parent
  strategy is `fpe`, reject unless `pcol` and `ccol` declare the SAME non-null
  `fpe_join_group` (so the tweak is the shared group, `_fpe.py:130-131`, not the
  column name). New code `chunked_fk_fpe_tweak_mismatch`. Closes shape 5.

Predicate 8 closes the reported multi-hop cascade; 9-12 close the remaining
silent-wrong-value holes the plan-gate surfaced. All are pure reads over
`config` and the resolved column entries.

## 3. Behavior contract (what "correct" means)

- The manual chunked route ADMITS an FK-child edge only when every existing
  condition AND predicates 8-12 hold. Any violation FAILS CLOSED: the gate
  raises the specific new `PlanCompileError` code, so the route refuses the job
  rather than silently emitting a diverging value (the gate's existing
  raise-on-inadmissible contract; it does not "reroute").
- The legitimate shape stays admitted and byte-identical: a root-key parent
  (its key node is not an FK child), chunk-safe matching strategy, matching
  namespace/provider_config/dtype, no effective `when` on either key, no
  provider on either key, and (for fpe) a shared `fpe_join_group`.
- No change to the automatic route, the oracle, or any out-of-core module.

## 4. Explicit non-goal (do NOT close here)

A parent key that self-masks correctly but whose strategy can emit a per-row
`RowError` (`date_shift`, `bucketize`, `top_code` -- `_top_code.py:178`) still
diverges in DISPOSITION when a referencing child row exists: the oracle
quarantine-removes the cascaded child row (`_pipeline_finalize.py:179`), while
the chunked route raises `RowErrorsFailedError` on any recorded row error
(`_chunked.py:599`). That is loud-vs-quarantine, not a silent wrong value, and
is the pre-existing documented "chunked has no quarantine machinery, fail closed
on any row error" limitation. Out of scope. (Note: `fpe` is NOT in this list --
invalid fpe input raises `StrategyError` immediately, `_fpe.py:150`, not via the
row-error channel.)

## 5. Acceptance tests (authored before impl; no later contributor weakens them)

Gate-kill tests extend `test_chunked_fk_gate_kills.py`; the byte-parity /
divergence proofs mirror `test_chunked_fk.py:170-268`
(`TestByteParityWithRemapOrphans`).

1. **Gate-kill per new code.** A 3-table A->B->C where `b_id` is A's child and
   C's parent asserts `chunked_fk_parent_not_root`; a parent-key non-blank
   `when` -> `chunked_fk_parent_when_unsupported`; a child-key non-blank `when`
   -> `chunked_fk_child_when_unsupported`; a `provider` on the parent (then the
   child) FK key -> `chunked_fk_endpoint_not_scalar`; an fpe edge with no /
   mismatched `fpe_join_group` -> `chunked_fk_fpe_tweak_mismatch`. Each pins
   `.code` and `.path`.
2. **Exact-key-node correctness (predicate 8 not over-broad).** The distinct-
   column self-FK `employees.id -> employees.manager_id` stays ADMITTED and
   byte-identical; `A.id->B.a_id` + `B.id->C.b_id` stays admitted for the
   `a_id`/`b_id` children; only the SAME-key chain (`b_id` as both A's child and
   C's parent) rejects.
3. **Multi-hop cascade divergence proof.** Build the 3-table oracle where A's
   key errors on X under a quarantine-covering config; show the oracle emits
   `C.c_fk = None` for the X-referencing row (the value the empty-graph route
   would have `F(X)`-masked); assert the gate now blocks that config end-to-end
   via `run_mask_pipeline_chunked(..., table="C")`.
4. **FPE tweak parity.** An fpe parent+child with a SHARED `fpe_join_group`
   stays admitted and byte-identical (RI preserved); without a shared group it
   rejects (and, as a divergence witness, the default-column-tweak values
   differ between parent and child).
5. **`when` normalization.** A blank/whitespace `when` on an FK key does NOT
   reject (matches the compiler's None-normalization); a non-blank `when` does.
6. **No-regression.** The existing single-hop byte-parity test
   (`TestByteParityWithRemapOrphans`, root `customers -> orders`, no `when`, no
   provider, hash) stays admitted and byte-identical; the full chunked-FK gate
   suites (`test_chunked_fk_gate_kills.py`, `test_chunked_fk.py`,
   `test_de10_chunked_fk_*`, `test_chunked_admitted_set.py`) stay green (update
   the admitted-set snapshot only for the newly-rejected shapes).

## 6. Failure modes (each fails closed)

| Condition | Behavior | Test |
|---|---|---|
| parent key node `(P, pcol)` is itself an FK child endpoint | raise `chunked_fk_parent_not_root` | #1, #3 |
| parent key column has an effective (non-blank) `when` | raise `chunked_fk_parent_when_unsupported` | #1, #5 |
| child key column has an effective (non-blank) `when` | raise `chunked_fk_child_when_unsupported` | #1, #5 |
| either FK key endpoint declares a `provider` | raise `chunked_fk_endpoint_not_scalar` | #1 |
| fpe edge without a shared `fpe_join_group` | raise `chunked_fk_fpe_tweak_mismatch` | #1, #4 |
| legit single-hop root-key parent, no when/provider, hash or fpe+shared-group | admit (unchanged) | #2, #4, #6 |
