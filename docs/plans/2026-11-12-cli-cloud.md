## 0. Frame

### 0.1 What a CLI user can do after this row

- Point a `decoy run` target at S3 or GCS (`type: s3` with `bucket` and `key`, or `type: gcs`
  with `bucket` and `object`; the schemas exist today, `config/_targets.py:68`, `:102`). The run
  uploads each output under a fresh run prefix and then moves one pointer object. Consumers read
  `<dir>/CURRENT`, which holds the run id, and then `<dir>/runs/<run_id>/<file>`. No existing
  object is overwritten, ever.
- Point a `decoy run` source at S3 or GCS (`config/_sources.py:258`, `:317`). The CLI downloads
  the one named object into a private scratch arena, reads it with the same readers as a local
  file, and removes the copy on every exit.
- Use the credentials the machine already has: the AWS default chain (environment, shared config
  and credentials files, SSO, container and instance metadata) and Google Application Default
  Credentials. The CLI stores nothing and asks for nothing.
- Get the same strict and best-effort delivery as a local run (DELIV): strict delivers every
  table or none; best-effort drops a failed table and its dependents; a post-scan block withholds
  the run; a run that loses the pointer race exits 3 and delivers nothing.
- `decoy validate` checks the cloud layout offline (one bucket, one directory, legal key shapes)
  with value-free `layout.*` codes.

### 0.2 Out of V1 (each has a V2-LOG line in 14)

Windows (out of the V1 build, like F22 w1); `credentials_ref` in the CLI; `endpoint_url`
(MinIO, R2, other S3-compatible stores); prefix or glob sources (one object per source only);

`subset`, `tokenize`, `demo` and `api.mask()` (F02, row 87, and later rows); retention or

## 1. Guarantee

> A `decoy run` whose targets are all S3 (or all GCS) under one bucket and one key directory
> `<dir>` writes each delivered output as a new object under `<dir>/runs/<run_id>/` with a
> create-only precondition, and makes the run current by one conditional write of
> `<dir>/CURRENT` against the version it read when the run opened. Strict delivers every table
> or uploads nothing that a consumer can reach through `CURRENT`; best-effort uploads only the
> tables `plan_delivery` delivers. A run whose expected `CURRENT` version is stale delivers
> nothing and exits 3. No object that existed before the run is changed. No credential, secret
> reference, SDK message, bucket-internal path beyond what the user typed, or data value reaches
> stdout, stderr, `--json`, logs, the run result or evidence.

Threat model (claudeorchestrator ruling, also DELIV): accidental leaks only. A hostile principal
with write access to the bucket can always replace objects; the plan does not defend against one.

Named limits (12): an abandoned run prefix after a crash mid-upload; an incomplete multipart
upload after SIGKILL; the vault window of DELIV 12.1; a `CURRENT` write whose result is unknown
and cannot be re-read.

## 2. Established solutions

Search run (2026-11-12): AWS S3 user guide, "How to prevent object overwrites with conditional
writes" and "conditional requests"; AWS what's-new, Nov 2024 (If-Match on PutObject and
CompleteMultipartUpload); GCS "Request preconditions" and JSON API `objects.insert`; Delta Lake
"multi-cluster writes to Delta Lake storage in S3" (2022) and later put-if-absent commits; the
lakehouse atomicity write-ups (Iceberg, Delta, Hudi); in the codebase, DELIV 4.4 and 7.1, F22
5.0 to 5.4, the platform's `api/jobs/v2_cloud_materialize.py`, engine `connectors/_clients.py`.

Found and followed:
- Put-if-absent for immutable data files: S3 `If-None-Match: *` on PutObject and
  CompleteMultipartUpload; GCS `ifGenerationMatch=0` ("succeed only if there are no live
  versions"). Delta Lake's commit log relies on exactly this to make one writer win a name.
- Put-if-unchanged for the pointer: S3 `If-Match: <etag>`; GCS `ifGenerationMatch=<generation>`.
  A loser gets 412 Precondition Failed (S3 can also answer 409 ConditionalRequestConflict to a
  concurrent conditional write). This is the table-format pattern: immutable files under a
  unique prefix, then one compare-and-swap of a small metadata pointer (Iceberg's catalog
  pointer swap; git `update-ref <ref> <new> <old>` locally, which DELIV already follows).
- Never overwrite live keys: the UX map 5.2 cloud recipe. The platform's temp-key, copy and
  delete pattern (`v2_cloud_materialize.py`) overwrites the canonical key and is not followed.

Custom code left: the key-directory rule (4.2), the outcome mapping onto DELIV's receipt
(4.4), and the re-read after an ambiguous pointer write (4.3 step 8). All small.

## 3. Behaviour

### 3.1 Behaviour table

| Situation | What the user sees | Exit | Bucket after |
|---|---|---|---|
| All tables succeed, strict | one line per table plus `s3://<bucket>/<dir>/CURRENT -> <run_id>` | 0 | new `runs/<run_id>/` objects; `CURRENT` names the run |
| One table fails, strict | `table <name>: withheld (decoy/delivery_withheld)` for each other table | 3 | unchanged |
| One table fails, best-effort | delivered tables listed; failed and dependent tables named with codes | 6 | delivered tables only under the run prefix; `CURRENT` moved |
| Post-scan block | withheld lines | 4 | unchanged |
| Another run moved `CURRENT` since this run opened | `delivery_pointer_moved` | 3 | this run's objects deleted (best-effort, warning on failure); `CURRENT` is the other run's |
| `CURRENT` write returns 412 but a re-read shows this run's id | delivered (a retried request had already won) | 0 | as success |
| `CURRENT` write result unknown and the re-read fails | warning `publication_commit_uncertain` | 0 | the run may or may not be current; vault kept (DELIV `uncertain`) |
| Upload of one object fails | `publication_failed` | 3 | objects this run created are deleted; `CURRENT` unchanged |
| No credentials, access denied, bucket missing | `table <name>: cloud target unavailable (access_denied)` (fixed reason word) | 3 | unchanged; raised at sink open, before any upload |
| Mixed local and cloud targets; two buckets; two directories | `layout.delivery_root_split` | 1 | nothing contacted |
| Key is `CURRENT`, ends in `/`, has an empty, `.` or `..` segment, starts with `/`, or two tables share a basename | `layout.cloud_target_invalid` naming the table | 1 | nothing contacted |
| `credentials_ref` or `endpoint_url` set; quarantine on; `--chunked` | `layout.cloud_target_unsupported` naming the table and the field name | 1 | nothing contacted |
| Cloud source object larger than free disk | capacity failure from the spool write | 5 | unchanged |
| Cloud source missing or denied | `table <name>: cloud source unavailable (not_found)` | 3 | unchanged |
| Ctrl-C before the `CURRENT` write | aborted; this run's objects deleted | 130 | unchanged |
| Ctrl-C after the `CURRENT` write | delivered; the result says so | 130 | as success |

Exit codes come from DELIV's `RUN_EXIT_MAP` (`C:src/decoy/cli/exit_codes.py`, DELIV C3). This
plan adds no exit code.

### 3.2 Failure modes the design must hold

- F1, overwrite of live data: closed by create-only uploads and a run prefix nobody else uses.
- F2, older run replaces newer: closed by the conditional `CURRENT` write against the version
  read at open, never a blind put.
- F3, retried conditional write misread as a loss: the SDK may resend a write that already
  succeeded and then see 412. Closed by re-reading `CURRENT` after any 412 or unknown result and
  comparing the bytes with this run's id (run ids are unique per invocation).
- F4, cloud target silently skipped on some route: closed by keeping the refusal for every
  route but `decoy run` (and `validate`, which checks offline), behind one function.
- F5, SDK text leaking identity or paths: closed by fixed error words in `connectors/_clients.py`
  and `raise ... from None` with no context.
- F6, credentials stored or echoed: the CLI never constructs a credential, never passes static
  keys, refuses `credentials_ref`.
- F7, a store that ignores preconditions: closed by refusing `endpoint_url` in V1 (Q3).
- F8, abandoned local copies of source rows: closed by the F25 scratch arena (reclaimed on every
  exit, swept after a crash).

### 4.2 The cloud root rule

All targets of a run are cloud targets of one type (`s3` or `gcs`), one `bucket`, one `region`
(S3), and one key directory `<dir>`: the part of `key` (S3) or `object` (GCS) before its last
`/`, empty when there is no `/`. Each target's basename is the part after the last `/`.

- Mixed file and cloud targets, two types, two buckets, two regions or two directories:
  `layout.delivery_root_split` (DELIV's code, exit 1). It is the same single-root rule as kind A,
  so it lives in the same function.
- `layout.cloud_target_invalid` (new): a key or object that starts with `/`, ends with `/`, has
  an empty, `.` or `..` segment, has a control character, has a basename equal to `CURRENT` or
  starting with `runs`, or shares its basename with another table's target. Matching uses
  `re.fullmatch` (recurring defect 1). The message names the table and the rule, never the key.
- `layout.cloud_target_unsupported` (new): `credentials_ref` set, `endpoint_url` set,
  `quarantine.enabled: true`, or `--chunked`. The message names the table and the field name.

The rule is offline (no network), so `decoy validate` and the run gate run it before anything is
read. Objects land at `<dir>/runs/<run_id>/<basename>`; the pointer is `<dir>/CURRENT`. The key
the user wrote is never itself written (Q1).

### 4.3 Run order, kind `cloud_prefix`

DELIV 4.2 steps with the cloud arm:

1. Gate: `layout_issues` runs the cloud root rule (CC1).
2. `DeliverySink.open`: kind `cloud_prefix` when every target is cloud. Opens a
   `ScratchArena` for the stage, builds the engine `CloudDeliveryStage` (EC4), which reads
   `CURRENT` (at most 65 bytes; absent is a valid state) and records its version (S3 ETag, GCS
   generation, or `absent`). Any connector error here fails the run before an upload.
3. Routes write through `sink.write_table` into arena paths (`Placer` from DELIV C2a returns
   `arena.local_path(<basename>)`). The arena file is created 0600 by `ScratchArena.create_file`.
4. Post-scan as DELIV step 4.
5. `plan_delivery(config, outcomes)`, where outcomes now cover cloud-target tables (EC0).
6. Nothing to deliver: `sink.abort()`; the arena is reclaimed; the bucket is untouched.
7. `sink.deliver(decision, before_visible)`:
   a. upload each delivered table with create-only (`stage.put(basename, fd)`); on any upload
      failure, delete the objects this run created and return `nothing`, `publication_failed`;
   b. `before_visible()`: vault then evidence, each with its backup (DELIV `PreVisible`);
   c. the conditional `CURRENT` write with this run's id (DELIV `HeldPointer.swap` semantics:
      the value read at open is the expected value; any other version refuses);
   d. on success the sink state becomes `delivered` in the statement that passes the write;
   e. discard or restore the vault and evidence backups; reclaim the arena.
8. Ambiguous write (412, 409, timeout): re-read `CURRENT`. Equal to this run's id: delivered.
   Different: `delivery_pointer_moved`, delete this run's objects, restore backups. Re-read
   fails: `uncertain` with `publication_commit_uncertain` (DELIV maps `uncertain` as delivered
   with a warning; the vault is kept, because restoring it could leave the new outputs current
   with a vault that cannot reverse them).

No lock is taken: the conditional write is the compare-and-swap (UX map 5.2: "an equivalent ...
lock is acceptable only if it also compares the recorded version"). Two runs into the same
`<dir>` both upload under their own run prefixes; the second `CURRENT` write loses.

### 4.4 Engine contracts

- EC0, `delivery/_plan.py`: the delivery universe becomes the declared tables whose target type
  is `file`, `s3` or `gcs` (one frozenset, `DELIVERABLE_TARGET_TYPES`). DELIV AT-1c changes its
  `s3` example to an unknown name only. Pure, no I/O.
- EC1, `connectors/_clients.py`: `s3_client(*, region, endpoint_url, access_key_id,
  secret_access_key)` (moved from `s3.py:139`, same timeouts and `max_attempts: 1`) and
  `s3_error(exc) -> ConnectorError` with fixed text per class: `access_denied`, `not_found`,
  `precondition_failed`, `conflict`, `transient`, `unexpected`. No `{exc}`, no `Message` field,
  no ARN; `raise ... from None` and `__context__` cleared (recurring defect 3). `s3.py` keeps
  its public names and calls these. The outbound sentry gains an S3 arm: a `boto3.client` call
  outside `_clients.py` is a finding.
- EC2, `connectors/object_store.py` (new, public through `connectors/__init__.py`):
  `ObjectStore` protocol with `S3ObjectStore(S3Config)` and `GCSObjectStore(GCSConfig)`:
  - `put_new(key, fd) -> Version`: create-only (S3 `IfNoneMatch="*"` on `put_object` and on
    `complete_multipart_upload`; GCS `if_generation_match=0`); abort the multipart upload on
    failure; SDK default checksums on (botocore flexible checksums, GCS crc32c).
  - `read_small(key, limit) -> tuple[bytes, Version] | None`: bounded GET; `None` when absent.
  - `put_if(key, data, expected: Version | None) -> PutResult` (`won`, `lost`, `unknown`):
    `IfMatch` or `IfNoneMatch="*"` on S3, `if_generation_match` on GCS. 412 and 409 map to
    `lost`; a timeout or 5xx after send maps to `unknown`. Never retried inside the store.
  - `delete_created(key, version)`: S3 `delete_object` (and the version id when the response
    carried one), GCS `if_generation_match=<generation>`, so only the object this run made goes.
  - `iter_object(key) -> Iterator[bytes]`: the existing source `open` path, used by the spool.
  Every error goes through EC1 or `gcs_error`. Credentials are whatever the config carries: the
  CLI passes none, so the SDK walks its default chain; the platform may pass resolved ones.
- EC3, `publication/_current.py` (DELIV E2a): `CurrentPointer` takes a `PointerStore` with
  `read() -> PointerState(raw, version)` and `replace_if(state, new: bytes) -> PutResult`. The
  local store is DELIV's code (held lock, raw compare, durable replace); `ObjectPointerStore`
  (new `publication/_object_pointer.py`) wraps EC2. The rule stays DELIV's: any stale expected
  value refuses, whatever the operation id. Gap 13.1: E2a as planned takes an `OutputDir` and a
  held `flock`, which an object store does not have.
- EC4, `delivery/_cloud_stage.py` (new): `CloudDeliveryStage.open(store, dir, run_id)`, `put`,
  `abort`, `deliver(before_visible) -> DeliveryReceipt`. It owns the created-object list, the
  re-read of step 8, and the cloud rows of DELIV's outcome table:

| Source | Value | Receipt state | Cause |
|---|---|---|---|
| open | pointer read fails | nothing (raised before any write) | connector error word |
| put | any failure | nothing; created objects deleted | `publication_failed` |
| pointer | `won` | delivered | none |
| pointer | `lost`, re-read shows this run | delivered | none |
| pointer | `lost`, re-read shows another value | nothing; created objects deleted | `delivery_pointer_moved` |
| pointer | `unknown`, re-read fails | uncertain | `publication_commit_uncertain` |
| delete after loss | any failure | unchanged; a warning | none |

### 4.5 Credentials

The CLI never reads, writes, prints or forwards a credential. It builds `S3Config` and
`GCSConfig` with only bucket, region and prefix; `access_key_id`, `secret_access_key`
(`connectors/s3.py:110`) and `service_account_json` (`connectors/gcs.py:50`) stay unset, so the
SDK walks its default chain (`s3.py:149-151` comment). `credentials_ref` is refused (4.2), because
the engine treats it as opaque and only the platform resolves it (`config/_targets.py:7`). AWS
profile and region come from the environment (`AWS_PROFILE`, `AWS_REGION`) or the config's
`region`. No `--profile` flag in V1. A CLI sentry fails on any CLI module that passes those three
config fields or imports `boto3` or `google.cloud.storage` directly.

### 4.6 Errors, reason codes and records

- Engine connector errors carry a fixed word (EC1); the CLI prints
  `table <name>: cloud target unavailable (<word>)` or `cloud source unavailable (<word>)`.
- No new reason code: delivery uses DELIV's four, `publication_failed` and
  `publication_commit_uncertain` (`reasons/decoy/_core.py:73-84` and F22). If the build finds one
  is needed, it is added with `since=UNRELEASED` once REG-RELEASE E2 (#506) is on main, with a
  `changelog.d/` fragment and no `REGISTRY_VERSION` edit.
- Run result and evidence carry table names, formats, basenames, digests of the staged file and
  the run id. The cloud URI (`s3://<bucket>/<dir>/runs/<run_id>/<basename>`) is built only from
  what the user typed plus the run id and appears only on stdout and in `--json` `outputs`
  (Q4). Nothing listed from the bucket ever reaches any surface.

### 4.7 Cloud sources

`read_source` (`C:src/decoy/cli/_sources.py:168`) gains a cloud arm that calls
`C:src/decoy/cli/io/_cloud.py` `spool_source(table, src, arena)`: one object (S3 `key`, GCS
`object`), streamed by `ObjectStore.iter_object` into `arena.create_file(<table>.src)` (0600),
then read by the existing local reader on `arena.local_path(...)`. The arena is opened and
reclaimed by the caller of `read_source`, so the copy is gone on every exit; after SIGKILL the F25
sweep reclaims it (`sweep_scratch`, called by the CLI, F25 Q7). `iter_source_chunks` gets the
same arm with the arena held by the generator's `finally`. Cloud sources are refused on
`--chunked` in V1 only if the build cannot keep the arena alive across the chunk loop (Q6).

### 4.8 CLI side

- `C:src/decoy/cli/io/_cloud.py` (new, beside `_targets.py`): `CloudRoot` (type, bucket,
  region, dir, basenames), parsed once from the config; `cloud_root_issues(config)` for the gate;
  `store_for(root)` building the engine `ObjectStore`; `spool_source`.
- `C:src/decoy/cli/io/_delivery.py`: `RootKind.cloud_prefix`; the sink holds a
  `CloudDeliveryStage` instead of a `DeliveryStage` and an arena instead of an F22 stage.
- `C:src/decoy/cli/io/_placement.py`: `layout_issues` calls `cloud_root_issues`.
- `C:src/decoy/cli/io/_layout_errors.py`: the two new descriptors.
- `C:src/decoy/cli/extras.py`: `check_cloud_endpoints_supported` keeps refusing for every caller
  except the run route, which passes `route="run"`; the refusal text drops "yet". It stays the one
  refusal function, so every other command still fails closed (F4).
- `C:src/decoy/cli/explain.py`: the extras text says what run does with S3 and GCS.
- Lane: CLI-CLOUD writes no `C:src/decoy/cli/run/` module, so it does not enter the `run/` lane
  (ROADMAP 5.2 rule 2 asks the plan to say so). The run route reaches the cloud kind through the
  sink DELIV C2a already wires. If the build finds `ctx._published` (`dict[str, Path]`,
  `C:_targets.py:443`) cannot carry a URI, a `run/_context.py` change joins the lane after DELIV
  C5 (14).

### 4.9 Design notes

- Principles: one owner per fact (4.1); dependency rule (the CLI calls the engine stage; the
  engine never knows the CLI); open for a new backend through `PointerStore` and `ObjectStore`,
  which are the two seams expected to grow (Azure, SFTP, F02).
- Established pattern: section 2.
- House style: typed `CloudRoot` and `PointerState` objects, no flag arguments that switch
  behaviour (the store type picks the backend), comments say why.

## 5. Hostile cases by surface

- Keys from the config are untrusted input that builds object names (4.2 rule, AT-C04).
- `CURRENT` contents are untrusted (another tool may write it): read bounded, decoded only when
  it is a run id (`is_run_id`, DELIV), compared as raw bytes; garbage still compares, so the run
  loses rather than overwrites (AT-C08).
- SDK messages are untrusted text (EC1, AT-C10).

### 6.2 Exit paths

- Success: `CURRENT` moved; arena reclaimed; backups discarded (DELIV `_flow.py` success path,
  `C:src/decoy/cli/run/_flow.py:72-81`).
- Refusal at the gate (exit 1): nothing contacted; no arena opened.
- Connector error at sink open (exit 3): arena reclaimed; nothing uploaded.
- Decision `deliver=False` (exit 3 or 4): arena reclaimed; nothing uploaded.
- Upload failure (exit 3): created objects deleted; arena reclaimed; backups untouched.
- Pointer lost (exit 3): created objects deleted; backups restored.
- Pointer unknown (exit 0, warning): objects kept; vault kept.
- `KeyboardInterrupt` before the pointer write: `abandon()` reaches the sink callback; created
  objects deleted (best-effort); exit 130.
- `KeyboardInterrupt` after it: delivered; exit 130.
- SIGKILL: arena left for `sweep_scratch`; objects under the run prefix left (named limit);
  incomplete multipart uploads left (named limit).

### 6.3 Routes

- `decoy run`, plain route: through the sink (`C:src/decoy/cli/run/_execute.py:267`, `execute`).
- `decoy run --chunked` with a cloud target: refused (`layout.cloud_target_unsupported`); the
  chunked writer appends per table (`C:_targets.py:498`), which cannot be create-only in V1.
- `decoy validate`: offline cloud root rule only.
- `decoy run --preview`: writes nothing; cloud sources are read through the spool.
- `tokenize`, `demo`, `api.mask()`, `scan`, `fit`, `subset`: refused by
  `check_cloud_endpoints_supported` as today (`C:extras.py:123`).
- Platform: unchanged (PARKED); the engine stage is its future seam.

### 6.4 FK shapes

- Parent and child both cloud targets: best-effort drops the child with a failed parent and
  never uploads it (DELIV AT-3 rerun with `s3` targets, AT-C05).
- Two parents, one failed: the child is dropped, the good parent uploaded.
- Table-level cycle: the component drops whole, nothing of it uploaded.
- Generate `reference` parent with a cloud target: the edge from `generation_order` applies
  unchanged (`generation/synthesize.py:226`).

### 6.5 Fields

- `PointerState`: `raw: bytes | None`, `version: str | None` (ETag or generation as text).
- `PutResult`: `won | lost | unknown`.
- `CloudRoot`: `type`, `bucket`, `region`, `dir`, `basenames` (per table).
- `TableDelivery.output` (`run_result/_model.py:282-287`): the basename for cloud outputs (Q4).
- `CURRENT` object: the run id as UTF-8 plus `\n`, nothing else (the same bytes as `LATEST`).

### 6.6 Output surfaces

- stdout and stderr (`C:src/decoy/cli/run/_render.py`, `C:src/decoy/cli/run/_errors.py`):
  table names, codes, fixed words, the URI built from typed parts.
- `--json` `outputs` and `output_dir`: the URIs (Q4).
- Run result and evidence: basenames, digests, run id, no bucket.
- The bucket: `runs/<run_id>/` objects and `CURRENT`.
- Logs and spans: no new attributes.

## 13. Missing in DELIV, F22 and F25 for the cloud route

1. DELIV E2a (4.4): `CurrentPointer(parent: OutputDir, name)` compares raw bytes under a held
   `flock` and writes by durable replace. An object store has no lock and no `OutputDir`; its
   compare-and-swap is the conditional write on a version. 7.1's "a cloud `OutputDir` behind the
   same `CurrentPointer`" is not buildable as written. Ask: E2a defines the `PointerStore` seam
   (`read() -> PointerState`, `replace_if`) with its local store, so EC3 only adds a store.
2. DELIV E1a (merged #519): the delivery universe is `type == "file"` only and AT-1c pins an
   `s3` outcome as an error. EC0 widens it.
3. DELIV 4.3 kind R stages through an F22 directory stage; the cloud kind has no F22 unit and
   stages in an F25 arena. DELIV's sink must take the stage from the kind, not assume F22.
4. DELIV 7.1 does not say what happens to uploaded objects after a lost race or a failed
   upload, nor how to read an ambiguous conditional write. 4.3 step 8 and Q8 answer both.
5. DELIV `ctx._published` is `dict[str, Path]` (`C:_targets.py:443`); a URI does not fit (14).
6. F22: `OutputDir`, `publish_unit`, the descriptor and rule D are local-filesystem only; the
   managed `CURRENT` is deferred (F22 5.4). Nothing in F22 serves objects, which is fine; the
   F22 5.4 starting rule should name the `PointerStore` seam when F22 builds `CURRENT`.
7. F25 lists "caller-side cloud-to-local spools" as a required integration inventory,
   "asserted, verify before build" (F25 plan line 85), with no named caller. CLI-CLOUD is that
   caller: `ScratchArena.create_file` plus `local_path` (#494). F25 should list CC3 in its
   consumer table.
8. The UX map 5.2 says "the pointer names only delivered tables". With best-effort uploads
   limited to delivered tables, the run prefix holds only those, so `CURRENT` stays a run id
   and keeps one format with `LATEST`.

## 16. Pre-mortem

A route writes cloud objects outside the sink: G-ONE-DELIVERY-SINK (AT-C15). An older run moves
`CURRENT` back: conditional write against the version read at open (AT-C08). A retried pointer
write reports a false loss and deletes a delivered run's objects: the re-read (AT-C12). An S3
error prints an ARN: fixed words and no context (AT-C10). A user's existing object is replaced:
outputs never use the typed key, and uploads are create-only (AT-C02, AT-C03). Source rows stay
on disk after a crash: the F25 arena and sweep (AT-C13). A store ignores preconditions:
`endpoint_url` is refused (AT-C17). `_delivery.py` passes its cap: CC2 keeps the cloud kind's
code in `io/_cloud.py` and the engine stage, so the sink adds about 65 lines.
