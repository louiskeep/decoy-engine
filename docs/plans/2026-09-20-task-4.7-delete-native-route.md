# Task 4.7: delete the superseded standalone native routing lane

> Roadmap: Stage A item 3 (Phase 4). Follows route activation (engine #165). Cam

> Codex plan-gate: GO (round 3 conditional + round-4 amendment applied, 2026-09-20).

## Frame

The unified-slice lane is now the production default (`unified_slice_enabled=True`,
engine #165). The older standalone native STREAMING lane (`_native_route.py` +
siblings, gated by `native_route_enabled`) has **zero production ownership**: the
flag defaults `False` at `_pipeline.py:173` and no production caller ever sets it
True (the platform worker `_isolated_worker.py:226` never injects it; the platform
repo has zero references). It is dead code -- a never-executed path. Task 4.7 removes
it to leave one production decision path.

**This is an intentional pre-GA public-API hard cutover.** `run_pipeline`'s
`native_route_enabled` kwarg and `ExecutionResult.native_route` are public surfaces,
and `run_pipeline` accepted `native_route_enabled=True`. Verified non-use is scoped to
the two first-party repos checked (decoy-engine + decoy-platform); an unknown external
embedding caller could in principle pass the kwarg or read the field. The engine is
pre-GA (`decoy_engine.RELEASE_PHASE`; `is_pre_ga()` true), where the standing policy is
hard delete, not deprecate (CLAUDE.md "Pre-GA = hard delete"; [[decoy-pre-release-no-locking]]).
So this removes the surfaces outright. Record it in the CHANGELOG as a breaking pre-GA
API change; Cam's merge confirm (gate sequence) is the owner sign-off.

Scope is wider than "delete 3 files + a flag": the flag and its native-admission
fact are threaded into the **live** `execution/physical/` compiler that the active
unified slice runs through, so the physical modules import the files being deleted.
Deleting the lane therefore forces coordinated edits across `physical/` and shifts
the internal `plan_hash`. This is behavior-safe (every touched path is behind the
always-False flag) but it edits live-path code, so the full gate stack applies.

**No capability is lost.** The native lane is streaming (LazySource, single-pass,
flat RSS); the unified slice is full-frame only. Because the flag is always False,
single-table non-FK passthrough/redact/truncate jobs already bypass the native lane
today and reach the legacy pandas full-frame oracle (`_pipeline_sources.materialize_source`
→ `LazySource.to_table()`), which is unchanged by this deletion. The only thing the
native lane offered -- a dormant flat-RSS streaming speedup for three strategies --
was never shipped; it survives in git history + two mutation ledgers if ever revived.

## plan_hash handling (observable, pre-GA identity change)

Removing `native_route_enabled` from `PhysicalPlanInputs` changes the compiled
`plan_hash` (it is a hash input at `_inputs.py:472`; asserted by
`test_compiler_units.py`). Correction to an earlier draft: `plan_hash` is NOT purely
internal -- an admitted unified-slice run emits it into
`quality_metrics[QUALITY_METRICS_KEY]["plan_hash"]` (`_unified_slice.py:357`), and the
isolated worker serializes `quality_metrics` into its result envelope
(`_isolated_worker.py:242`, described as platform-manifest-safe). So `plan_hash` is an
OBSERVABLE identity that surfaces in the job manifest.

Because `native_route_enabled` is always False in production, the field's hash-input
value is constant today; removing it shifts every admitted job's `plan_hash` by a
one-time constant. Handling:
- Treat this as a pre-GA observable-identity change (same pre-GA hard-cutover framing
  as the API surfaces above; nothing is locked pre-GA, [[decoy-pre-release-no-locking]]).
- BUILD STEP (do first): inventory platform readers of `plan_hash` -- grep decoy-platform
  for `plan_hash` and confirm nothing compares it ACROSS the deletion boundary (e.g. an
  equality check between a stored pre-deletion manifest and a post-deletion run). A
  within-run or forward-only consumer is fine; a cross-boundary equality check is not.
  If a cross-boundary consumer exists, STOP and escalate before proceeding.
- Add a SERIALIZATION/consumer test (not merely a golden re-pin): assert an admitted
  run still emits a well-formed `plan_hash` in `quality_metrics` and that the worker
  envelope round-trips it. Re-pin the compiler goldens and delete the now-moot
  `test_plan_hash_changes_with_native_route_enabled`.
- CHANGELOG: note the one-time `plan_hash` shift under the pre-GA breaking-change entry.
