## 1. FRAME

**Problem.** The engine can estimate k-anonymity during profiling (a heuristic search over 2- and
3-column combinations, `profiling/profiler.py::_compute_k_anonymity`), but it cannot measure the
standard syntactic privacy models over a quasi-identifier set the caller names: k-anonymity with
its class-size distribution, l-diversity of a sensitive column, and t-closeness. F37 (post-mask
privacy risk) and the later enforcement search (V2-3.3) both need one exact, tested measurement
primitive.

**Definition of done.**

1. A new sub-package `decoy_engine.quality.anonymity` exports three measurement families:
   - `measure_k_anonymity(table, quasi_identifiers, *, k_target=None) -> KAnonymityReport`
   - `measure_l_diversity(table, quasi_identifiers, sensitive, *, l_target=None, recursive_c=None) -> LDiversityReport`
   - `measure_t_closeness_equal(table, quasi_identifiers, sensitive, *, t_target=None) -> TClosenessReport`
     and `measure_t_closeness_ordered(...)` with the same signature.
2. `table` is a `pandas.DataFrame` or a `pyarrow.Table`; both give identical reports (only the
   named columns are read).
3. Results match the published definitions: Sweeney 2002 (k), Machanavajjhala et al. 2007
   (distinct, entropy, recursive (c, l)), Li, Li and Venkatasubramanian 2007 (EMD with equal and
   ordered ground distance). The salary worked example from Li et al. 2007 (Tables 4 and 5)
   reproduces the paper's numbers.
4. Reports are frozen dataclasses holding only counts, measures, booleans and fixed tokens. No
   quasi-identifier value, sensitive value or class key appears in a report, its repr, or any
   error message or exception chain.
5. Null policy is stated in the module docstrings and tested (section 3).
6. Dark: no config key, strategy, planner check, validator registration, reason code, CLI change,
   dependency or lock change. `decoy_engine.quality.__init__` lazy exports are not extended; the
   sub-package is reached only by importing it.

**Non-goals (recorded follow-ups, not blockers).**

- Running as a post-mask validator, failing a run, quality-contract integration, evidence
  attachment (second V2-3.2 slice; needs reason codes and F35).
- Generalization, suppression, search, information-loss metrics (V2-3.1, V2-3.3).
- Hierarchical ground distance for t-closeness (needs V2-3.1 hierarchies). The paper's disease
  numbers (0.278) use it and are therefore not a fixture here.
- Journalist and marketer risk (need a population table or sampling weights); only the two
  prosecutor-model figures ARX reports from the data alone are included.
- Probabilistic or (alpha, k) variants, delta-presence, differential privacy (separate DPS program).
- ARX cross-check oracle test (ARX is Java; adding it is a dependency; follow-up for a dev-only
  lane).
- Streaming or chunked measurement: the named columns must fit in memory (section 9).
- Changing the profiler (section 1, reuse check).

**Risk: R2.** New privacy logic whose numbers a later slice will use to pass or fail a release,
and a new public import path. Rollback: revert; nothing is persisted or wired.

**Reuse check.**

- `profiling/profiler.py::_compute_k_anonymity` (640-line file) computes the minimum group size
  over candidate combinations with `df.loc[:, combo].dropna().groupby(...).size().min()`. It is a
  candidate search, not a measurement over a given set, and it drops rows with any null
  quasi-identifier, which differs from this module's null policy (nulls are their own value). The
  new module becomes the one place where equivalence classes over a named quasi-identifier set are
  computed. Switching the profiler to call `measure_k_anonymity` would change its numbers for any
  table with null quasi-identifiers, so it is out of scope; follow-up: "profiler k-anonymity
  reuses `quality.anonymity`, with a decision on null policy".
- `quality/_distribution_gof.py` and `snapshot.py` work on binned summaries; they cannot give
  per-class distributions, so nothing there is reusable for EMD.
- `scipy.stats.wasserstein_distance` would compute ordered EMD on value positions, but scipy is not
  a declared dependency (brief constraint 2) and it works on one pair of distributions at a time,
  which is a Python loop over up to n classes. Not usable.
- pandas `factorize` and `groupby` (already dependencies) do the grouping.

## 2. Established solutions

Searches run (2026-11-07, WebSearch): "t-closeness Li Li Venkatasubramanian 2007 Earth Mover's
Distance ordered distance formula equal distance worked example"; "ARX data anonymization
l-diversity recursive (c,l) entropy distinct definition null handling"; "sdcMicro ldiversity
freqCalc measure_risk k-anonymity missing values NA handling"; "t-closeness salary example 3K 11K
EMD 0.375 0.167 ordered distance"; "ARX anonymization t-closeness EqualDistance OrderedDistance
HierarchicalDistance javadoc". Codebase: `grep k_anonymity|quasi` over `src/`. Direct fetches of
the two PDF copies of Li et al. 2007 (cerias.purdue.edu, profsandhu.com) were blocked by the
session's network allowlist; the formulas below are the paper's as quoted in the search results
and in the arXiv tutorial (Domingo-Ferrer and Soria-Comas, "A Tutorial on Computing
t-Closeness", arXiv:1911.11212), and the worked-example numbers were re-derived by hand (section 7).

Findings:

- **k-anonymity** (Sweeney 2002, "k-anonymity: a model for protecting privacy"): every
  equivalence class (rows sharing all quasi-identifier values) has at least k rows. ARX reports,
  for the prosecutor attacker model, the highest re-identification risk `1 / min class size` and
  the average risk `classes / rows`; both need only class sizes.
- **l-diversity** (Machanavajjhala, Kifer, Gehrke, Venkitasubramaniam 2007, TKDD 1(1)): distinct
  l-diversity (at least l distinct sensitive values per class), entropy l-diversity
  (`-sum p log p >= log l` per class) and recursive (c, l)-diversity (`r_1 < c (r_l + ... + r_m)`
  with counts sorted descending). ARX implements all three under the same names.
- **t-closeness** (Li, Li, Venkatasubramanian, ICDE 2007): a class satisfies t-closeness when the
  EMD between its sensitive distribution P and the whole table's Q is at most t. Equal ground
  distance: `EMD = 1/2 sum |p_i - q_i|` (total variation). Ordered ground distance over the m
  ordered values: `d(v_i, v_j) = |i - j| / (m - 1)` and
  `EMD = 1/(m-1) * sum_{i=1..m} |r_1 + ... + r_i|` with `r_i = p_i - q_i`. ARX names the variants
  EqualDistance, OrderedDistance and HierarchicalDistance t-closeness.
- **Nulls.** sdcMicro `freqCalc` treats a missing key value as a wildcard matching every category
  (weighted by `alpha`), which raises class sizes and so lowers measured risk. ARX treats
  suppressed records as removed from the release. No source found for ARX's handling of nulls in
  the sensitive attribute.

Design follows: the three papers' definitions exactly, ARX's variant names and its two
prosecutor risk figures, and pandas `factorize` plus `groupby` for grouping (the profiler's own
mechanism). Custom code is needed for (a) the null policy, chosen conservative (section 3), and
(b) a sparse evaluation of the ordered EMD so it costs O(nonzero class-value pairs times log m)
instead of a dense classes-by-values matrix (n squared for a k = 1 table). The sparse form is an
algebraic rearrangement of Li et al.'s formula, checked against the direct formula by a property
test (section 7).

## 3. Behavior

### Inputs

| Input | Rule |
|---|---|
| `table` | `pandas.DataFrame` or `pyarrow.Table`; anything else `TypeError`. A pyarrow table is reduced with `select(columns)` and converted with `to_pandas(types_mapper=pd.ArrowDtype)`, which is lossless (an `int64` column with nulls stays `int64[pyarrow]` instead of becoming `float64`; timestamps keep their unit and range). Other columns are never converted. A conversion failure is re-raised value-free (section 3, failure modes). |
| `quasi_identifiers` | non-empty sequence of distinct column names (a bare `str` is refused: it is a sequence of characters); each must exist. |
| `sensitive` | one column name; must exist and must not be a quasi-identifier. |
| `k_target`, `l_target` | `int >= 1`, or None. `bool` is refused (`TypeError`), as are floats and numeric strings. |
| `recursive_c` | real `> 0` (`int` or `float`, not `bool`, finite), or None. |
| `t_target` | real in `[0, 1]`, finite, not `bool`, or None. |

### Null policy (stated in the package docstring)

- **Quasi-identifiers: a null is its own value.** Rows whose quasi-identifier is null share a
  class only with rows that are null in the same columns and equal elsewhere. This is the
  conservative choice for measuring risk: it never merges a null row into a larger class (unlike
  sdcMicro's wildcard), so measured k is never higher than the data supports. A null that stands
  for a suppressed record (ARX's treatment) therefore still counts as a row; callers that suppress
  rows drop them before measuring. `NaN`, `None`, `pd.NA`, `NaT` and Arrow nulls are all null and
  all the same value. The report counts rows with any null quasi-identifier.
- **Value identity in quasi-identifiers is exact and family-aware.** Two non-null cells are the
  same quasi-identifier value only when they are equal and of the same canonical type family. The
  families are: `bool` (`bool`, `np.bool_`), `int` (`int`, every `np.integer`), `float` (`float`,
  every `np.floating`), `complex`, `decimal`, `str` (`str`, `np.str_`), `bytes`, `datetime`
  (`datetime.datetime`, `pd.Timestamp`, `np.datetime64`), `date`, `time`, `timedelta`
  (`datetime.timedelta`, `pd.Timedelta`, `np.timedelta64`); any other type is its own family by
  qualified name. So in an `object` column `1` and `np.int64(1)` are one value, `"a"` and
  `np.str_("a")` are one value, `pd.Timestamp` and an equal `datetime.datetime` are one value, but
  `1`, `1.0` and `True` are three (pandas `factorize` alone merges them because they hash equal),
  and `1` and `"1"` are two. Across families this can only split classes, which errs towards
  lower k. Typed columns (numeric, Arrow types, datetimes, categoricals) hold one family, so
  equality alone decides; an Arrow `int64` column keeps `2**53` and `2**53 + 1` apart because the
  conversion is lossless. `Decimal` values compare by number (`Decimal("1.0") == Decimal("1.00")`),
  as Python and Arrow do. `-0.0` equals `0.0`.
- **Value identity in the sensitive column depends on the model (each conservative for it).**
  For l-diversity sensitive cells are coded by plain equality (`1`, `1.0` and `True` in an
  `object` column are one sensitive value): merging can only lower distinct, entropy and
  recursive l. For t-closeness they are keyed by type family, like quasi-identifiers: merging
  could only lower the total variation and the ordered EMD (an `object` sensitive column with
  classes `[1, 1]` and `[1.0, 1.0]` is 0.5 apart as two values and would read 0 merged). Ordered
  EMD refuses `object` columns, so in practice the family keying affects equal-distance EMD.
  (Revision after code review P2-1.)
- **Arrow dictionaries with null or NaN entries.** A dictionary entry that is null (for example
  from `dictionary_encode(null_encoding="encode")`) or NaN marks a null cell; such entries are
  removed and the rows pointing at them become null before conversion, keeping the order and the
  `ordered` flag of the remaining entries (pandas cannot hold a null category).
- **Chunked ordered Arrow dictionaries.** When the chunks of an ordered dictionary column carry
  different dictionaries (common for Parquet read per row group), pandas would merge the
  categories in order of appearance and keep `ordered=True`, inventing an order. If one chunk's
  dictionary holds every other chunk's entries in the same relative order, all chunks are
  re-indexed onto it; otherwise the column is treated as unordered, so ordered t-closeness refuses
  it with the value-free `TypeError` naming the column. Reconciliation runs only for the sensitive
  column of ordered t-closeness (k, l and equal t factorize by value and accept such columns
  as they are) and searches the distinct chunk dictionaries only. (Revisions after code review
  rounds 2 and 3.)
- **Float NaN is null everywhere.** A float NaN is null whether it comes from pandas or is a NaN
  value inside an Arrow `float`/`double` column (Arrow keeps NaN and null apart; under
  `pd.ArrowDtype`, `isna()` reports only nulls). The null mask therefore ORs `pyarrow.compute.is_nan`
  into `isna()` for Arrow floating columns, so a NaN quasi-identifier joins the null class and a NaN
  sensitive value is excluded like a null.
- **Sensitive column: nulls are excluded from distributions.** Counting null as a sensitive value
  would raise distinct and entropy l (it looks like diversity); for l-diversity excluding it is
  conservative. The reports count null-sensitive rows. A class whose sensitive values are all null
  has distinct l 0, entropy l 0 and recursive l 0, is reported in
  `classes_without_sensitive_values`, and so fails any l target.
- **t-closeness with unmeasured classes is undetermined, not a pass.** A class with no non-null
  sensitive value has no distribution, so its EMD cannot be measured. It is counted in
  `classes_without_sensitive_values` and `rows_in_unmeasured_classes`. `meets_target` is `False`
  when any measured class exceeds t; otherwise `None` (undetermined) whenever an unmeasured class
  exists; `True` only when every class was measured and none exceeds t. Excluding nulls is not
  called conservative for t: when nulls carry meaning (for example "not tested"), null skew
  between classes is a disclosure that t-closeness over the non-null values does not see
  (section 9). If the table has no non-null sensitive value, l measures are 0, `max_emd` is None
  and `meets_target` is None.

### Outputs

All reports are `@dataclass(frozen=True, slots=True)` with only builtin `int`, `float`, `bool`,
`None`, fixed `Literal` tokens and tuples of builtin `int` pairs; constructors coerce numpy
scalars with `int()`/`float()`, and each report's `__post_init__` checks the exact runtime type of
every field value (a numpy scalar, a `str` outside the token set, or any other object raises
`TypeError`). Sizes are row counts.

| Report | Fields |
|---|---|
| `KAnonymityReport` | `row_count`, `class_count`, `k_min` (None when empty), `class_size_distribution` (tuple of `(class_size, number_of_classes)` sorted by size), `rows_with_null_quasi_identifier`, `highest_prosecutor_risk` (`1 / k_min`; None when empty), `average_prosecutor_risk` (`class_count / row_count`; None when empty), `k_target`, `classes_below_target`, `rows_below_target`, `meets_target` (None when no target) |
| `LDiversityReport` | `row_count`, `class_count`, `rows_with_null_sensitive`, `classes_without_sensitive_values`, `distinct_l_min`, `entropy_l_min` (`exp` of the smallest class entropy, natural log; the "effective number of values"), `recursive_c`, `recursive_l_min` (None without `recursive_c`), `l_target`, and per variant `classes_below_target` / `rows_below_target` / `meets_target` for distinct, entropy and recursive |
| `TClosenessReport` | `ground_distance` (`"equal"` or `"ordered"`), `row_count`, `class_count`, `classes_measured`, `classes_without_sensitive_values`, `rows_in_unmeasured_classes`, `rows_with_null_sensitive`, `distinct_sensitive_values` (m), `max_emd` (None when no class was measured), `t_target`, `classes_above_target`, `rows_above_target`, `meets_target` (True, False, or None for no target or undetermined; section 3 null policy) |

Per-class definitions (d = distinct non-null sensitive values in the class, counts
`r_1 >= ... >= r_d`, n_c = non-null sensitive rows in the class):

- distinct l = d.
- entropy l = `exp(H)`, `H = -sum (r_i / n_c) ln (r_i / n_c)`. The class meets target l when
  `H >= ln l - 1e-12` (absolute tolerance, so a class of l equally frequent values is not failed by
  rounding).
- recursive l at c = the largest `l` in `1..d` with `r_1 < c * (r_l + ... + r_d)`; 0 when none
  holds (only possible for `c <= 1`). The predicate is monotone in l (tail sums shrink), so the
  largest l is the class's measure, and `(c, l_target)`-diversity holds when it is at least
  `l_target`. A recursive l of 1 is a convention of this module, not the paper's (Machanavajjhala
  et al. define recursive (c, l) for `l >= 2`): it means `r_1 < c * n_c`. Target checks for
  recursive need both `recursive_c` and `l_target`; with `l_target` but no `recursive_c`, the
  recursive fields (`recursive_l_min`, its below-target counts and `meets_target`) are None, as
  documented in the function docstring.
- equal EMD = `1/2 sum_v |p_v - q_v|` over all distinct sensitive values in the table.
- ordered EMD = `1/(m-1) sum_{i=1..m-1} |F_c(i) - G(i)|`, F and G the cumulative class and table
  distributions over the sorted distinct values; 0 when m = 1. "Meets t" is `emd <= t + 1e-12`.

Ordered ground distance needs an ordered sensitive column: numeric (including bool and Arrow
`decimal128`/`decimal256`), datetime, timedelta, a pandas ordered `Categorical`, or an Arrow
dictionary column with `ordered=True` (order = category or dictionary order; categories not present
in the data are not counted in m, matching Li et al.'s m as the number of values in the table).
Strings, unordered categoricals and unordered Arrow dictionaries, and every `object` column
(including pandas columns of `Decimal` objects; convert them to an Arrow decimal or float first)
are refused with `TypeError`: a lexicographic or mixed-type order is not an ordinal distance.

| Failure | Behavior |
|---|---|

value.

## 4. Design notes

- **Structure.** One shared private module computes everything the three models must agree on:
  input normalization, column and target validation, equivalence class codes (null policy for
  quasi-identifiers) and sparse (class, sensitive value) counts (null policy for the sensitive
  column). One module per model turns those counts into a report. Change pain addressed (single
  responsibility, information hiding): the null policy and class identity are one fact in one
  place, so k, l and t can never disagree on what a class is; the second slice (validator wiring)
  and V2-3.3 (search) depend on the three small `measure_*` functions, not on pandas grouping
  details.
- **Lossless input.** A pyarrow table is converted with `to_pandas(types_mapper=pd.ArrowDtype)`
  (probed: `int64` with nulls stays `int64[pyarrow]`, and `pd.factorize` gives `2**53` and
  `2**53 + 1` distinct codes; ordered dictionaries keep `ordered=1`; `decimal128` and far-range
  timestamps convert without a cast). The conversion and every Arrow compute call sit inside one
  `_read_columns` function whose failures are re-raised value-free.
- **Class codes.** Two named functions (not one function with a mode flag) share one null-mask
  helper and one factorize helper:
  `_quasi_identifier_codes(series, column)` and `_sensitive_codes(series, column)`. The null
  mask is `series.isna()`, ORed with `pc.is_nan` for Arrow floating columns. Non-null cells are
  factorized with `pd.factorize(..., use_na_sentinel=True)` and null cells get one explicit code
  (probed: with `use_na_sentinel=False` an Arrow dictionary column still returns -1 for null, so
  the flag is not relied on). For an `object` quasi-identifier column, `_type_family(cell)` is also
  factorized and combined with the value code, giving family-aware identity; the sensitive
  function skips that step (plain equality). Any exception from factorizing or from the family
  step (`TypeError` for unhashable cells, `pa.ArrowNotImplementedError` for an Arrow list column,
  `pa.ArrowInvalid`, `ValueError`) is turned into a value-free `TypeError` naming the column, raised
  after the `except` block closes. The per-column quasi-identifier codes are grouped with
  `groupby(..., sort=False).ngroup()`, giving one `int64` class id per row; `(class_id,
  value_code)` pairs are counted with one `groupby().size()`. For ordered distance, value codes
  are re-ranked to sort order (the sorted unique non-null values for numeric, decimal, datetime
  and timedelta; category or dictionary index order for ordered categoricals and dictionaries).
- **Sparse EMD.** Equal: for each class, `EMD = 1/2 (1 + sum_{v present} (|p_v - q_v| - q_v))`
  (absent values contribute `q_v`). Ordered: F_c is constant between the class's present values,
  so the sum splits into segments `[a, b)` with constant `f`; G is non-decreasing, so with
  `s = searchsorted(G, f)` clipped to `[a, b)` and PG the prefix sum of G,
  `sum_{i=a}^{b-1} |f - G(i)| = f(s-a) - (PG(s)-PG(a)) + (PG(b)-PG(s)) - f(b-s)`. All segments of all
  classes are evaluated in one vectorized pass; cost O(P log m) for P nonzero pairs.
  Precision: the whole numerator is computed exactly in integers. With N non-null sensitive rows,
  `CQ(i)` the table's cumulative count and `CP` the class's cumulative count,
  `|F_c(i) - G(i)| = |CP * N - CQ(i) * n_c| / (n_c * N)`. The crossing point is
  `s = searchsorted(CQ, ceil(CP * N / n_c))` (integer ceiling division, exact), and each segment's
  bracket `CP*N*(s-a) - n_c*(PCQ(s)-PCQ(a)) + n_c*(PCQ(b)-PCQ(s)) - CP*N*(b-s)` uses the integer
  prefix sums `PCQ` of `CQ`. Every term is bounded by `n_c_max * N * m`; when that bound is below
  `2**62` the arithmetic runs in `int64`, otherwise in numpy `object` arrays of Python ints (exact,
  slower, no size refusal). The per-class numerator is then divided once by `n_c * N * (m - 1)`,
  which is the only rounding (one correctly rounded division of exact integers for the Python-int
  path; a conversion of two integers below `2**62` for the `int64` path, relative error about
  `1e-16`). Equal EMD is summed the same way from `|count_v * N - Q_v * n_c|` and divided once.
  Acceptance compares with `abs=1e-12, rel=1e-12` against exact fractions, and the Hypothesis
  comparison uses the same tolerances against a dense reference built with `fractions.Fraction`;
  because the numerator is exact, the bound holds at every size, not only at test sizes.
- **Report construction.** Each report is built by one constructor function per model from
  integer arrays, coercing to builtin `int`/`float`. Each dataclass's `__post_init__` checks the
  exact runtime type of every field value against its allowed set, so a numpy scalar or a stray
  string cannot be stored (enforced by construction); a guard test also walks field annotations
  and the values of every fixture's report (section 5).
- **Principles applied** (`architecture.md`): single responsibility and deep module (above). No
  registry: three fixed models from three papers, no open-ended variant set. Two t-closeness entry
  points instead of a `ground_distance=` switch (house style: no behavior-switching flag
  arguments); both call one core with the ground-distance kernel passed in.
- **House style.** Methodology citation in each module docstring (`Pattern:` line, registered in
  `docs/methodology-registry.yaml`); comments explain why.

## 8. Behavior on large tables (performance)

Memory: the named columns converted to pandas, one `int64` code array per quasi-identifier and
the sensitive column, one class-id array, and the (class, value) count table (at most n rows).
Roughly 8 bytes times (quasi-identifiers + 3) per row plus the columns themselves; the rest of the
table is never converted. Time: a prototype of the grouping step on 2,000,000 rows, 3
quasi-identifiers (about 1.9 million classes) and a 50-value sensitive column took 2.5 s on the
build machine. Measured on the build (1,000,000 rows; quasi-identifiers age, sex and a 1,000-value
ZIP giving 143,732 classes; 1,000-value float sensitive column): `measure_k_anonymity` 1.04 s,
`measure_l_diversity` (with `recursive_c`) 0.81 s, `measure_t_closeness_equal` 0.80 s,
`measure_t_closeness_ordered` 1.16 s, the same from a pyarrow table 0.35 s. Not asserted in T1.
`object` columns cost more: pandas `factorize` hashes Python objects, and a column whose
`pd.api.types.infer_dtype` (a C-level scan) does not report a single family also gets a per-cell
Python type-family pass. At 1,000,000 rows with two quasi-identifiers: two `string[pyarrow]`
columns 0.13 s; two `object` string columns (single family, pass skipped) 0.69 s; one `object`
column mixing `1` and `"1"` (pass runs) 0.74 s. Before the skip, two `object` columns took about
1.95 s (code review P2-3). This is in-memory whole-table measurement; it does not stream.

## 9. Known limits

- Whole-table, in-memory; no chunked or streaming path (X-12 notes the later search also needs the
  whole table).
- Floats as quasi-identifiers group by exact value; callers generalize first (V2-3.1).
- `-0.0` and `0.0` are one value; distinct NaN payloads are one null; `Decimal` values compare by
  number (`1.0 == 1.00`).
- t-closeness measures only non-null sensitive values. When nulls carry meaning (for example "not
  tested"), a skew in null rates between classes is a disclosure this measure does not see; the
  report gives `rows_with_null_sensitive` and `rows_in_unmeasured_classes` but no per-class null
  rate. Callers for whom null is meaningful should replace it with an explicit value before
  measuring. The package docstring says so.
- Ordered EMD refuses `object` columns, including pandas `Decimal` objects; convert to an Arrow
  decimal or float first. Above `n_c_max * N * m >= 2**62` it switches to exact Python-int
  arithmetic, which is correct but slower.
- Quasi-identifier families split values of different families that compare equal (`1`, `1.0`,
  `True`); sensitive values are family-keyed for t and merged by plain equality for l. Each
  choice errs in the conservative direction for its model.
- Timezone-aware timestamps for the same instant in different zones compare equal and fall into
  one class.
- A chunked ordered dictionary whose chunks disagree on order is refused for ordered t-closeness
  even when a total order could be merged from the chunks (for example `[1, 3]` and `[3, 4]`);
  only a chunk dictionary that already holds the full order is used.
- Null policy differs from the profiler's k estimate (which drops null rows) until the follow-up.
- Prosecutor risk only; no journalist or marketer risk.
- The metrics describe syntactic privacy models; they do not prove resistance to linkage with
  outside data, skewness or similarity attacks beyond what each model covers
  (`docs/what-we-cannot-prove.md` applies; the package docstring says so).
- The Li et al. PDFs could not be fetched in this session (network allowlist); formulas and
  example data come from search excerpts, the arXiv tutorial and the derivations in section 7.
  The salary class sets are corroborated by the paper's reported 0.375 and 0.167; the Disease
  column of Table 5 is reproduced from memory of the paper and is not corroborated, so test 2 is
  labelled a hand-computed fixture on that release, not a paper number.
