## 1. FRAME

**Problem.** V2-3.1 gives a lattice of full-domain generalizations and V2-3.2 measures k, l and
t on one table. Nothing chooses a node: a user who wants "k = 5 and entropy l = 3 over these
quasi-identifiers, suppressing at most 2% of rows" has to try nodes by hand, and nothing says
which node loses the least information. That choice is the core of formal anonymity enforcement
(F37 / X-12).

**Guarantee (the whole promise of this slice).** For a table `T`, a `Lattice` `L` over its
quasi-identifiers, a non-empty set of privacy models `M` and a suppression limit `s` in `[0, 1]`:

- G1 (feasibility). A node is *feasible* when the rows in its failing classes (classes that fail
  at least one model in `M`, section 3) number at most `floor(s * rows)`. Suppressing those rows
  (the *outliers*) leaves every remaining class meeting every model, where t-closeness is
  measured against the sensitive distribution of all rows of `T` (ARX's rule, section 2).
- G2 (optimality). `search_lattice` returns the feasible node with the least loss under the
  chosen metric, over every node of `L`; ties are broken by fewer suppressed rows, then the
  smaller sum of levels, then the lexicographically smaller node (column order is `L.columns`).
  If no node is feasible it says so (`node is None`).
- G3 (determinism). The chosen node, its loss figures and the suppressed-row count depend only
  on the multiset of rows (not their order, chunking, or the pandas/Arrow route), `L`, `M`, `s`
  and the metric.
- G4 (application). `apply_search` returns the table generalized to the chosen node with every
  row kept, plus a boolean row mask of the suppressed rows; `drop_suppressed()` gives the table
  without them. Removing the masked rows from the generalized table leaves classes whose k and l
  measured by V2-3.2 meet the targets (t: against `T`'s distribution, section 3).
- G5 (bounded). A lattice with more than `MAX_LATTICE_NODES` (10,000) nodes is refused before
  any data is read.
- G6 (value-free, dark). Results and errors carry no cell value and no exception chain; V1
  behaviour is unchanged.

**Definition of done.** G1 to G6 hold, proved by the acceptance tests of section 8, including
brute-force optimality over every node of small lattices; the information-loss figures match
hand-computed fixtures; the duplicate `type_family` is folded to one definition (section 4); the
accepted limits are in `docs/what-we-cannot-prove.md`; CHANGELOG `[Unreleased]` entry.

**Non-goals (recorded follow-ups, not blockers).**

- Config keys, planner admission, route refusal, memory estimate and reason codes (slice 2,
  section 13).
- Local (cell-level) recoding, multidimensional recoding (Mondrian), microaggregation (V2-3.4),

## 2. Established solutions

Searches run (2026-11-12, WebSearch and WebFetch): "ARX anonymization isMonotonicWithSuppression
l-diversity t-closeness monotonic privacy model suppression limit"; "Kohlmayer Flash efficient
stable optimal k-anonymity 2012 predictive tagging lattice search algorithm"; "ARX anonymization
suppression limit outliers suppressed records removed"; "non-uniform entropy information loss
metric Gionis Tassa 2009"; "Incognito LeFevre DeWitt Ramakrishnan 2005 rollup property frequency
set generalization subset property". Fetched from the ARX source
(`github.com/arx-deidentifier/arx`, master, Apache-2.0): `criteria/KAnonymity.java`,
`LDiversity.java`, `DistinctLDiversity.java`, `EntropyLDiversity.java`,
`RecursiveCLDiversity.java`, `TCloseness.java`, `EqualDistanceTCloseness.java`,
`metric/v2/MetricSDNMDiscernability.java`, `metric/v2/MetricMDNMLoss.java`. The PMC copy of
Prasser et al.'s ARX paper was blocked by the session's network allowlist (host
`pmc.ncbi.nlm.nih.gov`). Codebase: the V2-3.1 and V2-3.2 packages and plans, the probe above.

Findings:

- **Full-domain generalization with record suppression** (Samarati 2001; Sweeney 2002): every
  value of a column is recoded to the same level; records that still violate the model are
  suppressed, up to a limit. ARX's README: with tuple suppression "a subset of data items of
  pre-defined relative size may fail the chosen anonymity criterion", and that subset is
  suppressed (ARX's *suppression limit*, a fraction of rows).
- **Incognito** (LeFevre, DeWitt and Ramakrishnan, SIGMOD 2005): the frequency set (each distinct
  quasi-identifier combination with its count) of a generalization can be computed from the
  frequency set of any finer one by summing counts (rollup), and k-anonymity is monotone under
  generalization. **Flash** (Kohlmayer, Prasser, Eckert, Kemper and Kuhn, PASSAT 2012) and its
  predecessor OLA walk the same lattice with *predictive tagging*: when the criterion is
  monotone, an anonymous node's successors are anonymous and a non-anonymous node's predecessors
  are not, and with a monotone loss metric no successor of an anonymous node can be better.
- **Where monotonicity does not hold, and ARX's handling.** ARX declares two flags per criterion
  (`monotonicWithSuppression`, `monotonicWithGeneralization`) in the constructor:
  `KAnonymity` `(true, true)`, `DistinctLDiversity` `(true, true)`, `EntropyLDiversity`
  `(false, true)`, `RecursiveCLDiversity` `(false, true)`, `TCloseness` `(false, true)`. So
  entropy l, recursive (c, l) and t-closeness are monotone only without suppression: merging a
  passing class with a failing one can produce a failing class, so the outlier set can grow from
  a node to a successor (the merged class's entropy or EMD is a weighted mix of the parts, which
  can fall below the target). The README states that "with tuple suppression with l-diversity or
  t-closeness or non-monotonic metrics, the framework utilizes a modified algorithm" to stay
  optimal. ARX's metrics with suppression are non-monotone too: generalizing can remove
  suppressed rows and lower the loss.
- **ARX lower bounds.** `MetricSDNMDiscernability.getLowerBoundInternal` sums `count^2` over all
  classes ignoring suppression; it is a lower bound on the suppression-aware value (a suppressed
  class costs `rows * count >= count^2`) and is monotone under generalization. This is how ARX
  keeps optimal pruning sound for non-monotone criteria and metrics.
- **ARX t-closeness reference distribution.** `EqualDistanceTCloseness.initialize` takes the
  table distribution once, `distribution = manager.getDistribution(attribute)`, from the input
  data; every class is compared with that fixed distribution regardless of suppression.
- **Information-loss metrics.**
  - Discernibility (Bayardo and Agrawal 2005; ARX `MetricSDNMDiscernability`):
    `DM = sum over non-suppressed classes |E|^2 + rows * suppressed_rows`.
  - Loss metric (Iyengar 2002; ARX `MetricMDNMLoss`): per attribute and row, the share
    `(M - 1) / (|A| - 1)` of the domain covered by the row's generalized value (M leaves under
    it, |A| domain size); a suppressed row costs the full share 1 (ARX with the default
    generalization/suppression factor 0.5 gives `sFactor = gFactor = 1`); averaged over
    attributes and rows.
  - Non-uniform entropy (Gionis and Tassa, IEEE TKDE 21(2), 2009; ARX `MetricMDNUEntropy`):
    `sum over rows and attributes of -log2 Pr(original value | generalized value)`, with the
    probability taken from the column's frequencies in the input. Monotone under generalization.
- **Complexity.** Optimal t-closeness generalization is NP-hard for every `t < 1` (Liang and
  Yuan, arXiv:1301.1751); optimal full-domain search is exponential in the number of columns,
  which is why ARX and this slice bound the lattice.

**Design follows.** ARX's model set and flags (K, distinct / entropy / recursive-(c, l) l,
equal / ordered t, each a model object as in ARX's `config.addPrivacyModel`), ARX's suppression
semantics (outliers are the rows of failing classes, limited as a fraction of rows; t against
the input distribution), Incognito's rollup of frequency sets, the three metrics with ARX's
suppression penalties, and ARX's lower-bound pruning for optimality with non-monotone criteria
and metrics.

**Where it departs, and why.**

- **No predictive tagging of the property.** Flash's tagging saves *property checks*; here the
  per-node cost is building the node's classes (a rollup), which the loss bound needs anyway, and
  the property check on those classes is cheap. The search therefore visits nodes bottom-up by
  height (Incognito's breadth-first order) and prunes only by the metric's lower bound, which is
  sound whether or not the models are monotone. The ARX flags are still recorded on each model
  descriptor, and a property test pins them (section 8), so a later Flash-style traversal can
  rely on them.
- **Exhaustive within a ceiling, not Flash's greedy paths.** Flash's path strategy pays off on
  large lattices for monotone k-anonymity without suppression; this slice's guarantee is
  optimality under suppression with non-monotone criteria, on a lattice of at most 10,000 nodes,
  checked by brute force. A Flash traversal is a follow-up if measurement shows the ceiling is
  too low.
- **Loss metric domain.** ARX takes `|A|` and M from the hierarchy's leaves; V2-3.1 hierarchies
  are rules, not trees, so `|A|` and M are counted over the column's observed distinct values
  (null counted as one value, as in V2-3.2). This is the ARX "materialized" domain share for a
  hierarchy built from the data.

Custom code is needed because no allowed dependency implements the search (ARX is Java; no new
dependencies). It is the traversal, the rollup per node, and the three metrics; class identity
and the per-class model predicates are reused from V2-3.2.

## 3. Behaviour

**API (new import paths).**

```python
from decoy_engine.anonymize.hierarchies import Lattice, interval_hierarchy, prefix_hierarchy
from decoy_engine.anonymize.search import (
    MAX_LATTICE_NODES, Discernibility, LossMetric, NonUniformEntropy,
    SearchResult, apply_search, search_lattice,
)
from decoy_engine.quality.anonymity import (
    KAnonymity, DistinctLDiversity, EntropyLDiversity, RecursiveCLDiversity,
    EqualTCloseness, OrderedTCloseness,
)

lattice = Lattice({"age": interval_hierarchy((5, 10, 20)), "zip": prefix_hierarchy(5)})
result = search_lattice(
    df, lattice,
    models=(KAnonymity(k=5), EntropyLDiversity("diagnosis", l=3)),
    suppression_limit=0.02,
    metric=LossMetric(),            # default
)
# SearchResult(columns=("age", "zip"), node=(2, 3), rows=10000, rows_suppressed=143,
#              allowed_suppressed=200, metric="loss", loss=0.41..., discernibility=...,
#              loss_metric=0.41..., non_uniform_entropy=..., class_count=..., k_min=...,
#              lattice_size=30, nodes_evaluated=17, found=True, ...)
released = apply_search(df, lattice, models, result)   # new table, input unchanged
released.table           # every row, generalized to (2, 3)
released.suppressed      # numpy bool mask, 143 True
released.drop_suppressed()   # the table without those rows
```

**Privacy models** (frozen dataclasses in `decoy_engine.quality.anonymity`, value-free: a column
name and thresholds). Each states which classes fail, using the V2-3.2 definition and tolerance:

| Model | Fails a class when | ARX flags (suppression, generalization) |
|---|---|---|
| `KAnonymity(k)` | size `< k` | true, true |
| `DistinctLDiversity(sensitive, l)` | distinct non-null sensitive values `< l` | true, true |
| `EntropyLDiversity(sensitive, l)` | no non-null sensitive value, or `H < ln l - 1e-12` | false, true |
| `RecursiveCLDiversity(sensitive, c, l)` | recursive l at c `< l` | false, true |
| `EqualTCloseness(sensitive, t)` | equal EMD to the table distribution `> t + 1e-12`, or no non-null sensitive value | false, true |
| `OrderedTCloseness(sensitive, t)` | ordered EMD `> t + 1e-12`, or no non-null sensitive value | false, true |

Arguments are strict (recurring defect 2): `k`, `l` are `int >= 1` (not `bool`, not numpy);
`c > 0` finite real; `t` in `[0, 1]`; `sensitive` a `str`. Reused validators from V2-3.2
(`check_int_target`, `check_positive_real`, `check_unit_interval`). A class with no non-null
sensitive value fails every l and t model: for t this is the conservative reading of V2-3.2's
"undetermined" (a release must not pass on an unmeasured class).

**Outliers and suppression.** At a node, the outliers are the rows of every class that fails at
least one model. All classes are formed over all rows of `T`, and t compares each class with the
sensitive distribution of all rows of `T` (fixed for the whole search, as ARX). Suppressed rows
are kept in `released.table` (generalized like every other row) and flagged in
`released.suppressed`; the guarantee covers the non-suppressed rows only (ARX: the suppressed
group is not itself checked against the models; recorded in known limits and
`docs/what-we-cannot-prove.md`). `allowed_suppressed = floor(s * rows)` computed exactly
(`fractions.Fraction(s) * rows`). `suppression_limit` is `int` or `float` in `[0, 1]`, not
`bool`; default `0.0`.

**Metrics** (descriptor objects, as ARX's `Metric.create*`; one is the objective, all three are
reported). `n` rows, `q` quasi-identifiers, `D_j` observed distinct values of column j (null is
one value):

| Metric | Value at a node | Lower bound (no suppression) |
|---|---|---|
| `Discernibility()` (`"discernibility"`) | `sum_{E not suppressed} |E|^2 + n * suppressed_rows`; exact int | `sum_E |E|^2` |
| `LossMetric()` (`"loss"`) | `(1 / (n q)) sum_j sum_rows share_j(row)`, `share = (M - 1) / (D_j - 1)` with M the observed distinct level-0 values under the row's label; a suppressed row's share is 1; a column with `D_j = 1` contributes 0; exact `Fraction`, reported as `float` | same with no row suppressed |
| `NonUniformEntropy()` (`"non_uniform_entropy"`) | `sum_j sum_rows -log2(c_j(v) / c_j(label))`, counts over all rows of `T`; a suppressed row uses `c_j(label) = n`; `math.fsum` (exactly rounded, so order-independent) | same with no row suppressed |

Empty table: every node is feasible with loss 0; the bottom node is chosen.

**SearchResult** (frozen, slots; `__post_init__` checks exact builtin types, as V2-3.2 reports):
`columns: tuple[str, ...]` (schema identifiers, as error messages already name columns), `node:
tuple[int, ...] | None`, `found: bool`, `lattice_size`, `nodes_evaluated`, `rows`,
`rows_suppressed`, `allowed_suppressed`, `suppression_limit: float`, `metric` (token),
`loss: float | None`, `discernibility: int | None`, `loss_metric: float | None`,
`non_uniform_entropy: float | None`, `class_count: int | None` (non-suppressed classes),
`k_min: int | None` (smallest non-suppressed class). No cell value, no class key, no label.

**Failure modes.**

| Situation | Behaviour |
|---|---|
| `table` not DataFrame / Arrow table; `lattice` not a `Lattice`; `models` empty or holding a non-model; `metric` not a metric | `TypeError` / `ValueError`, fixed text |
| `lattice.size > MAX_LATTICE_NODES` | `ValueError` stating the size and the ceiling, raised before the table is read |
| a quasi-identifier or sensitive column missing or repeated; a sensitive column that is also a quasi-identifier | `ValueError` naming the column (V2-3.2's `check_columns`) |
| a value a hierarchy does not cover | `ValueError` from `Hierarchy.generalize` with the column name and a row count (V2-3.1 wording) |
| ordered t on a non-ordered sensitive column; unhashable or unreadable cells | V2-3.2's value-free `TypeError` naming the column |
| `suppression_limit` bool, NaN, outside `[0, 1]` | `TypeError` / `ValueError` naming the parameter |
| no feasible node | `SearchResult(found=False, node=None, ...loss fields None)`; `apply_search` refuses it with `ValueError` |
| `apply_search` given a result from another table or lattice (row count, columns or lattice size differ, or the recomputed suppressed count differs from the result's) | `ValueError`, fixed text |
| any error | no cell value in the message; `__cause__` and `__context__` are `None` (raised after `except` blocks close) |

`search_lattice` and `apply_search` never modify their input (`apply_search` returns a new table
through `Lattice.apply`).

## 4. Design notes

**Principles that apply.**

- *Open/closed, one descriptor per variant.* Privacy models and metrics will keep arriving
  (delta-presence, hierarchical t, risk-based models; precision, ambiguity metrics). Each model is
  one descriptor (its sensitive coding, its per-class failure rule, its ARX flags); each metric is
  one descriptor (its per-row cost table and its lower bound). The search never branches on the
  model or metric kind.
- *Single responsibility.* `quality.anonymity` owns class identity and per-class verdicts
  (measurement); `anonymize.search` owns the traversal, the metrics and the application
  (mutation has a name: `apply_search`).
- *Deep module.* `FrequencySet` hides pandas grouping, null policy, value identity, sensitive
  coding and rollup behind four methods.

**Pattern followed.** Incognito rollup of frequency sets; ARX criteria, suppression semantics,
metrics and lower bounds; full-domain lattice (V2-3.1). Sources in section 2.

**New public layer in `quality.anonymity`** (measurement, never mutates):

- `_models.py`: the six model descriptors. Each holds its arguments and a `ClassVar`
  `monotone_with_suppression`, names the sensitive coding it needs (the same three coders V2-3.2
  uses: plain equality for l, type family for equal t, rank for ordered t), and implements
  `failing_classes(frequencies) -> numpy bool array` by calling the V2-3.2 kernels. The threshold
  rules (entropy tolerance, recursive comparison, `emd > t + 1e-12`) move out of
  `measure_l_diversity` and `_t_closeness._measure` into small named predicates in
  `_l_diversity.py` / `_t_closeness.py` that both the measures and the models call, so each rule
  is written once; the measures' reports do not change (their tests stay green unchanged).
- `_frequency_set.py`: `FrequencySet`, the Incognito frequency set over the base (bottom-node)
  classes:
  - `FrequencySet.of(table, quasi_identifiers, models)`: reads the columns with V2-3.2's
    `read_columns` (lossless Arrow conversion), builds class ids with `equivalence_classes` (the
    one class identity), keeps per row the base class id, per base class its size and one
    representative row position (the first, by position, of the class), and per sensitive coding
    the sparse (class, value) counts (`sensitive_counts`).
  - `fs.representatives() -> numpy int array` (row positions; used to take the distinct rows).
  - `fs.rollup(column_codes) -> FrequencySet`: groups base classes by the given per-column integer
    codes (one array per quasi-identifier, length = base classes) and sums sizes and sparse
    counts (Incognito rollup). Grouping goes through the same `equivalence_classes` on an integer
    frame, so there is one grouping routine.
  - `fs.failing(models) -> numpy bool array` over classes (OR of each model's failing classes).
  - `fs.class_of_base` (base class to class, for mapping verdicts back to rows) and `fs.sizes`.
  Fields are integer arrays only (value-free).

**`anonymize.search`** (`search_lattice`, `apply_search`, metrics, `SearchResult`,
`MAX_LATTICE_NODES`):

1. Check arguments and the ceiling (`lattice.size <= MAX_LATTICE_NODES`), before reading data.
2. `base = FrequencySet.of(table, lattice.columns, models)`.
3. Representative table: the rows at `base.representatives()` (pandas `take` / Arrow `take`),
   only the quasi-identifier columns; `B` rows (B = base classes).
4. Per (column j, level h): `labels = hierarchy_j.generalize(rep[j], h)` (V2-3.1, on B rows), then
   `codes[j][h] = FrequencySet.of(labels as a one-column table, [j], ()).class_ids` (integers over
   B, same identity rule); and, for the metrics, per base class the count of observed level-0
   values under its label (M) and the row count of its label (`c(label)`), both from base sizes
   with `numpy.bincount` over the codes; and `c(v)` from the level-0 codes. These arrays are the
   per-(column, level) cache (memory below).
5. Traverse `lattice.nodes()` sorted by (sum of levels, node). A node is skipped (dominated) when
   any predecessor is dominated. Otherwise evaluate: `node_fs = base.rollup([codes[j][node[j]]])`;
   `failing = node_fs.failing(models)`; `suppressed = sizes[failing].sum()`; lower bound and loss
   from the cached per-base-class costs. Then:
   - if `lower_bound > best_loss` (strictly; for non-uniform entropy, beyond a `1e-9` relative
     margin): mark dominated (every successor's bound is at least this one, section 2);
   - if feasible (`suppressed <= allowed`) and better than best by the tie-break key
     `(loss, suppressed, sum(node), node)`: becomes best;
   - if feasible with nothing suppressed: mark dominated after recording (its loss equals its
     bound, and any successor has loss at least that, more levels, and so loses the tie-break).
6. Build `SearchResult` (all three metrics computed at the chosen node; the objective's value
   is `loss`).

`apply_search(table, lattice, models, result)`: checks the result matches (columns, rows,
lattice size), recomputes `FrequencySet.of` and the node's failing classes, checks the
suppressed count equals `result.rows_suppressed`, and returns
`Released(table=lattice.apply(table, node), suppressed=<bool mask>)`; `drop_suppressed()` filters
by the mask (pandas boolean indexing, which keeps the original index; Arrow `filter`).

**Why bottom-up with bound pruning is optimal (stated once, in the `_search.py` docstring).** For
each metric the no-suppression value is (a) a lower bound of the real value at the same node and
(b) non-decreasing from a node to any successor (classes only merge, labels only coarsen). A
dominated node therefore has no successor that beats the best found, and a feasible node with no
suppression has no successor that beats it under the tie-break. No property monotonicity is
used, so entropy l, recursive l and t-closeness with suppression are handled correctly.

**Determinism.** Every quantity is a function of class sizes and counts, which are row-order
invariant; base class ids depend on first appearance but nothing chosen depends on them. Sums are
exact integers or `Fraction` except non-uniform entropy (`math.fsum`, exactly rounded, so the
summation order does not matter). Ties use the stated key. The representative row of a base
class is the first by position, but all rows of a base class are equal under the identity rule,
so its labels do not depend on which row is taken.

**Memory and time.** `n` rows, `B` base classes, `q` quasi-identifiers, `H = sum_j (h_j + 1)`
levels. Memory: the read columns (V2-3.2's conversion), base ids (8n bytes), sensitive codes per
coding (8n bytes each), the representative table (B rows), and per (column, level) four int64 /
float64 arrays over B (32 B H bytes). Per node: one rollup, O(B q) time and O(B) memory, freed
after the node. Time: O(n) once, plus O(B) per generalize call (H calls), plus O(B q) per
evaluated node. At most `MAX_LATTICE_NODES` nodes. The build records measured times on the probe
shape (200,000 rows) for the ceiling's justification; nothing timing-based is asserted in T1.

**The `type_family` fold (merge-order item owned here).** `type_family` exists twice:
`anonymize/_values.py` (public, exported as `decoy_engine.anonymize.type_family`) and
`quality/anonymity/_classes.py:302`. The build deletes the `_classes.py` copy and imports

**House style.** Typed descriptors instead of string switches (no `model="entropy"` flags);

## 9. Known limits (also in `docs/what-we-cannot-prove.md` where marked *)

- \* The suppressed group is not checked against the models (ARX semantics). If few rows are
  suppressed and they stay in the released table, they form a small group of fully suppressed
  rows; callers that release them should drop them (`drop_suppressed()`) or treat them as
  removed. Slice 2 decides the pipeline behaviour.
- \* t-closeness is measured against the distribution of all input rows. After dropping
  suppressed rows, V2-3.2's `measure_t_closeness_*` on the result uses the remaining rows'
  distribution and can report a larger distance than the search did.
- \* The models are syntactic; meeting them proves nothing about linkage with outside data,
  background knowledge, or attacks the models do not cover (restated from V2-3.2).
- Optimal only within `MAX_LATTICE_NODES` (10,000); larger lattices are refused, not searched
  heuristically. Exponential in the number of quasi-identifiers.
- Full-domain global recoding only: one level per column for every row.
- The loss metric uses the observed domain (distinct values in the table), not a declared
  domain; adding rows with new values changes shares.
- Non-uniform entropy compares within a `1e-9` relative margin for pruning; its reported value
  is a float.
- Whole-table, in memory (as V2-3.2): no streaming path. Base-class representatives bound the
  generalize cost, but a table with all-distinct quasi-identifier rows gets no compression.
- The no-feasible-node case returns a result rather than relaxing targets; the caller chooses.
