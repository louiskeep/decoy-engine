## 10. Errata applied

- **M1**: `counts` is the sorted pair-tuple form; a `dict` raises `ValueError` (`test_field_walk[counts-dict]`); every field and nested value is checked by exact type.
- **M1-b**: a builtin maps by its own `cls.__name__` (`OSError` to `OSError`); `IOError` and `EnvironmentError` stay members and are never produced (`test_oserror_maps_to_oserror_not_ioerror`). The enum is built with the functional API over a member-less base. Under `TYPE_CHECKING` a stub declares `EXCEPTION`. The runtime build sits in the `else` branch, which mypy does not analyze, so no `type: ignore` is needed (`warn_unused_ignores` is on). `from_label` and the table call `SafeErrorType(value)` behind a set-membership check, so they need no ignore either.
- **H1**: one `ADAPTERS` entry `("safe_output/_event.py", "SafeEvent.to_dict")`. `to_dict` writes the reason identity from the registry spec that `require_known` returns, never from the caller's strings; `src/` builds no `ReasonRef`.
- **L1**: `StepRef(value)` raises `ValueError` on refusal; no lenient constructor.
- **N2**: `sev` is `reasons.Severity`; no `DEBUG`.
- **N7**: `0 <= seq <= 2**53 - 1`, `0 <= ts_ms <= 253_402_300_799_999`; both zeros valid (minimal event in E0a-5).
- **N8**: the member set equals `_safe_error_names() | {"Exception"}` (T5-d).

Deviations from the handoff text:
- The handoff asked the `_exception.py` docstring to cite the table under a name that the engine's residual-surface sentry (`tests/sentry/test_no_residual_removed_surface.py`) forbids in tracked `src/` files. The commit-3 docstring held it, and the sentry went red on it. Commit 4 cites "the exact-type table that `phase.error_result` held" instead. (Class 10: the sentry is the contract.)
- Ruff's import sorting changed in the three new test files once `decoy_engine.safe_output` existed (first-party detection). Commit 4 re-sorts those imports; no assertion changed.
- Test scope: the orchestrator ruling (no worker full suite) overrides both `WORKER-STANDARDS.md` and the handoff.
