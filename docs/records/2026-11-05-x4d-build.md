Findings from the runs, kept honest:

- The black-hole run for `GCSFileSource.open` and the `NotFound`-only mutation both show the
  layering: `gcs.py` re-translates through `_wrap_gcs_error`, so the read-time mutation is not
  visible through the connector. The direct `gcs_open` test is what pins it.
- The static AT-C10 test does not go red on the "drop `retry=` from `gcs_download`" mutation,
  because the sentry exempts `_clients.py`. AT-C10a is the test for that mutation. The static
  test is red for the reader-bypass mutation (a direct `download_as_bytes` outside the factory).

## Named limits

- The sentry matches by method name: a bound method stored in a variable and called later, a
  call wrapped in `functools.partial`, the `google.cloud.storage.transfer_manager` functions and
  a client built inside an unwrapped third-party library are not seen.
- `BlobWriter` deletes the partial upload on an exception (`terminate()`) with google-auth's
  default timeout, not the engine's.
- Token refresh with real credentials uses google-auth's own timeout.
- The `requests` read timeout is per socket read, so a server that drips bytes can outlast it.
