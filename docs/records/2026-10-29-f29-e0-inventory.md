## Reproduced census

The plan's AST probe reproduces exactly: **839 literal `code=` arguments, 509 distinct strings, 189 nonliteral**. The full scanner is wider than that probe because it also reads positional arguments (by discovering each class's `__init__` signature), class constants, module constants, `.code` writes, enum members of reason enums and payload dicts.

| Measure | Count |
|---|---|
| Producer sites | 1375 (kw 1031, module_const 138, class_attr 108, positional 32, attr_write 30, enum_member 30, dict_payload 6) |
| Distinct wire strings | 782 |
| Registry identities `(namespace, code)` | 804 |
| Namespaces | runtime 263, plan 212, config 102, route 95, quality 50, physical 26, warning 17, connector 15, provider 15, subset 9 |
| Consumer reads of `.code` / `getattr(x, "code")` | 51 (execution 35, plan 5, transforms 3, io 2, subset 2, connectors, generation, progress, unmask) |

The 804 versus 782 difference is the same wire string living in two namespaces. **28 strings** are in two or more namespaces (for example `unknown_provider` in `plan` and `provider`, `pk.duplicates` in `config` and `runtime`, `when_outside_closed_grammar` in `config`, `plan` and `runtime`). The namespace disambiguates each; no wire string is renamed. One symbol collision exists inside a namespace: `fpe.unencryptable_domain` and `fpe_unencryptable_domain` (both `runtime`); the registry keeps both wire strings and gives the dotted one a `__` symbol.

**Deferral needing approval before E1 touches it: the physical seam** (`execution/physical/`). Its decision catalog (`_reasons.py`, `_shadow_diff_codes.py`, 91 `ShadowDifference` sites) is finite and fits a registry namespace (`physical`, `route`). But it also composes `operator_reason` strings as `<code>:<detail>` (`out_of_core_below_threshold:<rows>`, `slice_native_admitted:<strategy>`) and falls back to `unclassified_<family>_rejection:<prose>` with unbounded prose. Those composites need a revised design (identity prefix plus typed context field, prose dropped) that the plan reserves for approval. The seam is internal and shadow-only, so E1 migrates the registry-shaped part last and records the composites as the one approved-design item. The registry never imports the seam (`tests/sentry/test_physical_seam_disconnection.py` stays).

- **Grounded:** `exception_error_text` (`execution/_isolated_common.py:266`) and its `_TRUSTED_CODES` set (`:253`), the policy in `docs/security/error-reporting-and-data-exposure.md`, and `tests/sentry/test_log_interpolation.py`. These are per-surface mechanisms.
- **Not found:** an F31 plan, a typed safe-event boundary or a single sanitiser in this checkout, in `decoy-platform/docs/` other than the roadmap/MASTER prose (`ROADMAP.md` F31 entry; MASTER section F31), or in `dev-rules`. The roadmap marks F31 FRAME as not started ("FRAME starts with: the emitter inventory + the single sanitizing boundary design").
- **Consequence:** E2 cannot integrate "the F31 boundary" because it does not exist. E1 can still proceed (registry, catalog, sentries). For E2, F29 supplies typed `ReasonRecord`/event fields with closed value types and registry-supplied summaries, so the F29 output contains only fixed vocabulary, counts and approved identifiers. It does not add a second redactor. Hooking F31's sanitiser onto identifier fields (`object_ref`, `storage_ref`) is blocked on F31's FRAME; until then identifier fields are emitted as `None`. This is the one gate to resolve before E2.
