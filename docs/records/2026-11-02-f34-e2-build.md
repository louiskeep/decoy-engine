Every A7 case (7a to 7p) is a parametrized `test_typed_cell_matrix` id; none is skipped or xfailed.
The "with and without pandas" requirement is met by `test_7m_same_output_without_pandas`. The parent
process has pandas loaded. The child sets `sys.modules["pandas"] = None` and checks that pyarrow's
own pandas lookup fails there. The two canonical outputs must be equal, so 7m runs in every
green run above.

Two facts found while building 7m:

- `import decoy_engine` imports pandas (`src/decoy_engine/__init__.py:76` to
  `detection/detectors.py:31`; pandas is a required dependency). With pandas blocked, the
  package cannot import at all. So 7m loads only the canary subpackage, with stub parent
  packages. Invariant I4's "without pandas" holds for the canary subpackage, not the whole
  engine.
- With `sys.modules["pandas"] = None`, pyarrow's Cython shim raises `AttributeError` on any call
  that boxes a Python object (`pa.array([...])`, `fill_null(0)`). The first build's
  `fill_null` read crashed this way. That is the same class as V1-1: an exception outside the
  closed set reaches the route. It is fixed by reading the values buffer through a validity-free
  `from_buffers` view. Mutation M10 shows 7m catches it. For the same reason, 7m sends its
  batches over Arrow IPC.
