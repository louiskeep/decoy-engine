## Round 4: listing read contract

Round 3 review found the run listing and the job listing read by two different pieces of code with different rules. The plan now carries one read contract for every API listing, and the script follows it.

- One reader, `_read_listing(fetch, page_path, list_field, item_fields, *, run_id=None)`, serves `_runs` and `_jobs`. Nothing else calls the listing endpoints.
- It reads pages until an empty one, up to `MAX_LIST_PAGES = 100`. Reaching the cap is an error, not a short read.
- Types are exact: the collection must be a `list`, `total_count` an `int` (a `bool` is refused), and each item field must have one of its allowed types.
- Ids must be distinct, `total_count` must be the same on every page, and the total must equal the ids read.
- Every refusal is a `CheckError` (exit 2) with a fixed message that repeats no value from the response.

Two fixtures written during the fix round were wrong and are corrected: one expected a `job_pages` count the fake never produces, and one page rewrite also changed the run listing, so the test failed before reaching the check it named.
