# Engine V2 Baseline Report

**Source:** benchmark CI run captured in `tests/perf_fixtures/engine-v2-baseline.json`
(run on `ci-ubuntu-latest-py311`, 2026-05-28, commit d8ef1e5). Numbers are from the
standardized benchmark CI (`.github/workflows/benchmark.yml`); local dev-box runs are
indicative only. See `scripts/run_engine_v2_baseline.py` for the measurement method.

**Matrix:** 11 strategies x 2 tiers (small = 1k rows, medium = 100k rows) x 2 substrates
(pandas, polars). Large tier (10M rows) is deferred to bigger hardware. Reference strategy
is excluded: it is I/O-bound rather than CPU-bound and belongs in a separate I/O matrix.

**Supersession note.** PERF.BASE.3 originally targeted a pandas baseline
(`run_perf_baseline.py` + `pandas-baseline.json`, with a sub-25% reproducibility band on
cheap-band cells). Those artifacts were retired in b9b73e1 when the engine became V2-only,
which left the committed V2 baseline (`engine-v2-baseline.json`) unguarded. This report and
the `tests/perf/` guards re-establish equivalent coverage against the V2 substrate baseline.
The legacy spec `docs/backlog/perf-baseline/perf-base-3-baseline-measurement.md` (status
"complete", pandas) is historical and describes deleted files.

All performance numbers below are valid only where the Correctness Gate = PASS.

## Hot-spot summary

| Band | Strategies | Typical p50 (medium, polars) | Substrate lift potential |
|---|---|---|---|
| Hot | faker, date_shift | 977 - 1579 ms / 100k rows | Pool-backed generation removes per-row Faker calls |
| Warm | fpe, hash, categorical, formula | 649 - 3594 ms / 100k rows | FPE: native-binding + parallelism; hash: HMAC vectorization |
| Fast | passthrough, redact, truncate, bucketize, shuffle | 21 - 87 ms / 100k rows | Already near memory-bandwidth; minimal substrate lift expected |

The pre-rewrite Faker lift measured 294.55x at medium (canonical 2026-05-28 CI run).
The absolute FPE throughput gate requires >= 15,000 rows/sec at medium on the shipped
substrate (polars); the calibration baseline measured 27,824 rows/sec (PASS).

## Reading guide for substrate-change PRs

To update this report after a substrate change:

```bash
python scripts/run_engine_v2_baseline.py --tier small --tier medium
python scripts/compare_baselines.py \
    --new tests/perf_fixtures/engine-v2-baseline.json \
    --output docs/v2/perf/engine-v2-baseline-report.md
```

A cell that regresses more than 5% vs the committed baseline JSON is a
waiver-candidate (report it in the PR; get explicit sign-off). The
`tests/perf/test_baseline_schema.py` and `tests/perf/test_baseline_reproducibility.py`
gates must stay green after any re-run.

## Caveats

- **Machine-specific numbers.** The committed baseline was captured on a shared
  `ubuntu-latest` GitHub Actions runner. Dev-box numbers are indicative; CI numbers
  are authoritative.
- **Large tier deferred.** A 10M-row run requires more memory than a standard dev box
  (estimated 5-10 GB Parquet load + multi-column faker). The small + medium cells are
  the active regression net.
- **Variance.** Adaptive iteration counts (1 iter for warmup > 30s, 2 for > 5s, 5
  otherwise) mean slower cells have less iteration coverage. The reproducibility test
  (`tests/perf/test_baseline_reproducibility.py`) is a harness-sanity check, not the
  regression gate: it asserts two runs of a mid-band cell land within 3x on polars p50,
  which catches a broken or non-deterministic harness, not a perf regression. The actual
  regression gate is `scripts/compare_baselines.py`, which flags any cell more than 5%
  slower than the committed baseline JSON (see the Reading guide above).
- **Polars boundary cost.** Cheap-band passthrough/redact/truncate cells show polars
  SLOWER than pandas at medium tier. This is the Arrow-boundary conversion cost
  dominating at sub-1ms operation time; the cell spends more time converting than
  masking. Not a regression; expected and documented in the S13 readiness notes.
