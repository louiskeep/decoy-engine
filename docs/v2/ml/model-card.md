### Intended use

Classify a tabular column (represented as aggregate content statistics and
tokenised header) into one of 11 semantic types: `ssn`, `pan`, `iban`,
`email`, `icd10`, `iso_date`, `npi`, `mrn`, `health_plan_id`, `cvv`, `none`.

**This model DETECTS possible PII column types. It does NOT de-identify or
redact any data.** Detection output is advisory; a human or downstream system
must decide what action to take (§B.1).

---

## 2. Intended Uses and Out-of-Scope Uses

**Intended uses:**

- Classify database columns in the Decoy Engine STORM pipeline to decide
  which masking/generation strategy to apply.
- Serve as a second-opinion signal alongside the deterministic regex baseline.
- Power the column-type recommendation UX (after ML3.1 classify-fields API is
  built; not in this sprint).

**Out-of-scope uses:**

- Direct de-identification or redaction of cell values.
- Production inference from arbitrary external model files (§B.5: on-prem
  only; SHA-256 is verified before `joblib.load`).
- High-stakes medical or legal classification without human review.
- Any use that treats model output as a de-identification guarantee.

## 3. Factors

The model was evaluated on two axes of variation:

**Header clarity (§A.8 subgroup breakdown):**

| Subgroup | Description |
|---|---|
| Clear-header | Column name contains a recognisable token (e.g. "ssn", "email", "npi") |
| Cryptic-header | Column name is opaque (e.g. "f1", "col_a", "x2"); signal is content-only |

**OOD (out-of-distribution) slice (§B.2):**

Single- or double-character header tokens (e.g. "e1", "f2") that are more
cryptic than most training examples.

**Known limitation: CVV in held-out evaluation.**

The 10 CVV columns (with clear headers like "cvv", "cvc") all landed in the
TRAINING fold due to value-level grouping (§A.3): the union-find assigned
them entirely to training when the StratifiedGroupKFold split was computed.
CVV is therefore not represented in the held-out test metrics. At inference
the model CAN predict `cvv` using both header tokens and the 4-digit content
signature; the absence from test metrics is a corpus artefact, not a
capability gap. A future corpus expansion (20+ CVV columns) would allow
proper held-out evaluation.

## 5. Evaluation Data

Training corpus: 291 synthetic columns, zero real PII, generated by
`storm/eval/fixtures.py:build_extended_fixtures()`.

See `corpus-datasheet.md` for full datasheet (7 sections, §B.3).

**Held-out split procedure (§A.3):**

`StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)` with
value-level groups computed by `storm/eval/split:assign_value_level_groups`
(union-find). Groups prevent any cell value from appearing in both training
and test folds. DictVectorizer and CalibratedClassifierCV were fit on the
training fold only.

## 6. Training Data

Same as evaluation data (same corpus, different split fold). See

## 7. Quantitative Analyses

**Threshold justification (§A.5):**

For PII detection, false negatives (missed PII) are more costly than false
positives (over-flagging). Using Elkan 2001's cost-sensitive threshold
formula: threshold = 1 / (1 + k), where k = FN:FP cost ratio.

k=5 was chosen (missing PII is 5x more costly than a false alarm), giving
threshold = 1/6 = 0.1667. At this threshold the model suppresses to `none`
only when it is less than 16.67% confident in any PII class, which strongly
biases toward recall.

**Calibration justification (§A.4):**

With ~234 training columns and a 5-fold CV calibration split (calibration
fold ~47 columns), the total calibration sample is below ~1000, so `sigmoid`
calibration was used (sklearn documentation §1.16: isotonic regression requires
larger calibration sets to avoid overfitting). Reliability curve and Brier score
are recorded in `lightgbm-report.json`.

## 8. Ethical Considerations

- All training data is fully synthetic. No real PII was used at any stage.
- The model is a DETECTOR, not a de-identification tool. It does not remove,
  mask, or transform any data.
- Model output must be treated as advisory. Automated actions based solely on
  this model's output should be reviewed by a human operator.
- The model is intended for on-premises deployment only (§B.5). It must not
  be used to send data to external cloud inference APIs.
- This model does NOT provide differential privacy guarantees.

---

## 9. Caveats and Recommendations

1. **CVV held-out gap:** CVV type has no test-fold evaluation due to corpus
   size. Expand to 20+ CVV training columns in a future corpus revision to
   allow proper held-out recall measurement.

2. **Calibration:** Mean calibration error (MCE) is 0.1997 on 9 classes; the
   model tends to be slightly overconfident at high-probability predictions.
   Use calibrated probabilities for threshold decisions, not raw scores.

3. **Provenance signing (ML3.2):** The pack is currently unsigned
   (`signing_key_ref: "unsigned"`). Before production use, implement the
   ML3.2 provenance signing sprint to generate a hardware-backed signature.

4. **Corpus expansion:** 291 training columns is sufficient to demonstrate
   the lift gate but is a small corpus. Pre-GA training should use a larger
   synthetic corpus (500+ columns per type).

5. **On-prem only:** Never load this pack from an external or untrusted
   source. The SHA-256 check in `ModelPackLoader` is a tamper-detection
   mechanism, not an authentication scheme.
