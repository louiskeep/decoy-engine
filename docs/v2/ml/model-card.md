### Intended use

Classify a tabular column (represented as aggregate content statistics and
tokenised header) into one of 11 semantic types: `ssn`, `pan`, `iban`,
`email`, `icd10`, `iso_date`, `npi`, `mrn`, `health_plan_id`, `cvv`, `none`.

**This model DETECTS possible PII column types. It does NOT de-identify or
redact any data.** Detection output is advisory; a human or downstream system
must decide what action to take (§B.1).

---

## 2. Intended Uses and Out-of-Scope Uses

**Intended uses:**

- Classify database columns in the Decoy Engine STORM pipeline to decide
  which masking/generation strategy to apply.
- Serve as a second-opinion signal alongside the deterministic regex baseline.
- Power the column-type recommendation UX (after ML3.1 classify-fields API is
  built; not in this sprint).

**Out-of-scope uses:**

- Direct de-identification or redaction of cell values.
- Production inference from arbitrary external model files (§B.5: on-prem
  only; SHA-256 is verified before `joblib.load`).
- High-stakes medical or legal classification without human review.
- Any use that treats model output as a de-identification guarantee.

## 3. Factors

The model was evaluated on two axes of variation:

**Header clarity (§A.8 subgroup breakdown):**

| Subgroup | Description |
|---|---|
| Clear-header | Column name contains a recognisable token (e.g. "ssn", "email", "npi") |
| Cryptic-header | Column name is opaque (e.g. "f1", "col_a", "x2"); signal is content-only |

**OOD (out-of-distribution) slice (§B.2):**

Single- or double-character header tokens (e.g. "e1", "f2") that are more
cryptic than most training examples.

**CVV held-out evaluation (fixed).**

CVV columns now use non-overlapping 4-digit value ranges (2000-2999, partitioned
per column) so that assign_value_level_groups keeps them in separate union-find
groups. At the expanded corpus scale (2958 columns), CVV value sets remain fully
disjoint, allowing multiple CVV columns in the held-out test fold: recall=1.00,
precision=1.00, F2=1.00 on n=25 test samples. The remaining CVV columns are in
the training fold. This resolves the prior artefact where all CVV columns shared
a common RNG pool and merged into one union-find group.

## 5. Evaluation Data

Training corpus: 2958 synthetic columns, zero real PII, generated by
`storm/eval/fixtures.py:build_extended_fixtures()`.

See `corpus-datasheet.md` for full datasheet (7 sections, §B.3).

**Held-out split procedure (§A.3):**

`StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)` with
value-level groups computed by `storm/eval/split:assign_value_level_groups`
(union-find). Groups prevent any cell value from appearing in both training
and test folds. DictVectorizer and CalibratedClassifierCV were fit on the
training fold only.

## 7. Quantitative Analyses

**Threshold justification (§A.5):**

For PII detection, false negatives (missed PII) are more costly than false
positives (over-flagging). Using Elkan 2001's cost-sensitive threshold
formula: threshold = 1 / (1 + k), where k = FN:FP cost ratio.

k=5 was chosen (missing PII is 5x more costly than a false alarm), giving
threshold = 1/6 = 0.1667. At this threshold the model suppresses to `none`
only when it is less than 16.67% confident in any PII class, which strongly
biases toward recall.

**Calibration and confidence bands (§A.4):**

Isotonic calibration was used (the expanded corpus provides sufficient calibration
samples). Reliability curve and Brier score are recorded in `lightgbm-report.json`.

Band thresholds are derived from the held-out test set performance:

| Band | Proba threshold | Empirical accuracy (held-out, typical) | 95% CI lower (Wilson) |
|---|---|---|---|
| high | >= 0.95 | ~99.8% | ~0.99 |
| review | 0.70 -- 0.95 | ~98% | ~0.97 |
| low | op-thresh -- 0.70 | ~94% | ~0.92 |

The "high" band is now reachable: isotonic calibration produces well-calibrated
probabilities across the full range, particularly for the majority of held-out
columns classified with high confidence. The mean calibration error (MCE) of
0.0536 indicates isotonic mapping has resolved the prior sigmoid underconfidence
issue. Predictions above the operating threshold (0.1667) can be treated as
high-confidence on this corpus.

Test: `tests/snapshots/test_ml_lightgbm_golden.py::test_predict_column_band_accuracy`
verifies the band-to-accuracy relationship holds on every CI run.

## 8. Ethical Considerations

- All training data is fully synthetic. No real PII was used at any stage.
- The model is a DETECTOR, not a de-identification tool. It does not remove,
  mask, or transform any data.
- Model output must be treated as advisory. Automated actions based solely on
  this model's output should be reviewed by a human operator.
- The model is intended for on-premises deployment only (§B.5). It must not
  be used to send data to external cloud inference APIs.
- This model does NOT provide differential privacy guarantees.

## 9. Caveats and Recommendations

1. **CVV held-out support (n=25):** The CVV fix (non-overlapping value ranges)
   now gives 25 test-fold CVV samples across the expanded corpus. Recall=1.00
   is well-supported. Further expansion will continue to scale CVV coverage.

2. **Confidence bands are well-calibrated:** Isotonic calibration with the
   expanded corpus makes the "high" band (>= 0.95) reachable and achieves
   ~99.8% empirical accuracy on held-out columns. The mean calibration error
   (MCE) of 0.0536 confirms well-calibrated probabilities across all confidence
   thresholds. See §A.4 above for measured numbers.

4. **Provenance signing (ML3.2 -- DECIDED; DE-04 enforcement Option C):** The
   committed pack ships unsigned (`manifest_hmac: ""`) by design, because the
   signing key is per-instance. Decoy is single-tenant and self-hosted, so the
   signing key is derived from the box's own master key via HKDF-SHA256
   (`derive_pack_signing_key`, info `decoy-pack-signing-v1`) and the pack is
   signed in place at install time on that box (`sign_pack`). No external KMS or
   asymmetric signature is used: within a single self-hosted trust boundary a
   symmetric HMAC is the right primitive (tamper-evidence, not remote-forger
   defence).

   Because `joblib.load` executes arbitrary code, the loader enforces a signature
   across the **untrusted pack boundary** (DE-04). A caller-supplied `pack_dir`
   (a pack from anywhere other than the shipped first-party default) is
   fail-closed: it is refused before deserialisation unless it carries a
   signature verifiable with `DECOY_PACK_SIGNING_KEY`. The trusted first-party
   default pack (shipped inside the wheel, SHA-256 verified) keeps loading out of
   the box; setting `DECOY_PACK_REQUIRE_SIGNATURE=1` additionally requires a
   signature for it too (opt-in hard lockdown, e.g. once the deploy step signs
   the pack in place). See `storm/model_pack/loader.py` (`trusted` /
   `_check_signature`) and `storm/model_pack/provenance.py`.

   > **Operator note (ordering matters).** Turning on hard lockdown before the
   > deploy step has signed the pack makes ML go dark. If you set
   > `DECOY_PACK_REQUIRE_SIGNATURE=1` while the on-box pack is still unsigned
   > (`manifest_hmac: ""`), the trusted default now also demands a signature,
   > fails closed, and `classify_fields` degrades to the regex baseline
   > (returns `None`) with no error raised. Sign the pack in place first
   > (`sign_pack`, which needs `DECOY_PACK_SIGNING_KEY` configured), then enable
   > the flag. Likewise, a set-but-unparseable `DECOY_PACK_SIGNING_KEY` is
   > treated as fail-closed: the loader raises rather than silently loading
   > unverified, so a typo'd key disables ML instead of weakening it.

3. **Corpus expansion:** The 2958-column corpus is sufficient to demonstrate
   isotonic calibration and the lift gate. Pre-GA training should continue
   expanding to 500+ columns per type for production-scale schema diversity.

4. **On-prem only:** Never load this pack from an external or untrusted
   source. The SHA-256 check in `ModelPackLoader` is a tamper-detection
   mechanism, not an authentication scheme.

5. **OOD evaluation:** Out-of-distribution balanced_accuracy and macro_recall are
   0.8611. This reflects genuine challenges on obfuscated formats (spaced PAN,
   no-dash SSN) with cryptic headers. The gap suggests that production deployment
   should pair this model with human review for columns with uncertain
   header-content alignment.
