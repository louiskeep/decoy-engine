### F2. MEDIUM, V2-LOG, class 9 (spec gap)
Where: scripts/check_pure_move_scope.py:55 (`def_time` drops annotations when lazy) and :143 (rule 8 checks only the future import)
What is wrong: under `from __future__ import annotations`, moving a `@dataclass` with a `ClassVar[...]` field to a module that does not import `ClassVar` returns PURE. dataclasses detects a string `ClassVar` by looking it up in the defining module's namespace, so the field silently becomes an instance field. The same applies to `InitVar` and to any `typing.get_type_hints` consumer. Handoff rule 8 explicitly does not require lazy annotation names, so the build follows the spec. The spec has the gap.
Evidence: P3 is PURE. Real packages: base `fields(S)` is `['a']`, head is `['a', 'k']`. Exposure today: none. No ClassVar or InitVar in the four sources, and the one dataclass (`Span`) stays in E1.
Fix: under lazy annotations, have rule 7 also require names used in class-body annotations of dataclass-decorated classes (or all annotation names), bound unconditionally in the destination. Record it as a plan amendment.
